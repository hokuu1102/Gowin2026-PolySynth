# PolySynth 最终功能版上板验收手册

版本：2026-10-28。适用对象：本交付包的默认 FPGA 鼓机配置及 ESP32-S3 曲库模式固件。实际文件哈希、提交号、构建结果和时序以交付清单为准。本手册是执行规程；没有填写实机记录的项目均为“待上板”，仿真通过不能替代上板通过。

## 1. 先确认交付与硬件

工程为 GW5AT-60B，器件为 GW5AT-LV60PG484AC1/I0、PBGA484A、60K Console 板。不要使用历史资料中的 138K 工程、引脚表或固件。主时钟 50 MHz，音频采样率为 50 MHz / 1024 = 48,828.125 Hz。每声部两个振荡器，最大 32 声部；Test Mode 验证档位为 4、8、16、32 声部。

默认版本保留 Hall 键盘、力度跟随、四种音色、滑音、延音、推子三档、鼓机、键盘鼓、Looper、曲谱播放/指引、双 I2S、HDMI 波形/XY/FFT、BLE、串口屏和运行时效果器。默认 source-B 是鼓机；节拍器为 SEL_DRUM=0 的编译配置，不能把默认鼓机节奏误记为独立节拍器验收。混响、预留 SPI 通道和预留 FX 掩码位不属于已实现功能。

准备：对应板卡和稳定电源、下载器、HDMI 显示器、低音量有源音箱/耳机、3 个 MCP3208、Hall/推子组件、4×4 矩阵键、EC11、三只常开踏板、ESP32-S3（16 MB Flash、匹配的 PSRAM）、3.3 V TTL USB 串口、支持 Web Bluetooth 的 Windows Chrome/Edge、可选串口屏。先断电接线，避免将 5 V 或 RS232 电平接入 FPGA。

每次验收填写：操作者、日期、板卡标识、FPGA/ESP 文件 SHA256、下载方式、供电、环境温度、外设型号、COM 口、浏览器版本。每项结果只能填 PASS、FAIL、待测或不适用并说明理由。保留原始串口文件、录音/视频和截图路径。

## 2. 接线核对

球位用于对照当前 CST，不替代板卡原理图。开发板连接器方向以丝印和原理图为准，不能仅按照片左右推断。

| 接口 | FPGA 球位 / 连接器 | 接法和判据 |
|---|---|---|
| 50 MHz / 复位 / 音色键 | V22 / AA13 / AB13 | 复位低有效；音色键使用现有板载连接 |
| 板载音频 I2S | BCK Y17、WS AB17、DIN AA16 | PA_EN_n 为 Y14，约束 LVCMOS15；该板高电平开启音频 |
| 外接 I2S | BCK F20、LRCK E22、DIN D22 | 接接收端 BCK/LRCK/DIN，共地 |
| PC UART | RX D14（J9-26）、TX D15（J9-25） | USB TX→FPGA RX，USB RX←FPGA TX，500000 8N1，无流控 |
| ESP UART | FPGA TX G21（PMOD0-9）、RX G22（PMOD0-10） | G21→ESP GPIO18 RX，G22←ESP GPIO17 TX，共地 |
| ESP 串口屏 | ESP TX GPIO4、RX GPIO5 | 屏 RX←GPIO4，屏 TX→GPIO5，115200 8N1 |
| 矩阵行 0..3 | D16/E16/E17/F16（J9-27/28/31/32） | 行顺序决定键编号 |
| 矩阵列 0..3 | F15/C20/D20/D19（J9-34/35/36/37） | 键号 = 行×4+列 |
| EC11 A/B/SW | E19/C19/C18（J9-38/39/40） | 共地，按当前上拉连接 |
| 延音 / 录制 / 播放踏板 | F18/E18/B22（PMOD0-7/8/6） | 常开触点接 GND，低有效；默认 5 ms 去抖 |
| 拨弦输入 | E21 / D21 | 上/下拨分别验证，不要与踏板针脚混淆 |
| ADC 共用 SCLK/MOSI | E14 / E13 | 3 个 MCP3208 共用时钟与 MOSI |
| ADC0 MISO/CS | C15 / C14 | 前 8 个 Hall 轴 |
| ADC1 MISO/CS | B13 / C13 | 后 8 个 Hall 轴 |
| ADC2 MISO/CS | A14 / A13 | CH1 总音量、CH2 深度、CH3 速率 |
| TLC5916 | LE A21、SDI B21、CLK B18；OE B17/C17/D17/A19/A18 | 按灯板原理图供电与限流 |
| WS2812 | W19/W20/F19；控制灯 C22 | 以板上电平转换和灯带方向为准 |
| HDMI | 使用板载 HDMI 接口 | 不手接 TMDS 差分线；HPD K13 |

SPI [3:5] 的 B16/B15、A16/A15、A20/B20 为预留，不是额外 24 个可演奏 Hall 轴。ESP 固件默认不启用其 WS2812/BLE 指示灯，不能将不亮误判为连接故障。

## 3. 烧录、首次启动与证据工具

1. 对照交付清单核验 SHA256：`Get-FileHash <文件> -Algorithm SHA256`。FPGA Programmer 选择实际 60K 器件。先下载 SRAM 验证；需要断电保存时再按板卡 Flash 型号写入非易失存储。SRAM 下载成功后断电丢失是正常现象。
2. ESP32-S3 使用交付的 flasher_args.json / flash_args 中地址与文件配套烧录，不能套用其他分区的偏移。示例：进入对应固件目录后运行 `python -m esptool --chip esp32s3 --port COMxx write_flash @flash_args`。先查看该文件并确认引用文件存在，保留烧录日志。COMxx 为 ESP 下载口，区别于 FPGA 500 kbaud 接口。
3. 开机时所有 Hall 键、推子与踏板保持静止。自动 tare 等待约 0.2 秒；Console 的 PA 在复位后持续高电平使能（PA_ON_DELAY 在本配置不参与延时），演示和弦约 40 ms 后触发并在约 1 秒后释放。该和弦是自检，不是持续挂音。心跳约 1 Hz。先把总音量调小，再缓慢提高。
4. 打开串口时不要发送换行或启用串口助手自动发送。多个程序不能同时占用同一 COM 口。首轮仅接 FPGA PC UART，确认后再加入 ESP 与串口屏。

在工程根目录执行（以下 COM31 只是占位，必须替换）：

```powershell
python tools/board_acceptance.py --selftest
python tools/board_acceptance.py --list-ports
python tools/board_acceptance.py --port COM31 --seconds 5 --case BOOT
python tools/board_acceptance.py --port COM31 --ascii V --case STATS
python tools/board_acceptance.py --port COM31 --bpm 120 --case BPM120
python tools/board_acceptance.py --port COM31 --transpose 0 --case TRANSPOSE0
```

工具默认保存原始 .bin 和 .json 到 D:\ChatGPT\Outputs\FPGA上板记录；只记录观测，不自动判定硬件 PASS。二进制上行与文本回包可能混流，不要用总长度必须为 14 的倍数来判错。保存原文件，再使用工程配套解析器查看事件和 CRC。

## 4. 所有面板操作

| 键号 | 操作 | 期望 |
|---|---|---|
| 0 | 短按 | B：鼓机/节奏开关 |
| 1 | 短按 | I：BASS→GUITAR→PIANO→PAD 循环 |
| 2 | 短按 | W：滑音开关 |
| 3 | 短按 | E：波形→XY→FFT 循环（复位默认 XY） |
| 4 | 短按 | K：手弹键盘鼓开关，不重写下载乐谱的音符 |
| 5 | 短按 | J：推子档位 0→1→2 循环；复位默认 1 |
| 6 | 短按 | 升八度，即 +12 半音，受范围限制 |
| 7 | 短按 | A：键盘/指板模式切换 |
| 8 | 短按 | D：四种鼓型循环 |
| 9 | 短按 | 当前推子档锁定/解锁；不是 FX 总开关 |
| 10 | 短按 | 降八度，即 -12 半音，受范围限制 |
| 11 | 短按 | M：4→8→16→32 声部 Test Mode→关闭 |
| 12 | 按住至少 2 秒 | 清空 Looper；短按不清空，长按只触发一次 |
| 13 | 短按 | Y：Looper 快照回传 |
| 14 | 短按 | 恢复变调为 0 |
| 15 | 松开 | tare 零位校准；短按/长按均只在释放时 tare |

按键 15 的旧“长按 span”功能已删除，不能照历史文档做满行程校准。串口 S 仍为遗留诊断入口，不属于日常校准步骤。EC11 普通模式按一下切换 BPM/音高对象，一整格对应 ±1 BPM 或 ±1 半音。反向旋转应抵消，不应一格跳四次。

EC11 参数模式使用小写 `p` 进入/退出、小写 `o` 后跟 0..7 参数号；不要误发大写 P（诊断）。工具 `--param-mode` / `--param-select 0` 可发送。参数依次是增益、补偿、混合、反馈、颤音深度、速率、延迟长度、合唱长度。进入参数模式旋转只改该参数，不改变 BPM/变调；退出恢复原来的 BPM/音高对象。

## 5. 基础演奏与输入验收

以下每个编号独立记录结果。每一步完成后回到静音/节奏关/Test Mode 关的基准状态，不用耳朵同时辨认多种来源。

| 编号 | 执行步骤 | 必须观察到的结果 |
|---|---|---|
| A01 | 连续冷启动 3 次，最后完成第 12 节的 10 次压力统计 | 有心跳和短暂自检和弦，自检释放；启动后无随机长音 |
| A02 | 松开全部 Hall 键，按键 15 释放后依次触动 16 轴 | 16 轴都可独立发音；静止时不自触发；零位探针返回合理且稳定 |
| A03 | 同一键按轻/中/重并保持各 2 秒，再缓慢改变行程 | 声音随行程平滑变化；同一行程重复力度接近；保持后不回到旧力度 |
| A04 | 按 1/2/4/8 个不同键并分别释放 | 和弦无串轴；释放一个键不切掉其他键；全部释放后在包络尾音结束时静音 |
| A05 | 四次切音色，每种重复同一音高和力度 | 四种音色可辨、切回一致；音色切换不改变键号/变调 |
| A06 | 总音量 CH1 从零缓慢到高再回零 | 零位静音，增益变化正常，无异常尖峰；注意 ADC 量化档位，不要求无限分辨率 |
| A07 | W 开/关后分别做相同相邻键/指板手势；切 A 模式试上下拨 | 滑音开启时连续变化、关闭时按普通模式；上下拨均被识别，无常驻触发 |
| A08 | 按住手弹音，踩延音、松键，再松踏板；重复 10 次 | 踩住期间保留手弹音，松踏板释放；不应要求该踏板延长下载曲谱的 OFF |
| A09 | J 循环三档，每档转动对应控制；锁住后变动输入，再解锁 | 0 变调、1 音高振动、2 幅度颤音；各档锁定独立，锁住值不跟动，解锁恢复 |
| A10 | 键 6/10/14、串口 F/G/H、EC11 都分别改音高 | 八度键每次 12 半音，F/G/EC11 每次 1 半音；H 为绝对 -12..12；复位键恢复 0，无叠加残留 |
| A11 | 全部 16 矩阵键各按 10 次，另外长按 9/12/15 | 无双触发、无错行错列；12 短按不清空，15 长按也不进入 span |

A02 探针用 `P`（位置）、`N`（位置诊断）和 `V`（统计），原始回包按对应工具解析。无声时优先核对 CH1 音量、PA、电源、I2S、Test Mode 和键盘模式，再比较串口输入事件；不要立刻以更改 RTL 掩盖接线问题。

## 7. 运行时效果器与回读

默认 mask=0，不表示链路未实现。只实现失真 bit0、合唱 bit1、延迟 bit2；颤音由独立深度/速率控制。切到推子档 0 或 1 再测 UART 颤音：档 2 的物理推子实时值优先于 UART 深度/速率影子寄存器。离开档 2 后 UART 值才成为有效输入。

```powershell
python tools/board_acceptance.py --port COM31 --fx 0x10 0 --case FX_OFF
python tools/board_acceptance.py --port COM31 --fx 0x10 1 --case DIST
python tools/board_acceptance.py --port COM31 --fx 0x10 2 --case CHORUS
python tools/board_acceptance.py --port COM31 --fx 0x10 4 --case DELAY
python tools/board_acceptance.py --port COM31 --fx 0x10 7 --case ALL_FX
python tools/board_acceptance.py --port COM31 --fx-status 0 --case FXSTAT0
```

| 变量 | 值与量化关系 | 验收方法 |
|---|---|---|
| 0x10 mask | 0..7 组合 | C01：依次 0/1/2/4/7/0，同音量录音比对可闻效果并恢复 |
| 0x11 gain | 字节×256，默认 64 | C02：分 16/64/128 改失真增益，配合 trim 控音量 |
| 0x12 trim | 字节×256，默认 32 | C03：调整补偿，检查单调变化和静音边界 |
| 0x13 mix | 干湿混合，默认 128 | C04：0/128/254，检查干湿差异 |
| 0x14 feedback | 默认 96 | C05：延迟模式低/中反馈，停止输入后应衰减，不以高反馈自激作为通过 |
| 0x15 depth | 默认 0 | C06：0/128/254，检查颤音深度和回零 |
| 0x16 rate | 默认 7 | C07：不同速率可区别，注意 0 的实际静态/最低状态 |
| 0x17 delay | 字节×128，上限 16383；默认寄存器 8192 | C08：改长度后有可重复差异，允许缓存重新填充 |
| 0x18 chorus | 字节×32，上限 2047；默认寄存器 736 | C09：合唱模式改长度后有差异，回到原值可恢复 |

帧为 `71 <变量> <值> FF FF FF`，值仅 0..254，FF 是结束符，不能作为普通值。C10：依次回读 Z 子命令 0..7，并比较 mask/延迟活动/合唱活动/缓存状态/削波计数/LFO/流水观测与实际操作；回包统一为 Zz<n><四位十六进制值>LF 共 8 字节；0=mask、1=削波计数、2=延迟活动、3={合唱活动,延迟已填充}、4=LFO、5=流水拍数，6/7 预留回 0000。接收端读取整行后解析，不能沿用旧 6 字节截断格式。共享 UART 的其他诊断回包可能插入 FXSTAT 行内；回读时停止其他诊断请求与 EC11 操作，逐条发送并等待完成。并发诊断的整帧隔离尚待后续处理。C11：进入 EC11 参数模式，每个参数正反各转一格，回读验证改变；BPM/变调不应一起变；退出后原对象恢复。功能检查结束恢复 mask=0、depth=0，避免影响后续验收。

## 8. Looper 录制、播放和回传

测试时先停曲谱、关鼓机和 Test Mode，打开工程的上行工具 `esp32/tools/upstream_studio.html` 或对应串口解析工具。R 为录/停，L 为播放/停，C 为清空，Y 为快照回传；录制先武装，等待下一小节，控制灯 #4 由黄变红后才开始演奏，播放为绿灯。实体 E18/B22 踏板等价于 R/L。清空键 12 需要长按 2 秒。

| 编号 | 执行步骤 | 必须观察到的结果 |
|---|---|---|
| D01 | 空 Looper 按播放，随后录制 4 个音，含轻重、和弦和完整松键，再停止 | 空录音播放被安全拒绝；录制后可播放且音序/力度/音色与输入一致 |
| D02 | 用 R/L 串口操作一轮，再用实体录/播踏板重复；每踏板按住 3 秒 | 一次按下只有一次命令；松开重踩可再触发；两路行为一致，未接踏板不误触发 |
| D03 | 录音覆盖完整 ON/OFF，播放至少 5 圈；边界前后释放音符 | 不漏首音/末尾 OFF，不累积挂音；循环周期稳定 |
| D04 | 停止、重新播放、长按清空、再播放 | 停止正确，重新播放从头；清空后无旧内容；短按清空键不丢数据 |
| D05 | Y 回传静止录音，保存原始流、解析 14 字节上行帧并导出 MIDI，再在 score_studio 转换上传播放 | 首尾完整、帧数/XOR校验/旋律音色/力度/ON-OFF 相符，重新导入可听一致；Looper 不录键盘鼓，鼓型由 O 实时上行验证 |
| D06 | 连续两次 Y；回传期间试录制/清空，完成后再执行 | 忙时按既定拒绝/原子快照策略处理，不混成半份数据；忙结束后可重试 |
| D07 | 开 O 实时上行，弹四音色与键盘鼓，检查 ON/OFF，再关 O | 每个事件可追溯到输入，通道/音色/鼓型一致；关 O 后停止实时事件，文本状态仍可回传 |
| D08 | 同时保持手弹、Looper 和曲谱几秒，再逐一停止 | 来源互不误关；停止一个来源不清掉另一个仍持有的音符；最终全部静音 |

Y 输出 14 字节带 XOR 校验的上行事件，不能把 .bin 原样当 9 字节下行谱面回灌；须从 upstream_studio 导出 MIDI，再交 score_studio 转换。Looper 保存的 phase_inc 有量化，导出不会恢复已经丢失的低位，损失计数要一并记录。

若实时与快照记录不一致，保留 .bin 和导出文件，记录发生在录制、快照、BLE 通知、解析还是重新导入阶段，不只记录“没有声音”。Y 大数据传输要等完成再发送其他诊断；不要把丢弃的忙时命令认成已执行。

## 9. ESP32-S3、BLE、串口屏和网页

当前设备名 `FPGA2026-Synth2`。服务 ABF0；DATA 写 ABF1、上行通知 ABF2、CMD ABF3、STAT ABF4。使用前先订阅 ABF2 通知；旧名字的浏览器授权可能需要重新选择设备。模式 B 使用 PSRAM 曲库，默认容量 2 MB，上传前核对实际剩余容量与帧数。不要将初代 ESP32 的经典蓝牙 SPP 工具用于本 BLE 固件。

网页通过 `esp32/tools/start_score_studio.bat` 启动 localhost 服务后打开 score_studio.html；也可在 tools 目录用 `python -m http.server 8765 --bind 127.0.0.1` 后访问 `http://localhost:8765/score_studio.html`。录制/导出页面为同源 upstream_studio.html。使用 localhost 的安全上下文，关闭占用 BLE 的其他页面。

| 编号 | 执行步骤 | 必须观察到的结果 |
|---|---|---|
| E01 | 上电后连接指定设备并订阅 ABF2；请求一次新统计 | 发现 ABF0..ABF4；CMD 02 后读取的 STAT 是本次更新，req/up 等新鲜度字段前进 |
| E02 | 上传交付测试 MIDI，检查转换预览、分包与总帧数，再 START | 先完整上传再播放；总量一致，曲名/进度正确，无错音丢尾 |
| E03 | 降低 BLE 分包长度、重复上传 3 次、核对二进制导出再导入 | 分包边界不改变 9 字节事件；数据保持、校验/帧统计正常，不靠 MTU 恰好对齐 |
| E04 | 播放到长音时 STOP，再 START；再在长音时 RESET | STOP 关掉已提交未配对音，重播从头；RESET 清池前补 OFF，清池后帧数归零，不挂音 |
| E05 | 以同音重复 ON、交叠 OFF、含 guide-only 和不同音色元数据的曲谱重复 E04 | 每个剩余引用有对应 OFF，灯光与声音最终释放，不错灭其他仍持有音 |
| E06 | 自然播完再 STOP/RESET，重复点击两次；再上传新曲 | 不重复补 OFF、不保留上首位置/完成事件，新曲可正常开始 |
| E07 | 测试带速度变化、长休止、持续音、四音色与四鼓的曲谱 | 变速与休止正确；长休止不是断连；末尾全部 OFF 后自然结束 |
| E08 | 曲库已上传后主动断开 BLE，再重连并刷新状态 | 记录实际独立播放行为；重连能获取新鲜统计并控制；不可要求断开必然自动停音，固件没有该承诺 |
| E09 | BLE 与 FPGA UART、Looper 回传同时负载，记录至少 5 分钟 | 通知解析不乱帧、可诊断丢包，无永远 busy 或必须重刷固件才恢复 |
| E10 | 有串口屏时从冷启动开始观察；使用其现有开始/停止/清空按钮 | 屏 boot ACK 0x88、等待约 2 秒；g0 曲名、j0 进度、n0 百分比、t1 状态、t2 计数、t3 蓝牙、t4 缓冲刷新约 200 ms，状态与实际一致 |

CMD 数值：01 RESET、02 STATS、03 START、04 STOP。默认 START_TRIGGER=0 为串口协议触发；可选 GPIO 触发使用 GPIO6，不能默认叫板载 BOOT。当前屏由 ESP 管理曲库状态；FX 帧走 FPGA UART 控制入口，不能据屏上出现按钮便认定所有 FX 已转发。

STOP 的定义是“停止继续放水并补关音”，已进入 FPGA 队列的尾部仍会按其时间执行；不是全局即时 panic，也不是暂停。START 从头重播；RESET 清 ESP 曲库也不等于 FPGA 硬件复位。观测停止延迟时应记录配置的提前量和队列尾部时间。紧急静音先降总音量，必要时复位 FPGA，并重新执行启动检查。

网页旋律分配最多 12 轴；超出时可能按转换器规则限制/抢占，不是任意 MIDI 都能原样无限复音。灯光身份账本默认 64 个身份，重复同身份使用引用计数；协议不带每次 ON 的实例号，OFF 按确定性身份匹配，不承诺区分完全相同身份的独立实例。超出容量的压力输入须记录为超范围，不能用来宣称无界支持。

## 10. 测试曲与交叉验证

随交付的测试素材包含四份 MIDI 及使用实际网页转换器生成的对应 .hex；逐项验收记录.csv 提供 58 项待填写行。先在 score_studio 预览再上传，不绕过现有转换器。四音色以显式音轨名和程序号核对；四鼓使用 GM36/38/42/45，对应底鼓/军鼓/踩镲/Tom，不能将第 4 件写成 clap。

F01：四音色逐轨与合奏，先听后比较导出回传。F02：12 路旋律交叠、分批 OFF，检查同映射灯仍有引用时不提前灭。F03：四鼓逐件和组合，对照上行鼓型。F04：速度变化、长休止、长保持和曲尾 OFF。F05：播放中反复 K，并执行 STOP/RESET 与重新上传。至少一轮录制 PC 音频，同时保存 UART 和 BLE 上行，便于定位“转谱错误”“传输缺帧”“FPGA 音频路径”三者的区别。

## 11. 故障定位与恢复

| 现象 | 先查什么 | 保留什么证据 |
|---|---|---|
| 烧录成功但重启无程序 | SRAM/Flash 下载方式、器件/Flash 类型、启动模式 | Programmer 截图、文件哈希、断电前后现象 |
| 全静音 | 总音量 CH1、PA Y14、电源、I2S、输入模式；用 M 和自检区分输入/输出 | 双路录音、V/P 回包、示波器时钟 |
| 只有某轴坏 | ADC0/1 的 MISO/CS、通道顺序、tare 时是否按住 | 16 轴逐项位置读数和键号 |
| 松键仍响/灯不灭 | 是否延音、Looper、曲谱仍有引用；检查对应 OFF、来源和 flags | ON 到最终 OFF 的完整原始流，不只截末尾 |
| BLE 发现不到 | 名字 Synth2、供电、浏览器授权、其他连接占用 | ESP 启动日志、浏览器错误、STAT |
| 上传完成但不播 | 曲库帧数/溢出、CMD START、GPIO 触发配置、G21/G22交叉接线 | ESP feed/uart 计数、FPGA入口统计 |
| 屏不刷新 | GPIO4/5、115200、boot ACK、屏工程对象名 | ESP HMI 日志、屏固件版本 |
| FX 看似不变 | mask、mix、源信号、缓存填充、档2推子覆盖 UART 颤音 | 写帧、Z 回读、前后同条件录音 |
| HDMI 黑屏/偶发音频错误 | 器件/时钟/供电/线缆，再核对当前时序欠裕量 | 温度、电源、运行时长、固件哈希、视频 |

只在断电时拔插无热插拔设计的外设。故障恢复顺序：停止上位机发送→降音量→保存日志→复位相关设备→重新核验版本与基准测试。不要同时重启所有设备后丢失定位依据。

## 12. 长稳与签收

G01：混合演奏/曲谱/Looper/HDMI/FX 连续 30 分钟，每 5 分钟保存统计，检查无卡死、永久挂音和持续丢帧。G02：10 次冷启动，记录自检、自动 tare、BLE发现和屏状态。G03：最低/常用/较高负载下分别测音频连续性与温升。G04：断开/重连 BLE、停止/清空/重新上传各 10 轮。G05：复核最终刷入的仍是交付清单版本，并导出最终日志。

时序不足已被明确允许延期优化，但仍是风险：负 setup 裕量意味着不同板卡、温度和电压下可能出现硬件故障。仿真不能消除这一点。记录本次原生时序报告中的 setup、hold、recovery、removal、违规数量和最差路径，不把降低检查标准当作时序通过；不要将“可生成 .fs”写成“时序收敛”。
