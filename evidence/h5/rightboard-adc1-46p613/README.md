# ⚠️ `RIGHT_ADC_ENABLE = 1`（右手板 A 联调档）**时序不达标** —— 请勿作为交付烧写

## 实测（2026-10-04 18:09，合并版源码 + 18.181 ns 余量预算）

| 项 | 值 | 判定 |
|---|---|---|
| **setup 违例** | **1630** | ❌ |
| hold 违例 | 0 | ✅ |

| Logic / Register / CLS | 36068 / 17085 / 24128（81%） | — |
| 码流 | 19,263,591 B / sha256 `4F33EA38…` | — |

## 结论

`RIGHT_ADC_ENABLE = 1` 这个配置**从来没有通过过时序**（`bringup/17-…` 文档里也只写
"要联调右手板 A ⇒ 改 1 后重跑"，暗示当时并未验证）。加入第 3 片 ADC（`adc_farm` 的
`N_ADC` 2→3）后出现了新的长路径，`clk_sys` 掉到 **46.6 MHz**。

⚠️ **46.6 < 50（物理时钟）** ⇒ 烧上去**行为不可靠**（可能出错音、串口/ADC 读数异常等）。

## 建议

1. ⛔ **不要把本档当交付烧写**。
2. 若只是想**快速做一次功能通断检查**（右手板 A 的推子/摇杆/音量是否被读到），
   可以在**知情**的前提下短时烧一次（用 SRAM 下载，掉电即失），
   ⚠️ 但要预期"可能有异常行为"，不能据此判定右手板坏。
3. ✅ **正确做法**：把"让 `RIGHT_ADC_ENABLE=1` 通过时序"当作一个**独立任务**：
   - 先定位这 1630 条违例集中在哪（很可能是 `adc_farm` 片2 的 SPI 采样 →
     颤音控制 → 相位增量这条新链，或 ADC 片2 的 CS/SCLK 输出路径）；
   - 再决定是加流水、还是把片2 的扫描降速、还是把颤音控制改为寄存器化输入；
   - 修复后必须重新过 51.5 门槛（并同时跑双配置回归）。

## 与"能不能用串口切换"的关系

`RIGHT_ADC_ENABLE` 是**编译期参数**（`rtl/top.v:292`），且为 0 时
`ADC_N = 2`（`top.v:1611`）⇒ **片2 根本不被扫描** ⇒ 数据不存在 ⇒ **任何串口命令都变不出来**。
✅ 若希望"一个码流同时兼容只有左手板 / 接了右手板"，需要**改 RTL**：
让 `ADC_N` 恒为 3 + 加一个**运行期使能寄存器** + 一条**串口命令**开关它
（默认关闭 ⇒ 只有左手板的机器仍安全）。这同样需要先解决上面的时序问题。
