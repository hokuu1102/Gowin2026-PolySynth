# 修法 3（电平感知归一化）—— 第一次尝试：**已回退**（2026-10-06）

## 一、根因（已完全量化，✅ 可信）

`rtl/w3b/tdm_render_mixer.v` 的复音归一化 `gain(N) = 64/√N`（Q8.7）。

推导：
```
sh24 = acc >> 8、acc = Σ(vs_c × env_c)、vs_c ≤ 32767
⇒ sh24_max = 128 × Σenv
⇒ 限幅器看到 = sh24 × gain / 128 = ⭐ Σenv × gain
⇒ 该值 = √N × 0.5 × 2^23
```

| N | gain=64/√N | 限幅器看到（满包络） | 占满幅 | 越过 87.5% 软膝 |
|---|---|---|---|---|
| 1 | 64 | 4.19e6 | 50% | 否 |
| 2 | 45 | 5.90e6 | 70% | 否 |
| **3** | **37** | **7.27e6** | **86.7%** | ⭐ **正好踩线** |
| **4** | 32 | 8.39e6 | **100%** | ⭐ **超** |
| 8 | 23 | 1.21e7 | 144% | 严重超 |

⇒ 与用户"**3 个及以上**出现"完全吻合；高持续比音色（BASS 0.70 / PAD 0.90）`Σenv` 更大 ⇒ **先踩线** ⇒ 只有这两个 ✅

## 二、⭐ 为什么"修法 1（降限幅裕量）"**本来就是错的**

`L397` 注释：`over_pos`/`over_neg` 的声明**移到归一化与限幅之后** ⇒ 软限幅看的是

## 四、⚠️ 失败现象（**未解决**）

`tb_tdm_render_mixer` **红 2 项**（其余 3 个测试台全绿、无编译错误）：

```
FAIL: 2-lane 1000/2000 @env 0x8000 => 91904 (weighted (9L0+7L1)>>4, gain=64)
FAIL: min input clamps to soft-knee ceiling -0x780000 (not wrap)
[sv] 2-lane 1000/2000 @env0xFFFF => 183808
```

**关键矛盾**：`env 0x8000` + **单声部** 时 `Σenv = 32768` ⇒ `n_eff = 0`
⇒ `gain_lin_lut(0) = 128` ⇒ `min(64,128) = 64` ⇒ **应当与旧值完全相同（91904）**
🔴 但它红了 ⇒ **说明 `n_eff_r` 的取值有问题**，最可能是：

> **`n_eff_r` 在 `render_start_i` 锁存【上一帧】的 Σenv ⇒ 有 1 帧滞后。**
> 而 tb 的**每个用例只跑一帧** ⇒ 它读到的是**上一个用例残留的值**（例如前面某个大 `Σenv` 的用例）
> ⇒ 增益被错误压低 ⇒ 值不对。

（注意：`n_active_r` 也是同样在 `render_start_i` 锁存，但 tb 的期望值是**按它的滞后语义**写的，
所以它不红；`n_eff_r` 是我新加的，tb 的绝对期望值没考虑它。）
