# 右手板拨弦"指板模式没声音" —— 诊断结论（2026-10-04）

> 用户 2026-10-04 决定：**不再深挖，收在"这是板子（硬件/接线）的问题"**。
> 本文件把**已证明 / 未证明**精确记录下来，避免以后被当成 RTL 问题返工。

## 一、用户实测数据（万用表，黑笔接 AGND）

| 动作 | `pluck_up_i`（**E21**） | `pluck_down_i`（**D21**） |
|---|---|---|
| 静止（回中） | **0 V** | **0 V** |
| **往前推**（保持） | **0 V** | ⭐ **3.3 V** |
| **往后推**（保持） | **0 V** | **0 V** |

## 二、⭐ 由此**已证明**的三件事

1. **极性是对的** —— 空闲 = 0、触发 = 3.3 V ⇒ 满足 RTL 的期望
   （`rtl/w3a/async_pluck_capture.v` 只在 **0→1 上升沿**产生 pluck）。
   ⚠️ 这条**推翻**了此前"LM393 开漏 ⇒ 空闲为高 ⇒ 极性反"的猜测。
2. **`pluck_up_i`（E21）永远不触发** ⇒ **UP 那一路没有有效信号**。
3. **`pluck_down_i`（D21）响应的是"往前推"** ⇒ **前推/后推与 UP/DOWN 的对应关系错位**。

## 三、由此**完全解释**了上板症状

| 用户动作 | 实际信号 | RTL 看到 | 结果 |
|---|---|---|---|
| 往前拨 | `DOWN`: 0→1 | 上升沿 | ✅ 响一下 |
| 自己回正 | `DOWN`: 1→0，**回弹过冲**可能再来一次 0→1 | 又一次上升沿 | ✅ 又响一下 |
| 往后拨 | **两路都不动** | 无边沿 | ❌ **不响** |

（文档要求比较器加"正反馈迟滞"就是为了抑制回弹过冲造成的这种二次触发）

## 四、⭐ 结论与边界（**重要**）

**已证明**：故障在 **FPGA 引脚之外**（信号本身就不符合设计意图），
⇒ **不是 RTL 的问题**，⛔ 不要去改 `play_mode_ctrl` / `async_pluck_capture` / `top.v` 的拨弦逻辑。

**尚未定位到**（用户决定不再深挖，留给硬件侧）：
- 到底是 **① 排线把两路接反了**（`TRIG_1` 座的 UP/DN 与比较器 1/7 脚交叉），
- 还是 **② 摇杆电位器极性与比较器通道分配相反**，
- 还是 **③ UP 侧阈值被调出可达范围**（外加"DOWN 一路前推就触发"的错位）。
⇒ 这三者的修法不同（改排线 / 对调比较器 +− 输入 / 重调阈值），
   若将来要修，**先用"直接量 `LM393` 的 1 脚与 7 脚"来区分**（方法见下）。

## 五、留给硬件侧的最小复现步骤（将来要修时照做）

1. **测点 C（关键）**：黑笔接 `AGND`，直接量 `LM393DR`（SOIC-8）的 **1 脚 / 7 脚**输出，
   重做"静止 / 前推保持 / 后推保持"。
   - 若 **1 脚**在前推时变 3.3、而 `TRIG_1` 座的 **DOWN** 变 3.3 ⇒ **排线交叉**（改排线即可）
   - 若 **7 脚**在前推时变 3.3、而 `TRIG_1` 座的 **DOWN** 变 3.3 ⇒ 接线是对的
     ⇒ 是**电位器极性 / 阈值分配**问题（对调比较器 `+`/`−` 或重调阈值）
2. **测点 A**：摇杆电位器滑动端对 `AGND` 的电压（静止 / 前推 / 后推）⇒ 看极性是否与比较器分配一致
3. **测点 B**：两个 `3296W` 阈值分压的滑动端电压 ⇒ 确认 UP 侧阈值没有超出可达量程

## 六、RTL 侧**不需要**做的事（⛔ 避免误改）

- ⛔ 不要给 `pluck_up_i`/`pluck_down_i` 加取反（极性实测是对的）
- ⛔ 不要改 `play_mode_ctrl` 的 `selected_valid` 逻辑（那是"必须先选音再拨弦"的设计语义）
- ⛔ 不要放宽 `REFRACT_CYC`（30 ms 不应期不是本次症状的原因）
- ✅ 若将来硬件修好，只需按原设计上板复验：**按住一个键 + 拨弦 ⇒ 出声**；
  **松手后拨弦 ⇒ 不出声**（这是指板模式的正确语义）
