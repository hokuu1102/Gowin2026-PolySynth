## 为什么做 A

用户实测：**换了 C 之后仍有"收音机滋滋声"，但"按完之后 1-2 秒才出现"**。

⭐ 量化原因：`115/n` 在 **N=3 时根本不生效**：

```
gain = min( gain_sqrt(3)=37 , gain_lin(3)=115/3=38 ) = 37
⇒ 输出 = Σenv × gain = 196605 × 37 = 7.27e6 = 86.7% 满幅
⇒ 软膝在 87.5% ⇒ 余量只剩 1%
⇒ 任何扰动（多一声部 / 包络一帧抖动 / 节拍器敲一下）都越界 ⇒ 软限幅持续咬住
```

改成 `100/n`：

| N | gain_sqrt | gain_lin(100/n) | 取 min | 限幅器看到 | 占满幅 |
|---|---|---|---|---|---|
| 1 | 64 | 100 | **64** | 4.19e6 | 50%（**不变**） |
| 2 | 45 | 50 | **45** | 5.90e6 | 70%（**不变**） |
| **3** | 37 | **33** | **33** | 6.49e6 | **77.4%**（原 86.7%） |
| **4** | 32 | **25** | 25 | 6.55e6（实测 6553300） | **78%** |
| 32 | 11 | 3 | 3 | 6.29e6 | 75% |

⇒ ⭐ **单音/双音完全不变**（用户硬要求满足 ✅）；N≥3 的电平从 86.7% 降到 **77%**，**余量 1% → 12%** ✅

## ⚠️ 一个必须写明的架构取舍

```
gain = 64/√N 在设计上就把 N=3 顶到 86.7%（软膝 87.5%）
⇒ 【保住 N=3 响度】与【N=3 有余量】在当前架构下【不可兼得】
⇒ A 方案选择【余量优先】：N=3 响度降 ~11%（37→33），换来 12% 余量
```

## tb 契约重述（**不是放宽容差**）

原判据 `3 voices => ~1.73x [power norm]` 断言的是 **√N 响度律** —— 而 A 方案
**故意**用 N=3 的响度换余量。改为断言**新意图**：

```systemverilog
chk("3 voices: bounded below 80% FS (headroom-first; sqrt3 law relaxed by design)",
    (sN > 0) && (sN < 24'sd6710886) && (sN > s2));
```

⭐ **同时保留、一条都没放宽**的三条：单调增 · 绝不是 3× · 不削顶（signed24 内）
📌 N=2 的 `~1.42x (√2)` 判据**保持原样**（电平项在 N=2 不生效）✅
