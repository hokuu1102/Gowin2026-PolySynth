## 改了什么（`rtl/w3b/tdm_render_mixer.v`）

1. **累加 Σenv**：在 TDM 遍历里与 `acc_r <= acc_r + prod_r` **同拍**累加
   `acc_env_r <= acc_env_r + env_s_r`（⛔ 零额外加法树；模块一帧 1024 拍只用 ~34 拍）
2. ⭐ **门控**：`env_gated = voice_active_i[cnt_sel] ? env_s : 0`
   —— ⚠️ **必须门控**：未在发声的 voice 其 `env_level` 可能残留非零，全累加会把 Σenv 抬大
3. **增益取较小**：`norm_gain_target = min(gain_sqrt_lut(n_active_r), gain_lin_lut(n_eff))`，
   `n_eff = acc_env_r[ACC_ENV_W-1:ENV_W]`，新增 33 项 `gain_lin_lut`（≈`108/n_eff`，⛔ 无除法器）

## 为什么这样能治（量化）

```
gain(N) = 64/√N ⇒ 限幅器看到 = Σenv × gain = √N × 0.5 × 2^23
```

|---|---|---|---|---|---|---|

## ⚠️ 调试记录（避免下次再踩）

**第一版用 `n_eff_r` 寄存器在帧边界锁存 ⇒ 读到【上一个用例残留的值】**
（实测 `n_eff_r=31` ⇒ `gain_lin_lut(31)=3` ⇒ 增益塌到 3 ⇒ tb 红 2 项）。
✅ **改为直接取本帧累加完的 `acc_env_r` 高位** —— 与 `acc_r` 同源同帧，**不可能串扰**。
📌 教训：**帧级控制量不要"再寄存一拍"**，否则单帧用例（tb）会读到串扰值；
   要滞后就必须像 `n_active_r` 那样**在 tb 里也按滞后语义写期望值**。

⇒ 比原来**更强**（同时守住符号与上限），且保留测试台注释里「**核心风险是回绕**」的原意。
