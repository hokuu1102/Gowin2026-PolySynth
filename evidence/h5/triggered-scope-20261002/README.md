# H5 波形显示："两条线"根因定位与修复（2026-10-02）

## 现象
上板后，按音时肉眼可见**两条绿色波形**（一亮一暗、横向错开），静音时只剩中心线。

## 根因（离线 dump 定位，非推测）
用 `tb_scope_dump.v` 给 `waveform_scope` 灌已知正弦（523.25 Hz，采样率 50 MHz/1024
= 48828.125 Hz），把整帧 640×480 的 RGB 逐像素 dump 成 PPM，再统计每列绿色段数与帧间位移。

**修复前的实测**：
- 每帧：**640/640 列各恰好 1 段绿**，>1 段的列 = 0 ⇒ **RTL 一帧只画一条波形**（不是渲染 bug）
- 但相邻两帧：**最佳横向位移 = −260 px（rms 0.9）**，不对齐时 640 列里只有 **1 列**相同
  ⇒ 相邻帧的波形横向错开约 **2.8 个音频周期**

**机制**：显示窗口 = 640 采样 = **13.107 ms**，而帧周期 = **16.683 ms**
⇒ 每帧窗口前进 3.559 ms ≈ **1.86 个周期** ⇒ 波形每帧横向"跳"约 260 列。
音频与视频不同源，快照起点固定在 vblank，因此相位每帧都不同；
LCD 像素响应 + 相机曝光不会瞬间清掉上一帧 ⇒ **上一帧的残影 = 第二条线**。

⇒ **不是故障，是"未触发示波器"的经典现象**。

## 修复：音频触发窗口（真正的示波器行为）
`rtl/hdmi/waveform_scope.v` 的快照逻辑改为：
1. 拷贝前先扫描环形缓冲尾部（从 `wr_seen-960` 起，最多 320 个采样），找**第一个上升过零点**；
2. 从该采样开始填充 `frame_y[0..639]` ⇒ 每帧波形的**起始相位一致**；
3. 找不到过零（静音 / 直流）时回退到最新的合法窗口起点 `wr_seen-640`（与旧行为一致）；
4. ⚠️ 扫描前两拍不判定（读流水线深度导致会与上一窗口的残留采样比较 ⇒ 假触发；
   实测该 bug 会让位移从 −260 只降到 −216）。

拷贝预算：≤320 扫描 + 640 填充 = 960 像素时钟 = 38 µs，起始于第一个消隐行（y=480），
消隐期 45 行 = 1.43 ms；最旧读取落后写指针 960 个采样（环形 1024）⇒ 时序与内容都安全。

## 修复后的实测（同一套 dump 工具）
| 指标 | 修复前 | 修复后 |
|---|---|---|
| 每帧绿色段数 | 640/640 列各 1 段 | 640/640 列各 1 段（不变，仍是一条） |
| 两帧 \|dy\| ≤ 1 px 的列 | 2 / 640 | **360 / 640** |
| 两帧 \|dy\| ≤ 2 px 的列 | — | ⭐ **640 / 640（100%）** |
| 两帧 \|dy\| > 10 px 的列 | 大量（最大约 180 px） | **0** |
| 平均 \|dy\| | 巨大 | **1.13 px**（采样格点量化极限） |

窗口起点样本值（相位）：copy1 = 157672、copy2 = 187300、copy3 = 15104
⇒ 折合相位误差 ≤ **0.7 个采样**（旧版是 2.8 个整周期）。

⇒ 残影现在**正好叠在波形上** ⇒ 上板应看到**一条干净的线**。

## 测试台更新
`tb/hdmi/tb_waveform_scope.sv`：
- 参考模型改为**触发窗口**（扫描 + 回退，与 RTL 同规则）
- 新增**独立不变量**：窗口首样本必须是上升过零点（找不到过零时走回退，不计入）
- 结果：6 个激励模式全帧逐像素通过；`PASS: triggered window started on a rising zero
  crossing in 4 snapshots`；`PASS: waveform_scope 2308886 pixel checks`
