# 波形"像素风"根因与修法（2026-10-09 诊断，⛔ 未落地）

## 一、根因（已精确量化，✅ 可信）

`rtl/hdmi/waveform_scope.v` 的 `sample_y()`：

```verilog
x6 = $signed({s[23:16], 2'b00}) + $signed({s[23:16], 1'b0});   // = 6 × s[23:16]
y_calc = 240 - x6;
```

`s[23:16]` 的 **1 个 LSB = 65536**，被乘 6 ⇒ ⭐ **输入每变 1 LSB，y 就跳 6 个像素**。

| 分度 | 1 LSB → y 台阶 | 观感 |
|---|---|---|
| ×1（P0-18） | 1 px | 平滑 |
| ×2 | 2 px | 略毛 |
| ×4 | 4 px | 有台阶 |
| **×6（当前）** | ⭐ **6 px** | ⭐ **明显像素风** |

⇒ 用户照片里的"像素风"就是这个 6 像素量化台阶。

## 二、修法（设计正确，但本次未落地）

**思路**：乘法前多留 3 位小数 ⇒ 台阶 6px → **0.75px**，尺寸完全不变。

```verilog
// 声明加宽到 14 位
reg signed [13:0] x6;
// x = $signed(s[23:13])（1 LSB = 8192）；6x 后 >>>3
x6 = ($signed({s[23], s[23:13], 2'b00}) + $signed({s[23], s[23:13], 1'b0})) >>> 3;
y_calc = 11'sd240 - x6;
```

### ⭐ 关键坑（本次踩到并已定位）

```
s[23:13] 最大 = 1023；6 × 1023 = 6138
而 Verilog 里 `$signed(13位) + $signed(12位)` 的结果只有【13 位】
13 位有符号范围 = −4096 … +4095  ⇒  6138 溢出回绕 ❌
⇒ 满幅正样本被算成负偏转 ⇒ 波形在极值处上下翻转
```
✅ **修法**：显式补符号位，把加法做到 **14 位**（如上式 `{s[23], s[23:13], 2'b00}`）。

## 三、⛔ 未落地的原因（诚实记录）

`tb/hdmi/tb_waveform_scope.sv` 里有一个**逐像素的期望图像模型**（`map_y()`）。
本次把它同步为"逐位等价"版本（含 11 位切片、14 位加法、floor 语义），**仍然在 mode=2（正弦）的
第 (50,253) 像素处不一致**（RTL 黑、模型绿）。

⇒ **未解决**。可能原因（下轮先查）：
1. 模型对 `frame_y` 快照时序的建模与 RTL 有细微差异（`copy_valid_q` / `snapshot` 的边界）
2. `s[23:13]` 在**负样本**上的切片语义与模型的 `floor` 不完全一致（需逐值对照）
3. 模型的 `image[]` 与 RTL 的 `frame_y[]` 在**环形缓冲回绕**处的索引不同

## 四、⭐ 下轮建议：**换一个更省力的验证方式**

与其继续对齐那个"整幅图像模型"，不如**加一条针对性判据**直接量量化台阶：

```
喂两个只差 1 LSB 的样本（如 0x100000 与 0x100001）到 sample_y()
⇒ 断言两次 y 的差 ≤ 1（⛔ 不是 6）
⇒ 红检：把分度改回 ×6（÷65536 那版）⇒ 这个差变成 6 ⇒ 必红（证明非空洞）
```
⇒ 这条判据**只测量化台阶本身**，⛔ 不需要整幅图像模型 ⇒ 便宜得多、也更直接命中用户看到的症状。
