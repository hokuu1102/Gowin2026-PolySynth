## 一、 审查说的对不对 ⇒  **对，已逐行核实**

 审查原文：*"全模块没有任何 `seen <= 0` 的帧边界清零 ⇒ 某轴一旦收到过一个样本，该位永久为 1"*

 **实测（ 机械核对，⛔ 不是读注释）**： `rtl/w3a/axis_snapshot.v` 里 `seen` 的**全部写点**只有两处 ：

|  行 |  代码 |  语义 |
|---|---|---|
|  `:138` |  `seen <= {AXIS_N{1'b0}};` |  **只在复位分支**  |
|  `:149` |  `seen[di*8 + sample_ch_i] <= 1'b1;` |  **只置位**  |

 全文 **没有任何第三处写点**  ⇒  **没有帧边界清零**  ⇒  `seen` 是**单调 sticky 位图**（ 复位后只会 0→1）

📌  **所以 `:66` 的端口注释与实现直接矛盾** ：

```verilog
output wire [AXIS_N-1:0] axis_seen_o   //  本帧收到过哪些轴（诊断）
```

 而实际语义是  **"自复位以来【曾经】收到过哪些轴"**  ——  **"本帧"两个字是错的**

 而 `adc_partial_w`  **OR 进 `fault_any_w`**  ⇒  **心跳灯快闪**
（ 即本周期 `as_seen` 那条可观测性修复  ——  见 `交接文档-20261011.md` §五-1 ）

###  于是产生**两个后果**（ 一个比一个要命 ）

|  # |  后果 |  为什么重要 |
|---|---|---|
|  **①** |  `adc_partial_w` **一旦置位就【永久】置位**  |  因为 `as_seen` 单调 ⇒  **某一片在某一瞬间掉过一次**（ 例如上电抖动 ）， 之后哪怕**完全恢复正常**， 这个故障位**也再不清零**  |
|  🔴 **②** |  它**无法回答它唯一想回答的问题**  |  用户上板要查的是" **现在**哪个键不响"  ——  而 sticky 位图**答不了**（ 它只说"历史上见过" ） |

🔴   **② 直接冲击上板验证清单** ：

 📄 `files/20-代码/上板验证清单-20261013.md` §〇 写的是 ：

>  *"灯闪 + **某个键不响** ⇒ **有轴从来没被采到**（`as_seen != 全 1`）"*

**实测语义与这句话不符** ：
-  **"有轴从来没被采到"** ⇒  与 sticky **一致** （ 这句对 ）
-  但  **"现在某个键不响"** ⇒  sticky **答不了**  ——  它可能只是**开机抖动**留下的历史痕迹

⇒   **不修的话**： 上板时**心跳灯快闪可能是个假警**（ 历史抖动 ），
 而**真正的"某个键现在不响"反而被淹没**（ 反正灯早就闪着了 ）

## 三、 修法（ 零面积  ·  单一写点重构 ）

 审查给的改法（ `:3290-3307`）**方向对**， 但需要**按真实帧边界**定 ：

 本模块**已有**一个权威帧边界信号  ——  `first_ch_of_frame`（ `:154-160` ）：
-  `frame_done_i` ⇒  置 1 （ 下一帧的 `ch0` 即将到来 ）
-  收到 `ch0` ⇒  清 0

⇒  **新帧的第一个样本 = `sample_valid_i && (sample_ch_i == 3'd0) && first_ch_of_frame`**
**这与 `:178` 固化 `prev` 用的是【同一个条件】**  ⇒  **天然同步，⛔ 不引入新的时序契约**

###  实现（ 合并成**单一写点** ）

```verilog
//  先算本拍命中的轴掩码（组合）
reg [AXIS_N-1:0] seen_mask_w;
integer mi;
always @(*) begin
    seen_mask_w = {AXIS_N{1'b0}};
    for (mi = 0; mi < N_ADC; mi = mi + 1)
        if ((mi * 8 + sample_ch_i) < AXIS_N)
            seen_mask_w[mi*8 + sample_ch_i] = 1'b1;
end

//  `seen` 的唯一写点：帧首清零、其余帧内累加
always @(posedge clk) begin
    if (!rst_n) seen <= {AXIS_N{1'b0}};
    else if (sample_valid_i) begin
        if (sample_valid_i && (sample_ch_i == 3'd0) && first_ch_of_frame)
            seen <= seen_mask_w;          //  本帧第一个样本 ⇒ 从空开始
        else
            seen <= seen | seen_mask_w;   //  帧内累加
    end
end
```

 且把 `:149` 那行**从原 `always` 里删掉**（ 否则两个写点 ⇒  后写的赢， 语义又乱了 ）

**必须同时改 `:66` 的端口注释【或】保留 sticky 语义并改消费端**  ——
 **两条路都可选， 必须先裁定** （ 见 §四 ）

## 四、 需要**用户裁定**的一处（ 因为两条路的**上板行为不同** ）

|  路线 |  语义 |  上板看到什么 |  代价 |
|---|---|---|---|
|  **A · 改成真"本帧"**  |  `axis_seen_o` =  **本帧**收到过哪些轴 |  灯闪 =  **现在**有轴掉 （ 自愈 ） |  1 个掩码 +  单一写点（ **零面积** ） |

2.  `adc_partial_w` 的**设计意图**就是" 有轴掉线" （ 交接文档 §五-1 明说" 免上电假警"）
   ⇒  **"自愈"正是它想要的**  ——  而 sticky 让"免上电假警"**只做了一半**
3.  A **零面积** （ 符合" 先不动 `CLS`"）

## 七、 合并后的重新评估（ 2026-10-13 合入 `origin/main` `7ef73f4` 之后 ）

###  1.  **本条的【核心缺陷】依然成立**  ——  而且**队友自己也确认了**

🔴  队友的验收文档  `files/20-代码/队友提交合并验收-20261013.md` §3 **结尾原话** ：
>  *"  **该位图仍是累计 seen 语义，不能单独检测运行中所有种类的后续丢样** "*

⇒   **这是【独立来源】的确认**  ——  他们修的是**上电假警** ，
**没有修"位图是累计的"这件事** （ 也没打算修 ）

###  2.  于是缺陷从"假警"变成了"**假警已修、 但漏报还在**"

 合并后的 `adc_partial_w = adc_scan_done_pipe[3] && (as_seen != 16'hFFFF)`
⇒  **两类行为** ：

|  场景 |  `as_seen` |  告警 |  对不对 |
|---|---|---|---|
|  上电、 全部 16 轴都采到过  |  `FFFF` |  不报  |  **对**（ 队友修好的 ） |
|  某轴**从来没被采到**（ 排线松 /  没上电 ） |  缺一位 |  **报**  |  **对**（ 这正是设计意图 ） |
| 🔴  **某轴先正常、 运行中掉线**（ 排线半断 /  芯片过热 ） |  **仍是 `FFFF`**（ 那位早就置上了 ） | 🔴  **不报**  | 🔴  **错 —— 漏报**  |

⇒   **第三行就是 P1-55 的实质** ：
 **它检测不了"曾经好的轴后来坏了"**  ——  而**这恰恰是上板调音时最需要知道的事**
（ 症状： **弹着弹着某个键不响了， 但心跳灯正常** 🔴 ）

###  3.  所以上板清单要**补一句**（ 重要 ）

 📄 `files/20-代码/上板验证清单-20261013.md` §〇 现在写的是 ：
>  *" 灯闪 +  **某个键不响** ⇒  **有轴从来没被采到**"*

**这句是对的， 但要补一条反向的** ：

>   **灯不闪 ⛔ 不等于所有轴都健康**  ——
>  `as_seen` 是**累计**位图 ⇒  **某轴先好后坏， 灯不会闪** 🔴
>  **所以"弹着弹着某键不响"必须【单独排查】**（ 排线 /  该片供电 /  SPI ），
>  ⛔ **不能靠心跳灯排除**

📌  **这一条的价值**： 它**防止上板时把"漏报"误读成"没问题"**  ——  那会浪费一整轮
