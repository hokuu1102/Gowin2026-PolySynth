## 一、先搞清楚"到底哪里不滑"

### 1.1 对照实验（真实 `top.v`，不是复刻）

写 `tb/top/tb_slide_e2e.sv`：例化**整个 `top`**，用 `mcp3208_model` 从机注入真实按键行程，
读 `note_manager` 里那个 voice 的 `phase_r`。**同一段手势跑两遍，只改一个变量 `am_mode`**：

```
A) am_mode = 0（交付默认：钢琴）
   [A] slide pulses = 1 (ax=6 b=7)               ← 探测器正确触发物理相邻对
   [A] phase before = 00ba039d  after = 00ba039d ← 音高【一动不动】
B) am_mode = 1（指板门打开）
   [B] phase before = 00ba039d  after = 00d0cb35   (fb_inc[7]=00d0cb35)
   ok : B4: 精确落到 B 轴的音高                    ← 【一位不差】
```

**结论**：滑音整链（探测 → 查表 → `pitch_upd` → `note_manager` 写入）**本来就是通的**。
真凶是**模式门**：

```
rtl/top.v  uart_ui 例化:  .MODE_PIANO_DEFAULT(1)          ← 交付默认 = 钢琴
rtl/top.v:1047  play_fretboard_mode = ~ui_mode_piano       → 0
rtl/top.v:4059  am_mode <= play_fretboard_mode             → am_mode = 0
rtl/top.v        pitch_upd_valid_i (... | (ee_slide_v & am_mode))
                                          └────── 恒 0 ──────┘
```

### 1.2 第二个问题：它是"跳"不是"滑"

`pitch_upd_value_i = am_inc_b` ⇒ **一步**把 A 的音高设成 B。
实测 `00ba039d` **直接跳到** `00d0cb35`，中间没有任何过渡帧。

## 二、真滑音的实现

### 2.1 为什么用"指数逼近"而不是线性插值

```
cur <= cur + ((target - cur) >>> SHIFT)
```

* 误差按 `(1 - 2^-SHIFT)` 衰减 ⇒ **相位增量上是指数**
* 而 `phase_inc ∝ 频率` ⇒ **音高近似【线性】滑动**
* 这正是人耳要的"圆润、自然"；**线性插值相位增量反而会"先慢后快/发飘"**（人耳听的是对数频率）

### 2.2 为什么它便宜（**这是之前两次失败的关键**）

| | 之前失败的猜测 | **实测结论** |
|---|---|---|
| 那 +287 LUT 是什么 | 以为是"斜坡本身" | 🔴 **是"第二查表口读两套表 ＋ mode mux"**（4 个 16 选 1） |
| 现在第二口 | — | ✅ **只读 `fb_inc`**（2 个 16 选 1）⇒ **斜坡只剩移位＋加减＋比较** |
| 斜坡代价 | — | ✅ **~70 FF ＋ ~100 LUT**，⛔ **不用乘法器** |
| 为什么能这么便宜 | — | ✅ **全局单引擎**（同一时刻只有一个音在滑） |

> ⚠️ 资源摊独立确认：「若给每路加 32 位饱和步进器 ⇒ **32 × ~34 ALU ≈ 1088 ALU
> ≈ 270~410 CLS** ⇒ **这正是两次被 CLS 挡住的量级**」
> ⇒ ⭐ **单引擎比 32 路并联便宜两个数量级**。
> 📌 而 `Register` 只用了 **31%（18,518 / 60,780）** ⇒ **FF 是唯一真正便宜的货币**。

### 2.3 判据（`tb/w3a/tb_slide_ramp.sv`，全绿）

```
[glide] steps recorded = 84   first=00c51339 second=00c5ceb8 final=00d0cb35
                              ↑ A 的音高      ↑ 第一小步      ↑ 精确落位
[glide] up=83 down=0 flat=0   ← 全程单调，一步不回头
PASS
```

覆盖：不滑时不动 · 第一小步不是跳 · 步数够多 · **精确落位** · 单调 · 下行对称 ·
**中途改目标从当前位置接着滑** · 小于 EPS 立即吸附（不会永久微分抖）。

### 2.4 时长旋钮

| `SHIFT` | 实测步数 | 时长（帧周期 500 µs） |
|---|---|---|
| 3 | 42 | ≈ 21 ms |
| **4（交付默认）** | **84** | **≈ 42 ms** |
| 5 | ~165 | ≈ 82 ms |

⚠️ **一个参数就是时长**，⛔ 不用动任何结构。

## 三、中途退回（用户规格"停在当前位置"）

**判据 5 抓到一个真 bug**：原实现每次 `trig_i` 都 `cur_r <= start_i` ⇒
⚠️ 手指退回时音高会**先跳回起点再滑**。

✅ 修法：**只有首次起滑才用 `start_i` 复位当前值**；已经在滑时，`trig_i` **只改目标**：

```verilog
end else if (trig_i) begin
    tgt_r <= target_i;                 // 目标总是更新
    if (!active_o) begin               // 🔴 只有首次才取起点
        cur_r <= start_i;
        value_o <= start_i;
        steps_o <= 16'd0;
    end
    active_o <= 1'b1;
end
```

## 四、模式切换（滑音能用的**前提**）

交付默认 `MODE_PIANO_DEFAULT = 1`（钢琴）⇒ `am_mode = 0` ⇒ 滑音项恒 0。
以前**只有屏**能切（触摸控件 0）⇒ **没屏就没法用滑音**。

✅ 新增串口 **`'A'`** 命令（`calib_cmd` 第 23 条）→ `uart_ui.mode_sw_req_i`，
**与屏触摸控件 0 完全同语义**（翻转 + 提交脉冲）⇒ **脱离屏可切**。

📌 代码里那条注释解释了为什么默认是钢琴：

> *"原来硬编码默认指板 ⇒ 上板**按了没声音**（指板模式要等 P4 的 LM393 拨弦比较器，
> 不接就永远不触发）"*

## 五、上板怎么验（三步）

| 步 | 做什么 | 判据 |
|---|---|---|
| 1 | 发串口 **`'A'`** 切到**指板模式** | `am_mode` 变 1 |
| 2 | 发串口 **`'W'`** 打开滑音（**默认关**） | 回包 `'w'` |
| 3 | 手指从一根弦**横滑**到**物理相邻**的弦 | 音高**连续滑过去**（不是跳），**力度不变** |

⚠️ 三个必知限制：
1. **必须物理相邻**（上排 `6-7-0-1`、下排 `5-4-3-2`；⛔ 轴号相邻不算）
2. 力度取 **A**（手指最初按下的那根弦）
3. 指板模式的**起音要等拨弦比较器**（LM393）⇒ 没接就永远不触发

### 6.1 为什么这次没炸（**关键结论**）

> 🔴 **之前那 +287 `CLS` 根本不是斜坡** ——
> 是「**第二查表口读两套表 ＋ mode mux**」（4 个 16 选 1）。
> 现在第二口**只读 `fb_inc`**（2 个 16 选 1），
> 而斜坡是**全局单引擎、不用乘法器** ⇒ **几乎免费**。

⚠️ 资源摊独立佐证：「若给每路加 32 位饱和步进器 ⇒ **32 × ~34 ALU ≈ 1088 ALU
≈ 270~410 CLS** ⇒ **那才是两次被挡住的量级**」
⇒ ⭐ **单引擎比 32 路并联便宜两个数量级**，这与实测的 **+6 CLS** 完全吻合。

## 八、测试加速（⭐ 值得复用）

端到端 tb 原本要 **~11 分钟**，因为 ADC 帧周期是 **500 µs = 25,000 拍**，
而测试要等 30 帧/遍 × 2 遍 = **150 万拍**。

✅ **`defparam` 从外部覆盖 `adc_farm` 的帧率**（⛔ 不改 RTL 一个字节）：

```verilog
defparam u_top.g_sound.u_adc_farm.CHANNEL_RATE_HZ = 20_000;   // 2 kHz → 20 kHz
defparam u_top.g_sound.u_adc_farm.SCLK_HZ         = 10_000_000;
```

帧周期 500 µs → **50 µs**；实测 **11 分钟 → 69 秒（10×）**。

📌 **为什么对判据毫无影响**：⭐ 斜坡是"**每帧走一步**"，
⭐ 帧变快只是让每步的**真实时间**变短 ⇒ **步数、单调性、落点全不变**。
⚠️ `SCLK_HZ` 必须一起抬，否则帧周期会短于 SPI 扫描时间（16 通道 × 16 位 = 256 SCLK）。
