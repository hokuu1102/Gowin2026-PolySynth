## 六、⭐⭐ 事件代码速查（逐个粘进对应事件页）

### ⭐⭐ 6.0-前 · 交互模型总则（先读这个，防走弯路）

> ⭐ 2026-10-30 补：很容易误以为"点按钮后要把所有变化写进按钮事件里"——**⛔ 不用**。
> 正确模型三句话：**屏只管发，FPGA 只管算，回显帧管显示**。

| 角色 | 职责 | 体现在哪 |
|---|---|---|
| **屏端事件** | 只写**一行 printh**：把手指动作翻译成一帧发给 FPGA 的报文 | §六各事件 |
| **FPGA** | 收帧 → 改内部状态 → **回发显示帧**：点名 objname 写控件属性（`.txt=` 文字 / `.val=` 数值 / `.bco=`/`.pco=` 颜色） | `uart_ui.v` 回显 FSM（47 字段） |
| **屏固件** | 收到回显帧 → **自动**改对应控件的显示。屏上没有任何"当前状态"变量 | 无需写代码 |

举例（点 b_timbre 切音色的完整闭环）：

```
点按钮 → 屏只发一帧 65 00 03（屏自己什么都不改）
→ FPGA 收到，切 timbre_sel_r，回发 t_timbre.txt="GUITAR"
→ 屏固件按 objname 找到控件、写 .txt 属性 → 大字自动从 BASS 变 GUITAR
```

⛔ **不要在按钮事件里写** `if(timbre==...) t_timbre.txt=...` 这类记账逻辑——状态源在 FPGA，
屏自己记账必然与 FPGA 失步。上位机里填的默认文字只是**上电初始值**，运行时由 FPGA 回显覆盖。

**仅有的三类屏端本地代码**（合法，与 FPGA 状态无关）：
1. **切页**：`page page1` / `page page0`
2. **心跳闪烁**：tm0/tm1 定时器翻圆点图（见下）
3. **后初始化**：切页回来发 `printh 88` 触发 FPGA 全量重发（见下）

**与队友 v2 定稿的有意差异（保留，均为已落地口径）**：
- **串口速率**：v2 写 500K → 本工程 **115200**（板载口 2026-10-28 改）
- **t_base**：v2 原案直接做成按钮 → v3 用**文本 + 叠放 b_oct 小按钮**（回显文字与按钮文案分离、互不覆盖）
- **page1 头部开关**：v2 写 TJC 原生自动帧（`65 01 02 01 …`）→ v3 用 **`71 19 <bit>` 翻转帧**（RTL 解析口径）

### 心跳闪烁（page0）

**tm0**（定时器，tim=500，en=1）事件：
```
if(p_hb.val==0)
{
  p_hb.val=1
}else
{
  p_hb.val=0
}
```

**tm1**（定时器，tim=1500，en=1）事件：
```
tm0.en=1
```

> 运行逻辑：FPGA 每秒发 `tm1.tim=1500` 持续复位 tm1 倒计时 ⇒ 联机时 tm1 永不超时；断联 ≤1.5s 后 tm1 超时 → `tm0.en=1` → 圆点闪。
> ⚠️ p_hb 是**双态按钮**（⛔ 不是图片控件，没有 `.pic` 属性）：sta=图片、pic=0/pic2=1，代码只翻 `.val`。

### ⭐ page0 / page1 后初始化事件（切页返回刷新，⭐ 两页都要加）

```
printh 88 FF FF FF
```

> **为什么要加**：切页期间 FPGA 发的本页更新帧会被屏丢弃（页私有）⇒ 返回显示旧值。
> 0x88 **每次收到都全量重发 47 帧**（2026-10-29 RTL）⇒ 每次回到该页自动拿最新全量
> （page1 的仪表 / 文本 / cur / gr 也一并刷新）。

> ⚠️ 按钮还要单独检查属性面板的 **font（字库）选了哪一档**（按钮统一选 ② 16px 那档）。

### 7.2 🔴 特殊符号（⛔ 不加必显示方块）

```
● ➔ ⬅ ★ ► ─ · ↕
```

> ⚠️ **按钮文案只用上表 + ASCII 里的字符**：`−1` 必须写成 ASCII `-1`（⛔ U+2212 不在集），
> `▶播` 必须写 `►播`（⛔ U+25B6 不在集，集里是 ► U+25BA）。

### 7.3 ASCII

字库工具勾选完整 ASCII（数字/字母/括号/百分号/冒号/方括号等全用到了）。

> ⭐ 生成步骤：工具 → 字库制作 → 编码 🔴 **UTF-8** → 字号选一档 → 粘贴 §7.1+§7.2 字符 → 生成。6 档字号各生成一次。
> ⚠️ 下载工程时**字库必须随工程一起下屏**，否则中文/符号全部方块。

## 八、⚠️ 已知边界与后续工作

### 1. z_pd / z_vd 两页重名（合法但要懂行为）

控件页私有，两页各有一个 `z_pd` 不冲突；但 FPGA 帧只作用于**当前显示页**的那个。page1 的 z_pd（深度旋钮）与 page0 的 z_pd（监视弧）是同一物理量，联机时在哪页哪页活。

| 状态 | 背景 bco | 前景 pco |
|---|---|---|
| 空闲 | 63455（浅灰） | 9509（深字） |
| 录音 | 52517（红） | 65535（反白） |
| 回放 | 6822（绿） | 65535（反白） |
| 武装 | 55264（琥珀） | 65535（反白） |

### 3. Page1 动态数据 ✅ 已落地（2026-10-29 RTL）

z_dg/z_dt/z_cl/z_mx/z_ll/z_lf/z_pr/z_vr + t_*_val + cur + gr 共 **25 字段全部有回显帧**（仪表与文本同源同值、
cur/gr 见 §四-3，帧型与口径见 §四-2 注）；tb 判据已扩充至 **312 checks PASS**。

### 4. led_* 状态灯 ✅ 已落地（2026-10-29 RTL）

`led_dist / led_chor / led_dly` 的 `.val=0/1` 随 fx_mask 联动（任一位变化 ⇒ 三灯 + 三状态条**共六帧齐发**）。
控件为双态按钮（圆点图复用 `tools/hb_dots/`），见 §三 底部状态条。
