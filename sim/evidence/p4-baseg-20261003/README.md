### 事实 ① —— 三条写路径写的都是【移位前】的值 ✅

⇒ ⭐ **事实①干净**：三条路径**都**可以无条件加"写入时左移 `base_oct_r`"。

### 事实 ② —— T3 会受影响，但只需**删掉那一次额外移位** ✅

```verilog
:1455   wire [PHASE_W-1:0] rot_phase = phase_r[rot_cnt];
:1456   wire [PHASE_W-1:0] rot_base  = (base_oct_r == 2'd0) ? rot_phase
:1457                                                       : (rot_phase << base_oct_r);
:1467   wire [PHASE_W+17-1:0] prod_w = rot_base * semi_ratio;   // 49 位 ✅（已避开 32 位陷阱）
:1488   phase_tr[rot_cnt] <= (prod_w >>> 15);
```

- `rot_base` **自己**在 `phase_r` 上做了一次 `<< base_oct_r`（`:1456-1457`）。
- 若 `phase_r` 改存**移位后**的值 ⇒ ⭐ **必须把 `:1456-1457` 改成
  `wire [PHASE_W-1:0] rot_base = rot_phase;`**（⛔ 否则**移两次**）。
- 乘比例与左移可交换：`((X<<b) * r) >>> 15` ≡ 原式（32 位截断一致）⇒
  `prod_w` / `phase_tr` **逐位不变** ✅
- ⭐ 全文件 `phase_r` 的**读**只有 3 处：`:1455`（T3 轮转）、`:1517`（`g_t3` 的
  `base_g`）、`:1535`（`g_t2` 输出）⇒ 影响面已穷举。

⇒ ⭐ **事实②干净**（可同步改，不影响 T3 数值）。

## 三、⭐ 阻塞（两条，第二条是致命的）

### 🔴 阻塞 A：计划 §二③ 的"右移精确"论证**不成立**（丢的是【高位】不是低位）

计划原文：*"⭐ 右移是精确的（因为当初左移过，低位本来就是 0）⇒ ⛔ 不丢信息"*。

低位那半句**对**；但**把 `X << a` 存进 32 位会丢掉 `X` 的【最高 a 位】**。
设 `X = phase_r`（32 位）、`a = 旧八度`、`b = 新八度 < a`：

```
参考实现  out_ref = (X << b) mod 2^32 = (X mod 2^(32-b)) << b
轮转实现  out_new = ((X << a) mod 2^32) >> (a-b) = (X mod 2^(32-a)) << b
⇒ 两者相差 X 的第 [32-a, 32-b) 位
   · a=1,b=0 ⇒ 差 X[31]      · a=2,b=0 ⇒ 差 X[30:31]
```

⭐ **可达性**：`tb/w3b/tb_transpose.sv:581` 用 `note_phase_inc = $random`
（**满 32 位随机**）⇒ 这些位**一半的拍都是 1** ⇒ 逐拍差分**必然**红。

✅ **修法（便宜）**：把 `phase_r` 存成 **34 位**、内容 `S = X << b`（**精确**，
因为 `X` 32 位 + `b ≤ 2` ⇒ 34 位刚好不丢）：
- 输出 = `S[31:0]` —— ⭐ **与参考逐位相同** ✅
- 降档 `S >> d`：低 d 位本来就是 0，且 `S` 精确 ⇒ **不丢任何位** ✅
- 升档 `(S << d)` 截到 34 位：低 32 位仍 == `(X << b_new) mod 2^32` ✅
- 代价：+2 位 × 32 lane = **+64 FF**（`T_Register` 有余量）

### 🔴🔴 阻塞 B（致命）：**"32 拍轮转"与"逐拍逐位相同"在定义上互斥**

轮转要 32 拍才走完一圈。在这 32 拍里，一部分 lane 已是新档、一部分还是旧档
⇒ ⭐ **`voice_phase_inc_o` 与参考必然不同**（R1 说的就是这个瞬态）。

但验收判据 2 要求"逐拍逐位相同"，而**现有的**逐拍差分判据是这样写的：

| 判据 | 位置 | 比较时机 |
|---|---|---|
| **T1** | `tb/w3b/tb_transpose.sv:447-468` | `always @(posedge clk)`，`t1_en` 期间 **每拍**比 `d_ph !== r_ph` |
| **T7** | `:498-523` | ⭐ **整个仿真期间每拍**比 `d_ph !== r_ph` |

而**换档就发生在被比较的窗口里**：
- T1 里 3 次提交：`:571-575`（`base_semi` = 0 / 12 / 24）
- T2 里还有 3 次：`:716-720`（oct 1、2）＋ `:727-730`（**oct 2 → 0，Δ = −2**）

⇒ ⭐ **每次换档都会给 T1/T7 贡献 ~32 拍不一致 ⇒ 两条判据必红**
⇒ ⭐ **"P4.2 做完 ⇒ 判据 2 成立"这条路不存在**。

⚠️ 而且判据一条**不许删/不许放宽**（任务书硬约束）⇒
**P4 的两条完成判据（①`T_Lut` 降 ≥2000 ＋ ②逐拍逐位不变）无法同时满足**。
