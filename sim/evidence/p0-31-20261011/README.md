## 一、缺陷（⭐ 真·听感 bug，⭐ 上一轮已确认）

⭐ `oscillator_bank` 的**扫频深度** = `bv >> (LSB_SH + 本档 SH)`，
⚠️ 而 `bv` = `base_phase_inc_i[vg]` = **`note_manager.phase_tr[vg]`**。

🔴 **`phase_tr[]` 是【轮转刷新】的**（`note_manager.v` 的 `rot_cnt` 自由运行 5 位
＋ ⭐ `P0-03` 之后的**写口 1 拍流水**）⇒ ⭐ **每条 lane 每 ≤33 拍才被重写一次**。
⭐ 而"提交"（`ST_COMMIT2` 改 `phase_r`）与"起音"（`voice_phase_rst_i` 被看见）
**可能只差 1 拍** ⇒ 🔴 **起音那一拍读到的 `bv` 还是【上一件鼓】的音高**。

📌 **为什么"分类对、深度错"**：⭐ `A3` 的正确修法把**分类**搬到了提交路径
（`drum_cls_i` ⇒ ⭐ **提交当拍就新鲜** ✅），🔴 但**深度**仍然乘 `bv`（轮转那一路）
⇒ ⭐ 于是"**用新鼓的档位**去乘**旧鼓的音高**"。

### ⭐ 实测数字（⭐ 用 `top.v` 生产参数：`LSB_SH=8` · `KICK_SH=0` · `TOM_SH=3`）

| 场景 | ⭐ 期望深度 | 🔴 实得 | 倍数 |
|---|---|---|---|
| 底鼓(5_368_709)紧跟嗵鼓(17_895_697) | `17_895_697 >> 11` = **8738** | `5_368_709 >> 11` = **2621** | ⭐ **浅 3.33×** |
| 嗵鼓紧跟底鼓 | `5_368_709 >> 8` = **20971** | `17_895_697 >> 8` = **69905** ⇒ ⭐ **16 位截断成 4369** | ⭐ **深 4.8×** |

📌 ⭐ **审查报告里写的 `8739` 是【笔误】** —— ⭐ `17_895_697 >> 11` 的真实值是 **8738**
（⭐ 2048 × 8739 = 17_897_472 > 17_895_697 ✅）。
⇒ ⭐ 本轮的 tb **期望值全部由 `localparam` 现算**，⛔ 不写死十进制 ⇒ ⭐ 这类抄写错误不再可能 ✅。

## 二、⭐ 判据（⭐ 先出"未修复能红"，⭐ 铁律①）

⭐ 新建 `tb/w3b/tb_drum_sweep_window.sv` —— ⭐ **6 条判据 / 3 个场景**：

| 场景 | ⭐ 内容 | 未修复 | ✅ 修复后 |
|---|---|---|---|
| **W1** | 底鼓→嗵鼓，`base_inc` 在**起音之后**才刷新（⭐ 硬件真实行为） | 🔴 **2 红** | ✅ 绿 |
| **W2** | 同上，但 `base_inc` 在**起音当拍**就刷新 | ✅ **绿（对照）** | ✅ 绿 |
| **W3** | 嗵鼓→底鼓，**起音之后**才刷新 | 🔴 **2 红** | ✅ 绿 |

⭐ **两条独立观测**（⭐ 分开报，⛔ 不合并）：
1. ⭐ **白盒**：⭐ `u_dut.gen_voice[0].sweep_q` 窗口内最大值（⭐ = 装载值）
2. ⭐ **端到端**：⭐ 每采样拍**相位增量**（`phase_acc_dbg_o` 差分）的最大值
   = `新音高 + (深度 << 8)`（⭐ `DETUNE_ON=0` ⇒ ⭐ 无第三项 ✅）
   ⇒ ⭐ 证明"装载值**真的走进了相位通路**"（⛔ 不是只改了寄存器）✅

### ⭐⭐ 非空洞性（⭐ 本 tb 的核心）

⭐ `W2` 与 `W1` **只差一件事**：`base_inc` 是"起音当拍刷新"还是"起音之后刷新"。
⇒ ⭐ `W2` **未修复时也绿** ⇒ ⭐ **证明 `W1`/`W3` 的红是"窗口"造成的**，
⛔ 不是"判据本身不成立" ✅。

### ⭐ 实测（⭐ 未修复 vs 修复后）

```text

   W1: 起音拍 sweep_q=2621  窗口 max=2618   相位增量 max=18566673（应 20132625）
   W3: 起音拍 sweep_q=4369  窗口 max=4364   相位增量 max= 6487173（应 10737285）
```

⚠️ **踩到的时基坑（⭐ 已写进 tb 文件头，⭐ 防复发）**：
⭐ tb 自己用 `<=` 驱动 `sample_tick` ⇒ ⚠️ **DUT 在 `posedge clk` 的 active 区读到的仍是旧值 0**
⇒ 🔴 **DUT 真正的采样拍 = `@(posedge sample_tick)` 之后【再一个】 `posedge clk`**。
📌 ⭐ 第一版忽略了这条 ⇒ ⭐ 起音落在 DUT 采样拍**之后** ⇒ 🔴 **窗口永远踩不到、判据假绿**
（⭐ 实测：`W1` 拿到 8738 而**误判为通过**）✅

## 三、✅ 改法（⭐ 为什么"晚一拍"就【必然】够 —— 推导，⛔ 不是经验值）

```
· ⭐ `voice_phase_rst_i` = `note_manager.voice_retrig_reset_o` = `retrig_reset_r`
   ⭐ 它在 `!sample_tick_i` 时置位、⭐ 在 `sample_tick_i` 那拍清零
   ⇒ ⭐ **恰好可见一个采样拍**（⭐ 这不是巧合，⭐ 是 `B2-a` 的设计约定）
· ⭐ 提交（改 `phase_r`）必然发生在**起音采样拍之前**（⭐ 电平被看见 ⇒ 提交更早）
· ⭐ `phase_tr[vg]` 的刷新 ≤ **33 拍**（32 拍轮转 + 1 拍写口流水）
· ⭐ 一个采样拍 = **1024 拍**（`CLK_PER_SAMPLE`）
⇒ ⭐ **"下一个采样拍"时 `phase_tr[vg]` 必然已是提交后的值** ✅
```

⭐ 实现（⭐ 主实现 `rtl/w3b/oscillator_bank.v` · ⭐ `gen_voice` 块，⭐ **每 voice 一份**）：

```verilog
reg  onset_d;                                   // ⭐ 唯一新增的寄存器
wire onset_v = (!test_mode_i) && (rst_v || (act_v && !act_d));   // ⭐ 逐项照抄原条件
...
if (onset_d)        sweep_q <= sweep_load;      // ⭐ 上一拍看到起音 ⇒ 现在装（bv 已新鲜）
else if (onset_v)   sweep_q <= {DRUM_SWEEP_W{1'b0}};  // ⭐ 起音当拍 ⇒ 只清 0、先不扫
else if (sweep_q != 0) sweep_q <= sweep_dec;
```

⭐ **与老行为的唯一差别**：⭐ 起音后扫频**晚一拍生效**
（⭐ 20.48 µs ÷ τ = 21 ms = **0.1%** ⇒ ⭐ 不可闻 ✅）。
⭐ 若起音电平**持续多拍**（⛔ 非 `note_manager` 的用法）⇒ ⭐ `onset_d` 保持 1
⇒ ⭐ **每个采样拍都重装** ⇒ ⭐ 与老行为**逐拍相同** ✅。

## 四、⭐ 参考副本同步（⭐ 铁律④）＋ ⭐ 顺手补上一个**真实的覆盖漏洞**

⭐ `tb/models/oscillator_bank_ref.v` **同步**加了 `onset_now` / `onset_d`
（⭐ 每 lane 一份，⭐ 与主实现的每 voice 一份在**非 test 档下逐拍等价** ✅）。

🔴🔴 **但顺手发现 `tb_p5_osc_equiv.sv` 有一个【真实的覆盖漏洞】**：

```
⭐ 该 tb 的 C 节（"鼓 voice + 音高包络"）此前 `voice_active` **一直是全 1**
   （⭐ A 节就抬起来了），⭐ 而 `voice_phase_rst` 全程恒 0
⇒ ⭐ `lane_active` **没有上升沿** ⇒ 🔴 **扫频装载【从未执行过】**（sweep_q 全程为 0）
⇒ 🔴 "P5-② 上提"对**扫频那一路**的等价性**根本没有判据覆盖**
   —— ⚠️ 这正是"主实现改了扫频、参考副本忘了同步"**不被发现**的缺口
```

✅ **修法**：⭐ 在 C 节先 `voice_active = 0` 跑 2 帧、再抬回全 1 ⇒ ⭐ 造出**真正的起音事件**
（⭐ 覆盖 `lane_active` 上升沿那条兼容路径）。

⭐ **非空洞性实测**（⭐ 必须做）：⭐ 把参考副本的 `sweep_kick` 故意改成 `sweep_tom`
⇒ 🔴 **tb 立刻红**（`FAIL frame 105: lane 0 PHASE ref=00b8510a dut=00f5c20a`，
⭐ `frame 105` 正好是**那个起音帧**）✅ ⇒ ⭐ 恢复后 `322 帧 0 mismatch` ✅
⇒ ⭐ **判据真的覆盖了扫频那一路** ✅
