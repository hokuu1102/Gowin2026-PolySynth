# 隐式 wire 缺陷：`top.v` 的 `wire looper_full;` 被**吞进注释**（2026-10-11 · ✅ 已修）

> ⭐ **来源**：⭐ **不是审查条目** —— ⭐ 是我**扫全部编译告警**时发现的 ✅
> ⭐ **证据**：⭐ `warning: implicit definition of wire 'looper_full'.` × **139 次**
> （⭐ 每次顶层编译都报一次 ✅）
> 📌 ⭐ **这正是"先找证据，再找改法"那条选题标准的产物** ✅

---

## 一、⭐ 缺陷

### ⭐ 原文（⭐ `top.v:4215`，⭐ 修之前）

```verilog
wire        looper_dump_clip;    // ⭐ 本条 `inc` 超 21 位（⭐ 导出会失真 ✅）        wire        looper_full;
```

🔴 ⭐ **两个 `wire` 声明被并成了【一行】** ✅ ——
⭐ **第二个 `wire looper_full;` 落在 `//` 之后** ⇒ ⭐ **它成了注释的一部分** ✅
⇒ ⭐ `looper_full` **从未被声明** ✅
⇒ 🔴 iverilog **自动建了一个隐式 1 位 wire** ✅

### 📌 ⭐ 根因（⭐ 本项目**已有记录**的那一类）

⭐ `AGENTS.md` §二 写着 ✅：

> 🔴 **静默丢元素**（`C72`）：⭐ **非 ASCII 序列吃掉后面的【换行】**
> ⇒ ⚠️ 注释与下一行**合并** ⇒ 🔴 **若下一行是数组元素 ⇒ 它【消失】**
> 📌 实测：107 个变异体 ⇒ ⭐ 脚本只读到 105（⚠️ **零报错、零警告**）

⭐ 那条规则当初是 **`.ps1` 编码**踩出来的 ✅ ——
⚠️ **这里是同一根因**：⭐ **一行被合并进上一行的注释里，而编译器只给"隐式 wire"告警** ✅
📌 ⭐ **所以它跟编码无关，是"编辑时丢换行"的通病** ✅

## 二、⚠️ 为什么它【今天恰好无害】，⚠️ 但仍然是雷

| ⭐ 项 | ⭐ 值 |
|---|---|
| ⭐ `looper` 的实参 | ⭐ `.LAYERS (1)` ⇒ ⭐ `full_o` 是 `[LAYERS-1:0]` = **1 位** ✅ |
| ⭐ 隐式 wire 的宽度 | ⭐ **1 位**（⭐ Verilog 的隐式 wire 默认 1 位 ✅） |
| ⇒ | ⭐ **宽度正好对** ⇒ ⭐ 今天**行为正确** ✅ |

🔴 **但它是一个陷阱**：⭐ `.LAYERS(1)` 旁边原本的注释写着 ✅：

```verilog
.LAYERS  (1),        // ⚠️ 本版**单层**（⭐ `T40` 再扩）
```

⇒ ⭐ **一旦 `T40` 把 `LAYERS` 扩到 >1** ⇒ ⭐ `full_o` 变宽
⇒ 🔴 **隐式 1 位 wire 会【静默截断】高几位** ✅
⇒ ⭐ **每层"录满"标志只剩第 0 层** ✅ —— 🔴 **与 `P1-20` 完全同类** ✅

📌 ⭐ 而且它的**发现成本极高**：⭐ 综合**不会报错**，⭐ 只会给一条**没人看的告警** ✅

## 三、✅ 改法（⭐ 沿用 `P1-20` 的**同源常量**套路）

```verilog
// ⭐ ① 声明拆回【独立一行】
// ⭐ ② 端口宽度与这里用【同一个 localparam】
localparam integer LOOPER_LAYERS = 1;    // ⚠️ 本版**单层**（⭐ `T40` 再扩 ✅）
                                         //   ⭐ 与下面 `.LAYERS` 同源 ⇒ ⛔ 不可能不一致 ✅
wire [LOOPER_LAYERS-1:0] looper_full;
...
    .LAYERS  (LOOPER_LAYERS),   // ⭐ 同源 ⇒ ⛔ 不可能静默截断 ✅
```

⇒ ⭐ **改一处就同时改两处** ⇒ ⭐ 将来扩到多层时，**端口与声明一起变宽** ✅
📌 ⭐ 这是**连续第二轮**用同一个套路（⭐ `P1-20` 的 `GUARD_ADC_N` ✅）
⇒ ⭐ **已固化为本项目的修法模式**：⭐ **"宽度一致"这类约束，⛔ 不要靠注释，靠【同一个常量】** ✅
