## 一、问题（原判）

⭐ `phase_tr` 是**轮转刷新**的影子数组（每拍 1 个 lane，32 拍一圈）
⇒ ⚠️ 任何变化最多 **32 拍（0.64 µs）**才反映到输出
⇒ 🔴 而 `oscillator_bank` 的**鼓音高档判据**（`is_kick`/`is_tom`）读的正是它
⇒ ⚠️ 若 `note_on` 距采样拍 **< 32 拍**，可能读到**上一个音的音高档**
⇒ 🔴 **该次鼓音的"扫频深度"取错**（⭐ 概率上界 **3.1%**，⛔ 不影响音高/音量/发声）

## 二、⭐ 试过的两版（都能量到，都有代价）

### 2.1 第一版：提交时把 `rot_cnt` 跳到该 voice

| 项 | 结果 |
|---|---|
| 想法 | ⭐ 提交（`cmt_en_r`）那一拍把 `rot_cnt` 置成 `cmt_idx_r` ⇒ 下一拍就刷到它 |
| 窗口 | ≤32 拍 → ⭐ **≤1 拍** |
| 代价 | ⭐ 一个 5 位 mux（⛔ 理论 0 LUT） |
| 🔴 实测 | **`tb_transpose` 红 3 条**（T2/T3/T6） |
| 根因 | ⭐ 提交是**突发**的（一帧最多 18 个事件）⇒ `rot_cnt` 被**连续钉住** ⇒ 🔴 **轮转停摆** ⇒ "34 拍内 32 lane 全刷新"不成立 |
| 处置 | ✅ 已回退（与 T5 版逐字节相同、`tb_transpose` 复绿） |

### 2.2 第二版：`note_manager` 输出未变调原始相位

| 项 | 结果 |
|---|---|
| 想法 | ⭐ 加一路 `voice_phase_raw_o` = **未变调**的每 voice 相位 ⇒ 鼓判据改读它 ⇒ ⭐ **零窗口** ✅ |
| 语义 | ⭐ **更对**：鼓种应由"**按的哪个键**"决定，⛔ 不该被变调带走 ✅ |
| 判据 | ⭐ 「tb/w3b/tb_osc_drum_raw.sv」（历史引用，当前未收录） **4/4 PASS**（⭐ `A1` 按 raw 判 / `A2` 悬空回退 base）✅ |
| 反向验证 | ⭐ 去掉修法 ⇒ **A1/A1b FAIL**（2 pass / 2 fail）✅ |
| 🔴 **代价（实测）** | ⭐ **变体 a**（`phase_r[g] << base_oct_r` 逐 voice 移位）：`T_Lut 27271 → 29417`（**+2146**）· `CLS 78% → 82%`<br>⭐ **变体 b**（阈值按八度缩放，移位只做在常量上）：`T_Lut 27271 → 29322`（**+2051**）· `CLS 82%` |
| 🔴 **根因（关键发现）** | ⭐ 阈值一旦从**编译期常量**变成**运行时 wire**，那 2×32 个「**常量比较器**」就变成**全 32 位比较器** ⇒ 🔴 每个 voice 多出上千 LUT<br>（⭐ 变体 a 的另一半原因：⭐ 逐 voice 移位 = **32 份 32 位移位器** = ⭐ **T3 影子架构当初省掉的那 ≈2650 LUT**） |
| 处置 | ✅ **已回退**（⭐ 残留检查 6 个符号全 0 · `T_Lut` 精确回到 **27271**） |

## 三、⭐⭐ 正确的修法（⭐ 记档，⛔ 本批未做）

⭐ **把鼓分类从 `oscillator_bank` 搬到【提交路径】**（`note_manager` 的 `ST_COMMIT2`）：

| 步 | 做法 |
|---|---|
| 1 | ⭐ `ST_COMMIT2` 里算**一次**（⭐ 每拍只判 **1 个 voice**）：<br>`cmt_inc_oct = (base_oct_r==0) ? cmt_inc_r : (cmt_inc_r << base_oct_r);`<br>`cmt_kick = (cmt_inc_oct <  KICK_MAX);` `cmt_tom = (cmt_inc_oct >= KICK_MAX) && (< TOM_MAX);` |
| 2 | ⭐ 存成**每 voice 2 bit 状态**（⭐ `drum_cls_r[cmt_idx_r]`，⭐ 32×2 = **64 FF**） |
| 3 | ⭐ 引出去（⭐ `voice_drum_cls_o`，64 位）⇒ `oscillator_bank` **直接读**，⛔ **不再有比较器** |
| ⭐ 收益 | ⭐ 比较器从 **2×32 = 64 个**降到 **1 套（TDM）** ⇒ ⭐ **净收益可能为正**（⭐ 不是代价！）✅ |
| ⚠️ 注意 | ⭐ 阈值参数要在两处一致（⭐ 或由 `top.v` 统一传）· ⚠️ 要改 `tb_drum_pitch_env` 的契约 |

📌 **为什么它更对**：⭐ 鼓种是**音的性质**（⭐ 在 `note_on` 那一刻就定了）
—— ⭐ 与 `timbre`/`velocity` 一样属于"**每 voice 属性**"，
⛔ 不该在 `oscillator_bank` 里**每拍重新推**（⭐ 那既贵又不准）✅

### 3.1 ⚠️⚠️ **但它的爆炸半径比预想大得多**（2026-10-08 实测盘点）

⭐ **11 个 tb 直接例化 `oscillator_bank`**：

```
tb_drum_pitch_env · tb_note_manager · tb_oscillator_bank · tb_p5_osc_equiv ·
tb_soft_hard_blend · tb_test_mode_fft · tb_velocity_headroom ·
tb_velocity_lane_isolation · tb_velocity_tone_decoupling · tb_w1_interfaces · tb_wavetable_bank
```

🔴 **死结**：⭐ 想**省下那 64 个比较器**（⭐ 那才是净收益的来源），就必须
**把 `drum_cls_i` 变成必接端口** ⇒ ⚠️ **上面 11 个 tb 全都要改**；
⭐ 若为了"老 tb 不用改"而做 **Z-safe 回退** ⇒ ⚠️ **比较器必须留着** ⇒ 🔴 **净收益归零**
（⭐ 那就退化成本次已回退的版本 —— 白花 +2000 LUT）✅

### 3.2 ⭐ 结论（给用户裁定）

| 维度 | 评估 |
|---|---|
| **收益** | ⚠️ 只影响**鼓音的"扫频深度"**（⭐ 音高包络的深度）· ⭐ 概率上界 **3.1%** · ⛔ 不影响音高/音量/发声<br>＋ ⭐ 一个语义小改进（⭐ 鼓种不再随变调漂移） |
| **代价** | 🔴 **改 11 个 tb** ＋ 改 `note_manager`/`oscillator_bank`/参考副本 ＋ ⚠️ **动到 `=1` 档那条只剩 +0.051 ns 的薄余量** |
| ⭐ **建议** | 🔴 **不做**（⭐ 收益/代价/风险**明显不成比例**）—— ⭐ 若哪天要动 `oscillator_bank` 的接口，可以**顺手**做掉 ✅ |
