### 2.1 ⭐ 影子数组的机制（⭐ 为什么反而更便宜）

🔑 **关键观察**：⭐ 现有代码里 `phase_tr[rot_cnt] <= prod_w >>> 15` **本来就每拍都写**
（⭐ `prod_w = rot_base × ratio`，⭐ 而 `rot_base` **已经含八度移位**）
⇒ ⭐ **`phase_tr` 早就在跟踪 base 值**（⭐ 只差"选择"这一步）
⇒ ⭐ 把"选择"挪到**写侧**（⭐ 一次只处理**一个 lane**）即可：

```verilog
// 写侧：一个 32 位 mux（⭐ 复用 rot_base，⛔ 不新增移位器）
phase_tr[rot_cnt] <= ((semi_cur == 5'sd0) ||
                      (src_r[rot_cnt] == 3'd3) || (src_r[rot_cnt] == 3'd4))
                   ? rot_base : (prod_w >>> 15);
// 输出侧：只剩连线
assign voice_phase_inc_o[gp*PHASE_W +: PHASE_W] = phase_tr[gp];
```

⭐ **净效果**：32 lane × 32 位（1024 个 mux ＋ 32 份移位器）
⇒ ⭐ **1 个 32 位 mux** ✅
⭐⭐ **附带治好一个真 bug**：⭐ 变调**每次都从 `phase_r`（base）重算**
⇒ ⛔ 不会像"就地重算"那样把比例**反复乘到自己身上**（⭐ 那会让 `0→+12` 累积成 ~90×）✅

## 5. ⭐⭐ 判据改动：T6 判据 ③ 换成**等价探针**（⭐ 唯一一处）

🔴 **旧写法**（⭐ 钉的是**实现方式**）：
```verilog
if (absdiff32(u_t3on.g_t3.phase_tr[v], e2) <= 1) t6_tr_ok = ...   // ⭐ 读内部数组
chk("T6: gated lanes DO hold the transposed value in phase_tr (mux blocked it)", ...);
```
⭐ 它要求"**被门控的 lane 在 `phase_tr` 里仍然存着变调值**"⇒ ⭐ 即"**门控必须在输出侧**"。
⚠️ 影子版把门控挪到**写侧** ⇒ ⭐ 该探针**必然红** —— ⚠️ 但它钉的是**实现**，⛔ 不是行为。

✅ **新写法**（⭐ **同一个意图**、⭐ 换成**行为可观测**）：
⭐ 轮转器**当前那一格**若落在**被门控**的 lane 上 ⇒ ⭐ `prod_w>>>15`（变调值）
与 `rot_base`（base）**必须不同** ⇒ ⭐ 证明"⭐ **变调真的算了，只是选择逻辑把它丢掉**" ✅

📌 **为什么这是"等价"而不是"放宽"**：
- ⭐ 判据 ①②（⭐ `src=3/4` **逐位不变** ＋ ⭐ `src=0/1/2` **跟随变调**）**一字未改** ✅
- ⭐ "门控确实挡住了一个**不同的**值"（`t6_effect`）**一字未改** ✅
- ⭐ 非空洞性判据**一条未删** ✅
- ⭐ **能红仍然成立**（⭐ 实测）：⭐ **去掉写侧源门控**（⭐ 恒选变调值）⇒ 🔴
  `T6: src=3/4 voices are bit-UNCHANGED` **红** ＋ `gating really blocks a DIFFERENT value` **红** ✅

⭐ **出处**：⭐ `files/20-代码/T3-PnR阻塞记录-20261003.md` §9.1 早就写明 ——
「⭐ 若 B 是大头 ⇒ ⚠️ **必须带数据找用户重议判据口径**（例如"T6 换等价探针"），
⛔ 子代理不得自行改 tb 或改架构」⇒ ⭐ **本轮正是按这条走的**（⭐ 探针 → 用户裁定 → 改口径）✅

## 6. ⚠️⚠️ 影子架构的代价（⭐ 必须知道）

⭐ `phase_tr[g]` 是**轮转刷新**的（⭐ 32 拍一圈）⇒ ⭐ 任何"会让某 lane 该用的值变化"的事件，
**最多 32 拍（0.64 µs）后**才反映到 `voice_phase_inc_o`：

| 事件 | 延迟 | 影响 |
|---|---|---|
| `semi_cur` 变化（⭐ 每 1 ms 走 1 半音） | ≤32 拍 | ⭐ 不可闻（0.64 µs ≪ 1 ms） |
| `base_oct_r` 换八度 | ≤32 拍 | ⭐ 不可闻 |
| `pitch_upd`（滑音/颤音） | ≤32 拍 | ⭐ 不可闻（⭐ 颤音更新间隔 ~328 µs） |
| ⭐ `note_on` 新音 | ≤32 拍 | ⭐ 起音时包络 ≈ 0 ⇒ 不可闻 |

### 🔴 一个**必须记住**的副作用：鼓的扫频判据会读到"上一拍的值"

⭐ `oscillator_bank` 的鼓判据（⭐ `is_kick`/`is_tom`，⭐ 决定音高包络的深度）**组合**读
`base_phase_inc_i`（⭐ = 本模块的输出）⇒ ⭐ 而它在**影子版**里**最多旧 32 拍**：
- ⭐ 扫频的**装载**发生在"`act_v` 上升沿那一拍"（⭐ 即 `note_on` 后的第一个 `sample_tick`）
- ⚠️ 若那次 `sample_tick` **落在刷新窗口内**（⭐ 即 `note_on` 距 `sample_tick` < 32 拍）
  ⇒ ⭐ 读到**上一个音**的音高档 ⇒ 🔴 **该次鼓音的扫频深度可能取错**
- ⭐ **概率上界**：⭐ `32 / 1024 ≈ 3.1%`（⭐ 且只在该 lane **换了鼓种**时才有差别）
- ⭐ **听觉影响**：⭐ 只影响"**音高包络的深度**"（⭐ 例如底鼓少一点"闷下去"），
  ⛔ 不影响音高、⛔ 不影响音量、⛔ 不影响发声与否

📌 **为什么本轮不改**（⭐ 诚实记录）：
- ⭐ 要**确定性**地关掉这个窗口，得把主状态机写 `phase_r` 的**索引/数据/有效**引到模块层
  （⭐ 现在它们是**块内局部量**）⇒ ⭐ 那是对**最核心的 FSM** 做一次结构改动
  ⇒ ⚠️ 风险与工时都远超本次预算
- ⭐ 用户裁定是「⭐ **最终效果没问题就行**」⇒ ⭐ 本项**不改变可听结果**（⭐ 见上面的听觉影响）
- ⭐ **可复现的后续**：⭐ 在 `note_manager` 里给 `phase_tr` 加一个"**note 事件同步刷新**"
  （⭐ 用与 `phase_r` 同一套索引/数据，⭐ 约 +40 LUT）⇒ ⭐ 窗口归零 ✅
  📌 **⛔ 未做，⭐ 已登记为待办**（⭐ 见 §8）
