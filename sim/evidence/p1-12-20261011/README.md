# `P1-12`：`S_DONE` 里重发 `'S'` **静默无效**（2026-10-11 · ✅ 已修）

## 一、⭐ 缺陷

### ⭐ 链路（⭐ 逐行）

```verilog
// rtl/w3a/calib_span.v —— ⭐ `S_DONE` 是【自锁终态】
S_DONE: begin
    need_press_o <= 1'b0;
    span_o       <= {N_ADC{1'b0}};
end                       // 🔴 没有出口：`start_i` 在这里【没有任何消费者】
                          //    ⭐ 唯一出口 = `abort_i`（`'X'`）或复位

// rtl/top.v:2371 —— ⭐ 门控只查 `at_done`（= 自动零点完成）
wire sp_start_gated = cmd_span_req & at_done;   // ⭐ 放行
```

⇒ 🔴 **"放行 + 无人消费" = 静默无效** ✅

### 📌 ⭐ 用户视角（⭐ 这是最难查的那一类）

| ⭐ 用户做了什么 | ⭐ 他看到什么 | ⭐ 实际发生 |
|---|---|---|
| ⭐ 发 `'S'` | ⭐ 回 `'s'`（⭐ "**已受理**" ✅） | 🔴 **什么都没发生** ✅ |

⭐ 而"什么都没发生"是**完全静默**的 ✅ —— ⭐ 用户会以为"标定又跑了一遍" ✅
📌 ⭐ 正是 `K-106` 那一类（⭐ **不许静默失效** ✅）

---

## 二、✅ 改法（⭐ 选审查给的**第二条路**：重跑，⛔ 不是拒绝）

⭐ 审查给了两条路 ✅：

| ⭐ 方案 | ⭐ 做法 | ⭐ 用户要多做什么 |
|---|---|---|
| ⭐ A（⭐ 审查的主推） | ⭐ `top.v` 门控加 `sp_state == S_IDLE` ⇒ ⭐ 第二次 `'S'` 回 `'!'`（⭐ 拒绝 ✅） | ⚠️ ⭐ 用户得**先发 `'X'`** 再发 `'S'` ✅ |
| ✅ **B（⭐ 本轮选的）** | ⭐ `calib_span` 的 `S_DONE` 收到 `start_i` ⇒ ⭐ **重新开始** ✅ | ✅ ⭐ **直接再发一次 `'S'` 就行** ✅ |

⭐ **选 B 的理由**：
1. ⭐ **对用户更简单**（⭐ 少一步 ✅）
2. ⭐ **判据是模块级的** ⇒ ⭐ **能红、能独立验证** ✅
   （⭐ A 的判据在 `top.v` ⇒ ⚠️ 需要一个**顶层** tb，⭐ 而本项目**没有**发 `'S'` 的顶层 tb ✅）
3. ⭐ **语义等价**：⭐ "重发 `'S'`" == "`'X'` 然后 `'S'`" ✅

### ⭐ 代码（⭐ 清场项**逐条照抄** `abort_i` 那段）

```verilog
S_DONE: begin
    need_press_o <= 1'b0;
    span_o       <= {N_ADC{1'b0}};
    if (start_i) begin
        state        <= S_PROMPT;      // ⭐ 与 abort 的唯一区别（abort 回 S_IDLE）
        done_o       <= 1'b0;
        cur_axis     <= 4'd0;   cur_axis_o  <= 4'd0;
        reject_cnt   <= 4'd0;   done_cnt_o  <= 4'd0;
        stable_cnt   <= 6'd0;   vote_cnt    <= 6'd0;
        prev_val     <= 12'hFFF; vmin       <= 12'hFFF;  vmax <= 12'd0;
        span_o       <= {N_ADC{1'b0}};
        wait_clk_cnt <= {WCW{1'b0}};
        span_sent_r  <= 1'b0;   prompt_phase <= 1'b0;
    end
end
```

📌 ⭐ **为什么清这么多**：⭐ 与 `abort_i` **同一套** ——
⭐ 否则"下次进入时带上一次的残留"（⭐ `reject_cnt`/`done_cnt_o`/`vmin`/`vmax` ✅）
⚠️ 那会**静默写坏标定** ✅（⭐ `abort_i` 的注释里写着这条 ✅）

## 三、⭐ 判据（⭐ 先出"未修复能红" ✅）

⭐ 加在 `tb/w3a/tb_calib_span.sv` 的**判据⑨** ✅：

| # | ⭐ 判据 |
|---|---|
| ⭐ setup 1 | ⭐ FSM 真的到了 `DONE`（⭐ `done_o === 1` ✅） |
| ⭐ setup 2 | ⭐ `busy_o === 0`（⭐ 确认真在 `S_DONE` ✅） |
| ⭐⭐ **主判据** | ⭐ **重发 `start_i` ⇒ `busy_o` 必须重新为 1** ✅ |

## 四、⚠️ 写判据时踩的两个坑（⭐ 都值得记）

### ① 🔴 **判据放在 tb 末尾 ⇒ 空洞**

⭐ 我第一版把判据⑨放在**tb 最末尾** ✅ —— ⚠️ 而那里 FSM 已被前面的
**超时测试/abort 测试**带离 `S_DONE` ✅ ⇒ ⭐ `busy_o` 当时**已经是 1** ✅
⇒ 🔴 **主判据无脑通过**（⭐ 空洞 ✅）

✅ **修法**：⭐ **在判据里重跑一遍完整流程**（⭐ 与判据⑧ 同一套 6000 拍循环 ✅），
⭐ 并加两条 **setup 判据**（⭐ `done_o === 1` ＋ ⭐ `busy_o === 0` ✅）
⇒ ⭐ **setup 判据就是"空洞守卫"** ✅

📌 ⭐ **教训**：⭐ **"跑到目标状态"这一步必须写进判据里** ——
⛔ 不能依赖"tb 走到这里时应该正好在那个状态" ✅
（⭐ 与 `P1-18` 的 `J1` 窗口、⭐ `DUMP-b` 的"地址 0 巧合"**同一族** ✅）

### ② ⭐ 用 `done_seen`（⭐ 一个"曾经出现过"的监视器）⛔ 不够

⭐ 我第一版用一个 `always @(posedge clk) if (done_o) done_seen <= 1;` ✅
⇒ ⚠️ 它只能证明"**曾经**到过 `S_DONE`" ✅ ⇒ 🔴 **证明不了"现在还在"** ✅
✅ **修法**：⭐ 直接查 **`done_o`（⭐ 当拍 ✅）＋ `busy_o === 0`** ✅
