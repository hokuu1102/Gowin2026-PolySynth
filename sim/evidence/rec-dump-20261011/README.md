## 二、⭐ ① `evt_buf` 高水位（L1）

### 改了什么

```verilog
parameter integer LOW_WM  = 256,
//  ⭐ L1：⭐ "还没丢，但余量告急"
parameter integer HIGH_WM = (DEPTH > LOW_WM) ? (DEPTH - LOW_WM) : 1
...
output wire high_water_o,
...
if (cnt_next >= HIGH_WM) hw_r <= 1'b1;   // ⭐ sticky，⭐ 与 ovf 共用 ovf_clr_i ✅
```

### 🔴🔴 **实测踩到的坑：`HIGH_WM` 必须【随 DEPTH 派生】**

⭐ 我第一版写死 `HIGH_WM = 768`（⭐ 交付档 1024 − 256 ✅）——
⚠️ 而 `tb/w3c/tb_evt_buf.sv` 的**小实例是 `DEPTH=8, LOW_WM=2`** ✅
⇒ 🔴 `cnt_next >= 768` 对 `DEPTH=8` **永远不成立** ⇒ ⭐ `high_water_o` **恒 0**
⇒ 🔴 **判据结构上不可能红（空洞）** ✅
＋ ⚠️ 对 `DEPTH=8` 的缓冲来说，"高水位 768"**本身就没有意义** ✅

✅ **修法**：⭐ `(DEPTH > LOW_WM) ? (DEPTH - LOW_WM) : 1`
⇒ ⭐ **任何参数组合下都保证 `1 <= HIGH_WM <= DEPTH`** ✅
📌 ⭐ 判据 `11k`/`11l` **专门钉这个派生**（⭐ `8−2=6` · ⭐ `1024−256=768` ✅）

### ⚠️ ⭐ 为什么⛔ 不把它 OR 进 `ovf_any`（⭐ 想清楚了才这么做）

⭐ `ovf_any` 驱动**心跳灯快闪**，⭐ 而那是**已交付语义**
（⭐ 交接文档写明"**心跳灯快闪 = 丢过曲谱事件**" ✅）
⇒ ⚠️ 把"**快满了**"混进去 ⇒ 🔴 **改变既有指示的含义**
＋ ⭐ 上板时"**真丢了**"与"**快满了**"是**必须分清**的两件事 ✅
✅ **处置**：⭐ 引出为**顶层挂钩**（⭐ `(* syn_keep = 1 *) wire eb_hw;` 防剪 ✅），
⭐ 语义留给**将来的状态回包** ✅

### 判据（⭐ `tb/w3c/tb_evt_buf.sv` ⑪ 段，⭐ 12 条）

| # | ⭐ 判据 |
|---|---|
| `11a` | ⭐ 复位/清后 `high_water` = 0 ✅ |
| `11d` | ⭐ 水位 = `HIGH_WM−1`（5）⇒ ⭐ **仍是 0**（"还没到"）✅ |
| `11f` | ⭐ 水位 = `HIGH_WM`（6）⇒ ⭐ **置位** ✅ |
| ⭐ **`11g`** | ⭐⭐ **非空洞性**：⭐ 此刻 **`ovf_o` 必须还是 0** ⇒ ⭐ 证明它**真的在"丢失之前"报** ✅ |
| `11i` | ⭐ **sticky**：⭐ 排空到 0 ⇒ ⭐ 仍是 1 ✅ |
| `11j` | ⭐ `ovf_clr_i` 清 ⇒ 归 0 ✅ |
| `11k`/`11l` | ⭐ **参数派生**：⭐ 6 与 768 ✅ |

⭐ **变异体 `MUT-G`**（⭐ 把置位条件改成 `if (1'b0)`）⇒ 🔴 **`11f`/`11i` 红** ✅

## 三、⭐ ② `looper` 导出读口

### 🔴🔴 **最关键的设计约束：⭐ 必须【复用】同一个读口**

⭐ `looper.v:551-560` **自己记着**一条实测教训 ✅：

> ⭐ 原来写的是**异步读**（`wire e_word = mem[rd_ptr_r];`）
> ⇒ 🔴 Gowin 报 `ERROR (IF0008): The number(135168) of DFF used to infer "mem"
> exceeds the resource limit(60780)` ⇒ ⭐ **整个综合失败** ⚠️
> ⚠️ 而**仿真 100% 全绿** —— ⭐ 正是 `K-91` 那一类："**仿真过了 ⛔ ≠ 能综合**" ✅

⇒ ⭐ 而 BSRAM 的**物理结构**是 **1 写口 ＋ 1 读口** ✅
⇒ 🔴 **再加一条** `always @(posedge clk) dump <= mem[dump_addr]`
⇒ ⭐ 综合器**推不出 BSRAM** ⇒ 退回 DFF 阵列 ⇒ ⭐ **就是上面那个综合失败** ✅

✅ **修法（⭐ 地址 mux ⇒ 结构上【只有一个读口】）**：

```verilog
wire             dump_en_w   = (dump_en_i === 1'b1);          // ⭐ Z-safe 解码
wire [CNT_W-1:0] mem_rd_addr = dump_en_w ? dump_addr_i : rd_ptr_r;
reg  [EW-1:0]    e_word_r;
always @(posedge clk_i) e_word_r <= mem[mem_rd_addr];         // ⭐ 仍只有这一条读
assign dump_data_o = e_word_r;
```

📌 ⭐ **优先级**：⭐ `dump_en_i` 高 ⇒ ⭐ **导出期间读口归导出** ✅
⚠️ 因此**导出时必须停止放音** —— ⭐ 由将来的导出 FSM 保证（⭐ 只在层空闲时导 ✅）
📌 ⭐ **这不是限制，⭐ 而是语义上就该如此**（⭐ 导出的是"**已录下的东西**" ✅）

### ⚠️ ⭐ 两个实现细节（⭐ 都踩过才写下来）

| # | 细节 |
|---|---|
| ① | ⭐ **位宽必须写【内联常量表达式】** —— ⚠️ 因为 `EW` 是本模块**端口表之后**才声明的 `localparam`（⭐ Verilog-2001 的 ANSI 端口表里**用不了**它 ✅）⇒ ⭐ 端口写成 `[TICK_W+KIND_W+AXIS_W+PHASE_W+VEL_W+TIMBRE_W-1:0]` ✅ |
| ② | ⭐ **Z-safe**：⭐ 老例化不接 `dump_en_i` ⇒ `z` ⇒ ⚠️ 用普通 `if` 会得 `x` ⇒ 🔴 判据真假不定 ⇒ ⭐ 用 `=== 1'b1` 解码 ✅（⭐ 与 `oscillator_bank.voice_phase_rst_i` / `drum_gen.pos_reset_i` **同一套口径** ✅） |

### 判据（⭐ `tb/w3c/tb_looper.sv` ⑩ 段，⭐ 9 条）

| # | ⭐ 判据 |
|---|---|
| `DUMP-b`/`c` | ⭐ 按地址读出 `mem[0]`/`mem[1]`（⭐ 走**共用读口** ✅） |
| ⭐ `DUMP-d` | ⭐⭐ **非空洞性**：⭐ 两条内容不同 ⇒ ⭐ **地址真的在选择** ✅ |
| `DUMP-e`~`h` | ⭐ 字段可解出（⭐ axis/inc/kind **往返一致** ✅） |
| ⭐ `DUMP-i` | ⭐⭐ **非干扰性**：⭐ `dump_en=0` ⇒ ⭐ 读口**回到放音指针** ✅ |

⭐ **变异体 `MUT-H`**（⭐ 把 mux 去掉、恒定 `rd_ptr_r`）⇒ 🔴 **3 条红** ✅
📌 ⭐ **注意**：⭐ `DUMP-b/e/g/h` 在变异体下**仍然绿** —— ⚠️ 因为 `rd_ptr_r` 恰好是 0
⇒ ⭐ `mem[rd_ptr_r] = mem[0]` ⇒ ⭐ 地址 0 **巧合相等** ✅
⇒ ⭐ **所以 `DUMP-c`（地址 1）与 `DUMP-d`（两条不同）才是真正抓它的那两条** ✅
📌 ⭐ 这条**值得记**：⭐ "查地址 0"这类判据**天然容易巧合通过** ⇒ ⭐ **必须配一个非 0 的地址** ✅
