### 1.1 ⭐ 为什么这次成了（而前两版不成）

| 维度 | ⭐ 本版 | 🔴 前两版 |
|---|---|---|
| **窗口** | ⭐ **0 拍**（⭐ 提交当拍就绪） | ⭐ ≤1 拍（⭐ 第一版）· ⭐ 0 拍但贵（⭐ 第二版） |
| **那 64 个比较器** | ⭐ **整段不综合**（⭐ 参数是编译期常量） | 🔴 必须留着（⭐ Z-safe 回退 / 阈值变运行时值） |
| **资源** | ⭐ **`T_Lut −131` · `T_Alu −32` · `FF +64`**（⭐ **净赚**）✅ | 🔴 **`T_Lut +2051 ~ +2146`**（⭐ 净亏） |
| **老 tb** | ⭐ **一个都不用改**（⭐ 参数默认 `0` = 老行为）✅ | 🔴 第二版要改 **11 个** tb |
| **语义** | ⭐ 鼓种由"**按的哪个键**"决定，⛔ 不被变调带走 ✅ | ⭐ 同（⭐ 第二版也对，⭐ 就是贵） |

📌 **关键洞察**：⭐ "**参数门控**"是这次唯一走通的路 ——
⭐ 它让"老行为"与"新行为"在**编译期**二选一 ⇒ ⭐ 既保住兼容，⛔ 又**不留下**那 64 个比较器 ✅
（⭐ 前两版都卡在"既要兼容、又要省"这个矛盾上 ✅）
