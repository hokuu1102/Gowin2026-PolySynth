## 一、缺陷

### 链路

```verilog
// rtl/top.v（改前）
wire [2:0] src_a_src = key_drum_r ? 3'd3            // 🔴 键盘打鼓 = SRC_AUX(3)
                      : ((SOURCE_A_SEL == 1) ? 3'd2 : sa_src);
// rtl/top.v:4391 —— 源 B 也是 3'd3
.b_src_i (3'd3),
// rtl/w3b/note_manager.v
assign same_hit[sg] = (gate_r[sg] | retrig_low[sg] | env_active_r[sg])
                    && (axis_r[sg] == cur_axis)
                    && (src_r[sg]  == cur_src);
```

🔴 **同轴 ＋ 同源 ⇒ 判成"同一个键还在响"** ⇒ ⭐ 走**同轴重触发**复用路径
⇒ ⭐ **把用户那个 voice 直接改判/重触发** ✅

⭐ 而 `metronome.AXIS_ID = 14` · ⭐ `drum_gen.AXIS_ID = 15`
⇒ ⭐ 打鼓模式下**轴 14/15 是真实键**（⭐ 踩镲）✅
⇒ 🔴 **每来一拍，轴 14/15 那个音被抢走/打断** ✅
📌 ⭐ 而 `SEL_DRUM = 1`（**鼓机**）是**交付默认档** ✅

### ⚠️ 原注释只承认了"一半"

⭐ `top.v:3838-3841` 的注释原文只写了：

> *"⚠️ **代价（⭐ 已评估）**：⭐ 鼓垫与"源 B（节拍器/鼓机）"**共用保留池**
> （⭐ `RESERVED_N = 5`）⇒ ⚠️ 两者同时响时抢 5 个 voice"*

⇒ 🔴 **它承认的是"资源争用"**（⭐ 池子小），
⚠️ **⛔ 没有承认"共用【标签】⇒ `(轴, 源)` 隔离失效"** —— ⭐ 那是**另一个、更严重的后果** ✅
📌 ⭐ **"抢 5 个 voice"与"直接改判同一个 voice"是两回事**：⭐ 前者是容量、⭐ 后者是**串音** ✅

### ⭐ `top.v` 里【不需要】改的地方（⭐ 已核实，⭐ 这是"零改动"的关键）

⭐ 打击乐包络**不按源判**，⭐ 而是按**保留池索引**：

```verilog
assign perc_trig      = nm_gate[POLY_TARGET-1:RES_BASE] & ~nm_gate_d;          // :4782
assign env_level_mix[POLY_TARGET*16-1 : RES_BASE*16] = perc_level;             // :4817
```

⇒ ⭐ 源 5 既然**进了保留池**（⭐ 改动 ②）⇒ ⭐ **自动拿到 perc 包络** ✅
⭐ 噪声波表也**自动生效**（⭐ `voice_drum_o` ⇒ `oscillator_bank.voice_drum_i` ✅）
⇒ ⭐ **`top.v` 只需改 `src_a_src` 一处** ✅

## 三、⭐ 判据（⭐ 4 个 tb 被牵动，⭐ 每条都"能红"）

### 3.1 ⭐ `tb/w3c/tb_key_drum.sv`（⭐ T2 改值 ＋ **新增 T2b**）

| 判据 | 内容 |
|---|---|
| `T2` | ⭐ 打鼓模式下 `src_a_src == 3'd5`（⭐ 原为 `3'd3` ✅） |
| ⭐ **`T2b`** | ⭐⭐ **`src_a_src !== 3'd3`** —— ⭐ **"必须与源 B 不同标签"** ✅ |

📌 ⭐ **为什么单独立 `T2b`**：⭐ `T2` 只钉"等于 5"，
⚠️ 而**真正的契约**是"**与源 B 不同**" ⇒ ⭐ 后者才是**缺陷的判据** ✅
（⭐ 将来换一个空闲值 ⇒ ⭐ 只改 `T2`，⭐ 而 `T2b` 永远成立 ✅）

### 3.2 ⭐ `tb/w3b/tb_pool_by_src.sv`（⭐ **a7 语义反转** ＋ 新增 a8）

🔴 **本 tb 原来有一条 `a7: unused src code 5 behaves like hand-play`** ——
⭐ 因为写它的时候编码 5 **确实空闲** ✅
⇒ ⭐ 现在 5 = 键盘打鼓 ⇒ ✅ **判据跟着改成**：

| 判据 | 内容 |
|---|---|
| ⭐ **`a7`（新）** | ⭐ 源 5 ⇒ ⭐ **进保留池 ＋ `drum=1` ＋ 拿到 voice** ✅ |
| ⭐ **`a8`（新）** | ⭐ **未使用编码 6/7** ⇒ ⭐ 仍按"未用 = 手弹"（⭐ 普通池 ＋ `drum=0` ✅） |

📌 ⭐ **扫描范围从 `0..5` 扩到 `0..7`** ⇒ ⭐ **"未用编码"的覆盖没有丢，⭐ 只是挪到了 6/7** ✅
📌 ⭐ **`a1`~`a3`（逐位透传）的上界从 `<5` 改成 `<6`** —— ⭐ 因为 5 现在是**已定义**编码，
⭐ `ns_src_w` **必须逐位透传它** ✅

### 3.3 ⭐ `tb/w3b/tb_transpose.sv`（⭐ **新增 T8**）

🔴 **为什么必须单独测**：⭐ `T1`/`T7` **全程**跑在 `semi_cur == 0` 下
⇒ ⚠️ 那时**所有源都 bypass**（⭐ `wr_data_v` 的**第一项**就是 `semi_cur == 0` ✅）
⇒ 🔴 **它们证明不了"源 3/4/5 的源门控"** ✅

⭐ **做法**：⭐ 把 `u_t3on.g_t3.semi_cur` **强成 `+12`** ＋ ⭐ 同一个 `phase_inc`
分别以 **源 0** 与 **源 5** 按下：

```text
INFO T8: semi_cur=+12 | src0 lane=0 inc=006688aa（应【变】）| src5 lane=0 inc=00445566（应【不变】）
  ok  : T8 non-vacuous: src=0 IS transposed while semi_cur=+12
  ok  : T8: src=5 (keyboard drums) BYPASSES transposition -- P1-59
```

📌 ⭐ **lane 号怎么拿**：⭐ `u_t3on` 的 `alloc_voice_o` **没接** ⇒ ⭐ 用 `u_dut`
（⭐ `T3_EN=0`，⭐ **接了** `d_avo` ✅）—— ⭐ 两个实例吃**同一份激励** ⇒ ⭐ 分配顺序一致 ✅

### 3.4 ⚠️ ⭐ 两个**逐位差分** tb：⭐ 随机源收紧（⭐ 如实记录）

🔴 **这是本轮唯一的"判据改动"，⭐ 必须说清**：

⭐ `tb_rot32_diff.sv:230` 原文 `note_src = rv[2:0]` · ⭐ `tb_transpose.sv:710` 原文 `note_src = $random`
⇒ ⭐ 两者都会**随机用到编码 5**（⭐ 以及 6/7 ✅）
⇒ 🔴 而它们的参照是**冻结的旧 `note_manager`**（⭐ 它把 5 归一化成手弹 0 ✅）
⇒ 🔴 **旧参照不可能知道 5 的新语义** ⇒ ⚠️ 随机会撞上 ⇒ **逐位差分必然红** ✅

✅ **契约收紧（⭐ 这是【正确的】契约）**：⭐ 这两个 tb 断言的是

> ⭐ **"ROT32 / T3 重构 ⛔ 不许改变【既有编码 0~4】的行为"** ✅

—— ⭐ 而编码 5 是**新功能** ⇒ ⭐ **它的行为【应当】变** ✅
📌 ⭐ 改动：⭐ `note_src = rv % 5` / ⭐ `note_src = (({$random} % 5) + 5) % 5` ✅
📌 ⭐ **覆盖没有丢**：⭐ 源 5 的新语义由 `tb_pool_by_src.a7` ＋ `tb_key_drum.T2/T2b`
＋ `tb_transpose.T8` 覆盖 ✅
