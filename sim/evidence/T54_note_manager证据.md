## 二、⭐ 过程中抓到的 **3 个真 bug**（全部"语法全对、功能错"）

### bug ① 🔴 `always @(*)` 块"全是常量" ⇒ 仿真器**直接不执行它**

```verilog
always @(*) begin
    for (pi = 0; pi < POLY_TARGET; pi = pi + 1) begin
        if (RESERVED_N == 0)          // ← 默认参数就是 0
            pool_mask[pi] = 1'b1;     // ← 纯常量，不读任何信号！
        ...
```

**现象**：`note_on` 之后 `voice_gate` **恒为 0** ⇒ ⭐ **一个 voice 都分配不出去（按下去完全没声音）**。

**工具给的判据**（⭐ 第一次跑 tb 就抓到）：

```text
warning: @* found no sensitivities so it will never trigger.
```

⇒ 该块**没有任何敏感信号** ⇒ **从不执行** ⇒ `pool_mask` 恒 0。

⚠️⚠️ **最危险处**：**综合器会把常量块正常折叠**（算出"掩码全 1"）
⇒ **仿真与综合行为不一致**（同族 `L66`/70 号）。

✅ **修法**：改 `assign` + `generate` 连续赋值。同一次还发现
**`always @(*)` 对数组元素（`gate_r[i]`）的敏感推断同样不可靠** ⇒ 一并改连续赋值。

### bug ② 🔴 抢占用**严格 `>`** 比年龄 ⇒ 同龄时**选不出任何候选**

所有 voice 同龄时（连续几拍内按满、还没来过 `sample_tick`）⇒ `sel_valid=0`
⇒ ⛔ **静默丢音**。✅ 修法：`>=` + 从高索引往低索引扫（**并列自然取最低索引**）。

### bug ③ 🔴⭐ **重触发压低期间，该 voice"看起来是空闲的"** —— 竞态

`free_mask = ~(gate_mask | env_active)`，而压低时 `gate_mask=0`
⇒ ⚠️ 那 **2 拍窗口内，另一个轴位的 `note_on` 会合法抢走这个 voice**；
紧接着重触发把 gate 抬回 ⇒ ⛔ **把新音符的 voice 又抢回去**。

**现象**：新按的音没声音 / 串音，**只在 2 拍窗口内偶发** ⇒ 上板后**几乎不可能靠听感定位**。

✅ **修法**：引入 `hold_mask` —— 重触发期间该 voice **仍算占用**（`live_mask` 含 hold、
`free_mask` 排除 hold、候选② 排除 hold），只是**对外 gate 表现为 0**（让 ADSR 看到下降沿）。

## 三、⚠️ 另外 **2 处是我 tb 自己的错**（⛔ 不是设计的锅）

| 我的错 | 真相 |
|---|---|
| `run_ticks` 把 `sample_tick` 拉了 **16 个 clk** | 它是**时钟使能**，必须**恰好高 1 拍** ⇒ 我实际跑了 16 倍采样步，包络快 16 倍 |
| 判据方向写反 | ADSR 重起 Attack 是**从 sustain 往峰值爬（上升）**，我写成"应下降"；⚠️ 且默认 `DECAY_STEP=4` 到 sustain 要 **4800 拍**，我只跑 200 拍 ⇒ **根本没到 sustain** |

📌 **教训**：**判据失败时先怀疑"我的时基/假设"，再怀疑被测设计** ——
否则会**把对的代码改坏**（经验库 `C33` / 73 号）。
