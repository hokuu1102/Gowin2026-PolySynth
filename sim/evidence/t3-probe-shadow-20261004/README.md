# 探针 · T3「影子数组」架构 —— ⭐ 比基线还便宜 1417 LUT（2026-10-04）

> **探针名**：`t3-probe-shadow-20261004`（⭐ **只跑综合**，⭐ 全程在 `build/t3-probe/` 的**副本**里，
> ⛔ **没有动 `rtl/`**）
> **起因**：⭐ 用户裁定 B —— ⭐ "先做便宜探针把 T3 可行性钉死"
> **背景**：⭐ 现有「数组 ＋ 32 lane 输出 mux」版 `T3_EN=1` 实测 **布不通**（`PR0004 490` · `CLS 85%`）

---

## 一、⭐⭐ 结论（一句话）

⭐ **存在一条 T3 架构，`T_Lut` 只有 29622 —— 比"关掉 T3"的基线（31039）还低 1417**，
⭐ 而且**彻底没有那个 32 lane 输出 mux**（⭐ 也就是 `PR0004` 的元凶）
⇒ ⭐ **它比现状更容易布通** ✅
⚠️ 代价：⭐ 换档/换八度/换源之后有 **≤32 拍（0.64 µs）的刷新延迟** ⇒ 🔴 **T1 判据会红**
（⭐ 这正是 2026-10-03 就挂起的那个"口径"问题 —— 现在有了**代价数字**）。

## 二、⭐ 三版对照（⭐ 同一份 RTL、同一台机、干净综合）

| 版本 | `T_Lut` | `T_Register` | `T_Alu` | `DSP` | `BSRAM` |
|---|---|---|---|---|---|
| **基线**（`T3_EN=0`，当前交付） | 31039 | 15858 | 6746 | 5 | 30 |
| **数组版**（`T3_EN=1`，⭐ 已证布不通） | 33040（**+2001**） | 16931（+1073） | 6776 | 6 | 30 |
| ⭐⭐ **影子版**（`T3_EN=1`，本探针） | ⭐ **29622（−1417）** | 16928（+1070） | 6771 | 6 | 30 |

⭐ **两条判读**：
1. ⭐ **数组（1024 FF）确实要 +1070 FF** —— ⭐ 影子版与数组版**一样**（⭐ 因为它**保留了数组** ✅）
2. ⭐⭐ **影子版把 LUT 从 33040 拉到 29622（−3418）** ⇒ ⭐ **连"关掉 T3 的基线"都比它高**
   ⇒ ⭐ 说明它**顺带干掉了一块比 T3 本身更肥的东西**（⭐ 见 §三）

## 三、⭐⭐ 为什么反而更便宜（⭐ 机制）

### 3.1 现有数组版的两处浪费

```verilog
// 现有：输出级【每个 lane】都要算一次 base_g（= 八度移位）
for (gp = 0; gp < POLY_TARGET; gp = gp + 1) begin : g_ph_t3
    wire [PHASE_W-1:0] base_g = (base_oct_r == 2'd0) ? phase_r[gp]
                                                     : (phase_r[gp] << base_oct_r);
    assign voice_phase_inc_o[...] = (semi_cur == 0) ? base_g            // ← 32 份移位器
                                  : (src∈{3,4})     ? base_g            // ← ＋ 32 lane mux
                                                    : phase_tr[gp];
end
```
- ⭐ **32 份 per-lane 八度移位器**（⭐ T3 记录 §12.1 实测 **≈2650 LUT**）
- ⭐ **32 lane × 32 位 输出 mux**（⭐ §12 实测 **1025 LUT**，⭐ **`PR0004` 的元凶**）
- ⚠️ 而 `g_t2`（T3 关）**也有那 32 份移位器** ⇒ ⭐ 那 2650 LUT **关不关 T3 都得付**

### 3.2 ⭐ 影子版：把"并行移位"改成"轮转移位"

🔑 **关键观察**：⭐ 现有代码里 `phase_tr[rot_cnt] <= prod_w >>> 15` **本来就每拍都写**
（⭐ `prod_w = rot_base × ratio`，⭐ 而 `rot_base` 已经含八度移位）
⇒ ⭐ **`phase_tr` 早就在跟踪 base 值**（⭐ 只差"选择"这一步）✅
⇒ ⭐ 那么"选择"**挪到写侧**即可 —— ⭐ 写侧**一次只处理一个 lane**：

```verilog
// ⭐ 影子版（本探针）：写侧一个 32 位 mux 搞定
if (rot_ok)
    phase_tr[rot_cnt] <= ((semi_cur == 5'sd0) ||
                          (src_r[rot_cnt] == 3'd3) || (src_r[rot_cnt] == 3'd4))
                       ? rot_base : (prod_w >>> 15);
// ⭐ 输出级只剩连线（⛔ 无 mux、⛔ 无 per-lane 移位器）
assign voice_phase_inc_o[gp*PHASE_W +: PHASE_W] = phase_tr[gp];
```

⭐ **代价对比**：32 lane × 32 位（1024 个 mux ＋ 32 份移位器）
⇒ ⭐ **1 个 32 位 mux**（⭐ 复用 `rot_base`，⛔ 不新增移位器）✅

⭐⭐ **附带治好一个真 bug**：⭐ 变调**每次都从 `phase_r`（base）重算**
⇒ ⛔ **不会像"就地重算"那样把比例反复乘到自己的结果上**（⭐ 那会让 `0→+12` 累积成 ~90× ✅）

## 四、⚠️ 代价：≤32 拍的刷新延迟（⭐ 必须拍板）

⭐ 影子版里 `phase_tr[g]` 是**轮转刷新**的 ⇒ ⭐ 任何"会让某 lane 该用的值变化"的事件，
**最多 32 拍（0.64 µs）后**才反映到输出：

| 事件 | 延迟 | 影响 |
|---|---|---|
| `semi_cur` 变化（⭐ 每 1 ms 走 1 半音） | ≤32 拍 | ⭐ 不可闻（0.64 µs ≪ 1 ms） |
| `base_oct_r` 换八度 | ≤32 拍 | ⭐ 不可闻 |
| `pitch_upd`（滑音/颤音） | ≤32 拍 | ⭐ 不可闻（⭐ 颤音更新间隔 ~328 µs） |
| ⭐ `note_on` 新音 | ≤32 拍 | ⭐ 起音时包络 ≈ 0 ⇒ 不可闻 |
| 🔴 **T1 判据**（`semi==0` ⇒ **逐拍逐位恒等**） | — | 🔴 **会红**（⭐ 判据是逐拍的） |

🔴 **所以必须选一个**（⭐ 与 2026-10-03 的 D1 是同一个问题，⭐ 但现在有数字了）：

| 选项 | 内容 | 代价 |
|---|---|---|
| **①** ⭐ 允许"换档/换八度/换源后 **≤32 拍不计**" | 改 T1 的**比较窗口**（⭐ 注释里写清原因） | ⚠️ 判据强度下降（⭐ 但 0.64 µs 听觉上为 0） |
| **②** 判据不放宽，**只改激励**：tb 只在**静音时**换档/换八度 | ⛔ 不再覆盖"演奏中换档" | ⚠️ 覆盖场景变窄 |
| **③** 放弃 T3 | 保持现状 | ⭐ 不交付变调 |
