# 修复改动二次审查

比较基点为 `c6b9aad`，首轮修复提交为 `a04c187`。两个独立审查者分别检查仓库规范和原始问题要求。原审查证据保留在 `review/`，不作为修复后通过证据。

## Standards

未发现新增的硬性编码规范违规。发现全局 16 个槽位仍会丢弃第 17 次相同 ON：把独立指引身份直接当作引用数量，导致重复 ON 容量不足。该复现已修复：相同身份的重复 ON 使用 32 位计数；新增 65,536 次 ON、65,535 次 OFF 的回归，剩余引用仍保持点亮。

边界说明：当前浏览器按音符区间分配旋律轴 0..11，超过 12 路会报告抢轴；历史 `tools/mid2evt.py` 仍按轨道分轴。指引模块支持 16 个不同的未结束映射身份，重复引用单独计数。没有把有限硬件容量写成无限制支持。跨映射的同轴同音重复事件采用确定的首个匹配身份消费规则，帧格式没有单独的 ON 实例编号。

## Spec

发现 Python 导出把所有鼓的关闭状态合并到 `(channel=9, axis=0)`。实测 Kick ON、Snare ON、Kick OFF 后没有补发 Snare OFF。已按鼓型保留独立身份，并对重叠鼓及截断录制补 OFF 做生产代码回归。

进一步将导出改为带轨名的 Format 1：BASS、GUITAR、PIANO、PAD、Drums。测试覆盖真实 Python 解析/导出，再交给真实网页灌谱转换代码，四种音色和四件鼓均保留；旧固件压缩到同轴的和弦按 OFF 音高配对。

HDMI 时序由原生 Gowin 报告单独验收，审查者的静态判断没有替代物理验证。
