#### 9.1.1 ⭐⭐ 2026-09-17 补齐：**DAC 型号与 I2S 帧格式**（`K-24` 结案）

| 项 | 结论 | 依据 |
|---|---|---|
| **板载 DAC 型号** | 🔴 **旧（NEO Dock）**：`PT8211-S` + 功放 `NS4263`<br>⭐ **新（Console 60K）**：**`MAX98357A`**（⭐ **I2S 输入 + DAC + D 类功放三合一**，⛔ 不是两颗） | Console 原理图 `AUDIO.kicad_sch`；旧记录来自 Dock 原理图 `DAC+PA.kicad_sch` |
| **数据位宽** | ⭐ **16 bit / 声道**（声明的"有效位" = 16） | 官方例程 `audio_drive.v` 注释：**"每个采样点占 32 个 BCK（左右声道各 16）"** |
| **帧结构** | ⭐ **每帧 32 个 BCK = 左 16 + 右 16** | 同上 |
| **帧极性 / 位序** | 🔴 **旧（PT8211-S）**：**LSBJ（日本格式）= 右对齐** ⇒ `JUSTIFY=1`<br>⭐ **新（MAX98357A）**：**标准 I2S / 左对齐**（MSB 延迟 1 BCK）⇒ ⭐ **`JUSTIFY=0`** （⚠️ 已改，见 `rtl/top.v` 的 `i2s_tx` 例化） | ⭐ Console 原理图 + `MAX98357A` 手册；⚠️ **换板后必须改**，否则整体移位 |
| **物理 MCLK** | ⛔ **不需要**（⭐ 两块板都不需要；`MAX98357A` 也不要 MCLK） | 原理图 + `.cst` 只有 BCK/WS/DIN/PA_EN 四根 |
| **`PA_EN` 极性** | 🔴 **旧（NS4263）**：**低有效 + 一线脉冲控制**（1 个下降沿 = AB 类）<br>⭐ **新（Console）**：🔴 **`PA_EN` = `MAX98357A` 的 `SD_MODE`** —— ⭐ **< 0.16 V = `Shutdown`（没声音）**、0.16~0.77 V = (L+R)/2、0.77~1.4 V = Right、**> 1.4 V = Left**<br>⇒ ⭐ **要出声必须驱动【高】**，⛔ 不是低 | ⭐ 原理图 `AUDIO.kicad_sch` + [`MAX98357A` 手册表](https://learn.adafruit.com/adafruit-max98357-i2s-class-d-mono-amp/pinouts)；⚠️ `SD_MODE` 内部有 **100 kΩ 下拉** ⇒ 悬空也是 `Shutdown` |
| **官方例程的 BCK** | 约 1.5 MHz（用 **PLL + CLKDIV** 凑的"1.536 MHz 近似时钟"，≈46.9 kHz fs，只为出声） | 官方例程的 `top.v`。⭐ **我们音频通路不用 PLL** —— 用 50 MHz 整数分频（见 `files/20-代码/W3接口冻结表.md` §二）。⚠️ 边界见 `K-41`/`K-114`：⛔ 禁的是"PLL 做全设计系统时钟"，✅ 外设时钟（如 HDMI 像素时钟）可用 PLL |

> ⭐ **对我们 RTL 的直接结论**（`K-39` 已结案，⭐ **2026-09-22 按 Console 更新**）：
> · 🔴 **旧（PT8211-S，NEO Dock）**：**LSBJ 右对齐** ⇒ `JUSTIFY=1`
> · ⭐ **新（MAX98357A，Console）**：**标准 I2S 左对齐** ⇒ ⭐ **`JUSTIFY=0`**（✅ 已在 `rtl/top.v` 改）
> · ⭐ 我们冻结的 **`BCLK = 3.125 MHz = 64 × fs`**（每声道 32 BCK）**两块板都能照用**：
>   ⚠️ 旧板 PT8211 在时隙里**塞 8 个空闲 BCK 照样正常** ⇒ **DAC 容许时隙里多出的 BCK**；
>   ⭐ 新板 `MAX98357A` 也是"读 32 个 BCK、取其中有效位"，⭐ 同样没问题。
> ⇒ ⛔ **`M0` 的 BCLK/LRCLK 数字不用改**。
> 🔴 **但 `PA_EN` 必须改**：⭐ 脚（`AB16`→**`Y14`**）+ ⭐ 极性（低→**高**）+ ⚠️ 电平（`LVCMOS15`）。

## ⭐⭐ `V22` = 50 MHz：**已查实**（2026-09-17，三处独立证据一致）

> **为什么专门查**：`sys_clk = 50 MHz` 原来在仓库里是**断言、没标出处**；
> 而 Dock 原理图 `/SYS_CLOCK/` 页（第 18 页）上 `V22` 附近有 **`100MHz`** 标签
> ⇒ ⚠️ **存在"实际是 100 MHz 而我们按 50 约束"的风险**（若真如此，则
> `fs`、`BCLK`、`LRCLK` 全部差 2 倍，**且时序分析会乐观一倍**）。⇒ 必须查实。

| # | 证据（**官方原件**） | 结论 |
|---|---|---|
| **1** | 官方例程 `cam_dvi/src/TMDS_60HZ.sdc` 第 1 行：<br>`create_clock -name clk -period 20 -waveform {0 10} [get_ports {clk}] -add` | ⭐ **period 20 ns = 50 MHz** |
| **2** | 官方例程 `cam_dvi/src/NEO_DOCK.cst`：`IO_LOC "clk" V22;` | ✅ `clk` 就是 `V22`，**与我们的 `.cst` 逐字一致** |
| **3** | 官方 PLL：`TMDS_PLL_60HZ.v` 与 `SDRAM_PLL.v` **都**写 `defparam PLLA_inst.FCLKIN = "50";` | ⭐ 两个**独立**例程都声明输入 50 MHz |

⭐ **而且第 1 条能自证**：同一份 `.sdc` 里把 TMDS 时钟定义为
`divide_by 200 -multiply_by 297` ⇒ `50 × 297/200 = **74.25 MHz**`（**标准 720p TMDS 时钟**）。
⚠️ 若输入真是 100 MHz，这条会算出 **148.5 MHz**（1080p 的时钟），**DVI 例程就会点不亮**
⇒ ⭐ **反证 `V22` 必是 50 MHz**。

> ✅ **结论**：我们的 `constr/top.sdc`（`-period 20 -waveform {0 10}`）**与官方完全一致**，
> ⛔ **不需要改**。原理图上那个 `100MHz` 标签**不属于 `V22`**（见下）。

### ⭐ 板上还有哪些"高速时钟源"（**都不是给用户逻辑用的**）

原理图第 18 页标题 `/SYS_CLOCK/`，板上有：

| 器件 | 说明 | 用途 |
|---|---|---|
| **`U7` `MS5351M`** | ⭐ **可编程时钟发生器**（由 **25 MHz 晶振 `Y1`** 驱动，**I2C 控制** `DBG_TWI.SCL/SDA`） | Sipeed wiki：*"Provides **RefClk for Serdes**; control output via onboard UART"* ⇒ ⭐ **主要为 SerDes/PCIe 提供参考时钟** |
| `Y125MHz` | 独立 125 MHz 振荡器 | 多为以太网/SerDes 参考 |
| `AB12` `USR_CLK_IN` | 外部时钟输入 | ⚠️ **在 `BANK9`，必须约束为 `1V5`**（对我们不友好） |
| 网络标签 | `100MHz` / `210MHz` / `125MHz` / `50MHz` / `100MHz X4 PCBEdge` | ⚠️ 这些是**板上其它时钟网络**的名字（SerDes / PCIe / 以太网），⛔ **不是 `V22` 的频率** |

⇒ ⭐ **结论：`V22` 是板上给用户逻辑的 50 MHz 时钟，与那些高速网络无关。**
**我们继续用 50 MHz，不用改任何东西。**

## 三、那个 3.5 mm 耳机口：现有资料判断不了，但有强线索

### 线索：现有页里能看到的 I2S，全部源自 **CPU 的 HDA 控制器**

```text
I2S_BCLK  ← LS2K_HDA_BITCLK
I2S_LR    ← LS2K_HDA_SYNC
I2S_DI    ← LS2K_HDA_SDI0
I2S_DO    ← LS2K_HDA_SDO
I2S_MCLK    （与 LS2K_HDA_* 同组）
LS2K_HDA_RESETN
```

这些出现在核心板 **Sheet 2/19（GPIO/EJTAG/CAN/RS232/485）** 的连接器上 ——
**它们是 CPU 的音频，不是 FPGA 的。**

### 三种可能（按可能性排序）

| 情况 | 判断依据 | 后果 |
|---|---|---|
| **A. 耳机口由 CPU 的 HDA codec 驱动**（**推断为最可能**） | 缺页里应有 codec 与耳机座；现有页找不到任何 codec/耳机座位号 | ⛔ **FPGA 用不了它**（codec 挂在 CPU 的 I2S 上）；⛔ 且**音频走板载 CPU 是赛题明令禁止的** |
| **B. 耳机口直连 FPGA 引脚（带 RC）** | 现有页无此证据 | 可用，但是 **1-bit PWM/ΔΣ**，**不是赛题要的 I2S→DAC** |
| **C. 耳机口只是引出，无 codec** | 现有页无此证据 | 可用，但仍须自己补 I2S DAC |

> ⚠️ **不论哪种，都不该把那个耳机口当成最终音频输出。**
> 最终产物是**自制板**，链路必须是**我们自己的 I2S → DAC**（赛题硬要求）。

## 六、⭐ 最小上板验证需要哪些引脚（只测音高与音色，不接任何输入）

> ⭐ **结论先行：只需要 1~4 根音频输出引脚**（`clk` / `rstn` 已知，不算在内）。

### 6.1 为什么这么少：音高与音色**不需要输入**

这是容易被想复杂的地方 —— **采集链跟"音高/音色验证"完全无关**。

| 要素 | 需要外部输入吗 | 说明 |
|---|---|---|
| **音高** | ⛔ 不需要 | 音高 = 相位增量 × fs / 2^N，**内部给增量就行** |
| **音色** | ⛔ 不需要 | DDS 波形表 / 谐波系数，**内部参数** |
| **ADSR** | ⛔ 不需要 | 内部包络 |
| **复音叠加** | ⛔ 不需要 | 内部同时起多个 Voice |
| 力度 / 滑音 / 触发 | ✅ 需要 | **但这轮不测**，留给左手区 |

**所以⛔这轮不接**：磁轴 · 霍尔 · ADC（SPI×3 + CS×3）· 按键 · 拨弦件 · 推子 · LED · 串口屏 · 推子。
**一个都不接。**

### 6.2 需要的引脚（按板上耳机口的形式分三种）

| 板上耳机口怎么接的 | 需要的引脚 | 数量 |
|---|---|---|
| **A. 板上自带 I2S DAC 芯片** | `I2S_BCLK` · `I2S_LRCLK` · `I2S_DIN`（可选 `I2S_MCLK`） | **3~4 根** |
| **B. FPGA 引脚 PWM 直出 + RC** | `PWM_AUDIO` | **1 根** |
| **C. 板上无 DAC，外接模块** | 同 A（走排针） | 3~4 根 |

**加上已知的 `clk`/`rstn`，合计 5~6 根。** 对比整机的 ~25 根 IO，这是零头。

> ⭐ **如果板上耳机口本来就是 FPGA 接的，那这几根引脚很可能已经在板上连好** ——
> 这时"引脚分配"其实只是**从原理图/示例工程里查出它们的器件 pin 编号**，
> 而不是去挑新引脚。这是当前唯一要查的东西。

### 6.3 没有输入，怎么让它出声？

用一个**自走测试音源**（全部在 FPGA 内部，不占引脚）：

| 做法 | 效果 |
|---|---|
| **自走音阶** | 内部计数器每 0.3~0.5 s 换一个音（C-D-E-F-G-A-B-C…），配合 ADSR 每音都有起音 → **能听出音高准不准** |
| **音色轮换** | 每几秒切一种音色（正弦 / 方波 / 锯齿 / 波表）→ **能听出音色差异** |
| **复音测试** | 间隔触发多个 Voice，或直接常开 4/8/16/32 个音 → **能听出叠加与是否削波** |
| **滑音扫描** | 相位增量线性爬升 → 听连续滑音（能听出有没有跳变/咔哒） |

> 这样**完全不接任何外设**，就能把音高精度、ADSR 形状、音色、复音数、混音削波全部测一遍。
> 等这些稳了，再去接左手区才有意义 —— 否则分不清"是采集错了还是合成错了"。

### 6.4 看波形：不需要额外引脚，但 ADDA 模块要慎用

**⭐ 关键：示波器看波形不需要 FPGA 引脚。** 只要有**一个模拟输出点**，探头夹上去就行：

| 想看什么 | 怎么接 | 额外引脚 |
|---|---|---|
| **模拟音频波形** | 示波器探头夹 DAC 的模拟输出（或耳机口） | **0 根** |
| **PWM 输出** | 探 FPGA 的 PWM 引脚（经 RC 前后各一个点更好） | **0 根**（探已有信号） |
| **I2S 三线时序** | 3 个探头夹 `BCLK`/`LRCLK`/`DIN` | **0 根**（探已有信号） |

⚠️ **ADDA 模块（SMA 接口）在音频这件事上是"用错了工具"**：

| 问题 | 说明 |
|---|---|
| **接口不匹配** | SMA 插不了音响 —— 它天生是给**示波器/频谱仪**用的，不是音频输出 |
| **要占很多 IO** | 这类模块通常是**并行接口**（12~14 位数据 + 时钟 + 使能），为一件事占用十几根引脚很不划算 |
| **带宽过剩** | 音频只要 48 kHz，而它常是几十 MHz 级 —— 属于"大炮打蚊子" |
| **另需适配** | 往往配套特定开发板，引脚定义得对上 |

> **什么时候它才值得用**：要看**高速数字波形**、或做信号处理实验（如 FFT 频谱验证）。
> **单纯听声音 / 看音频波形**，用 I2S DAC 模块 + 一个探头就够了。

| ⛔ | 原因 |
|---|---|
| **用 FPGA 的 IO 直驱耳机** | 32 Ω 负载远超 IO 驱动能力 —— 音量极小，且**有烧 IO 风险**。直出也必须经 RC 或放大电路 |
| **让音频经过板载 CPU（`LS2K1000`）** | **赛题明确禁止**（见 README「明确不做」：使用板载 CPU 参与音频通路不合规） |
| **在缺页的情况下猜耳机口接线** | 猜错就白费功夫；先把资料补齐 |
| **把这块板的 `.cst` 直接搬到赛题板** | 芯片相同但**封装引出/布线不同**，约束必须重写 |

---

## 八、待确认项

| # | 问题 | 影响 |
|---|---|---|
| 1 | 能否拿到核心板完整原理图（3~13 页） | 决定耳机口能否被证实/排除 |
| 2 | 能否拿到 `.cst` / GPIO 对照表 | ⚠️ **只挡"上板"**（不挡资源评估与音色仿真，见 §5.1） |
| 3 | 扩展板上有没有暴露 FPGA IO 的 2.54 mm 排针 | 决定接 DAC 的物理可行性 |
| 4 | 这块板是否就是赛题适配板本身 | 若是，则整套资料可直接复用，风险大降 |
| 5 | **ADDA 模块的型号与接口**（并行/I2S？位数？采样率？供电？） | ⭐ 若它的 DA 部分能收 FPGA 数据，**就省掉买 DAC**，还能直接接示波器看波形 |
