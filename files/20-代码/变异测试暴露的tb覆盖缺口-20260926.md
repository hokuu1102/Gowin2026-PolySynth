# 🔴 变异测试暴露的 tb 覆盖缺口（2026-09-26 凌晨）

> ⭐ **来源**：⭐ 对新增的 `seq_arb` / `drum_gen` 跑变异测试（`M118~M125`）
> **结论**：🔴 **发现 2 个 LEAK** ⇒ ⭐ **`tb_drum_gen` 的判据有缺口**（⛔ 不是 RTL 的错）

---

## 〇、⭐⭐ 一句话

```
🔴 `M123` 和 `M124` 都 **GREEN(LEAK)** —— ⭐ 变异体改了 RTL，🔴 **但我的 tb 没变红**
⇒ ⚠️ 说明 `tb_drum_gen` 【漏测了两条路径】：
   · ⭐ `transport` 门控（停了还敲）
   · ⭐ `bar_start` 小节对齐（跑飞失相）
📌 **这正是变异测试的价值** —— ⚠️ 它证明了"我的 tb 以为自己测了，其实没测"。
```

---

## 一、🔴 M123 LEAK：`transport` 门控没被守住

| ⭐ 项 | ⭐ 内容 |
|---|---|
| **变异** | ⭐ `wire fire = has_pending & transport_i;` ⇒ 🔴 `wire fire = has_pending;` |
| **后果** | ⭐ transport 拉低后**鼓机还在敲**（⛔ 停不住） |
| **我的判据** | ⭐ "②b transport 拉低 ⇒ 立刻停发" —— ⭐ **写了但没抓到** |
| 🔴 **为什么没抓到** | ⭐ 我的 tb 在那一步**先把 `pending_q` 清空了**（`if (!transport_i) pending_q <= 0`）<br>⇒ ⚠️ 即使 `fire` 不看 `transport`，⭐ **`has_pending` 已经是 0** ⇒ ⭐ `fire` 仍为假<br>⇒ 🔴 **两条路径【互相掩盖】**：⭐ 变异只拆了一条，另一条还在兜底 |

⭐ **修法**：⭐ **在 transport 拉低的当拍【正好有 pending】** ⇒ ⭐ 必须真的发不出来。

---

## 二、🔴 M124 LEAK：小节对齐没被守住

| ⭐ 项 | ⭐ 内容 |
| --- | --- |
| **变异** | ⭐ `wire step_zero_align = transport_i & bar_start_i;` ⇒ 🔴 `= 1'b0;` |
| **后果** | ⭐ 小节起点**不再强制回到 step 0** ⇒ ⚠️ 步进器**自由跑、会漂移** |
| **我的判据** | ⭐ "② 16 步 = 1 小节" —— ⚠️ **它只跑了一小节就检查总数** |
| 🔴 **为什么没抓到** | ⭐ 跑**一小节**时，⭐ 内部的 16 步计数器**恰好也走满 16 步**<br>⇒ ⚠️ **"对齐"和"没对齐"在一小节内看不出差别**<br>⇒ 🔴 **必须跑【多小节】+ 且让相位错开**才能暴露 |

⭐ **修法**：⭐ 跑 **≥2 小节**，⭐ 检查"**每个 `bar_start` 时刻 `step_cnt` 必须是 0**"。

## 二之二、🔴 `M121` LEAK：分源计数【接了但从没断言】

| ⭐ 项 | ⭐ 内容 |
|---|---|
| **变异** | ⭐ `wire [NW-1:0] pop_src = pop_data[ENT_W +: NW];` ⇒ 🔴 `= 2'd3;`（非法源 id） |
| **后果** | ⭐ 每条弹出都算成"未知源" ⇒ 🔴 **`live_cnt`/`score_cnt`/`demo_cnt` 三个计数全不涨** |
| 🔴 **真因** | 🔴 **三个信号【接了但从没断言】** —— ⭐ `tb_seq_arb` 里**接上了**（第 50/67 行），⚠️ **却一条判据都没用它们** |
| ✅ **修法** | ⭐ 新增判据 ⑪：⭐ 各发**确定条数**（手弹 3 / 曲谱 2 / 演示 2）⇒ ⭐ **三个计数必须分别对得上** |
| ✅ **验证** | ⭐ 注入 `pop_src=2'd3` ⇒ **FAIL ⑪**；⭐ 原版 ⇒ **PASS（12 条）** |

## 二之三、🔴🔴 `M116` LEAK：外置 DAC 那路（⚠️ **最深刻的一条**）

| ⭐ 项 | ⭐ 内容 |
|---|---|
| **变异** | ⭐ 外置那路的 `sample_l` 改成**全 0** |
| **后果** | ⭐ 时钟全对、⭐ 模块"正常"、🔴 **输出纯数字静音** = **外置音箱永远没声**<br>📌 这是"route A"**最危险**的失败：⭐ **看着全活、就是没声** |
| 🔴 **真因（⭐ 两层）** | **① 锚点撞车**：⭐ `.sample_l (sample_mono),` 在 `top.v` 里出现 **2 次**<br>　⇒ ⭐ `.Replace()` 把**板载与外置【一起】**变了 0<br>　⇒ 🔴 **"0 == 0" 仍成立** ⇒ ⭐ 我那条"逐拍一致"判据说"一致"，⚠️ **却什么都没验到**<br>**② 更根本**：⭐ `tb_top_m0` 是 **M0 静音档**（`DEMO_CHORD_ON=0`）<br>　⇒ ⭐ 两路 `DIN` **本来就都是 0** ⇒ 🔴 **它【原理上】测不了"音频内容"** |
| ✅ **修法（⭐ 两层）** | **a.** ⭐ 在 **`tb_top_sound`（出声档）** 新增第 5 组判据：⭐ 外置三线**活动量** + ⭐ **与板载同活动量** + ⭐ 逐拍一致<br>**b.** ⭐ `tb_top_m0` 的 J 组改成**档位感知**：⭐ 时钟线必须动；⭐ `DIN` 只要求**与板载同活动量** |
| ✅ **验证** | ⭐ 注入 ⇒ **FAIL 2 条**（活动量不等 + 逐拍不一致）；⭐ 原版 ⇒ **PASS**<br>📌 **实测证据**：⭐ `I2S2_DIN 翻转 = 21202` 拍 ⇒ ⭐ **外置那路确实携带真实音频** |

## 二之四、⭐⭐⭐ 三条一般化教训（⭐ 值得进经验库）

```
① 🔴 **"写了判据" ≠ "判据真能抓到"**
   四处 LEAK 都是【判据存在、但构造不出差异】：
      · 兜底路径互相掩盖（M123）
      · 观察窗口太短（M124）
      · 接了输出却从不断言（M121）
      · 在"静音档"里要求"有声"（M116）
   ⇒ ⭐ **回归全绿 + 判据齐全，🔴 保护力仍可能是 0**。

② 🔴🔴 **"一致性"判据有【固有盲区】：两边一起坏，它就看不出来**
   ⭐ M116 正是这类 —— ⚠️ 判 "A == B"，⭐ 而变异把 A 和 B **一起**变成了 0
   ⇒ ⭐ **必须补一条"绝对判据"**（⭐ "A 必须真的在动"）
   📌 **通用形式**：⭐ **相对判据（一致性）+ 绝对判据（活动量）= 才完整**。

③ 🔴 **判据要匹配【当前档位】**
   ⚠️ 我第一版在 M0 **静音档**里要求 `DIN` 必须翻转 ⇒ 🔴 **误报原版 FAIL**
   ⭐ 而 M0 的设计意图**恰恰是"静音就是真静音"**（⭐ E 判据）
   📌 ⭐ `R-16`/`K-69` 同族：⭐ **"测试配置"与"交付默认值"要分开**。
```

## 三、⭐⭐ 教训（⭐ 值得进经验库）

```
🔴 **"我写了那条判据" ≠ "那条判据真的能抓到"**
   ⚠️ 两条 LEAK 都是【判据存在、但构造不出差异】：
      · M123: ⭐ 两条兜底路径【互相掩盖】⇒ 只拆一条看不出来
      · M124: ⭐ 观察窗口太短 ⇒ 差异还没显形就测完了
📌 **这正是变异测试不可替代的原因** ——
   ⚠️ 回归全绿 + 判据齐全，🔴 **但实际保护力是 0**。
⭐ **同族**：⭐ `U-18b`（`play_seq` "16 判据全过、变异体 4/4 全抓"，
   🔴 但 `tick` 字段从没被测）—— ⭐ **同一个病**。
```
