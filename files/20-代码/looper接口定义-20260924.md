## 一、⭐⭐ 它在事件链里的位置（⭐ 上游文档 §一 的图，⭐ 我把它接成代码）

```
⭐ 上游设计的一句话：
   「looper 旁路监听 live_evt，⭐ 重放时把事件送进 evt_merge」
   「叠加 = 两条事件流 OR 起来」

⭐ 落到 top.v 的接法（⭐ 本文的新内容）：

   w3a_evt (手弹) ──┬──> 【looper 的 live 监听口】（⭐ 只读，⛔ 不改流）
                    │
                    └──> evt_merge.源 A        ← ⭐ 现状
   looper.play ─────────> 【?】                 ← 🔴 问题：evt_merge 只有 a/b 两个入口！
```

### 1.1 🔴 **接口缺口：`evt_merge` 入口不够用**

⭐ **实测 `evt_merge` 的接口**（`rtl/w3c/evt_merge.v:66-78`）：
```verilog
// 源 A：手弹 / 曲谱
// 源 B：节拍器 / 鼓机
```
⇒ ⚠️ **两个入口已经排满**：
| 源 | ⭐ 现在 | ⚠️ 将来 |
|---|---|---|
| **A** | 手弹（⭐ `SOURCE_A_SEL=0`） | ⚠️ **+ 曲谱**（见 `曲谱通路接入设计`） |
| **B** | 节拍器 | ⚠️ **+ 鼓机** |

🔴 **再加上 looper ⇒ 需要 4 路** ⇒ ⚠️ **必须扩 `evt_merge`**。

### 1.2 ⭐ **但有一个更省的做法（⭐ 我建议这个）**

⭐ **洞察**：⭐ **looper 的重放事件与"手弹事件"在语义上是同一类** ——
⭐ 都能走**源 A**（⭐ 上游文档 §一 的图里，`looper` 的输出**就是接到 `evt_merge` 的同一个口**）。

```
⭐ 做法：⭐ 在【进 evt_merge 之前】用 XOR/OR 合流：

   live_evt  ──┬──────────────────────┐
               │                      ├──> 【二选一仲裁】──> evt_merge.源 A
   looper.play ┘                      │
                                      │
   ⚠️ 但"手弹 + loop 同时" ⇒ 🔴 **同拍两条 ⇒ 会相撞！**
```

⇒ 🔴 **这正是 `evt_merge` 存在的理由**（⭐ 它专治"同拍相撞丢事件"，⭐ `U-6`/`M64~M68`）。

⭐ **所以正解是**：⭐ **让 `evt_merge` 变成 3 路**（⭐ 或把 looper 挂到源 B 的"空位"）。

## 二、⭐⭐ 建议的接口（⭐ `looper.v`）

```verilog
module looper #(
    parameter integer AXIS_W    = 4,
    parameter integer PHASE_W   = 32,
    parameter integer VEL_W     = 8,
    parameter integer KIND_W    = 2,
    parameter integer TICK_W    = 20,      // ⭐ 与事件位域一致（play_seq契约 §1.1）
    // ── 容量（⭐ 上游设计 §2.4 已估算）────────────────────────────────
    parameter integer LAYERS    = 3,       // ⭐ 3 层（贝斯/吉他/钢琴）
    parameter integer EVT_MAX   = 2048,    // ⭐ 每层事件上限（⚠️ 已拍板 2048/层 × 3 层）
    // ── 与 note_manager 的配额（⭐ 上游 §7.1）──────────────────────────
    parameter integer LIVE_RESERVE = 8,    // ⭐ 只给现场演奏的 voice 数
    parameter integer LOOP_QUOTA   = 8     // ⭐ 每层配额（⚠️ 三层层合计须 ≤ 27-8）
) (
    input  wire                    clk_i,
    input  wire                    rst_n_i,

    // ══════════════════════════════════════════════════════════════════
    // ① 音乐时钟（⭐ 来自 beat_gen）
    // ══════════════════════════════════════════════════════════════════
    input  wire                    tick_i,        // ⭐ PPQN tick 脉冲
    input  wire [TICK_W-1:0]       tick_cnt_i,    // ⭐ 小节内 tick 计数
    input  wire                    bar_start_i,   // ⭐ 小节起点
    input  wire                    transport_i,   // ⭐ run 状态

    // ══════════════════════════════════════════════════════════════════
    // ② ⭐ 手弹事件【旁路监听】（⭐ 只读！⛔ 不改动这条流）
    //    ⚠️ **关键**：⭐ 这几根线是"监听"⇒ ⭐ looper ⛔ 不许驱动它们
    // ══════════════════════════════════════════════════════════════════
    input  wire                    live_valid_i,  // ⭐ 手弹事件（单周期）
    input  wire [AXIS_W-1:0]       live_axis_i,
    input  wire [PHASE_W-1:0]      live_inc_i,
    input  wire [VEL_W-1:0]        live_vel_i,
    input  wire [KIND_W-1:0]       live_kind_i,

    // ══════════════════════════════════════════════════════════════════
    // ③ ⭐ 重放输出（⭐ → `evt_merge`，⚠️ 见 §一 的入口讨论）
    // ══════════════════════════════════════════════════════════════════
    output reg                     play_valid_o,  // ⭐ 单周期脉冲
    output reg  [AXIS_W-1:0]       play_axis_o,
    output reg  [PHASE_W-1:0]      play_inc_o,
    output reg  [VEL_W-1:0]        play_vel_o,
    output reg  [KIND_W-1:0]       play_kind_o,

    // ══════════════════════════════════════════════════════════════════
    // ④ 控制（⭐ 每层独立的 rec/play/clear）
    //    ⚠️ 上游 §3.2 有每层状态机 ⇒ ⭐ 这里给"命令口"
    // ══════════════════════════════════════════════════════════════════
    input  wire [LAYERS-1:0]       rec_req_i,     // ⭐ 开始录制（单周期）
    input  wire [LAYERS-1:0]       stop_req_i,    // ⭐ 停止录制（⭐ 会补发 note_off）
    input  wire [LAYERS-1:0]       play_en_i,     // ⭐ 播放使能（电平）
    input  wire [LAYERS-1:0]       clear_req_i,   // ⭐ 清空该层

    // ══════════════════════════════════════════════════════════════════
    // ⑤ ⭐⭐ 可观测性（⭐ `K-106`：⛔ 不许静默失效）
    // ══════════════════════════════════════════════════════════════════
    output wire [LAYERS-1:0]       layer_state_o, // ⭐ 每层状态（1 bit 编码：0=空闲 1=录/放）
    output wire [15:0]             evt_cnt_o      [0:LAYERS-1], // ⚠️ 见下方注
    output wire [LAYERS-1:0]       full_o,        // ⭐ 该层事件满（⭐ 再录会丢）
    output wire [15:0]             drop_cnt_o,    // ⭐ 丢了几个事件（饱和）
    output reg                     overflow_o     // ⭐ sticky，复位清
);
```

### 2.1 ⚠️ **三个接口细节必须注意**

| # | 细节 | ⚠️ 为什么 |
|---|---|---|
| **1** | ⭐ **`live_*` 是【只读监听】** | ⚠️ 若 looper 也去驱动这条线 ⇒ 🔴 **与 `w3a` 打架** |
| **2** | ⚠️ **`evt_cnt_o` 用数组端口不可综合** | 🔴 **Verilog-2001 ⛔ 不支持数组端口** ⇒ ⭐ 必须**展平成一个向量**：<br>`output wire [LAYERS*16-1:0] evt_cnt_flat_o`（⭐ 每层 16 bit） |
| **3** | 🔴 **`full_o` 必须有** | ⭐ 上游 §3.3 说"防挂音是最容易出错的地方" ⇒ ⚠️ 但**"录满了"也要能看见**（⭐ 否则静默丢事件） |

## 三、⭐⭐ 与 `evt_merge` 的接法（⭐ 本文件的核心贡献）

### 3.1 ⭐ 建议：**把 `evt_merge` 扩到 3 路**（⭐ 但分两步）

| 步 | 做什么 | ⚠️ 为什么分步 |
|---|---|---|
| **1** | ⭐ **先做"looper 单层 + 与手弹互斥"**（⭐ 方案 A） | ⭐ ⛔ **不动 `evt_merge`** ⇒ 风险最低 |
| **2** | ⭐ 验通后再**扩 `evt_merge` 到 3 路**（⭐ 方案 B） | ⭐ 那时"边 loop 边弹"才有明确需求 |

### 3.2 ⭐ 方案 A：**looper 走源 A，与手弹二选一**（⭐ 起步用）

```verilog
// ⭐ 源 A 仲裁扩一档（⭐ 与 `曲谱通路接入设计` 的改法同构）
//   SOURCE_A_SEL: 0=手弹 · 1=演示和弦 · 2=曲谱 · 🔴 3=looper 重放
wire src_a_valid = (SOURCE_A_SEL == 3) ? looper_play_valid :
                   (SOURCE_A_SEL == 2) ? eu_evt_valid :
                   (SOURCE_A_SEL == 1) ? demo_note_valid : w3a_evt_v;
```

⚠️ **代价**：🔴 **looper 播放时弹不了琴** ⇒ ⚠️ **"边 loop 边弹"（`T39`）做不到**。

### 3.3 ⭐⭐ 方案 B：**`evt_merge` 扩到 3 路**（⭐ 最终形态）

```
⭐ evt_merge 加一个输入口（源 C）：
   源 A = 手弹 / 曲谱（⭐ 仍按 SOURCE_A_SEL 仲裁）
   源 B = 节拍器 / 鼓机
   源 C = 🔴 **looper 重放**
```

⚠️ **改动清单**：
| # | 改什么 | ⚠️ 注意 |
|---|---|---|
| **1** | ⭐ `evt_merge.v` 加源 C 的 5 个输入 | ⚠️ **已落地模块** ⇒ 要重跑 `tb_evt_merge`（8 条判据）|
| **2** | ⭐ **轮转仲裁从 2 路扩到 3 路** | ⚠️ 现在的写法是 `a/b` 轮流 ⇒ ⭐ 要改成 3 路轮转 |
| **3** | ⚠️ **FIFO 深度的账要重算** | 🔴 现在的 `DEPTH=4` 是按"**待发 1 + 同拍 2**"算的（⭐ 注释原文）<br>⚠️ 3 路 ⇒ **同拍最多 3 条** ⇒ 🔴 **`DEPTH` 要 ≥ 5**（⭐ 建议 **6**） |
| **4** | ⭐ **加变异体** | ⚠️ 3 路轮转的新靶点（⭐ 见 `新模块变异靶点设计`） |

🔴 **第 3 条最容易漏** —— ⚠️ 若 `DEPTH` 不够 ⇒ 🔴 **同拍 3 条会丢 1 条**
⇒ ⭐ **而 `drop_cnt_o` 会告诉你有丢**（⭐ 这就是 `K-106` 的价值：**丢了看得见**）。

## 四、⭐ 落地步骤（⭐ 照上游 §6.2 的分步，⭐ 我补"接口层面"）

| 步 | 做什么 | ⭐ 判据 | ⚠️ 接口依赖 |
|---|---|---|---|
| **1** | ⭐ **单层录制 + 播放**（⭐ 上游第 3 步） | ⭐ 录 2 小节 → 循环不错拍 | ⭐ 用**方案 A**（⛔ 不动 `evt_merge`） |
| **2** | ⭐ **防挂音**（`active_mask` + 停录补 `note_off`） | ⭐ 循环 10 遍无长鸣 | 1 |
| **3** | ⭐ **叠加**（⭐ 方案 B：扩 `evt_merge`） | ⭐ loop 播着手弹有声 | 🔴 **要改 `evt_merge`** |
| **4** | ⭐ 扩 3 层 + **每层配额** | ⭐ 三层同时播 | ⚠️ 要改 `note_manager`（`LOOP_QUOTA`） |
| **5** | ⭐ **对齐到小节** | ⭐ 任意时刻起录仍对齐 | 4 |

⚠️ **第 3/4 步要动已落地模块** ⇒ ⭐ **必须**：
1. ⭐ **先写通知**（⭐ `note_manager` 是**队友乙**的？⚠️ 需确认归属）
2. ⭐ **改完重跑 `tb_voice_accept` + M2 延迟**（⭐ 上游 §七 明确写了）
