## 二、⭐ 根因（两个问题是同一个根子）

### 2.1 机制

```
⭐ 同一个 voice 的两个 lane 用的是【完全相同的波形】
   （`oscillator_bank.v` 的 `voice_timbre_i`：两个 lane 拿的是同一个）
⇒ 两个 lane 只差【频率】（失谐 1/256）⇒ 相位缓慢漂移
⇒ 相位差经过 0° → 180° → 0° 循环

vs = w0×L0 + w1×L1
  · 同相（0°）    ⇒ vs = (w0 + w1) × A
  · 反相（180°）  ⇒ vs = |w0 − w1| × A

🔴 现状 w0 = w1 = 0.5 ⇒ 反相时 vs = 【0】
⇒ ⭐【100% 调幅】⇒ 拍峰 ∞ dB 高于拍谷
```

### 2.2 为什么 P2（起音音量不一致）也是同一个根子

```
⭐ 按下键的那一刻，两个 lane 的相位差是【随机的】
   （取决于 lane1 相位累加器当时的漂移位置）
⇒ 起音瞬间的合成幅度 = |w0 + w1·e^{jφ}| ⇒ ⭐ 随 φ 随机
⇒ ⭐ 所以同一力度按键，响度会不一样
⇒ ⭐ 拍深越小 ⇒ 起音电平的随机范围越小 ⇒ P2 也缓解
```

### 2.3 与拍频周期的关系（已实测验证）

```
拍周期 T = 256 / f      （DETUNE_SH = 8 ⇒ Δf = f/256）
  · C3 (130.81 Hz) ⇒ 1.957 s   （用户实测「1s 尖音 1s 无」⇒ 误差 2.1%）
  · D3 (146.83 Hz) ⇒ 1.744 s   （用户实测 1.74 s ⇒ 误差 0.2%）
📌 这一条已在修 B2 时用上板波形确认过 ⇒ ⭐ 机制链条可靠
```

## 三、⭐ 选定方案：lane 权重不平衡

### 3.1 权重选择（⭐ 用户已定）🔴 **已作废** —— ⭐ 被 shift/add 版（`1.125 : 0.875` = 9/8 : 7/8）取代，见本文件 §十 `:234`

```
vs = (13×L0 + 3×L1) >> 4
     w0 = 13/16 = 0.8125
     w1 =  3/16 = 0.1875

· 同相  = (13+3)/16 = 1.000   ⇒ ⭐ 响度【不变】
· 反相  = (13−3)/16 = 0.625   ⇒ ⭐ 摆幅 = 20·log10(1/0.625) = 【4.1 dB】
```

### 3.2 候选对比（⭐ 已算过，供留档）

| 实现 | 权重 (w0/w1) | 同相 | 反相 | dB 摆幅 | 评价 |
|---|---|---|---|---|---|
| `(L0+L1)>>1` | 0.5 / 0.5 | 1.000 | 0.000 | **∞ dB** | 🔴 现状 |
| `(5L0+3L1)>>3` | 0.625 / 0.375 | 1.000 | 0.250 | 12.0 dB | 保守 |
| `(11L0+5L1)>>4` | 0.6875 / 0.3125 | 1.000 | 0.375 | 8.5 dB | 折中 |
| `(3L0+L1)>>2` | 0.75 / 0.25 | 1.000 | 0.500 | 6.0 dB | 中间 |
| ⭐ **`(13L0+3L1)>>4`** | **0.8125 / 0.1875** | **1.000** | **0.625** | ⭐ **4.1 dB** | ⭐ **已选定（最稳）** |

⭐⭐ **关键：⭐ 所有方案的【同相电平都是 1.000】⇒ ⛔ 不会变轻**

### 3.3 为什么选它（⭐ 而不是"两个 lane 用不同波形"）

```
🔴 之前试过"两个 lane 用不同 timbre"（commit 2371378，已回退 ef5c0fa）
   ⇒ ⭐ 用户实测听到「音色不同的音」⇒ 那是在【改音色】，⛔ 不可接受

✅ 本方案：⭐ 【波形完全不变】，只改两个 lane 的【相对权重】
   ⇒ ⭐ 音色不变 ✅    ⇒ ⭐ 响度不变 ✅    ⇒ ⭐ 只把拍深压小 ✅
```

## 四、⭐ 实施细节（⭐ 待做）

### 4.1 位置

`rtl/w3b/tdm_render_mixer.v`，lane 求和段（约 `:162-170`）：

```verilog
// 🔴 现状
reg signed [SUM_W-1:0] vs_c;
...
vs_sum = vs_sum + $signed(osc_sample_bus_i[(cnt_sel*OSC_PER_VOICE + oi)*OSC_SAMPLE_W +: OSC_SAMPLE_W]);
vs_c = vs_sum >>> NORM_SH;
```

### 4.2 改法

```verilog
// ✅ 改为：按 lane 索引加权（w0 = 13/16，w1 = 3/16）
//    13 = 8+4+1、3 = 2+1 ⇒ ⭐ 纯移位+加法，⛔ 不占 DSP
wire signed [OSC_SAMPLE_W+3:0] lane_w =
      (oi == 0) ? ( {lane_s, 3'b0} + {lane_s, 2'b0} + lane_s )   // ×13
                : ( {lane_s, 1'b0} + lane_s );                    // ×3
vs_sum = vs_sum + lane_w;
...
vs_c = vs_sum >>> (NORM_SH + 3);    // ⭐ 额外 >>4（权重和 = 16）
```

### 4.3 ⚠️ 必须注意的实现要点

| # | 要点 | 为什么 |
|---|---|---|
| 1 | ⭐ **保持有符号** | `L0`/`L1` 是 16 位有符号；权重运算必须保号（见 `B2-b` 的教训） |
| 2 | ⭐ **位宽要够** | `13 × 16bit` = 20 位 ⇒ `vs_sum` 必须是 `SUM_W` 以上（现有 `SUM_W` 已有防溢出余量，⭐ 但要复核） |
| 3 | ⭐ **移位量跟着权重和走** | 权重和 = 16 ⇒ `>> 4`；⭐ 若将来改权重，移位量必须同步 |
| 4 | ⭐ **`OSC_PER_VOICE != 2` 时要有兜底** | 现在 `OSC_PER_VOICE=2` 写死；⭐ 建议用 `generate` 或参数化，避免换 `OSC_PER_VOICE` 时静默出错 |
| 5 | ⚠️ **`OSC_PER_VOICE == 1` 时不需要加权** | 单 lane 没有拍 ⇒ 权重会白白降低电平 ⇒ 需分支 |

## 六、⚠️ 诚实的取舍与风险

| # | 项 | 说明 |
|---|---|---|
| **1** | ⭐ **"厚度感"会变弱** | 失谐的厚度**正是来自拍** ⇒ 拍浅了，厚度也弱<br>⭐ 这是**稳定性 vs 厚度**的取舍，用户已选"最稳" |
| **2** | ⚠️ **4.1 dB 仍不是 0** | 拍**依然存在**，只是幅度小了 ① ⇒ ⭐ 不会变成"完全稳定" |
| **3** | ⚠️ **P2 只是缓解** | 起音随机性来自"拍相位随机" ⇒ 摆幅小了，随机范围也小，⭐ 但**不归零** |
| **4** | ⭐ **不改音色**（⭐ 这是本方案的核心优势） | 波形没变 ⇒ 频谱不变 |
| **5** | ⚠️ **权重是编译期常量** | 若将来想调，需改 RTL 重新 PnR（⭐ 建议做成 `parameter`，便于 A/B） |

### ⭐ 为什么平均响度会 +1.43 dB（⭐ 已算，供留档）

```
⭐ 时均 RMS² = A²/2 × (w0² + w1²)     （交叉项在一个拍周期内平均为 0）

权重                      w0²+w1²     RMS/A     vs 现状
(L0+L1)>>1  [现状]         0.5000    0.5000     +0.00 dB
(5L0+3L1)>>3               0.5312    0.5154     +0.26 dB
(11L0+5L1)>>4              0.5703    0.5340     +0.57 dB
(3L0+L1)>>2                0.6250    0.5590     +0.97 dB
⭐ (13L0+3L1)>>4 [选定]     0.6953    0.5896     +1.43 dB

⭐ 原因：信号更多时间待在【峰值附近】，而不是每拍都荡到零
```
