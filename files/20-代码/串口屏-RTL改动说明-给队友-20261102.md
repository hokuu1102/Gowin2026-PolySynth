### R2. 参数按钮选参后，EC11 转不动参数【FPGA 改 1 行】

**现象**：点 `b0~b5` 选参后，转 EC11，屏上数值和指针都不动。

**根因**：`top.v:998-999`

```verilog
wire enc_par_up = enc_step_cw_w & enc_param_mode;
wire enc_par_dn = enc_step_ccw_w & enc_param_mode;
```

`enc_param_mode` 复位 = 0，只有串口 `'p'`（0x70）能翻转（`top.v:921`）。
屏上 `b0~b5` 只发 `6F 0n`（选参），**从不发 `'p'`** ⇒ 步进恒 0，转动被送去 BPM / 变调。

**改法**：选参时自动进参数模式（幂等，点几次都是 1）

```verilog
// top.v:902 附近
if (cmd_par_sel_val_req) begin
    enc_par_sel    <= cmd_par_sel_val[2:0];
    enc_param_mode <= 1'b1;          // ⭐ 新增
end
```

**退出**：屏上 `b_back` 弹起事件补 `printh 70 FF FF FF`。
（`0x70` 对 `uart_ui` 是空字符串帧，`70 FF FF FF` 直接结束、无动作；对 `top.v` 帧外解码就是 `'p'`，正好翻回 0。两边不冲突。）

**判据**：选 `b0` → 转 EC11 → `z_dg` 指针转、`t_dg_val` 数字变；回 page0 转 EC11 → 恢复调 BPM/变调。

> ⚠️ `uart_ui.v:565-589` 已把 `par_up_i/par_dn_i` 落到 fx 寄存器（带限幅 + `fx_commit_o`），
> 这段是对的，**不要重复实现**。

### R3b. **未锁定切档要归零，锁定才保持**【FPGA 改，4 行】

**现象**：从音高颤音切到音量颤音，未锁定时屏上还显示原来的值；按逻辑应是 `0/0`。

**根因**：`fader_gear.v:364-371`

```verilog
always @(*) begin
    vibrato_depth_o = vib_follow ? ch2_i : vib_d_hold;   // ← 离开该档就"保持"，与锁定无关
    vibrato_rate_o  = vib_follow ? ch3_i : vib_r_hold;
    trem_depth_o    = trm_follow ? ch2_i : trm_d_hold;
    trem_rate_o     = trm_follow ? ch3_i : trm_r_hold;
end
```

**改成：未锁定 → 0；锁定 → 保持**

```verilog
always @(*) begin
    vibrato_depth_o = vib_follow ? ch2_i : (hold_o[1] ? vib_d_hold : 12'd0);
    vibrato_rate_o  = vib_follow ? ch3_i : (hold_o[1] ? vib_r_hold : 12'd0);
    trem_depth_o    = trm_follow ? ch2_i : (hold_o[2] ? trm_d_hold : 12'd0);
    trem_rate_o     = trm_follow ? ch3_i : (hold_o[2] ? trm_r_hold : 12'd0);
end
```

逻辑校验：

| 情况 | `vib_follow` | 输出 |
|---|---|---|
| 档1 且未锁 | 1 | 跟推子 |
| 档1 且已锁 | 0 | `hold_o[1]` → 保持 ✓ |
| 其它档 且未锁 | 0 | **0** ✓ |
| 其它档 且已锁 | 0 | 保持 ✓ |

**判据**：档1 推 CH2 → 切档2（未锁）→ 音高两栏变 0；档1 推 CH2 → 锁定 → 切档2 → 音高两栏保持原值。

> ⚠️ 这一条**推翻了**之前"离开某档一律保持（两个颤音永远共存）"的旧语义 ——
> 新语义是**靠锁定位决定是否保留**。`tb_fader_gear` 里"切档后保持"的判据要同步改。

### R4b. 音量颤音 23.1 Hz 时进度条要满格【FPGA 改，量程错】

**根因**：`top.v:7929`

```verilog
wire [7:0] trem_rate_eff = trem_from_fader ? trem_rate_f[11:7] : ui_fx_rate;
```

`trem_rate_f[11:7]` 取 12 位的**高 5 位** ⇒ 实际范围 **0..31**，不是 0..255。
23.1 Hz 就是 `31`（`31 × 488280 >> 16 = 231` dHz，即 23.1 Hz）。

而回显用的是满量程 255 的 `ech_pct8`：

```verilog
ech_pct8(31) = 31 × 100 >> 8 = 12      // ← 进度条只有 12%
```

**改法**：新增一个 0..31 的换算函数

```verilog
function [7:0] ech_pct31;    // 0..31 → 0..99
    input [7:0] v;
    begin
        ech_pct31 = (v >= 8'd31) ? 8'd99 : ((v * 8'd100) >> 5);
    end
endfunction
```

然后 `ECH_F_ZVR` / `ECH_F_TVR` / `ECH_F_JVR` 三处用 `ech_pct31(st_vrate_c)`（见 R4-①）。

> `t_vr.txt` 用的是 `ech_vrate_hz`（算 Hz 的），**不用改** —— 它本来就正确，所以能显示 23.1Hz。
> 深度那栏 `z_vd` 用 `trem_depth_eff`（0..255），`ech_pct8` 正确，也不用改。

**判据**：档2 推 CH3 到顶 → `z_vr` 满格、`t_vr_val` 99%、`t_vr` 显示 `23.1Hz`。

### R10. 多帧连发只到第一帧（指针不实时 / page0 灯不动 / 录音色不变）【FPGA 改，优先级最高】

**现象**：一次状态变化会同时挂 2~6 帧，实际**只有第一帧生效**，其余丢失；
切页（屏发 `88` ⇒ 全量重发）时全部正常。

| 变化 | 挂几帧 | 实际表现 |
|---|---|---|
| 改效果器参数 | 2（`z_dg.val` + `t_dg_val.txt`） | **数字实时变、指针不实时动** |
| 开/关效果器 | 6（3 文本 + 3 个灯） | page0 底部三个灯不动 |
| Loop 状态变化 | 3（文本 + bco + pco） | 录音一直显示旧色（屎黄） |

**仿真已证明 RTL 会把两帧都发出来**：

```
feed 71 11 50（改增益）→ z_dg frame after gain change = 1  (capn=35)
```

⇒ 不是没生成，是**发出去之后丢了**。

**实测分界线（2026-11-02 晚，上板）**：

| 会正常显示的字段 | 帧长 | 不动的字段 | 帧长 |
|---|---|---|---|
| `t_timbre` = `GUITAR` | ~22 B | `t_mode` = `钢琴模式 [PIANO]` | ~36 B |
| `t_drum` = `Pattern II` | ~26 B | `t_slide` = `关闭 (GLIDE OFF)` | ~31 B |
| `t_bpm` = `120` | ~20 B | `t_kd` = `打鼓: 关闭 [音符演奏]` | ~45 B |
| | | `b_uplink` = `● 实时上行: 开启` | ~38 B |

⇒ **≤26 字节能过，≥31 字节过不去。**

**已排除屏的问题**：用串口助手直接把
`t_mode.txt="钢琴模式 [PIANO]"` + `FF FF FF`（UTF-8）发给屏，**屏正常显示** ⇒ 屏、字库、编码都没问题。

**根因**：

1. `uart_tx_fifo #(.DEPTH(8))` —— 一帧 20~52 字节，连发两帧就溢出；
2. `uart_ui` 的 echo FSM 若没有按 `tx_busy_i` 背压，就会一拍硬推一个字节。

**改法（四条）**：

- `DEPTH(8)` → **≥ 64**
- echo FSM 每次 `ech_push` 前判 `tx_busy_i`，忙就等
- 确认 `top.v:1728` `.tx_busy_i(ui_tx_busy)` 里 `ui_tx_busy` 真的是 `~txf_ready`（剩余 < 2 即置忙）
- 把 FIFO 的 overflow 引成可观测计数器（与 `err_cnt` 同款），转 EC11 时看它涨不涨

### S6. 头部按钮「状态记忆」——修 page1 切页回灰色【屏端，必须做】

**现象（用户 2026-11-02）**：
1. page1 点头部按钮 → 效果器开、按钮变彩色；
2. 切到 page0 再回 page1 → **按钮又变回灰色**（页面重新初始化，`bco` 回到属性面板里的 52857）；
3. 此时 FPGA 里效果器**还是开着的**；
4. 再点一次 → 屏以为"关→开"，实际发的是 `71 19` **XOR** ⇒ **把开着的关掉**；
5. 结果：屏显示彩色、实际是关的 —— 完全反相。

**根因**：屏端拿 `bco` 当状态记忆，而切页会把它重置成静态属性值；FPGA 的状态没变。

**修法：用全局变量做记忆（切页不丢）**

① `Program.s` 里声明（`dim=100` 之后）：

```
int fx0=0,fx1=0,fx2=0
```

> ⚠️ **不要用 `va0/va1/va2`** —— TJC 里 `va` 是变量控件的保留前缀，
> 直接写会报「变量名称无效:va0」+「索引超出了数组界限」。

② `page1` 的**初始化事件**（进页面按记忆恢复颜色）：

```
if(fx0==1)
{
  b_dist_hdr.bco=64608
}else
{
  b_dist_hdr.bco=52857
}
if(fx1==1)
{
  b_chor_hdr.bco=2016
}else
{
  b_chor_hdr.bco=52857
}
if(fx2==1)
{
  b_dly_hdr.bco=38943
}else
{
  b_dly_hdr.bco=52857
}
```

③ 三个头部按钮事件改成「先翻转变量、再按变量上色」（以失真为例）：

```
if(fx0==0)
{
  fx0=1
  b_dist_hdr.bco=64608
  printh 71 19 01 FF FF FF
}else
{
  fx0=0
  b_dist_hdr.bco=52857
  printh 71 19 01 FF FF FF
}
```

合唱：`fx0`→`fx1`、`64608`→`2016`、`71 19 01`→`71 19 02`；
延迟：`fx0`→`fx2`、`64608`→`38943`、`71 19 01`→`71 19 04`。

**局限性**：这是"屏自己记账"。若 FPGA 侧被别的入口改了（串口 `71 10`、重新下载位流），
屏的 `va` 不会跟着变，仍会偏。要彻底同步，得让 FPGA 直接下发颜色
（新增 `b_dist_hdr.bco=` 回显通路），屏完全不算账。
