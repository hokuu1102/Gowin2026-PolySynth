## 一、⭐⭐ 系统结构（⭐ 完整信号流）

```
                       ┌─────────────────────────────────────────┐
 霍尔键盘(16轴) ──SPI──>│ adc_farm → calib → axis_snapshot          │
                       │        → event_extract（阈值/迟滞/不应期）│
                       │        → axis_map（轴号→相位增量查表）     │
                       └──────────────────┬──────────────────────┘
                                          │ 事件(axis, phase_inc, velocity)
 节拍器/鼓机 ─────────────────────────────>│
                                          ▼
                                   ┌─────────────┐
                                   │ note_manager│  ← 分配/释放 32 个 voice
                                   │  （唯一事件口）│     维护 gate_mask / live_mask
                                   └──────┬──────┘
                          ┌───────────────┼───────────────┐
                          ▼               ▼               ▼
                   voice_active(32)  gate(32)      phase_inc(32×32)
                          │               │               │
                          │               ▼               ▼
                          │      ┌──────────────────────────────┐
                          │      │ envelope_bank（32×ADSR）      │
                          │      │  peak_level = velocity << 8   │◄══ 🔴 关键
                          │      └──────────────┬───────────────┘
                          │                     │ env_level(32×16, Q0.16)
                          │                     ▼
                          │      ┌──────────────────────────────────┐
                          │      │ oscillator_bank（64 路相位累加器）│
                          │      │  → 共享 512 点正弦波表            │
                          │      │  输出 64 lane × 16 bit            │
                          │      └──────────────┬───────────────────┘
                          │                     │ osc_sample_bus(64×16)
                          ▼                     ▼
                   ┌─────────────────────────────────────────────┐
                   │  tdm_render_mixer（TDM，32 拍 × 1 个乘法器）  │
                   │  ① 每 voice: vs = lane0 + lane1              │
                   │  ② prod = vs × env        （34 bit）         │
                   │  ③ acc  = Σ 32 个 prod     （40 bit）         │
                   │  ④ sh   = acc >>> 16      ← 还原 Q0.16       │
                   │  ⑤ sh24 = sh  <<< 8       ← 左对齐到 24 bit  │
                   │  ⑥ × gain_sqrt_lut[N]  >>> 7                 │
                   │  ⑦ 软限幅（阈值 87.5% 满幅，二次软膝）        │
                   └──────────────────┬──────────────────────────┘
                                      │ 24 bit signed
                                      ▼
                          ┌───────────────────────┐
                          │ master_mix（主音量+斜坡）│  gain = 0x7FFF（满）
                          └───────────┬───────────┘
                                      ▼
                          ┌───────────────────────┐
                          │ i2s_tx → PCM5102A     │  取【高 16 位】送 DAC
                          └───────────────────────┘
```

## 三、🔴🔴 核心问题：**增益结构的量化分析**

### ⭐ 3.1 单 voice 的幅度（⭐ 这是所有问题的源头）

```
⭐ 单个 lane 峰值           = 32767（16 bit 满幅）
⭐ 单 voice 两 lane 相加    = 2 × 32767 = 65534
⭐ 乘包络（env 满度 65536） = 65534 × 1.0 = 65534
⭐ prod = 65534 × 65535    = 4,294,770,690   （34 bit 装得下）
```

### ⭐ 3.2 accumulator 位宽

| ⭐ 量 | ⭐ 值 |
|---|---|
| `SUM_W`（两 lane 和） | **18** |
| `PROD_W`（× 包络） | **34** |
| `ACC_W`（累加 32 voice） | **40** |
| ⭐ **32 voice 满幅需要** | **37** ✅ |

✅ **⇒ 40 位 accumulator 是够的**（⭐ 这一层没问题）。

### 🔴 3.3 **问题所在：最终定标**

```
⭐ sh   = acc >>> 16        （还原 Q0.16 的包络乘法）
⭐ sh24 = sh  <<< 8         （左对齐到 24 bit —— 与下游 i2s_tx 的约定）
⇒ ⭐ **净效果 = >> 8**
```

⭐ **于是**：
```
⭐ 32 voice 满幅 = 32 × 65534 = 2,097,088
🔴 而 24 bit 满幅 = 8,388,607
⇒ ⭐ **32 个 voice 全满也只占 25%**
⇒ 🔴 **动态范围白白损失 ~12 dB**
```

### 🔴 3.4 归一化的尝试（⭐ 我加的）

⭐ 加了 `gain(N) = 基准/√N`（⭐ **查表，Q8.7 定点**）：

| ⭐ `N`（活跃 voice 数） | ⭐ `gain` | ⭐ 有效增益 |
|---|---|---|
| 1 | 44 | 0.344 |
| 2 | 31 | 0.242 |
| 4 | 22 | 0.172 |
| 8 | 16 | 0.125 |
| 32 | 8 | 0.0625 |

📌 **基准 44 的来历**（⭐ 数学推导）：
```
⭐ 约束 A（N=1）: 16776448 × (g/128)        <= 8388607 ⇒ g <= 64.0
⭐ 约束 B（N=2）: 2 × 16776448 × (g/√2)/128 <= 8388607 ⇒ g <= 44.2
⇒ ⭐ 取 44（同时满足两者的最大值）
```

## 五、⭐⭐ 已经排除的可能性（⭐ 都有实测证据）

| ⭐ # | ⭐ 假设 | ⭐ 怎么排除的 | ⭐ 结论 |
|---|---|---|---|
| **1** | ⭐ 音高映射错 | ⭐ 逐事件核对 `inc == fb_inc[axis]` 全匹配；⭐ 频谱分析：按下段 `E3` 能量 ×71 | ✅ 排除 |
| **2** | ⭐ I2S 位对齐错 | ⭐ 示波器：`DIN` 在 `LRCK` 下降沿**第 1 个 BCK** 开始 | ✅ 排除 |

| **4** | ⭐ 音箱低频差 | ⭐ 贝斯音响播 **E1 = 41 Hz** 清晰（⭐ 比我们的 110 Hz 更低） | ✅ 排除 |
| **5** | ⭐ 输出耦合电容高通 | ⭐ 耳机（32Ω）与 AUX（10kΩ）现象**相同**（⭐ 截止频率差 300 倍） | ✅ 排除 |
| **6** | ⭐ 采集链停止 | ⭐ 分窗口计数 `sample_valid` = 48/64/64（⭐ 从不停止） | ✅ 排除 |

| **9** | ⭐ 削顶（⭐ 硬饱和） | ⭐ 限幅阈值已提到 95%，⭐ 探针贴顶率可控 | ⚠️ 部分排除 |

🔴 **⇒ FPGA 输出、DAC、音箱、接线【全部正常】** ⇒ ⭐ **问题确实在纯净的"数字增益结构"上**。

### 🔴 第 4 轮的细节（⭐ 这条最能说明问题的耦合性）

```
⭐ 我原来用 live_mask（= "还能出声"，**含 Release 尾巴**）
🔴 ⇒ 自检和弦那 3 个音早 note_off 了，⭐ 但尾巴还挂在 live_mask 里
⇒ ⭐ **N 被"快死掉的音"撑大** ⇒ 🔴 按下时 N=8~12 ⇒ gain=13~16
⇒ 🔴 **真正在弹的键反而被压低**（⭐ 静置时 N=1 ⇒ gain=44）

✅ 改成 gate_mask（= "真正按住的"）⇒ N 降到 6~9 ⇒ gain 升到 15~20
🔴 **但 gain 变大 ⇒ 又顶到满幅 ⇒ 削顶了**（⭐ 探针实测 99~100%）
```

⚠️ **⇒ 这正是"按下葫芦浮起瓢"** —— ⭐ **说明这些参数是耦合的，⛔ 不能逐个试**。
