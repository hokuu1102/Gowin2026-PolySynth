## 一、上行帧 `byte[7]` 的最终口径

```text
bit [7:6]  保留，恒 0
bit [5:4]  音色 —— 但【鼓事件】这里被 drum_type 占用了
bit [3:0]  鼓标记：鼓 = drum_type(0/1/2/3)，手弹 = 0
```

⚠️ **`byte[7]` 在不同来源下长这样**：

| 来源 | `byte[7]` | 说明 |
|---|---|---|
| 手弹（旋律） | `0x_T_` | `[5:4]` = 真音色 0..3，`[3:0]` = 0（不是鼓） |
| 曲谱鼓 HiHat | `0x22` | `[5:4]` = 2（drum_type！），`[3:0]` = 2（鼓标记）|
| 曲谱鼓 Snare | `0x11` | `[5:4]` = 1、`[3:0]` = 1 |
| 曲谱鼓 Kick | `0x00` | ⚠️  Drum 也全是 0 ⇒ **与手弹低半字节同值，不可单独判** |
| 曲谱鼓 Tom | `0x33` | `[5:4]` = 3、`[3:0]` = 3 |

## 二、⚠️ 所以你们解"音色"时的规则

```
鼓事件（[3:0] != 0）：⛔ 不要读 [5:4] 当音色去发 program change
                     —— 那里是 drum_type，不是音色
手弹事件（[3:0] == 0）：[5:4] 是真音色，正常用
```

⭐ **为什么会这样**：帧的 `bit[8:7]` 被**复用**了 —— 下行时它是"鼓件类型"（`drum_type`），
上行时 `seq_arb` 把 `drum_type` 填进这一位。这是**既定取舍**（鼓的音色由"是哪件鼓"决定，
不需要独立音色字段），在 `rtl/top.v:1651-1655` 有记录。

## 三、我方已加的端到端判据（防这条口径被改坏）

```
tb/top/tb_top_upstream_timbre.sv  新增四件鼓的端到端判据：
  · dtype=1/2/3 => byte[7][3:0] 必须 == 对应值
  · ⭐ dtype=2(HiHat) => byte[7][3:0] !== 0（非空洞性）
  · 手弹 => byte[7][3:0] === 0
  · ⭐ force 的是 dut.ps_note_valid / ps_note_data（不是 score_is_drum_i）
    => 验的是 top.v 的 bit5/bit[8:7] 解码那一级，不是模块内部
```

⚠️ **一个已知的判据盲区**（我们如实记在注释里）：`drum_type=0`(Kick) 与手弹的低半字节**都是 0**，
⇒ **Kick 无法从上行帧单独区分**。若要区分，需要再开一位（当前没有空闲位了）。
