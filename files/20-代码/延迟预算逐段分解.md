# ⏱ 延迟预算 · 逐段分解

> **要证明的事**：控制 → 出声 **≤10 ms**（赛题红线）／ **≤5 ms 且确定性无抖动**（拓展要求）
> **日期**：2026-09-13 ｜ **责任人**：FPGA 侧（乙）
> **口径**：⚠️ 下表的数字**分「算出来的」与「必须实测的」两类** —— 不许把推算当实测
> **配套**：`files/20-代码/整体模块框图.md` §五（按通路分级）｜`files/30-方案决策/评分规则对齐.md` §二-2/§二-3

## 〇、🔴 三条结论先行

| # | 结论 |
|---|---|
| **1** | ⭐ **数字侧的合成与输出只占 ~0.14 ms，延迟几乎全在"采集的采样周期"上** —— 瓶颈不在 FPGA 内部 |
| **2** | ⭐⭐ **"等第二个阈值来定力度"会引入不可控延迟 → 违反"确定性无抖动"**。必须改成**先触发、后修正力度**（详见 §三） |
| **3** | **总预算约 0.65 ms（最坏）**，对 5 ms 目标有 **~7 倍余量** → 余量可以拿去换复音数，而不是省延迟 |

## 一、逐段预算表

**基准**：`sys_clk = 50 MHz`（20 ns/拍）｜`fs = 48.828 kHz`（**一个采样周期 = 20.48 µs**）
**采集**：24 通道 @ **2 kHz/通道**（每通道采样周期 **0.5 ms**）

| # | 段 | 机制 | 延迟（最坏） | 确定性 | 依据 |
|---|---|---|---|---|---|
| **①** | **采集：等待下一个采样点** | 动作发生到被 ADC 采到 | ⭐ **500 µs** | ✅ 固定（采样节拍恒定） | 由 2 kHz 通道速率决定 |
| **②** | ADC 转换 + SPI 读出 | `MCP3208` 转换 + 移位读出 | ~50 µs | ✅ 固定 | 视 SPI 时钟；估算 |
| **③** | 事件判定（阈值 / 拨弦去抖 / 不应期） | 比较 + 状态机 | **< 0.1 µs** | ✅ 固定（纯逻辑） | 几十拍 @50 MHz |
| **④** | Note Manager（分配 voice） | 查空闲 voice | **~0.02 µs** | ✅ 固定 | 1 拍 |
| **⑤** | 合成流水线 | 相位累加 → 波表查表 → ×包络 → 求和树 | **< 10 µs** | ✅ 固定（固定流水线深度） | ⚠️ 见 §四 关于时分复用 |
| **⑥** | 效果器（混响/延迟/合唱） | 延迟线读取 | **~0**（**不阻塞**） | ✅ 固定 | ⚠️ 干湿混合不加通路延迟 |
| **⑦** | 输出：I2S 帧 | 移位出一帧 | **~20.5 µs** | ✅ 固定 | 1 个采样周期 |
| **⑧** | DAC 建立 + 功放 | 模拟域 | **~5 µs** | ✅ 固定 | 数据手册量级 |
| | **合计** | | **≈ 0.59 ms** | ✅ **全段确定性** | |

> 📌 **"最坏"的含义**：动作恰好错过一次采样 → 要等一整个采样周期。
> **平均 ≈ 0.34 ms**（一半的采样周期 + 其余）。

## 二、⭐ 主项分析：瓶颈在哪一目了然

```text
① 采集等待采样点  ████████████████████████████████████████  500 µs   ← 84%
② ADC + SPI       ████                                        50 µs
⑦ I2S 输出         ██                                          20.5 µs
⑤ 合成流水线        █                                           10 µs
⑧ 模拟             ▌                                            5 µs
③④ 事件/分配        ·                                          < 0.2 µs
────────────────────────────────────────────────────────────────
合计              ~590 µs          目标 5000 µs  →  余量 ~8.5×
```

### ➡️ 由此得到两条重要推论

| # | 推论 |
|---|---|
| **1** | **想降延迟，唯一有效的动作是提高采集通道速率**（或减少每通道的分时轮转间隔）。优化 FPGA 内部流水线几乎无意义 |
| **2** | ⭐ **余量很大** → 不必为延迟牺牲复音数。想上 64 复音尽管上（合成流水线多几十 µs 也无所谓） |

**采集速率的杠杆效应**

| 每通道采样率 | ① 最坏 | 总最坏 | 说明 |
|---|---|---|---|
| 1 kHz | 1000 µs | ~1.08 ms | 仍远低于 5 ms |
| **2 kHz（当前）** | **500 µs** | **~0.59 ms** | ⭐ 当前设计 |
| 4 kHz | 250 µs | ~0.34 ms | 需确认 SPI/ADC 吞吐够 |
| 8 kHz | 125 µs | ~0.21 ms | 可能要放弃分时轮转、加片 |

> ⚠️ **注意**：提高采集率会增加 SPI 吞吐与 FPGA 侧通道扫描的负担。
> 当前 `2 kHz` 已经**远超需要**（余量 8.5 倍），**不建议为此改设计**。

## 三、⭐⭐ 设计陷阱：靠"等第二个阈值"定力度 → 破坏确定性

**背景**：力度用**双阈值测速法**（越过浅阈记 t1、深阈记 t2，Δt 小 = 力度大）。

### ❌ 错误做法：等 t2 到了再发声

```text
按下 → 越过浅阈 t1 →（等）→ 越过深阈 t2 → 算力度 → 【才发声】
                              ↑
                      Δt 取决于演奏者拨多快：
                        快拨 ~1 ms ｜ 慢拨 10~50 ms ｜ 轻按到底可能 >100 ms
```

**后果**：

| 问题 | 说明 |
|---|---|
| 🔴 **延迟不可控** | Δt 由人的动作速度决定 → **延迟随演奏变化** → 直接违反拓展要求的「**确定性无抖动**」 |
| 🔴 **慢速演奏会"哑"** | 轻轻慢按时可能几百 ms 才出声 —— 演奏体验直接崩 |
| 🔴 **节拍不稳** | 同一首曲子不同力度的音符**到达时间不同** → 节奏错乱 |

### ✅ 正确做法：**先触发、后修正**

```text
按下 → 越过浅阈 t1 → 【立刻发声】（用默认力度起音）
                          ↓
         越过深阈 t2 → 算出真实力度 → 【更新该 voice 的音量/亮度】
```

| 好处 | |
|---|---|
| ✅ **延迟固定** | 发声时刻只由 **t1** 决定 → 与"扫过阈值的速度"无关 → **确定性成立** |
| ✅ **力度仍然准确** | 更新发生在**起音阶段内**（ADSR attack 通常 20~100 ms）→ 听感上就是"这个音的力度" |
| ✅ **慢速也不哑** | t1 一到就响 |

> ### 📌 这条要写进接口约定
> **"事件"（触发）与"参数"（力度）必须分开走** —— 正好复用已有的
> **事件 / 参数分离**架构（`files/20-代码/整体模块框图.md` §三）：
> **触发走事件通路（低延迟、固定），力度走参数通路（可稍晚）**。
>
> ⚠️ **代价**：需要**在 voice 起音后仍能改它的包络目标值** →
> 这是 `③ 合成引擎层` 的一个**接口要求**（Note Manager 要支持"更新在响 voice 的参数"）。
> ⭐ 需在 `C3 接口冻结` 时写明。

## 四、⚠️ 会偷偷吃掉余量的三件事

| # | 隐患 | 机制 | 防范 |
|---|---|---|---|
| **1** | **时分复用（TDM）共用运算单元** | 若 N 个 voice 轮用一个乘法器，一轮 = `N × 每 voice 周期数`。32 voice × 100 拍 = 3200 拍 = **64 µs**（仍可接受，但要知道它存在） | 先算清"一轮多少拍"，别让轮转周期超过一个采样周期 |
| **2** | ⭐ **音频缓冲（FIFO / 双缓冲）** | **缓冲深度直接变成延迟**：双缓冲 = 1 个块大小。若块 = 128 样本 → **+2.6 ms**（一下子吃掉一半余量！） | ⛔ **不要用大块缓冲**；用小深度（几样本）或直接单样本流水 |
| **3** | **`fs` 本身** | 输出侧延迟 ≈ 1~2 个采样周期（20~41 µs）。`fs` 越低这项越大 | 当前 48.8 kHz 已足够；`fs` 减半只会加 20 µs 级别，影响很小 |

> ⭐ **第 2 条最危险** —— 很多人为了"平滑"习惯性加缓冲，一加就是几毫秒。
> **确定性通路上不该有缓冲。**

## 四之二、⭐⭐ 保证「确定性无抖动」的设计手段

> **赛题原文**（拓展要求 3）：「将演奏延迟压缩至 **≤5ms 且实现确定性无抖动延迟**」
>
> ⚠️ **"确定性"比"小"更难** —— 延迟小但**抖动大**，演奏上就是**节奏不稳**，
> 比"稳定地慢一点"更糟。所以这一节比 §一 的预算表**更需要遵守**。

### 4b.1 ✅ 八条设计手段

| # | 手段 | 为什么 |
|---|---|---|
| **1** | ⭐ **单时钟域**：全设计只用 `clk_sys = 50 MHz`，**禁止派生时钟**，用**节拍脉冲**代替 | 跨时钟域**必然**引入不确定的同步延迟（1~2 拍，且相位随机）；⚠️ 且经验库记载 **Gowin 上用 PLL 输出做系统时钟 → 综合通过但板子全死** |
| **2** | ⭐ **固定流水线深度** —— 不随数据/状态变化 | 若某条路径"数据特殊时多绕几拍"，延迟就抖了。深度写进 `files/20-代码/W3接口冻结表.md` §四 |
| **3** | ⭐ **确定性通路上不放缓冲 / 大 FIFO** | 缓冲深度**直接变成延迟**（见 §四-2） |
| **4** | ⭐ **采样节拍固定周期** —— 采集按**固定轮转**扫描，**不被 LED / 屏 / 其它模块打断** | 若扫描周期随负载变化，① 段的 500 µs 就不再是固定值 |
| **5** | ⛔ **不做"变长处理"** —— 不写"等条件满足再输出" | 变长 = 延迟随情况变化 |
| **6** | ⭐ **效果器不阻塞主通路**：干声与湿声**并行**算完再相加 | 效果器段延迟必须 **0 拍**（见 `files/20-代码/W3接口冻结表.md` §四） |
| **7** | ⭐ **触发与力度分开走**（先触发、后修正） | §三 那个陷阱 —— "等第二阈值"会让延迟由**演奏者速度**决定 |
| **8** | ⭐ **UI 链路与演奏链路彻底分离** | 串口屏的触摸扫描 + UART 传输延迟**不可控**（见 `files/20-代码/整体模块框图.md` §四） |

### 4b.2 ⛔ 反例清单（**违反即破坏确定性**）

| ⛔ 做法 | 后果 |
|---|---|
| 等第二个阈值才发声 | 延迟由**拨弦速度**决定（1 ms ~ 100 ms 不等） |
| 用块缓冲 / 双缓冲"平滑"输出 | 块大小直接变成延迟（128 样本 = **+2.6 ms**） |
| 让屏的 UART 写入阻塞主通路 | UART 一帧几 ms → 延迟不可控 |
| 跨时钟域用两级同步器"凑合" | 同步延迟 1~2 拍**且相位随机** → 抖动 |
| 动态调整流水线（省资源时变深） | 延迟随模式变化 |
| 用 `always @(posedge clk_in_other)` 多时钟 | 同上，且引入亚稳风险（经验库 `L28`：顶层直读 PLLx 域寄存器 → 偶发亚稳） |

### 4b.3 ⭐ 验证手段（与 `files/20-代码/验收计划.md` §一-③ 一致）

| 测什么 | 怎么测 | 判据 |
|---|---|---|
| **延迟上界** | 双通道示波器（通道 A = J8 事件标志，通道 B = DAC 起音） | ≤5 ms |
| ⭐ **抖动** | **同一动作重复 ≥50 次**，统计**极差** | **极差 ≤0.5 ms**（⛔ 不是看平均值） |
| **采样节拍** | 逻辑分析仪抓 SPI，量两次同通道采样的间隔 | **固定值**，不被其它模块打断 |

> ⚠️ **测量本身也要防陷阱**（经验库 `C10` 空测试陷阱 / `U30` 测量纪律）：
> 先确认**激励真的到达了被测点**，再相信读数。

## 五、必须**实测**（不能只推算）的三项

| # | 测什么 | 怎么测 | 为什么必须实测 |
|---|---|---|---|
| **1** | ⭐ **端到端真实延迟** | ① 光电/电信号同步法：拨弦件动作 → 示波器双通道（通道 A 抓动作信号，通道 B 抓 DAC 模拟输出起音）② 或用鼠标点击声 + 麦克风对齐 | 推算只能给量级；**评委要看的是实测数** |
| **2** | ⭐ **抖动的上界** | 同一动作重复 N 次（如 50 次），统计延迟的**极差**（不是平均） | "确定性"要求的是**上界稳定**，平均值好看没用 |
| **3** | **采集通道扫描的实际节拍** | 逻辑分析仪抓 SPI 时序，量两次同通道采样的间隔 | 确认 2 kHz 真的达到，且**不是被 LED / 屏打断的不规则节拍** |

> ⚠️ **测量方法本身要防陷阱**（经验库 `C10` 空测试陷阱 / `U30` 测量纪律）：
> 先确认**激励真的到达了被测点**，再相信读数。

## 六、验收口径（写进验收计划）

| 项 | 目标 | 证据形态 |
|---|---|---|
| 控制→出声延迟（触发/拨弦） | **≤5 ms**，且 **50 次重复的极差 ≤0.5 ms** | 示波器双通道截图 + 数据表 |
| 控制→出声延迟（音高/滑音） | ≤10 ms | 同上 |
| 力度更新延迟（起音后） | ≤20 ms（**听感上无察觉即可**） | 波形看包络 |
| 抖动（确定性） | **上界稳定**（不是平均值） | 重复测量统计 |
| 采集节拍 | 固定 2 kHz/通道，**不被其它模块打断** | 逻辑分析仪 |

> 📌 **"≤5 ms"是拓展要求，"≤10 ms"是基础要求** —— 我们按 5 ms 设计，
> 而**预算显示余量 8.5 倍**，所以这条红线的风险很低。

## 七、结论与对其它决策的影响

| # | 影响 |
|---|---|
| **1** | ✅ **延迟红线风险低**（预算 0.59 ms vs 目标 5 ms）→ 不必为它牺牲复音数或功能 |
| **2** | ⭐ **余量可以拿去换复音数** —— 支持 `A2-0` 里"按 2 个振荡器设计"的上探空间 |
| **3** | ⭐ **定了两条硬约定**：<br>· **触发与力度分开走**（先触发后修正）<br>· **确定性通路上不放缓冲** |
| **4** | **采集 2 kHz/通道 不变**（余量已足够，提速率没有收益却增加复杂度） |
| **5** | **待办**：端到端延迟与抖动的**实测**（见 §五），是 10/18 冻结前的必做项 |
