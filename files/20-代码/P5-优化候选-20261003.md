## 二、⭐ ADSR 共享化的可行性（最关键的一条，有明确算术答案）

| 问题 | 答案 | 依据 |
|---|---|---|
| 每采样可用拍数 | **1024**（`CLK_PER_SAMPLE=1024` @50 MHz = 20.48 µs） | `clk_gen.v:26` · `top.v:692` |
| 每 voice 更新需要几拍 | **1 拍**（`adsr.v:140-222` 是单拍组合 + 寄存器；`sample_tick_i` 只是使能） | `adsr.v:145` |
| 轮转延迟 | 32 拍 = 640 ns = 一个采样周期的 **3.0%**，**确定性** | 实测 |
| ⭐ 对包络精度的影响 | ⭐ **零** —— 每 voice 每帧仍**恰好更新一次** ⇒ 包络步数不变 ⇒ attack/decay/release **逐位不变** | 370 帧等价验证 |
| 帧内预算 | 32(包络) + 66(osc TDM) + 34(mixer TDM) = **132 / 1024 = 12.9%** ⇒ 余量 **7.8×** | `oscillator_bank.v:33` · `tdm_render_mixer.v:872` |
| ⭐ **为什么比表里的 6012 还肥** | `adsr.v:134-135` 的 `sustain_product_r <= peak_level * sustain_q8_u` ⇒ ⭐ **每 voice 一个 DSP** ⇒ `envelope_bank` 单独综合 = **32 个 `MULTALU27X18`**，而全设计只有 38 个 ⇒ **ADSR 吃掉 84% 的 DSP** | 隔离实测 |
| ⭐ 实现手法 | per-voice 状态放进**旋转移位寄存器**（`lvl_sr`/`st_sr`/`rel_sr`），头永远是当前 voice ⇒ ⭐ **读 0 LUT、写 0 LUT**；`env_level_o` 平铺总线照旧（`note_manager.v:345-353` 已在入口打拍） | — |

## 三、⭐ 用户/我的拍板（2026-10-03）

| # | 决定 | 理由 |
|---|---|---|
| **D1** | ⭐ **做 ADSR 共享（P0）** | 最大一块（−5891）、有算术背书、**逐位等价已验证** |
