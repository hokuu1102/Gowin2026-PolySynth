### 1.2 `generate` 分支与 `DEMO_CHORD_ON` 的关系（⭐ 最大命名/语义不符）

```verilog
generate
if (DEMO_CHORD_ON == 0) begin : g_silent   // top.v:640–660
else                    begin : g_sound    // top.v:661–2613
endgenerate                                 // top.v:2614
```

**`DEMO_CHORD_ON` 是布尔式使用**（`==0` 才静音），任何非 0 值 ⇒ `g_sound`。它同时干两件互不相干的事：

1. **结构上决定整条出声链是否存在**（`g_silent` 里**根本不例化**）：`test_mode_ctrl`、`envelope_bank`、`beat_gen`、`metronome`、`drum_gen`、`adc_farm`、`calib_autotare`、`calib×2`、`calib_span`、`axis_snapshot`、`event_extract`、`play_mode_ctrl`、`axis_map`、`param_extract`、`seq_arb`、`evt_merge`、`note_manager`、`oscillator_bank`、`tdm_render_mixer`、`master_mix`、`vibrato_lfo`、`right_analog_ctrl`、`pos_probe`、`span_probe` **全部消失**。
2. 是否播放上电自检和弦（`top.v:2504–2612`）。

🔴 **`DEMO_CHORD_ON=0` 的连带后果（注释完全没写）**：

| 后果 | 位置 | 说明 |
|---|---|---|
| `sample_mono = 0` | `top.v:652` | 出声链静音（这是唯一被文档化的意图） |
| **`tx_req=0` / `tx_byte=0`** | `top.v:658–659` | 🔴 **UART 回传整条死掉**：`'T'/'S'/'X'/'M'/'P'/'N'/'V'` **一个字节都不回**，`calib_cmd` 照常解析但无人消费 |
| `led_blink = 0` | `top.v:660` | LED 指引链的"拍点闪烁"失效（`top.v:2818`）；心跳 LED 仍在（`top.v:2775–2787`，在 generate 之外） |
| **ADC 采集/标定链消失** | 整个 `g_sound` | 无按键扫描、无零点标定 ⇒ **该档下任何"静音/无声"结论都不能代表真实设计** |

⚠️ 而 `tb/top/tb_top_m0.sv` 正是显式传 `0` 来做 M0 验收（`top.v:41–44, 57–58`）⇒ **M0 的"静音"证据是对一个"没有 ADC、没有标定、没有 UART 回传"的空壳取的**。

## 2. 时钟与复位

### 2.1 时钟源 / 分频 / 时钟域

- **唯一时钟**：`clk = V22`，50 MHz（`top.v:186`）。**不用 PLL、不派生时钟**（`clk_gen.v:11–14`）。
- `clk_gen` 只产生**使能**（clock-enable），不是新时钟（`clk_gen.v:95–111`）：

| 输出 | 分频 | 频率 | 用途 |
|---|---|---|---|
| `tick_audio` | ÷1024 | 48.828125 kHz（1 拍脉冲） | 音频帧起点 |
| `bclk_en` | ÷16 | 3.125 MHz | I2S 位使能 |
| `bclk_half_en` | ÷8 | 6.25 MHz | `HP_BCK` 翻转 |
| `lrclk` | 前半帧低 | 48.828125 kHz | WS（低=左） |
| `frame_start` | 帧内第 0 个 BCLK | — | I2S 对齐 |
| `mclk_en` | ÷4 | 12.5 MHz | 🔴 **在 `top.v` 里未使用（死输出）**，`top.v:321, 331` |

- **时钟域只有一个**（50 MHz）。`adc_farm` 的 SCLK 是**输出协议信号**，⛔ 不当内部时钟（`adc_farm.sv:41`）。

### 2.2 `tick_audio`（sample_tick）的产生方式

```verilog
cnt <= (cnt == CLK_PER_SAMPLE-1) ? 0 : cnt+1;          // clk_gen.v:78–82
tick_audio <= (cnt == {CW{1'b0}});                      // clk_gen.v:104（寄存输出）
```
⇒ 每 **1024 个 clk**（= 20.48 µs）一个**单拍**脉冲，`fs = 48.828125 kHz`（`top.v:324`）。注意它是**寄存**输出 ⇒ 相对 `cnt==0` 晚 1 拍，全设计一致使用，无歧义。

### 2.3 复位同步链与释放顺序

```verilog
rst_sync #(.STAGES(2)) u_rst_sync(...);   // top.v:314–318
sync_chain <= {sync_chain[STAGES-2:0], rst_n_async};   // rst_sync.v:42
assign rst_n_sync = sync_chain[STAGES-1];              // rst_sync.v:45
```

- 纯**同步**链（⛔ 第一级不接异步复位端，`rst_sync.v:14–18`）；`initial sync_chain=0` 只影响仿真（`rst_sync.v:51`）。
- **释放顺序**：全设计所有 FF 在**同一个 clk 沿**看到 `rst_n_sync` 抬升（这正是 R-08 的目的）。代价：复位**生效**也晚 2 拍（40 ns）。
- 🔴 **纪律破坏**：两处用了**异步复位**，与"全设计同步复位、低有效"约定（`clk_gen.v:42–43`）不符：
  - `calib.sv:87` 与 `calib.sv:139`：`always @(posedge clk or negedge rst_n)`
  - `adc_farm.sv:190`：`always @(posedge clk or negedge rst_n)`
  由于 `rst_n` 实际接的是**寄存过的** `rst_n_sync`，功能上暂时无害，但会引入 recovery/removal 时序检查，且一旦有人把 `calib` 接到真异步 `rst_n` 上就会破坏释放对齐。
- ⚠️ `calib.sv` 还用 `initial` 给**数组**赋初值（`zero_r/gain_r`，`calib.sv:164–169`）——上电安全性实际靠它，而不是靠复位（`rst_n` 不复位这两个数组！）。这意味着**复位不会清零点/增益**，`'T'`/`'S'` 的标定结果在按键复位后依然保留（可能是想要的，但注释里没写）。
- `PA_EN_n` 上电正确电平靠 `.cst` 的 `PULL_MODE=UP`（`top.v:21–23, 2745`）。

### 2.4 ⭐ 跨时钟域未同步信号

**结论：没有真正的 CDC 违规（设计只有一个时钟）。** 所有异步输入都做了同步：

| 异步输入 | 同步器 | 行号 |
|---|---|---|
| `rst_n`（按键） | `rst_sync` 2FF | `top.v:314`, `rst_sync.v:37–45` |
| `uart_rx`（D14） | `uart_rx` 内 `rx_d1/rx_d2` 2FF（复位值给 1=空闲高） | `uart_rx.v:107, 111–119` |
| `pluck_up_i`/`pluck_down_i` | `async_pluck_capture` 2FF（逐根） | `top.v:1858–1869`, `async_pluck_capture.v:36–41` |
| `spi_miso[1:0]` | `adc_farm` 内逐片 `sync_input` 2FF | `adc_farm.sv:87–95`, `sync_input.v:42–54` |

⚠️ 需要注意的**残余风险（不是 CDC，但同族）**：
1. `spi_miso[5:2]` **未连接**（`top.v:986` 只取 `[ADC_N-1:0]`）⇒ 依赖内部上拉，悬空时虽不上报但仍会进 `sync_input`（若将来 `ADC_N` 变大而排线未接，会读到随机值 ⇒ 误判为按键）。
2. 多比特一致性：每片 MISO **各自独立**同步（`adc_farm.sv:89–94`），作者已在 `sync_input.v:10–11` 说明"多比特偏斜"——此处因每片数据独立、且 `CS/SCLK` 同源扇出，暂不构成"不可能组合"。
3. `pluck_*` 在 `RIGHT_ADC_ENABLE=0`（默认）下硬件（LM393）未装：默认是钢琴模式（`play_mode_ctrl` 里 `!fretboard_mode_i` 分支忽略 `pluck_valid_i`，`play_mode_ctrl.v:51–58`）⇒ 悬空抖动**不会**产生音符，✅ 当前安全。

## 4. UART 资源分配（⭐ 重点）

### 4.1 `uart_rx` 字节流分给了谁


### 4.3 🔴 协议之间会不会互相误判 —— **会，而且已被仿真证明**

**① `0xA5` 是三路共用的魔数，且另两路的合法载荷里一定会出现它**

- TJC **数值返回帧 `0x71`** 的载荷是 4 字节小端数值 ⇒ **数值 165 = 0x000000A5 就含 `0xA5`**；GBK 中文串（`0x70` 字符串帧）也常含 `0xA5`。
- 后果 A（严重，已修）：`evt_uart_rx` 把它当帧头 ⇒ 后面 8 字节被拼成伪事件 ⇒ `axis = data[22:19]` 可为 **14/15（保留轴）**、`kind = data[10:9]` 可为 **0（note_on）**、`inc = data[43:23]` 可为 **0x1FFFFF**。作者已用 `tb/w3c/tb_evt_uart_rx_screen.sv` 复现"8 个屏幕数值帧 ⇒ 8 条伪事件，`axis=15, inc=0x1FFFFF, kind=0`"（`top.v:2123–2141`），并用 `SCORE_UART_ENABLE=0`（`top.v:2103, 2148`）**默认关闭曲谱通路**。
- 后果 B（**仍在生效**）：`calib_cmd` 同样跟踪 `0xA5` ⇒ 屏幕帧里的一个 `0xA5` 会让它**把接下来的 8 个字节当载荷吞掉** ⇒ 这 8 个字节里若有 `'T'/'S'/'X'` 就被**静默忽略**（只记 `in_frame_cnt`，`calib_cmd.v:241–245`）⇒ 表现为"**命令偶尔没反应**"。作者在 `top.v:376–377` 只说"会 +1 `hdr_err_cnt`"，**没提这个反方向的吞命令风险**。
- 后果 C：`uart_ui` 的结束符是 **3 连 `0xFF`**，而 `evt_uart_rx` 的 8 字节载荷是任意字节 ⇒ 事件帧可被屏解析器当帧尾（当前曲谱已关，风险低；但三路共线、无仲裁，任一路的合法载荷都可能被另一路误读，是**结构性**问题）。

**② 结论**：`evt_uart_rx` 与 `calib_cmd` **共用同一魔数 + 同一物理线**，无法从根本上互不误判。当前能工作只因为：① 曲谱通路被编译期关掉；② 屏幕与 PC 命令不同时发。**恢复曲谱功能必须换独立 UART 线**（`top.v:2146–2147` 已写明）。

> ⭐ **2026-09-28 用户更正**：本条（UART 伪事件注入）**不是当前挂音根因**（用户实测：**没接串口也挂音**）⇒ ⭐ **状态标注：「潜在缺陷」**，已用 `SCORE_UART_ENABLE=0` 关断（`top.v:2103/2148`）。当前挂音根因见 §6 的 2026-09-28 已修清单（`event_extract.q_cnt` 同拍增减覆盖）。

### 4.4 `uart_tx` 发送仲裁

```verilog
assign tx_req  = rep_req | pp_push | vp_push | np_push;                       // top.v:1552
assign tx_byte = np_push ? np_data : (vp_push ? vp_data
                 : (pp_push ? pp_data : rep_byte));                           // top.v:1554–1555
```

- **单入口、单 push**：四个来源**或**成一个 push，字节按 `np > vp > pp > rep` 选。
- `rep_req` 是 8 路事件或（`top.v:1532–1534`），`rep_byte` 优先级：`轴号 > '!'拒绝 > '.'通过 > 'D'完成 > '!'('S'被拒) > 'T'(autotare完成) > 't' > 's' > M档位 > 'x'`（`top.v:1535–1544`）。
- 🔴 **同拍两个来源 ⇒ 低优先级那个字节被静默丢弃**（`tx_req` 仍只 push 一次）。注释断言"两者不会同拍"（`top.v:1548–1551`），但 `pp_push`（`pos_probe` 逐字节推，`pos_probe.v:265–269`）与 `cmd_*_req`（来自 UART 字节）**没有互斥保证** ⇒ 最坏情况：`'t'` 受理回执被吞。
- `uart_tx_fifo`：`push_i & ~full` 才入队（`uart_tx_fifo.v:114`），满则丢并置 `ovf_o`/`drop_cnt_o`；`idle_o = empty & ~sending & ~busy_i`（`uart_tx_fifo.v:129`）供 `pos_probe`/`span_probe` 判包边界。`ovf_clr_i` 被硬接 `1'b0`（`top.v:623`）⇒ **溢出标志一旦置位永不清**，且该信号在顶层**未连接**（死）。
- 优先级实现为**四路独立 push 信号 + 一个 mux**，而不是一个带 valid 的仲裁器 ⇒ 结构上就允许"丢一个字节"。

### 5.2 ⭐ `zero_r` / `gain_r` 何时写、何时用 —— **有旧值时序问题**

```verilog
// calib.sv:96–108  span 触发（与 busy 互斥）
if (!busy && span) begin
    div_ch <= cal_ch;
    if (raw <= zero_r[cal_ch]) begin err <= 1'b1; gain_r[cal_ch] <= (1<<8); end  // 🔴 见 S5
    else begin err<=0; busy<=1; den_r <= raw - zero_r[cal_ch]; quo_r <= FULL<<8; end
end else if (busy) begin ... gain_r[div_ch] <= quo_r[GW-1:0]; end                 // 24 拍后写增益
// calib.sv:145–148  零点 + 正常通路（同一 always）
if (tare) zero_r[cal_ch] <= raw;                                                  // T+1 写
prod_r <= (raw > zero_r[ch]) ? ((raw - zero_r[ch]) * gain_r[ch]) : 0;             // 🔴 T+1 用【旧 zero/旧 gain】
```

| 时刻 | 事件 | 用的值 |
|---|---|---|
| T | `tare`/`span` 脉冲发出 | — |
| T+1 | `zero_r` 写入 / `gain_r` 在 span 分支**尚未**写 | `prod_r` 用**旧 zero + 旧 gain** ⇒ **本帧输出是脏的**（`top.v:1107–1121` 已定位并靠 `AT_EN_DELAY=16` 绕开） |
| T+2 | `prod_r` 正确 | — |
| T+25 | span 除法器写 `gain_r` | 之后才生效（⇒ 有 1 帧用旧增益） |

⇒ **结论**：`zero_r` 与 `gain_r` 都"晚一拍/晚 24 拍生效"，而 `calib` 的输出**当拍就用旧值**。这不是致命 bug（后续帧会正确），但 `event_extract` 必须在标定完成后**延迟放行**（`at_en_ready`，`top.v:1140, 1821`）——**如果将来把 `'T'` 做成"标定中继续判键"，同一坑会立刻复发**。

### 5.3 `pos` 的完整计算式与取值范围

```
raw(12b) --INVERT_AXIS=1--> raw_pol = 4095 - raw                    top.v:1242–1255
raw_pol --calib(tare 减零点)--> d = (raw_pol > zero) ? raw_pol - zero : 0   calib.sv:148
d --calib(span 增益 Q8.8)--> pos = saturate(d * gain >> 8, 0..4095)  calib.sv:113–115, 152–159
```

| 档位 | `gain` | `pos` 范围 | 阈值（当前硬编码） |
|---|---|---|---|
| **只 tare（上电默认）** | 256（=1.0） | 实测 **0 … 744**（理论 0…4095） | `TRIG_TH=0x0C0(192)=26%`、`REL_TH=0x050(80)=11%`（`top.v:1782–1783`），迟滞 112 |
| **做过 span** | `(4095<<8)/(raw_底−zero)`（≈1409） | **0 … 4095**（归一化，分辨率×5.5） | ⚠️ **必须重算**为 `TRIG=1065`、`REL=450`（注释 `top.v:1780–1781`），但**代码里没有任何运行时自适应** |

🔴 这构成一个**跨模块隐性耦合**：`param_extract.POS_FULL=12'd744`（`top.v:1966`）与 `TRIG_TH/REL_TH` **都是按"744 行程"编译期写死的**；操作者一旦按文档发 `'S'` 做 span，`pos` 空间变 4095 而阈值不变 ⇒ 触发点从 26% 掉到 **4.7%**、迟滞从 112 掉到等效 **20 码**（低于实测 48 码噪声）⇒ **键会一直抖 on/off**（详见 S7）。

> 补充证据链：`nm_gate = 0x08000000` = **voice 27** = `NORMAL_N = POLY_TARGET − RESERVED_N = 27` 起的**保留池**（`note_manager.v:162–164, 281–283`）⇒ 这个"恒 held 的 voice"**只可能来自 axis≥14**（演示和弦 axis 0/1/2 只能落 voice 0..26）⇒ **"水怪低吼" = 保留池里一个只收到 `note_on`、`inc` 极小（21 位域/单位错，或 =0）的 voice，被 ADSR 永久保持在 sustain 25%**。

### 附：本次分析中**未发现**问题的方面（避免过度悲观）

- ✅ 单时钟域、无 PLL、无门控时钟；异步输入（`rst_n`/`uart_rx`/`pluck_*`/`spi_miso`）**都有 2 级同步**。

- ✅ `note_manager` 的 `note_off` 清"**所有**同轴 gate 高的 voice"（`:510–516`），这是防挂音的正确设计。

**一句话总结**：设计的骨架（单时钟域、节拍使能、握手对齐、饱和可观测）是扎实的，但**"只发 `note_on` 的源"（节拍器/鼓机/曲谱伪事件）+ 保留池 + 无释放的 ADSR** 构成了一条**永久挂音/永久出声**的完整路径，而 `DEMO_CHORD_ON`/`METRONOME_ON` 两个参数的**名字与真实语义不符**（一个关整条链，一个管住源 B 全体且默认值与注释矛盾），使得"交付档"与"静音档"的差异远超文档描述；此外 `calib_span` 的 `S_DONE` 无重入、`calib.err` 粘滞、以及"span 后阈值不重算"三处会**静默**破坏标定/演奏。
