## 二、镲片变嗵鼓 —— 采纳扩位，而且比你们想的更便宜

### 2.1 ⭐ 关键：**"鼓要 8 条轴"这个约束已经不存在了**

```
旧设计：鼓的身份靠【轴号】=> 8 件鼓就需要 8 个专属轴号 => 而自由轴只有 12..15 四条
新设计：鼓的身份靠【drum_type 字段】=> 与轴号完全无关
=> 扩到 8 件【不需要任何新轴号】=> 那个约束随旧设计一起消失了
```

所以你们提的"两条出路"都不用走，直接扩位即可。

### 2.2 位从哪来（帧宽不变）

```
drum_type 现在 2 位 = timbre[8:7]
第 3 位取 【bit19】（原 axis[0]）
=> drum_type = { ps_note_data[19], ps_note_data[8:7] }   共 3 位
```

**为什么 bit19 安全**：它只在 `is_drum=1`（bit5）时被读，而 bit5 是保留位、旧工具保证写 0 ⇒ 旧 hex 永远不会误触发。（这也是当初把 `is_drum` 从 bit22 挪到 bit5 的同一个理由，你们在 §一 里已经看到那条论证。）

⚠️ **请你们核实**：你们写鼓事件时，**bit19 必须写 drum_type 的 MSB**，⛔ 不要因为它"原来是 axis 的最高位"就写别的。

### 2.3 八件的编号与 inc（⚠️ 需要你们确认编号顺序）

```
0 = Kick      35, 36
1 = Snare     38, 40
2 = HiHat     42, 44          (闭镲)
3 = Tom       41, 43, 45, 47, 48, 50
4 = OpenHat   46
5 = Crash     49, 52, 55, 57
6 = Ride      51, 53, 59
7 = Splash    55(如与 Crash 冲突见下)
```

⚠️ **55 在 GM 里是 Splash，57 是 Crash2**。上面的表里 55 同时出现在 Crash 和 Splash，请你们按 GM 标准定稿并告诉我们最终映射（我们不猜）。

**新的四个 inc**（由 `INC_HIHAT` 按倍数派生，⭐ 可复算、可追溯）：

```
公式：inc = f_out × 2^32 / 48000 = f_out × 89478.4853

INC_OPENHAT = 128_849_019   (≈1440 Hz, = HiHat × 0.75)
INC_CRASH   = 223_338_299   (≈2496 Hz, = HiHat × 1.30)
INC_RIDE    = 274_877_907   (≈3072 Hz, = HiHat × 1.60)
INC_SPLASH  = 343_597_384   (≈3840 Hz, = HiHat × 2.00)
```

⭐ 这四个值会加进 `rtl/w3c/drum_inc_defs.vh`（共享常量文件），**仍然是单一来源** ⇒ 键盘打鼓与灌谱的鼓必然一致。

**FPGA 侧代价**：32 位 8 选 1 mux，约 64 LUT（原来 4 选 1 是 32）。CLS 目前 88%，这次 PnR 会实测。

## 三、BASE_NOTE=45 的钳位 —— 你们报得对，但根因不在 BASE_NOTE

### 3.1 先说清一件根本的事

```
LED 只能指引【键盘上存在的键】：A2..D#4（MIDI 45..63）
引导轨若是贝斯（40~47）=> 40~44 这些音【键盘上根本没有对应的键】
=> 无论 BASE_NOTE 取多少，都不存在"正确的灯"可点
```

所以这不是"钳到 0 导致指错"，而是"**这些音本来就不该点灯**"。

### 3.2 但当前行为的确认错了（⚠️ 这是真 bug）

```
你们钳到 0 => offset 0 = A2
而 A2 在【指板表】里是【真实的键 5】
=> 贝斯低音区会点亮键 5（而不是不点灯）=> 指错
```

### 3.3 修法：**约定"超出可弹音域的音写 31"**（⭐ FPGA 侧不用改）

```
offset 31（MIDI 76 = E5）在两张表里都是哨兵 N => 不点灯
=> 请你们：音高 < 45 或 > 75 时，note_off5 写 5'd31，⛔ 不要钳到 0
=> FPGA 侧无需任何改动（表的哨兵已经处理了）
```

**请你们保留"钳位数"的日志**，并把它改成"**判为不可弹（写 31）的条数**" —— 这个数字有诊断价值（它说明引导轨超出了键盘音域）。

### 3.4 BASE_NOTE 不变

保持 45。理由：45 是指板表的最低音（`fb_inc[5] = A2`），表格与它对齐最干净；改成别的值只会让表偏移、不解决"键盘上没这个键"的根本问题。

## 四、vel 的差异 —— 建议统一到【真实力度】，但这是独立决定

### 4.1 现状（你们查得对，我们确认）

```
网页通路：真实力度（旋律 MIDI 力度 · 鼓 175/220/230/235 · OFF=0）
mid2evt.py:581：一律常量 130（原注释 "keep it simple"）
=> 两条通路只有 vel 不同，其余 0 条对不上
```

### 4.2 我们的建议：统一到真实力度

```
理由 1：FPGA 侧的包络【就是用 vel 的】（力度 -> 音量/音头）=> 真实力度是设计意图
理由 2：全 130 会让整首曲子【没有强弱】=> 鼓的 175/220/230/235 那种层次全丢了
理由 3：网页通路是较新的一条，已经按真实力度在跑
```

### 4.3 ⚠️ 但请注意这是一个**听觉行为变更**

```
改成真实力度后：轻的音会明显变轻（原来一律 130 = 中等偏弱）
=> 与你们之前听过的版本【听感不同】
=> 建议你们改完后先灌一份对比听，确认不是"变小声了"而是"有了强弱"
```

**这条不阻塞其他改动**，可以单独一个提交。你们定了告诉我们一声即可。
