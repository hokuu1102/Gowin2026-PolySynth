## 一、🔴 `inc` 位宽 —— 你们的分析错了（⭐ 有证据，⛔ 不是措辞）

### 1.1 权威来源：`tools/mid2evt.py:124-128`（⭐ **发送端**打包常量）

```python
TICK_W, TICK_SH = 20, 44
INC_W,  INC_SH  = 21, 23
AXIS_W, AXIS_SH = 4, 19
VEL_W,  VEL_SH  = 8, 11
KIND_W, KIND_SH = 2, 9
TIMBRE_W, TIMBRE_SH = 2, 7        # 音色号 0..3
# bits 6..0 reserved
...
INC_MAX = (1 << INC_W) - 1      # 2097151 > MIDI 127 (1077509), with headroom
```

⭐ **注释自己写明**：⭐ **MIDI 127 在这个字段里是 `1077509`** ✓

### 1.2 RTL 侧：`rtl/top.v:4575`

```verilog
wire [31:0] ps_evt_inc = {1'b0, ps_note_data[43:23], 10'b0};
//                        ↑零扩展  ↑取 21 位      ↑低 10 位补零
```

⇒ ⭐ **字段值 `× 1024` = 32 位 `phase_inc`** ✓

**验算（⭐ 逐位可核）**：
```
MIDI 127 → 1077509
1077509 × 1024 = 1,103,369,216
1,103,369,216 × 48828.125 / 2^32 = 12.54 kHz  =  MIDI 127 (12543.85 Hz)  ✅
```

⇒ ⭐ **所以字段语义 = `phase_inc >> 10`（32 位的【高 21 位】）**，
   🔴 **⛔ 不是"低 21 位"** ⇒ ⭐ **你们该发 `>> 10`，⛔ 不是 `& 0x1FFFFF`** ✓

### 1.3 ⭐ 四个鼓件**全部放得下**（21 位上限 = 2,097,151）

| 件 | `phase_inc` | **`>> 10`（⭐ 该发的值）** | 放得进？ | 余量 |
|---|---|---|---|---|
| Kick | 5 368 709 | **5 243** | ✅ | 400× |
| Snare | 42 949 673 | **41 943** | ✅ | 50× |
| HiHat | 171 798 691 | **167 772** | ✅ | 12.5× |
| Tom | 17 895 697 | **17 476** | ✅ | 120× |

⭐ **精度（⭐ 如实）**：⭐ `>> 10` 的量化误差 ≤ 1/1024 ⇒ **最坏 0.02%**
📌 HiHat 实测：`167772 × 1024 = 171 798 528`，理想 `171 798 691` ⇒ 差 **163** ⇒ **0.00009%** ⇒ ⭐ **听不出来** ✓

| **A**（借 `inc` 低 2 位存件号） | ⛔ **不需要** —— ⭐ 直接发真值就够（⭐ 而且**不占语义** ✅） |

## 二、🔴 真因：⭐ **来源标记**（这才是"鼓被推成音高"）

### 2.1 代码事实（⭐ 四处互相印证）

```
rtl/w3c/seq_arb.v:179        localparam [NW-1:0] SRC_SCORE = 3'd1;   ← 曲谱那一路打成这个
rtl/w3b/note_manager.v:292   localparam [2:0]    SRC_AUX   = 3'd3;   ← 源 B（节拍器/鼓机）
rtl/w3b/note_manager.v:316   localparam [2:0]    SRC_KDRUM = 3'd5;   ← 键盘打鼓
rtl/w3b/note_manager.v:650   pool_mask[pg] = ((cur_src == SRC_AUX) || (cur_src == SRC_KDRUM)) ...
rtl/w3b/note_manager.v:1873  voice_drum_o[g] = (src_r[g] == SRC_AUX) || (src_r[g] == SRC_KDRUM);
```

⇒ 🔴 **`SRC_SCORE` 两个条件都**不满足** ⇒ ⭐ 曲谱里的鼓**被判成乐音** ⇒ **被推成音高** ✓
⇒ ⭐ **这正是用户听到的"怪怪的"** ✅

### 2.2 修法（⭐ FPGA 侧，约 5 个 LUT）

⭐ 在 `seq_arb` 里：⭐ **曲谱事件若 `axis == 15` ⇒ 打成 `SRC_KDRUM`**（⛔ 否则仍是 `SRC_SCORE`）：

```verilog
// ⭐ 示意（⭐ 实际改在 `seq_arb.v` 曲谱那几条 `pack_src` 上）
mem[tail_q] <= pack_src((score_axis_i == 4'd15) ? SRC_KDRUM : SRC_SCORE,
                        score_axis_i, score_phase_inc_i, score_velocity_i,
                        score_kind_i, score_timbre_valid_i, score_timbre_i);
```

⇒ ⭐ **你们已经"鼓全走 `axis 15`"** ⇒ ⭐ **你们那边【一行都不用改】** ✓

⚠️ **代价（⭐ 如实说）**：⭐ **曲谱里 `axis 15` 从此被鼓占用** ⇒ ⛔ **旋律轨别用 15** ✓
📌 **若你们需要 15 留给旋律** ⇒ ⭐ **备选**：⭐ 用 64 位字里**空闲的 `bit[6]`** 当"鼓标志"
   （⭐ 那 7 位 `bits 6..0 reserved` **一直是 0** ⇒ ⭐ **不算改协议、不用重冻版** ✅）

### 2.3 ⭐ 为什么这个 bug 一直没暴露

| 🔴 **PC 灌的谱** | `SRC_SCORE` | 🔴 **两个条件都不满足** ⇒ **被当乐音** |

⇒ ⭐ **你们是【第一条】从 PC 来的鼓** ⇒ ⚠️ 所以这个洞**今天才第一次被踩到** ✓
