## 一、烧录

### 1.1 🔴 线缆选择（**这就是"Cable failed to open via the location"的原因**）

本机实测：板载调试器（BL616，伪装成 FT2232）在 Gowin 里的正确名字是 **`USB Debugger A`**。

| 界面里选的 | 结果 |
|---|---|
| ❌ `Gowin USB Cable` / `GWU2X` / `WINUSB` | **打不开** → 报 `Cable failed to open via the location` |
| ✅ **`USB Debugger A`** | **能用**（内部即 `Gowin USB Cable(FT2CH)`） |

**Gowin 支持的线缆全集**（CLI 报错时列出的，实测）：

```
'Gowin USB Cable(GWU2X)'      ← 官方线（Cypress 芯片），不是本板
'Gowin USB Cable(FT2CH)'      ← FT2232 类
'Parallel Port(LPT)'
'Digilent USB Device'
'USB Debugger A'              ← ⭐ 本板就是这个
'Gowin USB Cable(WINUSB)'
```

**怎么确认该选哪个**（不用猜）：

```powershell
cd 'C:\Gowin\Gowin_V1.9.12.03_x64\Programmer\bin'
.\programmer_cli.exe --scan-cables F     # 扫 FT2CH 类
.\programmer_cli.exe --scan-cables L     # 扫 LPT 类
```
实测输出：
```
Cable found:  USB Debugger A/0/0/null (USB location:0)      ← 本板
```

### 1.3 操作号（`--operation_index`）怎么选

来源 `C:\Gowin\Gowin_V1.9.12.03_x64\IDE\bin\programmer.json`：

| 模式 | 操作 | `CMD_INDEX` | 掉电后 |
|---|---|---|---|
| **SRAM Mode** | **SRAM Program** | **2** | ⚠️ **丢失**（适合快速验证） |
| SRAM Mode | SRAM Program and Verify | 4 | 丢失 |
| SRAM Mode | Reprogram（从 flash 重配） | 1 | — |
| Embedded Flash Mode | embFlash Erase,Program | 5 | ✅ 保留 |

📌 **验证阶段用 `2`（快，不写 flash）；要"开机自动跑"就用 flash 模式（`5`）。**

## 二、串口（给板子发命令）

### 2.1 参数

| 项 | 值 |
|---|---|
| 波特率 | **500000** |
| 数据位/校验/停止位 | **8N1**（无校验） |
| 流控 | 无 |

⚠️ **不是 115200**。代码里 `BAUD_DIV=100` = 50 MHz / 500 k。
⚠️ **不要试 1 Mbps** —— 代码注释记着实测：**1 Mbps 在这块板上【有误码】**（发 `'T'` 收到 `FA 54`），所以从 1 M 降到了 500 k。

### 2.2 用哪个串口（**容易搞错**）

| 设备 | 通道 | 串口（本机实测） | 用途 |
|---|---|---|---|
| 板载调试器 FT2232 | A | COM27 | **JTAG（烧录用）** |
| 板载调试器 FT2232 | B | COM28 | 调试器自己的 UART |
| **外接 USB-TTL（CH340）** | — | **COM31** | ⭐ **FPGA 的 UART** |

🔴 **FPGA 的串口不在板载调试器上** —— 约束文件写的是：

```
IO_LOC "uart_tx" D15;   // J9 · N25 · BANK1（出，USB-TTL 的 RX）
IO_LOC "uart_rx" D14;   // 入
```

⇒ **要把外接 USB-TTL 接到 J9 排针**（TX↔D14、RX↔D15、GND 共地）。

⚠️ **实测教训**：直接对 COM31 发命令**没有回包** ⇒ 说明 **USB-TTL 没接到 J9 上**（或接反了）。
⚠️ **COM 口号会变**：USB-TTL 重新插拔后从 COM24 变成了 COM31 ⇒ **每次插拔后重新确认口号**。

### 2.3 命令格式

⭐ **就是单个字母，不需要帧头**。
（`calib_cmd` 会跟踪 `0xA5` 事件帧的边界，只认"不在事件帧中间"的字母，所以直接发字母即可。）

**实测可用的收发姿势**（PowerShell）：

```powershell
$sp = New-Object System.IO.Ports.SerialPort 'COM31',500000,'None',8,'One'
$sp.ReadTimeout = 1000
$sp.Open(); Start-Sleep -Milliseconds 300; $sp.DiscardInBuffer()
$sp.Write('A'); Start-Sleep -Milliseconds 500
$r = $sp.ReadExisting()
"回包 = [" + ($r -replace '[^\x20-\x7e]','.') + "]"
$sp.Close()
```

## 三、⭐ 滑音验收（本次上板的核心）

### 3.1 三步

| 步 | 发什么 | 期望回包 | 说明 |
|---|---|---|---|
| 1 | **`A`** | **`a`** | 切到**指板模式**（fretboard） |
| 2 | **`W`** | **`w`** | **打开滑音**（默认**关**） |
| 3 | 手指从一根弦**横滑**到**物理相邻**的弦 | 听 | 音高**连续滑过去**，力度不变 |

🔴 **第 1 步不能省**：交付默认是**钢琴模式**，而滑音的音高更新被 `am_mode` 门控
（`top.v` 的 `pitch_upd_valid_i` 里的 `(ee_slide_v & am_mode)`），钢琴模式下 `am_mode=0` ⇒ **音高一动不动**。
✅ `'A'` 就是为这个加的（2026-10-13 新增，脱离屏切模式）。

### 3.2 物理相邻对（**必须物理相邻，⛔ 轴号相邻不算**）

```
上排：  6 - 7 - 0 - 1
下排：  5 - 4 - 3 - 2
```
例：`6 → 7` ✅ · `6 → 0` ❌（不挨着）

### 3.3 应该听到什么

| | 改之前（旧位流） | **现在** |
|---|---|---|
| 音高 | **一步**跳过去 | **84 小步连续滑**过去 |
| 时长 | 0 | **≈42 ms** |
| 力度 | — | **不变**（取 A 的） |

**时长旋钮**：`rtl/w3a/slide_ramp.v` 的 `SHIFT` 参数
（`3`≈21 ms · **`4`=交付默认 ≈42 ms** · `5`≈82 ms）。改完要重新综合 + 烧录。

### 3.4 听不到声音怎么办

1. **指板模式的起音要等拨弦比较器（LM393）** —— 代码注释写明：
   *"指板模式要等 P4 的 LM393 拨弦比较器，不接就永远不触发"*
   ⇒ 没接的话，**指板模式按了不出声**（这是设计如此，⛔ 不是 bug）
2. **临时验证办法**：先用**钢琴模式**（发 `A` 切回）确认"探测器触发"这条链活着
   —— 但钢琴模式下滑音**不改音高**（那是预期行为）
3. 确认功放使能：交付档 `PA_ON_AFTER_RESET=1` ⇒ `PA_EN_n` 恒高 ⇒ Console 板**出声**

## 四、故障排查

### 4.1 `Cable failed to open via the location`

| 检查 | 做法 |
|---|---|
| **① 线缆选错**（**最常见**） | 改成 **`USB Debugger A`**；用 `--scan-cables F` 确认 |
| ② Programmer 占着设备 | 关掉 `programmer.exe` 再试（**它会让 COM27 时有时无**，实测） |
| ③ 端口被占 | 别用串口工具打开 **COM27**（那是 JTAG 通道） |
| ④ 驱动 | 实测本机正常：`ftd2xx.dll` + `ftdibus.sys` + `ftser2k.sys`，版本 **2.12.36.20** |
| ⑤ USB 口 | 换直插口（⛔ 别用 hub），换数据线（不是充电线） |

### 4.2 烧录成功但串口没回包

| 检查 | 做法 |
|---|---|
| **USB-TTL 没接 J9**（**最常见**） | 接 TX↔D14 / RX↔D15 / GND 共地 |
| **COM 口号变了** | 重新 `[System.IO.Ports.SerialPort]::GetPortNames()` 确认 |
| 波特率 | 必须是 **500000 8N1** |
| 模式 | 已发过 `'A'` 吗？（发 `'A'` 应回 `'a'`；回 `'x'` 说明命令没被受理） |

### 4.3 回包对照表（常用）

| 发 | 回 | 含义 |
|---|---|---|
| `A` | `a` | ✅ 受理**模式翻转**（指板⇄钢琴） |
| `W` | `w` | ✅ 受理**滑音开关** |
| `I` | — | 切音色（循环） |
| `B` | — | 源 B 开/关（**交付档 = 鼓机开/关**，⛔ 不是节拍器） |
| `D` | — | 鼓机节奏型切下一个 |
| `T` | `t` | 受理 tare（重记零点） |
| `S` | `s` | 受理 span（行程标定） |
| `X` | `x` | 受理取消 |
| `P` | 轴号 | 诊断：回读 pos |
| `V` | — | 诊断：回读 span 状态 |
| — | `?` | 片号未知 / 被拒 |
| — | `!` | 稳定判据超时 / `'S'` 正忙被拒 |

📌 **完整命令表见** `Console引脚与控制接口总表-20261001.md`。
