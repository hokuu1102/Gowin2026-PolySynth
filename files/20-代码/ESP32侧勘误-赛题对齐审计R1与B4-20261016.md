## 二、B4 / R1：「LED 那一路**有意不闸**」——与代码不符，而且这是**第二个独立原因**

### 2.1 审计原文

> 「…`top.v:5607-5608` 闸掉 `.score_valid_i`；LED 那一路**有意不闸**（`top.v:7126-7127`）」

### 2.2 实际代码（`rtl/top.v` 的 `u_guide_lamp` 例化，当前在 **7172 行**起）

```verilog
// top.v:7177 起的注释自带真值表（原文）
//   LED 那一路的闸 = 全局 'U' 【或】 逐事件 bit6
guide_lamp.note_valid_i = ps_note_valid & (evt_guide_only | guide_only_r)
```

| `guide_only_r`（'U'） | `bit6`（逐事件） | 出声 | LED |
|---|---|---|---|
| 0 | 0 | 响 | **不指引** |
| 0 | 1 | 不响 | 指引 |
| 1 | 0 | 不响 | 指引 |
| 1 | 1 | 不响 | 指引 |

### 2.3 推论（这条比 note_off5 更硬）

⇒ **LED 亮的充要条件 = `bit6 = 1` 或 `'U'` 全局模式**。
⇒ **普通灌谱（`bit6=0`、`'U'` 关）LED 按设计就是暗的** —— 与 `note_off5` 无关。

⇒ 所以"上板 LED 大概率全暗"有**两个互相独立的原因**：

1. `note_off5` 没填（**已在 `feat/s3-ble` 解决**，见 §一）；
2. **没走引导模式**（`bit6` 与 `'U'` 都没开）—— 这一条**与 ESP32 填字段无关**，⛔ 填了也不会亮。

**正确用法**：走上位机的「引导 / 示范—重复」模式（我方逐事件置 `bit6`），或串口发 `'U'`。

### 2.4 顺带：行号已漂移（同族 C116）

`top.v:7126-7127` 那两行**现在是注释**（讲"三级依赖链"），不是例化 ⇒ 引用应加"**截至 `<commit>`**"。
