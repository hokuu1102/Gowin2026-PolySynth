> ⇒ ⭐ **"接进 `top.v`" ≠ "会进电路"** —— ⚠️ 它的 **8 个输出全都没有消费者**
> ⇒ 🔴 **串口灌曲谱现在完全无作用**（⭐ 连解析都没在跑）

## 一、⭐⭐ 现状（⭐ 全部实测，⛔ 不凭印象）

### 1.1 ⭐ `evt_merge` 的接口（`rtl/w3c/evt_merge.v`）

```verilog
module evt_merge #(...) (
    // ── 源 A：手弹 / 曲谱（`play_seq` 的输出，或 live 事件）──────
    input  wire a_valid_i;  a_axis_i;  a_phase_inc_i;  a_velocity_i;  a_kind_i;
    // ── 源 B：节拍器 / 鼓机 ────────────────────────────────────
    input  wire b_valid_i;  b_axis_i;  b_phase_inc_i;  b_velocity_i;  b_kind_i;
    // ── 合流后唯一出口（→ note_manager）─────────────────────────
    output evt_valid_o; evt_axis_o; evt_phase_inc_o; evt_velocity_o; evt_kind_o;
    // ── 可观测性 ───────────────────────────────────────────────
    output collision_cnt_o; merged_cnt_o; drop_cnt_o; overflow_o;
);
```

⭐ **注释原文**：
* 源 A = **"手弹 / 曲谱（`play_seq` 的输出，或 live 事件）"**
* 源 B = **"节拍器 / 鼓机"**

⇒ ⭐⭐ **架构上已经把"曲谱"归到源 A 了** ⇒ ⚠️ **但源 A 现在是【手弹】在用**。

### 1.2 ⭐ `top.v` 里源 A 的现状（⭐ 实测行号）

```verilog
// 行 1279~1283：源 A 的仲裁（⚠️ 只有 2 个选项）
wire src_a_valid = (SOURCE_A_SEL == 1) ? demo_note_valid : w3a_evt_v;
wire [3:0]  src_a_axis  = (SOURCE_A_SEL == 1) ? demo_note_axis  : w3a_evt_a;
wire [31:0] src_a_inc   = (SOURCE_A_SEL == 1) ? demo_note_inc   : w3a_evt_i;
wire [7:0]  src_a_vel   = (SOURCE_A_SEL == 1) ? demo_note_vel   : w3a_evt_v;
wire [1:0]  src_a_kind  = (SOURCE_A_SEL == 1) ? demo_note_kind  : w3a_evt_k;
```
* ⭐ `SOURCE_A_SEL = 0` ⇒ **W3a 手弹**（⭐ 交付/上板用）
* ⭐ `SOURCE_A_SEL = 1` ⇒ **演示和弦**（⭐ `T57` 验收用）

### 1.3 🔴 为什么它被扫掉了

```
⭐ evt_uart_rx 的 8 个输出（⭐ 实测：每个都只出现 2 次 = 声明 + 连接）：
   eu_evt_valid · eu_evt_data · eu_frame_cnt · eu_hdr_err_cnt
   eu_resync_cnt · eu_drop_cnt · eu_idx · eu_synced
⇒ 🔴 【没有任何消费者】⇒ ⭐ 综合器整体扫除
```

📌 **这是本项目第一次遇到"被优化掉"** —— ⚠️ 之前的坑是 `.gprj` **漏登记**（`U-30`/`84 号`），
⭐ 而这次是**登记了、也例化了、但没接线** ⇒ 🔴 **第三种"静默丢弃"**。

## 二、⭐⭐ 三种接入方案（⚠️ 按"改动大小"排序）

### 方案 ① ⭐⭐ **扩 `evt_merge` 到 3 入口**（⭐ 最干净，⚠️ 改动最大）

```
⭐ 给 evt_merge 加第三个入口（源 C）：
   · 源 A = 手弹（⭐ 不变）
   · 源 B = 节拍器 / 鼓机（⭐ 不变）
   · 源 C = 🔴 **曲谱**（⭐ 新增）
```

| ✅ 好处 | ⚠️ 代价 |
|---|---|
| ⭐ **三个源都能【同时】出声**（⭐ 手弹 + 节拍 + 曲谱） | 🔴 **要改 `evt_merge.v`**（⭐ 已落地模块，⭐ 有 tb + 5 个变异体）<br>⚠️ 要 `git` 出"3 路轮转仲裁" + 深度可能要从 4 加到 6 |
| ⭐ 语义最清晰 | ⚠️ **要重跑 `tb_evt_merge` + 加变异体** |

### 方案 ② ⭐ **把曲谱接到源 A，与手弹做模式切换**（⭐ 改动最小）

```
⭐ 扩 SOURCE_A_SEL 的取值：
   · 0 ⇒ 手弹（⭐ 现状）
   · 1 ⇒ 演示和弦（⭐ 现状）
   · 🔴 2 ⇒ ⭐ **曲谱**（⭐ 新增）
```

| ✅ 好处 | ⚠️ 代价 |
|---|---|
| ⭐ **⛔ 不改 `evt_merge`**（⭐ 它本来就写着"源 A = 手弹 / 曲谱"） | 🔴 **曲谱与手弹【互斥】** —— ⚠️ 播曲谱时**弹不了琴** |
| ⭐ 改动最小（⭐ 只改 `top.v` 一个 `parameter` + 3 行仲裁） | ⚠️ 演示时"伴奏 + 独奏"做不到 |

### 方案 ③ ⭐ **曲谱走源 B，与节拍器共享**（⚠️ 不推荐）

| ⚠️ 问题 |
|---|
| 🔴 源 B 是**专用池**（`axis_id >= 14`）⇒ ⚠️ 曲谱的旋律轴号是 **0~13**（普通池）<br>🔴 **走源 B 会占专用池的 voice** ⇒ ⚠️ 节拍器/鼓机被挤掉 |

## 三、✅ **已拍板：目标不互斥 · 现阶段只留接口（甲方案）**（⭐ 2026-09-24 用户确认）

> ⭐ **用户原话**：*"我本来想的是曲谱手弹**不互斥**。但是**现阶段可以先暂时不做**，
> **希望能留一点接口**吧。"*
> ⭐ **"留接口"方式**：⭐ **甲 —— 引到顶层端口**（⭐ 用户 2026-09-24 明确选择）

### 3.1 ⭐⭐ 决定

| 项 | ⭐ 决定 |
|---|---|
| **目标形态** | ⭐⭐ **不互斥** —— ⭐ 曲谱播放时手弹**照样出声**<br>⇒ 🔴 **必须扩 `evt_merge` 到 3 入口**（⭐ 见 §3.4） |
| **现阶段** | ⚠️ **先不做数据接入** ⇒ ⭐ **但必须"留接口"** |
| **"留接口"判据** | 🔴 ⭐ **`evt_uart_rx` ⛔ 不能被综合器扫掉**（⭐ 摆脱当前 `NL0002` 警告） |

### 3.2 🔴🔴 **为什么"只写 `parameter` 分支"是【无效】的**

```
⚠️ 若写成：wire src_a = (SOURCE_A_SEL==2) ? eu_evt_valid : w3a_evt_v;
🔴 而 SOURCE_A_SEL 是【parameter = 0】（⭐ 编译期常量）
⇒ ⭐ 综合器**先把三元式折叠** ⇒ 🔴 **`eu_*` 分支整块消失**
⇒ 🔴 **evt_uart_rx 照样被扫掉** —— ⭐ **陷阱没解决**
```

⚠️ **同族教训**：⭐ 这正是"**接进 `top.v` ≠ 会进电路**"的另一种形态
（⭐ 第一种是 `.gprj` 漏登记 `U-30`/`84 号`，⭐ 第二种是**无消费者**）。

### 3.3 ✅ **采用做法（甲）：引到顶层端口**

⭐ **为什么最可靠**：
```
⭐ 顶层【输出端口】⛔ 不可能被优化掉（⭐ 它要驱动真实引脚）
⇒ ⭐ 只要 `eu_*` 连到端口 ⇒ 🔴 **`evt_uart_rx` 必定被保留** ✅
```

⭐ **引哪两个**（⭐ **只引 2 个，⛔ 不贪多** —— ⚠️ 引脚省着用）：

| 信号 | ⭐ 为什么值得占一根引脚 |
|---|---|
| ⭐ **`eu_frame_cnt != 0`** | ⭐ **"收到过合法帧"** —— ⭐ **"串口通了"的最直接证据**，⭐ 上板一眼就能看 |
| ⭐ **`eu_hdr_err_cnt != 0`** | ⚠️ **"帧头错过"** —— ⭐ 诊断"波特率错/接线错"的**关键线索**<br>（⚠️ 且 ⭐ **发标定命令时它必然涨** ⇒ ⭐ 那是**预期行为**） |

```verilog
// ⭐ top.v 新增两个【调试输出端口】（⭐ 甲方案）
//   ⭐ 语义：⭐ 电平 = "该事件发生过"（⭐ 简化成 1 bit ⇒ ⭐ 省引脚）
//   ⚠️ 为什么不引完整计数器：⭐ 那要 32 根引脚 ⇒ 🔴 太浪费
output wire uart_dbg_rx_ok,     // ⭐ 1 = 至少成功解析过一帧（⭐ 串口通了的证据）
output wire uart_dbg_rx_err,    // ⭐ 1 = 出现过帧头错（⭐ 诊断用，⚠️ 发命令时会亮）

// ⭐ 驱动（⭐ 纯组合、零延迟）
assign uart_dbg_rx_ok  = (eu_frame_cnt   != 16'd0);
assign uart_dbg_rx_err = (eu_hdr_err_cnt != 16'd0);
```

### 3.3.1 ⭐⭐ 引脚从哪来 —— ⭐ **用 `PMOD`**（⭐ 2026-09-24 实测更正）

🔴🔴 **我第一版写错了**（⭐ 说"PMOD 已全部分配完、要借 `J9` 的预留脚"）——
⭐ **实测更正**：⭐ **`constr/top.cst` 用到的 31 个 ball 里，PMOD 的 16 根【一根都没用】**：

```
· 官方 Console `.cst` 共【180 个 IO】；⭐ 本项目已用 31 根
· ⭐ 三个排针的【真实】占用情况（⭐ 按 IO_LOC 清单核的，⛔ 不是看注释）：
    · 🟢 `PMOD0`（V18 V19 G21 G22 F18 E18 C22 B22）⇒ ⭐ **全空**
    · 🟢 `PMOD1`（W19 W20 F19 F20 E22 D22 E21 D21）⇒ ⭐ **全空**
    · 🔴 `J9`（38 根）⇒ ⭐ **22 个信号脚全部已分配**
        · N1~N6   = ADC（⭐ 已用）
        · N7~N10  = 片2/片3 预留（⭐ 已写进 `.cst`）
        · N11/N12 = +5V/GND
        · N13~N16 = 片4/片5 预留（⭐ 已写进 `.cst`）
        · N17~N24 = LED（⭐ 已用）
```

⭐ **原因**：⭐ **LED 组已从 `PMOD` 挪到 `J9`**（⭐ `2026-09-23` 引脚重排）
⇒ ⭐ 腾出的 PMOD 脚**一直没人用**。

⭐⭐ **结论（⭐ 已拍板）**：⭐ **调试端口用 `PMOD`** ——
⭐ 选 **2 根**（⭐ 建议 `PMOD0_IO0`/`IO1` = **`V18`/`V19`**）
✅ **好处**：⭐ 它是**标准 2.54 排针**，⭐ 最好接线（⭐ 比 `J9` 的双排更好插）
⚠️ **副作用**：⭐ **`PMOD 与 SDRAM` 是 `0Ω` 二选一** ⇒ ⛔ 插 PMOD 就不能插 SDRAM 模块
（⭐ 我们不用 SDRAM ⇒ ✅ 无冲突）

> 📌 **一条重要教训（⭐ 我踩了）**：⭐ **"文档/注释里写的引脚库存" ⛔ 不能当准** ——
> ⚠️ 我按 `top.cst` 的注释（"PMOD 16 根已全部分配完"）办事，
> ⭐ **差点把调试脚塞进已经排满的 `J9`** ⇒ 🔴 **那个"借预留脚"的方案是错的**。
> ⭐ **正解：⭐ 按 `IO_LOC` 实际清单核一遍**（⭐ 一条命令就能查）。


### 3.4 ⭐⭐ 真正接入时的形态（⭐ 将来做，⭐ 目标是"不互斥"）

> 🔴🔴 **2026-09-24 补充（⭐ 重要）**：⭐ **曲谱接入【必须与"鼓机接入"一起规划**
> —— ⚠️ 因为 `evt_merge` 的入口**不够用**（⭐ 见 §3.4.1）。

#### 3.4.1 🔴 **入口的账（⭐ 实测）**

⭐ **`evt_merge` 只有 2 个入口，且都已占用**（⭐ `top.v` 实测）：
| 源 | ⭐ 现在接的是 | ⚠️ 还要接 |
|---|---|---|
| **A** | ⭐ 手弹（`w3a_evt_*`） | ⭐ **+ 曲谱**（⭐ 目标"不互斥"） |
| **B** | ⭐ 节拍器（`met_evt_*`） | ⭐ **+ 鼓机**（⭐ 它也是专用池） |

⇒ 🔴 **总共需要 4 个源** ⇒ ⭐ **`evt_merge` 必须扩到 4 入口**
（⭐ 或 3 入口 + 源 B 内部先合流 —— ⚠️ 但**同拍相撞**问题要自己解）。

⭐⭐ **结论：⭐ "曲谱接入"与"鼓机接入"应该【合并成一次 `evt_merge` 改造】** ——
⚠️ 理由：⭐ 两者都要改同一个模块 ⇒ ⭐ **分开做要重验两次**
（⭐ 每次都要重跑 `tb_evt_merge` 8 条判据 + 补变异体 + 全量回归）。

⚠️ **改动清单（⭐ 合并做时的 checklist）**：

| # | 改什么 | ⚠️ 注意 |
|---|---|---|
| **1** | ⭐ `evt_merge.v` 扩到 **4 入口**（a/b/c/d） | ⚠️ **已落地模块** ⇒ ⭐ 要重跑 `tb_evt_merge` |
| **2** | ⭐ **轮转仲裁 2 路 → 4 路** | ⚠️ 现在是 `a/b` 轮流 ⇒ ⭐ 改 4 路轮转 |
| **3** | 🔴 **FIFO 深度的账要重算** | 🔴 现在 `DEPTH=4` 是按"**待发 1 + 同拍 2**"算的<br>⚠️ 4 路 ⇒ **同拍最多 4 条** ⇒ 🔴 **`DEPTH` 要 ≥ 6**（⭐ 建议 **8**） |
| **4** | ⭐ **加变异体**（⭐ 4 路轮转的新靶点） | ⭐ 见 `新模块变异靶点设计` 的做法 |

🔴 **第 3 条最容易漏** —— ⚠️ 若 `DEPTH` 不够 ⇒ **同拍 4 条会丢**
⇒ ⭐ **而 `drop_cnt_o` 会告诉你有丢**（⭐ 这正是 `K-106` 的价值：**丢了看得见**）。

### 4.3 ✅ **64 bit 事件的位域（⭐ 已核实，⛔ 不是猜的）**

📄 出处：`files/20-代码/play_seq接口冻结契约.md` **§1.1**（⭐ **冻结**，⭐ 来源 `tools/mid2evt.py`）

```
bit 63..44   tick      (20 bit)   音乐时间，PPQN = 960
bit 43..23   inc       (21 bit)   相位增量 phase_inc（kind==2 时改存 tick_inc）
bit 22..19   axis      (4 bit)    轴号 0..15
bit 18..11   vel       (8 bit)    力度
bit 10..9    kind      (2 bit)    0=note_on, 1=note_off, 2=换速
bit  8..7    timbre    (2 bit)    ⭐ 音色号 0..3（2026-09-22 夜新增）
bit  6..0              (7 bit)    ⭐ 保留，必须写 0
```

⇒ ⭐ **拆字段就是纯 `assign`**（⭐ 无状态、零延迟）：
```verilog
wire [3:0]  eu_axis_w  = eu_evt_data[22:19];
wire [31:0] eu_inc_w   = {11'd0, eu_evt_data[43:23]};   // ⭐ 21 位零扩展到 32
wire [7:0]  eu_vel_w   = eu_evt_data[18:11];
wire [1:0]  eu_kind_w  = eu_evt_data[10:9];
wire [1:0]  eu_timbre_w= eu_evt_data[8:7];              // ⭐ 见下方"附带收益"
```

#### ⭐⭐ **附带收益：`timbre` 字段可以让"多声部不同音色"真正生效**

⭐ **契约里写得很清楚**（⭐ 原文）：
> ⭐ **接收端【零改动】**：`note_manager` 的 `evt_timbre_valid_i` / `evt_timbre_i`
> **端口早就存在**（⭐ 注释写着"Looper 每层覆盖"）
> ⇒ ⚠️ **只需 `top.v` 接上**。

⚠️ **现状**：🔴 `top.v` 把 **`evt_timbre_i` 硬接成 0**
⇒ ⚠️ **所有声部（多把吉他/贝斯）音色全一样**（⭐ 这正是 `U-27` 的剩余项）。

⇒ ⭐⭐ **建议：本次接入时顺手把 `eu_timbre_w` 接上** ——
⭐ **代价 ≈ 0**（⭐ `note_manager` **零改动**，⭐ 只加一条 `assign`）
⭐ **收益**：⭐ **曲谱的 GUITAR / PIANO / BASS 声部音色立刻分开**（⭐ 听感提升明显）。

> 📌 **但注意**：⭐ 这**需要 `wavetable_bank` 真的支持 4 音色**（⚠️ `TIMBRE_N=4` 已参数化，
> ⭐ 见 `T51`/`K-86`）⇒ ⚠️ **要核实波表是否已生成 4 套**（⭐ 属另一条线）。

### 4.4 ⭐ 改 3：把可观测性接出去（⭐ 这条不能省）
