## 二、问题事实（已实测，⛔ 不是推测）

### 2.1 用户实测现象

用户灌了一份含鼓的 MIDI（`6.世界悲(已修订).mid`，轨名 "Drum"，通道 10，4320 个音符）：
> **"上到 fpga 听着怪怪的，是不是把鼓也推成音高了"**

⭐ **判断正确**。实测该轨用到的 MIDI 音高是
`36, 38, 42, 45, 46, 47, 48, 50, 51, 53, 55, 57` ——
这些是 **GM 打击乐音高**，被当成**乐音**发出去 ⇒ **鼓变成了低音区的音阶**。

### 2.2 根本冲突

你们 §五 给的鼓机四件 `phase_inc`（`rtl/w3c/drum_gen.v:180-186`）是 **32 位**：

| 件 | `phase_inc` | 频率 | 需要位数 |
|---|---|---|---|
| Kick | 5 368 709 | 61.04 Hz | **23 bit** |
| Snare | 42 949 673 | 488.28 Hz | **26 bit** |
| HiHat | 171 798 691 | 1953.12 Hz | **28 bit** |
| Tom | 17 895 697 | 203.45 Hz | **25 bit** |

🔴 **而下行事件字的 `inc` 字段只有 21 位**（`bit[43:23]`，
⭐ 你们 `top.v:4506` 自己也注明了 *"注意是 21 位！"*）。

⇒ **四个值全部放不下**：

| 件 | 超 21 位 | 被 `& 0x1FFFFF` 截断后 |
|---|---|---|
| Kick | 2.56 倍 | 1 174 405 |
| Snare | 20.48 倍 | 1 006 633 |
| HiHat | 81.92 倍 | 1 929 379 |
| Tom | 8.53 倍 | 1 118 481 |

⚠️ **21 位能表示的最高频率只有 23.84 Hz** —— **连 Kick（61 Hz）都装不下**。

📌 **实测复现**：我方按你们给的值填进 21 位字段，读回来就是"截断后"那一列。

## 三、需求（请你们从下面挑一条实现）

⚠️ 三条**都需要你们动手**（因为下行是你们在解码，而四个值放不进 21 位）。
区别只在**你们改多少**。⭐ 我方三种都能配合，且改动都很小。

### ⭐ 方案 A：`axis == 15` 时，用 `inc` 低 2 位查表（我方推荐）

**接口约定**：当下行事件的 `axis == 15` 时，
`inc` 字段的**低 2 位**表示鼓件号，**高 19 位填 0**：

```
inc[1:0] = 0 → Kick
         = 1 → Snare
         = 2 → HiHat
         = 3 → Tom
```

**你们要做的**：
```verilog
// 示意，位置由你们定（靠近 drm_evt_inc 即可）
wire [31:0] drum_inc = (inc[1:0] == 2'd0) ? 32'd5368709    // Kick
                     : (inc[1:0] == 2'd1) ? 32'd42949673   // Snare
                     : (inc[1:0] == 2'd2) ? 32'd171798691  // HiHat
                     :                      32'd17895697;  // Tom
```

**改动量**：⭐ **几行 RTL**（一个 4 选 1 mux + 一张 4 项常量表）
**我方改动**：填 `inc` 的两行（映射表已建好）
**代价**：⚠️ 需要你们**重跑一次 PnR**
**优点**：⭐ **不重排 64 位字、不动协议版本、不需要双方重新冻版**

⚠️ **需要你们确认的点**：用 `inc` 低 2 位存鼓件号，
   借用了字段语义 —— 请确认**不会与将来别的用途冲突**。

### 方案 B：把下行 `inc` 从 21 位加宽

当前 64 位字已用 **57 位**，空闲 **7 位**（`bit[6:0]`）。
要把 `inc` 加宽到 **28 位**（HiHat 需要），正好需要**额外 7 位** ⇒ **刚好用光**。

**代价**：⚠️ 要重排整个字 ⇒ 影响 `mid2evt.py`、RTL 解码、我方 `score_word.py`
与全部工具 ⇒ **必须双方先冻结新协议**。
**优点**：一劳永逸（将来别的乐器也不会再撞位宽）。
📌 我方认为**现在做收益不值** —— 除非你们本来就要改字布局。

### 方案 C：鼓走**另一条通路**（键盘打鼓那条）

⭐ 你们 §四 第 3 条说：**"键盘打鼓也靠来源：`src == SRC_KDRUM`"**，
§五 又说键盘 `'K'` 打鼓**用的是同一组常量**。

⇒ ⭐ **说明键盘打鼓本来就不走下行事件字**（否则也会有同样的位宽问题）。

**那么 PC 侧的鼓走【同一条路】最自然**：
**请你们给出那条路的接口**（命令码 / 参数格式 / tick 字段）——
我方按它发鼓，完全不碰 64 位字。

⚠️ 需要你们先定义接口（现在只有键盘用它）。
