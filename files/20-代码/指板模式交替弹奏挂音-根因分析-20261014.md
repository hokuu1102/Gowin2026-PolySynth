# 指板模式「连续交替弹奏 → 挂音」—— 根因分析（2026-10-14）

> **现象**：指板模式下连续交替弹奏后出现**挂音**（一个音一直响）
> **已排除**：用户拧了很多圈电位器**没有改善**
> **本文结论**：🔴 **是代码逻辑问题，⛔ 不是比较器阈值、⛔ 不是迟滞**

---

## 〇、结论先行

| 项 | 结论 |
|---|---|
| 是不是迟滞？ | ⛔ **不是** —— 迟滞只影响"触发几次"，🔴 **不会吞 `note_off`** |
| 调电位器有用吗？ | ⛔ **没有** —— 阈值只决定"沿何时出现"，⛔ 不决定"`note_off` 发不发" |
| 真因 | 🔴 **`play_mode_ctrl` 只跟踪【一个】正在响的轴** ⇒ 交替时旧音的 `note_off` 被**孤儿化** |
| 为什么"连续交替"才出现 | ⭐ 每交替一次就丢一个 `note_off` ⇒ **累积** |

⭐ **判据（关键）**：⭐ 挂音 = *"起了音但没收到 `note_off`"*
⇒ 🔴 一定是**释放路径**的问题，⛔ 不是触发路径 ✓

## 一、代码事实（⭐ 逐条，位置可核）

### 1.1 指板模式只跟踪【一个】"正在响的轴"

`rtl/w3a/play_mode_ctrl.v:92-100`
```verilog
} else if (pluck_valid_i && selected_valid) begin
    evt_valid_o <= 1'b1;
    evt_axis_o  <= selected_axis;
    evt_kind_o  <= KIND_PLUCK;      // ⭐ 起音
    gate_valid  <= 1'b1;
    gate_axis   <= selected_axis;   // 🔴 【只有这一个】gate_axis
end
```

### 1.2 释放（note_off）的**唯一出口**，且带条件

`rtl/w3a/play_mode_ctrl.v:126-132`
```verilog
if (gate_valid && ((axis_i == gate_axis) || (axis_i == selected_axis))) begin
    evt_valid_o <= 1'b1;
    evt_axis_o  <= gate_axis;       // ⭐ 释放【正在响】的那个轴
    evt_kind_o  <= KIND_OFF;
    evt_depth_o <= {DEPTH_W{1'b0}};
    gate_valid  <= 1'b0;
end
```

### 1.3 拨弦只认【上升沿】，且不应期内的沿【静默丢弃】

`rtl/w3a/async_pluck_capture.v:21, 43-50`
```verilog

wire down_rise = down_ff2 && !down_prev;

pluck_valid_o <= 1'b0;

    refractory_q <= refractory_q - 32'd1;      // 🔴 不应期内：只倒数，【沿被丢弃、无计数、无指示】
end else if (up_rise || down_rise) begin
    pluck_valid_o <= 1'b1;
    pluck_up_o    <= up_rise;
    refractory_q  <= REFRACT_CYC;              // top.v 传 1_500_000 = 30 ms
end
```

## 二、🔴 交替弹奏挂音的机理（逐步）

```text
① 按 A（axis ON）  ⇒ selected_axis = A
② 拨弦             ⇒ 发 PLUCK axis=A；gate_valid=1，gate_axis=A     ← A 起音
③ 按 B（axis ON）  ⇒ selected_axis = B        （⚠️ gate_axis 仍是 A）
④ 拨弦             ⇒ 发 PLUCK axis=B；gate_axis = B                 ← 🔴 直接【覆盖】
                      ⇒ A 被"孤儿化"：再没有任何变量记住"还有一个 A 在响"
⑤ 松 A（axis OFF） ⇒ axis_i(A) != gate_axis(B)；也不等于 selected_axis(B)
                      ⇒ ⛔ ①1.2 的条件不成立 ⇒ 【不发 note_off】
                      ⇒ 🔴 A 永久挂音
```

⭐ **每交替一次 ⇒ 丢一个 `note_off`** ⇒ 连续交替 ⇒ **挂音累积** ✓

📌 **为什么单次弹不挂**：⭐ 不做"③按新轴"就一直是 `axis_i == gate_axis` ⇒ 条件成立 ⇒ 正常释放 ✅
📌 **为什么"交替"才挂**：⭐ 正是③把 `selected_axis` 挪走、④把 `gate_axis` 覆盖 ⇒ 旧轴失联 ✅

## 三、为什么"电位器 / 迟滞"都治不了

| 项 | 它管什么 | 能不能治挂音 |
|---|---|---|
| **参考电压电位器** | 比较器翻转的**时机**（⇒ 沿何时出现） | ⛔ **不能** —— 它改变"触发"，⛔ 不改"释放" |
| **比较器迟滞** | 阈值附近的**抖动**（⇒ 会不会重复触发） | ⛔ **不能** —— 它只影响**触发次数**，🔴 **从不吞 `note_off`** |
| 🔴 **`gate_axis` 只有一个** | 记录"谁在响" | ✅ **真因** |

⭐ 用户**拧了很多圈没改善** —— 这个实测本身就是证据：⭐ 说明症状对阈值不敏感 ⇒ 指向逻辑侧 ✅

## 四、修法（⭐ 三选一，代价递增）

### 方案 A（⭐ 最小、语义正确）：**新拨弦前先放掉旧音**
- ⭐ 在 `pluck_valid_i && selected_valid` 分支里：⭐ 若 `gate_valid` 已为 1 ⇒ **先发一拍 `note_off(gate_axis)`**，⛔ 下一拍再发 `PLUCK`
- 📌 语义 = **单弦单音**（⭐ 吉他本来就是"再拨一次 ⇒ 前一个音停"）
- ⚠️ 代价：⭐ 两拍（⛔ 不能同拍发两个事件）⇒ 需一个小的二级状态
- ⭐ 资源：**~10 LUT**

### 方案 B：**`gate_axis` 改成位图**（⭐ 支持"多个轴同时在响"）
- ⭐ `gate_axis[15:0]` ⇒ 每个轴一位；`OFF` 时**按轴位**清
- 📌 语义 = **真复音**（⭐ 与"32 复音"的设计更搭 ✅）
- ⚠️ 代价：⭐ 改动面比 A 大（⭐ 涉及 `evt_axis_o` 从"单个轴号"变成"要释放哪个轴"的仲裁）
- ⭐ 资源：**~20 LUT**

### 方案 C（⭐ 兜底）：**松手即释放**
- ⭐ 放宽 ①1.2 的条件为：⭐ `gate_valid` ⇒ **任何轴 OFF 都放掉 `gate_axis`**
- ⚠️ 风险：⭐ 两根手指都按下时，⭐ 抬一根会把另一根的音也放掉 ⇒ 🔴 **误释放**
- ⭐ 资源：**~2 LUT**（⭐ 最省，但语义最糙）

## 五、验收判据（⭐ 每条都要能失败）

| # | 判据 |
|---|---|
| **A1** | ⭐ **交替两次不挂音**：`ON(A)→PLUCK→ON(B)→PLUCK→OFF(A)` ⇒ ⭐ **必须至少发出 1 个 `note_off`** |
| **A2** | ⭐ 做 A1 之后 ⇒ ⭐ **没有任何轴仍处于"在响"状态**（⭐ 查 `gate_valid` 或等价状态） |
| **A3** | ⭐ **零回归**：⭐ 既有的 P0-22 两条（滑品后松手 / 键盘→指板切换）**必须仍然绿** |
| **A4** | ⭐ **连续交替 20 次** ⇒ ⭐ `note_off` 数 **==** `PLUCK` 数（⭐ 防累积） |
