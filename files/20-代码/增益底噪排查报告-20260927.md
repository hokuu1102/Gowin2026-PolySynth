## 一、✅ 修复 1：开机竞态（commit `70d4f09`）

### 症状
⭐ "水怪低吼" + 示波器 1.4V 波动有负值 + 单键听不清

### ⭐⭐ 诊断链（⭐ 六个探针，⭐ 全部有实测证据）

| # | 探针 | 发现 |
|---|---|---|
| 1 | `dbg_idle.sv` | ⭐ 静音时 `sample_mono` 非零 **100%**、峰值 **34.8%** |
| 2 | `dbg_dc.sv` | ⭐ 逐级追踪：`mixer` 输出即 30% ⇒ 源头在 **mixer 上游** |
| 3 | `dbg_noteoff.sv` | 🔴 `note_manager` 收 **on=11 / off=3**（⭐ 多 8 个 `on`） |
| 4 | `dbg_pos.sv` | ✅ 稳态下 16 轴 `pos` 全 0、越阈 **0** ⇒ **键盘链干净** |
| 5 | `dbg_extra2.sv` | 🔴 键盘源 `w3a_evt_valid` 发 **8 个 `on`（无 `off`）** |
| 6 | `dbg_when.sv` | ⭐⭐ **决定性**：8 个事件在 `at_done` 上升沿后 5~19 拍，`pos = 2110` |

### 🔴 根因

```verilog
// calib_autotare.v —— T 拍
tare_o   <= {N_ADC{1'b1}};
if (cur_ch == (NCH-1)) state <= ST_DONE;   // ⭐ 同拍 ⇒ done_o 立刻置起

// calib.sv:145-148 —— T+1 拍
if (tare) zero_r[cal_ch] <= raw;                                  // ⭐ 写入（下一拍生效）
prod_r <= (raw > zero_r[ch]) ? ((raw - zero_r[ch]) * gain) : 0;   // 🔴 用【旧 zero】!
```

**⇒ `event_extract` 抢在 `zero` 生效前，拿 `pos = 2110`（未 tare）判按键**
**⇒ `2110 ≫ TRIG_TH = 192` ⇒ 16 轴全判"按下" ⇒ 8 个 `note_on` 无 `off` ⇒ 8 voice 恒响**

### 🔧 修法
`enable_i` 改用**延迟 16 拍**的 `at_en_ready`（320 ns，无感）。

### ✅ 验证

| 判据 | 修复前 | **修复后** |
|---|---|---|
| 键盘源事件 | 🔴 8 on / 0 off | ✅ **0 / 0** |
| `note_manager` | 🔴 11 on / 3 off | ✅ **3 on / 3 off** |
| `n_active` 峰值 | **8** | ✅ **3** |
| `sample_mono` 峰值 | 34.8% | ✅ **8.06%** |

## 二、✅ 修复 2：单音偏小（commit `710a1e2`）

### 量化（`build/exp/gain_chain.py`）

```
单 voice 满幅 sh24（>>>1 之后）= 8388096 = 100.0% 满幅
  >>>1    = −6.0 dB
  gain=44 = −9.3 dB
  合计     = −15.3 dB  ⇒ 单音只剩 34%  ⇒ "单音小"
```

### ⭐⭐ 关键：失谐已生效 ⇒ 叠加模型从"相干"变成"非相干"

| gain | N=1 | N=2 | N=4 | N=8 | N=16 |
|---|---|---|---|---|---|
| 44（同相） | 34% | 48% | 69% | 100% | 137% |
| 44（**非相干**） | 34% | 34% | 34% | 35% | 34% |
| **88（非相干）** | **69%** | **68%** | **69%** | **68%** | **69%** ✅ |

**⇒ 基准 44 → 88：单音 69%，且所有 N 恒定、不削顶。**

### 📌 澄清："104 全失真"不是 104 的错

**当时⛔ 无失谐** ⇒ 两 lane 严格相干（×2）⇒ N=2 就 115%。
**⇒ 问题在"无失谐"，⛔ 不在那个数。**

## 四、⭐ 开源对照（⭐ 源码级）

### 4.1 xls32（[repo](https://github.com/kazunori279/xls32-fpga-synth)）

| 项 | xls32 | 我们 | 评价 |
|---|---|---|---|
| 累加器 | `s32` | **40 位** | ✅ 更宽 |
| 归一化 | ⭐ **固定 `comp`**（按 unison 数 `256/√N`） | 动态 `popcount` | ✅ 等价 |
| `scale_mix` | ⭐ 只在最后一级 | 每 voice 乘 gain | ✅ 数学等价 |
| 2 振荡器 | ⭐ **detuned** | ⭐ **已补失谐** | ✅ 对齐 |
| 去相关初相 | ⭐ **LFSR 随机** | ⭐ **1/4 周期** | ✅ 等效（只有 1 个副本） |
| `note_off` | ⭐ 只写 `env_st = RELEASE`，ADSR 自归零 | 同上 | ✅ 一致 |

**⭐ 关键引用**（`apply_off` 注释）：
> *"`hard` does NOT zero env. adsr's OFF arm does it on the next sample…
> `apply_on`'s free-slot test is `env_st == OFF`."*

**⭐ 失谐的源码依据**（`process_voice`）：
```rust
let doff = match detsel { u2:0 => u32:0, u2:1 => inc >> u32:9, u2:2 => inc >> u32:8, _ => inc >> u32:7 };
let o12 = if detsel == u2:0 { main } else { (main + det2) >> u16:1 };   // ⭐ 取平均
```
**⇒ 我们的 `>>>1` + `>>8` 与它一致** ✅

## 五、⚠️ ⭐⭐ 三个"测量陷阱"（⭐ 我反复踩，⭐ 必须记住）

| # | 陷阱 | 错误结论 | 正解 |
|---|---|---|---|
| 1 | **`%0d` 打印 >32 位值被截断** | 🔴 "`acc_r ≈ 2^31`，位宽 bug" | ⭐ 小负数被折成无符号大正数 |
| 2 | **`at_done` 后立即清统计** | 🔴 "16 个轴都越阈" | ⭐ 把**标定前瞬态**算进去 |
| 3 | **等待时间 < 理论时间常数** | 🔴 "env 冻结，ADSR 有 bug" | ⭐ 实际在**正常衰减**（⭐ **踩三次**） |

### ⭐⭐ 陷阱 3 的量化

```
⭐ 衰减速率 = `RELEASE_STEP/sample_tick` = 2/1024 = 0.001953 env/拍
⭐ env 峰值 ≈ 50728 ⇒ 归零需 `50728/0.001953 = 26M 拍 = 0.52 秒`
🔴 而我先等 2M、后等 8M 拍 ⇒ 只看到"衰减中途" ⇒ 误判成"卡住"
```

**📌 规则**：⭐ **判断"是否归零"前，先按【理论时间常数】算出需要等多久**（⛔ 不凭感觉）。
