# 🔧 `K-133` 修复方案（⭐ 待回归跑完后执行）

> **问题**：⭐ `span_probe.v` 的 `'V'` 输出第 5 个可见字符是**硬编码常量 `'0'`**
> **影响**：⚠️ 输出长得像"4 位 reject"，🔴 **极易误读**（⭐ 我自己就先把 `V7090` 解成了 `rej=0x90=144`）
> **优先级**：⭐ 低（⭐ 只是可读性，⛔ 不影响功能）—— ⭐ 但它**每次排查都在用**，⭐ 修了省心

---

## 一、⭐ 现状（⭐ 字节级）

`span_probe.v` 的 `tx_byte_c` 查表：

| ⭐ `idx` | ⭐ 内容 | ⭐ 说明 |
|---|---|---|
| 0 | `8'h56` | ⭐ `'V'` |
| 1 | `hexch({1'b0, st_lat})` | ⭐ state |
| 2 | `hexch(ax_lat)` | ⭐ axis |
| 3 | `hexch(rj_lat)` | ⭐ reject_cnt（⭐ 全部 4 位都发出来了） |
| **4** | 🔴 **`8'h30`（常量 `'0'`）** | 🔴 **多余** |
| 5 | `8'h0D` | ⭐ CR |
| 6 | `8'h0A` | ⭐ LF |

### 🔴 设计时的误解

⭐ 当时以为 `reject_cnt` 需要**2 位 hex**，⚠️ **但它其实是 `reg [3:0]`（0~15）**
⇒ ⭐ **`hexch()` 已经覆盖 0~F** ⇒ 🔴 **`idx4` 完全多余**。

📌 **它现在的唯一作用是"让输出看起来像 4 位 reject"** ⇒ 🔴 **纯误导**。

---

## 二、⭐ 建议修法（⭐ 三选一）

| ⭐ 方案 | ⭐ `idx4` 改成 | ⭐ 价值 |
|---|---|---|
| **A** ⭐⭐ **`hexch(vote_cnt)`** | ⭐ 投票进度（⭐ 0~8） | ⭐ **卡在 VOTE 时能看出"收了几帧"** ⇒ 🎯 **对当前排查最有用** |
| **B** | ⭐ `hexch({2'b0, cal_busy_i, cal_err_i})` | ⭐ 看 `calib` 的反馈（⭐ 是否真在跑 / 是否报错） |
| **C** ⚠️ | ⭐ 直接**去掉 `idx4`**，`N_BYTES` 7 → 6 | ⭐ 最干净，⚠️ 但要**改 `top.v` 的 `N_BYTES`**（⭐ 两处一起改） |

### 🎯 **推荐 A**（⭐ 理由）

```
🔴 当前 `'S'` 的**未解之谜**是"为什么被拒"。
⭐ 而 `calib_span` 的拒绝有三条路：
   ① S_SETTLE 超时   ⇒ state 停在 2
   ② S_VOTE   超时   ⇒ state 停在 3
   ③ S_FIRE  离散度超 ⇒ 从 3 跳回 1
⭐ 方案 A 能【同时】区分 ①②（⭐ 看 state + vote_cnt）
   ⚠️ 而"3 但 vote_cnt 不满" ⇒ ⭐ **明确是收不齐帧**（⭐ 而非稳定问题）
```

---

## 三、⭐ 具体改法（⭐ 方案 A）

### ① 加一个端口（⭐ 传入 `vote_cnt`）

⚠️ `calib_span` 目前**没有**把 `vote_cnt` 导出 ⇒ ⭐ 需要新增一个输出。

```verilog
// calib_span.v —— 在诊断输出区加（⭐ 与 state_o / rej_cnt_o 并列）
output wire [5:0] vote_cnt_o          // ⭐ 投票进度（⭐ 诊断用）
...
assign vote_cnt_o = vote_cnt;
```

⚠️ **同时要在 `top.v` 里接出来**：
```verilog
wire [5:0] sp_vote_cnt;
...
.vote_cnt_o (sp_vote_cnt),
```

### ② `span_probe` 加端口 + 改查表

```verilog
// span_probe.v
input wire [5:0] vote_i,
...
    4'd4: tx_byte_c = hexch(vote_i[3:0]);    // ⭐ 改成投票进度（⭐ 原为常量 '0'）
```

⚠️ **`vote_cnt` 最大 8** ⇒ ⭐ 低 4 位够（⭐ 但为将来留余量用 `[3:0]` 即可）。

### ③ 更新注释

🔴 **必须把模块头部的格式说明改掉**（⭐ 否则下一个人还会照旧解）：
```
⭐ `V<state><axis><rej><vote>\r\n`     （⭐ 共 7 字节）
· `<vote>` —— ⭐ 1 位 hex：⭐ `vote_cnt`（⭐ 投票已收帧数，⭐ 0~8）
🔴 注意：⭐ 本行【原来是】一个硬编码的 '0' ⇒ ⚠️ 曾导致误读（⭐ 见 K-133）
```
