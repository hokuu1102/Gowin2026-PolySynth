## 二、本周期修好的两个 bug（根因 + 判据）

### bug 1 · `'A'` 命令完全不工作（🔴 最优先，是我自己留的缺口）

**用户原话**：「发 A 不回复 a，切过去和钢琴是一模一样的，音高一样，并且也不需要比较器就能触发」

**根因**：`rtl/w3a/calib_cmd.v` 有一个**总闸** `wire byte_is_cmd = ...`，
命令**必须先列进这个总闸**才会进入分发块。上次我只加了"抬脉冲"的分支，
**忘了把 `byte_is_mode_sw` 加进总闸** ⇒ `'A'` **连命令都不算**：
不回包、`cmd_cnt_o` 不增、`mode_o` 不变 —— 与用户看到的现象逐条吻合。

**坑的恶劣之处**：那个总闸旁边**有两条注释正在警告这件事**
（"四个新字母必须在这里"、"`'Y'` 同理"），**我还是踩了**。

**修法**：把 `byte_is_mode_sw` 加进总闸（`calib_cmd.v:389` 附近）+ 修缩进。

**判据**（`tb/w3a/tb_calib_cmd.sv`，共 7 条，**改前必红**）：

```
FAIL 'A' outside a frame raises mode_sw_req exactly once
FAIL 'A' increments cmd_cnt_o (4 -> 5)      ← cmd_cnt 不动是铁证
```

**已做全仓排查**：确认**没有别的命令**漏在总闸外
（唯二"有分支但不在总闸"的是 `byte_is_header` 和 `byte_is_cmd` 自身，都是设计如此）。

**端到端那一段也补了判据**（本次未提交的那处）：`tb/w3c/tb_uart_ui.sv` 加了 5 条，
证明 `mode_sw_req_i` 真的会翻转 `mode_o` 并发一拍 `mode_commit`（含"可连发""拉低后不翻转"）。

### bug 2 · 颤音推子（CH2）几乎无感

**用户原话**：「感觉颤音的第二个推子没什么用啊，只要不是在最底下，感觉都没什么太大的差别」

**根因**：`P0-19` 当年用一个**限幅**止血：`depth_eff = min(raw, 120)`。
⇒ 只有**最底 2.9%**（120/4095）的行程有效，**2.9%~100% 全是恒定满深度**
⇒ **推子等于开关** —— 与用户描述逐字吻合。

**修法**：改成**全行程线性映射**（`raw × 120 >> 12`；120 = 64+32+16+8，**不用乘法器**）。
滞回仍比较**原始**推子值 ⇒ 死区语义逐位不变；**最大深度不变** ⇒ 不翻负的保证仍成立。

**实测**：满行程峰值仍是 **952**（上限 960）；中点（2048）从 **952 → 480**。

**我自己也踩了一次**：第一版移位写错（写成 `[18:7]`，即 `>>7`，深了 32 倍，
峰值 30712），**被已有的"深度上限"判据当场抓住**。

**判据**：`tb/w3b/tb_vibrato_lfo.sv` 加 2 条（改前必红）——
中点深度必须**明显小于**满行程、且**明显非零**。

### 附带修的注释（纯注释，网表不可能变）

- `top.v` 两处把显示切换命令写成 `'Q'` —— 实际是 **`'E'`**（`'Q'` 现在归 BPM）
- `play_mode_ctrl.v` 写"切到 PIANO（`fretboard_mode_i=1`）" —— **两处都错**：
  ① 极性反了（`=1` 是**指板**，端口注释就是 `0=keyboard, 1=fretboard`）；
  ② `BASS→GUITAR→PIANO→PAD` 是**音色循环**（`'I'`），与**演奏模式**是两回事

## 五、硬约束速查（都是踩过的坑，别重犯）

### 5.1 加一条串口命令要改 **6 处**，第 6 处是头号陷阱

```
1. parameter [7:0] CMD_XXX = 8'hXX        # 常量
2. output reg xxx_req_o                    # 端口
3. wire byte_is_xxx = (rx_data_i == CMD_XXX);
4. 复位块 + 默认清零块：xxx_req_o <= 1'b0;   # 两处
5. if (byte_is_xxx) xxx_req_o <= 1'b1;     # 出脉冲
6. 🔴 把 byte_is_xxx 加进 byte_is_cmd 总闸  ← 'A' 就是漏了这步
```
**另需同步**：`cmd_tab[N]` + `N_CMD`；`top.v` 的回包映射
（`rep_req` 加 `| cmd_xxx_req`，`rep_byte` 加 `: cmd_xxx_req ? 8'hXX`，否则落到兜底 `'x'`）。
**空闲字母只剩 `O` / `U` / `Z`。**

### 5.2 其它

| 约束 | 说明 |
|---|---|
| `.ps1` 编码 | 必须 **UTF-8 BOM** 或**纯 ASCII**；`edit` 工具会掉 BOM，改完要补回（判据见 `check_ps1_encoding.ps1`） |
| HDL 编码 | **不许有 BOM**（`check_no_bom.ps1`） |
| 变异测试锚点 | `find`/`repl` **只留纯 ASCII**，尾部中文注释会静默 `SKIP` |
| 新建 HDL | **必须登记进 `Gowin2026.gprj`**（`type="file.verilog"`，`.sv` 也是这个 type），否则综合**静默丢弃**：不报错、时序正常、位流里没有它 |
| `.gprj` 注释 | **只能 ASCII**（文件头就是这么要求的） |
| 编辑大文件 | **只用 `edit` 工具**，不许"读文本+写文本"整体重写（会把行尾 LF 变 CRLF，整个文件都算改动） |
| 改长行 | `old_string` 必须**覆盖整行**，否则旧行剩余部分会变成孤立残行 |
| PnR | **确定性**，"重跑"没用；**绝不能并发**（两个实例会互相破坏输出目录） |
| 省 LUT 的改动 | 必须**实测** `u_<模块>` 的 Lut 与顶层 CLS 增量，**不能靠 (N−1) 模型推算当结论** |
| 报告纪律 | **所有说明必须输出到正文**，不许只藏在思考里（用户明确要求） |

- 此时**你的 ESP32（`VID_303A&PID_1001`）还在** ⇒ 说明只有 FPGA 板掉了

**让用户查**：① USB 线松了/被碰掉 ② 板子供电（Console 要 **5V/2A**）③ 换 USB 口（直插主板，别用 hub）④ 用**数据线**不是充电线。

## 八、这个项目的工作方法（给下一个会话）

1. **长任务挂后台**，别前台干等；用 `job_output` 收，别反复轮询。
2. **报告要外化** —— 所有说明写进正文，不要在思考里憋着（用户明确提过两次）。
3. **判据红了先回退**，不要一边红一边往前做。
4. **"跑完了"不等于通过** —— 回归看"通过数 == 共数"，PnR 看 `0 setup / 0 hold`。
5. **不要在没有复现步骤时瞎修症状**（P3 挂音就属于这类）。
6. **用户描述与我的模型不符时，不许当成用户听错**（本项目有过两次因此翻案）。
7. **代码是地面真相**：两份文档冲突且都自称"已拍板"时，先去读代码里**实际生效的那个常量**。
