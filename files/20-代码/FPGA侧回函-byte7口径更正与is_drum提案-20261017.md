## 一、确认：`[3:0]` 是轴号，不是鼓标记

```verilog
// rtl/w3c/evt_upstream.v:264
wire [7:0] b_axis = {2'b0, tm, ax};       // [7:6]=0 · [5:4]=音色 · [3:0]=轴号
// rtl/w3c/evt_upstream.v:291-296   14 B 帧
{ HDR, b_type, b_seq, tick[31:24..7:0], b_axis, inc[31:24..7:0], b_vel, b_ck }
```

- ✅ `[3:0]` = `ax`（轴号）
- ✅ `[5:4]` = `tm`（音色）—— 你们反算"全是 0 = BASS"✓ 与用户说法一致 ✓
- ✅ `[7:6]` = 0
- 🔴 **14 B 帧里没有任何 `is_drum` / `drum_type` 位** —— 内部 64 位字里的 `bit[5]`(`is_drum`)
  与 `bit[8:7]`(`drum_type`) **没有**被搬到上行帧 ✓

⇒ 你们上一轮的 §二 那封回函把这句会错意了，**是我方文档写错**（`bringup` 里也有同样措辞），已一并更正 ✓

## 四、提案：`byte[7][6] = is_drum`（⭐ 不加字节，≈2 LUT）

```verilog
// evt_upstream.v:264 改成
wire [7:0] b_axis = {1'b0, is_drum, tm, ax};
//                  ↑[7]  ↑[6]    ↑[5:4] ↑[3:0]
```

- 字节数 **不变**（14 B）✓ 校验和 `b_ck` 覆盖范围不变（它已经在异或 `b_axis`）✓
- FPGA 侧代价：`evt_merge` → `evt_upstream` 多传 1 位 ＋ 拼帧 1 行 ⇒ **≈2 LUT**
- ESP32 侧：解析 `byte[7] & 0x40` ⇒ **1 行**，且**向后兼容**（旧 build 该位恒 0）

### 语义（新）
| `byte[7][6]` | `byte[7][5:4]` | `byte[7][3:0]` |
|---|---|---|
| **1 = 鼓** | `drum_type`（0=Kick 1=Snare 2=HiHat 3=Tom）| 0 |
| **0 = 音高** | 音色（0=BASS 1=GUITAR 2=PIANO 3=PAD）| **轴号** |

⇒ ⭐ 从此 `[3:0]` **只在 `is_drum=0` 时有意义（轴号）**，鼓事件的轴号我们**不再借用** ✓
   （这样也顺手治了"Kick 的 `drum_type=0` ⇒ 无法与静止区分"那个老问题）

## 五、逐条答你们的三个问题

### 5.1 `[3:0]` 当鼓标记不成立

✅ **同意，而且比你们说得更彻底**：不是"只有灌谱鼓有值"，而是**一版一变、不能判** ✓
⇒ 过渡期（新版位流出来之前）**请 ESP32 侧一律不要用 `[3:0]` 判鼓**，
   显示层如果要区分，暂时只能靠"用户在网页上选的是鼓还是音高"这个**应用层信息** ✓

### 5.2 `note_off` 帧的 `vel = 250/229/255/185/235/241` —— 你们怀疑对了

```verilog
// rtl/w3c/evt_upstream.v:228
mem[wr_q] <= {tick_q, evt_kind_i, evt_velocity_i, evt_axis_i, ...};
// :265  wire [7:0] b_vel = vl;      vl 取自 FIFO 出来的 vel 字段
```

⇒ vel 就是**入队那一拍的 `evt_velocity_i`** ✓ 正常应为 0 或很小
⇒ 🔴 我们判：**live 路径在 `note_off` 那拍送出的 `evt_velocity_i` 不是 0**（疑似陈旧/未清）
⇒ ⭐ **认领为我方缺陷**，已排进修复队列；修完会在这份文档里追加确认，并给你们一条
   "**note_off 帧的 vel 必须为 0**" 的判据（改前必红）

### 5.3 键盘打鼓的 `[3:0]`

- 旧版：`seq_arb.evt_up_axis_o <= (pop_src == SRC_KDRUM) ? drum_type : 4'd0`
  ⇒ 键盘打鼓若走 `SRC_KDRUM` ⇒ `[3:0] = drum_type` ✓
- 但你们实测 live 的 `[3:0]` 是真实轴 ⇒ **说明那版 live 根本不走 `seq_arb` 的这个分支**
  （live 直接进 `evt_merge`，`evt_axis_i` 接的是真实轴）
- 当前版：`up_drum_mark_w` 统一三路鼓（`12 + drum_type` 反推，见 `top.v:6300` 起的长注释）
  ⇒ 所以"键盘打鼓"在**当前版**是有鼓标记的，在**旧版**没有 ✓

⇒ 结论：**这条路历史上有三种接法** ⇒ 更说明要靠 `byte[6]` 显式位，⛔ 不要靠推断 ✓
