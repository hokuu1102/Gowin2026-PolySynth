## 二、🔴 口径分歧：`(midi − 45) & 0x1F` 会**点错灯**（请勿按 §四 写）

你们 §四 写：

> 「你们可以直接写 `(midi − 45) & 0x1F`，⛔ 不必自己做钳位 —— FPGA 侧会安全地不点灯（`in_range` 挡住）」

⚠️ **`in_range` 只挡 `0..31` 之外，而 `& 0x1F` 的结果永远落在 `0..31` 之内** ⇒ 挡不住。
算例（按你们自己的灯位表 `guide_lamp.v:410-429`）：

| 真实 MIDI | `(m−45)&0x1F` | 被当成 | 后果 |
|---|---|---|---|
| **30**（低于音域） | `(-15)&0x1F = 17` | MIDI **62** | 🔴 **点亮 62 的灯**（完全错的键）|
| **77**（高于音域） | `32 & 0x1F = 0` | MIDI **45**（A2）| 🔴 指板模式**点亮 A2 的灯**；键盘模式 `KEY_NONE`（侥幸不亮）|
| **88** | `43 & 0x1F = 11` | MIDI **56** | 🔴 **点亮 56 的灯** |

⇒ ⭐ **`& 0x1F` 是"回绕"，不是"钳位"** —— 它把越界音**映射成另一个真实存在的键**。

**我方口径**（`mid2evt.py:542-544`）：

```python
if NOTE5_PITCH_MIN <= m <= NOTE5_PITCH_MAX:   # 45..75
    return m - BASE_NOTE                       # 0..30
return NOTE5_SENTINEL                          # 31 = 不可弹（不点灯）
```

⇒ 越界一律写 **31**。今天**安全**，因为你们的表只覆盖 MIDI 45..63（offset 0..18）⇒ offset 31
（= MIDI 76）**不在表里** ⇒ `KEY_NONE` ⇒ 不点灯 ✅。

### ⚠️ 但这有个**前置约定**，扩表时必须遵守

你们 §四 说"覆盖不足那一半由 FPGA 侧另行扩表" —— ⚠️ **如果扩表时把 MIDI 76 放进去**，
`offset 31` 就变成一个"真实存在的键" ⇒ 🔴 **哨兵会点亮 76 的灯**（越界音全部指到 76）。

⇒ **请约定：`bit[4:0] = 31` 永久保留为"本事件不参与 LED 指引"，灯位表里永远不放 MIDI 76。**
（64 位字里已无空闲位，所以"另开一位"不可行 —— 这条约定是唯一干净的解法。）

📌 反过来说：⚠️ 如果你们更希望"越界音也照实写"，那就**必须**让 FPGA 侧拿到
`midi < 45 || midi > 75` 这个信息 —— 而 `bit[4:0]` 装不下它（回绕后信息已丢）⇒ 只能靠约定。

## 三、✅ §三-3.3 的排序 bug：**真的、我方也有、已修**

你们的判断**完全正确**，而且实测**比你们给的数字更严重**：

```python
# 修前（tools/mid2evt.py:804）
events.sort(key=lambda e: (e["tick"], -1 if e["kind"] == KIND_TEMPO else e["kind"]))
#                                          ↑ KIND_ON=0 < KIND_OFF=1 ⇒ ON 排在 OFF 前，与上方注释相反
```

**实测"同 tick、同音高、ON 在 OFF 之前"的对数**：

| 曲 | 对数 | 占该曲字数 |
|---|---|---|
| 四音色测试曲 | 15 | 2.6% |
| **09_Conjurer** | **3428** | ≈29% |
| **6.世界悲(已修订)** | **2464** | ≈25% |

**修法**（与你们给的一行一致，把 `kind` 映射成 rank）：

```python
events.sort(key=lambda e: (e["tick"],
                           -1 if e["kind"] == KIND_TEMPO else
                           (0 if e["kind"] == KIND_OFF else 1)))
```

**修复验证**：

```

修后: 576 字 · 同tick同音高 ON在OFF前 = 0 对
字集合是否相同 = true          ← ⭐ 只改了顺序，内容一字未变
```

⇒ ⭐ **旧的 `.hex` 需要按新排序重新生成**（我方证据目录已重新生成；你们 `build/score/*` 下的
那些也要重出）。
