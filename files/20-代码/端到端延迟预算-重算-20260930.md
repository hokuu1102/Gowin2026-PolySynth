## 一、⭐ 时钟算术（显式，全部结论都由这几个数派生）

| 项 | 值 | 派生 |
|---|---|---|
| `sys_clk` | **50 MHz** | **1 clk = 20 ns** ｜ **1 µs = 50 clk** |
| `CLK_PER_SAMPLE` | **1024**（`rtl/top.v:519`） | — |
| `fs` | **48 828.125 Hz** | `50 MHz ÷ 1024` |
| ⭐ **1 个音频样本 / 1 个音频帧** | ⭐ **1024 clk = 20.48 µs** | ⭐ 全部音频段的时间单位 |

| ⭐ **ADC 帧周期** | ⭐ **25 000 clk = 500.00 µs** | ⭐ `CLK_HZ / CHANNEL_RATE_HZ = 50e6 / 2000`（`mcp3208_scanner.sv:36-40`） |

> ⛔ 不要当成两段各加一帧（那会**多算 20.48 µs**）。

## 二、⭐⭐ 通路拓扑：现行 RTL 是**两条**控制通路

> 🔴 **这是本轮最重要的结构性更正** —— 旧文档把"拨弦/阈值判定"写成走 ADC（② 段 `16.5 µs`），
> ⚠️ 而**现行 RTL 的拨弦根本不经过 ADC**。

```text
【通路 A · 轴位 / 键盘模式】← 最坏通路
  霍尔 → RC(1k+10nF) → MCP3208(逐通道扫描) → adc_farm → axis_snapshot
      → event_extract(迟滞+逐轴扫描) → play_mode_ctrl → top.v 音高流水(2 拍)
      → seq_arb → evt_merge → note_manager(32 拍扫描 FSM)
      → oscillator_bank → tdm_render_mixer → master_mix → sample_r
      → i2s_tx → MAX98357A(板载) / PCM5102A(外接)
   ⭐ 包含 ①②③④⑤⑥⑦⑧ —— 旧文档描述的其实就是这一条

【通路 B · 拨弦 / 指板模式】← 低延迟通路
  LM393(UP/DOWN) ──异步边沿──→ async_pluck_capture(2FF+边沿+不应期)
      → play_mode_ctrl(pluck 分支) → ……（④⑤⑥⑦⑧ 与通路 A 完全相同）
   ⭐ **没有 ① 和 ②** —— 事件在比较器边沿后 2~3 拍就被 FPGA 抓住
   ⚠️ 前提：`play_mode_ctrl` 要求 `selected_valid` 已置位
      （= 必须先由通路 A 选中一个轴 ⇒ **"先按品、后拨弦"**）
```

> ⭐ 依据：`rtl/w3a/async_pluck_capture.v`（`top.v:2425` 例化，`REFRACT_CYC=1_500_000` = 30 ms）
> ｜`rtl/w3a/play_mode_ctrl.v:59-67`（`pluck_valid_i && selected_valid`）
> ｜`rtl/top.v:2414-2455`（两种演奏模式的合流点）

## 四、⭐ 逐段推导（每一段都给出**代码位置 + 算式**）

### ① 采集：等下一个采样时隙 —— `25 000 clk = 500.00 µs`

- `rtl/drivers/adc_farm.sv:51` `CHANNEL_RATE_HZ = 2_000`（`top.v:1271` 也传 `2_000`）
- `rtl/drivers/mcp3208_scanner.sv:36-40`
  `FRAME_PERIOD = CLK_HZ / CHANNEL_RATE_HZ = 50_000_000 / 2_000 = 25 000`
- ⇒ ⭐ **同一个轴每 `25 000 clk` 才被采一次**
- ⭐ **最坏 = 整个帧周期**（动作恰好错过本帧该通道的采样瞬间）
- ⭐ **典型 = 半帧**（`12 500 clk = 250.00 µs`）
- 📌 仿真证据（**别人早就有**）：`sim/evidence/tb_adc_farm.log` 判据行 `frame period=500000 ns`
- ⚠️ **本段是"转换耗时 196 µs"与"帧周期 500 µs"的区分点** ——
  ⭐ 转换只占帧的 39%，其余 `STATE_WAIT_PERIOD` 是**空等**（`K-128` 更正过这条口径）

### ② ADC 转换 + SPI 读出 + 帧收齐 + 原子快照 —— `9 809 clk = 196.18 µs`

⭐ **本段由三块组成，旧文档只算了第一块：**

| 子项 | clk | µs | 依据 |
|---|---|---|---|
| (a) 本通道转换 + 读出 | **1 226** | 24.52 | `mcp3208_driver.sv:25-29` `HALF_DIV = 50e6/(2×1e6) = 25` ⇒ **50 clk/bit**；发 **24 bit** = 1200 clk；`STATE_FINISH` 再等 `HALF_DIV = 25` ⇒ **1226 clk** |
| (b) 等本帧剩余通道 | **8 583** | 171.66 | `mcp3208_scanner.sv:123-136`：`driver_done` 后立刻 `driver_start` 下一通道 ⇒ **背靠背 1226 clk/通道**；轴在通道 `k` ⇒ 还要等 `(7−k)` 个通道 = `1226 × (7−k)` |
| (c) `frame_done` → 原子快照 | **1** | 0.02 | `axis_snapshot.v:191-194` `snap_valid_o <= frame_done_i` |

- ⇒ ⭐ **轴号 = 片号×8 + 通道号**（`axis_snapshot.v:88-99`），片内通道 `k = 轴号 mod 8`
- ⭐ **最坏**（`k = 0`）：`1226 + 1226×7 + 1 = 9809 clk = 196.18 µs`
- ⭐ **最好**（`k = 7`）：`1226 + 0 + 1 = 1227 clk = 24.54 µs`
- ⭐ **典型**（`k` 均匀）：`9809 − 1226×3.5 = 5518 clk = 110.36 µs`
- 🔴 **旧文档写 `16.5 µs`**（"1.5 µs 转换 + 15 bit @1 MHz"）——
  ⚠️ 驱动实际发 **24 bit**（不是 15），且**完全没算 (b) 那 171.66 µs** ⇒ **差 12 倍**

### ③ 事件提取 + 模式判定 + 音高流水 —— `6 + k` clk（`k` = 轴号），最坏 `21 clk = 0.42 µs`

| 子项 | clk | 依据 |
|---|---|---|
| `event_extract`：`snap_valid` → 第 `k` 轴被处理 | `1 + k` | `event_extract.v:288-296`：`snap_valid` 下一拍起 `scanning=1`、`scan_axis=0`；`:296-350` **一拍一个轴** |
| 同上：push → `evt_valid_o`（FIFO 出队） | `+2` | `:305-310` push；`:357-363` 出队那一拍同时锁存 `evt_*`（`K-109`：valid 与数据同拍） |
| `play_mode_ctrl`（键盘直通，寄存一拍） | `+1` | `play_mode_ctrl.v:53-58` |
| `top.v` 音高映射流水 | `+2` | `top.v:2470-2495`：`am_vld_in` 打一拍；`am_vld_out`/`am_inc_out` 再打一拍 ⇒ `w3a_evt_valid = am_vld_out`（`top.v:2587`） |

- ⭐ **最坏 = `6 + 15 = 21 clk = 0.42 µs`**（触发的轴是 **15 号**，16 个轴里最后一个被扫）
- ⭐ **最好 = `6 + 0 = 6 clk = 0.12 µs`**
- ⭐⭐ **本段【没有去抖延迟】**：
  - `event_extract` 的迟滞是**纯组合比较**（`:299-341`：`pos ≥ TRIG_TH` 立刻发 `note_on`、`pos < REL_TH` 立刻发 `note_off`）⇒ **0 拍**
  - `REFRACT_N = 150` 帧（`:69`）= **75 ms** 是**不应期**，⭐ 只封锁**后续**边沿，⛔ **不推迟首次触发**（"先触发后修正"）
  - 🔴 **`rtl/drivers/debounce.sv` 的 `DB_MS = 5`（`250 000 clk = 5 ms`）⛔ 不在演奏通路上** ——
    ⭐ `top.v` 只把它用在**音色切换按键**（`top.v:452-476`，`TIMBRE_BTN_DB_MS = 5`）；
    节拍器按键已改走串口（`top.v:404-422`）⇒ **演奏路径上一次去抖都没有**
- ⭐ 通路 B 的 ③ = `async_pluck_capture` 2~3 拍（`async_pluck_capture.v:36-50`：2 级同步 + `*_prev` 边沿 + `pluck_valid_o` 寄存）+ 1 + 2 = **5~6 clk**

### ④ 仲裁 + 合流 FIFO + `note_manager` 分配 —— `41 ~ 51 clk = 0.82 ~ 1.02 µs`

| 子项 | clk（空队列） | 最坏追加 | 依据 |
|---|---|---|---|
| `seq_arb`（`live` 口 → 出口） | **2** | `+6`（深度 6 全满） | `seq_arb.v:80` `DEPTH=6`；`:282-305` 弹出那一拍输出 `evt_valid_o`；`:221` `push_n` 最多 3 |
| `evt_merge`（源 A → 出口） | **2** | `+4`（深度 4 全满） | `evt_merge.v:62` `DEPTH=4`；`:203-217`；`:172` `push_n` 最多 2 |
| ⭐ `note_manager`：**事件 → `gate_r` 高** | **37** | — | 见下 |

⭐ **`note_manager` 的 37 拍逐步展开**（`note_manager.v:206-216` 状态编码、`:830-1043` 状态体）：

```text
拍 0   note_valid_i 到达  → fifo_push，fifo_cnt 0→1        （:353/:654-669）
拍 1   ST_IDLE 见到 !fifo_empty ⇒ 锁存 cur_*，→ ST_DECIDE （:831-843）
拍 2   ST_DECIDE：无同轴可复用 ⇒ scan_cnt←0，→ ST_SCAN    （:921-926）
拍 3..34  ST_SCAN：**一拍考察一个 voice**，共 32 拍          （:929-943，SCAN_LAST=31）
拍 35  ST_COMMIT：只锁存 cmt_*（⭐ N-1 提交流水级）          （:945-986）
拍 36  ST_COMMIT2：gate_r[cmt_idx_r] ← 1                    （:1008-1038）
拍 37  ⭐ gate_r 已为高 ⇒ live_mask = gate_r | … = 1
```

- ⭐ **合计 `2 + 2 + 37 = 41 clk = 0.82 µs`**（队列空）
- ⭐ **最坏 `41 + 6 + 4 = 51 clk = 1.02 µs`**（两个 FIFO 都满）
- 🔴 **同轴重触发**（连按同一个键）走 `ST_DECIDE` 的 `same_valid` 分支（`:884-920`）：
  ⭐ 它把 `gate_r` 压低、置 `retrig_low`，**`gate_mask = gate_r & ~retrig_low` 要等到下一个 `sample_tick` 才抬起**（`:812-825`）
  ⇒ ⭐ **最坏再加 `0 ~ 1024 clk`**（`20.48 µs`）—— ⭐ **这是"连按"的确定上界，旧文档完全没有这一段**
- ⚠️ **代码里三个数互相矛盾**（⛔ 不能只看注释）：
  `note_manager.v:20` 写 **"≤34 拍"**（⭐ 那是 `N-1` 加提交流水级**之前**的旧值）；
  `note_manager.v:1093` 自检用 `POLY_TARGET + 4` = **36**；
  `tb/w3b/tb_note_manager.sv:41` 也写 **"POLY_TARGET+4 = 36 cycles"**；
  ⭐ **从 RTL 数出来的"事件→gate 高"是 37 拍**（含 FIFO 入队那 1 拍）——
  ⭐ 36 是 **FSM 自身**的拍数，37 是**含入队**的端到端拍数。⛔ 引用时请写清口径。

### ⑤ 包络起振帧 + 振荡器 + 混音 + 主混音 + 输出寄存 —— `1 132 ~ 2 155 clk = 22.64 ~ 43.10 µs`

| 子项 | clk | 证据 |
|---|---|---|

| (b) 🔴 **ADSR 起振要多一整个采样帧** | **1024** | `adsr.v:143-148`：`ST_IDLE` 且 `gate_i` ⇒ `env_level_o <= 0`、`state <= ST_ATTACK` ⇒ ⭐ **本帧包络仍是 0**；下一拍才 `+ATTACK_STEP` |
| (c) `oscillator_bank` TDM | **66** | `oscillator_bank.v:326-346`；`LANES = POLY_TARGET×OSC_PER_VOICE = 32×2 = 64` ⇒ `LANES + 2 = 66` ⭐ **`measured in simulation`**：`tb/w3b/tb_oscillator_bank.sv:200` 判据 `k ∈ [64, 68]` |
| (d) `tdm_render_mixer` | **41** | `tdm_render_mixer.v:98-99` `CNT_TOTAL = POLY_TARGET+2 = 34`；`:314-320` `valid_r`；`:848-854` `valid_d[4]` ⇒ `34+2+5 = 41` ⭐ **`measured in simulation`**：`tb/w3b/tb_tdm_render_mixer.sv:246-247` 判据 `k ∈ [POLY+3, POLY+8]`（该 tb 的计数器口径比拍号小 1） |

| (f) `top.v` 输出寄存 `sample_r` | **1** | `top.v:3422-3426` `else if (mm_valid) sample_r <= mm_sample` |

- ⭐ **`(a) + 1132`**：最坏 `1023 + 1132 = 2155 clk = 43.10 µs`；典型 `512 + 1132 = 1644 clk = 32.88 µs`；最好 `1132 clk = 22.64 µs`

  ⚠️ 而现行 RTL 里 **包络本身就要一整帧才出第一个非零值**，再加上 TDM 的 108 拍
  ⇒ ⭐ **最坏 20.48 → 43.10 µs（2.1 倍）**

- ⚠️ 若把端点定义成"voice 已分配、流水已提交"（⛔ 不是"可闻起音"），本段可减 1024 拍
  ⇒ ⭐ 最坏总计 `36 944 clk = 738.88 µs`。⛔ 但**评委听到的是可闻起音** ⇒ 正文按可闻口径。

- 📌 已归档的先行工作：`build/fx_parked/`（`fx_delay.v` + `tb_fx_delay.sv`），⛔ 未进 `top.v`

### ⑦ I2S 帧对齐 + 串行化 —— `932 clk = 18.64 µs`

| 子项 | clk | 依据 |
|---|---|---|
| (a) 等到下一个 `frame_start` | **916** | `sample_r` 在 tick 后第 **108** 拍稳定（`66+41+1`）；`frame_start ≡ tick_audio`（§一）⇒ 下一个帧边界在 tick 后第 **1024** 拍 ⇒ `1024 − 108 = 916` |
| (b) MSB 送到 DAC 的 DIN | **16** | `i2s_tx.v:184-198`：`frame_start` 那一拍装载、第 0 位是填充；`MSB_DELAY=1`（`top.v:3554`）⇒ **MSB 在第 1 个 `bclk_en`**，即 `1 BCK = 16 clk` |

- ⭐ **(a) 是常数**（不随事件相位变）⇒ ⭐ **⑦ 段是【确定性】的，⛔ 不是最坏/典型之分**
- 📌 **口径说明**：`18.64 µs` = "DAC 收到该样点的**第一位**"。
  若要"**整字传完**"：`916 + 16×16 = 1172 clk = 23.44 µs`
- ⚠️ 外接 `PCM5102A` 那一路是 `MSB_DELAY=0`（`top.v:3606`，上板实测出声那一档）
  ⇒ 其 (b) = **0 拍**，⛔ 与板载那一路不同（两路参数不同是**故意的**）

### ⑧ DAC 建立 + 功放 —— ⚠️ **未知（本段无法从 RTL 得到）**

- 板载器件 = **`MAX98357A`**（Console 60K，I2S 输入 + DAC + D 类功放）
- 外接器件 = **`PCM5102A`**（`top.v:3587-3619`）
- 🔴 **两份手册都没有查到可直接引用的"群延迟/建立时间"数字**
  （只找到数据表页，未见 spec 条目；⛔ 不许拿旧文档的"5 µs 手册量级"顶替）
- ⇒ ⭐ **本段保持 `assumed`，⛔ 不升级**（详见 §七-1）
