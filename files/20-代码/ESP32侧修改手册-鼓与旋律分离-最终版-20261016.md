## 〇、四条硬约束

```
1. 旋律线绝对不能变成鼓          <- 结构上保证，不靠"轴号不会撞上"这种运气
2. 鼓就是鼓的发声               <- 与键盘打鼓走同一张 inc 表、同一个池子
3. 鼓与旋律零重叠               <- 来源标签 / 池子 / inc 来源三处全部分开
4. LED 跟着音高走，且变调后不许指错  <- 键位必须在【变调之后】算
```

**资源口径（用户 2026-10-16 定）**：能完成基本功能的前提下，**FPGA 尽量省资源，ESP32 多承担**。

## 一、问题是怎么来的

```
2026-10-11 P1-59  把 SRC_KDRUM(3'd5) 从"与源B共用"里剥离开 => 鼓有了独立来源标签
                  那时候还没有灌谱
后来    加灌谱    为了让曲谱的鼓走鼓池，塞了一个轴号捷径 (axis == 15)
2026-10-16        为方案B 放宽成 axis >= 12 => 误伤从 1 个轴扩到 4 个轴
```

### 后果（用户实测）

```
用户报：灌谱的鼓像电子音，但键盘打鼓听着正常

机理：
  · 键盘打鼓走 drum_gen 的 inc 表 => 正确
  · 灌谱的鼓靠 axis>=12 被"猜"成鼓 => 走鼓池，但 inc 是【音高换算出来的】
  · 帧的 inc 字段只有 21 位，装不下 INC_SNARE(26位) / INC_HIHAT(28位)
  => 鼓池里发出一个音高纯音 => 电子音
```

### 附带发现：LED "只闪一盏"

```
tools/mid2evt.py:359  axis_of[ti] = nxt        <- 一条非鼓轨 = 一个轴号，该轨所有音符共用
         :390         axis = axis_of[ti] & 0xF
而 guide_lamp 把 axis 当"该按哪个键"用
=> 一盏灯 = 一条轨 => 16 盏里最多只用 4~6 盏（实测三首真曲轴号只出现 0..5）
```

## 二、最终位域（64 位不变，⚠️ **axis 那 4 位一个字节都不动**）

```text
bit 63..44   tick(20)
bit 43..23   inc(21)        <- 旋律的唯一音高来源；鼓事件写 0（FPGA 忽略）
bit 22..19   axis(4)        <- ⚠️ 保持原样，FPGA 侧判定【不再看它】
bit 18..11   vel(8)
bit 10..9    kind(2)        <- 0=note_on 1=note_off 2=tempo
bit 8..7     timbre(2)      <- ⭐ 鼓事件：这个字段当 drum_type 用
                               0=Kick 1=Snare 2=HiHat 3=Tom
bit 6        guide_only     <- 已用（逐事件"只亮灯不出声"）
bit 5        is_drum        <- 新增：显式鼓标志
bit 4..0     note_off5(5)   <- 新增：音符号偏移（给 LED 用）
```

### 2.0 为什么新字段放在 bit5 / bits[4:0]，而不是复用 axis

```
现在你们的工具把 axis 写成【轨序号】(0,1,2,3,...)
如果 is_drum 放在 axis 的最高位 (bit22)
  => 轨号 8..15 的 bit22 全是 1
  => 【那些轨会被读成鼓】=> 又变成"旋律变鼓"，而且更隐蔽

而 bits[6:0] 你们的工具本来就写死 0（score_word.py:46 "bit 6..0 保留，必须写 0"）
  => 放在 bit5 / bits[4:0] 【永远安全】
```

**这也是为什么 drum_type 复用 `timbre` 字段**：鼓的音色本来就由鼓件决定，`timbre` 对鼓事件没有意义，正好拿来用，不必占新位。

### 2.1 为什么音符号只传 5 位偏移

```
16 键的跨度约 2 个八度 = 24 个半音 => 5 位（0..31）足够覆盖
=> 正好放进 bits[4:0]，帧宽不用改

基准：note_off5 = MIDI音符号 - BASE_NOTE，建议 BASE_NOTE = 45（A2，指板表最低音）
      范围 0..31 覆盖 MIDI 45..76（A2..E5）
```

### 2.2 为什么键位不由你们算

```
FPGA 侧有运行期变调（推子 / 键6 / 键10 / 键14，范围 -12..+12 半音）
你们不知道变调量 => 你们算的键位在变调后必然指错
而且键位表是【非线性的物理布局】（有跳变、不单调）=> 不能简单加减

=> 你们只传【音符号偏移】（本来就知道，零成本）
   FPGA 加变调后查一张 16 项小表 => 灯永远指对
```

## 三、三条通路（改完就是这样）

```
旋律（is_drum = 0）
  src    = SRC_SCORE
  池子   = 旋律池
  inc    = 音高换算（你们现在就是这么写的，不变）
  timbre = 你们指定的音色

鼓（is_drum = 1）
  src    = SRC_KDRUM
  池子   = 鼓池
  inc    = FPGA 从 drum_gen 的表按 drum_type 四选一（你们写 0）
  timbre = 忽略

LED
  FPGA 用 note_off5 + 变调 => 查表 => 点亮对应键
```

## 四、ESP32 侧要改的地方

### 4.1 `tools/mid2evt.py`

| 改什么 | 怎么改 |
|---|---|
| **鼓的识别**（`classify()`，`:272` 附近） | 现在靠 ① 轨名含 `drum/perc/kit/cymbal/hat` ② GM 通道 9。**保留这两条，再加第三条**：允许命令行/配置**显式指定哪条轨是鼓**（用户最清楚）。三者取或 |
| **鼓轨的输出** | 现在鼓轨被**整轨排除**（`:27`、`:350-351`、`:365-366`）。改成：**鼓轨也输出事件**，每条置 `bit5=1`（is_drum）+ `drum_type 写进 timbre 字段 [8:7]`（按 GM 音符号映射：35/36→Kick(0) · 38/40→Snare(1) · 42/44→HiHat(2) · 41/43/45/47/48/50→Tom(3)），`inc` 写 0 |
| 🔴 **鼓的 `note_off`（`kind=1`）也必须带 `is_drum=1` 和同一个 `drum_type`** | **这是硬要求，漏了会挂音**：`note_manager.v:1320` 的 `note_off` 要求 `(axis, src)` 与 ON 匹配。若 OFF 被标成 `SRC_SCORE`，鼓的 voice **永久 held** ⇒ 鼓的保留池耗尽 ⇒ **打一会儿鼓就再也不响了**。⭐ 最容易漏的一点：只在 ON 上置标志 |
| **tempo 事件（`kind=2`）** | `is_drum` 写 0，`drum_type` 写 0 |
| **旋律轨** | `is_drum` **写死 0**（不依赖任何条件） |
| **音符号偏移** | 每条事件算 `note_off5 = MIDI音符号 - BASE_NOTE`，写进 `bits[4:0]`；超出 0..31 时钳到边界 |
| **校验器** | 加两条硬检查：① **任何 `is_drum=0` 的事件，都不许被路由到鼓池**（这是"旋律绝不变鼓"的机械保证）② `is_drum=1` 时 `inc` 必须为 0 |

### 4.2 `esp32/tools/score_word.py`

| 改什么 | 怎么改 |
|---|---|
| 位域定义（`:66-73`） | 按 §二 的新表改：`is_drum` / `drum_type` / `note_off5` |
| 保留位断言（`:46` 写"bit 6..0 保留，必须写 0"） | 改成按新语义校验 |
| 校验器（`:201-202`） | 同步更新 |
| 打包函数 | 加 `is_drum` / `drum_type` / `note_off5` 三个入参 |

### 4.3 GM 音符号到 drum_type 的映射表

```text
Kick  (drum_type=0)：35, 36
Snare (drum_type=1)：38, 40
HiHat (drum_type=2)：42, 44
Tom   (drum_type=3)：41, 43, 45, 47, 48, 50
其它 GM 打击乐音符号：本轮先归到 Tom，并在报告里列出来（将来可能扩 drum_type 到 3 位）
```

⚠️ **注意**：现在 `drum_type` 只有 2 位（4 件）。如果你们的谱里有 crash / ride / 更多嗵鼓，**必须提前告诉我们**，因为 4 件扩到 8 件要改位宽（`drum_type` 2 位 -> 3 位），那是帧位域的改动。

### 4.4 上行帧（FPGA -> ESP32）

```

        => 你们自己映射到 GM 音符号再发 MIDI
        （选这个是为了 FPGA 省资源：零额外逻辑，直接透传）
旋律事件：axis 字段回传 0
```

### 5.2 `rtl/w3c/seq_arb.v`

```verilog
// L119-120  新增端口

input  wire [1:0]  score_drum_type_i,

// L245-247  鼓的 inc 四选一（来自共享常量文件）

                               (score_drum_type_i == 2'd2) ? INC_HIHAT : INC_TOM;

wire [31:0] score_inc_eff = score_is_drum_i ? drum_inc_by_type : score_phase_inc_i;
wire [NW-1:0] score_src_w = score_is_drum_i ? SRC_KDRUM : SRC_SCORE;

## 六、验收判据

### FPGA 侧（我们会加 tb）

```
1. is_drum=0 的事件，在【任意轴号】下都不产生 SRC_KDRUM
   （专门测 axis = 12 / 13 / 14 / 15 四条边界）
2. is_drum=1 的事件必须产生 SRC_KDRUM，且 inc == drum_gen 对应那件的 inc
3. 灌一份 16 轨的谱，逐条比对 src，旋律不许有一条变成鼓
4. LED：同一轨的不同音高点不同的灯；⭐ 变调后仍指对键
5. 既有判据（seq_arb / key_drum / note_manager / guide_lamp / led）全绿
```

### ESP32 侧（请你们过）

```
1. 谱里的鼓轨被正确识别（轨名 / GM 通道 9 / 显式指定）
2. 输出的 events.hex 里：鼓事件 is_drum=1 且 drum_type 正确且 inc=0；
   旋律事件 is_drum=0
3. 校验器零问题
4. 灌谱上板：鼓听起来与键盘打鼓一致；旋律绝无电子音鼓
5. LED 跟着音高走；⭐ 在 FPGA 上变调后灯仍指对键

## 七、联调顺序

### 7.1 铁律：不许有"鼓变旋律"的过渡期

```
⛔ 错误做法：FPGA 先改成 is_drum 判定，等你们慢慢改
   => 在你们写 is_drum 之前，所有曲谱事件 is_drum=0
   => 曲谱的鼓【全变成旋律音符】=> 正是要避免的事

✅ 正确做法：两边一起上
   FPGA 侧先准备好（改好但不合入），等你们 mid2evt.py / score_word.py 改完、
   产出的 events.hex 里 is_drum 已经正确，再一起合入。
   或者：FPGA 保留旧的 axis>=12 判定直到你们改完（但那会继续误伤旋律，不推荐）
```

### 7.2 步骤

```
第一步（我们做，先准备好不合入）：
   seq_arb 的判定从 axis>=12 换成 is_drum；鼓的 inc 按 drum_type 四选一
   guide_lamp 改成 note_off5 + 变调后查表
   判据同步改（6 条改激励 + 新增边界判据）

第二步（你们做）：
   mid2evt.py / score_word.py 按 §四 改
   ⭐ 关键：鼓的 note_off（kind=1）也必须带 is_drum=1 和同一个 drum_type
          否则鼓 voice 永久 held => 保留池耗尽 => 打一会儿鼓就不响了

第三步（一起验）：
   你们产出 events.hex -> 我们灌进 tb 跑一遍（不用上板就能验 src/inc）
   两边都过 -> 上板听：鼓是鼓、旋律是旋律、灯跟着音高且变调后指对
```

### 7.3 上板前的机械检查（我们会做）

```
1. 逐条扫 events.hex：is_drum=0 的事件里，有没有任何一条的轴号落在 12~15
   （有 => 说明还有依赖轴号的路径，必须查清）
2. 逐条扫：is_drum=1 的事件，它的 note_off 有没有配对地也带 is_drum=1
3. 统计 drum_type 的分布，确认四件都有
```

```

3. 上行帧的 axis 字段回传 drum_type（我们零代价）可以吗？

```
