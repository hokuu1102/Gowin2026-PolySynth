# LED 演奏指引 —— 实现计划清单（2026-10-14）

> **范围**：⭐ **只写 LED 这条线**（⛔ 不含效果器/频谱/其他评分项）
> **目标**：⭐ **指引模式**（只亮灯 ＋ 节拍器/鼓机照响，⛔ 音符不出声）
> ＋ ⭐ **提前亮**（可能提前一拍）＋ ⭐ **写码阶段尽量省资源** ✅
> **依据**：⭐ 赛题 B3 *"基于 FPGA 逻辑实时生成可视化：**LED 演奏指引**…"*
> ＋ ⭐ B4 *"脱机演奏 **LED 曲目指引**"* ✅

---

## 一、⭐ 需求（原样照抄）

> **B3** *"延迟压到 **≤5ms 且确定性无抖动**；基于 FPGA 逻辑实时生成可视化：**LED 演奏指引、李萨如图形、实时频谱、波形显示**"*

> **B4** *"脱机演奏 **LED 曲目指引**；**可**搭载蓝牙与手机 App（在线曲谱下载、键位自定义、演奏录音回传）"*

> **E4（反推硬约束）** ⭐ 音频与视觉效果的**"生成"⛔ 绝不能用软核/MCU**；⭐ **专用状态机不算软核** ✅

⭐ **用户口径（2026-10-14）**：
> *"加一个指引模式：只有 led 指引（可能提前一拍亮起？）和谱面对应的节拍器/鼓机，没有声音。
> 也就是说灌谱分成两种：一种是上面说的指引，另一种就是普通的演奏模式：
> 什么时候发声，led 就亮对应的轴。"*

## 三、⭐ 要做的三块

### 🟢 L1 · 指引模式（⭐ 改动最小，优先做）

| 项 | 内容 |
|---|---|
| **语义** | ⭐ 灌谱时：⭐ **只亮 LED ＋ 谱面对应的节拍器/鼓机照响**，🔴 **音符不出声** ✅ |
| **静音点** | 🔴 **`seq_arb.score_valid_i`**（`top.v:4991` 附近） |
| **为什么正好在这里** | ⭐ `guide_lamp` 读的是**它上游**的 `ps_note_valid` ⇒ ⭐ **闸住进 `seq_arb` 那一路，LED 照常工作** ✅ |
| **节拍器/鼓机** | ⭐ 走**源 B**，⛔ 完全不受影响 ⇒ ⭐ 正好是你要的"**节拍器/鼓机照响**" ✅ |
| **命令** | ⭐ `'U'`（空闲字母只剩 `U`/`Z`）· 回包 `'u'` · **复位默认关 ⇒ ⛔ 零回归** ✅ |
| **控制板键** | ⭐ idx **13**（映射表里正是"备用"）⇒ ⭐ 脱离 PC 也能切 ✅ |
| **代码改动** | ⭐ **1 个寄存器 ＋ 1 处表达式**（见下） |
| **资源** | ⭐ **1 FF ＋ ~2 LUT ⇒ ≈ 0 CLS** ✅ |

```verilog
//  ⭐ 唯一的功能改动（⭐ `top.v`）
seq_arb ... .score_valid_i (SCORE_UART_ENABLE & ~guide_only_r ? ps_note_valid : 1'b0)
```

### 🟡 L2 · 提前亮（⭐ "可能提前一拍"）

| 项 | 内容 |
|---|---|
| **难点** | 🔴 `guide_lamp` 处理的是**到达它那一刻**的事件，而 `play_seq` 是**到 tick 才吐** ⇒ ⭐ **要提前，必须提前看到下一个事件** |
| 🔴 **不能怎么做** | ⛔ **给 `evt_buf` 加第二个读口** —— ⚠️ **BSRAM 只有 1 个读口**，且它已经被 `play_seq` 占用 ✅ |
| ✅ **怎么做（⭐ 便宜）** | ⭐ **在 `play_seq` 里预读**：⭐ `evt_buf` 是 **FWFT**（队头常驻）⇒ ⭐ **每次 pop 之后，队头就自动变成下一个事件** ⇒ ⭐ 把它**latch 进 `next_evt_q`** ⇒ ⭐ 再比 `cur_tick + lead >= next.tick` ⇒ ⭐ 提前输出预览 ✅ |
| **资源** | ⭐ **~64 FF ＋ ~25 LUT**（⭐ 一个 64 位保持寄存器 ＋ 一个 tick 比较器） |
| **提前量** | ⭐ 用 `localparam LEAD_TICK`（⛔ **不做除法器/乘法器**，⭐ 直接给常数或寄存器）✅ |
| **接口** | ⭐ `play_seq` 加 `pre_valid_o`/`pre_data_o` ⇒ ⭐ `guide_lamp.note_valid_i = ps_note_valid \| ps_pre_valid` ✅ |
| ⚠️ **风险** | ⭐ 提前亮之后，**到点还要再亮一次吗**？⭐ 语义要定：⭐ **提前亮 = 一直亮到真到点**（⭐ 不闪两下）✅ |

### 🔵 L3 · 省资源纪律（⭐ 你点名要求的）

| # | 纪律 | 为什么 |
|---|---|---|
| **R1** | ⛔ **不加 BSRAM** | ⭐ 余量 49 块，⚠️ 但**CLS 才是真瓶颈**（85%）⇒ ⭐ 加 BSRAM 会连带吃 CLS ✅ |
| **R2** | ⛔ **不加 DSP** | ⭐ 余量 96，⚠️ 但 DSP 会拉低 Fmax ✅ |
| **R3** | ⭐ **复用现成链** | ⭐ `guide_lamp`/`led_data`/`tlc5916_bank` **都已接好** ⇒ ⛔ 不重写 ✅ |
| **R4** | ⭐ **不新增计数器/分频** | ⭐ `blink_i` 已有（来自 `beat_gen`）⇒ ⭐ 直接复用 ✅ |
| **R5** | ⛔ **不做整段滚动 LED（L4）** | ⭐ 资源需求大；⭐ L1+L3 **已满足赛题** ✅ |
| **R6** | ⭐ **提前量用常数/寄存器** | ⛔ 不做"可调 ÷ 运算" ⇒ ⭐ 省 LUT/DSP ✅ |
| **R7** | ⭐ **每加一块立刻跑 PnR 量 CLS** | 🔴 ⛔ 不许攒着一起上（⭐ 本项目 CLS 余量只 4,660 ✅） |

| 项 | FF | LUT | CLS | BSRAM | DSP |
|---|---|---|---|---|---|
| **当前余量** | 41,000 | 19,900 | **4,660** | 49 | 96 |
| **L1 指引模式** | +1 | +2 | **≈ 0** | 0 | 0 |
