## 二、我方本轮修的一个真缺陷（与你们无关，但值得记）

### 症状

PC 连上 ESP32 后，**只能发现 4 个 GATT 强制特征**
（`2a05` 服务变更 / `2a00` 设备名 / `2a01` 外观 / `2aa6` 中央地址解析），
**我方自己的 `0xABF1`~`0xABF4` 一个都没有** ⇒ 所有 BLE 工具全线失败。

### 排查过程（每步都有判据）

| # | 尝试 | 结果 |
|---|---|---|
| 1 | 板子自证 | 属性表创建 + 句柄 40/42/44/47/49 + `service started` **全部正常** |
| 2 | 板子复位 / 重烧固件 | 无效 |
| 3 | 改设备名 | 能扫到了，**但服务表还是 4 个** |
| 4 | 延长等待（1/3/6 秒） | 无效 |
| 5 | 强制 UNCACHED（bleak 的 `winrt={"use_cached_services": False}`） | 仍是 4 个 |
| 6 | 广播包加入服务 UUID（AD type `0x03`） | 广播侧正确宣告 `0xABF0`，连上仍 4 个 |
| **7** | 加日志记录**【客户端读了哪些句柄】** | **板子收到的 ATT 请求 = 0 条** |
| **8** | **对照实验：同一台 PC 连另一个 BLE 设备** | **能正常发现它的自定义服务（`fe55`）** |
| 9 | 发 GATT Service Changed 指示（`0x2A05`） | 返回 `ESP_OK`，但服务表没变 |

### 根因

**Windows 按【MAC 地址】缓存 GATT 服务表**，
认定"这个设备只有 4 个服务"，于是**根本不发起服务发现**
（第 7 条证据：ATT 请求 0 条）。

⚠️ **改设备名绕不过它** —— 因为**缓存键是 MAC，不是名字**。

### 修法

广播地址由**出厂 public 地址**改为**随机静态地址**：

```
94:A9:90:2D:A6:62   →   C2:AA:20:26:00:01
```

- `.own_addr_type`: `BLE_ADDR_TYPE_PUBLIC` → `BLE_ADDR_TYPE_RANDOM`
- 启动时调 `esp_ble_gap_set_rand_addr()`
- 用**固定值**而不是每次随机 ⇒ 重启后地址不变，便于日志比对

**验证**：`0xABF*` 从 **0 个 → 4 个** ✅

### 顺带修的一处

`CONFIG_BT_GATTS_SEND_SERVICE_CHANGE_MODE` 由 `AUTO` 改 `MANUAL` ——
否则 `esp_ble_gatts_send_service_change_indication()` 会被协议栈拒绝
（日志原文：`can't send service change indication manually,
please configure the option through menuconfig`）。

⭐ 保留它的价值：**将来改 GATT 结构时客户端能自动重新发现**，⛔ 不必再清缓存。
已同步进 `sdkconfig.defaults`。

### ⚠️ 给你们的提醒（如果你们那边也要接 BLE）

你们的板子如果换固件后 PC 认不出服务，**先怀疑这个 MAC 缓存**，
⛔ 不要先去查 RTL。判据：**看板子收到的 ATT 请求是不是 0 条**。
