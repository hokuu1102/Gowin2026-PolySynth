# WS2812 指示层规格（2026-10-03 · 用户给定语义）

> **用户给定**：WS2812 负责 **7 个东西**的状态显示，每个 3~5 个状态。
> **架构**：⭐ 三层分离 —— **各子系统（已有状态）→ 指示层（状态码→颜色）→ PHY 驱动（位时序）**。
> ⭐ **好处**：加一个功能 = **表里加一行**，⛔ 不是加一套状态机。

---

## 一、⭐ 七路指示（用户原文 → 结构化）

| # | 东西 | 状态 | 建议显示 | 状态码位宽 |
|---|---|---|---|---|
| **1** | **音色** | 4 种音色 | 4 种颜色**常亮**（白/青/紫/橙） | 2 位 |
| **2** | **节拍器** | 开 / 关 | ⭐ **开 = 按 BPM 闪烁**（绿色，每次拍点闪一下）· 关 = **灭** | 1 位 + ⭐ **拍点脉冲** |
| **3** | **鼓机** | 开（4~5 种节奏型）/ 关 | 4~5 种颜色常亮（红/洋红/黄/橙红/粉）· 关 = **灭** | 3 位 |
| **4** | **键盘打鼓** | 开 / 关 | 蓝色常亮 / **灭** | 1 位 |
| **5** | **looper** | 空闲 / 录音 / 回放 | 暗蓝常亮 / ⭐ **红色快闪** / 绿色常亮 | 2 位 |
| **6** | **推子功能（gear）** | 颤音 / 变调 / 摇把 / 无 | 青 / 紫 / 黄 / ⭐ **灭** | 2 位 |
| **7** | **指板 / 键盘模式** | 指板 / 键盘 | 橙 / 绿 | 1 位 |

⭐ **合计需要约 19 种不同颜色 + 2 种闪烁效果**（快闪 / 按拍点闪）⇒ ⭐ 一张**颜色表**就能覆盖 ✅

## 二、⭐ 三层接口（⭐ 这就是"不麻烦"的原因）

```
┌─────────────────────────────────────────────────────────────┐
│ 第 1 层：各子系统（⭐ 它们本来就有状态，只需引出状态码）        │
│   音色: timbre_id[1:0]        节拍器: metro_on + beat_pulse   │
│   鼓机: drum_on + drum_pat[2:0]  键盘打鼓: keydrum_on         │
│   looper: loop_st[1:0]        推子: gear[1:0]                │
│   模式: fb_mode                                               │
└──────────────────────────┬──────────────────────────────────┘
                           ↓  ⭐ 全部是"读现成信号"，⛔ 不新增状态机
┌─────────────────────────────────────────────────────────────┐
│ 第 2 层：指示层（⭐ 表驱动：状态码 → 24 位 GRB 颜色）          │
│   · 每路一个 case 表（4~6 行）                                │
│   · 闪烁由"拍点脉冲"或内部快闪计数器调制                      │
│   · 输出：7 × 24 位颜色 + 7 位使能（灭 = 颜色 0 且使能 0）      │
└──────────────────────────┬──────────────────────────────────┘
                           ↓  "每颗灯什么颜色"
┌─────────────────────────────────────────────────────────────┐
│ 第 3 层：WS2812 PHY（⭐ 正在写的那个驱动）                     │
│   · 4 通道共用位时序引擎（800 kHz · GRB · ≥300 µs 复位）        │
└─────────────────────────────────────────────────────────────┘
```

⭐ **加第 8 个东西的代价**：① 子系统引出 2~3 位状态码（~5 LUT）② 表里加一个 case（~30 LUT）③ 灯序里加一颗 ✅ ⇒ ⭐ **完全不需要动 PHY** ✅

## 三、⭐ 资源估算（⭐ 依旧很小）

| 项 | 估算 | 说明 |
|---|---|---|
| 颜色表逻辑 | **~200~400 LUT** | 7 路 × (case 表 ~30 LUT) + 使能/闪烁调制 |
| 颜色寄存器 | **~168 FF** | 7 × 24 位（⭐ 若灯数多则放 BSRAM） |
| 快闪计数器 | ~20 LUT + 16 FF | 一个共享的（⛔ 不要 7 个） |
| PHY 驱动 | ~150~300 LUT | 正在写 |
| **合计** | ⭐ **~400~700 LUT ≈ 设计的 1~2%** | ✅ 完全可接受 |

⭐ **省资源的三个要点**：① **快闪计数器共享**（⛔ 不是 7 个）② **4 通道共用位时序引擎**（⛔ 不是 4 套）③ 颜色表用 `case` ⇒ 综合成**分布式 ROM** ✅

| # | 灯 | 状态码 | 颜色（RGB888） |
|---|---|---|---|

| 2 | 鼓机 | 关 / 0/1/2/3 | 灭 / 红 `FF0000` · 洋红 `FF00FF` · 黄 `FFFF00` · 橙红 `FF4000` |
| 3 | 键盘打鼓 | 关 / 开 | 灭 / 蓝 `0000FF` |

### 7.7 ⭐⭐ 集成判据（2026-10-04 补）—— `tb/top/tb_top_led_strip.sv`

🔴 **为什么必须补**（⭐ 这是 §7.5 四道门当时**没盖住**的地方）：
`tb_led_indicator` 只测**本模块**、`tb_ws2812_driver` 只测 **PHY**，
⛔ **全仓没有任何 tb 观察 `ctrl_ws_o`** ⇒ `top.v` 里
"7 路颜色 → 写口 `case` → 驱动"这段接线**当时没有判据**：
⚠️ 切片顺序写错 / 灯序颠倒 / `WS_LED_N` 差一 ⇒ **119 个 tb 全都会绿**。

⭐ **做法**：⭐ 只看**引脚波形** —— 把线上 **384 个 bit cell** 解回 GRB → 24 位颜色，再**逐颗**比对。
⭐ 两个 `top` 实例（`DEMO_CHORD_ON=1` 出声档 / `=0` 静音档）⇒ ⭐ 顺带钉住
**两根跨 `generate` 状态线**（⭐ §7.1 第 1 条那个"两个互斥分支各自驱动"的手法）。

| # | 判据 | 钉住什么 |
|---|---|---|
| 1 | 上电帧 `LED0..LED6` == 白/灭/灭/灭/暗蓝/青/绿 ＋ **`LED7..LED15` 全灭** | ⭐ 切片顺序 · 灯序 · 写口 `default` |
| 2 | ⭐ **活体**：发裸 `'I'`（切音色）⇒ 下一帧 LED0 变青，⭐ **且只有它变** | ⛔ 不是常量、⛔ 不是串线 |
| 3 | ⭐ 静音档实例 ⇒ **LED5 必须灭** | ⭐ 跨 `generate` 分支的驱动 |
| 4 | 整帧 = **384 × 62 拍** ＋ 帧间长低 ≥ 10000 拍 | ⭐ 位周期 / 帧间复位契约 |
| 5 | `ws_strip_o` 恒 `000` · `esp_uart_tx_o` 恒高 | ⭐ 预留脚**没被这次改动碰** |
| 6 | A8：`ctrl_ws_o` 无 X/Z | — |
