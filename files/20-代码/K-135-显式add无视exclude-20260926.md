# 🔴 `K-135`：显式路径 `git add` 会**无视** `.git/info/exclude`（2026-09-26 实测踩到）

> **状态**：⭐ **[已确认 + 已修复]** —— ⚠️ **push 前的敏感文件扫描抓到了**
> **危害等级**：🔴 **公开仓库** ⇒ ⚠️ 一旦推上去**无法从历史撤回**

---

## 〇、⭐⭐ 一句话

```
🔴 `git add "<显式路径>"` 会让文件【入库】，⭐ 哪怕它在 `.git/info/exclude` 里！
⇒ ⚠️ 因为 `exclude` **只对【未跟踪】文件生效** ——
   🔴 而显式路径 add **本身就是"要跟踪它"的意思**，⭐ 直接绕过 exclude。
```

## 二、🔴 为什么 `exclude` 没挡住

```
⭐ git 的忽略规则分三层，⛔ 但它们【都只对未跟踪文件生效】：
   ① `.gitignore`         （⭐ 会被推送）
   ② `.git/info/exclude`  （⭐ 本地私有，⛔ 不会推送）
   ③ `core.excludesFile`  （⭐ 全局）

🔴 **共同前提**：⭐ 文件必须是【未跟踪】的。
⇒ ⚠️ 而 `git add <path>` 的含义是"**开始跟踪这个路径**"
⇒ 🔴 **它优先于忽略规则** —— ⭐ 这正是设计如此，⛔ 不是 bug。
```

📌 **推论**：⭐ 一旦某个文件被 `add` 过，🔴 **`exclude` 对它永久无效**，
直到 `git rm --cached <file>` 把它**退回未跟踪**。

---

## 三、✅ 正确做法

### ① ⭐ 加私有文件时，**两步一起做**

```powershell
# ⭐ 第一步：先写 exclude（⭐ 顺序很重要）
Add-Content ".git\info\exclude" "交接文档-20260926.md"

# ⭐ 第二步：确认它真的被忽略
git check-ignore -v "交接文档-20260926.md"
#   期望：输出 `.git/info/exclude:NN:交接文档-20260926.md`
#   🔴 若无输出 ⇒ 说明【没生效】⇒ ⛔ 别继续
```

### ② ⭐ **永远不要**显式 `git add` 一个私有文件

```powershell
# 🔴 反面教材（我踩的）
git add "交接文档-20260925深夜.md"        # ← 无视 exclude！

# ✅ 正确：只 add 该推的，⭐ 逐个列出
git add rtl/top.v tb/w3c/tb_seq_arb.sv files/20-代码/xxx.md
```

### ③ 🔴 **push 前必扫**（⭐ 这一条是最后的防线）

```powershell
git diff --name-only origin/main..HEAD |
  Select-String -Pattern '备料|\.xlsx$|交接|待答复|meeting-|对外咨询'
#   🔴 有任何输出 ⇒ ⛔ 停下，先处理
```

### ④ ⚠️ 已经误入库了怎么办

```powershell
# ⭐ 必须在【push 之前】处理！
git rm --cached "<file>"     # ⭐ 退回未跟踪（⛔ 不删工作区文件）
# ⭐ 然后 commit —— 若在压 commit 阶段，reset --soft 后它自然就没了
```

🔴 **一旦 push 出去，就只能靠 force-push 改写历史**（⭐ 公开仓库上**极危险**，
⚠️ 可能覆盖队友提交）⇒ ⭐ **所以 push 前的扫描是唯一可靠关口**。

## 五、⭐⭐ 教训（⭐ 建议进经验库）

```
🔴 **忽略规则与 `git add` 的优先级，是"显式命令赢"** ——
   ⚠️ `exclude`/`.gitignore` 都只是"**建议**"，⭐ `git add <path>` 是"**决定**"。
⇒ ⭐ **私有文件的正确姿势是"先 exclude、再验证 `check-ignore`"**，
   ⛔ 不是"先写文件、最后靠 exclude 兜底"。
📌 **最后防线**：⭐ **push 前扫 `git diff --name-only origin/main..HEAD`** ——
   ⭐ 这一条与 `K-121`（push 权限）同族：⭐ **"发送前先看清楚要发什么"**。
```
