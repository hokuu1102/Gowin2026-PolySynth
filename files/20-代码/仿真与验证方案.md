## 〇、⭐ 三条铁律

1. ⭐⭐ **一切验收必须有"可复现的仿真证据"**（波形 / 日志 / CSV / 频谱图 / 统计表），⛔ 不接受"我看波形是对的"这种口头结论。
2. ⚠️ **基石板 ≠ 正式板**：器件型号不同 ⇒ **基石板上综合/布局布线通过，不能代表 GW5AT-60 的时序收敛**。
   ⇒ 基石板只能证明 **"RTL 能综合、能上电、能被观测"**（逻辑正确性），⛔ **不能用来验收音频**。
3. ⭐ **每个模块都要有 tb**；没写 tb 的模块视为"没做完"。

## 一、⭐ 必须建立的 5 个行为模型

| # | 模型 | 干什么 | 关键点 |
|---|---|---|---|
| **S1** | **`MCP3208` 从机模型** | 按 `Start / SGL / D2..D0 / Null / B11..B0` 帧回数据 | 逐位对齐 `SCK` 边沿；`CS` 高时 `DOUT` 必须**高阻**（⭐ 用来抓"多片 `MISO` 并线"的隐患，`K-06`） |
| **S2** | **I2S 从机 + DAC 重构模型** | 把 `BCLK/LRCK/DIN` **解串回样点**，再经一阶/二阶重构滤波 | ⭐ 这是**没有耳机时"听见声音"的替代品**：输出模拟样点流，可画波形/做 FFT |
| **S3** | **`TLC5916` 从机模型** | 收 `SDI/CLK/LE`，维护移位寄存器与输出锁存 | ⭐ **必须实现 Special Mode 检测**：`OE` 上出现"一个 `CLK` 宽的脉冲"就置 `special_mode=1` 并持续报错（`K-01`） |
| **S4** | **机械触点抖动模型** | 给按键/编码器注入带抖动的波形 | 参数化抖动宽度；用来验证 `debounce` 只出一次事件 |
| **S5** | **音频参考模型（golden）** | 按 `phase_inc` 算出**期望输出样点** | ⭐ M1/M2 的判据靠它：**逐点比对**而不是"看着像" |

> ⭐ 这 5 个模型建议放 `tb/models/`，**所有人共用**（⛔ 别各写一份）。

## 二、⭐ 必须建立的检查器（断言）

| # | 断言 | 护住哪条 | 放在哪 |
|---|---|---|---|
| **A1** | ⛔ **`OE_n` 上不得出现宽度 ≤1 个 TLC `CLK` 的脉冲** | `K-01`（Special Mode） | `tlc5916` 接口监视器 |
| **A2** | ⛔ **`LE` 在 TLC `CLK` 活动期间必须为低**（只在移完后打一个宽脉冲） | `K-03` | 同上 |
| **A3** | ⛔ **灯的移位 `CLK` 与 ADC 的 SPI `SCK` 不是同一根线** | `K-13` | `top` 结构检查（例化期） |
| **A4** | ⛔ **三片 ADC 的 `CS` 不得同时有效** | `K-06` | `adc` 监视器 |
| **A5** | ⛔ **`MISO` 任一时刻只有一个驱动源** | `K-05`/`K-06` | 同上 |
| **A6** | ⭐ **每音频帧 1024 个系统时钟内必须完成渲染与后处理**，超时置 `deadline_fault` | 架构文档 §4.1 第三瓶颈 | `top` |
| **A7** | ⭐ **变调/滑音时 `phase_acc` 不得被清零或复位** | `K-10`（咔哒声） | `voice` |
| **A8** | ⛔ **仿真全程无 `X` 传播** | 通用 | 每个 tb |

## 三、⭐ 验收映射（里程碑 → 仿真证据）

| 里程碑 | 仿真证据（替代硬件验收） | 判据 |
|---|---|---|
| **M0 时基与安全上电** | 波形量周期 + 安全态快照 | `BCLK`=**3.125 MHz**、`LRCLK`=**48.828125 kHz**（即 ÷4/÷4/÷256）；`PA_EN_n=1`、`OE_n=1`；**A1 通过** |
| ⭐ **M1 第一次"出声"** | ⭐ **S2 解串 + S5 逐点比对 + FFT** | 解串回样点与 golden **逐点一致**（容差内）；FFT 上**单根谱峰**、频率 = `phase_inc×fs/2^32`；SNR 达标、无杂散 |
| **M2 低延迟拨弦** | 延迟统计 tb：注入 `UP/DOWN` → 数到**首个非零样点**的周期数，跑 **50 次** | 输出 `min/max/极差`；⭐ 数字端目标 **<2 个音频帧**、极差 **<0.1 ms**；`A7` 通过 |
| **M3 三 ADC 与控制** | S1 假从机回数据 + 通道对齐检查 | 同一通道重访间隔 = **25000 周期（0.5 ms）**；三片并行、`CS` 不互扰（`A4`/`A5`）；⭐ 音量曲线**单调且近似对数**（导出 CSV 画曲线） |
| **M4 32 voice / Test Mode** | S2 + FFT 谱峰计数 | ⭐ **N = 4/8/16/32 时谱峰数正好为 N**；综合报告能数出 **32 份相位/包络状态**；`deadline_fault=0`（`A6`） |
| **M5 32×2 与两音色** | FFT 差异 + lane 计数 | 64 lane 状态可追溯；两音色**频谱形状可辨**；颤音速率变化无音高跳变（相位连续，`A7`） |
| **M6 UI/LED** | 映射真值表 + `A1`/`A2` 回归 | 编码器对象环、四键、4 双色灯映射**逐条查表正确**；⭐ `A1` 全程无 Special Mode |
| **M7/M8** | 全系统回归 + 压力 | 所有 A1~A8 全绿；`deadline_fault=0` |

> ⭐ **硬件到货后的增量**（不是重做）：把 M0/M1 换成**实测**（示波器量 `BCLK/LRCLK`、耳机听声、逻辑分析仪看 I2S），并补 **DAC+模拟功放的未知延迟**（架构文档 §7.1 标注为"必须实测"）。

## 四、⭐ 基石板现在能做什么（有限，别高估）

| 能做 ✅ | 不能做 ⛔ |
|---|---|
| **综合 / 布局布线能过**（证明 RTL 无语法/无不可综合结构） | ⛔ **时序收敛**（器件型号不同，`K-22`） |
| **上电后 LED / UART 观测**（若基石板 IO 够引出） | ⛔ **音频验收**（没有 I2S DAC 通路） |
| 时钟分频**用示波器量**（若有时钟输出脚） | ⛔ **IO standard / 脚位**（正式板脚位未定，`K-23`） |
| `TLC5916` 驱动**若基石板能接灯** | ⛔ 三片 ADC / 板A 板B 的真实时序 |

⭐ 结论：**基石板的定位是"烧得进去、跑得起来、能看见状态"** —— 它是**冒烟测试**，不是验收。

## 五、⭐ 建议补的工具脚本（放 `tools/`）

| 脚本 | 作用 |
|---|---|
| `vcd2csv.py` | 从 VCD 抽指定信号 → CSV（供 Python 分析） |
| `csv_fft.py` | 对样点流做 FFT，**画频谱 + 报主峰频率/SNR/杂散**（M1/M4/M5 的验收图） |
| `latency_stats.py` | 读延迟测量日志 → 输出 **min/max/均值/极差**（M2 的验收表） |
| `peak_count.py` | 数谱峰个数并与期望 `N` 比对（M4 的自动判定） |
| `tb_all.ps1` | ⭐ **一条命令跑全部 tb**（自动发现 `tb/**`，汇总通过/失败） |

> ⭐ `tb_all.ps1` 是**L0 的交付物**：有了它，"跑一遍回归"才有统一的入口。
