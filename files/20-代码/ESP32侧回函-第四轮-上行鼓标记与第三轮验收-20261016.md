## 一、🔴 用户实测抓到一个上行回传的硬伤：帧里没有"鼓"这一位

### 1.1 现象（用户原话）

> "我全程只用 bass 弹的，但是识别出了鼓"
> "这是我分别用 4 个音色回传的，但是都还是只显示了一个音色"

### 1.2 根因（我方已核到 RTL 原文，一次不差）

```verilog
rtl/w3c/seq_arb.v:380   evt_axis_o   <= pop_data[AX_O +: AXIS_W];   // 轴号原样透传
rtl/w3c/seq_arb.v:385   evt_timbre_o <= pop_data[0 +: TIMBRE_W];    // timbre 原样透传
```

⇒ 上行帧里 `axis` 与 `timbre` **都是从下行帧原样透传**，而：

| 字段 | 在下行帧里的含义 | 能不能区分鼓？ |
|---|---|---|
| `axis[22:19]` | voice 定位键（对所有来源都成立） | ⛔ **不能** —— 手弹/旋律的槽位由你们分配，实测在 0..15 里跳（截图里 bass 的轴 = 4/13/3/2/13/12/10/11…），跳到 12..15 就被判成鼓 |
| `timbre[8:7]` | 旋律 = 音色 0..3；鼓 = drum_type 0..3 | ⛔ **不能** —— 两者**共用同一个 0..3 编码空间** |

📌 旁证（你们自己早就修过同族缺陷）：`rtl/w3b/note_manager.v:644` 的注释
"🔴 原缺陷：按 `cur_axis >= 14` 选池 ⇒ 物理键 14/15（G#3/A#3）被误判成鼓"。
⇒ **"把轴号当鼓标记"是这套设计的老毛病**，这次只是显形在上行回传面板上。

### 1.3 我方已做的止血（⛔ 不是根治）

`esp32/tools/score_studio.html`（提交 `d6ed6bd5`）：回传侧三处**删掉"用轴号猜鼓"**：

- 卷帘配色：`uTimbreColor` 只按 `timbre` 分色（删掉 `isDrumAxis(axis) → DRUM_COLOR`）
- 图例：删掉「鼓」项；为空时提示"帧内无音色/鼓标记"
- 导出 `.mid`：通道只按 `timbre`（删掉 `isDrumAxis(axis) ? 9` —— 原来会把 bass 错塞进 GM 鼓通道 9）

⇒ 现在只弹 bass 显示橙色（BASS），不会再冒出假鼓。**但这是止血**：
⚙️ 鼓在上行仍不可判（我们不再猜，也**不再展示**"鼓"）。

### 1.4 ⭐ 根治：请你们实现手册 §4.4（这是本轮唯一必须你们做的事）

手册 §4.4 原文：

```text

```

⇒ 改 `seq_arb.v` 的上行输出即可（你们那两行透传改成按 `score_is_drum_i` 分流）：

```verilog

evt_axis_o <= score_is_drum_i ? {2'b0, score_drum_type_i} : 4'd0;   // 鼓回传 dt，旋律回传 0
```
