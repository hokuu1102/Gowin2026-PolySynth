# 🔴🔴 `K-132` 定案：`'S'` 只回 `s`、不回轴号 —— 根因与修复（2026-09-25）

> **状态**：⭐ **[已确认]** —— ⭐ 上板现象 + 仿真正反向双证
> **现象**：⭐ 发 `'S'` ⇒ 🔴 **只回一个 `s`，⭐ 没有轴号，⭐ 也没有 `!`**
> **修复**：⭐ `calib_span.v` 的 `S_PROMPT` **改为停留 2 拍**（⭐ 新增 `prompt_phase`）
> **回归保护**：⭐ 新增 `tb_span_retry_reemits_axis`（⭐ 已反向验证）

---

## 〇、⭐⭐ 一句话

```
🔴 `need_press_o` 一旦拉起就**再也不会落下**（⭐ 直到 `S_WAITBUSY`/`S_DONE`）
⇒ ⭐ 超时重试回到 `S_PROMPT` 时它**本来就是 1** ⇒ 🔴 **没有 0→1 跳变**
⇒ 🔴 `top.v` 的**上升沿检测** `ev_need = sp_need_press & ~sp_need_r` **不再产生事件**
⇒ 🔴 **轴号只发第一次，之后永远不发。**
```

---

## 一、⭐ 现象（⭐ 用户上板实测）

```
发 8 次 'S'  ⇒  ⭐ 回 `ssssssss`
                🔴 **没有轴号，⛔ 也没有 `!`**
⚠️ 而 `'P'`（读 ADC）和 `'V'`（读状态）都【正常】
```

⚠️ **注意这【不是】原来那个 `s0!0!0!...`** —— ⭐ 现象**变了**：
| ⭐ 阶段 | ⭐ 回包 |
|---|---|
| 早期（`K-126` 修复后） | ⭐ `Ss0!!!!!`（⭐ **有轴号** + 5 个拒绝） |
| **现在** | 🔴 `ssssssss`（⭐ **连轴号都没有**） |

⇒ ⭐ **"轴号消失"是【新暴露】的问题**，⭐ 恰好与 `K-126` 是**同一个字段（轴号）的第二个 bug**。

---

## 二、🔴 根因链路（⭐ 逐跳）

### 跳 ①：`S_PROMPT` 只停 1 拍

```verilog
// calib_span.v （⭐ 修复前）
S_PROMPT: begin
    cur_axis_o   <= cur_axis;
    need_press_o <= 1'b1;     // ⭐ 置位
    ...
    state        <= S_SETTLE; // 🔴 **同拍就离开！**
end
```

### 跳 ②：之后**没有任何状态清它**

⭐ 全文件 `need_press_o <=` 的赋值点（⭐ **修复后**核实）：

| ⭐ 行 | ⭐ 状态 | ⭐ 动作 |
|---|---|---|
| 224 | 复位 | ⭐ `<= 0` |
| 292 | `S_IDLE` | ⭐ `<= 0` |
| **321** | `S_PROMPT` | ⭐ **第 1 拍 `<= 0`**（⭐ 造下降沿） |
| **325** | `S_PROMPT` | ⭐ **第 2 拍 `<= 1`**（⭐ 上升沿） |
| 469 | `S_WAITBUSY` | ⭐ `<= 0` |
| 588 | `S_DONE` | ⭐ `<= 0` |

🔴 **`S_SETTLE` / `S_VOTE` / `S_FIRE` 三者【都没有】** ⇒ ⭐ **它一直保持 1**。
📌 这正是 `K-132` 的**第二半**：⭐ 不是"没置位"，🔴 而是**置位后再也不落**。

### 跳 ③：`top.v` 用的是**上升沿检测**

```verilog
// top.v
sp_need_r   <= sp_need_press;                          // ⭐ 打一拍
wire ev_need = sp_need_press & ~sp_need_r;             // 🔴 **只在 0→1 时成立**
wire [7:0] rep_byte = ev_need ? axis_char : ...;       // ⭐ 轴号
```

### 🔴 合起来 ⇒ 轴号永久丢失

```
第 1 次进 S_PROMPT：need_press 0→1  ⇒ ✅ ev_need ⇒ 发轴号
超时 ⇒ 回 S_PROMPT：need_press 本来是 1
        ⇒ S_PROMPT 又写 <= 1 ⇒ 🔴 **值没变 ⇒ 没有跳变**
        ⇒ 🔴 **ev_need 不成立 ⇒ 轴号不发**
⇒ ⭐ **只有第一次有轴号，之后全没有**  ← 🔴 与上板现象【完全一致】
```

## 三、⭐⭐ 仿真正反向双证（⭐ 决定性证据）

⭐ 新增 `tb_span_retry_reemits_axis`：⭐ **制造 9 次重试**，⭐ 并复刻 `top.v` 的边沿检测数"轴号会发几次"。

| ⭐ 版本 | ⭐ 进 `S_PROMPT` | ⭐ `ev_need`（= 回轴号） | ⭐ 判定 |
|---|---|---|---|
| 🔴 **修复前** | 9 | 🔴 **1** | ⭐ **FAIL** ✅ 正确抓到 |
| ✅ **修复后** | 9 | ✅ **9** | ⭐ **PASS** |

⇒ 🔴 **修复前的"9 次机会只发 1 次"正是上板现象** ⇒ ⭐ **根因坐实**。

### ⚠️ 为什么以前没抓到（⭐ 判据盲区）

| ⭐ tb | ⭐ 它判什么 | ⚠️ 漏了什么 |
|---|---|---|
| `tb_calib_span` | ⭐ `need_press_o` **拉起来了** | 🔴 **没判"轴号发出去了几次"** |
| `tb_uart_calib_chain` | ⭐ `need_press_o is high` | 🔴 同上 |

⇒ ⚠️ **`K-87` 同族**：⭐ **"看得见状态，看不见结果"** ——
⭐ 它验证了 `need_press_o`（⭐ 状态）✅，🔴 但**没验证"轴号字节"（⭐ 结果）**。

## 四、✅ 修复

```verilog
S_PROMPT: begin
    cur_axis_o <= cur_axis;
    if (!prompt_phase) begin
        need_press_o <= 1'b0;     // ⭐ 第 1 拍：造出【下降沿】
        prompt_phase <= 1'b1;
    end else begin
        need_press_o <= 1'b1;     // ⭐ 第 2 拍：干净的【上升沿】⇒ ev_need
        prompt_phase <= 1'b0;
        ...                       // ⭐ 清 vmin/vmax/vote_cnt/stable_cnt/prev_val
        state        <= S_SETTLE;
    end
end
```

### 📌 设计取舍

| ⭐ 方案 | ⚠️ 评价 |
|---|---|
| ⭐⭐ **`S_PROMPT` 停 2 拍**（⭐ 采用） | ✅ **改动局部**、⭐ 语义清晰 ⇒ ⭐ **每次重试都重发轴号** |
| ⚠️ 把 `top.v` 的边沿检测改成**电平** | 🔴 **会每拍都发** ⇒ ⚠️ 刷屏 |
| ⚠️ 让 `need_press_o` 保持到"按稳" | ⚠️ 那**正是当前行为** ⇒ 🔴 **就是 bug 本身** |

⭐ **为什么用显式标记 `prompt_phase` 而不是"数拍子"**：
⚠️ 数拍子在重构时会**静默漂移**（⭐ 改别处一不小心就错位）；⭐ 标记把**意图写在代码里**。
📌 **复位**与 **`abort_i`** 分支都清零该标记（⭐ 否则中途取消会带脏状态）。
