## 〇、一句话摘要

**H5 波形显示的"两条线"是真实的显示缺陷（上一帧残影），修复方案已被离线逐像素证明有效 ✅；
但该修复在 91% CLS 占用的设计上触发了全局重布局，把 `clk_sys` 从 53.425 MHz 打回 ~50.0–50.5 MHz ❌。
过程中的所有尝试都指向同一个根因：复位分发（扇出 12805）与"多个锥挤在 50.x"的拥挤布局。**
**当前安全版本仍是已推送并已打标签的 `d449504`（53.425 MHz、setup/hold 0/0、带残影）。**

## 一、过程记录（按时间顺序，全部为实测）

### 1.1 起点：用户报"波形是两条线"

| 步骤 | 做法 | 结果 |
|---|---|---|
| 1 | 读 `rtl/hdmi/waveform_scope.v` 绘制逻辑 | 一帧只画两样：绿色波形（`00ff00`）+ y=240 暗灰基线（`282828`）⇒ **不可能有两种亮度的绿** |
| 2 | 写离线测试台 `tb_scope_dump.v`：灌已知正弦（523.25 Hz @ 48.828 kHz），dump 整帧 640×480 RGB | 两帧各 307,200 像素，尺寸精确 |
| 3 | 逐列统计绿色段数 | **frameA/frameB 各 640/640 列恰好 1 段，>1 段的列 = 0** ⇒ ⭐ **RTL 一帧只画一条波形** |
| 4 | 统计两帧之间的横向位移 | **最佳位移 = −260 px（rms 0.9）**；不对齐时 640 列里只有 **1 列**相同 |

**结论（已证明）**：显示窗口 = 640 采样 = **13.107 ms**，而帧周期 = **16.683 ms**
⇒ 每帧窗口前进 3.559 ms ≈ **1.86 个音频周期** ⇒ 波形每帧横向跳 ~260 列；
音频与视频不同源、快照固定在 vblank ⇒ **上一帧的残影就是"第二条线"**（LCD 响应 + 相机曝光）。

### 1.2 修复：音频触发窗口（`rtl/hdmi/waveform_scope.v`）

把固定窗口 `wr_seen-640` 改成：**先扫描环形缓冲尾部（从 `wr_seen-960` 起、最多 320 个采样）找第一个上升过零点，
从该采样开始填 `frame_y[0..639]`**；找不到过零（静音/直流）时回退到 `wr_seen-640`（与旧行为一致）。
拷贝预算 ≤ 960 像素时钟 = 38 µs，起始于第一个消隐行（y=480，消隐 45 行 = 1.43 ms）⇒ 时序与环形内容都安全。

**过程中修掉的一个真 bug**：读流水线深一拍 ⇒ 扫描最初两拍会与**上一窗口的残留采样**比较，
产生 `scan_i_q=0` 的**假触发**（实测：位移只从 −260 改善到 −216）。加 `scan_warm`（前两拍不判定）后：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 每帧绿色段数 | 640/640 列各 1 段 | 640/640 列各 1 段（不变） |
| 两帧 \|dy\| ≤ 1 px 的列 | 2 / 640 | **360 / 640** |
| 两帧 \|dy\| ≤ 2 px 的列 | — | ⭐ **640 / 640（100%）** |
| 两帧 \|dy\| > 10 px 的列 | 大量（最大 ~180 px） | **0** |
| 平均 \|dy\| | 巨大 | **1.13 px**（采样格点量化极限） |

窗口起点样本值：copy1 = 157672、copy2 = 187300、copy3 = 15104 ⇒ 相位误差 ≤ **0.7 个采样**（旧版 2.8 个整周期）。

**测试台同步更新** `tb/hdmi/tb_waveform_scope.sv`：参考模型改为触发窗口 + 新增**独立不变量**
（窗口首样本必须是上升过零点，回退时不计入）⇒ 6 个激励模式全帧逐像素通过，
`PASS: triggered window started on a rising zero crossing in 4 snapshots`，`2308886 pixel checks`。

### 1.3 代价：`clk_sys` 被打回 50.x（**本次拉锯的核心**）

| 构建 | 改动 | setup/hold | `clk_sys` | 最差路径 slack |
|---|---|---|---|---|
| 基线 `d449504` | 无显示修复 | **0 / 0** | **53.425 MHz** | +1.282（ADSR 锥） |
| B1 | + 触发窗口 | 0 / 0 | **50.085 MHz** | **+0.034**（同一条 ADSR 锥） |
| B2 | + `hdmi_soft` + `rst_sync_grp` 区域约束 | 0 / 0 | 50.062 MHz | +0.025（换成 `tm_n_code→env_level_o`） |
| B3 | + `adsr.v` 按音色参数打一拍（撤 `hdmi_soft`） | 0 / **4** | **50.449 MHz** | +0.178（复位网） |
| B4 | + HDMI 复位改 `!video_reset_n` | **4** / 0 | **51.458 MHz** | +0.567 |
| B5 | + 序列化器内 `serial_clk` 域复位同步器 | 0 / **2** | 50.527 MHz | +0.209 |
| B6 | + 定向 CDC false path | ⛔ **构建失败**（`TA2003`，见 §2.6） | — | — |

**量化对比（关键）**：
- 显示改动净增 **≈ 33 个触发器 + 约 60 个 LUT**（全设计 Logic 50409/59904 = 85%、**CLS 26977/29952 = 91%**、Register 26%）
- 即 **0.1% 的逻辑量换来 6% 的周期退化** ⇒ 在正常占用率下不可能发生
- 同一条 ADSR 锥（逻辑一字未改）在 B1 里退化 **1.248 ns**；时钟偏斜在两次构建间从 **−0.454 ns** 摆到 **−0.008 ns**

### 1.4 途中发现的**真实缺陷**（与显示无关，值得单独保留）

1. **OSER10 的 RESET 原来直接接 `clk_sys` 的裸复位**（`hdmi_scope.v`：`.rst(!rst_n)`），
   而它由 **FCLK（serial_clk）** 采样 ⇒ 异步复位跨域。三种接法各报一条违例：
   - `clk_sys → pixel_clk` hold **−0.053**（复位同步器被搬近之后）
   - `pixel_clk → serial_clk` setup **−0.516**（RESET 改由像素域驱动）
   - `clk_sys → serial_clk`（`rst_serial_*` 的 PRESET）hold **−0.178**（加 serial 域同步器后）
2. **`u_rst_sync/sync_chain_1_s0` 的扇出 = 12805**（接近全设计 15733 个 FF）⇒ 走**通用布线资源**，
   一段网络就 **4.7 ns**；它一度位于 **R73C54**（芯片底部），却要驱动 **R31C8** 的 `test_mode_ctrl` ⇒ 跨 42 行 46 列。
3. **`adsr.v` 的按音色参数是组合查表**（`attack/decay/sustain/release_for_timbre(timbre_i)`），
   `sustain_q8_u` 直接喂乘法器 ⇒ 甲当年的注释（`adsr.v:120`）已把它标为"时序回归的第二个来源"。

## 二、已认识清楚的问题（有证据，可直接引用）

### P1 ✅ 显示缺陷的根因 = 帧间相位漂移造成的残影（**已证明**）
RTL 一帧只画一条（640/640 列各 1 段）；相邻帧错开 260 px（= 1.86 个音频周期）。
证据：`evidence/h5/triggered-scope-20261002/`（工具 + PPM + PNG + README）。

### P2 ✅ 修复本身有效（**已证明**）
触发窗口后两帧 **100% 列在 2 px 内一致**，相位误差 ≤ 0.7 采样。

### P3 ✅ 这个设计的 CLS 已 91%，**布局质量是离散跳变的**
0.1% 的逻辑变化 ⇒ 同一条锥退化 1.25 ns；偏斜大幅摆动。
⇒ **任何单次构建的 Fmax 都不是"稳健余量"**，而是**一次抽签**。

### P4 ✅ **53.425 MHz 不是设计的真实余量，而是一次好签**
那次所有锥都宽裕（最差 +1.282）；现在同一批锥全挤在 **+0.025 ~ +0.6**。
这同时解释了另一件事：**甲在无 H5 时能到 58.581 MHz**，而任何一点改动都会掉回 50.x。

### P5 ✅ 复位分发（扇出 12805）是**反复出现的**瓶颈
B3/B5 的最差路径都是 `u_rst_sync/sync_chain_1_s0/Q → …/env_level_o`（**同步**复位，属于真实功能路径）。
把复位同步器搬到中部（`rst_sync_grp`）确实生效（R73C54 → R49C20），但随即在**别的域**报出 hold。

### P6 ✅ 异步复位跨域"怎么接都会报一条"
见 §1.4-1：`clk_sys→pixel_clk` / `pixel_clk→serial_clk` / `clk_sys→serial_clk` 三种都试过，各报一次。

### P7 ✅ 当前工作区**不是**可交付状态
最后一次成功构建（B5）：**setup 0 / hold 2**、`clk_sys` 50.527 MHz ❌。
安全版本仍是 `d449504`（标签 `timing-53p425-h5-20261002`，已推远端；码流 `M_timing53p425_h5.fs`）。

### P8 ✅ 一条**工具语法**的坑（新增）
`set_false_path -from [get_pins {…/Q}] -to [get_pins {u_hdmi/u_serializer/*}]`
⇒ `ERROR (TA2003) Can't set timing constraint to object`：`*` 通配**没有解析出对象**。
⛔ 不是"生效但无效"，是**直接让构建失败**。

## 四、修改方向（按"把握 ÷ 代价"排序）

### D1 ⭐ 先锁定安全版本，再逐项推进（**最稳**）
1. 以 `d449504`（标签 `timing-53p425-h5-20261002`）为**交付锚点**（53.425 / 0/0，带残影）
2. 在它之上**只加 ADSR 打拍**（已验证 ✅、3 个 tb 全绿 ✅）⇒ 期望 ≥53.4，真实余量增加
3. 再单独攻**复位分发**（D2）
4. 复位分发有真实余量后，**最后**把显示修复加回来
> ⛔ 不要在"显示修复 + 未修复位"的状态下继续调约束——那是在抽签（P3）。

### D2 ⭐⭐ 治本：复位分发（当前最大瓶颈）
- **D2a 分层缓冲**：在 `envelope_bank.v` 里按 4 组 × 8 voice 各做一份**局部复位缓冲**（寄存一拍），
  把 32 个 ADSR 从同步器的直接负载上摘下来。⚠️ 语义：同步复位晚一拍生效，需在提交说明里写明并跑 tb。
- **D2b 复制同步器**：`top.v` 里实例化 2–4 份 `rst_sync`，分区驱动（音频 / HDMI / LED 等）。
  ⚠️ 改动面更大（`top.v` 是共享文件，属代修）。
- **D2c 减少复位面**：把"数据通路上其实不需要复位"的寄存器改成**无复位 + FSM 清零**（H2 的验证）。

### D3 继续削 ADSR 锥（真实余量）
`adsr.v` 的 `state`/电平算术若仍是最差，可继续打拍（⛔ 每次都要逐拍差分 + 回归）。

### D4 把 CDC 复位写对（工具支持的形式）
- 试**具体引脚名**逐条列 4 个 lane（`u_hdmi/u_serializer/lanes[0..3].u_oser/RESET`），⛔ 不用 `*`
- 或改用时钟对形式（`-from [get_clocks clk_sys] -to [get_clocks serial_clk]`）
- ⚠️ 但**优先考虑 D2b**：让 HDMI 用**自己的**复位同步器，从根上不跨域，比加 false path 更干净

### D5 显示修复的替代实现（降低对 clk_sys 的侵入）
- 把**扫描/触发逻辑整体放到 pixel 域**（采样侧只留一个跨域握手），减少 clk_sys 的新增负载（H4/H7）
- 或退一步：**降低刷新率**（帧 RAM 每 N 帧更新一次）⇒ 画面在 N 帧内静止，残影重合，
  代价是"跳着更新"；改动比触发窗口更小（约 +3 行）

### D6 工程层面的选项（需要用户/甲拍板，⛔ 不是我能单方面决定）
- 接受"**0 违例但低于 3% 门槛**"的阶段版本（需项目方接受偏差）
- 重新审视 **3% 这个政策值**（它是 10-01 由 5% 改成的；⛔ 不能因为本版卡住就自行降低）
- 降 CLS 占用 / 换速度等级（AC2/I1）—— 后者与"实物是 AC1/I0"冲突，⛔ 不可取

## E.4 给后续的三条硬结论

1. **改 PnR 选项后必须删 `impl/` 才能还原**（见 E.2）—— 否则会静默用错配置，白跑构建。
