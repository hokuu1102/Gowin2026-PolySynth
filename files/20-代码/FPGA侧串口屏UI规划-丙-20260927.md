## 〇、🔴 先厘清：这是【第三条】串口通路，别和另两条混

项目里现在有**三条物理上独立**的串口通路，本规划只管**第三条**：

| # | 通路 | 走哪 | RTL | 谁管 |
|---|---|---|---|---|
| 1 | 标定命令（`'T'`/`'S'`/`'X'`） | PC ──USB-TTL──> FPGA | `calib_cmd.v` | 甲 |
| 2 | 曲谱事件帧（`0xA5`） | ESP32 ──UART──> FPGA | `evt_uart_rx.v` | 甲 |
| **3** | ⭐ **串口屏（TJC 文本指令）** | **屏 ──UART──> FPGA（D14/D15）** | ⭐ **`uart_ui.v`** | ⭐ **丙** |

> ⛔ **别把本规划和 `esp32/串口屏控件清单.md` 搞混**：
> 那份是 **ESP32 通路（BLE 曲谱下载）** 用的 **TJC3224（2.0 寸 320×240）**，
> 走 **ESP32 的 UART2（GPIO4/GPIO5）**，显示「下载进度/蓝牙状态」。
> 本规划是 **FPGA 直接驱动的屏**（走 FPGA 的 D14/D15），显示「演奏控制/Test Mode」。

## 一、⭐ 屏的硬件规格（⚠️ 尚未闭环，先按此规划）

| 项 | 值 | ⚠️ 状态 |
|---|---|---|
| 型号 | 淘晶驰 **TJC X2 7 寸**（决议清单 §九-3 评估对象） | 🟡 硬件选型表 I1 写的是「6 寸」，**尺寸未最终钉死** |
| 分辨率 | **1024 × 600**（7 寸规格） | 🟡 若换 6 寸则坐标需重算 |
| 串口电平 | 3.3 V / 5 V TTL | 🔴 **待核实**（选型表 I1） |
| 波特率 | 默认 **115200**；画波形可考虑 **921600** | 🟡 最高波特率待核实（决议清单 §九-3 ④-1） |
| 供电 | 屏要 **5 V**（⛔ 不是 3.3 V） | ✅ 已核实（控件清单 §七） |

> ⭐ **本规划不纠结像素坐标**——型号/分辨率没钉死，坐标算了也白算。
> 核心价值是**「控件语义 + ID 映射 + 指令契约」**这一层，它们与 RTL 一一对应、
> 且不随分辨率变化。坐标等型号定了再补（照本表 ID 拖控件，坐标以不重叠为准）。

## 二、⭐⭐ 控件清单（⭐ 4 个交互控件 + 1 个状态回显，ID 必须严格照填）

> 🔴 **`ID` 是 RTL 解析的关键**——`uart_ui.v` 按 `body_q`（= 控件 ID）落地控制量，
> ⛔ **ID 不对就收不到**。ID 约定见 §三。

### 2.1 交互控件（屏 → FPGA，触发触摸返回 `0x65`）

| # | ⭐ **控件 ID** | 类型 | ⭐ 对应 RTL 输出 | 说明 |
|---|---|---|---|---|
| **1** | ⭐ **`0`** | 双态按钮 / 单选框 | ⭐ `mode_o`（翻转） | ⭐ **模式切换**：指板 ↔ 钢琴（决议清单 §B 第 7 项） |
| **2** | ⭐ **`2`** | 按钮（循环） | ⭐ `test_mode_o` / `test_mode_n_o` | ⭐ **Test Mode 切档**：关→4→8→16→32→关（A1） |
| **3** | ⭐ **`1`**（数值变量） | 下拉框 / 数字控件 / 滑块 | ⭐ `base_semi_o` | ⭐ **起始音选择**（§B 第 8 项，⚠️ 八度级） |

> ⚠️ **为什么 ID 是 0 / 2 / 1 而不是 0 / 1 / 2**：
> 触摸控件用 **`0`（模式）** 和 **`2`（Test Mode）**；起始音走的是**数值变量返回**
> （`0x71`，变量序号 = `1`），不是触摸控件。这是 RTL 里已经定死的约定，
> ⛔ **屏侧必须照这个 ID 填**。

### 2.2 状态回显控件（FPGA → 屏，`uart_ui` 握手后回写）

| 控件 | 类型 | ⭐ 回写什么 | 指令 |
|---|---|---|---|
| 模式指示 | 文本 | `指板` / `钢琴` | `t0.txt="钢琴"` |
| Test Mode 档位 | 文本 | `关` / `4` / `8` / `16` / `32` | `t1.txt="8"` |
| 起始音 | 文本 | `C4` / `C5` / … | `t2.txt="C5"` |

> ⚠️ **状态回显是「下一版」的事**：`uart_ui.v` 当前**只做了下行解析**（屏→FPGA），
> 上行回写（FPGA→屏）只留了 `tx_start_o`/`tx_data_o` 接口，**回显内容还没实现**。
> 见 §五「下一步」。

## 三、⭐⭐ ID 映射表（RTL 与屏的契约，⛔ 不可改）

`uart_ui.v` 的返回解析逻辑（`RET_TOUCH`=0x65 / `RET_NUM`=0x71）：

| ⭐ 屏侧控件 | 返回码 | `body_q`（= 变量序号/控件 ID） | ⭐ RTL 动作 |
|---|---|---|---|
| 触摸控件 **ID=0** | `0x65` | `0` | `mode_o <= ~mode_o` + `mode_commit_o` |
| 触摸控件 **ID=2** | `0x65` | `2` | Test Mode 切档 + `test_mode_commit_o` |
| 数值变量 **序号=1** | `0x71` | `1` | `base_semi_o <= {1'b0, val_q[7:1]}` + `base_commit_o` |
| 系统启动 | `0x88` | —（无帧体） | `hb_ready_o <= 1` |

> ⚠️ **起始音的值语义**：`base_semi_o` 是**八度级**（每 12 半音），
> 但 RTL 现在写的是 `{1'b0, val_q[7:1]}`（= `val_q >> 1`，**除以 2**）。
> 🔴 **这是 RTL 的一个待精修点**：除以 2 ≠ 除以 12。
> 屏侧先按「发八度偏移值」准备（如 `val=24` 表示高 2 个八度），
> RTL 的「÷12 取整」修正见 §五-2。

## 四、⭐⭐ 指令契约（照这个发/收）

### 4.1 屏 → FPGA（`uart_ui` 解析的返回帧）

统一以 `0xFF 0xFF 0xFF` 结尾。`uart_ui` 只认这几种返回码：

| 返回码 | 含义 | 帧体 |
|---|---|---|
| `0x65` | 控件点击（触摸） | 控件 ID（`body_q`） |
| `0x71` | 数值变量返回 | 变量序号 + 数值 |
| `0x88` | 系统启动成功 | 无（握手） |
| 其他（`0x66`/`0x67`/`0x70`…） | 忽略 | — |

### 4.2 FPGA → 屏（回写，⚠️ 尚未实现，见 §五）

| 时机 | 指令 | 屏上效果 |
|---|---|---|
| 握手后 | `t0.txt="钢琴"` | 模式指示 |
| Test Mode 切档后 | `t1.txt="8"` | 档位指示 |
| 起始音落地后 | `t2.txt="C5"` | 起始音指示 |

> ⭐ 上电顺序（官方要求，⛔ 别省）：屏上电 → 屏发 `0x88` → 发 `00 FF FF FF` 清缓冲 → 发正式指令。
