# FPGA 线：LED 挂灯的上游缺口（必须 ESP32 配合，RTL 只能兜底）2026-10-16

> 收件人：ESP32 线
> 来源：我方只读审查队实证（`审灯 LAMPAUDIT`）
> 结论：**这条 RTL 侧无法根治，必须你们在帧里补一个字段**。我方同时在 RTL 侧做兜底，但兜底不能替代正确数据。

---

## 一、现象（用户实测）

```
1. "没有灌谱的时候，键盘上的 LED 也在闪"
2. "闪的那颗，复位之后就不闪了"
3. "按住那颗会变常亮"
```

三句被同一行代码解释。

## 二、根因（带行号，全部可复核）

```
guide_lamp.v:316-343    guide_key_o 只有两条清除路径：note_off(key_valid) 和 rst_n
                        ⭐ 没有超时、没有引用计数、没有"停播即清"
led_data.v:73/79        blink_keys = guide_key_i & ~key_active_i
                        key_pattern[ki] = key_active_i[ki] | (blink_keys[ki] & blink_i)
top.v:2496-2502         led_blink = 125ms 方波（bg_beat 派生，与 BPM 同步）
```

**致命的组合 —— `note_off` 帧不带音高**：

```
note_on  帧  bit[4:0] = 真实音高偏移（如 A3）
note_off 帧  bit[4:0] = 0            ← ⚠️ 三个工具【全都不写】
```

⇒ `guide_lamp` 的 ON/OFF 共用同一套 `key_sel` 推导（`:329/:336`），但它只保证"**同一条 `note_off5` 下** ON/OFF 指向同一盏灯"，⛔ **不保证不同事件的 `note_off5` 相同**。

⇒ **ON 点的是"A3 对应的那盏"，OFF 灭的是"A2 对应的那盏（或哨兵，哨兵则完全不清）"** ⇒ 灯永不熄。

⇒ 残留位跟着 `led_blink`（125 ms 方波）一直闪 ⇒ **没灌谱也闪**。
⇒ 复位清 `guide_key_o` ⇒ **复位后不闪** ✓
⇒ 按住那颗 ⇒ `key_active_i` 优先级最高 ⇒ **常亮** ✓（这条是对的，不是 bug）

## 三、要你们改的三处（缺一不可）

| # | 文件 | 改什么 |
|---|---|---|
| 1 | `esp32/tools/mid2evt.py:502` | `note_off` 帧的 `bit[4:0]` 填**与配对 `note_on` 逐字节相同**的 `note_off5`（现在恒 0） |
| 2 | `esp32/tools/score_word.py:121` | 位域定义/打包：`note_off` 也要带 `note_off5`（现在只给 `note_on`） |
| 3 | `esp32/ble/main/pool.c:724` | ⚠️ **flush 补发的 off 帧** —— 它从 `open_inc[j]` 能反算出音高，请把对应 `note_off5` 写回去（现在也写 0） |

⚠️ **第 3 处最容易漏**：flush 是"掉电/切换时补发所有未关闭的音"，如果它写 0，那这条补发的 OFF **永远灭不掉灯**。

## 四、我方同时在做的兜底（⛔ 不能替代正确数据）

```
给 guide_key_o 加"停播即清"超时（曲谱事件流停了 ~1 秒就整片清零）
=> 能治"没灌谱也闪"（因为停了会清）
=> 但【治不了】"正在播的曲子里，某些灯该熄没熄"（因为流没停）
```

⛔ **所以兜底只是止血，根治必须靠你们把 `note_off5` 补上。**

## 五、验收口径（你们改完，我方验）

```
1. 你们产出的 events.hex 里，逐条核对：
   ⭐ 每个 note_off 的 bit[4:0] == 它配对的那个 note_on 的 bit[4:0]
   （⭐ 建议直接写个断言，跟 check_drum_split.py 一个套路）
2. 上板看：曲谱播完后（transport 停），键盘 LED 应该【全灭】
   （现在是"全灭 + 若干颗残留闪"）
3. 灌一份含同轴和弦的谱：和弦期间那颗灯应保持亮，和弦结束才熄
```
