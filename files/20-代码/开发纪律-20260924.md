## ✦ 先说一件事：⭐⭐ **为什么同一个坑会反复踩**（⭐ 值得所有人看）

⭐ **2026-09-24，用户问：** *"写经验，怎么老是遇到这个编码问题，之前也是 PowerShell 编码有问题"*
⇒ ⭐ 我查证后发现 —— 🔴 **问题不在"没记"，而在【规则被写成了描述】**：

| ⭐ 位置 | ⭐ 说法 | ⚠️ 性质 |
|---|---|---|
| ⭐ **经验库**（⭐ 2026-09-17） | ⭐ **"带中文的 `.ps1` 【必须】UTF-8 with BOM"** | ✅ **要求**（⭐ 正确） |
| ⭐ **项目 K 清单**（⭐ `K-55`） | ⭐ **"编辑 `sim/*.ps1` 后【必须复查 BOM】"** | ✅ **要求**（⭐ 正确） |
| 🔴 **另一处项目文档** | 🔴 **"`mutation_test.ps1` 是【无 BOM 的 UTF-8】，而 PS 5.1 按 GBK 解码它"** | 🔴 **描述**（⭐ **把缺陷当成事实接受了**） |

⭐⭐ **关键区别**：
```
✅ 要求写法：⭐ "脚本【必须】带 BOM"
🔴 描述写法：⭐ "脚本是【无 BOM】的，所以 PS 5.1 按 GBK 解，所以……"
                ↑ ⚠️ 读的人会认为"这是环境特性，只能适应它"
                ⇒ 🔴 于是所有人都在"适应"，⛔ 没人去修根因
```

⇒ ⭐⭐ **这就是反复踩坑的机制：⭐ 不是"忘了"，⭐ 而是"规则被降级成了描述"。**

### ⭐⭐ 三条可迁移的教训

| # | ⭐ |
|---|---|
| **1** | ⭐⭐ **"必须 X" 和 "现在是 X" 要分得清** —— ⚠️ 前者是可执行规则，⭐ 后者只是观察<br>🔴 一旦把缺陷写成"现状描述"，⭐ **它就会被当成不可改变的环境** |
| **2** | ⭐⭐ **同一件事出现【多条规则】时，必须检查它们是否【冲突】** |
| **3** | ⭐⭐ **复发 = 规则失效的信号** —— ⚠️ 此时**补一条新经验是【没用的】**，<br>🔴 **必须去找"为什么旧经验没起作用"** |

📌 **所以以后看到"这个问题又出现了"** ⇒ ⭐ **先问三句**：
```
① 有没有规则？   ② 规则之间冲突吗？   ③ 规则是"要求"还是"描述"？
```

## 一、🔴🔴 `.ps1` 必须 UTF-8 with BOM

### 1.1 ⭐ 规则

```
⭐ 所有 .ps1：带 UTF-8 BOM（EF BB BF），⭐ 或者【全文纯 ASCII】。
🔴 判据：非 ASCII 字节 > 0 且 无 BOM ⇒ FAIL
```

### 1.2 🔴 为什么（⭐ 两种失败模式）

| # | ⭐ 模式 | ⚠️ 症状 | ⭐ 能否发现 |
|---|---|---|---|
| **1** | ⭐ **语法错** | ⚠️ PS 5.1 按 **GBK** 解码无 BOM 的 UTF-8 ⇒ 中文变乱码 ⇒ ⚠️ **报错行与真因无关** | ✅ **能**（⭐ 报错） |
| **2** | 🔴 **静默丢元素** | 🔴 **非 ASCII 序列吃掉后面的【换行】** ⇒ ⚠️ 注释与下一行**合并**<br>⇒ 🔴 **若下一行是数组元素 `@{...}` ⇒ 它【消失】** | 🔴 **不能**（⭐ **零报错、零警告**） |

📌 **实测（2026-09-24）**：
```
⭐ 变异体 catalogue 写了 107 个
🔴 脚本实际只读到 105 个
⇒ ⚠️ -Filter M98 报 "matched 0 mutants"（⭐ 而 M98 就写在文件里）
⇒ ⭐ 被吞的是 M98 和 M62 —— 它们【上方都有中文注释】
⭐ 判据：GBK 解码行数 ≠ UTF-8 行数 ⇒ 就有换行被吃
```

⭐⭐ **同一根因，后果升级了**：⭐ **从"报错"（能发现）⇒ 🔴 "静默少东西"（发现不了）**
⇒ ⭐⭐ **所以：报错反而是好事 —— 最怕的是它不报错。**

### 1.3 ✅ 机械检查

```bash
# ⭐ 检查（exit 0 = 通过）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\check_ps1_encoding.ps1

# ⭐ 修（⭐ 先干跑看一眼，⭐ 加 -Apply 才真改）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\add_ps1_bom.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools\add_ps1_bom.ps1 -Apply
```

### 1.4 ⚠️ 另一条：编辑 `.ps1` 后要复查 BOM

⚠️ **编辑工具会【静默剥掉】BOM**（⭐ `K-55` 实测）
⇒ ⭐ **改完 `.ps1` 一定要跑一次检查脚本**。

## 二、🔴 变异体锚点必须纯 ASCII

### 2.1 ⭐ 规则

⭐ **`bringup/mutation_test.ps1` 里每条 `@{ id=; file=; find=; repl=; why= }`**：
```
🔴 find / repl 【只含纯 ASCII】（⛔ 尾部中文注释删掉）
🔴 find 在目标文件里必须【唯一】
```

### 2.2 ⚠️ 为什么

⭐ **锚点要与 `rtl/` 源码逐字符相等** —— ⚠️ 而**脚本按 GBK 解、源码按 UTF-8 读**
⇒ 🔴 **两者永不相等 ⇒ `Contains` 为假 ⇒ 该变异体 `SKIP`**（⭐ **静默失去保护**）。

📌 **实测（`M85`）**：
```
find = "gain_r <= {GAIN_W{1'b0}};    // 复位静音（安全态）"
                                     └─ 27 个非 ASCII 字节 ⇒ SKIP
⭐ 而手动验证 ReadAllText(...).Contains(find) 竟然 = True
⇒ ⚠️ 极易误判成"锚点过时"，实际是【编码】
```

### 2.3 ✅ 判别法（⭐ 一步）

```powershell
$b = [Text.Encoding]::UTF8.GetBytes($find); ($b | ? {$_ -gt 127}).Count   # >0 ⇒ 就是这条
```

### 2.4 ⚠️⚠️ 两个"SIP"长得一样，根因可能完全不同

| 变异体 | ⭐ 真因 | ⭐ 判别 |
|---|---|---|
| `M40` | ⚠️ **真·锚点过时**（⭐ 信号改名 `mx_*` → `mm_*`） | `Contains` ⇒ **False** |
| `M85` | 🔴 **编码**（⭐ 锚点含中文） | `Contains` ⇒ ⚠️ **True（矛盾！）** |

⇒ ⭐ **必须逐个查，⛔ 不能一起下结论**。

## 三、🔴 编辑 `.md`/源码：⛔ 不用"读文本+写文本"整体重写

🔴 **`[System.IO.File]::ReadAllLines()`/`ReadAllText()` + `WriteAllLines()`/`WriteAllText()`
会把行尾重写（LF → CRLF）** ⇒ ⚠️ **整个文件每行都被标记为改动**。

```
⚠️ 实测（K 清单）：⭐ 只加 2 行 ⇒ 🔴 193 insertions / 184 deletions
✅ 换成文本 Replace + 手动拼 LF ⇒ ✅ 2 insertions / 0 deletions
```

✅ **正确做法**：
1. ⭐ **用编辑器/工具按【字面替换】**（⭐ 最稳）
2. ⭐ **文本 `Replace`**：先探出行尾，⭐ 替换后**手动用同种行尾拼**
3. ⚠️ 真要重写 ⇒ ⭐ **改完立刻 `git diff --numstat` 核对**（🔴 增删数对不上就是踩了）

📌 **本仓库文件是【LF】**（⭐ 不是 CRLF）。

## 四、⭐ Verilog：声明必须先于使用

⚠️ **`implicit definition of wire` 只是【warning】** ⇒ 🔴 **多位信号会被静默截断成 1 位**。

```
⭐ 判据：把这warning【当错误处理】—— 看到就修，⛔ 不要"反正能编译"
📌 与 `K-91`（Verilog-2001）配合看：Gowin 按 Verilog-2001 编译
   ⇒ ⚠️ SV 独有构造会被【静默丢弃整个模块】，而 iverilog 全绿
```

## 五、🔴🔴 跨模块"组合选择/组合使能"必须打一拍

### 5.1 ⭐ 规则

```
🔴 顶层里凡是 `sel = busy_a ? x : y` 这类【纯组合选择】
⇒ ⭐ 必须问一句："它驱动的模块，会不会通过任何路径影响它的选择条件？"
⇒ ⚠️ 答"可能" ⇒ 🔴 打一拍（用寄存器版），⛔ 不要赌
```

### 5.2 🔴 为什么（⭐ 实测事故）

```verilog
// ⭐ 改前（看起来完全无害）
wire [2:0] cal_ch_mux = sp_busy ? sp_ch : at_ch;
//                       ⚠️ sp_busy 是 calib_span 的组合输出

// 🔴 环：
//   cal_ch_mux → calib.cal_ch → 采集通路 → calib_span.busy_o → cal_ch_mux
⇒ 🔴 iverilog 在【时间 0】反复求值 ⇒ 不收敛 ⇒ 仿真挂死
```

⚠️ **症状极具迷惑性**：
```
🔴 tb 日志仅 84 字节（连一行 PARAM_OK 都没打）
🔴 tb 自带的 200 ms 仿真看门狗【无效】（⭐ 仿真时间不推进）
🔴 tb_all.ps1 报 120 s 超时
```

### 5.3 ⚠️ 三条必记

| # | ⭐ |
|---|---|
| **1** | ⭐⭐ **"模块的 tb 全过" ⛔ 不等于 "接进顶层没问题"** —— ⚠️ **组合环只在【跨模块回路】里成立**<br>📌 本模块的独立 tb 用**常量输入** ⇒ ⭐ **永不形成回路** |
| **2** | 🔴 **`iverilog` 编译【零 error】** ⇒ ⚠️ **"编译过了" ⛔ 不是"没有环"** |
| **3** | ⚠️ **提交时那个 tb 的证据显示 PASS** ⇒ 🔴 **可能是【更早一次】的日志** |

### 5.4 ⭐⭐ 定位方法：三分实验法（⭐ 可复制）

| 实验 | ⭐ 做法 | ⭐ 判据 |
|---|---|---|
| **0** | ⭐ **`git worktree` 检出【旧版本】跑同一个 tb** | ⭐ **旧版 PASS / 新版挂** ⇒ ✅ **确认"新引入"**（⚠️ **⛔ 别先怀疑环境**） |
| **A** | ⭐ 把某模块的**输入接常量** | ⭐ **若解挂** ⇒ 它**参与**了环 |
| **B** | ⭐ 恢复输入，**改掉那个组合选择** | ⭐ **若解挂** ⇒ ⭐⭐ **元凶锁定** |

⚠️ **所有实验都在 `git worktree` 里做** ⇒ ⭐ **主仓库零污染**。

## 六、⭐⭐ 引用 `rtl/` 源码：写【符号名】，⛔ 不写行号

### 6.1 ⭐ 规则

| # | ⭐ 要求 |
|---|---|
| **1** | ⭐⭐ **引用 `rtl/` 源码时 ⛔ 不写行号，写【符号名】** —— `parameter`/`localparam` 名 · `assign` 名 · `module` 名 · 状态名 · 端口名 · 寄存器名 |
| **2** | ⭐ **写法**：⭐ `见 `LIM_TH_W`（`tdm_render_mixer.v`）` · ⭐ `见 `pool_mask` 的 `assign`（`note_manager.v`）` |
| **3** | 🔴 **例外（⛔ 不改）**：⭐ 引用**带日期的历史快照**时**保留当时的行号**，并在文中标注 **"（当时快照）"** |
| **4** | ⚠️ **例外（找不到单一符号）**：⭐ 若某处指的是"**一整段 / 一张表**"、找不到单一符号 ⇒ ⭐ **保留行号**，并在其后加 **`（行号可能漂移，以符号为准）`** |
| **4a** | ✅ **例外之例外（文件头注释）**：⭐ 若目标是**文件头注释**（⭐ 它**天然钉在文件顶部**、⛔ 不会漂）⇒ ⭐ 直接锚成 **``X.v` 的文件头注释`**，⛔ **不必保留行号、也不必加括注**（⭐ 实测已按此处理 `wavetable_bank.v:2/:3`、`note_manager.v:20`） |
| **5** | ⚠️ **超长行（1~3 KB 的表格行）的编辑手法**：⭐ `old_string` 取**该行内唯一的一段**（⭐ 覆盖要改的引用 ＋ 前后足够上下文）⇒ ⭐ **⛔ 不必整行复写**（⭐ 对 1~3 KB 的行整行复写反而有转写误差风险）。⭐ **判据**：⭐ `git diff --numstat` **增 == 删** ＋ ⭐ 回读确认该行**仍以 `|` 开头结尾**（⭐ 实测 32/32、36/36 通过） |
| **6** | ⚠️ **裸 `:NNN`（同行/邻近已指明文件名）**：⭐ 同样要锚点化 ⇒ 换成 `` `文件名` 的 `符号` ``；⭐ 若上下文不足以唯一确定目标 ⇒ **保留 + 登记**，⛔ 不猜 |

⭐ **哪些算"历史快照"**（⭐ 机械判据）：⭐ **文件名带 `YYYYMMDD` 且属于「审计 / 通知 / 清单 / 交接」类** ——
⭐ 例：`*审计-<YYYYMMDD>.md` · `待发通知-*` · `进度核对*` · `缺口总清单*` · `交接*` · `files/历史/**`。
⭐ 它们记的是**当时的**行号 ⇒ ⚠️ **行号过时是【预期】的，⛔ 不是缺陷** ⇒ 🔴 **改它等于篡改快照**。

### 6.2 🔴 为什么（⭐ 本项目已两次踩到）

| ⭐ 事故 | ⭐ 事实 |
|---|---|
| **① `top.v` 整体偏移 +4** | ⭐ 在 `top.v` 里插入注释 ⇒ ⭐ **其后所有行的行号 +4** ⇒ 🔴 **文档里所有 `top.v:NNNN` 一次性全部作废** |
| **② 本轮 ~26 处因插入注释而漂** | ⭐ `note_manager.v` **16 处** · `tdm_render_mixer.v` **5 处** · `oscillator_bank.v` **5 处** —— ⚠️ 全是"注释一插就漂" |

⭐ **根因**：⭐ **行号是【派生量】**（⭐ 它随"插了几行注释"变化）⇒ 🔴 **任何按行号写的引用都是迟早会失效的引用**。
⭐ 而 **符号名是【契约】** —— ⭐ 改名会被**编译器 / 工具**抓到；⚠️ **行号漂移没有任何东西会报警**。

### 6.3 ✅ 机械检查（⭐ 别靠记）

```powershell
# ① 本次改动里有没有"新写的 rtl 行号引用"（⭐ 期望：0 条 ⇒ 无输出）
git diff -U0 -- 'files/' 'rtl/' | Select-String -Pattern '^\+.*[A-Za-z0-9_]\.(v|sv):[0-9]+'

# ② 存量盘点（⚠️ 会列出历史遗留与快照里的行号）
#    ⭐ 判据是"【新增行】里 ⛔ 不许再有"，⛔ 不是"存量必须为 0"
git grep -n -E '[A-Za-z0-9_]+\.(v|sv):[0-9]+' -- files rtl
```

> 📌 **口径来源**：⭐ **用户 2026-10-01 拍板** —— ⭐ **走结构修法：以后引用 `rtl/` 一律用【符号锚点】，⛔ 不写行号**。
