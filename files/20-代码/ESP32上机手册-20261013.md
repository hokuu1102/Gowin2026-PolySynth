## 〇、先回答两个问题

### 0.1 这块板是"完全板"吗？

**硬件层面：是。** ESP32-S3-WROOM-1 **N16R8**（16 MB Flash + 8 MB PSRAM），
三路 UART 全部实装，全部已实测跑通。

| 外设 | 引脚 | 参数 | 状态 |
|---|---|---|---|
| UART0（日志） | TX `GPIO43` / RX `GPIO44` | 115200 | 实测通 |
| UART1（→ FPGA） | TX `GPIO17` / RX `GPIO18` | 500000 | 实测通（字节级已验证） |
| UART2（→ 串口屏） | TX `GPIO4` / RX `GPIO5` | 115200 | 实测通（6 栏全部跟随） |
| BLE | 板载 | GATT `0xABF0`~`0xABF4` | 实测通（含断连重连） |
| WS2812 | `GPIO48` | **关闭** | 见 0.3 |
| 起播按键 | `GPIO6` | 当前**未启用** | 见 0.2 |

### 0.2 能做 FPGA 联调吗？

**下行（ESP32 → FPGA）能，上行（FPGA → ESP32）还差 FPGA 侧两项。**

| 方向 | 状态 | 卡在哪 |
|---|---|---|
| **下行**：PC 灌谱 → ESP32 池 → UART1 → FPGA | 我方全部就绪 | 卡 `G21`/`G22` **引脚未分配**（FPGA 侧 `PMOD0`）⇒ 电气上还没接 |
| **上行**：FPGA → ESP32 → PC → MIDI | 我方全部就绪 | FPGA 侧**未实现 14 B 实时事件帧**（现在只发 9 B 回传帧） |
| 上行时间轴 | 代码就绪 | `tick` **单位未裁定**（两份 FPGA 文档冲突，见 §五） |

这两条**不是我方的缺口**。FPGA 侧 `上板验证清单-20261013.md` §三 也写明：

> "所以这条现在【验不通】—— 是**已知的协议缺口**，不是坏了"

### 0.3 安全默认（动手前必须知道）

| 项 | 值 | 为什么 |
|---|---|---|
| WS2812 | `WS2812_ENABLE = 0` | 板载灯有锁存，能扛过重启。**保持关闭** |
| 起播触发 | `BLE_START_TRIG_SERIAL` | 串口发 `S`/`X`/`R` 触发，**不是**板载 BOOT 键 |
| 模式 | `BLE_MODE_B_POOL` | 池模式（不是直通） |

## 三、上位机使用（三个页面 + 一个 Python 版）

### 3.1 怎么启动

**必须走本地服务器**，不能双击 HTML 打开：

```
双击  esp32\tools\start_score_studio.bat
```

| 为什么 | 说明 |
|---|---|
| Web Bluetooth 要求**安全上下文** | `http://127.0.0.1` 是安全的，`file://` **不是** |
| 直接双击 | Chrome/Edge 会拒绝 `navigator.bluetooth` |

`.bat` 会做三件事：在 `127.0.0.1:8777` 起 `python -m http.server` → 等 2 秒 → 打开浏览器。
**停止**：关掉那个最小化的 `[ScoreStudioServer]` 窗口。

三个页面都在同一台服务器上：

| 页面 | 地址 | 用途 |
|---|---|---|
| 曲谱上位机 | `http://127.0.0.1:8777/score_studio.html` | 灌谱 + 起播 |
| 回传可视化 | `http://127.0.0.1:8777/upstream_studio.html` | 看 FPGA 回传的事件 |
| 链路自检 | `http://127.0.0.1:8777/link_test.html` | 六步自检 |

### 3.2 曲谱上位机（`score_studio.html`）

**用途**：把曲谱灌进 ESP32 的池，然后起播。

| 区域 | 内容 |
|---|---|
| 钢琴卷帘 | 按轴着色 / 变速虚线带（含 BPM）/ 八度参考线 / 悬停读数 |
| 统计 | 事件数、时长、音域 |
| 上传 | 进度与速率 |
| 控制 | 起播 / 停止 / 清池 |
| 状态 | 实时读 `0xABF4` |
| 日志 | 每步操作与回包 |

**操作顺序**（顺序错了会失败）：

1. 点「连接」→ 选 `FPGA2026-Synth`（**只能开一个页面**，见 3.5）
2. 点「清池」→ 确认 `pool=0`
3. 点「上传」→ 等进度到 100%
4. 点「起播」→ 观察「已喂帧」开始涨

**判据**：`pool` 从 0 涨到谱面事件数；`run=运行中`；屏上显示「播放中」。

`?demo=` 参数可以自动加载内置音阶，用于快速验通路。

### 3.3 回传可视化（`upstream_studio.html`）

**用途**：订阅 `0xABF2`，把 FPGA 回传的事件画成滚动卷帘，可导出 `.mid` / `.bin`。

**注意**：它需要 ESP32 真的收到 FPGA 的回传。目前 FPGA 侧**还没实现 14 B 事件帧**
⇒ 这一个页面现在**看不到真数据**。可以用「PC 当 FPGA」的方式验通路（见 §四）。

### 3.4 链路自检（`link_test.html`）

六步，每步一个判据：

```
BLE 连接 → 读 STAT → 下行 → 起播 → 上行 → 屏
```

**用途**：出问题时先跑它，能一次定位到是哪一段断了。

### 3.5 Python 版（`score_uploader.py`）

```powershell
cd esp32\tools
python score_uploader.py
```

单文件 tkinter GUI，**不需要浏览器**。

**什么时候用它**：浏览器不方便时（例如要脚本化、或 Web Bluetooth 被策略挡了）。

### 3.6 三个必须知道的限制

| # | 限制 | 后果 |
|---|---|---|
| 1 | **网页与 Python 工具不能同时用** | 两者都要独占 BLE。同时开会造成「僵尸连接」：`mtu=517 / CONN` 但 `ble_rx=0`，板子停止广播，所有工具连不上。**关掉网页后几秒内恢复** |
| 2 | **一个浏览器只能开一个页面** | 同上，两个页面抢 BLE |
| 3 | **CH340 只能一个读者** | 串口独占，两个工具同时开同一个口会失败 |

## 四、不用 FPGA 也能验的（PC 当 FPGA）

FPGA 侧到位之前，可以用 CH340 冒充 FPGA，把两条链都验一遍。

### 4.1 下行字节级校验

```powershell
cd esp32\tools
# 先把 CH340 的实际端口查出来（不要照抄下面的 COM24）
python -c "import sys;sys.path.insert(0,'.');from run_all_tests import find_port,VID_CH340;print(find_port(VID_CH340))"
python _uart1_wire_check.py --port <上一步输出的口> --events 200 --seconds 25
```

**判据**：`前 200 帧载荷【逐字节一致】`

它证明的是：ESP32 的 UART1 出口，**线上字节与灌进去的 events 完全一致**
（不是只看 `sent` 计数）。

注意 `--seconds` 是**抓取窗口**，不是谱面时长：

| 值 | 实测结果 |
|---|---|
| `20` | 偶发 `帧数 194 != 期望 200`（**窗口偏短，不是真丢帧**） |
| `25` | 连跑 3 次全为 `200.00 帧`，逐字节一致 |

`--seconds` 偏短时，最后几帧还在路上就被判成"少了"。
**看到"差几帧"先加时间重跑**，不要直接当成丢帧。

### 4.2 上行闭环校验

```powershell
python _upstream_loop_check.py --port <CH340 口> --n 300 --seconds 18
```

**判据**：`上行 301 帧 / 4282 字节【逐字节一致】`

### 4.3 MIDI 回传端到端（离线，不需要任何硬件）

```powershell
python demo_midi_roundtrip.py
```

**判据**：音符号序列 = C 大调上下行 · 音符时刻与谱面**逐点一致** · 时长 3.75 秒

产物：`esp32\evidence\MIDI回传演示-C大调音阶-20261013.mid`（可直接播放）

## 五、全量测试

```powershell
cd esp32\tools
python run_all_tests.py        # 全量（离线 + 真机）
python run_all_tests.py --selftest   # 只验执行器自己
```

**输出**：汇总表 + `合计 N 项：通过 x · 失败 y · 前置 z`，**退出码 = 失败项数**。

三种结果的含义：

| 结果 | 含义 |
|---|---|
| `通过` | 判据关键字出现且退出码 0 |
| `失败` | 退出码非 0 或判据关键字缺失 |
| `前置` | **依赖没满足**（例如需要冷启动），**不是失败** |

真机项是**串行**的（BLE / 串口独占），跑一轮约 6 分钟。

## 六、故障速查

| 现象 | 先查什么 |
|---|---|
| 所有工具都连不上 BLE | 是不是有网页占着？（见 3.6）关掉网页等几秒 |
| 某个工具报「前 0 帧」 | **接线**（GND 共地 / TX-RX 交叉）· 端口选错（用 `find_port`） |
| `esptool` 报 `FileNotFoundError` | **设备掉了**，重新插 USB（⛔ 不是端口名错） |
| `esptool` 报「拒绝访问」 | 端口**被占用**，找占用进程 |
| 读 `0xABF4` 少一组 | **容量被撑爆导致截断**，见交接文档 |
| 屏上数字不变 | 屏的回包**不走 BLE**，只在串口日志里 |
| 起播约 20 秒后重启 | 已修（BTC 任务栈）。若复发查 `up=` 是否归零 |

### 6.1 别做的事

| 禁止 | 原因 |
|---|---|
| `Get-Process python \| Stop-Process -Force` | 会误伤持有串口句柄的工具，**实测触发 USB 掉线**；也会杀掉 HTTP 服务器。按 PID 精确杀 |
| 杀浏览器进程 | 用户的 Edge 与 agent 开的窗口**共用进程**（会丢用户的标签页）。只关 agent 自己开的窗口 |
| 在网页开着时跑 Python 工具 | 见 3.6 |

## 九、与 FPGA 侧的接口约定

| 项 | 值 |
|---|---|
| 下行帧 | 9 B（`0xA5` + 8 B 大端事件字） |
| 上行帧 | v1.1：14 B（`0xA5` + 类型 + seq + tick + axis + phase_inc + vel + 校验） |
| 事件字位域 | `tick[63:44]` `inc[43:23]` `axis[22:19]` `vel[18:11]` `kind[10:9]` `timbre[8:7]` |
| 上行类型码 | `0x01` note_on · `0x02` note_off · `0x03` calib · `0x04` looper · `0x05` transport_start · `0x10` tablesync |
| 校验 | XOR，覆盖除帧头外的全部字节 |
| `ppqn` | 960（由 `0x05` 锚点帧携带） |
| 波特率 | 500000 |

**两个待裁定项**：

| # | 问题 | 影响 |
|---|---|---|
| 1 | **`tick` 单位**：音乐 tick（PPQN 960）还是自由运行计数？两份 FPGA 文档冲突 | 决定 MIDI 时间换算 |
| 2 | 9 B 回传帧改 **11 B**（加类型码 `0x20` + 校验） | 决定回传能否被解析 |
