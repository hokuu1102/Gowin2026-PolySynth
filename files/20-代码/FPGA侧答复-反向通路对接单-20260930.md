### 7.2 ⭐⭐ 上行（FPGA → ESP32）内容约定

> ⭐ **关键设计决定**：⭐ **因为 ESP32 是【单独一路 UART】，⛔ 它不需要和 `J9` 那路争字符空间**
> ⇒ ⭐ **这一路可以有【自己的协议】**，⭐ **且可以更大胆**（⭐ 建议用**带帧头的帧**，⛔ 不用逐个 ASCII 字母 —— 理由见下）。

| # | 内容 | ⭐ 约定 |
|---|---|---|
| **①** | ⭐ **标定事件**（⭐ 已有信号，⭐ 只是现在发在 `J9`） | ⭐ **原样再发一份**：`t`/`s`/`x` · 轴号 `0`~`F` · `.` · `D` · `T` · **6 类原因码** `!`/`w`/`o`/`b`/`?`/`0`/`1`/`2`<br>⚠️ **已知坑（⭐ 必须写清）**：`0`/`1`/`2` **既是原因码又是轴号字符** ⇒ ⭐ **我们的解析纪律 = "拒绝字节总是紧跟在【一个轴号之后**】"（`top.v:2005`）⇒ ⭐ 请你们也按**位置**解析，⛔ 不按字母表 |
| **②** | ⭐ **looper / 事件回传**（⭐ 见 7.3） | ⭐ **建议用带帧头的帧**（⭐ 与你们下行的 `0xA5` 帧同构 ⇒ ⭐ **两端复用同一套解析思路**） |

**⭐ 为什么建议 ② 用帧、而不是继续用 ASCII 单字节流**（⭐ 三条理由）：

```
① ⭐ 上游是【真 UART】⇒ 字节边界天然保留 ⇒ ⛔ 不需要下行那条"9N 对齐"纪律（⭐ 同意你们 §4.4-1）
② ⭐ looper 事件带【数值】（轴号 / 力度 / 时刻 / 层号）⇒ ASCII 单字节装不下
   ⚠️ 而若硬塞进 ASCII，就必须再引入转义/分隔符 ⇒ 🔴 又把"字母冲突"问题引回来
③ ⭐ 单独一路 ⇒ ⛔ 不会与 J9 的调试判据冲突（⭐ 我们那套 `T0~T8` 判据读的是 J9）
```

|---|---|---|
| **Note On** `0x9n` | `note`(0–127) + **`velocity`(0–127)** | ⭐ **按下力度** |
| **Note Off** `0x8n` | `note` + **`release velocity`(0–127)** | ⭐ **松开力度**（⚠️ 多数设备写 0 或 64，**基本没人用**） |
| ⚠️ 特例 | `velocity = 0` 的 Note On **等价于 Note Off** | ⭐ 标准约定 |

⭐ **我们这边的料是够的**：`vel` 是 **8 位（0–255）** ⇒ ⭐ **÷2 缩放到 0–127**；
⭐⭐ 而 `looper` **连"本音峰值力度"都记着**（`vel_max_r`，⭐ 它把 `note_off` 的力度换成"本次按键的峰值"）
⇒ ⭐ **release velocity 那一栏我们也有真实值可填** ✅

### ⭐⭐ 为"逆向回 MIDI"设计的【上行帧约定草案】

⭐ **建议与你们下行的 `0xA5` 帧同构**（⭐ 两端复用同一套解析思路）：

```
⭐ 帧 = 【帧头 0xA5】【类型 1B】【载荷】【(可选)校验 1B】

类型 0x01  NOTE_ON   载荷: tick(4B) + axis(1B) + phase_inc(4B) + vel(1B)
类型 0x02  NOTE_OFF  载荷: tick(4B) + axis(1B) + phase_inc(4B) + vel(1B)   ← ⭐ vel = 本音峰值力度
类型 0x03  CALIB     载荷: 事件字节（t / s / x / T / . / D / 6 类原因码）
类型 0x04  LOOPER    载荷: 状态位 + 层号 + 事件数 + 溢出标志
```

| 字段 | ⭐ 为什么这么定 |
|---|---|
| ⭐ **`tick`（4B 自由运行计数器）** | ⭐ MIDI 需要 Δt ⇒ ⭐ PC 侧用相邻 `tick` 之差算 Δt，再映射到 tempo。⚠️ **`tick` 计数器是新增的**，⭐ 但它**极便宜**（一个 32 位计数器） |
| ⭐ **`phase_inc`（4B，⛔ 不是音符号）** | ⚠️ **对数在 FPGA 上太贵**（要 LUT/DSP ＋ 迭代）⇒ ⭐ **FPGA 只回传相位增量，⭐ 由 PC/ESP32 侧反算音符号**（`note = 69 + 12·log₂(f/440)`，⭐ `f = phase_inc × fs / 2³²`） |
| ⭐ **`axis`（1B）** | ⭐ 让 PC 侧知道"是哪个物理键" |
| ⚠️ **`axis → 音高` 是张表**（`axis_map.kb_inc[]`），⭐ **而且变调/换模式会改它** | ⭐ **要么 PC 侧硬编码同一张表，⭐ 要么约定一条"表同步"命令**（⭐ 我们建议后者，⛔ 否则两边表必然漂） |
| ⭐ **`vel`（1B）** | ⭐ 映射到 MIDI velocity（⭐ `/2`） |

### ✅ ⭐ 带宽够不够？⭐ **绰绰有余**（⭐ 这条是好消息）

```
⭐ 弹奏速率 ≈ 每秒 10~30 个事件（note_on + note_off）
⭐ 每帧 ≈ 12 字节 ⇒ ⭐ ≈ 360 B/s
⭐ 反向通路上限（你们 §2.3 给的）≈ 514 B / 10 ms ≈ 51 KB/s
⇒ ⭐ 占用不到 1% ⇒ ⭐ **MIDI 回传的带宽【不是问题】** ✅
⚠️ 唯一要小心的是：⭐ 若把 laper 重放的密集事件也全回传 ⇒ ⚠️ 才需要限速/摘要
```
