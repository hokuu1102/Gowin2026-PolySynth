## 一、⭐⭐ 为什么要加（⭐ 三个具体场景）

### `#1` 回显 —— ⭐ **解决"发错字符就什么都没有"**

```
🔴 现在：⭐ 只有【命令被受理】时才回字
⚠️ 所以你发错一个字符（⭐ 或波特率差一点）⇒ 🔴 什么都没有
🔴 而你分不清：
     · "没收到"（⭐ 线/波特率问题）
     · "收到了但不认识"（⭐ 发错了）
```

✅ **加 `#1` 之后**：⭐ **收到【任意】字节就回一个字符**
⇒ ⭐ **发任何东西都有回音** ⇒ ✅ **"链路通不通"一眼可判**。

### `#2` 上电 beacon —— ⭐ **不用发东西就知道 FPGA 活着**

```
⚠️ 现在：⭐ 必须【你先发】才有回音
🔴 若板子没起来 / 串口没接好 ⇒ ⚠️ 沉默 ⇒ 你分不清是"板子死"还是"线没接"
```

✅ **加 `#2` 之后**：⭐ **上电后主动发一个字符**（⭐ 如 `'B'`）
⇒ ⭐ **接上串口就能看到** ⇒ ✅ **立刻确认 FPGA 活着 + 串口通**。

### `#5` 告警 —— ⚠️ **两个"完全看不到"的故障**

| 信号 | ⚠️ 现状 | 🔴 后果 |
|---|---|---|
| `af_fault`（⭐ ADC 采集故障，⭐ 2 位） | 🔴 **完全看不到** | ⚠️ **采集挂了但标定还在跑** ⇒ 卡死（⭐ 本轮修的就是这个） |
| `met_cfg_warn`（⭐ `RESERVED_N` 配对错） | 🔴 **完全看不到** | ⚠️ **专用池配错 ⇒ 节拍器被抢**（⭐ `K-106` 那一族） |

⇒ ⭐ **上板最怕"板子有问题但不知道"** ⇒ ⭐ **这两个必须能回传**。

## 二、⭐⭐ 具体设计

### 2.1 ⭐ `#1` 回显（⭐ 最简单）

```verilog
// ⭐ 在回传优先级【最低】的位置加一条：
//   ⭐ 语义：⭐ "收到了一个字节" ⇒ ⭐ 回声一个小写 'a'
//   ⚠️ 为什么放最低优先级：⭐ 命令受理（t/s/x）比回声更有信息量
wire rx_any = ur_done;          // ⭐ `uart_rx` 的完成脉冲（⭐ 已有）

wire       rep_req  = ... | rx_any;                       // ⭐ 加上
wire [7:0] rep_byte = ... : rx_any ? 8'h61 : 8'h78;       // 'a'
```

⚠️ **注意**：⭐ 这会让**每次发命令回两个字符**（⭐ 如 `Ta`）——
⭐ 那是**对的**（⭐ `T` = 受理，`a` = 收到回声）。

### 2.2 ⭐ `#2` 上电 beacon（⭐ 需要一个小延时）

```verilog
// ⭐ 上电后等一段时间（⭐ 等 `autotare` 跑完，⭐ 免得抢串口）
//   ⚠️ 用现有参数：⭐ `AUTOTARE_DELAY`（⭐ 实测 200 ms 量级）
reg [23:0] boot_cnt_q;
wire boot_fire = (boot_cnt_q == BOOT_DELAY_CLK) & ~boot_sent_q;

// ⭐ 回传字符：⭐ 'B'（⭐ Boot）
//   ⭐ 语义：⭐ "我起来了，串口通，⭐ 可以发命令了"
```

⚠️ **判据**：⭐ **上电后【不发任何东西】就能在串口助手看到 `B`**。

### 2.3 ⭐ `#5` 告警（⭐ 边沿触发，⛔ 不重复刷屏）

```verilog
// ⭐ 语义：⭐ 故障【新出现】时回一个字符（⭐ 边沿，⛔ 不是电平）
//   ⚠️ 若用电平 ⇒ 🔴 会一直发，⭐ 把串口刷满
wire af_fault_new = (af_fault != af_fault_r);      // ⭐ 变化才报
wire cfg_warn_new = (met_cfg_warn & ~met_cfg_warn_r);

// ⭐ 回传字符：⭐ 'F' = 采集故障 · 'W' = 配置告警
```

⚠️ **注意**：⭐ `af_fault` 有 **2 位**（⭐ 每片一位）⇒ ⭐ 建议**上报哪一片**：
```
⭐ 'F' + 片号（⭐ 如 'F0' = 片0 故障）
```
⚠️ 但那要**发两个字节** ⇒ ⚠️ 需要一个小状态机（⭐ 见 §三）。

## 三、⚠️ 一个必须解决的架构问题：**单字节 vs 多字节**

🔴 **现在的回传是"一个请求 ⇒ 一个字节"**（⭐ `tx_req` 单拍 + `tx_byte` 8 位）。

⚠️ **有些新消息需要多个字节**（⭐ 如 `F0`、⭐ 或将来的状态查询）：

| 选项 | ⭐ 说明 | ⚠️ 代价 |
|---|---|---|
| ⭐ **(甲) 只用单字节**（⭐ **本次采用**） | ⭐ 告警只回 `'F'`/`'W'`，⛔ 不带片号 | ✅ **⛔ 不改架构** · ⚠️ 信息略少（⭐ 但"有故障"已经够） |
| ⚠️ (乙) 加一个小的"发送序列"状态机 | ⭐ 支持多字节 | ⚠️ **改动较大** + ⚠️ 新增状态 ⇒ ⭐ **新的变异靶点** |
| ⚠️ (丙) 把告警编码进一个字符 | ⭐ 如 `'0'`~`'3'` 表示"哪片故障" | ⚠️ 字符语义变复杂（⭐ 人记不住） |

⭐ **建议 (甲)** —— ⚠️ 理由：⭐ **"有没有故障"比"哪一片"更急**，
⭐ 且**片号可以从别的证据推断**（⭐ 如串口标定的轴号）。

## 四、⭐⭐ 调试端口（⭐ 用 PMOD）

### 4.1 ⭐⭐ 引脚选择（🔴 **2026-09-24 修正：原来选错了**）

> 🔴🔴 **我第一版选了 `PMOD0_IO0`/`IO1`（`V18`/`V19`）—— ⭐ 那是【错的】**：
> ⚠️ 项目文档**明确写着**（`ESP32通路交接文档-20260922.md`）：
> ```
> ⚠️ PMOD0_IO0/IO1（V18/V19）是 JTAG 复用脚
>    （原理图同一行标着 JTAG.TMS / JTAG.TDO）
> ⇒ ⚠️ 占它们可能影响 JTAG，⭐ 优先用 PMOD0_IO2..7
> ```

#### ⭐⭐ `PMOD0` 的 8 根该怎么分（⭐ 实测全表）

| ⭐ 网络 | ⭐ ball | ⭐ BANK | ⚠️ 状态 |
|---|---|---|---|
| `PMOD0_IO0` | **`V18`** | `BANK8` | 🔴 **JTAG.TMS 复用** ⇒ ⛔ 避开 |
| `PMOD0_IO1` | **`V19`** | `BANK8` | 🔴 **JTAG.TDO 复用** ⇒ ⛔ 避开 |
| `PMOD0_IO2` | **`G21`** | `BANK2` | 🔴 **ESP32 TX**（⭐ 已被占） |
| `PMOD0_IO3` | **`G22`** | `BANK2` | 🔴 **ESP32 RX**（⭐ 已被占） |
| ⭐ **`PMOD0_IO4`** | ⭐ **`F18`** | `BANK2` | 🟢 **✅ 本设计采用** |
| ⭐ **`PMOD0_IO5`** | ⭐ **`E18`** | `BANK2` | 🟢 **✅ 本设计采用** |
| `PMOD0_IO6` | **`C22`** | `BANK2` | 🟢 备用 |
| `PMOD0_IO7` | **`B22`** | `BANK2` | 🟢 备用 |

⭐⭐ **结论：⭐ 调试端口用 `PMOD0_IO4`/`IO5` = `F18`/`E18`**
* ✅ **避开 JTAG**（⭐ `IO0`/`IO1`）
* ✅ **避开 ESP32**（⭐ `IO2`/`IO3`）
* ⚠️ **与 ESP32 同一条排针** ⇒ ⭐ **物理上不冲突**（⭐ 不同针）

#### 🔴 **ESP32 的引脚分配（⭐ 已定，⛔ 别改）**

```
⭐ 交接文档原文（`ESP32通路交接文档-20260922.md:226,298`）：
   "把 ESP32 的 UART2 接到 FPGA 的 PMOD0（G21=TX / G22=RX，⚠️ 交叉接：TX↔RX）"
⇒ ⭐⭐ **ESP32 走 `PMOD0_IO2`/`IO3`（`G21`/`G22`），⭐ ⛔ 不抢 USB-C**
```
📌 **所以"PC 直连板载串口"与"ESP32 走排针"【互不干扰】** ✅

#### ⚠️ `BANK2` 的电平 —— 🔴 **待核实**（⛔ 别照抄 `BANK8`）

⚠️ **实测**：⭐ `BANK2` 的电平**在现有文档里【查不到】**：
* ⚠️ 官方 `.cst`（`tang_mega_60K_pins.cst`）**不含 PMOD 脚**（⭐ 那些是 Dock 排针，⭐ 不在官方 cst 里）
* ⚠️ `开发板与引脚资料.md` 只给了 **`BANK2_G21_IOT144A`** 这种命名（⭐ 含 BANK 号，⛔ **不含电平**）

⇒ 🔴 **落地前必须确认 `BANK2` 是 3.3 V 还是别的**：
```
⭐ 判据来源（⭐ 优先级从高到低）：
   ① ⭐ 板卡原理图里 PMOD0 的 VCCIO 网络
   ② ⚠️ 实测：用万用表量 PMOD0 的 VCC 针

⚠️ **若 `BANK2` 不是 3.3 V** ⇒ 🔴 **调试脚的 `IO_TYPE` 要跟着改**（⭐ 否则可能损坏）。
