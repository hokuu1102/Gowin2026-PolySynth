### 实测判据结果（2026-10-14 亲自跑过）

```
PASS: fx_delay (priming / hard bypass / dry mix / echo timing /
      feedback decay / chorus modulation / saturation / stream)
```

| 覆盖的契约 | 内容 |
|---|---|
| priming | 延迟线填满前湿声保持静音（防开机"半截回声"） |
| hard bypass | `fx_en = 0` 时输出与输入**逐位相同** |
| dry mix | `mix = 0` 时输出与输入**逐位相同** |
| echo timing | 回声精确落在配置的延迟上（65280 拍） |
| feedback decay | 每次重复都更小，两次重复之间没有杂音 |
| chorus modulation | 抽头随 LFO 移动、双向、在配置深度内 |
| saturation | 高反馈时钳位而不是回绕 |
| stream | 一进一出、不丢不重、`valid_o` 不连续两拍高 |

### 设计要点

| 项 | 值 |
|---|---|
| 延迟线 | `AW = 14`，16384 样点 × 18 bit |
| 延迟时长 | 16384 ÷ 48828.125 = 335.5 ms |
| BSRAM | 16384 × 18 = 294 912 bit ÷ 18 432 = 16 块 |
| 挂载点 | `tdm_render_mixer` → `fx_delay` → `master_mix` → `i2s_tx` |
| 为什么在 `master_mix` 之前 | 音量关到底时回声也一起消失，与真机一致 |

## 三、拟新增的效果

### 3.1 失真 / Fuzz

失真是**无记忆非线性**，只看当前一个样点，所以 **BSRAM = 0**。

```
y[n] = f( x[n] )
```

用户裁定（2026-10-14）：**先只做硬削，留三个空位。**

| 档 | 做法 | DSP | LUT | 本期 |
|---|---|---|---|---|
| 硬削 | `xg = x×gain`（gain 取 1/2/4/8，用移位）→ `clamp(xg, −T, +T)` | 0 | ~60 | 做 |
| 空位 1 | 软削：分段线性 `\|xg\|>a ⇒ y = a + (\|xg\|−a)>>1` | 0 | ~150 | 留位 |
| 空位 2 | Fuzz：非对称阈值（`T1 ≠ T2`） | 0 | ~100 | 留位 |
| 空位 3 | 预留（位压缩 / 过载 / 自定义曲线） | — | — | 留位 |

软削不要用三次方（`y = x − x³/3`），那要 2 个乘法器，不值。

"留位"的准确含义：只留接口/参数槽位，不实例化逻辑，零资源成本。

#### 三个必须做的细节

| # | 细节 | 为什么 |
|---|---|---|
| 1 | 输出电平补偿 | 失真把 RMS 抬起来，不补偿会顶到 `master_mix` 的饱和 |
| 2 | 挂载顺序：失真在时间类效果之前 | 与真实效果器链一致（drive → modulation → time） |
| 3 | DC 阻断器（**留接口**） | 非对称削波会引入直流偏置，顶掉功放动态余量。一阶高通 `y = x − x_prev + 0.99×y_prev`，移位近似约 40 LUT。本期只做硬削（对称），可先不做，但做 fuzz 时必需 |

#### 一个如实的取舍：不做过采样

失真会产生超过 Nyquist 的谐波，理论上有混叠。正经做法要过采样（需滤波器 + 更多资源）。建议不做，理由：混叠在失真里本来就是"脏"的一部分；资源换来的听感提升不明显；用户已裁定"评委听不出来差别"。

#### 增益可调（用户裁定：资源够就用连续）

硬削的 `gain` 有两种做法：

| 做法 | 资源 | 档位 |
|---|---|---|
| 移位 | 零 DSP | 4 档（1/2/4/8） |
| 乘法器 | 1 DSP | 连续 |

用户裁定：**DSP 和其他资源够就用连续。** 当前 DSP 22/118（19%），余 96 个，
加 1 个做连续增益绰绰有余，所以**做连续**。

参数入口见 §6.4（推子参数页），不是 EC11。

### 3.2 音量颤音 Tremolo

> ⭐⭐ **2026-10-15 已实现**（`rtl/w3c/fx_trem.v`，判据 `tb_fx_trem` **16/16 绿**）
> ⚠️ **两处与本节原设想不同，如实记录**：
> 1. **自带 LFO**（三角波，约 30 LUT），⛔ **没有复用 `vibrato_lfo`** ——
>    复用要给它加输出端口，而它是**上板验证过的模块** ⇒ 改成自带、零耦合 ✓
> 2. **固定常开，没有使能位**（用户 2026-10-15 裁定）——
>    深度 = 0 时它逐位等于输入（`g=256` ⇒ `(x×256)>>8 = x`）
>    ⇒ 推子推到零就等于关掉，不需要开关 ✓ 顺带省掉 24 位旁路 mux ✓

用户裁定：**与音高颤音共用推子，用「推子功能键」切换。**

```
推子功能键（键盘 idx 5，等同 'J'）：
  按一下：推子的作用对象在【音高颤音】与【音量颤音】之间切换
  不需要额外推子，左手板推子数量不变
  状态由 WS2812 灯 5（推子功能灯）显示
```

| 项 | 评估 |
|---|---|
| 实现 | 在 `master_mix` 的增益通路上加一级 LFO 调制 |
| DSP | 0，幅度调制用移位（`sample >> k`，k 随 LFO 变） |
| LUT | 约 80~150 |
| BSRAM | 0 |
| 改动 | 要碰 `master_mix`，但它已有乘法器，可能 0 额外 DSP |
| 推子即参数 | 深度 / 速率，与音高颤音同一套交互 |

#### 在链里的位置：最后一级（紧挨 `master_mix`）

| 理由 | 说明 |
|---|---|
| 最便宜 | `master_mix` 已有乘法器，可能 0 额外 DSP |
| 音乐上正确 | 真实音箱自带的 tremolo 就是后级，调制整个信号（含回声） |
| 与推子同处一条增益链 | 用户要求共用推子，推子本来就在那条链上 |
| 互相独立 | 关掉延迟不影响颤音，关掉颤音不影响延迟 |

另一种味道是放在延迟之前（回声里带颤音）。将来要换只改 `fx_chain` 里的连线顺序，不用动 `fx_trem` 本体。

### 3.3 混响 Reverb

用户裁定：**暂时先不做，留位。**

| 做法 | 质量 | BSRAM | LUT | 本期 |
|---|---|---|---|---|
| 正经 Schroeder（4 梳 + 2 全通） | 像混响 | ~33 块 | ~800 | 不做 |
| 简易 2 梳（共用现有延迟线） | 像"短延迟+反馈"，不像真混响 | 0 | ~200 | 留位 |

## 四、效果器链架构

### 4.1 延迟线的分配：⭐ **合唱与延迟各用一条**（2026-10-15 用户裁定）

> ⭐ **用户原话**：*"最好延迟合唱能同时开，bsram 应该还有余量吧"* ✅

**先说资源账**（BSRAM 现在 **69/118 = 59%**，余 **49 块**）：

| 效果 | 线长 | 位宽 | BSRAM 块（估算） |
|---|---|---|---|
| 合唱 | 2048 样点（`AW_CH=11`）⇒ **42 ms** | 18 bit | 2 |
| 延迟 | 16384 样点（`AW=14`）⇒ **335 ms** | 18 bit | 16 |
| **合计** | | | 18 |

⭐ **实测（2026-10-15 综合冒烟）**：**20 块**（`SDPB 18` + `SDPX9B 2`）
—— ⚠️ 比估算多 2 块（合唱的 18 bit 被拆成 2 个 9 bit 块）
⇒ 落地后 **69 + 20 = 89/118 = 75%** ✅ 仍然宽裕

⭐ **关键点：合唱不需要 335 ms 的线** —— 它的调制抽头典型只要 10~30 ms
（深度 ±2.6 ms）⇒ 2048 样点足够 ⇒ **只要 2 块 BSRAM** ✅

**为什么不做"一条线 + 两个抽头"**（预研文档的原始设想）：

```
共用一条线 ⇒ 两个效果都读【同一份缓冲内容】⇒ 实际是【并联】
⇒ 延迟回声里【不会】带着合唱 ⇒ 串联顺序丢了
```

⭐ 改成两条独立的线之后，链是**真串联**：
```
dry ─►[失真]─►[合唱]─►[延迟]─►[混响·留位]─►[音量颤音]─► out
      0 BSRAM   2 块    16 块      0          ~30 LUT
```
⇒ 延迟回声里**带着合唱**（这才是真实效果器链的行为）✅

📌 **代价**：多花 2 块 BSRAM（相对共用一条）＋ 多一级 4 拍的流水线（80 ns）✅
📌 **若将来嫌 BSRAM 紧**：可以退回"共用一条 + 两个抽头"省 2 块，
⚠️ 但要接受**并联拓扑**（回声里不带合唱）✗

### 4.2 链的顺序（⭐ 含"第 0 级"）

```
音高颤音 ─► 振荡器 ─► … ─► tdm_render_mixer ─► [失真] ─► [合唱] ─► [延迟] ─► [混响·留位] ─► [音量颤音] ─► master_mix
（第 0 级，振荡器域）                            bit0      bit1      bit2       bit3         常开
                                                 └──────────── 音频域的效果器链（fx_chain.v）────────────┘
```

顺序依据：真实效果器链是 drive → modulation → time-based → 后级。
失真先塑造谐波，调制再加动感，时间类铺空间，音量颤音在后级调制整个信号（含回声）。

#### ⭐ 为什么"音高颤音"是第 0 级，而且**不能**搬进 `fx_chain`

> ⭐ **用户 2026-10-15 问**：*"那音高颤音肯定也还得用啊，接在最前级可以实现吗"*

✅ **能，而且它本来就在最前级** —— 只是位置在**振荡器域**，不在音频域 ✓

🔴 **搬不进 `fx_chain` 的原因是原理性的**：`fx_chain` 处理的是**已经生成的样点**，
而音高颤音改的是"**要生成什么音**"（喂给振荡器的 `phase_inc`）⇒ 它天然在链的**上游** ✗

要在音频域做音高颤音，只有一条路：**调制延迟线**（100% 湿、无干声）——
那是**移调器**，要再花一条延迟线，而且线性插值会有音质损失，
听感**还不如现在**（现在改的是相位增量 = 真正的音高颤音）✗

📌 **两者作用范围不同**（这是真实设备上的分工，不是妥协）：

| | 音高颤音 | 音量颤音 |
|---|---|---|
| 位置 | 链的**最前级**（第 0 级，振荡器域） | 链的**最后级**（第 5 级，音频域） |
| 作用对象 | 每个**新生成的音** | **全部输出** |
| 含 looper 回放 / 延迟回声 | ❌ 不含 | ✅ **含** |
| 开关 | 常开（推子置零即无效果） | 常开（推子置零即无效果） |

混响那级留位不实例化，链上是直通，零成本。

### 4.3 每级的"零回归"保证

```verilog
out = en ? effect(in) : in        // 硬旁路，en=0 时数值逐位相同
```

- `fx_delay` 的判据已证："with fx_en=0 the output is bit-identical to the input"
- 全部 enable = 0 时输出与今天数值逐位相同，169 个 tb 不受影响

一个要如实说清的细节：旁路走的是同一条流水线（`fx_delay` 里是 `fx_out = en_s2 ? mix_sat : dry_s2`，旁路取 `dry_s2`），数值相同，但时序差 4 拍 = 80 ns。相对 10 ms 的延迟预算可忽略。

### 4.4 接口改动（按"多留拓展性"设计）

```verilog

output reg  [1:0]  fx_sel_o,        // 只能选 1 个
// 改成
```

位分配（留了 4 位给将来）：

| 位 | 效果 | 本期 |
|---|---|---|
| `[0]` | 失真（硬削） | 做 |
| `[1]` | 合唱 | 做 |
| `[2]` | 延迟 | 做 |
| `[3]` | 混响 | 留位 |
| `[4]` | ~~音量颤音~~ → ⭐ **空闲**（2026-10-15：颤音改成**常开**，不再占位） | 空 |
| `[5..7]` | 预留（压缩 / 相位 / 均衡 / 八度…） | 留位 |

> ⭐ **音量颤音为什么不需要位**（用户 2026-10-15 裁定"固定常开"）：
> 深度 = 0 时它**逐位等于输入**（`g=256` ⇒ `(x×256)>>8 = x`）
> ⇒ 推子推到零就等于关掉，**开关是多余的** ✓
> 📌 顺带省掉那个 24 位 2:1 旁路 mux（约 24 LUT）✓

|---|---|
| `rtl/w3c/uart_ui.v` 就是串口屏（淘晶驰 TJC X2）人机交互层 | 文件头 |
| 它挂在 `uart_rx`（D14/D15，PC 那路 USB-TTL） | `top.v` 例化 `u_uart_ui` 用 `ur_done`/`ur_data` |
| 已有指令表（文本指令）和 TX 通路 | `tx_start_o` / `tx_data_o` |
| **FPGA 现在不往屏上发** | `top.v` 把 `tx_busy_i` 钉死成 `1'b1`，注释"本版只接收屏的控制帧" |
| 屏的协议：返回帧统一 `0xFF 0xFF 0xFF` 结尾；帧头是返回码（`0x65` 触控 / `0x70`·`0x71` 参数 / `0x88` 握手） | `uart_ui.v` 文件头 |
| FPGA 与 ESP32 另有独立 UART | `esp_uart_tx_o`(G21) / `esp_uart_rx_i`(G22)，PMOD0 针 9/10。**已查清：收发都占满了** —— RX 是曲谱上传通路（`u_uart_rx_esp`），TX 是 14 B 实时上行帧（`u_evt_upstream`） |

用户裁定：**屏和 PC 共用一路 UART，在码流里二选一**（不留运行时入口）。

设计要点：

- 用一个**编译期参数**（例如 `UART_OWNER_SCREEN`）在综合时决定归属，不是运行期开关
- 归属屏时，`uart_rx` 的字节只喂 `uart_ui`；归属 PC 时只喂 `calib_cmd` / `evt_uart_rx`
- `uart_tx` 同样二选一，避免 PC 回包和屏指令混在一条线上
- 好处：不占逻辑、不需要切换键、不会有"为什么串口没反应"的困惑
- 代价：换用途要重新出码流

用户裁定：**打通之后默认接屏**（不再走 PC 发指令），但屏还没打通，
所以**现在的码流维持 PC**。等屏打通了，把那个参数翻过来重出一版码流即可。

**已确认（2026-10-14）**：ESP32 那一路（G21/G22）收发都已占用
（RX = 曲谱上传 `u_uart_rx_esp`，TX = 14 B 上行帧 `u_evt_upstream`），
屏无法改走那路，所以与 PC 二选一是必需的。

### 6.3 WS2812 灯位：控制板 8 颗，第 8 颗就是留给效果器的

**权威文档是 `files/20-代码/控制板16键功能映射-20261013.md`（第 3 版）**，
它定的控制板布局是 **8 颗 WS2812**（不是 7 颗）：

| # | 功能 | 颜色（档位） | 时间（开关量） |
|---|---|---|---|
| 1 | 音色 | 白=BASS / 青=GUITAR / 紫=PIANO / 橙=PAD | 无 |
| 2 | 16 键行为 | 橙=指板 / 绿=键盘 | 蓝+呼吸=键盘打鼓（覆盖前两者） |
| 3 | **推子功能** | 紫=变调 / 青=颤音 / 黄=摇把 | 灭=当前无推子功能 |
| 4 | 节奏 | 红/洋红/黄/橙红=鼓机 4 型；绿=鼓机关但节拍器开 | 每拍暗 100 ms=节拍器开 |
| 5 | looper | 绿=回放 / 暗蓝=空闲 | 红+快闪=录音 |
| 6 | EC11 对象+音高状态 | 分时（见该文档 §1.3） | — |
| 7 | HDMI 显示 | 蓝=波形 / 品红=李萨如 | 无 |
| **8** | **效果器** | 灭=关（占位期恒灭） | 预留 |

所以：

- **效果器有专门的第 8 颗灯**，不用去抢别的灯，也不用拓展板
- **推子功能是第 3 颗灯**，正好承载"推子参数页"的显示（含新增的"效果"页）

**RTL 现状** —— ⭐⭐ **2026-10-15 已完成**（用户裁定"灯序一起改"）：

| 项 | 改前 | 改后 |
|---|---|---|
| `led_indicator.N_CH` | 7 | **8** |
| 灯序 | 音色/节拍器/鼓机/键盘打鼓/looper/推子功能/指板键盘 | **按第 3 版重排**（合并了节拍器+鼓机、16键行为+键盘打鼓） |
| 第 6 颗（idx 5） | 指板/键盘 | **EC11 对象 + 音高状态**（分时，含 26 位超时计数器） |
| 第 7 颗（idx 6） | 无 | **HDMI 显示**（波形蓝 / 李萨如品红） |
| 第 8 颗（idx 7） | 无 | **效果器**（关=灭；开=按 `fx_sel` 分色） |
| `top.v` 的 `WS_LED_N` | 16 | **8** |
| `top.v` 的 `NCH_LED` | 7 | **8** |

**新增的 6 个端口**（`led_indicator`）：

```verilog
input wire signed [4:0] transpose_i,   // #5 变调半音（-12..+12）
input wire              slide_i,       // #5 滑音开关（优先级高于变调）
input wire              enc_act_i,     // #5 EC11 刚被动过（临时色）
input wire              enc_obj_i,     // #5 EC11 对象：0=BPM · 1=音高
input wire              scope_mode_i,  // #6 HDMI：0=波形 · 1=李萨如
input wire              fx_en_i,       // #7 效果器使能
input wire [1:0]        fx_sel_i       // #7 效果器选择
```

**新增的闪烁方式**：`BL_BEAT_OFF`（每拍**暗** 100 ms）——
第 3 版把节拍器语义从"无拍点灭、拍点亮"改成"**常绿 + 每拍暗一下**"，
所以灯 3 用 `BL_BEAT_OFF` 而不是旧的 `BL_BEAT_ON`。

**判据**：`tb_led_indicator`（重写，8 灯 + 新语义）与 `tb_top_led_strip`
（`LED_N` 16→8 + 新灯序）都已同步，**全绿**。

**拓展板另有 3 根预留**（`ws_strip_o[2:0]`，PMOD1 针 11/12/9，W19/W20/F19），
现在恒 `3'b000`。既然控制板第 8 颗已经给了效果器，这 3 根**不需要动**。

#### 三层结构（避免把 `led_indicator` 误当成 WS2812）

```
各子系统状态码
      ↓
led_indicator          ← 指示层（表驱动）：状态码 → 每颗灯的 24 位 RGB888 + 闪烁
      ↓  led_col_o[N_CH*24-1:0]
top.v 里的 case        ← 把 N_CH 路颜色接到驱动的写口
      ↓  wr_en / wr_addr / wr_data
ws2812_driver          ← PHY：颜色 → 800 kHz 单线位时序
      ↓  dout_o
ctrl_ws_o (C22) → 控制板灯带
```

| 模块 | 是什么 | 管什么 |
|---|---|---|
| `rtl/w3a/led_indicator.v` | 指示层（表驱动） | 决定每颗灯什么颜色、怎么闪。输出 `N_CH × 24` 位 |
| `rtl/w3a/ws2812_driver.v` | PHY | 按 800 kHz 单线协议发送。有 `wr_en_i`/`wr_addr_i`/`wr_data_i` 写口 |

`led_indicator` 不知道 WS2812 协议，`ws2812_driver` 不知道"推子功能"是什么。
两者靠 `top.v` 的 `case` 接起来（驱动是 16 颗的缓冲，LED7..15 恒灭）。

所以改灯序 = **改 `led_indicator` 里的颜色表**，灯带协议那层不用动。

加一路的代价（`WS2812指示层规格-20261003.md` §49）：子系统引出 2~3 位（约 5 LUT）
＋ 表里加一个 case（约 30 LUT）＋ 灯序里加一颗。

### 6.5 效果器链相关的路径总览

#### A. 音频信号路径（从声源到输出）

```

             ├─► tdm_render_mixer ──► [fx_chain] ──► master_mix ──► i2s_tx ──┬─► HP_DIN（板载）

```

## 九、一句话总结

| 问题 | 答 |
|---|---|
| 能实现效果器链吗 | 能，而且便宜。串联本身只花约 80 LUT；贵的是延迟线 —— 合唱 2 块 + 延迟 16 块，⭐ **实测 20 块 BSRAM**（现在 69/118 ⇒ 落地后 **89/118 = 75%**） |
| 失真简单吗 | 最简单。零 BSRAM，连续增益只多 1 个 DSP，约 120 LUT |
| 音量颤音贵吗 | 不贵。**自带三角波 LFO**（约 30 LUT）、1 个乘法器、零 BSRAM ✓<br>⚠️ 原本设想"复用 `vibrato_lfo`"，但那要给它加输出端口，而它是**上板验证过的模块** ⇒ 改成自带、零耦合 |
| LUT 够吗 | 够（70%），但 CLS 是瓶颈（会到 87%） |
| 混响要做吗 | 已定：暂不做，留位（留位 = 零资源成本） |
| 怎么选效果 | **串口屏直接点选**；控制板矩阵 行2列1（idx 9）也留了硬件入口 |
| 怎么调参数 | **推子参数页**：`fader_gear` 的档 2 改成"效果"页（2 位够用，不扩位），复用右手板现有 2 个推子。不用 EC11 |
| 怎么切页 | 控制板矩阵 **行1列1**（`J`，idx 5），已连通 |
| 怎么显示 | 控制板 **第 8 颗** WS2812（专给效果器）+ **第 3 颗**（推子功能含效果页）；串口屏显示详细链 |
| 串口怎么走 | 屏与 PC **编译期二选一**（不留运行入口）；打通后默认屏，现在维持 PC |
| 不用的效果器影响链路吗 | 音质不影响（旁路数值逐位相同）；时序差 4 拍 = 80 ns（可忽略）；资源照占（`en` 是运行期信号） |
