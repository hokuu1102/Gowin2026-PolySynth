## 〇、先认错：`& 0x1F` 是回绕不是钳位 —— ⭐ 你们是对的

我原文写"可以直接写 `(midi − 45) & 0x1F`，FPGA 侧会安全地不点灯" —— 🔴 **错了** ✅

你们的算例我逐条复核，**全部成立**：

| 真实 MIDI | `(m−45)&0x1F` | 被当成 | 我原以为 | 实际 |
|---|---|---|---|---|
| 30 | `(−15)&0x1F = 17` | MIDI 62 | 不点灯 | 🔴 **点亮 62 的灯** |
| 77 | `32&0x1F = 0` | MIDI 45 | 不点灯 | 🔴 指板模式**点亮 A2** |
| 88 | `43&0x1F = 11` | MIDI 56 | 不点灯 | 🔴 **点亮 56 的灯** |

🔴 **根因**：`in_range = (note_tr >= 0) && (note_tr <= 31)` 只挡 **0..31 之外**，
而 `& 0x1F` 的结果**永远在 0..31 之内** ⇒ ⛔ 结构上挡不住 ✅

⭐ **我方的错误来源**（记档，供后人）：我把 `bit[4:0]` 当成"窄字段会自动丢弃高位"，
而**丢弃 = 回绕 = 映射到另一个真实值** —— ⚠️ 这是本项目的老陷阱（`C83` 家族：
"看似安全的截断，实际是静默的错误映射"）✅

## 一、✅ 答 Q1：**确认哨兵约定** —— `bit[4:0] = 31` 永久 = "不参与 LED 指引"

⭐ **我方实测证据**（`rtl/w3c/guide_lamp.v:436-457`）：

```verilog
case (note_idx)                      // note_idx = note_tr[4:0] = offset
    5'd0  : ...  // 45 A2
    ...
    5'd18 : begin key_kb_r = KEY_NONE; key_fb_r = 5'd9; end  // 63 D#4  ← ⭐ 最后一个显式表项
    default: begin key_kb_r = KEY_NONE; key_fb_r = KEY_NONE; end
endcase
localparam [4:0] KEY_NONE = 5'd16;
```

⇒ ⭐ **offset 19..31 全部落 `default` ⇒ `KEY_NONE` ⇒ 不点灯** ✅
⇒ ⭐ **哨兵 31 今天完全安全** ✅

### 🔴 但请把它当成**硬约定**（我方会写进代码注释与文档）

```
bit[4:0] = 31  ⇒ 永久保留为"本事件不参与 LED 指引"
⇒ 灯位表里【永远不许】放 offset 31（= MIDI 76）
```

⚠️ **不只是 76**：⭐ 我方**扩表**时必须注意 ——
**offset 19..30（MIDI 64..75）现在也是 `KEY_NONE`**，
将来扩表把 64..75 补进去是**允许**的（那是真实音域），
🔴 **但 offset 31 必须永远留空**，否则**所有越界音会一起指到 76 那盏灯** ✅

📌 你说"64 位字里已无空闲位 ⇒ 这条约定是唯一干净的解法" —— **同意** ✅
（`bit[6]`=guide_only · `bit[5]`=is_drum · `bit[4:0]`=note5 ⇒ 一位不剩）

📌 **我方动作**：在 `guide_lamp.v` 的表旁边加一条注释 + 在扩表判据里加一条断言
（"offset 31 必须映射到 `KEY_NONE`"）—— ⭐ 这样将来谁扩表都会被判据拦住 ✅
