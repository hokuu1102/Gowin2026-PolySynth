# 🔧 上电自动 `tare`（零点标定）设计方案

> **状态**：⭐ **设计完成，⛔ 未落地**（⚠️ 等变异测试跑完才能改 `rtl/`）
> **依据**：用户 2026-09-23 拍板 —— *"这个感觉标定一次就够了吧 / 或者到时候专门用一个按键或者串口屏进入校准模式"*
> **目标**：⭐ **上电后自动记下 16 个轴的零点**（松手位），⛔ 不需要人配合
> **配套**：`files/10-硬件/左右手板-纯仪器测试指南-20260923.md`（⭐ 上电前的硬件验证）

---

## 〇、⭐⭐ 一句话

> ⭐ **上电后等 ~200 ms（让霍尔稳定），逐个通道发一次 `tare`，把每个轴当前的原始码记为零点。**
> ⚠️ **`span`（满量程）本次【不做】** —— 它需要人把每个轴按到底，⚠️ 留给"校准模式"（按键/串口屏）。

---

## 一、⭐ 为什么要做（⛔ 不做的后果）

| 项 | 不标定 | 标定后 |
|---|---|---|
| **零点** | ⚠️ `zero = 0` ⇒ ⭐ **松手时读到的不是 0**（霍尔偏置 + 装配公差） | ⭐ **松手 = 0** |
| **后果** | 🔴 **`event_extract` 的触发阈按错基准判** ⇒ ⚠️ **松手就被判成"按下"**（⭐ 挂音）<br>⚠️ 或**要按很深才触发**（⭐ 手感差） | ✅ 阈值基于**真实行程** |

⭐ **依据**：`calib.v` 头注释 —— ⭐ *"对齐 `K-16` 比例式口径"*：`out = (raw − zero) × gain`。
⚠️ **未标定时 `zero=0`、`gain=unity` ⇒ 输出 = 原始码**（⭐ 我已实测确认：喂 `0x800` 得 `0x800`）。

---

## 二、⭐⭐ 关键约束（⭐ 这是设计的难点）

### 2.1 🔴 `tare` 必须在【目标通道的样本恰好到达那一拍】断言

⭐ 依据 `calib.v:145`：
```verilog
if (tare) zero_r[cal_ch] <= raw;     // ⚠️ raw 是【当拍的输入】，⛔ 不是寄存器
```

⚠️ **`raw` 是芯片【当前送来的那一个通道】的值** ⇒ 🔴 **`tare` 与 `sample_ch` 必须同拍对得上**,
⛔ **否则会把【别的通道】的值记成这个通道的零点** —— ⭐ **而且是静默的**（`cal_ch` 对，但 `raw` 错）。

> 📌 **这正是 `K-87` 那一族**：⭐ **锚点/时机对不上，但没有任何报错** ⇒ ⚠️ 零点全错而测试全绿。

### 2.2 ⚠️ 必须等霍尔供电稳定

⚠️ 霍尔 + LDO 上电有**建立时间**；⭐ 刚上电时读数会漂。
⇒ ⭐ **等 `TARE_DELAY`（建议 ~200 ms = 10,000,000 拍 @50 MHz）再开始标定。**

### 2.3 ⚠️ 每个通道只能标一次

⭐ `cal_ch` 逐通道走 **0→7**（每片），⚠️ 走完就**停**（⛔ 不要循环,否则会把"按下的位置"记成零点）。

---

## 三、⭐ 实现方案（⭐ 一个独立小模块，⛔ 不改 `calib`）

### 3.1 为什么做成**独立模块** `calib_autotare.v`

| 方案 | 评价 |
|---|---|
| ⚠️ 改 `calib.v` 内部加自校 | 🔴 **不做** —— ⭐ 它是**队友的模块**（有单测 + 变异体）,⚠️ 且"逐通道脉冲"本是**外部的职责** |
| ⭐ **新模块 `calib_autotare.v`** | ✅ **职责单一**：⭐ **只产生 `tare` + `cal_ch` 脉冲序列**；⚠️ 不碰 `calib` 内部 |

### 3.2 接口

```verilog
module calib_autotare #(
    parameter integer NCH         = 8,          // ⭐ 每片通道数
    parameter integer N_ADC       = 2,          // ⭐ 片数（本版 2）
    parameter integer DELAY_CLK   = 10_000_000, // ⭐ 上电等待 ~200 ms @50 MHz
    parameter integer SETTLE_CLK  = 50_000      // ⚠️ 每通道之间的间隔 ~1 ms
) (
    input  wire                    clk,
    input  wire                    rst_n,
    // ── 来自 adc_farm（⭐ 用于对齐时机）──────────────────────────────
    input  wire                    sample_valid_i,   // ⭐ 单拍脉冲
    input  wire [2:0]              sample_ch_i,      // ⭐ 当前是哪个通道
    // ── 去 calib（⭐ 每个 calib 一份）───────────────────────────────
    output reg  [N_ADC-1:0]        tare_o,           // ⭐ 逐片独立
    output reg  [2:0]              cal_ch_o,
    output wire                    done_o,           // ⭐ 全部标完
    output wire                    busy_o
);
```

### 3.3 ⭐ 状态机（⭐ 三段）

```
┌─────────────┐   DELAY_CLK 到   ┌──────────────┐   8 个通道标完   ┌────────┐
│  WAIT_POWER │ ───────────────> │  TARE_SWEEP  │ ──────────────> │  DONE  │
│ (等霍尔稳定) │                  │ (逐通道 tare) │                 │ (停住) │
└─────────────┘                  └──────────────┘                 └────────┘
```

**`TARE_SWEEP` 的核心逻辑（⭐ 时机是关键）：**

```verilog
// ⭐ 当【目标通道的样本】到达那一拍 ⇒ 拉高 tare
//   ⚠️ 判据 = sample_valid_i && (sample_ch_i == cur_ch)
if (sample_valid_i && (sample_ch_i == cur_ch)) begin
    tare_o   <= {N_ADC{1'b1}};   // ⭐ 所有片同拍（⭐ 它们锁步）
    cal_ch_o <= cur_ch;
    cur_ch   <= cur_ch + 1;
end else begin
    tare_o   <= {N_ADC{1'b0}};   // ⭐ 必须是【单周期脉冲】
end
```

> 🔴 **⚠️ 两个必须说清的点**：
> **① `tare` 只能是【单周期脉冲】**（⭐ `calib.v:36` 原文 *"1 周期"*）——
>    ⚠️ 拉高多拍会**把多个通道的值连续写进同一个 `zero_r[cal_ch]`**。
> **② `cal_ch_o` 必须与 `tare_o` 【同拍】** —— ⚠️ 上面的写法**天然满足**（同一 `always` 块、同一拍锁存）。

### 3.4 ⚠️ 为什么"等 `sample_ch == cur_ch`"而不是"数满 8 拍"

⭐ **`adc_farm` 是锁步的**：⭐ 每帧**固定 ch0→ch7** 顺序扫。
⇒ ⭐ 等 `sample_ch_i == cur_ch` **天然对齐**,⛔ 不需要额外计数器,⚠️ 也**不怕帧间隔变化**。

⚠️ **反面做法（⭐ 不要用）**：⚠️ 数"每 8 个 `sample_valid` 标一个" ——
🔴 一旦 `N_ADC`/扫序变化就**静默错位**（⭐ 同 `K-87`）。

## 四、⭐⭐ 与既有模块的接线（`top.v` 改动）

```verilog
// ⭐ 新增：自动 tare 控制器
wire [1:0] at_tare;
wire [2:0] at_ch;
wire       at_done, at_busy;

calib_autotare #(.NCH(8), .N_ADC(2), .DELAY_CLK(AUTOTARE_DELAY_CLK))
u_autotare (
    .clk(clk), .rst_n(rst_n_sync),
    .sample_valid_i (af_sample_valid),
    .sample_ch_i    (af_sample_ch),
    .tare_o         (at_tare),
    .cal_ch_o       (at_ch),
    .done_o         (at_done),
    .busy_o         (at_busy)
);

// ⭐ 把 u_calib0/1 的 tare 从"硬接 0"改成接 at_tare
.calib0:  .tare (at_tare[0]), .cal_ch (at_ch),
.calib1:  .tare (at_tare[1]), .cal_ch (at_ch),
```

⚠️ **`span` 仍硬接 0**（⭐ 本版不做）。

## 五、⭐⭐ 判据（⭐ 每条都必须能失败）

| # | 判据 | ⛔ 怎么让它失败 |
|---|---|---|
| **1** | ⭐ **上电后 `tare` 在 `DELAY_CLK` 之前【不出现】** | ⚠️ 去掉延时 ⇒ 判据 1 红 |
| **2** | ⭐ **每个通道【恰好】收到一次 `tare`**（⭐ 共 `NCH` 次） | ⚠️ 循环标定 ⇒ 次数变多 |
| **3** | ⭐ **`tare` 是高【单周期脉冲】**（⛔ 不是多拍） | ⚠️ 拉高多拍 ⇒ 判据 3 红 |
| **4** | ⭐⭐ **`tare` 出现在【`sample_ch == cal_ch`】那一拍** | ⭐ **这是最关键的一条** |
| **5** | ⭐ **`cal_ch` 按 0..7 递增**（⛔ 不跳、⛔ 不倒序） | ⚠️ 改序 ⇒ 判据 5 红 |
| **6** | ⭐ **`done_o` 置起后 ⛔ 不再产生 `tare`**（⭐ 自锁） | ⚠️ 去掉自锁 ⇒ 判据 6 红 |

> ⭐ **判据 4 的测法**：⭐ tb 里用**每个通道给不同值**的假 ADC
> （如 ch0=`0x100`、ch1=`0x200`…）⇒ ⭐ **标定后逐一核对 `zero_r[k] == 0x100*(k+1)`**
> ⇒ ⚠️ **若时机错一拍,值会串位** ⇒ ⭐ **立刻红**。

### ⭐ 变异体建议（⭐ 落地时一起加）

| ID | 靶点 | 守护判据 |
|---|---|---|
| `M88` | 去掉 `DELAY_CLK` 等待 | #1 |
| `M89` | `tare` 拉高多拍（⛔ 不是脉冲） | #3 |
| `M90` | **时机判据改成"数 8 拍"** | ⭐ **#4**（⭐ 最关键 —— ⚠️ 模拟"静默错位"） |
| `M91` | 去掉 `done` 自锁（循环标定） | #6 |

## 六、⚠️ 本次**不做**的（⭐ 诚实边界）

| # | 不做 | 为什么 |
|---|---|---|
| **1** | ⚠️ **`span`（满量程标定）** | ⚠️ 需要人**把每个轴按到底** ⇒ ⭐ 要有引导（按键/LED/串口屏） |
| **2** | ⚠️ **零点持久化**（掉电保存） | ⚠️ 需要 NVM/Flash ⇒ ⭐ **每次上电重新标定即可**（⭐ 反正霍尔一上电就位） |
| **3** | ⚠️ **温度漂移补偿** | ⚠️ 霍尔有温漂 ⇒ ⭐ 但**一场比赛内可忽略** |
| **4** | ⚠️ **标定有效性检查** | ⚠️ 若上电时有人按着键 ⇒ 🔴 **那个轴零点就是错的**（⭐ 见 §七） |

---

## 七、⚠️ 一个已知风险（⭐ 必须写进上板指南）

> 🔴 **上电时⛔ 不要按着任何键** ——
> ⭐ 因为自动 `tare` 会把**当前位置**记成零点
> ⇒ ⚠️ 若按着上电，⭐ **那个轴的零点就是"按到底"** ⇒ 🔴 **之后永远触发不了**。

⭐ **缓解建议（⚠️ 将来可选）**：
- ⭐ **上电后 LED 提示"正在标定"**（⭐ 依赖丙的 `led_data`）
- ⭐ 或**加合理性检查**：⚠️ 若某轴零点 > 满量程 30% ⇒ 判为异常、⚠️ **该轴回退到默认 0**

⚠️ **本次先只写进文档**（⭐ 上板指南已含"上电前不要按键"）。
