## 〇、⭐ 五条硬约定（先看这个，比信号表更重要）

| # | 约定 | 违反的后果 |
|---|---|---|
| **1** | ⭐ **单时钟域**：全设计只用 `clk_sys = 50 MHz`，**禁止派生时钟**；用**节拍脉冲**（`tick_*`）代替 | 跨时钟域亚稳；且经验库明确记载 **Gowin 上用 PLL 输出做全设计系统时钟 → 综合通过但板子全死** |
| **2** | **统一复位**：`rst_n` 同步复位、**低有效**，全设计极性一致 | 混用极性是最常见的集成 bug |
| **3** | ⭐ **固定流水线深度** —— 每个模块的延迟拍数**写进接口表且不许随意改** | 延迟预算的"确定性"靠它保证；深度一变，`files/20-代码/延迟预算逐段分解.md` 的预算就失效 |
| **4** | ⭐ **单周期脉冲必须"边沿时刻断言"**，⛔ 不许"事后查询" | 经验库 `L12`：脉冲信号事后查询必然漏采 |
| **5** | **一人一文件**（或一目录）—— 三人不改同一个 `.v` | 否则 git 冲突 + 语义冲突 |

> ⚠️ 第 1 条是**刻意设计**：我们**不需要 PLL**（50 MHz 整数分频即得 `fs`）。
> **⛔ 不要"顺手改成用 PLL 更规范"** —— 那正好是已知会炸的那条路。

## 三、⭐ 接口定义（三条通路）

### 接口 ① · 事件通路（W3a → W3b）

**为什么单独一条**：⭐ **事件驱动 Note ON/OFF，要求低延迟且固定**。

```verilog
// 音符事件 —— 单周期脉冲
typedef struct packed {
    logic              valid;      // 单周期脉冲，边沿时刻断言（约定 4）
    logic [3:0]        axis_id;    // 轴位 0..15
    logic [31:0]       phase_inc;  // ⭐ 相位增量（含音名映射 + 变调 + 双压插值）— 见 ①-补
    logic [7:0]        velocity;   // 0..255 ⚠️ 用 DEFAULT_VEL 先起音
    logic [1:0]        kind;       // 0=note_on 1=note_off 2=pluck
} note_evt_t;

// ⭐ 力度修正事件 —— 后到，用于更新"已在响"的 voice
typedef struct packed {
    logic              valid;
    logic [3:0]        axis_id;    // 按轴位寻址（W3a 不知道 voice_id）
    logic [7:0]        velocity;
} vel_update_t;

// ⭐ 音高修正事件 —— 滑音持续移动时更新音高（见 ①-补）
typedef struct packed {
    logic              valid;
    logic [3:0]        axis_id;
    logic [31:0]       phase_inc;
} pitch_update_t;
```

> 📌 **`phase_inc` 取代了原来的 `note_num`** —— 原因与精度核算见下方 **接口 ①-补**。
> ⚠️ **本节是这三个结构的唯一权威定义**，别处只引用、不重抄。

> ### ⭐⭐ `vel_update_t` 的存在原因（**这是从延迟预算里挖出来的陷阱**）
>
> 力度用**双阈值测速法**（越过浅阈 t1、深阈 t2，Δt 小 = 力度大）。
> **若等 t2 到了才发声** → 延迟由"演奏者拨多快"决定 → **不可控 → 违反「确定性无抖动」**，
> 且慢按可能几百 ms 才响。
>
> ✅ **正确做法：越过 t1 就发声**（用 `velocity = DEFAULT_VEL` 起音），
> t2 到了再用 `vel_update_t` **修正**那个 voice 的音量。
> 修正发生在 ADSR 起音阶段内（几十 ms），**听感上就是"这个音的力度"**。
>
> ⚠️ **对 W3b 的要求**：`NoteManager` **必须支持"更新在响 voice 的参数"**。
> （详见 `files/20-代码/延迟预算逐段分解.md` §三）

### 接口 ② · 参数通路（W3a → W3b）

```verilog
// 表情参数 —— 持续调制，可周期性更新
typedef struct packed {
    logic              valid;
    logic [3:0]        axis_id;
    logic [7:0]        vibrato;      // 颤音深度（来自右手推子）
    logic [3:0]        timbre;       // 音色选择（≥2 种）
    logic signed [11:0] pitch_fine;  // ⚠️ 含义待澄清 —— 见下
} expr_param_t;
```

> ### ⚠️⚠️ 待澄清（2026-09-13）：**"滑音"不在这条参数量里**
>
> **原写法**把 `pitch_bend`（滑音偏移）放在这里，**那是错的**。
>
> 因为 `files/20-代码/采集链参数复核.md` §六 已确认：**横向移动靠"相邻轴位双压插值"实现**
> （每轴位只有 1 个霍尔 —— 磁轴**直上直下**、磁铁**不产生横向位移**）
> → 滑音的**计算落在映射层**（`axis_map.v`，属 W3a）→ 输出的是**已经算好的相位增量**。
>
> ✅ **已在接口 ①-补 中解决**：滑音走 `pitch_update_t`（带 `phase_inc`），**不走参数量**。
>
> | 因此 | |
> |---|---|
> | ⭐ **W3b 不需要"滑音参数"** | 它收到的是算好的 `phase_inc` |
> | ⭐ **`pitch_fine` 已取消** | 原字段是"音名 + 音分"方案的残留 —— 改传相位增量后不需要了 |
> | ✅ **本接口只留 `vibrato`（深度）与 `timbre`** | 颤音由 **W3b 内部 LFO** 生成（推子给深度） |

### 接口 ①-补 · ⭐ 音高怎么传：**直接传相位增量，不传音名**（2026-09-13 定，C8）

> **背景**：C7 已确认滑音靠「**相邻轴位双压插值**」实现 →
> **插值出来的音高不在半音格点上** → 只给 7 bit `note_num` 会把滑音"**拉直成台阶**"。
> 本节解决"那该传什么"。

#### 方案对比

| 方案 | W3a 输出 | W3b 需要做 | 评价 |
|---|---|---|---|
| **A. 音名 + 音分** | `note_num[6:0]` + `note_fine[7:0]` | ⚠️ **指数运算** `2^((n+fine/100)/12)` —— 不能直接用乘法器，要查表 + 内插 | ⚠️ 多一层运算与误差 |
| ⭐ **B. 相位增量** | **`phase_inc[31:0]`** | ✅ **直接喂给相位累加器**，零运算 | ⭐ **推荐** |

> ### ⭐⭐ 选 B，理由三条
> 1. **W3b 完全不需要懂音乐理论** —— 它只管振荡器（相位累加 + 查表 + 包络）
> 2. **避开指数运算** —— 音名→频率是 `2^(n/12)`，用 DSP 乘法器做不了，必须查表
> 3. **滑音插值变成一次线性插值** —— 而**线性插值频率在这里是够准的**（见下方核算）

#### ⭐ 精度核算：为什么"线性插值"就够（不需要对数插值）

| 项 | 数值 | 结论 |
|---|---|---|
| 相邻半音的频率比 | `2^(1/12) = 1.0595` | —— |
| **线性**插值中点 | `(1 + 1.0595)/2 = 1.0297` | —— |
| **正确**（音分）中点 | `2^(1/24) = 1.0293` | —— |
| **两者差** | 0.04 % ≈ **0.7 音分** | ⭐ **远低于可闻阈（~5 音分）→ 可忽略** |

**相位增量位宽核算**（`f_out = phase_inc × fs / 2^32`）

| `PHASE_W` | 频率分辨率 | 对 440 Hz 的相对精度 |
|---|---|---|
| 24 bit | `48828/2^24 = 0.0029 Hz` | ≈ **0.011 音分** ✅ 够 |
| **32 bit** ⭐ | `48828/2^32 = 1.1e-5 Hz` | ≈ **0.000045 音分** ✅ 极精细 |

**双压插值的精度**（行程比例 `w` 来自 12 bit 霍尔）

| 项 | 数值 |
|---|---|
| `w` 的量化误差 | `1/4096` |
| 折算到音高 | `(1/4096) × 0.0595 × f` ≈ **0.025 音分** ✅ 可忽略 |

> ➡️ **结论：`PHASE_W = 32`、12 bit 霍尔、线性插值 → 音高误差 < 1 音分，全部够用。**
> **⛔ 不需要对数插值、不需要浮点、不需要额外精度手段。**

#### ⭐ 映射表怎么组织（两层，都很省）

```text
第 1 层：轴位 → 音名     16 项 × 7 bit  →  两套（钢琴模式 / 指板模式）
第 2 层：音名 → 相位增量  128 项 × 32 bit = 4 kbit  →  ⭐ 只用 LUT RAM，不占 BSRAM
```

| 好处 | 说明 |
|---|---|
| ⭐ **两套模式共用同一张音高表** | 模式切换只换第 1 层 → 省资源、且两种模式音准天然一致 |
| ⭐ **变调（八度切换）零成本** | 查表索引写成 `note_num + transpose` 即可，**不需要任何乘法** |
| ⭐ **表是编译期常量** | 全在 RTL 常量里，运行时零运算 |

#### ⭐ 结构定义见接口 ①（不重复）

> ⛔ **本节不重抄 `note_evt_t` / `vel_update_t` / `pitch_update_t`** ——
> **接口 ① 是唯一权威定义**（改接口只改一处，避免两份定义漂移）。

#### ⚠️ 为什么要多个 `pitch_update_t`（而不只是起音时给一次）

双压插值出来的音高**在手指移动过程中是连续变化的** → 需要**持续更新**已在响的 voice，
而不是每变一点就发一个新音符。

⭐ 这同时守住了 **"参数永不产生音符"** 这条铁律 ——
**移动动作在架构上不可能**被当成新音符（这是"误触发"的结构性解法）。

#### ⚠️ 颤音为什么不走 `pitch_update_t`

现有决定是「**推子给深度、FPGA 内固定 5~6 Hz 速率**」→ 所以 **W3b 内部生成 LFO**，
`expr_param_t` 只传**深度**。

⛔ **不要试图用 `pitch_update_t` 传颤音** —— 那要求极高的更新率（要平滑就得 ≥1 kHz），
**精度反而不如内部 LFO**，还白占带宽。

#### ⭐ 代价与对策

| 代价 | 对策 |
|---|---|
| **可读性变差** —— 看到 `phase_inc = 0x024E0000` 不知道是什么音 | ⭐ 调试/测试模式用一张「`phase_inc` → 音名/Hz」反查表显示；仿真时用 Python 反算 |
| W3a 多一张音高表 | 只用 LUT RAM，4 kbit，可忽略 |

> ⚠️ **铁律**：**参数永不产生音符**（见 `files/20-代码/整体模块框图.md` §三）。
> 这是"误触发"问题的**结构性解法** —— 调制动作（抖行程、横向滑音）**在架构上就不可能**被当成新音符。

### 接口 ③ · 音频通路（W3b → W3c）

```verilog
typedef struct packed {
    logic              valid;        // ⭐ 每个样本一个脉冲（fs 节拍）
    logic signed [23:0] sample;      // 单声道（立体声则在 W3c 复制）
} audio_t;
```

> 📌 **单声道 vs 立体声**：当前按**单声道**走（DAC 双声道输出同一路即可）。
> 若要做立体声效果（合唱/混响的声像），在 **W3c** 内部展开 —— **不改这条接口**。

## 五、⛔ 六条禁令（违反即集成失败）

| # | 禁止 | 原因 |
|---|---|---|
| **1** | 用**派生时钟**（除 `clk_sys` 外） | 约定 1；Gowin 上有实测炸机案例 |
| **2** | **不用缓冲/大 FIFO** 放在确定性通路上 | 缓冲深度**直接变成延迟**；块缓冲 128 样本 = +2.6 ms |
| **3** | 让**参数**产生音符事件 | 破坏"误触发"的结构性解法 |
| **4** | 共用**相位累加器**或**包络**来省资源 | ⛔ 评分规则要求"独立"——共用就**不算独立振荡器**，吞吐量数会缩水 |
| **5** | 在**事件通路上加去抖等待** | 去抖引入固定延迟；用**不应期**（先触发再封锁）代替 |
| **6** | 三人同改 `top.v` / `clk_gen.v` / `top.cst` 而不通知 | 集成层是汇合点 |
