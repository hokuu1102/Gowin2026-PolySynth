# 第二步「运行时切换」重新设计（2026-10-10）

> 起因：第一次实现（`SCOPE_MODE` 参数 → 运行时端口）**构建失败** ——
> 两条渲染路并存 ⇒ CLS 贴天花板（81%）⇒ 布线器 **40 分钟 ~ 12 小时**都布不通（实测两次）。
> 回退后源码与 `L_rightboard_xy_qcmd_ok.fs`（55.034 MHz · 0/0）对齐 ✅

---

## 一、为什么第一次失败（根因，不是"再调调参数"能解决的）

```
波形模式：  frame_y 快照 → on_trace 逐列比较 → RGB     （一整套独立渲染器）
李萨如模式：xy_fb 帧缓冲 → 逐像素取位 → RGB            （另一套独立渲染器）
```

把 `SCOPE_MODE` 改成运行时 ⇒ **两套必须同时存在** ⇒
- CLS 从 24235 再涨（波形那套 ≈ +100~150）
- 而 **CLS 已经 81%** ⇒ 布线器找不到合法路径 ⇒ **布不通**

⇒ ⭐ **结论：不是资源调参问题，是【架构】问题** —— 两套渲染器不该并存。

---

## 二、⭐ 重新设计：**让两种模式共用同一个渲染器**

### 核心洞察

**两种模式在"渲染"这一步是完全一样的**：
```
每像素：读帧缓冲的对应位 → 亮 = 绿、暗 = 黑
```
差别只在 **vblank 期间往帧缓冲里"画什么"**：
| 模式 | vblank 画什么 |
|---|---|
| 波形 | 把 640 列的**竖线段**画进帧缓冲 |
| 李萨如 | 把 1024 个点的**轨迹**画进帧缓冲 |

⇒ ⭐⭐ **渲染器只有一套；`SCOPE_MODE` 只切换 vblank 的"画法"** ✅

### 改后结构

```
                    ┌──────────────────────────────────────┐
   history ────────►│  打点 FSM（vblank 内跑）              │
                    │    scope_mode_i == 0 ⇒ 波形画法       │
                    │    scope_mode_i == 1 ⇒ 李萨如画法     │
                    └──────────────┬───────────────────────┘
                                   │ 单一写口
                              ┌────▼─────┐
                              │  xy_fb   │  ← 唯一帧缓冲（640×480×1bit）
                              └────┬─────┘
                                   │ 单一读口（按屏幕坐标）
                              ┌────▼─────────────────────┐
                              │ 渲染器（⭐ 模式无关）      │
                              │  绿 = 该位为 1            │
                              └──────────────────────────┘
```

### ⭐ 省掉了什么

| 项 | 说明 |
|---|---|
| **`on_trace` / `point_q` / `previous_y` / `segment_previous`** | 波形那套逐列比较逻辑（≈30~50 CLS） |
| **`frame_ready` 快照机制** | 不再需要（波形直接画进帧缓冲） |
| **两套渲染器之间的 mux** | 渲染器只有一套 ⇒ mux 消失 |
| **`frame_y`** | 已在 B 里删掉 ✅ |

### 代价

波形画法要在 vblank 里画 640 条竖线段 ⇒ **单段上限 `MAX_SEG`**（与李萨如同一个思路）：

```
预算：清屏 9600 + 640 段 × (2·MAX_SEG + 6)
       MAX_SEG = 12 ⇒ 9600 + 640×30 = 28,800 < 36,000 ✅（80%）
       MAX_SEG = 16 ⇒ 9600 + 640×38 = 34,000 < 36,000 ✅（94%，偏紧）
⇒ ⭐ 取 MAX_SEG = 12
```
⚠️ 超长跳变（瞬态）会被截断 ⇒ 该列画不满 ⇒ **与现在的行为不同** ⚠️
（现在波形是"整列画满"，改后是"最多 12 像素"）
⇒ ⭐ **这是唯一的视觉取舍，需要你确认**：
   - 若不能接受 ⇒ 波形画法给 **MAX_SEG = 32**（9600+640×70 = 54,400 ❌ 超预算）
     ⇒ 那就得**减少列数**或**分两帧画**（隔行交替）⚠️

## 三、另一个更省的方案（备选）：**双窗口常显**

不做切换，而是**一屏同时显示两个**：
```
上半屏 640×240：波形
下半屏 640×240：李萨如
```
- ⭐ **零切换成本**（不需要运行时 mux，两套画法各画各的半屏）
- ⚠️ 但仍需两套渲染器并存 ⇒ CLS 问题**没解决** ❌
- ⇒ **不如方案二**

---

## 四、第三个方案：**降帧缓冲分辨率**

把 `xy_fb` 从 640×480 降到 **320×240**（BSRAM 64 → ~30）
- ✅ 资源大幅释放 ⇒ 两套渲染器可能装得下
- ❌ **重新引入 2×2 方块感**（你之前要求消掉的那个）⚠️
- ⇒ 只有在前两个方案都不行时才考虑
