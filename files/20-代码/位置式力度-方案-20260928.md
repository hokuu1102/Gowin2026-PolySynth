## 一、⭐ 两个关键发现（决定改哪里）

### 1.1 ✅ **架构已经支持"实时跟随"** —— 不用改 `adsr.v`

```verilog
adsr.v:50-52
    wire [ENV_W-1:0] peak_level    = {velocity_i, {(ENV_W-VEL_W){1'b0}}};   // = velocity << 8
    wire [ENV_W+7:0] sustain_product = peak_level * SUSTAIN_Q8_U;
    wire [ENV_W-1:0] sustain_level  = sustain_product >> 8;                 // = peak × 64/256

adsr.v:115-124  ST_SUSTAIN:
    if (env_level_o < sustain_level) begin
        ... env_level_o <= sustain_level;
    end else if (env_level_o > sustain_level) begin
        ... env_level_o <= sustain_level;
    end
```

⭐⭐ **⇒ `sustain_level` 与 `peak_level` 都是 `velocity_i` 的【组合输出】，
而 `ST_SUSTAIN` 会【持续朝 `sustain_level` 收敛】**
⇒ ⭐ **改 `velocity_i` ⇒ 音量【立刻跟随】** ✅ **不需要改 `adsr.v`**

### 1.2 🔴 **但 `note_manager` 只允许【调大】** —— 必须改

```verilog
note_manager.v:531-535
    if (vel_upd_valid_i) begin
        for (i = 0; i < POLY_TARGET; i = i + 1)
            if (gate_mask[i] && (axis_r[i] == vel_upd_axis_i))
                ⭐ if (vel_upd_value_i > vel_r[i])          // 🔴 只允许【调大】
                    vel_r[i] <= vel_upd_value_i;
    end
```

🔴 **这条与"实时跟随"直接冲突** —— ⭐ 按浅了要能变**小**。

⭐⭐ **⇒ 修法：去掉 `if (vel_upd_value_i > vel_r[i])` 这个限制**，直接赋值。

## 四、⭐ 映射公式（⭐ 已验证，误差 < 1 LSB，⛔ 无乘法器）

```
目标：pos ∈ [0, 744]  ⇒  vel ∈ [64, 255]

⭐ 实现：vel = 64 + ((pos × 263) >> 10)
   · 263 / 1024 = 0.25684  ，而 191/744 = 0.25672  ⇒ 误差 0.05%
   · ⭐ 263 = 256 + 8 − 1  ⇒  ⭐ (pos<<8) + (pos<<3) − pos  ⇒ ⛔ 不用乘法器
```

### 核对表（⭐ 已实测跑过）

| `pos` | 理想 `vel` | 实际 `vel` | 误差 |
|---|---|---|---|
| 0 | 64.0 | **64** | 0.0 |
| 96 | 88.6 | 88 | −0.6 |
| **192**（`TRIG_TH`） | 113.3 | **113** | −0.3 |
| 288 | 137.9 | 137 | −0.9 |
| 384 | 162.6 | 162 | −0.6 |
| 480 | 187.2 | 187 | −0.2 |
| 576 | 211.9 | 211 | −0.9 |
| 672 | 236.5 | 236 | −0.5 |
| **744**（满行程） | 255.0 | **255** | 0.0 |

### ⚠️ 一条要知道的推论

```
⭐ 因为 note_on 只在 pos > TRIG_TH(192) 时才触发
⇒ ⭐ 实际起音力度范围是 【113 ~ 255】，⛔ 不是 [64, 255]
⇒ 那个"下限 64"只在【按住后往回松】时才可能用到（⭐ 但那时 pos 仍 > REL_TH）
```
📌 **如果希望"轻按也能到 64"** ⇒ 需要**降低 `TRIG_TH`**（⭐ 那会影响触发的灵敏度，
⚠️ 是另一个话题，⛔ 本方案不动）。

## 五、⭐ 实施细节

### 5.1 `note_manager.v`：去掉"只允许调大"

```verilog
// 🔴 现状
if (vel_upd_value_i > vel_r[i])
    vel_r[i] <= vel_upd_value_i;

// ✅ 改为（⭐ 实时跟随：可增可减）
vel_r[i] <= vel_upd_value_i;
```

📌 **保留 `gate_mask[i] && (axis_r[i] == vel_upd_axis_i)` 这个条件不变** ——
⭐ 它正是"**只在按下时**"的硬保证（`gate_mask = gate_r & ~retrig_low`）。

⚠️ **一个已知的小瑕疵**：重触发压低窗口（≤ 1 tick）内 `gate_mask` 为 0
⇒ 那一拍的位置更新会被跳过。⭐ 影响可忽略（下一拍就补上）。

### 5.2 `top.v`：生成位置式力度流

```verilog
// ⭐⭐ 位置式力度：每 sample_tick 扫一个轴（8 轴轮转）
//     · 判据：pos > TRIG_TH ⇒ ⭐"按下中"（抬起后自动失效 ⇒ 力度冻结）
//     · 死区：|pos − 上次发出的 pos| >= 16 ⇒ 才发
//     · 映射：vel = 64 + ((pos*263)>>10)，饱和到 255
reg  [2:0]  vu_ax_r;                     // 轮转轴
reg  [11:0] vu_last [0:7];               // 上次发出的 pos（死区判据）
reg         vu_valid_r;
reg  [3:0]  vu_axis_r;
reg  [7:0]  vu_val_r;

wire [11:0] vu_pos     = as_pos[vu_ax_r*12 +: 12];
wire [21:0] vu_prod    = (vu_pos << 8) + (vu_pos << 3) - vu_pos;   // ×263
wire [7:0]  vu_vel     = 8'd64 + vu_prod[21:10];                   // >>10
wire        vu_far     = (vu_pos > vu_last[vu_ax_r] + 12'd16)
                      || (vu_pos + 12'd16 < vu_last[vu_ax_r]);

always @(posedge clk) begin
    vu_valid_r <= 1'b0;
    if (sample_tick) begin
        vu_ax_r <= vu_ax_r + 3'd1;
        if ((vu_pos > TRIG_TH) && vu_far) begin
            vu_valid_r        <= 1'b1;
            vu_axis_r         <= {1'b0, vu_ax_r};
            vu_val_r          <= (vu_vel > 8'd255) ? 8'd255 : vu_vel;
            vu_last[vu_ax_r]  <= vu_pos;
        end
    end
end

// ⭐ 接到 note_manager（⛔ 不再是硬接 0）
.vel_upd_valid_i (vu_valid_r),
.vel_upd_axis_i  (vu_axis_r),
.vel_upd_value_i (vu_val_r),
```

### 5.3 `top.v`：起音力度也改成位置式

```
⭐ 事件里的 `w3a_evt_vel` 现在是【常量 200】
⇒ ⭐ 改为：用【触发那一刻该轴的 pos】算出来
   （⭐ 事件通路里 `am_pos_in` 就是该轴的 pos ⇒ 现成的）
```

## 七、⚠️ 风险与取舍

| # | 风险 | 说明 / 缓解 |
|---|---|---|
| **1** | ⭐ **台阶声（zipper noise）** | 包络跟随 `sustain_level` 会**逐级跳**。⭐ 缓解：死区 16 码 + 每轴 164 µs 更新。<br>⚠️ 若上板听到"台阶" ⇒ ⭐ 加大死区或降低更新率 |
| **2** | ⚠️ **重触发窗口漏一拍** | `gate_mask` 在 ≤1 tick 内为 0 ⇒ 那一拍跳过。⭐ 影响可忽略 |
| **3** | ⚠️ **起音力度范围只有 [113, 255]** | 见 §四 的推论。⭐ 要更宽的动态需降 `TRIG_TH`（⭐ 另一话题） |
| **4** | ⚠️ **`vel_upd` 与 `note_on` 抢同一拍** | ⭐ 若同拍，`note_on` 先写 ⇒ `vel_upd` 后写 ⇒ 后者赢。<br>⭐ 实际两者不会同轴同拍（`vel_upd` 要求 `pos > TRIG_TH`，而 `note_on` 由 `event_extract` 的深阈+折射期控制） |
| **5** | ⚠️ **去掉 `>` 限制的连带影响** | 该限制原本是为"力度只增不减"设计的（⭐ 早期方案）。<br>⭐ 现在用户明确要"实时跟随" ⇒ ⭐ 去掉是正确的 |
| **6** | ⭐ **与"音量起伏"方案的相互作用** | ⭐ 两件事**互相独立**（一个是 lane 权重、一个是力度通路）<br>⭐ 但都会改变响度 ⇒ ⭐ **建议分开实施、分开上板验证**（⭐ 便于定位） |

## 十一、⭐⭐ 更正：两个方案**不是互相独立**（⭐ 用户指正，我接受）

> ⭐ 用户原话：「位置式力度和音量起伏不应该是相辅相成的吗，
>   因为起音就涉及到音量大小，还是说我理解有误，请你指出」

⭐⭐ **⇒ 用户理解正确，我此前说"两件事互相独立"是不准确的。**

| 层面 | 是否互相影响 | 为什么 |
|---|---|---|
| **数学上** | ⛔ 不影响 | 两者都是**乘性因子**（lane 权重 × 包络电平）⇒ 相乘 |
| ⭐ **经限幅器** | ⭐ **影响** ✅ | 力度大 ⇒ 电平高 ⇒ 软膝限幅介入更多 ⇒ ⭐ **拍峰被压** ⇒ 表观拍深变小 |
| ⭐ **起音一致性** | ⭐ **影响** ✅ | 起音电平同时取决于"包络峰值（力度）"与"拍相位（权重）" |

⭐⭐⭐ **但"一步一步改"的理由【仍然成立】** —— ⛔ 不是"它们独立"，
⭐ 而是为了**归因**：上板结果不对时能立刻知道是哪个改动造成的。
