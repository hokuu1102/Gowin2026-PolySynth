### ⭐ 为什么 A1 解释"挂音"

```
相邻轴同帧越阈 ⇒ 后一条事件【滞留 FIFO】⇒ 只在"下一次 push"时才吐出
⇒ note_off 被推迟到下次按键 ⇒ ⭐ 听感 = 挂音，"再按一下就好"
⇒ 若滞留的是本次演奏最后一条 ⇒ 🔴 永久不发 ⇒ 永久挂音（几分钟不停）
```
⭐ **与用户实测吻合**：「按两个及以上按键才触发」「按一阵之后」「再按同键能清掉」。

## 八、⭐ 跨文件审计发现（事件全通路，1/3 已回）

### 🔴 8.1 三级队列丢 `note_off` **均不可恢复**

`seq_arb` / `evt_merge` / `note_manager` 三级都**只计数、不恢复**；
`event_lost_clr_i` 在 `top.v` **硬接 `1'b0`** ⇒ **没有回灌路径**。
⭐ **"可见" ≠ "可恢复"** —— 这是单文件审计看不出来的。

### 🔴 8.2 `note_manager` 重触发窗口**吞掉 `note_off`**（⭐ 可达的挂音路径）

```
(f) 重触发段写在 case 之前，且【独立执行】
RT_LOW 期间每拍执行 gate_r[retrig_idx] <= 1'b1
⇒ 同拍到达的 note_off 清了 gate_r，⭐ 下一拍 RT_LOW 又把它拉回 1
⇒ 🔴 该 voice 无 off 地持续发声 ⇒ 永久挂音
```

**⭐ 修法（已确定）**：在 `note_off` 分支里**显式清 `gate_r[retrig_idx]`**：
```verilog
if ((retrig_state != RT_NONE) && (axis_r[retrig_idx] == cur_axis)) begin
    retrig_state <= RT_NONE;
    retrig_hold  <= 1'b0;
    gate_r[retrig_idx] <= 1'b0;   // ⭐ 新增：(g) 段在 (f) 之后 ⇒ 后者赢
end
```

### 🔴 8.3 `event_extract.FIFO_D = 4` **小于轴数 16**

on 分支**先置 `key_on` 再判满** ⇒ 同帧 ≥5 轴越阈时第 5 轴起 `note_on` **丢失**，
但 `key_on` 已是 1 ⇒ ⭐ **那个键这一轮彻底不出声**（"按下去没反应"）。
⭐ **`note_manager.FIFO_DEPTH=32` 单独看是够的** ⇒ 瓶颈在**上游写死的 4**。

## 九、⭐⭐⭐ B3 挂音：**根因确认并修复**（2026-09-28，红→绿闭环）

### 9.1 🔴 缺陷机制（精确）

```verilog
(f) 段：RT_LOW 期间【每拍】执行 gate_r[retrig_idx] <= 1'b1
(g) off 分支：if (gate_mask[i] && axis_r[i]==cur_axis) gate_r[i] <= 1'b0;
              └─ gate_mask[i] = gate_r[i] & ~hold_mask[i]
                 而压低期间 hold_mask[i]=1 ⇒ gate_mask[i] = 0
              ⇒ 🔴 【跳过该 voice】
同时 (g) 把 retrig_state 推回 RT_NONE（于是 (f) 不再管它）
⇒ ⭐ 若 note_off 恰好落在 (f) 抬 gate 的那一拍
   ⇒ 🔴 gate_r 永久卡 1 ⇒ 永久挂音
```

### 9.2 ⭐⭐ 决定性判据（Verilator 定向探针，**精确相位扫描**）

| 代码 | 结果 |
|---|---|
| ⭐ **原始** | `off_phase=1021 -> gate=1` 🔴 **STUCK**（`cleared=31 STUCK=1`）⇒ **BUG PRESENT** |
| ⭐ **修复后** | `cleared=32 STUCK=0` ✅ **PASS** |

⚠️ **踩过的坑**：第一版扫描**步长 64**（`0,64,...,960`）**跳过了 1023** ⇒ 原始代码也"PASS" ⇒ **假绿**。
⭐ **教训**：判"某相位相关的缺陷"时，**必须精扫边界**（`sample_tick` 附近），⛔ 不能只用粗步长。

### 9.3 ⭐ 为什么这解释用户的**全部**实测

| 用户实测 | 机制 |
|---|---|
| ⭐ **挂音音高 = 我按过的键** | ✅ 挂的是**键盘轴**的 voice（⛔ 不是伪事件/悬空引脚） |
| ⭐ **按同键/所有键都清不掉** | ✅ `retrig_state=RT_NONE` 后无人再清；再按会重进压低窗口 ⇒ 又被跳过 |
| ⭐ **"按了几次以后才会触发"** | ✅ **概率 ≈ 1/1024** ⇒ 低概率、随按键次数累积 |
| ⭐ **"是板1 代码的逻辑问题"** | ✅ 是 `note_manager` 的重触发状态机 |
| ✅ **断电才清** | ✅ 寄存器状态 |

### 9.4 ✅ 修法（⭐ 最稳健，⛔ 非最小改动）

```
① 单套全局寄存器 → ⭐ 每 voice 一位的 retrig_low[31:0] 位图
   ⇒ ⛔ 不存在"retrig_idx 被抢占 ⇒ 孤儿 voice"（同族缺陷）
   ⇒ ⛔ 不存在"gate_mask 永久 0 ⇒ 既不能发声也不能被分配"
② off 分支判据改用 (gate_r | retrig_low)，**并同时清位图**
   ⇒ (g) 在 (f) 之后 ⇒ ⭐ note_off 无条件优先
③ 顺带去掉 32 个 5 位比较器 ⇒ ⭐ 改善 Fmax
```
