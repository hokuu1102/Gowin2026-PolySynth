# ESP32 侧更正：`byte[7][3:0]` 是**轴号**，⛔ 不是鼓标记 —— 上一轮口径按 RTL 纠正

> 收件人：FPGA 线
> 触发：用户实测「bass 音色回传，全被标成【鼓】」
> 结论：**上一轮我们按《上行帧 byte7 口径补正》改的解码器是错的**（⛔ 是那封回函的 §二 误导，
> 我方也没先核 RTL 就跟着改了）。**地面真相在你们自己的 RTL 里**，一眼可核。

---

## 一、地面真相（`rtl/w3c/evt_upstream.v`）

```verilog
// :264
wire [7:0] b_axis = {2'b0, tm, ax};      // bit[5:4] = 音色 · bit[3:0] = 【轴号】
// :290-296
wire frame_w = { HDR, b_type, b_seq,
                 tick_ev_q[31:24], [23:16], [15:8], [7:0],
                 b_axis,
                 inc[31:24], [23:16], [15:8], [7:0],
                 b_vel, b_ck };          // = 14 B
```

⇒ **`byte[7]` = `{2'b0, timbre[1:0], axis[3:0]}`** —— 2+2+4 位**已经排满**，
⭐ **14 B 帧里没有任何 `is_drum` / `drum_type` 位**（内部 64 位字里的 `bit[5]`/`[8:7]`
**没有**被搬到上行帧里）。

⚠️ 上一轮的 §二 把 `seq_arb.v:417` 的
`evt_up_axis_o <= (pop_src == SRC_KDRUM) ? drum_type : 4'd0`
当成了"`[3:0]` = 鼓标记" ⇒ ⛔ **不成立**（见下方实测）。

## 二、用户实测（14 条，bass 音色）

```
显示 drum_type = 5 / 4 / 3 / 2 / 13 / 12 / 11 / 10
```

| 判据 | 说明 |
|---|---|
| **全部 > 3** | `drum_type` 只有 2 位 ⇒ 若真是它，**只可能是 0..3** ⇒ 🔴 它不是 drum_type |
| **每个音 -1，到 2 之后跳 13** | 那正是**轴号**被贪心分配器复用的节奏（我们网页按"最早空出的轴"分配）|
| **`[5:4]` 解出来全是 0** | = **BASS** ✓ —— 与用户所说"我用的 bass 音色"完全吻合 ✓ |

⭐ 反算（`axis = b7 & 0x0F`）：

```
显示 5  => axis=5   timbre=0 (BASS)
显示 4  => axis=4   timbre=0 (BASS)
显示 13 => axis=13  timbre=0 (BASS)      ...
```

⇒ 🔴 **`[3:0]` 是轴号**，不是鼓标记；用户看到的"全是鼓"是因为我方把
**每个轴号 ≠ 0 的音**都当成了鼓 ✗。

⚠️ 顺带修正上一轮那句"键盘打鼓走 `live_*` ⇒ 恒 `SRC_LIVE` ⇒ `[3:0] = 0`"：
实测 **live 路径的 `[3:0]` 就是真实轴号**（5/4/3/2/13/12/…）⇒ 那条
`evt_up_axis_o` 的 `SRC_KDRUM` 选择**不在 live 路径上**，或者本 build 没生效。
📌 请你们核一下这条到底在哪条路径上生效 —— 但**无论如何**，`[3:0]` 都不能当鼓标记用
（它对不同来源语义不同，⛔ 不可判）。

## 三、⚠️ 另一个实测异常：**live 的 `note_off` 帧 `vel` 字段像是脏数据**

```
note_on  vel = 80 / 83 / 81 / 80 / 80 / 81 / 80      ← 正常（用户弹的力度）
note_off vel = 250 / 229 / 255 / 185 / 235 / 241     ← 🔴 不合理
```

按 RTL `wire [7:0] b_vel = vl;`（`vl = hold_q[...]`）⇒ 那几帧的 `vl` 就是这些值。
正常的 note_off 力度应是 **0 或很小** ⇒ 🔴 疑似 **`hold_q` 里 vel 字段在 off 事件上未被赋值/是陈旧值**。

📌 请你们查：
1. live 路径的 **note_off 事件**是怎么构造的？`vel` 字段有没有写？
2. 如果没有语义，⭐ 建议 **off 帧的 `vel` 恒写 0**（我们这边对 off 的 vel 不做任何判断，
   但它是"解析器是否错位"的最灵敏探针 —— 脏值会让人怀疑整帧错位，⛔ 浪费排查时间）。
