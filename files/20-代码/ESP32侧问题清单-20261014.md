## 0. 我方本轮已修的（你们不必查，但要知道现象已变）

### 0.1 🔴 进度条分母取错 —— 已修

**现象**：PC 与屏上的播放进度**跑飞 / 早早到 100%**。

**根因**：本曲总长 `ttot` 取的是**池里末帧**的 tick，
而谱面可以是**多轴交织**的（每个 `axis` 是一条独立时间线），
交织存放后**整池 tick 不单调**，末帧未必是时间最晚的那帧。

实测（我方测试谱面，111 帧）：

```
axis=0:  31 帧, tick 0 .. 7200
axis=1:  48 帧, tick 8160 .. 100320     ← 时间最晚的在轴 1
axis=2:  32 帧, tick 3840 .. 19200      ← 而末帧恰好属于轴 2
```

⇒ 末帧 tick = `19200`，但全曲真正到 `100320`（**10 秒 vs 52.25 秒**）。

**修法**：`ttot` 改为**池内所有帧 tick 的最大值**。
**验证**：修复前 `ttot=19200`，修复后 `ttot=100320` ✓

### 0.2 pump 周期被 FreeRTOS tick 卡在 10 ms —— 已修

**现象**：放水节奏与音乐时间对不上。

**根因**：`CONFIG_FREERTOS_HZ=100` ⇒ 1 tick = 10 ms
⇒ `pdMS_TO_TICKS(2)` = 0.2 ⇒ 取整 0 ⇒ 兜到 1 tick = **10 ms**。

**修法**：`CONFIG_FREERTOS_HZ` 100 → **1000**。
**验证**：实测 pump 周期 `pum` 从 **9996 us → 2065 us** ✓

### 问题 2：起播等待时间能否缩短

**现状**：起播后有 **10.4 秒**的提前量（`lead=20000` tick @ 120 BPM / 960 PPQN）才开始出声。

**我方理解的取舍**：

| 调大 | 调小 |
|---|---|
| 抗 BLE 抖动（不会掉音） | 起播快 |
| FPGA 缓冲可能溢出（**静默丢**） | 一卡就 underrun（**掉音但可见**） |

**我方需要的**：**FPGA 侧的缓冲容量**（能装多少 tick / 多少事件）。

⭐ 有了这个数，我方就能算出"**抗抖动前提下最短的提前量**"。
⚠️ 现在的 20000 是**保守值**，⛔ 不是算出来的。
