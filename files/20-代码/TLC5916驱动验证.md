# TLC5916 驱动验证

> **状态**：RTL 与功能仿真已通过；真芯片时序、引脚约束和 LED 电流尚待上板验证。

## 一、范围

`rtl/drivers/tlc5916_driver.sv` 是单颗 `TLC5916ID` 的正常模式串行驱动，负责将 8 位 LED 图案以 MSB first 顺序送入芯片，再产生锁存脉冲。

左手区共有两块板，每块板使用一颗 TLC5916。本模块只控制一颗；系统顶层集成时应实例化两次，不在本驱动内合并两颗芯片的状态。

## 二、接口与参数

| 名称 | 方向 | 含义 |
|---|---|---|
| `clk` | 输入 | 系统时钟，默认 50 MHz |
| `rst_n` | 输入 | 低有效、**同步复位** |
| `start` | 输入 | 空闲时拉高一拍，锁存并发送 `led_data` |
| `led_data[7:0]` | 输入 | OUT7 到 OUT0 的亮灭数据，1 表示开启对应输出 |
| `outputs_enable` | 输入 | 高有效的逻辑使能，驱动内转换为低有效 `tlc_oe_n` |
| `tlc_clk` | 输出 | TLC5916 数据时钟 |
| `tlc_sdi` | 输出 | TLC5916 串行数据 |
| `tlc_le` | 输出 | 锁存使能，8 位发送完成后产生一次高脉冲 |
| `tlc_oe_n` | 输出 | 低有效输出使能；复位时保持高电平以燄灭 LED |
| `busy` | 输出 | 正在发送或锁存时为 1 |
| `done` | 输出 | 一次传输完成后拉高一个系统时钟周期 |

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `CLK_HZ` | `50_000_000` | 系统时钟频率 |
| `DATA_HZ` | `1_000_000` | TLC5916 数据时钟频率 |

驱动在 `start` 被接受时锁存 `led_data`，因此发送期间修改输入数据不会破坏当前帧。`busy=1` 时的新 `start` 不会被接受。

## 三、运行仿真

在仓库根目录打开 PowerShell，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\sim\run_tlc5916.ps1
```

若要在仿真通过后打开 GTKWave：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\sim\run_tlc5916.ps1 -OpenWave
```

脚本会优先从 `PATH` 寻找 Icarus Verilog，也支持本机已有的 `D:\iverilog\bin` 安装位置。仿真产物生成在 build 下的 sim/tlc5916 子目录，该目录已被 `.gitignore` 排除。

## 四、自动验证项

`tb/drivers/tb_tlc5916_driver.sv` 通过公开接口自检查，不依赖驱动内部状态名。当前覆盖：

- `8'h00`、`8'hA5`、`8'hFF`、`8'h3C`、`8'h5A` 的完整传输；
- 每帧恰好 8 个 `tlc_clk` 上升沿；
- MSB first 串行顺序和接收数据一致；
- 每帧恰好一次 `tlc_le` 锁存脉冲；
- `busy`、`done` 及 `tlc_oe_n` 的完成状态；
- `rst_n` 只在 `clk` 上升沿生效，复位后返回空闲态且关闭 LED 输出。

全部检查通过时，终端最后会显示：

```text
PASS: all TLC5916 tests completed successfully
```
