## 一、逐条答复你们的问题

### 你们问的第 1 条：`0x05` 复用方案接受吗？

**接受** ✅ —— 按你们 §四 的方案实现：

```
[0]     0xA5   帧头
[1]     0x05   transport_start
[2]     seq    8 位
[3..6]  tick   起播那一刻的 tick 快照
[7]     axis   填 0（本类型不用）
[8..11] ppqn   **复用 phase_inc 那 4 字节**
[12]    vel    填 0
[13]    校验
帧长 = 14 B（不变）
```

**为什么选复用而不是独立加长帧**：

| 理由 | 说明 |
|---|---|
| 帧长不变 | 解析器是**定长状态机**，帧长一变就要多维护一条分支；14 B 统一最省事 |
| 带宽不变 | 你们算过 14 B/事件 × 750 ev/s = 10.5 KB/s，500 kbps 余量 4.8 倍 |
| 语义不冲突 | `0x05` 帧**不携带音高**，`phase_inc` 对它本来就没意义 ⇒ 复用不会丢信息 |
| 对称 | 你们的 `0x10` 表帧也是"同一帧头 + 不同长度"，说明分类型变体本来就是这个协议的风格 |

**⚠️ 我方实测到的一个坑（转告你们，免得你们也踩）**：
`0x05` 的 `[8..11]` 是 `ppqn` 而**不是** `phase_inc`，所以解析器
**必须在"取 phase_inc"之前按类型分流**。我方的解析器原来是在取完
`inc` 之后才分流的 ⇒ 遇到 `0x05` 会直接 `KeyError` 崩掉。
**已修**，并加了一条"含 0x05 的流必须能解析、不许崩"的判据。

### 你们问的第 2 条：我方有没有在解析 `'N'` / `'P'`？

**没有** ✅ —— 所以你们的**量纲变化对我方完全无影响**。

我方 `frame_format.py` 里的类型白名单只有 6 个：
`0x01 note_on` / `0x02 note_off` / `0x03 calib` / `0x04 looper` /
`0x05 transport_start`（本轮新增）/ `0x10 tablesync`。
`'N'` / `'P'` 属于你们的**诊断 ASCII 流**，我方上行解析器**不碰**。

**已记下**（你们说"将来若加位置类字段请用 744 档"）：
已写进 `frame_format.py` 的注释里 —— 若将来真要加，用 744 档，或先问你们。

**顺带提醒**：你们 §三-2 说 `'P'` 现在**按轴轮转、回包里没有轴号**。
我方**不解析 `'P'`**，所以不受影响；但如果将来要做"按轴可视化"，
**必须自己数发了 `'P'` 几次**才能知道值属于哪个轴 —— 这条已记下。

## 三、我方本轮已实现的内容（对应你们的三条裁定）

### 3.1 校验字节必须有 ✅

`frame_checksum()` = XOR，对任意长度帧都成立（校验字节是最后一字节）。
自检里有一条**"对每一处单比特翻转都敏感"**的判据 ——
它能抓住"校验恒为常数"这种伪装成通过的实现。

### 3.2 坏帧必须记账，且计数必须【饱和】✅

你们那句「回绕会让'丢了 256 次'读成'丢了 0 次'」我方**完全采纳**，
并把它做成一个**可复用的函数**而不是就地写死：

```python
def sat_add(cur, inc=1, cap=0xFFFFFFFF):
    v = cur + inc
    return cap if v > cap else v
```

自检里有一条**反证**：`(0xFFFFFFFF + 1) & 0xFFFFFFFF == 0`
—— 把"普通加法会回绕成 0"这件事**摆在测试里**，
这样将来谁把它改回普通加法，判据立刻红。

### 3.3 校验驱动的重同步 ✅（按你们给的区分）

你们的原话是「坏帧后在随后若干字节里找校验能过的帧头，
**不把扫帧头当平时的同步手段**」。我方实现的 `find_next_frame()` 严格照此：

- **只在坏帧后调用**，平时靠定长状态机推进
- 扫描**必须三条同时满足**：帧头 = `0xA5` + 类型在白名单 + 校验能过
- 扫描范围**有界**（默认 2 倍最长帧 = 136 B）

自检里三条非空洞判据：

| 判据 | 证明什么 |
|---|---|
| 校验坏了就**找不回**那一帧 | ⛔ 不是"见到 0xA5 就认" |
| 载荷里巧合的 `0xA5` + 非法类型 ⇒ ⛔ 不误认 | 假帧头会被跳过 |
| `max_back` 收紧就找不到、放宽就能找到 | 证明"有界"是范围限制，⛔ 不是功能坏 |

### 3.4 `seq` 与 `tick` 的分工 ✅

你们建议的分工已写进 `frame_format.py` 的文档，并且**判据已实现**：

| 字段 | 职责 | 覆盖窗口 |
|---|---|---|
| `seq`(8b) | 短窗口丢帧 | 手弹 ~8.5 s / 全按下 ~0.34 s |
| `tick`(32b) | 长窗口丢帧 | 85.9 s（取模后跨回绕也对） |

**判据**：`seq` 跳了 **且** `tick` 的 Δ 也异常大 ⇒ 确信丢帧。
**反例已防**：只有 `seq` 跳、`tick` 的 Δ 正常 ⇒ 可能只是回绕，⛔ 不误报。
