# 串口屏显示清单与 EC11 映射（纯梳理，2026-10-16）

> 本文性质：只读梳理 + 方案建议。未改任何 `rtl/` / `tb/` / `.ps1`（全量回归 `pwsh-1163` 在跑）。
>
> 触发需求（用户原话）：
> > "效果器的参数还是希望能用 EC11 手拧增减，但是可能需要配合串口屏。
> > 现在先梳理一下串口屏需要显示的内容。比如指板模式、滑音 on/off、当前起始音、BPM、效果器链等等参数。
> > 先列出来内容，不一定要放在一个屏幕上"
>
> 本轮（第二轮）修订，用户拍板 3 条：
> 1. 屏 7 寸（尺寸已定，按 1024x600 重算三屏全部坐标）。
> 2. 音量颤音也由推子调，推子应该能切到"音量颤音"这一档。
> 3. 屏 2 要体现"效果器链的链"，这是能体现特点的地方。
>
> 上一轮（第一轮）已拍板 5 条，仍然有效：
> 1. 页数可以集合一点。
> 2. 屏直接接 FPGA 的 `D14`/`D15`，不走 ESP32 中转。
> 3. 推子负责颤音与实时变调，EC11 负责效果器程度参数，两者是不同域，不冲突。
> 4. 专门做一页效果器链，点击某个参数的控件就激活 EC11 对该参数的调节。
> 5. 本文不用任何 emoji 或装饰符号。
>
> 第三轮修订（本轮），用户拍板 1 条，落实为 3 处：
> 1. "效果器链里面也保留音量颤音这个大块吧，点到这个的时候推子自动切换到音量颤音档位"。
>    落实为：链式图保留 5 个节点（含音量颤音），音量颤音节点自带 depth / rate 两个控件；
>    点这个节点（或它的 depth / rate 控件）就发一条"推子切到档 2"的命令，节点高亮，之后由推子连续扫。
>    EC11 目标清单**定为 6 个**（gain / trim / chorlen / dlylen / fb / mix），depth / rate 归推子档 2。
>
> 第四轮修订（本轮），用户拍板 1 条，落实为 2 处：
> 1. "点失真/合唱/延迟，高亮代表开启，再点一下表示关闭。总之就是点一下就翻转状态，不能只有参数调节"。
>    落实为：点**节点标题** = 翻转该效果器开/关（屏本地翻转掩码对应位，再用**现有的** `71 10` 帧整帧写出），
>    高亮 = 开启；点**参数控件** = 设 EC11 目标。音量颤音节点没有开关，点它只做"推子切到档 2"。
> 2. "不一定要实现翻转，我的意思是状态翻转。反正能实现功能就行了"。
>    落实为：**不新增任何协议、不新增任何寄存器**。屏 2 这一页的交互全部复用现有帧
>    （参数写入用 `71 11..18`，开关用 `71 10`）；凡需要动 rtl 的，一律标成"下一轮可选增强"，
>    不塞进最小可用第一步（见第八节）。
>
> 取证方式：逐个 `grep` / `read` 代码，不照抄任务书给的起点信号（其中两条已与代码不符，见 1.3）。
>
> 代码基线：`rtl/top.v` 7130 行。本轮刚落地 bit6 逐事件引导、心跳灯三态、键14 音高归零、方案B、指板多弦、延迟 send-return、失真 x256 加 `drive`、合唱下界 129。

## 〇、一句话结论

| 问 | 答 |
|---|---|
| 屏要显示什么 | 30 条运行时状态（见第一节全表）。按使用场景分 3 屏：演奏加节奏 / 效果器链 / 标定加调试。 |
| 屏尺寸 | 已定：7 寸，1024x600。全部坐标按此重算（第二节）。 |
| EC11 现在调什么 | 只有 2 个对象：`enc_obj_r = 0` 调 BPM，`= 1` 调变调。按压换对象。已接线并可用（`top.v:757-796`）。 |
| EC11 改成调什么 | 由屏点选目标，**定为 6 个**（失真 / 合唱 / 延迟 的 gain / trim / chorlen / dlylen / fb，加两级共用的 mix，见 4.2）。EC11 只增减当前目标，对象寄存器不必扩到 11 个，只要"屏指定的那一个"。 |
| 推子调什么 | 三个档：档 0 = 变调，档 1 = 音高颤音（上电默认），档 2 = 音量颤音（本轮新增，需要改 `fader_gear`，见第五节）。 |
| 点哪里决定谁来调 | 点效果器**节点标题** = 翻转该效果器开/关（高亮 = 开、灰 = 关，并带文字）；点**参数控件** = 设 EC11 目标。三条通路互相独立，见 2.2.3。 |
| 开关翻转怎么发帧 | **不新增协议**：屏本地维护掩码缓存，点击时翻转对应位，再用**现有的** `71 10 <新掩码> FF FF FF` 整帧写出（该帧早已实现，见 `uart_ui.v:428-430`）。风险一行：掩码没有回读时屏的缓存可能过期，见 6.5。 |
| 档 2 的两条进入方式 | 推子自己的切档循环（串口 `'J'` / 矩阵 idx 5）与屏点选（`65 09 FF FF FF`，**下一轮可选增强**），两条写**同一个寄存器** `fader_gear.gear_o`，见 5.5。 |
| 最大的问题 | FPGA 到屏的"值回读"通路完全不存在。`uart_ui` 的发送口被接成 `tx_busy_i = 1'b1`（`top.v:1217`），而且该模块内部根本没有发送状态机（见 3.2）。屏上显示的所有数字都只是它自己发过的缓存。 |
| 第二大的问题 | BPM 在 FPGA 里没有数字寄存器。tempo 状态只有 `play_seq.tick_inc_o`（32 位相位增量，`top.v:2521`）。屏上要显示"BPM = 120"，必须先加一个 BPM 寄存器（见 6.4）。 |
| 与 2026-10-14 裁定的关系 | 不冲突，是不同域。那次裁定说效果器参数不用 EC11、改走推子参数页；本次把"音量颤音"明确划给推子档 2，EC11 只负责失真/合唱/延迟的程度参数。三组目标寄存器完全不重叠（见 5.1 核验）。 |

屏尺寸已定：7 寸，分辨率 **1024 x 600**（`files/30-方案决策/产品形态决议清单.md:644` 写 X2 7 寸；`files/10-硬件/采购与验证清单.md:339` 写 X2 7.0 寸 1024x600，两者一致）。

全部三屏按同一套基准重算：

| 项 | 值 |
|---|---|
| 分辨率 | 1024 x 600 |
| 顶部常驻状态条 | y 0..36（高 36，每屏都有，见 2.5） |

| 32 号字 | ASCII 16 px，中文 32 px，行高 64 |

| 每列可放行数（32 号） | 564 / 64 = 8 行 |
| 每列可放行数（24 号） | 564 / 44 = 12 行 |

三屏总览：

| 屏 | 控件数 | 布局 | 字号 | 结论 |
|---|---|---|---|---|

若屏 3 也要 32 号字，就把 16 轴原始码做成弹出子页，变成 4 屏。本文按 3 屏给方案，并把"16 轴子页"作为可选。

### 2.2 屏 2 效果器链（链式布局，本轮重点）

用户要求体现"效果器链的链"。先把 RTL 里的真实顺序核清楚。

#### 2.2.1 链的真实顺序（从 `rtl/w3c/fx_chain.v` 逐级核实）

| 级 | 模块 | 文件:行号 | 使能来源 | 本级参数 | 输入 |
|---|---|---|---|---|---|
| 1 | 失真 `u_dist` | `fx_chain.v:214-226` | `en_mask_i[0]`（`:180`） | `dist_gain_i`（增益）、`dist_trim_i`（补偿） | `sample_i`（链输入） |
| 2 | 合唱 `u_chorus` | `fx_chain.v:243-262` | `en_mask_i[1]`（`:181`） | `chor_delay_i`（长度）、`dly_mix_i`（干湿，共用） | `d1_sample`（失真输出，`:250`） |
| 3 | 延迟 `u_delay` | `fx_chain.v:277-290` | `en_mask_i[2]`（`:182`） | `dly_delay_i`（长度）、`dly_fb_i`（反馈）、`dly_mix_i`（干湿，共用） | `d2_sample`（合唱输出，`:284`） |
| 4 | 混响 | `fx_chain.v:300-301` | 无（留位直通） | 无 | `d3_sample`（延迟输出） |
| 5 | 音量颤音 `u_trem` | `fx_chain.v:322-334` | 硬接常开 `en_i(1'b1)`（`:330`） | `trem_depth_i`（深度）、`trem_rate_i`（速率） | `d4_sample`（等于 `d3_sample`） |

结论（与用户给的图一致，并有两条 RTL 事实要补）：

```
输入 -> [失真] -> [合唱] -> [延迟] -> [混响(留位直通)] -> [音量颤音] -> 输出
        开/关      开/关      开/关     无参数               常开
        gain       chorlen   dlylen                        depth
        trim                 fb                            rate
                             mix(与合唱共用)
```

补两条 RTL 事实：

1. **混响是留位直通**（`fx_chain.v:300-301`：`d4_valid = d3_valid; d4_sample = d3_sample;`），没有逻辑。链图上画成一个灰色占位节点，让链看起来完整，但不可点、无参数。
2. **合唱与延迟各自独立，串联顺序是合唱在前**（`fx_chain.v:191-197` 原文："延迟与合唱各自独立（用户要求能同时开）；合唱走自己的短延迟线，延迟走自己的长延迟线；两者串联（合唱在前）=> 延迟回声里带着合唱"）。所以链图上合唱必须在延迟左边，顺序不能画反。
3. **mix 是两级共用**：`dly_mix_i` 同时接到 `u_chorus.mix_i`（`:252`）与 `u_delay.mix_i`（`:286`），而顶层只有一个寄存器 `ui_fx_mix`（`top.v:6371`）。所以链图上 mix 画在合唱与延迟之间，标注"两级共用"。
4. **fb 只属于延迟**：`u_chorus.fb_i` 硬接 0（`fx_chain.v:252`，原文理由："合唱线只有约 15 ms 且被 LFO 调制，一旦加反馈，抽头就变成共振梳状滤波器，音色发金属声；真机 chorus 没有反馈"）。所以 fb 只画在延迟节点下。
5. **音量颤音固定常开，没有使能位**（`fx_chain.v:184-189`、`:305-307`：深度为 0 时 `g = 256` => `(x 乘 256) >> 8 = x`，逐位等于输入 => 推子推到零就等于关掉，不需要开关）。所以链图上它的"开/关"栏写"常开"，没有开关控件。
6. **失真没有类型选择**：`dist_sel_i` 在顶层硬接 `2'd0`（`top.v:6369`，注释："没有运行时寄存器，模块里 sel 1/2/3 语义上就等于 0"）。所以屏上不要做"失真类型"下拉。
7. **音量颤音节点的两个参数由推子调**（用户第三轮拍板）：depth 与 rate 在链上保留显示，但点它们不是"选 EC11 目标"，而是"把推子切到档 2"。所以它虽然还在 `fx_chain` 里（链的最后一"大块"），调它的手是推子。见 2.2.3 与 5.4。
8. **三个效果器节点的标题是开关**（用户第四轮拍板）：点 [失真] / [合唱] / [延迟] 的名字就翻转它的开/关，点一下翻一次，不是长按、不是双击、不是进子页。使能来源是 `fx_mask` 的 bit0/bit1/bit2（`fx_chain.v:180-182`）。**音量颤音节点没有开关**（固定常开，见上面第 5 条），所以点它只做"推子切档 2"。见 2.2.2 与 2.2.3。
9. **混响节点的标题不可点**（它没有逻辑，见上面第 1 条）。

高亮规则（两类必须能同时显示且不混淆）：

| 高亮种类 | 用在哪里 | 建议视觉表现 | 含义 |
|---|---|---|---|
| **开关状态高亮** | 三个效果器节点的**名称行**（层 B） | 名称行**整行亮底** + 状态行文字 `开`；关时名称行**灰底** + 状态行文字 `关` | 亮 = 该效果器**开启**，灰 = **关闭**。这是"状态"，不是"选中" |
| **EC11 目标高亮** | 被选中的那个**参数控件**（层 C） | 参数控件**加粗边框**（用矩形控件当框）+ 数值变色 `FFFF00` | 亮边框 = **这个参数被选中**。这是"选中"，不是"状态" |
| 推子接管高亮（下一轮，见 2.2.5） | 音量颤音节点名称行与它的 depth / rate | 橙底 `FF8000` + 双线边框 + 文字 `推子控制` | 这两个参数**由推子连续控制** |
| 无高亮 | 其余节点与控件 | 暗底 + 细边框 | 常态 |

为什么"开关状态"用**整行亮底**、而"选中"用**加粗边框**：两种语义不同（一个是"这个块开不开"，一个是"我在调哪个数"），视觉通道也要不同。若都用"亮底"，用户会分不清"这个效果器开着"和"我在调这个效果器的参数"，而这两件事可以同时成立。

补充三条：

- 两类高亮**可以同时出现**（选中了失真增益，同时合唱是关的）。这是"状态"与"选中"两件事的可见形式，不是冲突。
- 开关状态**必须同时有文字**（`开` / `关`），不能只靠颜色：颜色在强光/色弱下不可靠，而且 `开` 这个字本身还兼作"点了会变关"的提示。
- 高亮分两级：点下去**本地立即高亮**（零延迟），随后由 FPGA 的**回读确认**（读回 `ui_fx_mask`）成为权威状态。第二级对"开关状态"尤其必要，理由见 6.5。

#### 2.2.3 两种点击目标（本轮的核心交互）

| 点哪里 | 做什么 | 高亮含义 |
|---|---|---|
| **点节点标题**（失真 / 合唱 / 延迟 的名字，层 B 的名称行） | **翻转该效果器的开/关**：屏本地把掩码缓存的对应位翻转，再用**现有的** `71 10 <新掩码> FF FF FF` 整帧写出。点一下翻一次（不是长按、不是双击、不是进子页） | **亮 = 开启，灰 = 关闭**（同时有文字 `开` / `关`） |
| **点节点下方的参数控件**（gain / trim / chorlen / dlylen / fb / mix，层 C） | **选中该参数**（设 EC11 目标）。需要动 rtl，属**下一轮可选增强**（见 2.2.5）；但**参数本身的最小可用路径不受影响**：屏可以直接用现有 `71 11..18` 帧改数值 | **亮边框 = 该参数被选中** |
| 点音量颤音节点标题或它的 depth / rate | 推子切到档 2（**下一轮可选增强**，见 2.2.5）。**它不翻转任何开关**（音量颤音固定常开） | 橙 = 推子在调 |
| 点混响节点标题 | 什么都不发（不可点） | 无（留位直通，无逻辑） |

设计约定：

1. **翻转就是"点一下翻一次"**：不是长按、不是双击、不是进子页。TJC 的触摸事件本身是"按下即发一次 `0x65`"，屏侧在收到触摸回调时翻转本地缓存并发一帧即可。
2. **音量颤音节点没有开关**（它固定常开，`fx_chain.v:330` 硬接 `en_i(1'b1)`），所以点它只做"推子切档 2"，不翻转。
3. **两类点击目标各自独立**，不会"点错东西"：名称行 = 开关，参数控件 = 选中。混响节点标题不可点。
4. **点参数控件时推子档不动**（推子与 EC11 是两条独立通路，各自保持自己的目标）。这一条只在下轮增强落地后才有实际影响，届时若要改成"自动切回档 0/1"，再单独确认。

#### 2.2.4 点击时发什么帧（原则：不新增协议）

| 交互 | 屏发出的帧 | FPGA 侧落地 | 需要动 rtl 吗 |
|---|---|---|---|
| **开关翻转**（点节点标题） | `71 10 <新掩码> FF FF FF` | `fx_mask_o <= val_q`（**早已实现**，`uart_ui.v:428-430`） | **不需要** |
| **参数改值**（滑条 / 数字 / 加减按钮） | `71 11..18 <值> FF FF FF` | `fx_*_o`（**早已实现**，`uart_ui.v:431-483`） | **不需要** |
| 选中参数（供 EC11 手拧） | `65 03..08 FF FF FF` | `enc_tgt_r` | 需要，**下一轮可选增强** |
| 推子切档 2 | `65 09 FF FF FF` | `gear_sel2_i` | 需要，**下一轮可选增强** |
| 推子档循环 | `65 13 FF FF FF` | `gear_next_o` | 需要，**下一轮可选增强** |
| 退出选中 | `65 14 FF FF FF` | `enc_obj_r` 回 0 | 需要，**下一轮可选增强** |

**本轮只做前两行**（零 rtl 改动）。后四行是设计留档，落地见 2.2.5。

开关翻转的具体流程（屏侧三步，不需要 FPGA 配合）：

```
1. 屏收到触摸回调（TJC 的 0x65）
2. 屏本地掩码缓存  mask_local <= mask_local ^ 对应位
3. 屏发 71 10 <mask_local> FF FF FF
4. 屏按新的 mask_local 重绘该节点（亮底/灰底 + 文字 开/关）
```

#### 2.2.5 下一轮可选增强（需要动 rtl，不塞进最小可用第一步）

| 增强 | 要动什么 | 为什么不在第一步 |
|---|---|---|
| EC11 选中参数（`65 03..08`） | `uart_ui` 加 `enc_up_i` / `enc_dn_i` / `enc_tgt_o`；加 8 个影子字节寄存器；`enc_obj_r` 扩到 2 位 | 要改两个 RTL 模块 + 重跑 `tb_uart_ui`。而**参数本身用现有 `71 11..18` 帧已经能改**，不阻塞屏 2 上线 |
| 推子切档 2（`65 09`） | `uart_ui` 加 `gear_to_trem_o`；`fader_gear` 加 `gear_sel2_i` 与三态切档；`top.v` 加 mux | 要改三个 RTL 模块 + 改 `tb_fader_gear` 的 6 处判据 + 一次 PnR |
| 推子档循环 / 退出选中（`65 13` / `65 14`） | `uart_ui` 加两个单周期脉冲输出 | 与上面两条同批做更省 |
| 掩码"原子翻转"（FPGA 侧异或） | `uart_ui` 加 3 个异或分支 | **本轮不做**（用户澄清"不一定要实现翻转，状态翻转就行"）。现有做法在单人使用时够用，风险见 6.5 |

"推子切到档 2"落地时的做法（设计留档，本轮不动）：`uart_ui` 出一个单周期脉冲 `gear_to_trem_o`，顶层 OR 进 `fader_gear` 的新输入 `gear_sel2_i`，由它把 `gear_o` **直接写成 `2'd2`**（与当前档位无关）。不用"连发若干次 `'J'` 让它循环过去"：那样落点取决于当前档位，且"回读 -> 算次数 -> 发脉冲"之间档位可能被串口或矩阵键改掉，有竞态。

## 三、接线：屏直连 `D14` / `D15`

### 3.1 现状（已核）

| 项 | 事实 | 出处 |
|---|---|---|
| 物理口 | `D14`（RX）/ `D15`（TX），走 `XH_SCREEN` | `top.v:488-489` |
| 该口承载 | 调试加命令加串口屏共用一条 | `top.v:1109` 明写 |
| 屏到 FPGA | 活的。`uart_ui` 解析 TJC 返回帧 | `uart_ui.v:336-517` |
| FPGA 到屏 | 不通。`tx_busy_i` 接死 | `top.v:1217` |
| ESP32 独立口 | `G22`（RX）/ `G21`（TX），走 `XH_ESP32` | `top.v:523-524` |
| 该口承载 | 曲谱接收（`evt_uart_rx`）加上行事件帧（`evt_upstream`） | `top.v:1565`、`:5807` |
| 回包镜像 | 命令回包同时喂 `u_uart_tx`（板载 `D15`）和 `u_uart_tx_esp`（`G21`） | `top.v:1955-1962` |

按用户拍板，屏走 `D14`/`D15` 直连 FPGA。原方案里"屏挂 ESP32 的 `GPIO4`/`GPIO5`"这条支路删除，不再考虑。

### 3.2 必须做的三件事

**第一件：FPGA 到屏的发送通路（这是最大的一块）**

必须澄清一个事实：`uart_ui` 内部**根本没有发送状态机**。`tx_start_o` / `tx_data_o` 在全模块只出现三处，都是"清零"：

```
rtl/w3c/uart_ui.v:317-318   （复位分支）tx_start_o <= 1'b0; tx_data_o <= 8'd0;
rtl/w3c/uart_ui.v:326       （每拍默认）tx_start_o <= 1'b0;
```

所以 `top.v:1217` 的 `tx_busy_i = 1'b1` 不是"把一个能用的发送器关掉"，而是"把一个**从未被驱动**的口标成永久忙"。要"接活 TX"实际是**新写一个发送器**，不是把现成的接上。这一点直接影响工作量估算。

两条实现路线：

| 路线 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A（推荐） | 在 `uart_ui` 内新写回读发送器：一个文本拼装 FSM，把 `tx_start_o` / `tx_data_o` 接进 `u_tx_fifo` 的 `push_i` / `data_i`，`tx_busy_i` 接 `~txf_ready` | 6 个效果器参数寄存器加 EC11 目标寄存器已经在模块内，回读它们零引线 | `uart_ui` 变大；其余 21 条状态要新增输入端口 |
| B | 新增独立模块 `rtl/w3c/hmi_status.v`，照 `pos_probe.v` 的成熟结构（文本拼装加 ready 握手加 `QUEUE_WHEN_BLOCKED`），保持 `uart_ui` 只收不发 | 对 `uart_ui` 的接收 FSM 零风险 | 6 个参数寄存器要引出（或让 `hmi_status` 只读 `ui_fx_*` 的顶层线，反正已经在顶层） |

无论走哪条，**多字节文本必须一次独占 TX 通路**，不能与命令回执交错。理由是 `uart_tx_fifo.v:116-129` 记录的那条教训：上游若只看 `ready_o`（队列没满）就开新包，两个包会在 FIFO 里首尾相接，接收端按行读就错位（实测症状 `0\n\nP217`）。现有先例是 `rec_dump` 的导出通路，`top.v:3752-3758` 的注释写着"Export bypasses this FIFO and owns both UARTs until its footer ends. Normal replies queue here; ready-aware producers pause during export."，建议照它做。

另外，回读通路的时钟必须用慢使能（例如 1 kHz），不要进 50 MHz 关键路径，理由见第九节。

**第二件：新增回读帧**，见第六节。

**第三件：波特率对齐**，见 3.3。

### 3.3 波特率：屏侧要配多少

先说清楚一个容易混的点：`uart_ui` 的 `BAUD` 参数**不决定实际波特率**。它只用来算空闲归位阈值（`uart_ui.v:197-199`：`BYTE_CLK_I = (CLK_HZ + BAUD/2)/BAUD`）。实际波特率由 `uart_rx.BAUD_DIV` 和 `uart_tx.BAUD_DIV` 决定（`BAUD_DIV = 50 MHz / 波特率`）。

现值的两处不一致（都是事实，不矛盾）：

| 位置 | 值 | 说明 |
|---|---|---|
| `uart_ui.v:61` 模块默认 | `BAUD = 1000000` | 只有 `tb/w3c/tb_uart_ui.sv` 用它 |
| `top.v:1188` 交付实传 | `.BAUD(500_000)` | 与 `uart_rx.BAUD_DIV=100` 同档 |
| `uart_rx`（`top.v:1095`） | `.BAUD_DIV(100)` | 500 kbaud，50 MHz / 500 k 等于 100，整除，零误差 |
| `uart_tx`（`top.v:1924`） | `.BAUD_DIV(100)` | 同上 |

所以**上板实际跑的是 500 kbaud 8N1**，屏侧必须配 500000。

可选档位（来自 `uart_rx.v:28-34` 的表）：

| 波特率 | BAUD_DIV | 50 MHz / 波特率 | 误差 | 备注 |
|---|---|---|---|---|
| 1 M | 50 | 50.000 | 0%（整除） | 交付默认曾是它，但 2026-09-24 实测本板有误码，已降档 |
| 500 k | 100 | 100.000 | 0%（整除） | 现值。2026-09-24 起交付档 |
| 460800 | 108 | 108.51 | 0.47% | 标准档，对端兼容性好 |
| 230400 | 217 | 217.01 | 0.005% | 备选 |
| 115200 | 434 | 434.028 | 0.006% | 历史档位 |

**未确认项（必须查屏手册）**：淘晶驰 TJC 的 `bauds` 属性是否支持 500000。这个值**不是标准波特率**。已知事实：ESP32 侧那块 T1 屏（`TJC3224T120_011R_A01`）的工程 `program.s` 里写的是 `bauds=115200`（`esp32/串口屏上位机使用说明.md:281`、`esp32/串口屏指令表.md:95`）。而 `files/00-总览/对外问询清单.md:76-78` 的 Q7（"串口屏最高可设 baud 是多少"）**至今未问、未答**。

三种处理：

1. 若屏支持 500000：什么都不用改，屏工程里把 `bauds` 设成 500000。
2. 若屏不支持 500000 但支持 460800：FPGA 侧改 4 处（见下），误差 0.47% 可接受。
3. 若屏只支持到 115200：FPGA 侧同样改 4 处，误差 0.006%，最稳。代价是回读 30 条状态约 600 字节需要 52 ms，对参数面板完全够用（现状的 `'P'` 诊断包本来也是人眼读的）。

**改波特率要动的地方（注意：`top.v:1061-1067` 那条"四处一起改"的注释已经过时）**：

板载口这一侧要改 4 处：

```
rtl/top.v:1095   uart_rx     .BAUD_DIV(100)   -> 434（若 115200）
rtl/top.v:1188   uart_ui     .BAUD(500_000)   -> 115200
rtl/top.v:1333   calib_cmd   .BAUD(500_000)   -> 115200
rtl/top.v:1924   uart_tx     .BAUD_DIV(100)   -> 434
```

**不要**跟着改的 3 处（它们在 ESP32 那条线上，仍走 500 k）：

```
rtl/top.v:1144   uart_rx_esp  .BAUD_DIV(100)
rtl/top.v:1558   evt_uart_rx  .BAUD(500_000)   <- 它已改接 esp_rx_done（:1565）
rtl/top.v:1956   uart_tx_esp  .BAUD_DIV(100)
```

`top.v:1061-1067` 的注释把 `evt_uart_rx` 列在"板载四处"里，那是它还在板载口时的写法。2026-10-11 它改走 ESP32 独立 UART 之后，这条注释就与代码不符了。改波特率时按上面的清单走，不要按那条注释走。

### 3.4 与调试串口的冲突（讲清加方案）

**冲突是硬件事实**：`files/10-硬件/Console拓展板接线需求-20261003.md:563` 明写"串口屏 | 共用同一条 UART | 已分配；与调试口不能同时用"。屏长期插在 `D14`/`D15` 上，PC 的 USB-TTL 就没地方插了。

但要把"看"和"发"分开看，因为这两件事的现状不同：

| 方向 | 现状 | 屏占用板载口之后 |
|---|---|---|
| FPGA 到 PC（看回包、看诊断） | 回包同时镜像到板载 `D15` 和 ESP32 的 `G21`（`top.v:1955-1962`） | **仍然可用**，走 `G21` 到 ESP32 再到 BLE 到 PC。ESP32 侧的反向通路已验收（`esp32/README.md` 记"2000 字节 round-trip 逐字节一致"） |
| PC 到 FPGA（发命令 `'T'`/`'S'`/`'W'` 等） | `calib_cmd` 只吃板载口的 `ur_done`（`top.v:1338`） | **断了**，这是真正的损失 |

所以真正要解决的只是"命令输入改走哪条路"。三个方案：

| 方案 | 做法 | 评价 |
|---|---|---|
| 1（推荐） | 把 `calib_cmd.rx_done_i` / `rx_data_i` 从 `ur_done` / `ur_data` 改成 `esp_rx_done` / `esp_rx_data`（即改走 `G22`），板载口完整让给屏 | **物理隔离，零风险**。理由见下 |
| 2 | 屏上做一页"命令"页，用 TJC 的 `printh` 发裸字节（例如 `printh 54` 发 `'T'`） | 可用，但要在屏工程里为每条命令做一个按钮，工作量落在屏侧；且 `uart_ui` 会把这些字节当"非法返回码"计入 `err_cnt_o`（不影响功能，只是计数器会涨） |
| 3 | 物理切换：调试时拔屏插 USB-TTL | 零 RTL 改动，但台面操作麻烦，且不能边看屏边调 |

方案 1 为什么零风险：`calib_cmd` 自带 `0xA5` 帧边界跟踪。`top.v:1516-1522` 已核实：`calib_cmd` 的 `idx_q` 只在看到 `0xA5` 时离开 0，而命令只在 `idx_q == 0` 时被识别，所以"帧内的 `T`/`S`/`X`/`M` 是载荷，不当命令"（`top.v:1258` 原文）。ESP32 那条线上跑的是 0xA5 开头的曲谱帧，所以命令与曲谱帧可以安全共线。而屏帧（TJC 的 `0x65` / `0x71`）走板载口，与 `calib_cmd` **物理上不同线**，不可能互相误判。这比原来"屏与命令共用一条线"的局面更干净。

代价：需要 ESP32 侧把 PC 的字节透传过来。它的定位本来就是"无线的 USB 线，PC 怎么发就原样照搬、不看内容"（`top.v:1127`），反向通路也已验收，所以这一侧基本不用改。

## 四、EC11 映射方案（屏点选激活，EC11 手拧）

**本节定位**：这是"**下一轮可选增强**"的设计（见 2.2.5）。它需要动 rtl（`uart_ui` 加输入端口、`enc_obj_r` 扩位），所以**不塞进最小可用第一步**（第八节）。但**参数本身的最小可用路径不受影响**：屏可以直接用现有 `71 11..18` 帧改数值（见 2.2.2）。

### 4.1 EC11 现在干什么（已核，已接线可用）

```
物理：enc_a_i(E19) / enc_b_i(C19) / enc_sw_i(C18)      top.v:513-515
  -> Z-safe 归一（用 === 1'b0 判）                       top.v:719-721
  -> sync_input 打两拍（K-62 纪律：先同步再去抖）         top.v:723-728
  -> debounce（NKEY=1, DB_MS=5, ACTIVE_LOW=1）           top.v:731-755
  -> enc_cw_w / enc_ccw_w / enc_sw_down_w
  -> 除 4（一次"定位" = 4 个格雷步）                      top.v:778-785
  -> enc_step_cw_w / enc_step_ccw_w
  -> 按 enc_obj_r 分流                                   top.v:793-796
       enc_obj_r = 0（BPM）   -> enc_bpm_up_w/dn_w    -> play_seq.bpm_up_i/bpm_dn_i（加减 1 BPM）
       enc_obj_r = 1（变调）  -> enc_trans_up_w/dn_w  -> cmd_trans_up_req（加减 1 半音）
  -> 对象切换 = 按压                                     top.v:758-762
       enc_sw_down_w => enc_obj_r <= ~enc_obj_r
```

| 问题 | 答案 |
|---|---|
| 现在有几个对象 | 2 个：0 = BPM，1 = 变调（`enc_obj_r` 是 1 位） |
| 怎么换对象 | 按压一下（`enc_sw_down_w` 翻转 `enc_obj_r`） |
| 一格等于多少 | 除 4 之后等于 1 步（`top.v:771-785`），即 BPM 加减 1 或变调加减 1 半音 |
| 变调那条走哪 | 与串口 `'F'` / `'G'` 同一条下游（`cmd_trans_up_req`，`top.v:1324`），复用现成通路 |
| BPM 那条走哪 | 直接进 `play_seq.bpm_up_i` / `bpm_dn_i`（`top.v:2537-2538`），不过小节对齐器（`:791-792` 有意为之：旋钮要边转边听） |
| 指示 | 灯 5：动过就临时显示对象色（黄 = BPM，紫 = 音高），1 秒回落（`led_indicator.v:58-68`） |

### 4.2 用户要的方案

```
屏点选  = 设定 EC11 目标（屏发一条命令"EC11 目标 = 第 N 个参数"）
EC11 转 = 只增减当前目标那一个参数
EC11 按 = 保持"切换对象"语义（见 4.6）
```

优势：`enc_obj_r` 不必扩到 11 个对象，只要"屏指定的那一个"。这也符合用户第 4 条"点击对应效果器的控件就可以激活 EC11 对该参数的调节"。

**EC11 目标清单 = 6 个（失真 / 合唱 / 延迟 的程度参数）**：

| 目标号 | 参数 | 所属节点 | 顶层线 | 步进量 | 饱和上限 |
|---|---|---|---|---|---|
| 0 | 失真 增益 `gain` | 失真 | `ui_fx_gain`（16 位） | 加/减 16'h0100 | 0 .. 16'hFE00（字节 254） |
| 1 | 失真 补偿 `trim` | 失真 | `ui_fx_trim`（16 位） | 加/减 16'h0100 | 0 .. 16'hFE00 |
| 2 | 合唱 长度 `chorlen` | 合唱 | `ui_fx_chorlen`（11 位） | 加/减 11'd32 | 0 .. 2016（字节 63） |
| 3 | 延迟 长度 `dlylen` | 延迟 | `ui_fx_dlylen`（14 位） | 加/减 14'd128 | 0 .. 16256（字节 127） |
| 4 | 延迟 反馈 `fb` | 延迟 | `ui_fx_fb` | 加/减 1 | 0 .. 254 |
| 5 | 干湿混合 `mix` | 合唱与延迟共用 | `ui_fx_mix` | 加/减 1 | 0 .. 254 |

**音量颤音的 depth 与 rate 不在 EC11 目标里**（改由推子档 2 负责）。这是**已定**（用户第三轮拍板：点音量颤音节点时推子自动切到该档），理由与交互见 2.2.3 与 5.4。

`mask`（3 个使能开关）也不进 EC11 目标，它是开关，屏上直接点。

### 4.3 屏点选怎么实现（复用现有 `0x65` 触摸帧，不新增帧类型）

`uart_ui.v:369-388` 已经处理 `RET_TOUCH`（`0x65`）帧，按 `body_q`（控件 ID）分派：`body_q == 0` 翻转模式，`body_q == 2` 切 Test Mode 档。

所以在同一个 `case` 里加分支即可，映射表见 2.2.4（控件 ID 3..8 对应 EC11 目标 0..5，9 = 推子切档 2，13 = 推子档循环，14 = 退出 EC11 参数模式；开关翻转走 `71 10`，不占控件 ID）。

屏侧只需把屏 2 的那些控件设成对应 ID，点一下屏就发 `65 <ID> FF FF FF`。**不需要新帧类型、不需要新返回码**。

同时屏上做两级反馈：
1. 本地立即高亮（零延迟，点哪亮哪）。
2. FPGA 回读确认（读回 `enc_tgt_o` 与 `enc_obj_r`，见第六节），把高亮改成权威状态。

第 2 级是必要的，因为 `esp32/evidence/串口屏HMI验收报告-20261001.md` 第三节记录过一个坑：**"值对了但屏不重绘"**（实测 `get t3.txt` 回 `pBT OK` 而屏上仍是 `BT --`），以及"屏上没变不等于命令没生效"。只靠本地高亮会在帧丢失时显示错误状态。

### 4.4 `uart_ui` 具体要加什么（这是本节的关键约束）

**结构性约束**：8 个（加 mask 共 9 个）效果器参数寄存器是 `uart_ui` 内部的 `output reg`（`uart_ui.v:165-173`），唯一写入点在帧解析那条 `else if (body_q == 8'd16..24)` 链（`:428-483`）。顶层只能读 `output`，不能反向赋值。所以 EC11 要写它们，**必须给 `uart_ui` 新增输入端口**。

建议新增 3 个端口：

```verilog
input  wire       enc_up_i,    // EC11 顺时针一步（单周期脉冲）
input  wire       enc_dn_i,    // EC11 逆时针一步（单周期脉冲）
output reg [2:0]  enc_tgt_o    // 当前 EC11 目标（0..5），同时供屏回读
```

内部加一个 `reg [2:0] enc_tgt_r`，由 4.3 的触摸帧设置，`enc_tgt_o` 就是它的观测输出。

**步进逻辑写在哪儿**：写在**现有那条 `else if (body_q == ...)` 链之外、同一优先级层级**，用一个 `if / else if` 链表达"帧写优先、EC11 次之"：

```
if (帧路径命中某参数)      该参数 <= 帧值
else if (enc_up_i)         按 enc_tgt_r 选中的那一个 <= 步进加
else if (enc_dn_i)         按 enc_tgt_r 选中的那一个 <= 步进减
```

注意：**必须复用同一组换算函数**。`uart_ui` 的 9 条换算各不相同（`gain` / `trim` 乘 256，`dlylen` 乘 128，`chorlen` 乘 32，`dlylen` / `chorlen` 还有饱和），EC11 那一路不能另写一套，否则"屏发 23"和"EC11 拧到 23"会得到不同的值，这是最容易埋的坑。

**最稳的落地方式（推荐）**：为每个参数加一个 **8 位影子字节寄存器**（`fx_gain_b` / `fx_trim_b` / ... / `fx_chorlen_b`），帧路径与 EC11 路径**都只写影子字节**（0..254 的整数），再由**同一处**换算从影子字节产生 `fx_*_o`。好处三条：

1. 格点天然对齐（影子是整数 0..254），不会出现"从 16383 减 128 得到 16255"这种不在格点上的值。
2. 饱和语义只在一处（换算函数里），与帧路径逐位一致。
3. EC11 的步进就是"影子字节加 1 或减 1"，与目标号无关，代码极简。

代价：8 个影子寄存器共 64 个 FF。**注意时序**：换算必须保持"帧落地后 1 拍更新 `fx_*_o`"的既有延迟，所以要用组合的 next 值参与换算（`fx_gain_o <= {next_gain_b, 8'b0}`），不要写成"先写影子、下一拍再换算"，否则 `fx_*_o` 会晚 1 拍，可能踩到 `tb/w3c/tb_uart_ui.sv` 的既有判据。这一条必须在动手时核对那个 tb。

### 4.5 脱屏可用性（回答"屏没接时 EC11 干什么"）

方案设计成**两态兼容**，`enc_obj_r` 从 1 位扩到 2 位：

| `enc_obj_r` | 含义 | 屏在不在 |
|---|---|---|
| 0 | BPM | 与现状逐位相同 |
| 1 | 变调 | 与现状逐位相同 |
| 2 | 屏选参数（由 `enc_tgt_r` 决定是 6 个里的哪一个） | 只有屏点选才会进入 |
| 3 | 预留 | 不可达 |

**推荐做法（零回归）**：EC11 按压**保持现状的 0 与 1 之间循环**，模式 2 只能由屏点选进入，屏上给一个"退出"按钮把它设回 0 或 1。这样：

- 屏不在时，EC11 的行为与今天**逐位相同**（BPM 与变调），不会因为改了对象宽度而失灵。
- 屏在时，点某个参数就进模式 2，转旋钮调它，点"退出"回到 BPM 或变调。

**可选增强**：把按压改成 0 -> 1 -> 2 -> 0 三态循环，这样脱屏也能进参数模式（进入时保持上次的 `enc_tgt_r`，复位默认 0 即失真增益）。代价是改变了现有按压行为，必须确认没有 tb 依赖它。

已核：`tb/` 下没有任何 tb 直接检查 `enc_obj_r`（只有 `tb/w3c/tb_evt_uart_rx_gate.sv:69-70` 接了 `ui_tx_start` / `ui_tx_data` 两根空线）。所以扩位的 tb 风险低，但有一个必须同步的地方：`led_indicator.enc_obj_i` 是 **1 位**（`led_indicator.v:107`）。`enc_obj_r` 扩成 2 位后如果不同步改这个端口，Verilog 会**静默截断取 LSB**，症状是"模式 2 的灯显示成 BPM 的颜色"。这正是 `led_indicator.v:108-115` 已经记录过的同一个坑（当年 `scope_mode_r` 从 1 位扩到 2 位时，FFT 被截断成波形色）。扩位时**必须同时改 `led_indicator` 的端口宽度与颜色表**。

### 4.6 EC11 按一下干什么（回答）

建议：**保持"切换对象"语义，不用它切使能开关**。

理由三条：

1. 使能开关是屏的职责。屏 2 上已经有 3 个开关控件（失真/合唱/延迟各一个），点一下比拧旋钮快，而且能一眼看到三个的当前状态。
2. 按压已经在表达"我在切换对象"（灯 5 的临时色就是这个语义，`led_indicator.v:65-68`）。让它同时兼任"切开关"会让两种语义混在一起，用户分不清"这一下是切对象还是切开关"。
3. 保持现状语义意味着零回归风险。

若将来用户觉得"屏不在时想用旋钮开效果"，再单独设计（例如长按切换使能，`debounce` 已经提供 `enc_sw_lvl` 电平，可做长按判定）。

## 五、推子分工与"音量颤音"档（本轮新增）

**本节定位**：档 2 需要动 rtl（`fader_gear` 加端口与三态切档、`top.v` 加 mux、`tb_fader_gear` 判据要改），所以也属"**下一轮可选增强**"（见 2.2.5），不塞进最小可用第一步。屏上"推子档"的**显示**属于第一步（`led_gear_st` 已是模块层 wire，零引线）。

### 5.1 三档分工（核代码：三组目标寄存器零交集）

| 控件 | 档位 | 调什么 | 目标寄存器 | 下游模块 | 出处 |

核验结论：推子档 0 改 `transpose_semi`（进 `note_manager`），推子档 1 改音高颤音（进 `vibrato_lfo`），推子档 2 改音量颤音（进 `fx_chain` 的 `u_trem`），EC11 改失真/合唱/延迟参数（进 `fx_chain` 的 `u_dist` / `u_chorus` / `u_delay`）。**四组目标寄存器没有交集**。用户说的"推子负责颤音和实时变调"与代码一致。

所以 2026-10-16 第一版里"A. 与 10-14 裁定冲突"那一节**作废**。2026-10-14 的裁定是"效果器参数不走 EC11、走推子参数页"；本轮把"音量颤音"划给推子档 2，EC11 只负责失真/合唱/延迟，两者不抢同一个寄存器。

**必须提醒的命名区分**（这一条容易误解）：

| 名字 | 模块 | 文件:行号 | 参数 | 谁调 |
|---|---|---|---|---|
| 音高颤音（vibrato） | `vibrato_lfo` | `top.v:6006` | `vib_depth_sel` / `vib_rate_sel` | 推子档 1 |
| 音量颤音（tremolo） | `fx_trem`（在 `fx_chain` 内） | `fx_chain.v:322-334` | `trem_depth_i` / `trem_rate_i` | 推子档 2（本轮新增），帧 `0x15`/`0x16` 也可写 |

屏上标签必须区分，建议分别写"音高颤音"与"音量颤音"，否则用户会以为调的是同一个量。

### 5.2 现状：档 2 与档 3 结构上不可达（原因）

`fader_gear.v:237-242` 原文：

```
// 'J'：档 0 与档 1 之间切
//   用 (gear_o == 0) ? 1 : 0 而不是 gear_o + 1：
//       后者一旦 gear_o 是 2/3 就会走到 3/2，预留档会被"走进去"。
//   本写法结构上保证档 2/3 不可达
if (gear_next_i)
    gear_o <= (gear_o == 2'd0) ? 2'd1 : 2'd0;
```

为什么当初要"结构上不可达"：档 2 与档 3 在 2026-10-01 的定稿档位表里是**预留**（档 2 = 摇把范围与速率，档 3 = 主音量微调），两者都**没有实现**。如果让切档走到档 2，而档 2 的语义是"预留摇把"，那么：

- 档 2 下 `vibrato_depth_o` / `vibrato_rate_o` 会被归零（`fader_gear.v:258-266` 的 `else` 分支）=> **颤音静默失效**；
- 而档 2 想驱动的"摇把"并不存在 => **两个推子什么都不做**，用户会以为推子坏了。

所以作者刻意用三元式把 2/3 排除在外，宁可"切不到"也不要"切进去没反应"。这是**有意的设计，不是遗漏**。

改法方向：把"档 2 是空档"这个前提换掉（本轮给档 2 真正的语义 = 音量颤音），然后让切档走三态循环，**并新增一条"屏直接置档 2"的入口**：

```verilog
// 入口 1：推子自己的切档循环（'J' / 矩阵 idx 5）
// 推荐写法：显式 case，档 2 可达、档 3 仍不可达
if (gear_next_i) begin
    case (gear_o)
        2'd0:    gear_o <= 2'd1;
        2'd1:    gear_o <= 2'd2;
        2'd2:    gear_o <= 2'd0;
        default: gear_o <= 2'd0;   // 2'd3 兜底回 0，保持"3 不可达"
    endcase
end

// 入口 2（本轮新增）：屏点选，直接置档 2，与当前档位无关
//   优先级：放在 gear_next_i 之后 => 同拍时"屏置档"胜（屏是明确意图）
if (gear_sel2_i) begin
    gear_o <= 2'd2;
end
```

为什么用显式 `case` 而不是 `gear_o + 2'd1`：`gear_o + 2'd1` 在 2 位下是 `3 -> 0`（回绕），行为上其实也安全，但"档 3 不可达"就变成**靠位宽回绕保证**，读代码的人看不出来；显式 `case` 把"3 兜底回 0"写成一条明线。

### 5.3 档 2 完整改动清单

#### 5.3.1 要动的文件

#### 5.3.2 档 2 的接线（推荐路线：在 `fx_chain` 例化处做 mux）

关键结构约束：`ui_fx_depth` / `ui_fx_rate` 是 `uart_ui` 内部的 `output reg`（`uart_ui.v:171-172`），顶层只能读、不能写。所以**不能**让推子直接驱动这两个寄存器。

推荐做法：**不去动 `uart_ui` 的写入口**，而是在 `fx_chain` 的例化处把"生效值"选出来：

```verilog
// 档 2 时音量颤音由推子控制；其余档由 uart_ui 的寄存器控制
wire        trem_from_fader = (led_gear_st == 2'd2);
wire [11:0] trem_depth_f;    // <- fader_gear.trem_depth_o
wire [11:0] trem_rate_f;     // <- fader_gear.trem_rate_o
wire [7:0]  trem_depth_eff  = trem_from_fader ? trem_depth_f[11:4] : ui_fx_depth;
wire [7:0]  trem_rate_eff   = trem_from_fader ? trem_rate_f[11:7]  : ui_fx_rate;

// fx_chain 例化处（top.v:6372）
.trem_depth_i(trem_depth_eff), .trem_rate_i(trem_rate_eff),
```

位宽换算（12 位推子 -> 8 位寄存器，`fx_chain.DEPTH_W = RATE_W = 8`，`fx_chain.v:110-111`）：

| 参数 | 推子源 | 映射 | 得到的范围 | 说明 |
|---|---|---|---|---|
| 深度 `depth` | `ch2_i`（12 位，0..4095） | `[11:4]` | 0..255 | 全行程都有意义（0 = 数值恒等，255 = 最深）。**注意**：帧路径受 `0xFF` 帧尾限制只能到 254（`uart_ui.v:159-161`），推子能到 255，是帧路径的**超集**，无害 |
| 速率 `rate` | `ch3_i`（12 位，0..4095） | 建议 `[11:7]` | 0..31 | **必须缩放**：默认速率是 7（`fx_trem.v:86` 的 `RATE_DEFAULT = 8'd7`），而 `RATE_W = 8` 允许 0..255。若直接取 `[11:4]`，推子前 3% 的行程就覆盖了整个常用区间，后面 97% 全是"过快"=> 手感极差。取 `[11:7]` 给 0..31 更合理，但**具体系数待上板听感确定** |

推荐路线与备选路线的取舍：

| 路线 | 做法 | 评价 |
|---|---|---|
| A（推荐） | 在 `fx_chain` 例化处 mux 生效值 | 对 `uart_ui` 的写入口零改动；不引入"推子 vs 帧 vs EC11"三方仲裁；代价是 `ui_fx_depth`/`ui_fx_rate` 在档 2 下"写了不生效" |
| B | 把推子做成 `uart_ui` 里深度/速率影子寄存器的第三个写源 | 语义统一（所有写源都进同一个影子），但要加优先级仲裁，而且 `fader_gear` 已有的"推子动过才接管"边沿检测（`fader_gear.v:199-211` 的 P3.1/P3.2）要为档 2 再做一套 => 复杂度明显更高 |

**路线 A 必须写清的语义（属于"静默无效"，与 `K-106` 纪律有张力，必须处置）**：

档 2 下，帧 `0x15` / `0x16` 对 `ui_fx_depth` / `ui_fx_rate` 的写入**仍然会写进寄存器，但不影响出声**（被 mux 挡住）。处置三条：

1. 屏上 `depth` / `rate` 显示**生效值**（即 mux 之后的值），并在旁边标注"推子控制"，不要显示 `ui_fx_depth` 的原值。
2. 退出档 2 后，`ui_fx_depth` / `ui_fx_rate` 回到帧设的值 => 行为可预期（"推子只管档 2 期间"）。
3. 回读通路要把"当前档位"和"depth/rate 是否由推子控制"一起报给屏，否则用户看到数值在动却不知道是谁在动。

#### 5.3.3 判据（必须能红）

新增或扩 `tb/w3a/tb_fader_gear.sv`：

```
a. 复位后 gear == 1（不变）
b. 按一次 'J' -> gear == 2（本轮新增的落点）
c. 再按一次   -> gear == 0
d. 再按一次   -> gear == 1（三态循环闭合）
e. 档 2 时：trem_depth_o == ch2_i、trem_rate_o == ch3_i，且 vibrato_depth_o == 0、vibrato_rate_o == 0
f. 档 1 时：vibrato_depth_o == ch2_i、vibrato_rate_o == ch3_i，且 trem_depth_o == 0、trem_rate_o == 0
g. 档 0 时：四个输出全 0（与现状逐位相同）
h. 档 2 时发 'H' 24 -> transpose_semi_o == +12
   （依据 fader_gear.v:214-218：trans_down/up/abs_i 优先级最高、与档位无关
     => 档 2 下串口仍能改变调，这是"保持"语义而不是"锁死"）
i. 切回档 1 -> vibrato_depth_o 恢复等于 ch2_i，trem_depth_o 归 0
j. 切回档 0 -> 推子接管变调（沿用现有 G 组的接管判据）

入口 2（屏直接置档 2，本轮新增）：
k. 档 0 时给一个 gear_sel2_i 脉冲 -> gear == 2（一条命令一定落到档 2）
l. 档 1 时给一个 gear_sel2_i 脉冲 -> gear == 2
m. 档 2 时再给一个 gear_sel2_i 脉冲 -> 仍是 gear == 2（幂等，不会绕走）
n. gear_sel2_i 与 gear_next_i 同拍 -> 以 gear_sel2_i 为准（gear == 2）
o. gear_sel2_i 只高 1 拍 -> 下一拍起 gear 保持 2（不是脉冲式回弹）

变红方式：
  - 把 case 写成 gear_o + 2'd1 且不写 default 兜底 -> 可能进档 3 -> 红
  - 把 trem_depth_o 与 vibrato_depth_o 接成同一个信号 -> e / f 必红（档 2 与档 1 输出相同）
  - 档 2 分支忘了给 vibrato_* 归零 -> f 必红
  - 把 gear_sel2_i 写成"再发一次 gear_next_i"（循环而非直置）-> k / l / m 里至少两条红
  - 把 gear_sel2_i 放在 gear_next_i 之前 -> n 红
```

`rtl/top.v` 侧（顶层判据，可加在 `tb/w3c/tb_top_fx_audio.sv` 或新增）：

```
k. 档 1（默认）：改 ui_fx_depth 后出声的颤音深度跟着变（走寄存器）
l. 档 2：改 ui_fx_depth 后出声的颤音深度【不】跟着变，而是跟着推子走
   （判据：分别拨动 ch2 与发帧 0x15，看哪一个影响 trem 深度）
m. 退出档 2 回到档 1：ui_fx_depth 的值重新生效（回到帧设的值）
变红方式：把 mux 的选择信号写成常量 0（永远用寄存器）-> l 红
```

#### 5.3.4 影响面（必须知道的连带成本）

**必改的既有判据（这是本条改动最要紧的影响面）**：

`tb/w3a/tb_fader_gear.sv` 里有两处**依赖"档 2/3 不可达"和"按一次从档 1 落到档 0"**的判据，档 2 可达后**必红**：

| 位置 | 原文 | 为什么红 |
|---|---|---|
| `:76-78` | `always @(posedge clk) if (rst_n && (gear == 2'd2 \|\| gear == 2'd3)) bad_gear = bad_gear + 1;` | D 组的连续监视把**档 2 也算违规**。档 2 可达后 `bad_gear > 0` => 必红。必须改成只监视 `2'd3` |
| `:302` | `pulse_gear(); chk("G9 -> gear0", gear == 2'd0);` | 从档 1 按一次，新循环落到**档 2**，不是档 0 => G9 必红 |
| `:330` | `pulse_gear(); // -> gear0` 然后 `:332` `chk_semi("G12 ...", 0)` | 复位后从档 1 按一次落到**档 2** => G12 必红（它断言"档 0 下推子未动 => 0"） |
| `:333-334` | `chk_semi("G13 ...", 0)` | 同上 => G13 必红 |
| `:341` | `pulse_gear(); // -> gear0` 然后 `:343` `chk_semi("G14 ...", -12)` | 同上 => G14 必红 |
| `:345` | `chk_semi("G15 ...", -12)` | 同上 => G15 必红 |

修法：加一个 `pulse_gear_to(target)` 辅助任务（连续按 `'J'` 直到 `gear == target`，带次数上限），把需要落到档 0 的地方改成按两次。注意 G12-G15 在 tb 里被标注为 `[smoke]`（冒烟检查），但它们的 `chk` / `chk_semi` **仍然会累加 `errors`** => 回归会红，不能因为标了 smoke 就忽略。

**要重跑的验证**：

| 项 | 要不要重跑 | 理由 |
|---|---|---|
| `tb/w3a/tb_fader_gear.sv` | 要，且**判据要先改** | 切档逻辑改了 |
| `tb/w3a/tb_led_indicator.sv` | 只在改档 2 颜色时才要 | 颜色表已有档 2 行，保留黄色则不用改 |
| `tb/w3c/tb_fx_chain.sv` / `tb_fx_trem.sv` | 不用 | mux 在 `top.v` 的例化处，模块级行为不变（`en_i` 仍是 `1'b1`，端口语义不变） |
| 凡在顶层按过 `'J'` 或矩阵 idx 5 的 tb | **要核对** | 一次按键的落点从"档 0"变成"档 2"=> 那些 tb 的期望值可能变 |
| 全量回归 | 要 | 改了两个 RTL 模块 |
| **PnR** | **要** | 新增 2 个 12 位输出 + 一个 8 位 2:1 mux + 档位 case 改动 => 必须重新综合与布局布线（按项目纪律：先 PnR 再回归） |

另一条要提醒的：档 2 时 `led_gear_st == 2'd2` => 灯 3 变黄（"推子功能"灯）。而**效果器使能灯 8**（`top.v:7075`，`ui_fx_en = |ui_fx_mask[2:0]`）反映的是"效果器开没开"。两者语义不同（一个说"推子现在管什么"，一个说"效果器开没开"），不要混。

### 5.4 音量颤音的归属：已定归推子档 2

用户第三轮拍板："效果器链里面也保留音量颤音这个大块吧，点到这个的时候推子自动切换到音量颤音档位"。

所以：

| 项 | 结论 |
|---|---|
| 链式图上 | **保留音量颤音节点**（第 5 个节点），并自带 depth / rate 两个控件 |
| 谁调 depth / rate | **推子档 2**（CH2 = 深度，CH3 = 速率），连续扫 |
| EC11 目标清单 | **定为 6 个**：gain / trim / chorlen / dlylen / fb / mix。**不含 depth / rate** |
| 进入方式 | 点音量颤音节点（或它的 depth / rate 控件）=> 屏发 `65 09` => 推子切到档 2 |
| 屏上表现 | 该节点与两个控件转"推子接管高亮"（橙），数值随推子实时变（靠回读） |

这样定的理由四条：

1. 用户明确"音量颤音也由推子调"，且明确要在链上保留这一块。
2. 推子是**连续行程**（可以一扫而过），适合"深度从 0 扫到满"这种大范围量；EC11 是加减 1 的微调，6 个参数已经要拧很多圈。
3. 若 EC11 也写 depth / rate，就会变成三方仲裁（帧 `0x15`/`0x16` / EC11 / 推子）。`fader_gear` 已有"推子动过才接管、串口设的值保持到推子动"那套边沿检测（`fader_gear.v:199-211` 的 P3.1/P3.2，用**量化档位**做迟滞）。5.3.2 的路线 A 正是为了避开这个复杂度。
4. EC11 目标数保持 6，屏 2 的分工更清楚：音量颤音节点一看就是"推子控制"，失真/合唱/延迟一看就是"EC11 步进"。

将来若用户想让 EC11 也能微调 depth / rate（例如脱开推子时精调），再单独加：那时 EC11 目标回到 8 个，并且要补一条"档 2 下 EC11 与推子谁优先"的规则。**本轮不做。**

### 5.5 档 2 的两条进入方式（写同一个寄存器）

档 2 有两条入口，都落到同一个寄存器 `fader_gear.gear_o`：

| 入口 | 操作 | 路径 | 落点 |
|---|---|---|---|
| 1 推子自己的切档循环 | 串口 `'J'`（`calib_cmd.CMD_GEAR_NEXT`）或控制板矩阵 idx 5 | `cmd_gear_next_req` => `fader_gear.gear_next_i` | `case` 三态循环：档 0 -> 1 -> 2 -> 0 |
| 2 屏点选 | 点音量颤音节点或其 depth / rate 控件 | 屏发 `65 09` => `uart_ui` 出 `gear_to_trem_o` 脉冲 => 顶层 OR 进 `fader_gear.gear_sel2_i` | **直接写 `2'd2`**（与当前档位无关） |

两条写同一个寄存器，所以：

- 后写者胜（与 `play_seq` 的 `bpm_load` / `bpm_up` 同一手法，`play_seq.v:339-344`）。不需要仲裁器。
- 屏上的"推子档"显示（状态条第 5 项）永远反映 `led_gear_st`，所以无论从哪条入口进档 2，屏都会跟着变。
- 档 2 与 `enc_obj_r` **互不影响**：前者是"推子管什么"，后者是"EC11 管什么"。两者可以同时是"音量颤音"与"某个失真参数"。

## 六、协议建议

### 6.1 现有协议（已核）

方向 1：屏到 FPGA（唯一活着的方向）

```
TJC 返回帧：  <返回码> <帧体...> 0xFF 0xFF 0xFF
返回码（uart_ui.v:204-207）：
  0x65  控件点击事件     -> body_q = 控件 ID
  0x70  字符串变量返回   -> 不落地（uart_ui.v:485）
  0x71  数值变量返回     -> body_q = 变量序号，val_q = 值
  0x88  系统启动成功     -> 握手（置 hb_ready_o，无帧体）
```

已实现的写入点：

| 功能 | 帧 | 落地 |
|---|---|---|
| 模式翻转 | `65 00 FF FF FF` | `mode_o <= ~mode_o`（`uart_ui.v:373-375`） |
| Test Mode 切档 | `65 02 FF FF FF` | 关 -> 4 -> 8 -> 16 -> 32 -> 关（`:376-388`） |
| 起始音 | `71 01 <v> FF FF FF` | `base_semi_o <= v>>1`（`:414-419`），屏发 `0/24/48` |
| 效果器 9 项 | `71 10..18 <v> FF FF FF` | `fx_*_o`（`:428-483`） |
| 开关翻转（点节点标题） | `71 10 <新掩码> FF FF FF` | `fx_mask_o <= val_q`（**已实现**，`uart_ui.v:428-430`）。屏本地翻位后整帧写出，见 6.5 |

方向 2：FPGA 到屏（现状不通，见 3.2）。

现有"回读"能力盘点：

| 形式 | 命令 | 回包 | 含值 |
|---|---|---|---|
| 命令受理回执 | `'A'` / `'W'` / `'B'` / `'K'` / `'O'` / `'U'` / `'I'` / `'D'` / `'Q'` / `'J'` / `'R'` / `'L'` / `'C'` | 单字节（`'a'` / `'w'` / `'b'` / `'k'` / `'o'` / `'u'` / `'x'` 等） | 不含 |
| Test Mode 回执 | `'M'` | 单字节 `'4'` / `'8'` / `'A'` / `'B'` / `'0'` | 含档位（唯一含值的单字节回执） |
| 标定进度 | `'S'` | 单字节轴号加拒绝原因码 | 部分 |
| pos 探针 | `'P'` | 8 字节 `P<ch><4 位十进制>` 加 CRLF | 有 |
| 逐轴探针 | `'N'` | 8 字节（逐轴自动切） | 有 |
| span 状态 | `'V'` | 7 字节 `V<state><axis><rej_hi><rej_lo>` 加 CRLF | 有 |
| 事件上行 | `'O'` 开 | 14 字节 `0xA5` 加 type 加 seq 加 tick(4) 加 axis 加 inc(4) 加 vel 加 xor | 有，但只是音符事件 |

结论：现有协议几乎没有值回读。30 条状态里只有 4 条能读回来（`'P'` / `'N'` / `'V'` / `'M'`），其余 26 条屏上全是本地缓存。这正是本次要做的事。

### 6.2 回读帧格式建议

设计原则（全部对齐本项目既有约定）：

| 原则 | 理由与先例 |
|---|---|
| FPGA 到屏不新造帧头，直接发 TJC 指令文本 | 屏认的是 `t0.txt="..."` / `n0.val=45` / `j0.val=100` 这类文本，帧尾 `FF FF FF`。`esp32/串口屏控件清单.md:240-258` 已有一整套实测通过的写法，照抄 |
| FPGA 直接发完整 TJC 指令，不是"发值、屏自己拼" | 屏自己不会拼。这与 ESP32 侧 `hmi.c` 的做法一致 |
| 屏到 FPGA 的"读请求"复用 `0x71` 帧 | `body_q` 已能区分变量号，新增变量号即可，不动帧格式 |
| `0xFF` 是帧尾，所以值域上限 254 | `uart_ui.v:159-161` 已论证，这是 TJC 协议的固有约束 |
| 回读帧不用 `0xA5` 帧头 | `0xA5` 是曲谱帧头（`evt_upstream.v:10`）。虽然曲谱已改走 `G22`，但板载口的 `'P'` / `'V'` 诊断包仍在，不要混 |

建议格式（推荐方案 A）：

```
触发时机三类：
  1. 屏发读请求帧：71 <状态 ID> <任意值> FF FF FF
  2. 状态变化时主动推（事件驱动）
  3. 收到 0x88 握手后推一遍全量快照（初始化）

FPGA 到屏的字节流（ASCII，每条以 FF FF FF 结尾）：
  n0.val=120<FF FF FF>              BPM
  t1.txt="指板"<FF FF FF>           模式
  n1.val=3<FF FF FF>                变调（+3）
  t2.txt="BASS"<FF FF FF>           音色
  n2.val=2<FF FF FF>                EC11 当前目标（0..5）
  n3.val=2<FF FF FF>                推子档位（0/1/2）
  t3.txt="DIST+DLY"<FF FF FF>       效果链
  ...

优点：屏侧零代码（只要拖控件），与 ESP32 侧同一套做法（已被验收）
长度：一条状态约 15..25 字节，30 条约 600 字节
耗时：500 kbaud 下约 10 ms，115200 下约 52 ms，对参数面板都够
```

备选方案 B（紧凑二进制，只在要高频刷时用）：

```
  0xA5 | 0x03(类型=状态回读) | seq(1) | 状态 ID(1) | 值(4, 大端) | XOR(1)   共 9 字节
  与 rec_dump / evt_uart_rx 的 9 字节帧同构
  缺点：屏侧要写解析代码（TJC 的 printh / prints 能做，但麻烦）
```

推荐方案 A。本次目标是"能显示"，不是"最高带宽"。屏自带字库、数值控件、进度条，让屏做显示、让 FPGA 只发文本，这是 `产品形态决议清单.md:597-607` 已经论证过的分工。将来若要画实时波形（100 点乘 4 字节等于 400 字节每帧，约 28 fps），那时再上方案 B。

### 6.4 BPM 前置（必须先做，否则屏上显示不了 BPM）

BPM 在 FPGA 里**没有数字寄存器**。tempo 状态只有 `play_seq.tick_inc_o`，它是一个 32 位相位增量，语义是：

```
tick_inc = BPM 乘 1374 加 47        （play_seq.v:176-181）
验算：120 乘 1374 加 47 = 164927，与 TICK_INC_DEFAULT 逐位相同
40 BPM -> 55007，240 BPM -> 329807
```

要从 `tick_inc` 反推 BPM 需要一个除法器，不值得。正确做法是**在 `play_seq` 里加一个 8 位的当前 BPM 寄存器**：

```verilog
output reg [7:0] bpm_cur_o    // 当前 BPM（40..240）
```

三条写路径都要更新它：

```
bpm_load_i  分支：bpm_cur_o <= bpm_clamped        （限幅后的目标值，play_seq.v:196-197）
bpm_up_i    分支：bpm_cur_o <= (bpm_cur_o >= 240) ? 240 : bpm_cur_o + 1
bpm_dn_i    分支：bpm_cur_o <= (bpm_cur_o <=  40) ?  40 : bpm_cur_o - 1
复位：bpm_cur_o <= 120（与 TICK_INC_DEFAULT 对应）
曲谱 kind=2 事件：tick_inc 被换速事件直接写（play_seq.v:322-324），此时 bpm_cur_o 无法从 inc 反推
```

最后一条是**必须如实标注的局限**：曲谱 `kind=2` 事件直接写 `tick_inc_o`，不经过 BPM 语义，所以 `bpm_cur_o` 在"曲谱换速"之后会与真实 tempo 不一致。两种处理：

1. 屏上把 BPM 显示成"约"或加一个"由曲谱控制"标记。
2. 或者用 `bg_beat` 实测：数 1 秒内的拍点数得到实际 BPM（分辨率为 1，1 秒窗口下误差约 1 BPM），显示成"实测 BPM"。这是地面真相，但需要 1 秒窗口。

建议：`bpm_cur_o` 用于手动设定值显示，另可选加一个"实测 BPM"用于校验。先做前者。

这个改动很小（约 8..16 个 FF），但**必须重跑 `tb/w3c/tb_play_seq.sv`**，因为三条写路径的限幅语义不能变。

### 6.5 "点一下翻转开关"怎么落地（本轮简化：不新增协议）

用户第四轮要求"点失真/合唱/延迟，点一下就翻转状态"，随后澄清"不一定要实现翻转，我的意思是状态翻转。反正能实现功能就行了"。

所以本节的结论是**一句话**：

```
沿用现有协议：屏点一下 -> 屏自己算出新的掩码值 -> 发 71 10 <新掩码> FF FF FF
屏本地维护掩码缓存，点击时翻转对应位再整帧写出
```

| 项 | 内容 |
|---|---|
| 帧 | **`71 10 <新掩码> FF FF FF`**，即现有的"写整个掩码"帧（`uart_ui.v:428-430`，`fx_mask_o <= val_q` 直传）。**不新增帧、不新增寄存器、不改 FPGA** |
| 屏侧做什么 | 维护一个本地掩码缓存；收到触摸回调时 `mask_local <= mask_local ^ 对应位`，然后发上面那一帧，并按新值重绘该节点 |
| 掩码位序 | bit0 = 失真，bit1 = 合唱，bit2 = 延迟（`fx_chain.v:180-182`）。bit3 是混响留位、bit4 空闲，**不要动** |

**风险一行**：掩码目前**没有回读通路**（`top.v:1217` 的 `tx_busy_i = 1'b1`，见 3.2），而串口助手与屏**共用同一条 UART**（`top.v:1109`）。所以若别人改了掩码，屏的本地缓存会**过期**，屏下一次整帧写出会**静默覆盖**对方的改动。**正常单人使用时不会发生**（只有屏在写）；回读通路做完之后（第八节的 S0），屏的缓存可以由回读自动对齐，这条风险自然消失。

本轮**不做**"FPGA 侧原子异或"那种方案（它要新增 3 个 `RET_TOUCH` 分支）。留作下一轮可选增强，见 2.2.5。


## 七、缺口清单（没有回读通路的状态，屏上不可信）

这一节是本文最要紧的结论。

判据：只要"FPGA 到屏"没有携带该值的字节，屏上那个数字就只是它自己发出去的缓存。一旦别的来源改了同一个量（矩阵键、EC11、推子、串口助手、曲谱事件、上电默认），屏上就会撒谎。

### 7.1 完全无回读（屏上不可信），26 条

| 危险度 | 状态 | 会被谁偷偷改掉，屏立刻撒谎 |
|---|---|---|
| 最高 | BPM | 曲谱 `kind=2` 事件会改 BPM（屏上还显示旧值）、EC11、串口 `'Q'` |
| 高 | 变调 `transpose_semi` | 4 个来源：推子（档 0）、串口 `'F'`/`'G'`/`'H'`、EC11、矩阵键14 |
| 高 | 模式（指板 / 钢琴） | 3 个来源：串口 `'A'`、矩阵模式键、屏触摸控件 0 |
| 高 | EC11 当前目标 | EC11 自己（若按压也能换对象）与屏点选 |
| 高 | 效果器 `mask` 加 6 个参数 | 串口助手（与屏共用同一条 UART）、EC11、屏自己点节点标题翻开关。**这一条是本轮最需要回读的**：屏上"开/关"文字与底色若来自本地缓存，串口助手一改掩码屏就撒谎（见 6.5） |

| 中 | 滑音、音色、节拍器、鼓机节奏型、键盘打鼓、looper 已录事件数、Test Mode 权威状态 | 各有 1..2 个非屏来源（串口字母或矩阵键） |
| 低 | 起始音（唯一只屏能改的）、引导模式、显示模式、复音占用 | 无 |

| 状态 | 现有回包 | 缺什么 |
|---|---|---|

| `af_fault` / `mx_fault` / `ovf_any` 的分源 | 全部取或成 `fault_any_w`（`:2845`），一个心跳灯快闪 | 8 个溢出源加 3 个故障源合成 1 个 bit，"哪一路溢出了"完全看不到 |

### 7.3 一个必须警惕的机制（会让屏看起来对、其实错）

`uart_ui` 有两处**静默丢弃**：

1. 帧体不足：`uart_ui.v:410-413`，`RET_NUM` 帧若 `body_len < 2`，什么都不做（不落地、不发脉冲）。
2. 未知变量号：`:486` 的 `default` 分支，什么都不做。

也就是说，屏发了帧但没生效时，FPGA **不回任何错误**。结合"屏上显示的是本地缓存"，症状就是"屏上数字变了，实际没变"，这比"不显示"危险得多。

本轮又多了一处**语义上的静默无效**：档 2 下帧 `0x15`/`0x16` 写了 depth/rate 但被 mux 挡住（见 5.3.2）。处置办法已写在 5.3.2 第 3 条（回读要同时报档位与"谁在控制"）。

建议：回读通路上线后，屏每次写完必须回读确认。或者在回读协议里给"写失败"加一个错误码（当前是静默的，属于可选增强，见第九节）。

### 8.3 判据（必须能红）

四条判据，每条都给出"怎么让它变红"。（判据 5 见 6.5 已删，本轮不新增协议所以不需要翻转判据。）

判据 1（`bpm_cur_o`，改 `tb/w3c/tb_play_seq.sv`）：

```
a. 复位后 bpm_cur_o == 120
b. bpm_load_i 送 200 -> bpm_cur_o == 200
c. 连发 bpm_up_i 到 240 后再发一次 -> 保持 240（限幅）
d. 连发 bpm_dn_i 到 40 后再发一次 -> 保持 40（限幅）
e. 送 0 -> bpm_cur_o == 40（限幅下界）
f. 送 255 -> bpm_cur_o == 240（限幅上界）
变红方式：把任一条限幅去掉，c / d / e / f 立刻红
```

判据 2（回读发送器，新增 `tb/w3c/tb_hmi_status.sv` 或扩 `tb_uart_ui.sv`）：

```
a. 给定固定状态（BPM=120，模式=指板，变调=+3，音色=BASS，mask=0x05，fault=0），
   发一次"全量快照"请求
b. 断言串口输出字节序列逐字节等于
   'n0.val=120' + FF FF FF + 't1.txt="指板"' + FF FF FF + ...
c. 断言两条命令之间没有交错（前一条的 FF FF FF 之后才是下一条的第一个字节）
变红方式：把文本表里任一个字符改错，a / b 立刻红；
          把"等空闲再发"改成"看 ready 就发"，c 红（这是 uart_tx_fifo.v:116-129 记录的错位坑）
```

判据 3（屏点选加 EC11 步进，扩 `tb/w3c/tb_uart_ui.sv`）：

```
a. 发 65 03 FF FF FF -> enc_tgt_o == 3'd0
b. 发 65 08 FF FF FF -> enc_tgt_o == 3'd5
c. 发 71 10 01 FF FF FF -> fx_mask_o == 8'h01（**现有帧**，不是新增协议；见 6.1）
d. enc_tgt_o == 0 时给一个 enc_up_i 脉冲 -> fx_gain_o 由 16384 变 17408（加 16'h0100）
e. 连发 enc_up_i 到上限后再发 -> 保持 16'hFE00（饱和，对应字节 254）
f. 连发 enc_dn_i 到下限后再发 -> 保持 16'h0000
g. enc_tgt_o == 2 时给一个 enc_up_i 脉冲 -> fx_chorlen_o 由 736 变 768（加 11'd32），
   且 fx_gain_o 不变
h. 发 71 11 64 FF FF FF（帧路径设 gain=64）-> fx_gain_o == 16384；
   再发 71 11 65 FF FF FF -> 17408。
   即"屏发 65"与"EC11 从 64 拧一格"必须得到同一个值
i. 发 65 09 FF FF FF -> gear_to_trem_o 出一个单周期脉冲（且只出一拍）
j. 发 65 13 FF FF FF -> gear_next_o 出一个单周期脉冲
k. 发 65 14 FF FF FF -> enc_obj_r 回 0
l. 发 65 09 FF FF FF -> enc_tgt_o **不变**（点音量颤音节点只切推子档，不动 EC11 目标，
   这是 2.2.3 第 4 条约定：两条通路独立）
变红方式：去掉饱和，e / f 红；
          把 EC11 那一路另写一套换算（不复用），h 红（这正是 4.4 说的最容易埋的坑）；
          不按 enc_tgt_o 选参数（6 个一起动），g 红；
          把 65 09 与某个 enc_tgt_r 分支写在一起（顺手也设目标），l 红
```

判据 3 的 h 组是**最重要的一条**，它守的是"帧路径与 EC11 路径逐位一致"这个契约。

判据 4（推子档 2，改 `tb/w3a/tb_fader_gear.sv`）：见 5.3.3 的 a..o，加 `tb/w3c/tb_top_fx_audio.sv` 的 k..m。

（判据 3 与判据 4 都属于**下一轮可选增强**，见 2.2.5；最小可用第一步只需判据 1 与判据 2。开关翻转走现有 `71 10`，不新增协议，所以不需要新判据。）

```
第二步：把 21 条 g_sound 内状态引到模块层，屏 1 与屏 3 的其余字段接上
第三步：屏 2 的链式图细化（5 个节点，其中 3 个节点标题可点翻转开关，8 个参数控件），
        两类高亮与回读联动（开关状态靠 ui_fx_mask 回读，选中靠本地状态）
第四步（下一轮可选增强，见 2.2.5）：EC11 选中参数 + 推子档 2 + 推子档循环
第五步：把 mx_n_active（复音占用）、ui_frame_cnt 等"被剪的观测线"接上消费者
第六步：溢出分源（8 个 bit）与 af_fault / mx_fault 分源引线，屏 3 列 2 铺开
```

注意屏 2 的"开 / 关"文字与底色必须由 `ui_fx_mask` 回读刷新，不能长期靠本地缓存（理由见 6.5 的风险一行）。所以第一步的回读通路是屏 2 能上线的前提。
