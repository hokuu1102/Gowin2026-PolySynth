### 🔴🔴 一条**必须更正的技术判断**（⭐ 用户提议 vs 实际机制）

> ⭐ 用户原话：「**FPGA 要负责对齐时序，那边消除一下亚稳态应该没问题吧**」
>
> 🔴 **"消亚稳态"解决不了这个问题** —— ⚠️ **因为它不是亚稳态问题**：
>
> | 项 | ⭐ 说明 |
> |---|---|
> | **亚稳态** | ⚠️ 跨时钟域时**某一位**在采样瞬间不确定 ⇒ ⭐ 两级触发器同步即可 |
> | 🔴 **这里的真问题** | ⭐ **不是"某位采不准"**，⚠️ **而是"两边从【不同的起点】开始数时间"** |
>
> ⭐ **具体**：⭐ ESP32 起播时把"谱面第 0 拍"锚在**自己的 `esp_timer`** 上（`pool.c:412`）；
> ⚠️ FPGA 收到第一个事件时，**不知道它对应谱面第几拍** ⇒ 🔴 **无法对齐**。
>
> ✅ **正解（⭐ 靠【格式】，⛔ 不靠同步器）**：
> ⭐ **上行事件里【带上 `tick`】** ⇒ ⭐ **FPGA 自己就能对齐** ——
> ⭐ 这样"谁按的键"**根本不重要**，✅ **ESP32 起播完全可行**。
>
> ⇒ ⭐ **用户的方向（ESP32 起播）是对的**，⚠️ **只是"对齐"的实现手段要写对**：
> 🔴 **是"事件带 tick"，⛔ 不是"消亚稳态"。**

### ⚠️ 由此推出的一条**新的协议要求**（⭐ 给 FPGA 侧）

> ⭐ **上行事件的载荷【必须包含 `tick` 字段】** ——
> ⚠️ 否则 FPGA 无法把自己的动作对齐到谱面时间轴。
> ⭐ 具体位域**由 FPGA 侧定**（⭐ 我们不知道那边有什么可报的），
> ⚠️ **但"必须带 tick"这一条是硬要求。**

## 一、⭐⭐ 冲突的准确表述

### 1.1 两侧各自的主张（⭐ 都有白纸黑字）

| 侧 | 主张 | 出处 |
|---|---|---|
| **FPGA 侧** | 「**方案③ —— 上板手动按键起播**。协议保持冻结，⛔ 不新增命令帧，⛔ **你那边不用改固件**」 | `files/20-代码/FPGA侧答复-ESP32对接清单-20260923.md:24` |
| **FPGA 侧** | 「固件要不要改 \| ⭐ **一行都不用改**」 | 同上 `:58` |
| **FPGA 侧** | 「起播动作**不由发送端触发**，⭐ 所以**"灌完自动开演"这个流程不存在**」 | 同上 `:16` |
| **FPGA 侧** | 起播键 = **`Y12`**（`BANK9` 1.5 V）→ `debounce` → `run_i` / `pos_reset_i` | 同上 `:159` / `:214` |
| **ESP32 侧** | 模式 B：「PC 一次性灌整曲 → ESP32 缓存 → ⭐ **ESP32 自己算发送时刻**」 | `esp32/ble/main/pool.c:9` |

### 1.2 🔴 互斥点在哪

⭐⭐ **关键在于：「谁在放水」**

```
方案③ 隐含的架构          模式 B 实际实现的架构
─────────────────         ────────────────────
谁缓冲   → ⭐ FPGA 自己      谁缓冲   → ⭐ ESP32 缓冲整曲(160 KB PSRAM)
谁控节奏 → ⭐ FPGA 自己消费   谁控节奏 → ⭐ ESP32 按 tick 限速推
起播     → FPGA 按键        起播     → ⚠️ 应由 ESP32 自己定时
```

🔴 **两者都要"自己决定什么时候往外出数据"** ⇒ ⛔ **没有交集**。

### 1.3 ⚠️ 为什么"FPGA 按键 + ESP32 放水"这个组合**技术上不成立**

⭐ 这是本节最重要的推理 —— **不是风格之争，是硬冲突**：

`pool_start()` 的实际行为（`pool.c:408-418`）：

```c
void pool_start(void)
{
    s_play_idx = 0;
    s_t0_tick  = (uint32_t)ev_tick(pool_peek_word(0));   /* 谱面起点 */
    s_t0_us    = esp_timer_get_time();                   /* 🔴 锚到【ESP32 的当下】 */
    s_running  = true;
}
```

🔴 **它把"谱面第 0 拍"锚在【ESP32 调用 pool_start 的那一刻】。**

⇒ ⚠️ 那么问题来了：**FPGA 按键的那一刻，和 ESP32 锚定的那一刻，怎么对齐？**

| 情形 | 后果 |
|---|---|
| **ESP32 先 `pool_start`，人后按键** | 🔴 ESP32 已在全速放水，FPGA 还没开始消费 ⇒ **8 KB 缓冲 92 ms 灌满** ⇒ 🔴 **静默丢事件** |
| **人先按键，ESP32 后 `pool_start`** | ⚠️ FPGA 已开始计时，ESP32 却还没发 ⇒ 🔴 **错拍**（音乐从错误的相位开始） |

🔴 **而且没有任何机制能让两者对齐** —— 因为 `pool.c:22` 明确写着：

> 「§4.4 已拍板【**不做反向通道**】⇒ FPGA 满了我们【**不知道**】」

⭐⭐ **⇒ 结论：FPGA 侧 `L24` 那句「你那边不用改固件」隐含的前提是
「ESP32 只当透传管道（= 模式 A）」，🔴 而【模式 B 已经实现了】——
两者从未对齐过。**
