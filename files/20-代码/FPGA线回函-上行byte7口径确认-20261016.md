## 一、逐位真相（`rtl/w3c/evt_upstream.v:264`）

```verilog
wire [7:0] b_axis = {2'b0, tm, ax};
//   tm = evt_timbre_i  (2 位, :250 取值 · :228 写侧随事件锁存)
//   ax = evt_axis_i    (4 位, = top.v:6107 的 sa_up_axis)
```

`byte[7]` 就是帧的第 8 字节（`FRAME_B = 14`，`evt_upstream.v:58/:283-289`）。⚠️ **没有第二个字节。**

## 二、⚠️ 更正：`[3:0]` 鼓标记**只有灌谱鼓成立**

`seq_arb.v:417-419`：

```verilog
evt_up_axis_o <= (pop_src == SRC_KDRUM) ? {2'b0, pop_data[0 +: TIMBRE_W]} : 4'd0;
```

而 `pop_src` 是**入队时**打的源标记（`seq_arb.v:458-486`）。查三路：

| 来源 | 入队源标记 | `[3:0]` | `[5:4]` |
|---|---|---|---|
| **灌谱鼓**（PC 帧 bit5 = 1） | `score_src_w = SRC_KDRUM`（`:269`）| ✅ `drum_type` | ✅ `drum_type` |
| **键盘打鼓** | 走 `live_*` ⇒ **恒 `SRC_LIVE`**（`:458` 等）| 🔴 **`0`** | ✅ `key_drum_dtype`（`top.v:5855`）|
| **内部鼓机 / 节拍器** | 走源 B，**不经 `seq_arb`** | 🔴 **上次 pop 的陈旧值** | ⚠️ 恒 `DRUM_TIMBRE=2`（`top.v:5933`，不随件变）|

⭐ **根因**：`top.v:5890` 的 `src_a_src = key_drum_r ? 3'd5 : ...` 是**喂 `note_manager` 的那一份**（`:5999-6007`），
它**不经过** `seq_arb` 的入队路径 ⇒ `seq_arb` 内部看到的仍是 `SRC_LIVE`。

⇒ 🔴 **后果**：你们按 `[3:0] != 0` 判鼓时，**键盘打鼓会被当成旋律**；
而 `[5:4]` 那时装的是 `drum_type`（1=Snare/2=HiHat/3=Tom）⇒ 会被解成 GUITAR/PIANO/PAD 音色。
📌 灌谱鼓**不受影响**（你们 `[4b]` 那 6 条实帧断言全对）。

## 三、✅ 你们问的第一条：`[3:0]` 合法值域 = **0..3**，当前确实是 2 位

- `rtl/w3c/seq_arb.v:120`：`input wire [1:0] score_drum_type_i` ⇒ **2 位**
- 四件鼓（`seq_arb.v:261`）：`0=Kick · 1=Snare · 2=HiHat · 3=Tom`
- ⇒ **你们按"只有 0..3、>3 计越界"是【对的】** ✅
- 📌 将来扩件数必须**同时**改三处：`score_drum_type_i` 位宽 · `evt_upstream.TIMBRE_W` · 你们的 `DRUM_MARK_MAX`。
  ⚠️ `[5:4]` 只有 2 位 ⇒ **鼓件数被这个字段卡死在 4**，要扩必须先挪字段。

## 四、✅ 你们问的第二条：`evt_up_axis_o` **就落在 `byte[7][3:0]`**，没有独立字节

`top.v:5651` `.evt_up_axis_o(sa_up_axis)` → `top.v:6107` `.evt_axis_i(sa_up_axis)` → `ax` → `byte[7][3:0]`。
⇒ **你们按 `byte[7]` 解，结构是对的。** ✅

## 五、⚠️ Kick 盲区（你们已兜住，记录备查）

`seq_arb.v:414` 注释写"上行帧里 `axis != 0` 等价于'这是鼓'"——🔴 **对 Kick 不成立**：
Kick 的 `drum_type = 0` ⇒ `[3:0] = 0`，与旋律的 `[3:0]` **完全相同**。
⇒ 单看 `byte[7]`，`0x00` 有三种可能：**灌谱 Kick** / **键盘打鼓** / **旋律+音色0**。
⭐ 你们用 `kick_ambiguous` 标注"不猜"是**正确处置**，我方认可。
