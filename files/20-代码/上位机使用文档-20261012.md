## 一、有什么

| 文件 | 是什么 | 打开方式 |
|---|---|---|
| `esp32/tools/start_score_studio.bat` | **启动器**（双击它） | 双击 |
| `esp32/tools/score_studio.html` | **曲谱上位机** —— 看谱、灌谱、起播 | 经启动器打开 |
| `esp32/tools/upstream_studio.html` | **回传可视化上位机** —— 看 FPGA 回传的事件流 | 经启动器打开 |

| `esp32/tools/demo_upstream.bin` | 自带回传演示流（101 帧） | 见 `?demo=` |

### 为什么必须用启动器（⛔ 不能直接双击 .html）

浏览器的 **Web Bluetooth / Web Serial 要求"安全上下文"**：

- `http://127.0.0.1` ✅ 是安全上下文
- `file://` ❌ **不是** ⇒ 浏览器会直接拒绝蓝牙和串口

启动器做的事：在本目录起一个本地服务（端口 **8777**），再用浏览器打开
`http://127.0.0.1:8777/...`。

⚠️ 启动器会开一个**最小化的服务窗口**（标题 `ScoreStudioServer`）——
**关掉它服务就停了**。

## 二、曲谱上位机（灌谱 → 起播）

### 操作顺序

| 步 | 操作 | 判据（怎么知道成了） |
|---|---|---|
| 1 | 点右上角 **连接蓝牙** | 弹出**独立的选择框窗口**（标题 `http://127.0.0.1:8777 想要配对`）→ 点设备行 → **配对**亮起** → 点配对 → 页面显示 `● 已连接 FPGA2026-Synth` |
| 2 | 点左边 **谱面** 区域选文件，或把 `events.hex` 拖进去 | 左边统计出现事件数 / 时长 / tick 范围 / 变速点 / 类型分布 / 整包字节 |
| 3 | 点 **一键上传** | 日志出现 `清池（CMD 0x01）…` 然后 `上传完成：N 字节 / M 事件`；**池**变成 M、**总数帧**变成 M |
| 4 | 点 **起播** | 日志出现 `已发 起播`；**运行** 变成 `运行中`；**已喂帧** 开始往上涨 |

### 面板怎么看

| 字段 | 含义 | 正常值 |
|---|---|---|
| **池 / 容量** | ESP32 里已灌入、还没喂出去的帧数 | 上传后 = 事件数；容量固定 **18204** |
| **已喂帧** | 已经发给 FPGA 的帧数 | 起播后从 0 涨到事件数 |
| **总数帧** | 本曲总帧数 | = 事件数 |
| **溢出** | 池满后被丢掉的帧数 | **0**（≠0 说明灌多了） |
| **落后** | 喂水落后于播放位置的量 | 小数字正常；一直涨说明卡了 |
| **运行** | 播放状态 | `已停` / `运行中` |
| **未识别帧头 / 不匹配** | 收到坏帧的计数 | **0** |

### 谱面文件从哪来

`events.hex` 由 **`mid2evt.py`** 从 MIDI 生成：

```powershell
python <FPGA2026>\tools\mid2evt.py --in 曲子.mid --out-dir 输出目录
```

⭐ 上位机**也支持直接拖 `.mid`**，但它会去找 `mid2evt.py`；找不到会给出提示。

⭐ 想秒开演示：在地址栏的网址后面加 `?demo=demo_scale.hex`。

## 三、回传可视化上位机（看 FPGA 回传）

**它看的是另一个方向**：FPGA → ESP32 → BLE 通知 `0xABF2` → 浏览器。

| 步 | 操作 | 判据 |
|---|---|---|
| 1 | 点 **连接并订阅回传** | 日志出现 `已连接并订阅 0xABF2` |
| 2 | 让 FPGA（或 PC 当 FPGA）往 ESP32 的 **GPIO18** 发数据 | 卷帘开始出点、事件流开始滚 |

面板：**字节 / 帧 / 速率 / 音符 / 表同步 / 坏校验 / 未知类型 / 重新同步**。

⭐ **坏校验 / 未知类型 / 重新同步 三个数必须是 0** —— 不为 0 说明线路或波特率有问题。
⭐ 可以把收到的东西**导出成 `.mid`** 直接播放，或存原始 `.bin`。

⭐ 演示：网址后面加 `?demo=demo_upstream.bin`。

## 四、链路自检（一键跑 6 项）

| 步 | 检查 | 需要接什么 |
|---|---|---|
| ① | 蓝牙连接 | 只需 ESP32 上电 |
| ② | 读状态 `0xABF4`（必须 **8 组齐全**） | 同上 |
| ③ | 下行链路：清池 → 灌 200 帧 → 核对**逐帧守恒** | 同上 |
| ④ | 起播：`sent` 涨到 200 | 同上 |
| ⑤ | 上行链路：串口灌 → BLE 收 → **逐字节比对** | CH340 的 **TX → GPIO18** + 共地 |
| ⑥ | 串口屏：发 `get t1.txt`，从 ESP32 日志里读回包 | ESP32 的 **USB 口**（COM29） |

⭐ ③ 的判据是**守恒不变量**：`收到的帧数 == 进池的 + 溢出的`。
⚠️ 注意：**BLE 的无响应写没有投递保证**，少掉的帧根本没到 ESP32 ⇒
⛔ 不能断言"溢出数 == 超出的帧数"。

## 五、故障对照表

| 现象 | 多半是什么 | 怎么查 |
|---|---|---|
| 页面顶部有黄色提示条 | 用了 `file://` 打开 | 用启动器 |
| 🔴 **Python 工具突然全部连不上板子** | ⭐ **网页还开着、握着 BLE** ⇒ 板子停在「僵尸连接」里**不广播** | ⭐ **关掉网页**（或点页面的「断开」），几秒后板子恢复广播。判据：`_upstream_loop_check.py` 那种扫描能重新找到 `FPGA2026-Synth` |
| 连上了但报 `Characteristic 0xABF3 was not found` | 板子刚重启、GATT 还没注册完 | 等几秒重连；⚠️ 若持续如此见 §六 |
| 点"连接蓝牙"没反应 | 按钮没点上 / 选择框没弹 | ⭐ 看**日志有没有出现"请求设备…"** |
| 选择框一闪就没了 | 它**失去前台焦点就自动取消** | 别点别处；页面日志会写 `User cancelled the requestDevice() chooser` |
| 选择框里"配对"是灰的 | **没选中设备** | 先点设备那一行 |
| 上传后"池"不变 | 没清池 / 没连上 | 看日志有没有 `上传完成` |
| 起播后"已喂帧"一直是 0 | 前 **10.4 秒是预灌期**，属正常 | 等一会儿 |
| 屏上什么都不显示 | 屏没上电（5V）/ GPIO4-5 交叉接错 / 没共地 | 用自检第 ⑥ 项 |
| 串口读不到数据 | **同一个串口被两个程序打开**（`U85`） | 一次只让一个程序读 |

> ⚠️ **最重要的一条**：⭐ **网页上位机和 Python 工具不能同时用** ——
> BLE 只允许一个中心设备连接。⭐ 网页连着时，板子看起来像"死了"（不广播），
> 但**其实没问题**，只是链路被浏览器占着。**关掉网页即可。**

## 六、⚠️ 已知缺陷（2026-10-12，真机复现两次）

> **起播后约 20 秒，BLE 掉线，且 ESP32 会重启。**

**证据**：

| 项 | 观察 |
|---|---|
| 页面日志 | `起播` 之后约 23 秒出现 `蓝牙已断开` |
| ESP32 串口日志 | 时间戳**倒退**（如 `241001` → `178341` 毫秒）⇒ 中间重启过 |
| 重启后 | `pool=0/18204`（灌进去的帧全丢）、`mtu=23 \| ----`（未连接） |
| 复现次数 | **2 次**（都用网页上位机：连接 → 上传 → 起播） |

**已知的差异（怀疑方向）**：网页上位机**每 1.2 秒轮询一次 STAT**
（发 CMD `0x02` + 读 `0xABF4`），而此前的 Python 工具**不轮询**且从未重启。
⇒ 假设：**播放中并发 GATT 读写**是触发条件。

⚠️ **状态**：`[验证中]` —— A/B 对照实验已写好（`esp32/tools/_ble_poll_stress.py`），
但**尚未拿到结论**。⛔ 在此之前**不要**把它当成"上位机的问题"或"固件的问题"。

**规避**：⭐ 灌完谱面后，可以**先关掉网页**（释放 BLE），
再用 Python 工具起播（`_score_play_probe.py`），这样不会掉线。

## 七、给"自动化操作"的坑（用 GUI 自动化时踩过的）

⭐ 详见经验库 `C157` / `C158` / `U110`，这里只列要点：

1. ⭐ **操作后必须看"状态真的变了"再走下一步** —— 工具的"已发送"⛔ 不等于"已生效"。
   - 反面：连点 5~6 次其实一次没生效；
   - 反面：其实成功了但看太早 ⇒ 又点一次 ⇒ **执行了两遍**。
2. ⭐ **蓝牙选择框是独立窗口**，主窗口截图里看不见 ⇒ 要列窗口去找。
3. ⭐ **选择框里的设备行：像素点击选不中，必须用无障碍元素点击**。
   判据 = 无障碍树里"配对"按钮**从无动作变成有动作**。
4. ⭐ **选择框失焦即自动取消** ⇒ 操作前先把目标窗口**钉到前台**。
5. ⛔ **不要为了清理窗口去杀浏览器进程** ——
   实测 `launch_app` 开的新窗口**可能挂在你自己已有的浏览器进程上**，
   杀进程会**连你的标签页一起关掉**。只关自己那一个窗口。

## 八、命令行版（可全自动，⛔ 不需要浏览器）

```powershell
cd C:\Users\hokuu\Desktop\FPGA\FPGA2026-esp32\esp32\tools

python run_all_tests.py                              # ⭐ 全量：离线 + 全部真机，顺序跑，出汇总表
python run_all_tests.py --offline-only               # 只跑离线（不需要硬件）
python run_all_tests.py --with-play                  # 追加"灌真谱面并放到底"（+9 分钟）
python run_all_tests.py --list                       # 只列出要跑什么
python run_all_tests.py --selftest                   # 执行器自己的自检（含非空洞性三态）

python score_uploader.py --selftest                  # 离线自检（不需要硬件）
python score_uploader.py --autotest <events.hex>     # 无人值守跑完整流程（真机）
python _score_play_probe.py --hex <events.hex> --minutes 9   # 灌真谱面并观察到底
python _uart1_wire_check.py --port COM31 --hex <events.hex> --seconds 450  # 线上字节级校验
python _upstream_loop_check.py --port COM31 --n 300  # 上行闭环逐字节校验
python _exception_paths_check.py                     # 未知帧头 / 池满 / 断连重连
python selftest_all.py                               # 全量离线自检（23 工具 / 517 项）
```

### `run_all_tests.py` 的判据怎么读

- ⭐ **退出码 = 失败项数** —— 0 才算全过。
- 每项是**双重判据**：`退出码` **且** `判据关键字`；输出里出现 `RED` 也直接判红。
- 端口**按 VID 现场探测**（ESP32=`303A`，CH340=`1A86`）—— ⛔ 不要写死 COM 号，会漂。
- ⚠️ 跑之前**确认网页已关**，否则真机项会全部连不上（见 §五 那条）。
