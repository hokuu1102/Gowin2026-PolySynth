# 第二路 UART 对接单 —— 给 FPGA 侧（2026-10-01）

> **提出方**：ESP32 线
> **目的**：⭐ **打通 ESP32 ↔ FPGA 端到端**（⭐ 这是 P1 唯一的大块缺口）
> **裁定**：⭐ **用户 2026-10-01 拍板 = 在 `PMOD0` 的 `G21`/`G22` 上【新开第二路 UART】**
> ⚠️ **⛔ 不是**复用现有那一路（理由见 §二）
> ⚠️ 本单所有 `FPGA2026\` 的行号均**按权威 main worktree 现场核过**（⛔ 不是本 worktree 的旧快照）

---

## 一、⭐ 一句话

⭐ 请在 **`PMOD0_IO2`/`IO3`（= `G21` / `G22`）**上**新开第二路 UART**
（⭐ 新端口 + 新例化 + 2 条 `IO_LOC`），波特率 **500 kbps**，与现有那路**完全独立**。

---

## 二、🔴 为什么必须"新开"，⛔ 不能复用

**实测（权威 `FPGA2026\`，⭐ 2026-10-01 核）**：

| ⭐ 事实 | ⭐ 依据 |
|---|---|
| ⭐ FPGA **只有一对** UART 端口 | `rtl/top.v:416-417`（`input wire uart_rx` / `output wire uart_tx`，⭐ 之后即 `);`） |
| 🔴 它绑在 `J9` 的 `D14`/`D15` | `constr/top.cst:364` / `:366` |
| 🔴 且注释**明写是给 USB-TTL 的** | `constr/top.cst:352-353`；⭐ `top.v:416-417` 行尾注释「外接 USB-TTL」 |
| ⭐ `PMOD0`（含 `G21`/`G22`）**当前未分配** | `constr/top.cst:137` |
| ⭐ `PMOD0`/`PMOD1` 的 16 根**一根都没用** | `constr/top.cst:136-140` |

⇒ ⭐ 复用 `J9` 那对脚**物理上可行，但会顶掉 USB-TTL 调试口**；
⭐ 用户裁定**保留 USB-TTL、另开一路** ⇒ ⭐ **必须新增端口与例化**（⛔ 不是改绑）。

---

## 三、要 FPGA 侧做的（⭐ 3 项）

**① `rtl/top.v`：新增一对端口**
⭐ 建议命名 `uart2_rx` / `uart2_tx` —— ⛔ **不要复用** `uart_rx`/`uart_tx`（⭐ 那两个已归 `J9` 的 USB-TTL）。

**② `rtl/top.v`：新增一组例化**（⭐ 可**直接照抄**现有那两处，改个名字即可）
| ⭐ 方向 | ⭐ 抄这一处 |
|---|---|
| 收 | `top.v:702-703` `uart_rx #(.BAUD_DIV(100)) u_uart_rx (...)`（⭐ `:785`/`:831` 是 `.BAUD(500_000)`） |
| 发 | `top.v:945-946` `.BAUD_DIV(100)` `) u_uart_tx (...)` |

⭐ **`.BAUD_DIV(100)` = 500 kbps**（⭐ 50 MHz ÷ 500 k = **100，整除 ⇒ 误差 0**）。

**③ `constr/top.cst`：新增 2 条 `IO_LOC` + 2 条 `IO_PORT`**
```
IO_LOC  "uart2_rx" G22;    // ⭐ PMOD0_IO3（FPGA 收 ← ESP32 的 TX）
IO_PORT "uart2_rx" IO_TYPE=LVCMOS33 PULL_MODE=UP   BANK_VCCIO=3.3;   // ⚠️ 电平待核，见 §四
IO_LOC  "uart2_tx" G21;    // ⭐ PMOD0_IO2（FPGA 发 → ESP32 的 RX）
IO_PORT "uart2_tx" IO_TYPE=LVCMOS33 PULL_MODE=NONE DRIVE=8 BANK_VCCIO=3.3;  // ⚠️ 同上
```
⚠️ `uart2_rx` 用 `PULL_MODE=UP`（⭐ **串口空闲是高电平**），`uart2_tx` 用 `NONE`（⭐ 输出，上拉无意义）
—— ⭐ 与现有那路的理由**逐条一致**（`constr/top.cst:359-362`）。

## 四、⚠️ 引脚与电平（🔴 有一项**必须现场核**）

| ⭐ 项 | ⭐ 值 | ⭐ 依据 |
|---|---|---|
| 引脚 | `PMOD0_IO2` = **`G21`**（FPGA 发）· `PMOD0_IO3` = **`G22`**（FPGA 收） | `files/10-硬件/板卡替换评估/引脚预算核算.md:147-148` |
| Bank | 🔴 **`BANK2`**（`BANK2_G21_IOT144A` / `BANK2_G22_IOT144B`） | `files/10-硬件/开发板与引脚资料.md:161-162` |
| 电平 | 🔴 **未核** | ⚠️ 见下 |

### 🔴🔴 ⛔ 别照抄 `PMOD0_IO0`/`IO1` 的结论

⭐ `PMOD0_IO0`/`IO1`（`V18`/`V19`）在 **`BANK8`**（= `LVCMOS33`），
⚠️ 而 `IO2`/`IO3`（`G21`/`G22`）在 **`BANK2`** ⇒ 🔴 **不同 bank，电平必须单独核**。

⭐ **核法（⭐ 二选一）**：
1. 查板卡原理图里 **`PMOD0` 的 VCCIO 网络**；
2. 实测：用万用表量 **`PMOD0` 的 VCC 针**。

⚠️ §三 示例里的 `LVCMOS33` / `BANK_VCCIO=3.3` 是**占位值** ⇒ ⭐ **核完再写**。

### ⚠️ 另一个已知约束

⭐ **`PMOD` 与 `SDRAM` 是 `0Ω` 二选一**（`constr/top.cst:154`）
⇒ ⭐ 用 `PMOD0` 就**不能插 `SDRAM` 模块**（⭐ 本项目不用 SDRAM ⇒ ✅ 可用）。

## 五、⭐ 接线（🔴 交叉接）

| ESP32 侧 | ⭐ 方向 | FPGA 侧 |
|---|---|---|
| `GPIO17`（UART1 **TX**） | ──→ | **`G22`**（`uart2_rx`，FPGA 收） |
| `GPIO18`（UART1 **RX**） | ←── | **`G21`**（`uart2_tx`，FPGA 发） |
| `GND` | ── | `GND`（⭐ **必须共地**） |

⭐ 依据：`esp32/ble/main/ble_config.h:91-92`（⭐ 原文即写
`ESP32 TX(GPIO17) -> FPGA UART2_RX(G22)` / `ESP32 RX(GPIO18) <- FPGA UART2_TX(G21)`）。

### ⚠️⚠️ 命名陷阱（⭐ 两侧叫法不同，⛔ 别串）

| ⭐ 侧 | ⭐ 它叫 | ⭐ 依据 |
|---|---|---|
| **ESP32 侧** | **`UART1`** | `esp32/ble/main/ble_config.h:91`（ESP32 的 UART1 外设） |
| **FPGA 侧** | **`UART2`** | `files/10-硬件/板卡替换评估/引脚预算核算.md:147` |

⇒ ⭐ **同一条物理链路，两侧名字不一样** ⇒ ⭐ 文档与对话里**必须带侧别**，⛔ 否则必然串。
