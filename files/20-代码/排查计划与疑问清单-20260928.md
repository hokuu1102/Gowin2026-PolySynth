## 一、🔴 核心怀疑（结构性缺陷，有代码依据）

`note_manager.v` 的"重触发两步走"用了**单套全局寄存器**：

```verilog
reg        retrig_hold;      // ← 只能表达"一个 voice 在重触发"
reg [IDX_W-1:0] retrig_idx;  // ← 只能指向"一个 voice"
reg [1:0]  retrig_state;     // ← RT_LOW / RT_HIGH 是【全局】的

assign hold_mask[mg] = retrig_hold & (retrig_idx == mg);   // 只对 1 个 voice 有效
assign gate_mask[mg] = gate_r[mg] & ~hold_mask[mg];
```

⚠️ **而"两步走"本质是【每 voice 一个】的操作** ⇒ 🔴 **两处孤儿路径**：

### 孤儿路径 ①：`retrig_idx` 被**抢占**

```
① voice A 进入重触发 ⇒ retrig_idx=A, retrig_state=RT_LOW, gate_r[A]<=0
② 一个 sample_tick ⇒ gate_r[A]<=1, retrig_state=RT_HIGH, retrig_hold<=0
③ 🔴 另一轴的 same_valid 命中 voice B
   ⇒ retrig_idx <= B        ← ⭐ A 【失去所有者】
④ ⇒ (f) 段此后只操作 B
   🔴 而 A 的 gate_r[A] 停在 1，hold_mask[A]=0
   ⇒ ⭐ 没有任何人再拉低它（除非该轴再来一个 note_off）
```

### 孤儿路径 ②：`note_off` 被 `gate_mask` **挡掉**

```verilog
// ST_DECIDE 的 note_off 分支（:514-516）
for (i = 0; i < POLY_TARGET; i = i + 1)
    if (gate_mask[i] && (axis_r[i] == cur_axis))   // 🔴 gate_mask = gate_r & ~hold_mask
        gate_r[i] <= 1'b0;
```

```
① voice A 在 hold 期间 ⇒ hold_mask[A]=1 ⇒ 🔴 gate_mask[A]=0
② 此时该轴的 note_off 到达 ⇒ 循环【跳过 A】⇒ gate_r[A] 没被清
③ 随后 RT_HIGH 又把 gate_r[A] 抬回 1
④ ⇒ 若此后再无该轴的 note_off ⇒ ⭐ A 永久 gated ⇒ 【一直响】
```

### ⭐ 两条路径都与用户描述吻合

| 用户描述 | 吻合点 |
|---|---|
| ⭐ **"按一阵之后才出现"** | 需要**两次重触发重叠**（多轴 + 快速）⇒ 概率累积 |
| ⭐ **"50% 概率"**（尖音） | 竞态 ⇒ 与 `sample_tick` 相位相关 |
| 🔴 **"等几分钟仍存在"** | `gate_r=1` 无人拉低 ⇒ **永久** |
| ⭐ **"按新键，回音音高变成新键"** | 孤儿 voice 被 `ST_COMMIT` 抢占 ⇒ `axis_r`/`phase_r` 被改写 |
| ⭐ **"按两键以上才触发"** | 需要**多轴**才有 `same_valid` 抢占 |

| 量 | 值 | 来源 |
|---|---|---|
| `sample_tick` 周期 | **1024 clk = 20.48 µs** | `clk_gen` |

| decay peak→sustain | 9600 tick = **196.6 ms** | `DECAY_STEP=4` |

📌 **纪律**：判"卡死/不收敛"前，⭐ **静默时间必须 > 上表最坏值**。

⭐ **⇒ "尖音" = 极短（<1 ms）的大尖峰（~11 倍）**，⭐ 与用户 #5/#6/#7 完全吻合。

## 十一、⭐⭐⭐ 重大发现（2026-09-28，已仿真证明）

### 🔴 发现 1：曲谱 UART 与串口屏/命令**共用一条线** ⇒ **伪事件注入**

| 项 | 内容 |
|---|---|
| **位置** | `top.v`：`ur_done`/`ur_data` 同时喂 `uart_ui` + `calib_cmd` + `evt_uart_rx` |
| **协议** | `evt_uart_rx` 帧头 = **`0xA5`**，**9 字节定长**，靠**字节计数 + 空闲归位**同步 |
| 🔴 **缺陷** | 另外两路的**合法载荷里都可能出现 `0xA5`** ⇒ 被误当事件包 |
| ⭐ **仿真证据** | `tb/w3c/tb_evt_uart_rx_screen.sv`：喂 **8 个屏幕数值帧** ⇒ 🔴 **8 条伪事件** |
| 🔴 **伪事件内容** | `axis = 15`（**保留轴**）· `inc = 0x1FFFFF` · `kind = 0`（**只有 note_on**） |

#### ⭐⭐ 这直接解释"挂音"的**全部**特征

```
⭐ 伪事件是 axis 14/15（保留轴）且【只有 note_on】
⇒ 而键盘（axis 0~13）【永远不可能】产生 axis 14/15 的 note_off
⇒ 🔴 那个 voice 的 gate_r 永久为 1，⛔ 任何按键都清不掉
```

| 用户实测 | ✅ 吻合 |
|---|---|
| 「按同键不能清」 | ✅ |
| 「按**所有**键也不能清」 | ✅ |
| 「持续几分钟」 | ✅ 无人能清 |
| 「断电才清」 | ✅ 寄存器状态 |
| 「~50% 概率」「按一阵后累积」 | ✅ 取决于 UART 上是否出现 `0xA5` |

#### ✅ 已实施的**最小修复**

```verilog
// top.v —— 曲谱通路做成编译期开关，⭐ 默认 0 = 禁用
localparam integer SCORE_UART_ENABLE = 0;
...
.score_valid_i (SCORE_UART_ENABLE ? eu_evt_valid : 1'b0),
```

⛔ 不动 `evt_uart_rx` / `uart_ui` / `calib_cmd`；⭐ 恢复曲谱需换**独立 UART 线**。
