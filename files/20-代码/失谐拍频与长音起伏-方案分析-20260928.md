## 二、① Beating 的根本原因（逐条回答你列的 6 问）

### 2.1 固定频差为什么**必然**产生拍

两个同幅振荡器，频率 f₁ = f、f₂ = f + Δf：

```
x(t) = A·cos(2πf₁t) + A·cos(2πf₂t) = 2A·cos(πΔf·t) · cos(2π f̄ t)      f̄ = (f₁+f₂)/2
                     └──── 包络 ────┘   └── 载波 ──┘
```

- **载波** = 平均频率 f̄（音高）
- **包络** = `|2A·cos(πΔf t)|` ⇒ **周期 T = 1/Δf，深度 100%（理论零点 = 0）**

关键点：**两路之间的相对相位 φ(t) = 2π·Δf·t + φ₀ 是 t 的线性函数，斜率就是 Δf。**
只要 **Δf ≠ 0**，φ(t) 就会一直转，包络就一直起伏 —— 这与"是什么波形"**无关**。

> ⚠️ 注意：这里说的"必然"是指**存在性**必然。**深度**可以改变（见 2.4、2.6），**周期**不能。

### 2.2 为什么 **random initial phase 不能消灭长期拍**

初相只进 `φ₀`：

```
包络 = |2A·cos(πΔf·t + φ₀/2)|
```

| 改什么 | 结果 |
|---|---|
| 改 `φ₀`（随机初相） | ⭐ **只是把拍的【时间起点】平移** —— 周期不变、深度不变、**永远重复** |
| 改 Δf | ⭐ **才改变周期**（这是唯一有效的旋钮） |

⇒ ⭐⭐ **对"单个长音"这个场景，随机初相的效果是 0。**
它的真实作用只有三个（都要保留，但别指望它治拍）：

| 真实作用 | 机理 |
|---|---|
| ① **起音 headroom** | 多个副本同相起音会瞬时叠加（`N×A`）；去相关后是 `√N·A`（`oscillator_bank.v` 的 `phase_seed` 去相关初相注释已记） |
| ② **多 voice 去相关** | 不同键/不同层弹**同一个音高**时，避免"像重弹一次"（`K-95`） |
| ③ **让每个音的拍起点不同** | ⚠️ **只在同时有几个 voice 在响时**才让整体听感不那么齐 —— 单音场景无效 |

⚠️ **当前实现是"固定 0 / 1/4 周期"，不是随机**（`oscillator_bank.v` 的 `phase_seed`）⇒
每次按同一个键，拍的相位**完全一样** ⇒ **"机械感"被重复强化的一个来源**。
（这是 C 方案唯一的真正价值所在，见 §三.C。）

### 2.3 为什么**低音区**特别容易出现慢速、明显的起伏

两个独立机制叠加：

**(a) 恒定 cents ⇒ 拍频 ∝ 频率 ⇒ 低音拍慢**（§1.4 的表：0.43 Hz vs 1.08 Hz）

**(b) 人耳对"起伏"的敏感区间是有窗口的**（听感事实，非项目特有）：

| Δf 区间 | 听感 |
|---|---|
| ≪ 0.5 Hz | 不再是"波动"，而是**一次缓慢的电平变化**（长音里像"渐弱/渐强"） |
| **0.5 ~ 3 Hz** | 🔴 **清晰的周期性起伏** —— "机械、打拍子、一鼓一鼓"（**= 本项目当前所处区间**） |
| 3 ~ 15 Hz | ⭐ 合唱/厚度/颤动（"厚、活"） |
| 15 ~ 40 Hz | ⚠️ 粗糙（"嗡/走音"） |
| > 临界带宽 | 🔴 分成两个音高（"走调"） |

**(c) 低频的临界带近似恒定（~100 Hz）**，而低音的 Δf 只有 0.4~1 Hz
⇒ 两路**落在同一个临界带内被融合成一个音** ⇒ 听不到"两个音"，**只听到幅度在动** ⇒ 更容易被听成"音量故障"而不是"音色厚"。

⇒ ⭐ **低音区的困境（本文最重要的一条）**：
要让低音的"厚度"来自拍，就得让 Δf 落在 3~15 Hz；在 110 Hz 上，那需要
**`c ≈ 1200·log₂(1+3/110) ≈ 47 cents`**（≈ 半个半音）⇒ ✅ 厚，但 🔴 **走音/粗糙**。
⇒ **在小 cents 下，低音的"厚度"与"慢幅起伏"是同一个东西，参数上分不开。**
这条数学事实决定了：**低音区必须换一套加厚机制**（§三.E、§九）。

### 2.4 为什么两个波形**越像**，抵消越明显

把波表写成谐波和 `Aₙ`（相对相位 φₙ），两路各以 f₁、f₂ 播放：

```
x = Σₙ 2Aₙ·cos(π n Δf t) · cos(2π n f̄ t + φₙ)
       └──── 第 n 个谐波对各自的包络 ────┘
```

- **两路波形完全相同** ⇒ 每个谐波对的幅度乘积都是 `Aₙ²`，且相位一致
  ⇒ 交叉项最大 ⇒ **包络最接近"整体 100% 调制"**（理论：单个正弦对 → 零点为 0）
- **两路频谱互补/差异大** ⇒ 交叉项 `Σ AₙBₙ` 小 ⇒ **包络浅**

⭐ 这就是 E 方案（不同 wavetable）的数学根据：**厚度来自频谱并集，拍来自频谱交集。**

定量参考（两路**等频**时的零点深度，`r` = 较弱/较强一路的幅度比）：

| r | 零点 / 峰 | 深度 |
|---|---|---|
| 1.0 | 0.00 | **完全消失（−∞ dB）** |
| 0.9 | 0.053 | −25.6 dB |
| 0.8 | 0.111 | −19.1 dB |
| **0.7** | 0.176 | **−15.1 dB** |
| 0.5 | 0.333 | −9.5 dB |
| 0.3 | 0.538 | −5.4 dB |

⇒ ⭐ **F 方案（不等电平）能显著削浅"零点"**：r=0.7 时起伏不再是"消失/出现"，而是"轻微呼吸"。
⚠️ **但它不改变周期**（拍照旧一秒一次）⇒ 单独用只能**缓解**，不能消除"机械周期感"。

### 2.5 为什么 **normalization 解决不了**这个问题

| # | 原因 |
|---|---|
| 1 | 归一化的输入是 **`popcount(voice_active)` = 有几个 voice 在响**，⛔ **对相位关系完全盲**（`tdm_render_mixer.v` 的 `pc_l1`/`pc_sum` 与 `gain_sqrt_lut`） |
| 2 | 拍发生在**同一个 voice 内部的两个 lane 之间** ⇒ 是**相干叠加**；`1/√N` 的前提假设是**非相干**（`N` 个不同音高）⇒ **前提就不适用** |
| 3 | 它是**逐样本的静态增益**：一个与时间无关的常数，⛔ **改不了"包络随时间起伏"这个事实** |
| 4 | 限幅器（87.5%、二次软膝 + 平台）是**兜底**：正常演奏根本不该碰（`tdm_render_mixer.v` 的 `LIM_TH_W`/`KNEE_W`/`ceil_w`）⇒ 它管不了"低于阈值内的起伏" |

⭐ 它**唯一相关**的副作用（你们上一份分析已经抓到）：把"固定的最坏峰值"换成"时变峰值"
⇒ 影响的是 **headroom/标定**，⛔ 不是拍的听感。**两个问题必须分开记账。**

### 2.6 ⭐⭐ 换成真实乐器波表后，机制**变了吗**？

**周期：⛔ 没变。深度与音色：✅ 变了。** 逐条：

| # | 结论 | 依据 |
|---|---|---|
| 1 | **总包络仍是严格的周期函数，周期仍 = 1/Δf** | 所有谐波对的拍频是 `n·Δf`（都是 Δf 的整数倍） |
| 2 | **深度变浅、涟漪变多** | 各 `n` 的包络相位不同，零点不重合 ⇒ 总和的极小值抬高 |
| 3 | ⭐ **性质变了：从"音量起伏"变成"音色呼吸"** | 第 n 个谐波的零点在 `t = 1/(2nΔf)` ⇒ **基频消失的时刻，二次谐波还在峰上** ⇒ 每次拍不是"整体变轻"，而是"**基频周期性消失、只剩别的谐波**" |
| 4 | ⚠️ **越丰富的波表越容易"粗糙"** | 高次谐波的 `n·Δf` 会先进粗糙区。经验上限：**`N_max·Δf ≲ 15 Hz`** ⇒ **`c ≲ 25944 / (N_max · f)` cents** |
| 5 | ⭐ **不要因为"不是正弦波了"就认为拍不存在** | 上述 1 是数学恒等式，与波形无关 |

**由第 4 条得到的、可直接使用的"每张波表的 detune 上限"表**（按 `N_max·Δf ≤ 15 Hz` 反算）：

| f (Hz) | N_max = 10 | N_max = 20 | N_max = 40 |
|---|---|---|---|
| 110 | 23.6 c | 11.8 c | 5.9 c |
| 130.8 | 19.8 c | 9.9 c | 5.0 c |
| 164.8 | 15.7 c | 7.9 c | 3.9 c |
| 220 | 11.8 c | 5.9 c | 2.9 c |
| 261.6 | 9.9 c | 5.0 c | 2.5 c |
| 440 | 5.9 c | 2.9 c | 1.5 c |

⇒ ⭐⭐ **这张表就是"波表无关"的接口**：不写死"某音色用多少 cents"，
而是**由波表自己的最高有效谐波 `N_max` 反算上限**（可由脚本从波表数据算出，见 §三.I）。
⚠️ 注意：**原 `DETUNE_SH=8`（6.75 cents）在 C4 + 20 次谐波下超出上限**（`20 × 1.02 = 20 Hz > 15 Hz`）；⭐ **交付的 `DETUNE_SH=9`（3.38 cents）已回到上限内**（`20 × 0.51 = 10.2 Hz ≤ 15 Hz`）。

### 2.7 【附】如果未来 `OSC_PER_VOICE ≥ 3`：间隔要"不可通约"

N 个等间隔失谐副本（间隔 Δf）= 周期 1/Δf 的包络，零点更深但更窄。
⭐ **若间隔取** `Δf` 与 `1.414·Δf`（**无理比**），合成包络**没有短周期**（准周期）
⇒ **天然不机械**，且完全不需要漂移/随机。
⇒ ⭐ **这条对"未来增加 oscillator 数量"的场景是零成本方案**（只是不同的移位值，见 §三.H）。

## 三、② 各方案原理（A~G 逐条 + 我认为还该加的三条）

> 每个方案统一给：**原理 / 能解决什么 / ⛔ 不能解决什么 / 成本量级**。
> 成本量级用 §1.5 的换算基准：**每 lane 每 32 位加法器 ≈ 35~45 LUT**。

### A. Keytracked Detune（音高相关的失谐量）

**原理**：同一 cents 在不同音高上给出**不同的 Δf**。音高相关 ⇒ 拍周期可控。

**⭐ 方向辨析（必须澄清的一个常见说法）**：
"低音用更小 detune、高音用更大 detune"这句话**在本项目的目标下成立，但在"让合唱感一致"的目标下是反的**：

| 目标 | 正确的 keytrack 方向 | 理由 |
|---|---|---|
| 让每个音域都有"合唱感"（Δf 落在 3~15 Hz） | **cents ∝ 1/f（低音【更大】cents）** | 110 Hz 要 ~15.7 cents 才有 1 Hz 拍 |
| ⭐ **本项目的目标**（长音不要机械起伏 + 保留厚度） | **cents 随音高【升高】而增大，并由 `N_max` 设上限** | 低音区用小 cents **换不到厚度**（只有慢幅起伏），而 cents 一大就进入粗糙/走音区 ⇒ **低音区应把加厚任务交给波形差异（E）** |

⇒ ⭐ **结论：两条都对，对应不同目标。** 本项目选后者，但**理由不是"低音更容易走音"**，
而是 **"低音区靠 detune 根本换不到厚度"**。

> ⭐⭐ **外部依据见 §10.2（源码级核实）**：Surge 的 keytrack **实际是"以 MIDI 60 为中心的双极性"**
> （`±1 per 12 半音`）——⛔ **不是"低音少、高音多"**；issue #2449 已 closed 且**未改代码**。
> ⇒ ⛔ **不要把这个说法当成"业界既有做法"来引用**（会被当成事实错误）。
> ⭐ 但 issue 里那个"**把 keytrack 当乘数用**"的技巧值得借（见 §三.I）。

**能解决**：把"最坏的 1~2.3 s 机械区间"整体移开（低音区更慢/更低深度；中音区进入合唱区）。
**⛔ 不能解决**：只要 Δf ≠ 0，**周期依然存在**（只是换了周期）⇒ 对"绝对不能有周期性"的要求，需要配 D。

**实现口径（关键：只用移位，不用乘法器）**：
`detune_off = base_inc >> sel`，`sel` 按音高选择。
- `sel = 8 → 6.75 c`、`9 → 3.38 c`、`10 → 1.69 c`、`11 → 0.84 c`
- ⭐ **候选值全是"固定移位"= 纯连线**（0 成本）；成本只在"**选择**"那一步（见 §十一）
- ⭐ **不需要乘法器**：cents 只由移位档位离散给出，**精度 0.4 cents 级**（远优于需要）

**成本**：选择逻辑。**两条实现路线**（差别很大，见 §七）：

| 路线 | 位置 | 成本 |
|---|---|---|
| ① per-lane 3:1 选择（组合） | `oscillator_bank` lane 内 | **≈ 64 lane × 32 bit × 2 LUT ≈ 4,000 LUT** 🔴 偏贵 |
| ② **per-voice 寄存器 + 共享慢速更新** | `oscillator_bank` voice 级 | **≈ 1,000 FF + 150 LUT** ✅ 便宜（推荐） |

### B. Per-Voice Detune Spread（每个 voice 的失谐量略有不同）

**原理**：给每个 voice 一个不同的 detune 偏移（例如 ±0.2/±0.5/±1 cent），
让**不同键/不同层**的同音高不再严格相干。

**🔴 必须澄清（最容易被误解的一条）**：
**它【不解决】单个长音的拍** —— 因为拍是**同一个 voice 内部两个 lane** 之间的事，
换一个 voice 只改变"另一个 voice 的拍频"，**它自己内部的拍分毫不减**。
它解决的是 **`K-95`：跨 axis/跨层同音高的相位干涉**（"听起来像重弹了一次"）。

**实现（无状态哈希，⛔ 不需要 32 个随机源）**：
`spread = hash(voice_idx ⊕ lfsr_global)` ⇒ 取 2 bit 去做 `sel` 的 ±1 偏移。
**成本**：≈ 2 XOR × 32 voice + 1 个 16 位 LFSR ⇒ **≈ 100~200 LUT / 16 FF**。

**能解决**：多声部/多层的"齐奏感、干涉感"。
**⛔ 不能解决**：单音长音的周期性起伏（**用户的报告正是单音场景**）。

### C. Random Initial Phase（随机初相）

**原理/边界**：见 §2.2 —— ⭐ **对拍的周期与深度【零效果】**，只移动拍的起点。

**⭐ 它的真实价值（建议做，但别当成解法）**：

| 价值 | 说明 |
|---|---|
| ① 起音 headroom | 现状已用"0 / 1/4 周期"实现（`:185-211`） |
| ② ⭐ **打破"每次按键都一模一样"** | 现状初相**固定** ⇒ 每次按同一个键，拍的相位完全相同 ⇒ 机械感被重复强化 |
| ③ 多 voice 去相关 | 配合 B 一起做才有效 |

**实现**：**note-on 时刻**从 LFSR 取一个相位种子给 osc1（⛔ 不是每个 lane 各自随机 ——
那会破坏"起音不抵消"的现有保证）。
**成本**：**1 个 16~24 位 LFSR**（≈ 24 FF + 5 LUT）+ note-on 锁存（`POLY_TARGET × 32 bit` 若逐 voice 存）
—— ⚠️ 如果只想"每次按键不一样"，连锁存都不用：直接给一个全局 LFSR 相位。

> ⭐⭐ **代码实查（⚠️ 与"初相"有关的两个后果，供并发的"尖音"线参考）**：
> `oscillator_bank.v` 的 `phase_q` 复位分支只在 **`!rst_n_i`（复位）**时写 `phase_q <= phase_seed`，
> **note-on 时⛔ 不重置相位**；相位只在 `lane_active` 时推进（`:226-228`）。
> ⇒ ① **"0 / ¼ 周期"这对初相实际上只在上电后那一次生效**；
>    之后每次按下键，两 lane 的相对相位 = **上次释放时冻结下来的任意值** ⇒ ⭐ **起音峰值是随机的**：
>    接近同相 ⇒ 峰值 ≈ `2A`（`>>>1` 后仍 ≈ `A`），接近正交 ⇒ ≈ `√2·A` ⇒ ⚠️ **两者差 3 dB**。
> ⇒ ② 若"偶发尖音/失真"与幅度有关，**一条低成本候选修法**是：
>    **在 note-on（`lane_active` 上升沿）应用一次固定/随机的去相关相位**，
>    让起音峰值**确定且更低**（而不是靠"上次留下的相位"碰运气）。
> ⚠️ **但这条⛔ 不治长音拍**（§2.2）—— 它只治**起音那一下**。两件事要分开记账。

### D. Very Slow Oscillator Drift（慢漂移）—— ⭐⭐ 分清两种，否则白做

| 类型 | 机理 | 对拍的效果 |
|---|---|---|
| **D1 · 音高漂移**（两 lane 同向 `+δ` cents） | Δf 不变（差值里抵掉了） | 🔴 **完全无效**（只加"模拟味"） |
| **D2 · 失谐深度漂移**（改变两 lane 的**频率差**） | **Δf 随时间变化** | ⭐⭐ **有效：拍不再严格周期** |

**D2 的量化条件**（这是本节的关键）：
- 要让"周期"不可分辨 ⇒ **Δf 的相对变化要 ≥ ±30%**，理想是 **0.5× ~ 2×**
- 变化的时间尺度 **0.3 ~ 1.5 s**（更快 → 变成颤音/抖；更慢 → 又被听成周期）
- ⭐ **实现方式 = 让 `sel` 在 {7,8,9} 之间慢速跳变** ⇒ Δf 在 0.5×~2× 之间游走
  （110 Hz：0.43 → 0.86/1.72 Hz ⇒ 周期 2.3 s → 1.2/0.6 s，**不再是一个固定周期**）
- ⭐⭐ **跳变不会产生咔声**：相位是连续的，**只有频率斜率变**（对比"改相位"会咔）

**成本**：1 个慢速 LFSR/计数器（≈ 24 FF）+ 每 voice 2 bit 的 dither 选择（XOR 哈希，≈ 100 LUT）。
**⛔ 不能解决**：它让"机械周期"变成"无规呼吸"，**但仍有幅度起伏** ⇒ 想彻底没有起伏必须减小 Δf 或走 E。

### E. 不同 waveform / wavetable / harmonic structure —— ⭐ 最重要的一条

**原理（数学）**：厚度来自**频谱并集** `Σ(Aₙ² + Bₙ²)`，拍来自**频谱交集** `Σ AₙBₙ`。
把 B 选得与 A **互补**，就能在不制造深拍的前提下加厚。

**四种组合的对照（本节核心结论）**：

| 组合 | 拍 | 音色 | 结论 |
|---|---|---|---|
| 同音高 + **同一张**波表 | 无（严格同相 = 相干 ×2） | **无变化** | 🔴 **纯浪费**（就是修复前"假 unison"的行为，`:72-78`） |
| 同音高 + **不同**波表（固定相位关系） | ⭐ **完全没有** | = **一张新波表** | ⭐ **数学上等价于"把两张表加起来做成一张新表"** ⇒ 若两 osc 永远同音高同相位，**直接改表更省资源** |
| 同音高 + 不同波表 + **相位关系缓慢变化** | 无周期 | **缓慢的音色呼吸** | ⭐⭐ **低音区最佳配方**（靠 D2 让相对相位慢漂） |
| **微小频差（0.5~2 c）+ 不同波表** | 周期 5~25 s（当前音域） | 厚 | ⭐ 单音内**看不到一个完整周期** ⇒ 不会被听成机械 |

**选择规则（与具体波表解耦、可自动化）**：

| 规则 | 判据 |
|---|---|
| R1 | 优先选**频谱互补**的一对（如"基频强 + 高次弱" vs "基频弱 + 高次强"；或奇/偶互补），**⛔ 不要选"两张都很亮的相似表"** |
| R2 | 两表的**互相关系数**（时域归一化互相关）应尽量小；可脚本计算，**目标 < 0.5** |
| R3 | 两表都要**同周期（单周期波表）**且**无直流**（否则会引入偏置/低频跳动） |

**⭐ 现成资源（零 BSRAM）**：`wavetable_bank` **每个音色已经存了 soft/hard 两份**
（`soft` = 正弦族、`hard` = 锯齿族），当前**按力度插值**（`oscillator_bank.v` 的 `mix_q`/`blend_sum`）。
⇒ **osc0 读 soft、osc1 读 hard** 就能立刻拿到"同音高、不同谐波结构"的厚度：
- **新增 BSRAM = 0**、**新增表数据 = 0**
- 只需把"TDM 那条软硬插值"改成**与 lane 相关**（`mix_q` 变成 `f(OSC_IDX)`），或给 osc1 的插值权重加一个固定偏置
- ⚠️ 注意：这会**改变当前"力度→亮度"的映射**（因为现在两个 lane 都吃同一个 `mix_q`）⇒
  建议用"**osc0 用当前 `mix_q`、osc1 用 `min(255, mix_q + BIAS)`**"，既保留力度-亮度语义，又制造两路频谱差
- ⚠️⚠️ **标定影响（必须先算这笔账）**：`soft` 峰值 = **16384（50% 满幅）**、`hard` = **32767（100%）**
  （逐点读过 `wavetable_bank.v` 的 timbre 0 数据）⇒ ⭐ **让 osc1 偏向 `hard` 会抬高两路之和的峰值与 RMS**
  ⇒ 🔴 **会动到 `gain = 88` 的标定前提**（`tdm_render_mixer.v` 的 `gain_sqrt_lut`/`norm_gain_r` 已因这类改动返工 6 次）。
  ✅ 安全做法（二选一）：① **把两路权重按"峰值和不变"归一**（osc0 权重略降）；
  ② 或**改完立刻用 `build/exp/exp_mixer_headroom.v` 那套方法重测峰值**，⛔ 不许"看着差不多就这样"

**成本**：读表选择逻辑 ≈ **10~40 LUT**（TDM 共享，1 份）；若未来改成"每音色 N 个 frame 变体" ⇒ 表数据 +131 kbit/音色对（**+5 BSRAM**，占 118 块的 4%）。

**⛔ 注意边界**：把 osc 换成不同 frame 属于**"音色设计"范围**，⛔ **不要在这儿引入效果器**（§十三）。

### F. Unequal Oscillator Level（不等电平）

**原理**：零点深度 = `(1−r)/(1+r)`（§2.4 表）。r=0.7 ⇒ 起伏只剩 15 dB 深。

**⭐ 关键工程约束（避免重演 gain 反复返工）**：
> **用"权重和 = `OSC_PER_VOICE`"的写法**（例如 `1.15 : 0.85`，和 = 2）
> ⇒ **最大相干峰值不变** ⇒ **`gain = 88` 的标定继续有效**。
> ⛔ **不要用 `1.0 : 0.7`（和 = 1.7）** —— 那会改变单 voice 峰值，
> 必须**连带重标定 `gain`**（`tdm_render_mixer.v` 的 `gain_sqrt_lut`/`norm_gain_r` 已经因为这类改动返工过 6 次）。

**成本**：⭐ **在 mixer 做（共享硬件）≈ 40 LUT**；⛔ **不要在每个 lane 做**（+2,000 LUT）。

**⛔ 不能解决**：周期仍在（§2.4）⇒ 单独用只把"消失/出现"变成"呼吸"。

### G. `0 / +D` 而不是 `−D / +D` —— ✅ **现状已经是 0/+D**，但有个副作用没人提

**现状**：`detune_off` 只加在 `OSC_IDX != 0` 上（`:177-179`）⇒ 已经是 **0/+D**。

**两种写法的定量差异**（`r = 2^(c/1200)`）：

| 写法 | Δf | 音高中心 |
|---|---|---|
| **0 / +c** | `f·(r−1)` | **偏高 c/2**（当前 **+3.4 cents** 🔴） |
| **−c/2 / +c/2（对称）** | `f·(r−1)`（同总跨度时相同） | ✅ **标称** |
| **−c / +c** | `f·(r−1/r)` ≈ **2 倍** | ✅ 标称 |

⇒ ⭐ 两条结论：
1. **"0/+D vs ±D"真正的差别不是"有没有拍"，而是**：同数值下 **Δf 差 2 倍**、**音高中心差 c/2**。
2. ⭐ **当前整机在 `DETUNE_ON=1` 时比标称【高 3.4 cents】**（恒定音准偏移，不是抖动）。
   要修也很便宜：**对称化**（`osc0 = base − off/2`、`osc1 = base + off/2`）⇒ **0 成本、Δf 不变、音准回到标称**。

> ⭐ 外部对照（§10.1、§10.6）：Surge / `clap-saw-demo` 的 detune 都是**相对（半音/音分）** ⇒ 拍频随音高变；
> 但 Surge **另有 `absolute` 模式 = 恒定 Hz（0..16 Hz，扩展 0..192 Hz）**
> ⇒ ⭐ **"恒定 Δf"是一个正式的产品口径**；本项目若要做 keytrack，**本质上就是把这条口径做成 per-note 表**（§三.A / §三.I）。

### H. 【新增】不等间隔 / 不可通约间隔（面向"未来 osc 变多"）

**原理**：3 个以上副本时，间隔取**无理比**（如 `Δf` 与 `1.414·Δf`）⇒ 合成包络**准周期**。
**成本**：0（只是不同的移位值）。**适用**：`OSC_PER_VOICE ≥ 3` 的未来形态。

### I. 【新增】"由波表自动定 detune 上限"（把音色变成数据，而不是代码分支）

**原理**：脚本对每张表统计 **N_max**（最高有效谐波）与**谱重叠**，反算
`c_max = 25944/(N_max·f)`（§2.6），生成**每音色的 detune 档位表**（表数据）。
**成本**：0 逻辑（表常量）+ 生成脚本。
⭐ **收益**：以后队友**换波表/加波表/加 frame** 时，只需要**重跑脚本**，
⛔ **不需要改 RTL、不需要重新设计算法** —— 这正是你要求的"与具体音色解耦"。

### J. 【新增】"失谐深度 dither"（= D2 的量化实现）

见 D2。**成本**：≈ 150 LUT + 24 FF，**无新时钟域、无新乘法器**。

## 五、④ 三套组合方案

### 方案 1 · Minimal（目标：最小改动、**不碰队友文件**、可当天上板对比）

| 组成 | 具体 | 成本 |

| ① `DETUNE_SH` 8 → **9** | 6.75 c → **3.38 c** ⇒ T 从 0.9~2.3 s 变成 **1.8~4.7 s** ⇒ 单个长音内**不到一个完整周期** | **0**（`top.v` 参数） |

  ⛔ **还没得到"真正的加厚"**（那要靠 E）

**⭐ 收益 vs 复杂度（你要求的分析）**：

| 收益 | 是否值得 |
|---|---|
| ⭐⭐ **低音区终于有"真厚度"**（来自频谱并集，不来自拍） | ✅ **值得** —— 这是唯一能同时满足你三条约束的机制 |

### 6.1 ⭐⭐ 判据 1（决定性）：**拍周期是否 ∝ 1/f**

> ⭐⭐ **已有证据 + 缺的那一半**（详见 §1.6.1）：
> 现成的 `echo_period.txt` 实测 **1.740 s**，与 **D3 的预测 1.744 s 差 0.2%**（其他候选都差 20%+）
> ⇒ ✅ **"是不是失谐"这一问，其实已经有半张答卷了**。
> ⛔ **不要重测同一件事**；缺的**只有两件**：
> ① **回查**那次抓取弹的是哪个键（若确实是 D3 ⇒ 结论成立）；
> ② ⭐ **换一个键**（例如 C3 或 A3，与 D3 差 ≥3 个半音）**再抓一次**，看周期是否按 `256/f` 变。
> ⇒ ② 是**唯一还没被验证的那一步**，也是**唯一能排除"计数器/帧周期"类解释的一步**。

**做法**：按住 **C3(130.81 Hz)** 与 **A3(220 Hz)** 各 5 秒（**单音、⛔ 不要和弦、⛔ 不要带释放段**），
导出/抓取后量**包络自相关主峰**（⛔ 不要用"过均值计数"，见 §1.6.2 第 3 条）。
**预言**：**1.96 s vs 1.16 s，比值 = 220/130.81 = 1.68**。

| 观测 | 结论 |
|---|---|
| 周期比 ≈ 1.68（且与音高成反比） | ✅ **确认是失谐拍频** ⇒ 按 §五 的方案做 |
| 周期**与音高无关**（同一个值） | 🔴 **不是失谐** ⇒ 去查力度/`pos`/ADSR/`gain` 通路（见 6.2 的 ②③） |
| 周期 ≈ 节拍器周期 / 计数器回绕（0.671 / 1.342 s…） | 🔴 查 `popcount`/保留池/自由计数器（⚠️ `_period.txt` 已列出候选，见 §1.6.2） |

### 8.2 ⚠️ 先固定"detune 口径"（⛔ 不然后面所有数字都对不上）

> ⭐ 外部核实（§10.1、§10.6）：**Surge 的 "Unison Detune" 与 `clap-saw-demo` 的 "Unison Spread"
> 都是【单边峰值】，不是总展宽** —— 系数跨度是 2，所以 **总展宽 = 2 × 参数值**。
> ⚠️ 本项目现在写 `3.38 cents`（交付 `DETUNE_SH=9`），**语义是"第二路相对第一路的偏移" = 单边** ⇒ **总展宽也是 3.38 c**
> （因为另一路是 0）。若改成对称 `±D/2`，**总展宽仍是 3.38 c**（每边 1.69 c）。
> ⇒ ⭐ **每次报数必须写清是"单边偏移"还是"总展宽"**，⛔ 否则和文献/队友对不上。

## 九、⑤ 任意 wavetable 下的稳定规则（逐条回答你的 5 问）

| # | 问题 | 规则 | 依据 |
|---|---|---|---|
| **1** | 两 osc 波表**高度相似** | 🔴 **拍的深度最大**（交叉项最大）⇒ **detune 必须很小或为 0**；加厚改走"不等电平 + 慢速相位漂移"；⭐ 最优解是**把其中一路换表** | §2.4 |

### 10.1 ⭐⭐ Surge · Unison detune 的实际算法

**源码**（`libs/sst/sst-basic-blocks/include/sst/basic-blocks/dsp/OscillatorDriftUnisonCharacter.h:183-196`）：

```cpp
if (n_unison == 1) bias = 1.0;  else bias = 2.0 / (n_unison - 1);       // L183-186
inline valtype detuneOffset() const { if (n_unison == 1) return 0; return -1; }  // L190-195
inline valtype detune(int voice) const { return detuneBias() * voice + detuneOffset(); } // L196
```

⇒ **线性、等间距、关于中心对称（−1 … +1）**，`voice=0` ⇒ −1、最后一个 ⇒ +1。**⛔ 不是随机。**

| 项 | 值（源码/手册一致） |
|---|---|
| 参数范围 | **0…100 cents**（extend 0…1200 cents；absolute 模式 0…16 Hz / 0…192 Hz） |
| 应用方式 | 以**半音**加到 pitch：`pitchlag.v + lfodetune + ud * unisonOffsets[u]` |
| ⇒ 后果 | 离心量在**音分**上恒定，**⛔ 不随音高缩放**（唯一随音高变的是 absolute 模式） |
| 随机在哪里 | ⭐ **只用在初始相位**（`ClassicOscillator.cpp:239-241`）与 drift |

### 10.2 ⭐⭐⭐ Surge · keytrack 的**真实方向**（⚠️ 直接纠正一个流行说法）

**源码**（`SurgeVoice.cpp:511-512`，L831 同式）：

```cpp
modsources[ms_keytrack]->set_output(0, (state.pitch - (float)scene->keytrack_root.val.i) * (1.0f / 12.0f));
```

⇒ ⭐ **双极性：±1 per 12 半音，中心 = "Keytrack Root Key"（默认 MIDI 60）**
⇒ ⭐ **高于根音更多 detune，低于根音【也】更多 detune** —— ⛔ **不是"低音少、高音多"**。

**⭐ Issue #2449 的原文与结局**（[issue #2449](https://github.com/surge-synthesizer/surge/issues/2449)，2020-08-07，**已 closed 但【无 PR】**）：

| 项 | 内容 |
|---|---|
| 作者**期望** | "低音少 detune、高音多 detune"（⭐ **这正是那个说法的出处**） |
| **实际**行为 | 双极性、以 MIDI 60 为中心；⭐ **60 附近几乎无 detune，越远离 60（上或下）越大** |
| 维护者解释 | 贴出上面两行源码："basically +/- 1 per 12-tone-octave"；提议把 `12` 换成 `scale.length`（**未采纳**） |
| 作者的**解法** | ⭐⭐ **Unison Detune 固定 6 cents，再给 `Keytrack → Unison Detune` 一个 0.001 cents 的极小深度** ⇒ **把 keytrack 当成"乘数"用** ⇒ 得到单向递增 |
| 当前 main | `1.0f/12.0f` **未改**，行为不变 |

⇒ ⭐⭐ **对本项目的三条直接启示**：

1. ⛔ **"低音更小、高音更大"不是 Surge 的实现行为**，而是 issue **报告者的期望**
   —— 本项目**不能**把它当"成熟 synth 的既有做法"来引用（⚠️ 会被当成事实错误）。
2. ⭐ **但"把它当乘数用"这个技巧可直接借**：实现成"**基准 detune（表）× keytrack 系数（表）**"，
   换波表/换音域只改数据（= 本文 §三.I）。
3. ⭐ **方向问题本文 §三.A 已按物理独立推出**：方向取决于目标
   （"合唱感一致" ⇒ 低音要**更多** cents；"低音不要机械起伏" ⇒ 低音要**更少** cents）。

### 10.3 ⭐⭐⭐ Surge · Osc Drift（**非周期的**慢漂移，per-unison-voice）

**源码**（同头文件 `:36-68`，`DriftLFO`）：

```cpp
inline void init(bool nzi) { d = 0; d2 = 0; if (nzi) d2 = 0.0005 * ((float)rand() / (float)(RAND_MAX)); } // L40-46
inline float drift_noise(float &lastval) {
    constexpr float filter = 0.00001f;
    constexpr float m = 316.227766017f;               // 1/sqrt(filter)
    float rand11 = (((float)rand() / (float)RAND_MAX) * 2.f - 1.f);
    lastval = lastval * (1.f - filter) + rand11 * filter;   // ⭐ 极重低通的随机游走
    return lastval * m; }
```

| 项 | 实测/推算 |
|---|---|
| 本质 | ⭐ **随机游走（非周期！）**，⛔ 不是 LFO ⇒ **天生不会产生"机械周期"** |
| 更新率 | 每 `process_block` 一次（`BLOCK_SIZE = 32`）⇒ 48 kHz 下 **≈1500 次/秒** |
| 等效拐点 | `α ≈ 0.0149 /s` ⇒ **≈0.002 Hz**、时间常数 **≈67 s**（计算值） |
| 深度 | "Osc Drift" **0…100%**，**直接以半音**加进 pitch；100% 时滤波后 std ≈ **0.41 半音（≈41 cents）** |
| 粒度 | ⭐ **每个 unison voice 一份**（`DriftLFO driftLFO[MAX_UNISON]`），各自 `rand()` |
| ⭐ "Randomize initial drift phase" | = `nonzero_init_drift`（`scene->drift.extend_range`）⇒ ⭐ **给每条随机游走一个随机起点** |

⇒ ⭐⭐ **关键认知（比"drift 有多少 cents"重要得多）**：
**Surge 的 drift 时间常数 ≈67 s ⇒ 在单个 5 秒的音符内它几乎是"静止"的**
⇒ 单音内部的拍**仍然是周期的**！
⇒ 它之所以不"机械"，靠的是 ⭐ **"每次 note-on 取随机起点"** ⇒ **每个音的有效失谐量都不同**。
⇒ ⭐⭐ **这正好印证本文 D2 的结论**：真正的杠杆是"**让 Δf 不是一个固定值**"，
实现它有两条路：① **慢速游走**（Surge 用 67 s；本项目可用更短的 **0.3~3 s** 让它在一个长音内也动起来）
② **每次 note-on 随机起点**（⭐ 成本最低、收益最直接）。

### 10.4 Surge · 归一化 = **1/√N** ✅（与本项目 `gain = 88/√N` 的选择一致）

### 10.5 Surge · 初相 / retrigger（⭐ "默认就是随机初相"）

### 10.6 ⭐ `clap-saw-demo/src/saw-voice.cpp`（Surge 官方教学实现，255 行全文核实）

```cpp
// note-on 时算一次（⛔ 不是每块/每样本）
float dI = 1.0*i/(unison-1);
unitShift[i] = 2*dI - 1;                              // ⭐ 线性对称 ∈ [-1,+1]
phase[i]     = dI;                                    // ⭐ 相位【等分】，非随机
panL[i] = cos(0.5*pi*dI); panR[i] = sin(0.5*pi*dI);   // 等功率 pan
norm[i]  = 1.0/sqrt(unison);                          // ⭐ 1/√n
// 相位增量：uniSpread 单位 cents，/100
dPhase[i] = baseFreq * pow(2.0, (uniSpread+uniSpreadMod)*unitShift[i]/100.0/12.0) / sampleRate;
// 混音：L += 0.2 * norm[i] * AR * panL[i] * saw;      // 0.2 = 固定 headroom
```

| Osc Detune | **−200..+200 cents** | 与 unison spread 分开建模 |

### 10.8 ⭐⭐ 研究小结：成熟 synth **不"消除"拍**，它们让拍"不可辨"

把上面所有已确认事实合起来，Surge 的做法其实只有三招，⛔ **没有任何一招标榜"消除 beating"**：

| # | 招 | 作用 | 本项目能否照抄 |
|---|---|---|---|
| ① | **每振荡器独立慢漂移**（随机游走，τ≈67 s，深度可到几十 cents） | 让"有效失谐量"随时间/随音符变化 ⇒ ⭐ **拍频不是固定值** | ⚠️ **半照抄**：τ=67 s 意味着**单个 5 秒音符内它几乎是静止的** ⇒ 必须补上 ②；或把 τ 缩短到 **0.3~3 s**（本项目音域窄，缩短代价更小） |
| ② | ⭐ **note-on 随机初相**（默认行为）+ **drift 随机起点** | 让**每个音符都不一样** ⇒ 消除"每次按同一个键都一样"的机械感 | ✅ **完全可照抄**（1 个小 LFSR，见 §十一：≈24 FF + 5 LUT） |
| ③ | `1/√N` 电平归一（无任何自适应增益） | headroom/响度稳定，⛔ **与拍正交** | ✅ 本项目已有（`gain = 88/√N`） |

⇒ ⭐⭐ **由此得到本项目最关键的一条取舍**：

```
成熟 synth 的"厚度"来自 unison（同一振荡器复制 N 份，线性对称 detune）；
它们靠"独立慢漂移 + 每音随机"把拍变成"不可辨的游走"。

⛔ 本项目的困境不在"没有这套机制"，而在【音域只有 1.5 个八度】：
   · 低音区（110~160 Hz）：Δf 太小 ⇒ 加厚无效、只剩慢幅起伏
   · 又没有第二个八度以上的空间去"摊薄"这个效应

⇒ 所以本项目【必须】补一条成熟 synth 不需要的机制：
   ⭐ 把低音区的厚度从【音高失谐】搬到【频谱/谐波结构差异】（方案 3 的 E）
   并把 detune 降到 1~3 cents 的量级（只作为"活"的调味，不作为厚度的主力）
```

⚠️ **诚实标注（⛔ 不要当成"业界共识"）**：
"用不同波表叠同音高做厚度"**在成熟软件里查不到主流依据**（§10.7），
它是**按本项目约束推出来的**（§三.E 的数学是成立的，但与 Surge 的路线不同）。
⇒ 汇报/答辩时**要说清这一点**（⛔ 别说成"Surge 也这么做"）。

## 十二、【相关但 ⛔ 本次不处理】波表峰值 / 削顶

> 按你的要求**严格分开**。这里只写"边界"，⛔ 不并入上面的方案。

| 项 | 内容 |
|---|---|
| **现象** | 某些 wavetable 单独播放就可能削顶/峰值过高 |
| **与拍的边界** | **削顶 ⇒ 波形被切平（"破/糙"）；拍 ⇒ 幅度周期性起伏（"响→轻→响"）**。**判据不同**：前者看**幅度直方图两端堆积/贴顶率**，后者看**包络的自相关周期** |
| **为什么本次不合并** | 削顶是**量纲/标定问题**（`gain` 基准 vs 波表峰值），拍是**频率差问题**，**修法正交**：改 `gain`/限幅治不了拍；改 detune 治不了削顶 |
| **唯一的交互点（⚠️ 只记账，不处理）** | 拍会把"恒定峰值"变成"时变峰值" ⇒ 让一个按恒定峰值标定的固定增益在某些时刻偏高（`失谐破音原因分析-20260927.md` 已定量）⇒ 这属于 **headroom 标定**，⛔ 不要用"减小 detune"去解决它 |
| **本次唯一要做的** | ⭐ 量一次**贴顶率**，确认"起伏不是削顶引起的假象"（§6.4） |
