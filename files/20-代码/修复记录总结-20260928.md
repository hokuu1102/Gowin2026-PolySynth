## 二、⭐⭐ B3 挂音：根因与证据链（**本文最重要的一节**）

### 2.1 🔴 缺陷机制

```verilog
(f) 段：RT_LOW 期间【每拍】执行 gate_r[retrig_idx] <= 1'b1
(g) off 分支：if (gate_mask[i] && axis_r[i]==cur_axis) gate_r[i] <= 1'b0;
              └─ gate_mask[i] = gate_r[i] & ~hold_mask[i]
                 压低期间 hold_mask[i]=1 ⇒ gate_mask[i] = 0
              ⇒ 🔴 【跳过该 voice】
同时 (g) 把 retrig_state 推回 RT_NONE（于是 (f) 不再管它）
⇒ ⭐ 若 note_off 恰好落在 (f) 抬 gate 的那一拍
   ⇒ 🔴 gate_r 永久卡 1 ⇒ 永久挂音
```

### 2.2 ⭐ 为什么这解释用户的**全部**实测

| 用户实测（原话） | 机制 |
|---|---|
| ⭐ **「挂音的都是我按过的键啊，音高都一样的」** | ✅ 挂的是**键盘轴**的 voice（⛔ 不是伪事件/悬空引脚） |
| ⭐ **「按同键不能清」**「**按所有键也不能清**」 | ✅ `retrig_state=RT_NONE` 后无人再清；再按会重进压低窗口 ⇒ 又被跳过 |
| ⭐ **「按了几次以后才会触发」** | ✅ **概率 ≈ 1/1024** ⇒ 低概率、随按键次数累积 |
| ⭐ **「不是什么都不做就能随机触发」** | ✅ 必须发生**同轴重触发**（快速连按同一个键） |
| ⭐ **「是板1（左手板）代码的逻辑问题」** | ✅ 是 `note_manager` 的重触发状态机 |
| ✅ **「断电才清」** | ✅ 寄存器状态 |

### 2.3 ⚠️ 我踩的坑（⭐ 必须记住）

```
🔴 第一版判据扫描步长 = 64（0,64,...,960）
   ⇒ 【跳过了 1023】⇒ 原始代码也"PASS" ⇒ ⭐ 假绿！
   ⇒ 我一度错误地以为"重触发窗口不是挂音路径"
✅ 改成精扫 sample_tick 附近（1016~1023 + 0~7）
   ⇒ 原始代码立刻在 off_phase=1021 暴露 STUCK
```

⭐ **教训（已录入经验库）**：判"相位相关缺陷"时，**必须精扫边界**，
⛔ 不能只用粗步长 —— **粗步长会产生"假绿"，比"假红"危险得多**。

## 十一、⭐⭐ B2 尖音的**新头号候选**（跨文件复审，已量化）

### 11.1 🔴 `same_hit` 用 `gate_mask` 判"同键还在响"，而真值在 `live_mask`

```verilog
same_hit[sg] = gate_mask[sg] && (axis_r[sg] == cur_axis);   // note_manager.v:318
gate_mask[i] = gate_r[i] & ~retrig_low[i];                   // :233
live_mask[i] = gate_r[i] | retrig_low[i] | env_active_i[i];  // :234  ← 真值
```

### 11.2 ⭐ 机制与**量化**（⭐ 落进 DS0004 实测的 10.6~11.1 倍）

```
① 松手后 gate_r=0，但 adsr 的 release 是 RELEASE_STEP=2/tick
   ⇒ 从 sustain(12800) 归零要 131 ms，从起音峰(51200) 归零要 524 ms
② 这个窗口内 gate_mask=0 ⇒ same_hit=0 ⇒ same_valid=0
   ⇒ ⭐ 走 ST_SCAN 【分配第二个 voice】（同 axis_r、同 phase_inc）
③ 旧尾巴(≤51200) + 新起音峰(velocity<<8 = 51200) = 102400 = ⭐ 8 × sustain(12800)
④ 再乘 tdm_render_mixer 【无斜坡】的 1/√N 增益台阶
   n=2→62 而正常段 n=4→44 ⇒ ×1.41 ⇒ ⭐ 8 × 1.41 ≈ 11.3×
   n=8→31  ⇒ ×2.0 ⇒ 16×
   ⇒ ⭐⭐ 落进 DS0004 实测的 10.6 ~ 11.1 倍
⑤ 两个 voice 同音高 ⇒ ⭐ 基频一致 ✅
⑥ 绝对值仅约满幅 1.4%（0.0138 V）⇒ 限幅器不介入 ⇒ ⭐ 无平顶 ✅
⑦ 重按间隔落在 131~524 ms 释放窗口内的比例 ≈ 一半
   （REFRACT_N=60=30 ms 又挡掉了更快的重按）⇒ ⭐ ~50% ✅
```

### 11.3 ⭐ 为什么 B2-a 的修复**没能**消除它

B2-a（`retrig_reset` 电平化）只修了**复用同一 voice** 的重触发路径；
⭐ 而走"**新分配 voice**"这条路径时，**旧 voice 的尾巴不会被清零**
（`ST_COMMIT` 只对 `best_idx` 发 `retrig_reset`）⇒ 尖音从这条缝里活下来。

### 11.4 ✅ 修法（**已实施**）

```verilog
// same_hit 改用 live_mask（"尾巴未结束的再按"也算同键还在响）
assign same_hit[sg] = (gate_r[sg] | retrig_low[sg] | env_active_i[sg])
                    && (axis_r[sg] == cur_axis);
```
⇒ 让"尾巴未结束的再按"走 `same_valid` ⇒ 拿到 `retrig_low` + `retrig_reset` ⇒ ⭐ **干净重启**。

### 11.5 ✅ 判据（**红 → 绿闭环已完成**）

```

判据：数"axis==A 且 live_mask==1"的 voice 个数
⭐ 原始  ：2  (DUPLICATE)  ⇒ BUG PRESENT
⭐ 修复后：1  (reuse=6, DUPLICATE=0) ⇒ PASS
✅ 回归 tb：tb_note_manager PASS
```
