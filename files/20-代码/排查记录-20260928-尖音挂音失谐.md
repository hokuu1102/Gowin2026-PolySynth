## 一、⭐ 串口诊断工具（新增，可复用）

### `tools/board_probe.py`（已存在）+ 新增 `'N'` 命令

| 命令 | 回包格式 | 用途 |
|---|---|---|
| `'P'` | `P` + 通道号(hex) + 4 位十进制 + CRLF | 回**极性校正后的原始 ADC 码** `af0_pol` |
| ⭐ **`'N'`** | `N` + **轴号**(hex) + 4 位十进制 + CRLF | ⭐ 回 **`calib` 后的 `pos`**（判键用的那个数） |
| `'T'` | — | 逐轴 tare |
| `'S'` | — | 逐轴 span 标定 |
| `'V'` | `V` + state + axis + rej + CRLF | 看 `calib_span` 内部状态 |
| `'X'` | — | 中止标定 |

⭐ **`'N'` 每次自动轮转到下一个轴** ⇒ **连发 16 次即可扫完全部 16 轴**。

### ⚠️ 实测发现的两个坑（已写进代码注释）

1. 🔴 **`'P'` 回的是【原始码】，⛔ 不是 `pos`**
   - 实测静止值 ≈ **2150**（未标定的原始 ADC 码）
   - ⭐ 而 `pos = (raw − zero) × gain >> 8`，静止时应 ≈ **0**
   - **⇒ 从 `'P'` 推断不出 `pos`** ⇒ ⭐ **这就是加 `'N'` 的原因**

2. ⚠️ **`S_DONE` 状态名有误导性**：它**同时代表"成功"和"放弃"**
   - 区分标志是 `done_o`，⭐ 而 `'V'` 回包**不含它**
   - ⇒ 实测 `V 7 0 9 0`（state=7=DONE, rej=9 ≥ REJECT_MAX=8）**其实是"放弃"**

## 三、✅ 结论 2：B4「周期性音量起伏」= **失谐拍频**（⛔ 非 bug）

### 机制

```
每个 voice 有 2 个 lane（OSC_PER_VOICE=2）
lane 1 的相位增量 = lane 0 × (1 + 1/256)     [DETUNE_SH=8]
⇒ 拍频 = f / 256  ⇒ 周期 T = 256 / f
```

### ⭐ 三重验证（用户实测周期 ↔ 音高表）

| 用户实测 T | 反推基频 | 音高表 | 误差 |
|---|---|---|---|
| **1.90 s** | 134.7 Hz | **C3 = 130.81** | 3.0% |
| **1.74 s** | 147.1 Hz | **D3 = 146.83** | **0.2%** |
| **1.44 s** | 177.8 Hz | **F3 = 174.61** | 1.8% |

⭐ **而且用户说"每个音高周期不一样"** —— ⭐ **正是失谐的指纹**（T ∝ 1/f）。

📌 **⇒ 这是设计意图**（让声音更厚），⛔ **不是缺陷**。
⚠️ **若听感不喜欢**：可调 `DETUNE_SH`（8→9/10 偏移更小）或 `DETUNE_ON=0`。

## 五、🔴 结论 4：B2「偶发尖音」= **仍未解决**（⚠️ 无方向）

### 用户描述（原话）

> · **"一个键按下去有两个音色，有一个音色很尖"**
> · **"大概 50% 概率出现"**
> · **"每次出现都失真"**
> · ⭐ **"尖音和当前按下键的音高一致"**
> · **"和按的速度以及深浅关系不大"**

### ⭐ 已排除的假设（都有证据）

| # | 假设 | 排除依据 |
|---|---|---|
| 1 | 波表数据本身有问题 | 默认 **BASS（三角波，跳变仅 128）**；插值算术**无溢出**（0 越界） |
| 2 | `pitch_upd` 改音高 | `pitch_value_o` **恒 0**、`pitch_valid_o` **从不置 1** |
| 3 | timbre 取错值 | `live_timbre_valid_i` 硬接 **0**；`score/demo` 空闲时 valid=0 |
| 4 | 相位去相关失效 | ⭐ 仿真：复用后相位偏离仅 **0.1%**（⛔ 不足以突变） |
| 5 | 削顶（幅度超满幅） | ⭐ DS0005 直方图**两端占比 0.3~0.7%** ⇒ **无平顶** |
| 6 | 波形变方（timbre 错） | ⭐ DS0005 大跳变仅 **0.0~0.3%** ⇒ **不是方波** |
| 7 | ADC / 接线 | 16 通道原始码全正常 |
| 8 | 力度通路 | 禁用 `vel_upd` 后**症状不变** |

### ⚠️ 关键障碍：**没有捕捉到尖音那一刻的波形**

| CSV | 内容 | 判定 |
|---|---|---|
| DS0003 / 0004 / 0005 | 全部是**正常波形** | ⚠️ **未捕获到尖音** |

📌 **DS0005 是 200 µs/点 × 10000 = 2 秒** ——
⭐ 而尖音是**偶发、50% 概率、每次很短** ⇒ **2 秒窗口很容易错过**。

### ⭐ 需要的下一步（需上板）

```
① ⭐ 示波器用【单次触发】（Single），触发源设在【幅度突变】上
② ⭐ 时基加大（如 100 ms/div）覆盖更长时间，事后找异常段
③ ⚠️ 或：同时抓 DAC 的 L 与 FPGA 的 HP_DIN，对比"数字端是否已失真"
     · 若数字端正常、模拟端失真 ⇒ 问题在 DAC 之后
     · 若数字端已失真 ⇒ 问题在 FPGA 内
```

## 六、⚠️ 结论 5：B5「力度反馈」= 已禁用，根因明确

### 根因（代码分析）

```verilog
// note_manager.v:456-461 —— 力度修正【只允许调大】
if (vel_upd_valid_i)
    if (vel_upd_value_i > vel_r[i])       // 🔴 只增不减
        vel_r[i] <= vel_upd_value_i;
```

⭐ 而起音已用 `DEFAULT_VEL = 200` ⇒

| 按法 | `vel_lut` 给值 | 是否生效 |
|---|---|---|
| 快按（Δt 小） | 255 | ✅ 生效（200→255） |
| ⚠️ **慢按（Δt ≥ 64 帧）** | **64** | 🔴 **被 `>` 挡掉，不生效** |

⇒ ⭐ **只有"快按"才有力度变化，⛔ 慢按完全无感** —— 与用户"感受不到力度"吻合。

📌 **当前状态**：`top.v` 已把 `vel_upd_valid_i` 置 **0**（诊断用，⛔ 未删通路）。
🔧 **恢复方法**：换回 `pe_vel_v` 即可。

⚠️ **同一模块还有第二个问题**：`pos` 在 `VEL_T2_EFF` 附近抖动会**反复**发 `vel_upd`
⇒ ⭐ **需要加深阈迟滞**才能修好。
