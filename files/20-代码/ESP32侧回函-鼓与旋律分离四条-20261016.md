## 一、🔴 先纠一条硬事实：§2.1「不需要新轴号」不成立

你们写：

> 新设计：鼓的身份靠【drum_type 字段】=> 与轴号完全无关 ⇒ 扩到 8 件**不需要任何新轴号**

**RTL 原文不支持这个推论。** `rtl/w3b/note_manager.v:1413-1416`（`ST_DECIDE` 的 off 分支）：

```verilog
for (i = 0; i < POLY_TARGET; i = i + 1)
    if ((gate_r[i] | retrig_low[i])
        && (axis_r[i] == cur_axis)          // ⭐ 仍然比轴
        && (src_r[i]  == cur_src)) begin    // ⭐ 再比源
        gate_r[i] <= 1'b0;
```

而你们自己 §5.2 刚确认：`score_src_w = score_is_drum_i ? SRC_KDRUM : SRC_SCORE`
⇒ **四件（将来八件）鼓的 `src` 全是 `SRC_KDRUM`**。

⇒ 合起来：`note_off` 清的是 **同轴 + 同源** 的所有 voice ⇒
**同一条轴上的两件鼓会互相清**（任一件的 OFF 把另一件的 voice 一起掐掉）。
轴号不是"与鼓的身份无关"，它仍是 **voice 的唯一分隔键**。

📌 这不是新问题：2026-10-15 的「方案 B（四件分轴 12/13/14/15）」做的正是这件事 ——
我方的判据 ②（`check_drum_split.py`）与三份既有判据都按"**一件一轴**"卡。

### 那 8 件怎么办：**不用改 RTL，也不用牺牲旋律轴** —— 把 axis 写成「dt 键」

⭐ **关键洞察**：`drum_type` 的第 3 位（**bit19**）**就是 `axis` 字段的 LSB**（`axis = bits[22:19]`）。
⇒ 对鼓事件来说，"**写 axis**" 与 "**写 drum_type 的高位**" 是同一件事。只要把 axis 写成：

```text
鼓事件的 axis = dt 键 = ((dt & 3) << 1) | (dt >> 2)
   dt: 0→0 · 1→2 · 2→4 · 3→6 · 4→1 · 5→3 · 6→5 · 7→7     （8 个互不相同）
```

则三件事同时成立：

| | 为什么 |
|---|---|
| ✅ 你们 §2.2 的 `drum_type = {bit19, timbre[8:7]}` 自然成立 | axis 的 LSB 就是 bit19，写这个键 ⇒ bit19 自动等于 dt 的 MSB |
| ✅ **八件天然隔离**（`note_off` 的 `(axis, src)` 匹配就够） | 八件的 axis 值互不相同 ⇒ 同轴同源不再发生 |
| ✅ **旋律仍然用 0..11，一条轴都不用让** | 与鼓数值重叠没关系 —— `src` 不同（`SRC_SCORE` vs `SRC_KDRUM`），`(axis, src)` 本来就是两维匹配 |

⇒ **零 RTL 改动**：你们**不用动 `note_off`**，我方只改 axis 的赋值。

⚠️ **更正我上一版回函**：那里写的"**甲**：鼓用 8..15、旋律让到 0..7"**作废** ——
那个方案还有个****（我自查时发现）：把 axis 写成 8..15 会让 **bit19 恒为 1** ⇒
`drum_type` 的 MSB 也就恒为 1 ⇒ **低四件（dt 0..3）根本表示不出来**。
"**乙**"（改 `note_off` 匹配键）也不再需要。

⚠️ 请你们核一件事：`seq_arb` / `note_manager` 侧对鼓事件读的 `axis` 就是 `bits[22:19]`（含 bit19）
⇒ 与我方上面这个写法一致。若你们那里**另外**把 bit19 从 axis 里剔掉（只留 22..20 当轴），
那八件就会退化成四条轴、又会互相清 —— 请确认没有这种剔法。

## 二、其余四条：照做

### ② `drum_type` 扩到 3 位 = `{bit19, timbre[8:7]}` —— 采纳

我方按此实现（bit19 = drum_type 的 MSB）。已核：写鼓事件时 bit19 写的是 **drum_type 的 MSB**，
⛔ 不会因为"它原来是 axis 的最高位"而写别的。旋律/ tempo 事件的 bit19 一律写 0。

### ④ 超音域写 `note_off5 = 31` —— 采纳，这条是我方写错了

你们说得对：`45..63` 才是键盘上真实存在的键（A2..D#4），**40~44 键盘上根本没有键**，
所以不是"钳到 0 指错"，而是"这些音本来就不该点灯"。我方改法：

```text
音高 < 45 或 > 75  ⇒  note_off5 写 5'd31（哨兵 = 不可弹）
                    ⛔ 不再钳到 0（0 是 A2 = 真实的键 5，会点亮错误的灯）
```

日志也从"钳位数"改成"**判为不可弹的条数**"（诊断价值更高：它直接反映引导轨超出键盘音域）。

### ⑤ `vel` 统一到真实力度 —— 采纳，独立一个提交

按你们 §4.2 的理由（FPGA 侧包络就用 vel；全 130 会丢掉强弱层次）：
`mid2evt.py` 改成与网页一致 —— 旋律用 MIDI 真实力度、鼓用 175/220/230/235、**OFF 写 0**。
