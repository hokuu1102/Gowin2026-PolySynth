# P4 详细计划 · `base_g` 优化（2650 LUT → ~150）· 2026-10-03

> **目的**：⭐ **腾出资源打开 T3**（T3 需要 ~1025 LUT + 时序余量，三条减重路已实测全堵）。
> **用户已批准**：⭐ 可以做 P4（"列一个详细的计划然后开始"）。
> **⛔ 不做**：共享 ADSR / 共享 DDS / looper 重构（用户拍板"暂不大改"）。

## 一、要解决的问题（已实测）

`rtl/w3b/note_manager.v` 的输出端每 lane 一个**变量移位器**：

```verilog
wire [PHASE_W-1:0] base_g = (base_oct_r == 2'd0) ? phase_r[g] : (phase_r[g] << base_oct_r);
assign voice_phase_inc_o[g*PHASE_W +: PHASE_W] = base_g;
```

- ⭐ **32 lane × 32 位变量移位 ≈ 2650 LUT**（用"摘掉它"的综合差实测得到：摘掉后总 LUT 比无 T3 基线还低 1714）
- ⚠️ 它放在**输出端**是 T2 的**刻意设计**（`note_manager.v:1465-1468` 的注释）：`phase_r` 有**三条写路径**（起音 / 提交 / **滑音 `pitch_upd`**）⇒ 放输入端只覆盖前两条 ⇒ **滑音会绕过八度移位**（不一致）

## 二、⭐ 方案：把"每拍移位"改成"**写入时移位 + 换档时轮转重算**"

| 步 | 做法 |
|---|---|
| **① 写入时移位** | 三条写路径写 `phase_r` 时**都左移 `base_oct_r`**（起音 / 提交 / `pitch_upd` 各一次，⭐ 共享 1 个移位器即可，三条路径是**稀疏事件**，不冲突） |
| **② 输出端去掉移位器** | `voice_phase_inc_o[...] = phase_r[g];` ⇒ ⭐ **省掉 2650 LUT** |
| **③ 换档时轮转重算** | `base_oct_r` 变化时，用 **32 拍轮转**把每个 lane 按**差值**重新移位：`new > old` ⇒ 左移 `new-old`；`new < old` ⇒ 右移 `old-new`。⭐ **右移是精确的**（因为当初左移过，低位本来就是 0）⇒ ⛔ 不丢信息 |
| **④ 共享移位器** | ③ 的移位器与 ① 共用（⭐ 都是稀疏路径）⇒ 只加 **~32 LUT + 一个 5 位轮转计数器** |

⭐ **净收益估算**：−2650（输出移位器）＋ ~150（写入移位 + 轮转）≈ ⭐ **−2500 LUT** ✅（足够装 T3 的 1025 LUT，还能改善 SETUP slack ✅）

### 8.1 ⭐ 关键物理事实（三条路线共享）

⭐ **对 1024 位施加 0..2 的变量移位，放在哪一级都值 ~2234 LUT** —— 贵的是"**每 lane 在 3 个版本间选择**"，⛔ 不是移位本身。
⇒ 想真省，**必须把移位搬进存储** ⇒ 换档就**必须重算存储** ⇒ 共享重算**必然 >1 拍** ⇒ ⭐ **瞬态躲不掉，差别只是 1 拍还是 32 拍**。

### 8.2 ⚠️ ROT32 为什么只比 (B2) 多省 770（而非预期 ~1000）

轮转省掉整阵列那 1088 个 mux，但**加回**了：5 位计数器 ＋ **32 个 lane 的"本拍轮到我吗"比较器** ⇒ 净省 731 落在 `u_note_manager` 自己身上（(B2) 的 −1352 里大头是**全局重映射**）。
⚠️ **两次的"局部 vs 全局"比例完全不同** ⇒ ⛔ **不能互相外推**。

### 8.3 🔴 方法学教训（⭐ 值得进项目知识）

⚠️ **README 的文字描述不足以复现综合结果** —— 子代理照 §七.5 的文字重建 (B2) 得到 **36948（+867 错）**，必须从**上一会话的 zstd transcript 取回原始 edit 对**才逐字节复现 **36081**。

2. ⭐ **写移位器是【一个】共享 wire**（3 选 1 mux + 移位），⛔ **不是 3 个**

### 9.2 🔴🔴 探针版为什么是**错的**（⭐ 本轮最有价值的发现）

⭐ 探针版（`build/p4rot32_backup/note_manager.v.ROT32`）把三条写路径**共用一个** 3 选 1 mux 的移位器：
```verilog
wire [PHASE_W-1:0] wr_src = pitch_upd_valid_i ? pitch_upd_value_i
                           : (cmt_en_r         ? cmt_inc_r
                                               : cur_inc);
wire [PHASE_W+1:0] wr_shift = {2'b00, wr_src} << base_oct_r;
```
🔴 **两条独立的错误**（⭐ **只跑综合【永远】发现不了**）：

1. 🔴 **(e) 滑音段与 FSM 写【可以同拍、写【不同】lane】**
   —— ⭐ `pitch_upd` 是**组合段**（⭐ 每拍都可能写，⭐ 命中 `(axis,src)` 匹配的 lane），
   而 `ST_RETRIG` / `ST_COMMIT2` 是**另一条写路径**（⭐ 写 `same_idx_r` / `cmt_idx_r`）
   ⇒ ⭐ **一个 mux ⛔ 表达不了"两个 lane 各拿自己的值"** ✅
2. 🔴 **`cmt_en_r` 是【锁存标志】**：⭐ 它只在下一次 `ST_DECIDE` 才被改写
   ⇒ ⚠️ **进 `ST_RETRIG` 时它可能还是 1**（⭐ 上一次提交留下的）
   ⇒ ⭐ 选择子会把**陈旧的 `cmt_inc_r`** 写进重触发 lane ✅

⭐ **实测（⭐ 新 tb `tb/w3b/tb_rot32_diff.sv`，⭐ 与**改动前 RTL 的逐字节副本**逐拍差分）**：
```

正式版口径：逐拍比较 50266 拍   phase_inc 不同 = 0       ← ✅
```
⇒ ⭐ **若直接照 §八 的探针版落地，就是静默错 97% 的拍** ✅
