## 一、⭐ 为什么不能复用现有波形渲染器

现有 `waveform_scope` 是**按列光栅扫描**：
```verilog
frame_y[0:639]   // 第 x 列的 y
// 渲染：对每一列 x，从 frame_y[x-1] 画竖线到 frame_y[x]
```
⇒ 它的隐含前提是 **x 单调、每个 x 只有一个 y**。

但李萨如的本质是 **X = 信号值**（⛔ 不是时间）：
```
点 k = ( X = f(sample[k]) , Y = g(sample[k-D]) )
```
⇒ 点**散布在整个平面上、x 不单调** ⇒ ⭐ **列扫描结构上画不了** ❌

⇒ **必须换成「点阵帧缓冲 + 打点」架构**。

## 二、架构（复用现有骨架，只换渲染器）

```
sample_i ──► [历史缓冲 1024×24bit + gray 指针 CDC]   ← ✅ 完全复用现有
                        │
          ┌─────────────┴─────────────┐
          │                           │
   [波形渲染器]                  [李萨如渲染器]（新增）
   frame_y[0:639]                XY 帧缓冲 320×240×1bit（BSRAM）
   列扫描 + 竖线                  清屏 → 打点 → 上采样 2×
          │                           │
          └─────────────┬─────────────┘
                    mode 选择
                        │
                  r_o/g_o/b_o
```

⭐ **复用清单**：`hdmi_clk`（PLL）· `video_timing` · `tmds_encoder` ×3 · `tmds_serializer` · 历史缓冲 + CDC · 输出端口
⛔ **不改**：`hdmi_scope` 的对外接口、`top.v` 的例化、**音频通路**（`scope_sample = mm_sample` 旁接不变）

## 三、XY 帧缓冲

| 项 | 取值 |
|---|---|
| 分辨率 | **320×240**（渲染时**上采样 2×** ⇒ 显示仍是 640×480，⛔ 零额外逻辑） |
| 位深 | 1 bit（单色绿） |
| 总量 | 76,800 bit |
| **BSRAM** | ⭐ **约 5 块**（现用 33/118 ⇒ **剩 85 块，装得下** ✅） |
| 组织 | 每字 **8 像素**（一行 320 px = 40 字节）⇒ `mem[0:9599]` × 8 bit，字节可寻址 ✅ |
| 地址 | `addr = py*40 + (px>>3)`，位选 `px[2:0]` |

## 四、打点算法（每帧一次，在 vblank 里做）

```
① 清屏：9600 字节写 0                ⇒ 9600 拍
② 打点：k = 0..639（从 1024 点里取 640 点，抽 1.6 倍）
      X = map_x(history[k])
      Y = map_y(history[k-D])        // D = 延迟参数
      读-改-写该字节的对应位          ⇒ 640 × 3 拍 ≈ 2000 拍
③ 合计 ≈ 11,600 拍
```
⭐ **vblank 有 `800×45 = 36,000` 拍** ⇒ **装得下** ✅（且打点只在 vblank，⛔ 不干扰有效行）

**映射函数**（都带参数，便于上板调）：
```verilog
map_x(s) = 160 + ((s >>> X_SH) & ...)     // 目标：让图占满 320 宽
map_y(s) = 120 - ((s >>> Y_SH) & ...)     // 目标：让图占满 240 高
```
⚠️ 必须**饱和夹取**（⛔ 不回绕）—— 沿用本项目"核心风险是回绕"的纪律

## 五、⭐ 模式切换：**串口命令 `'A'`**（用户 2026-10-09 指令）

> ⭐ **用户指令**："模式切换不用自动轮播，而是使用串口，串口发 `A` 从波形切换成下一个"

### 命令定义

| 项 | 值 |
|---|---|
| 命令字节 | ⭐ **`'A'` = 0x41** |
| 帧格式 | 与其它命令一致：`65 41 FF FF FF`（HEX，**500 kbaud**） |
| 行为 | ⭐ **循环切换显示模式**：波形 → 李萨如 → （后续可加频谱）→ 波形 |
| 选 'Q' 的理由 | ✅ **命令表与回包前缀都未占用**；⛔ 'A' 已作回包前缀（轴 10~15） |
| 无回包 | 与 `'I'`（切音色）同风格 ⛔ 不回包 |

### ⚠️ 与既有回包前缀的**方向冲突**（必须在注释里写清）

```verilog
top.v:2368        : (8'h41 + (sp_cur_axis - 10));   // 'A'..'F' = 轴 10..15 的【探针回包】
pos_probe.v:193   : (8'h41 + (ch_lat - 10));
span_probe.v:113  : (8'h41 + (v - 10));
```
⇒ `'A'` 已被用作**回包（TX）**方向的轴号前缀；命令表（`T S X P V M N R L C I B D K F G H J`）
里**没有 `'A'`** ⇒ 作为**命令（RX）**可用 ✅ —— **方向不同、功能不冲突**，但读日志时容易混，
⇒ ⭐ **代码注释与本文件都必须写明这一点**。

### ⚠️⚠️ 跨线冲突风险（丙正在改同一个文件）

```
origin/wip/c-fx_delay-p0-28  10-09 22:30
  feat(丙): uart_ui 实装效果器控制面（D-1）
```
`uart_ui.v` 已有留位端口 `fx_en_o` / `fx_sel_o`（"留位，恒 0"）—— **丙正在实现它们**。
而本设计要加的 `scope_mode_o` **也在 `uart_ui.v`** ⇒ ⚠️ **会撞车**。

⇒ ⭐ **开工前必须先跟丙/甲对齐**，或**等丙那条分支合完再动** `uart_ui.v`。
⇒ 退路：先只做**编译期参数 `SCOPE_MODE`**（0=波形 / 1=李萨如）把李萨如本体做完并上板，
   **串口切换等 `uart_ui` 空闲了再接**（本体与切换解耦，互不阻塞）。

## 六、资源估算

| 项 | 估计 |
|---|---|
| **BSRAM** | **+5 块**（33 → 38，占 32%）✅ |
| LUT/CLS | **+150 ~ 250 CLS** ⚠️（现 24147/29952 = 81%，**剩 ~5800** ⇒ 装得下，但不宽裕） |

⚠️ **若 CLS 装不下**：退路是**把帧缓冲降到 160×120**（+2 块 BSRAM，逻辑更少）

## 七、验证（三道门 + 针对性判据）
