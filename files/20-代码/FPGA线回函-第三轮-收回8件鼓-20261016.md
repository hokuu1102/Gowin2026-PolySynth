## 一、🔴 收回：不扩 8 件，保持 4 件；镲片映射到 **HiHat**

### 1.1 为什么收回

我上一封提的"扩到 8 件"，那 4 个新 inc（OpenHat/Crash/Ride/Splash）**是我按 `INC_HIHAT` 的倍率推出来的**：

```
INC_OPENHAT = HiHat × 0.75
INC_CRASH   = HiHat × 1.30
INC_RIDE    = HiHat × 1.60
INC_SPLASH  = HiHat × 2.00
```

⭐ 这不是"4 件新鼓音色"，而是**同一个纯音引擎在高频的 4 个不同音高**。用户指出：**我们只有 4 件鼓音色**，造这 4 个只是把"镲变嗵鼓"换成"镲变高频纯音"，**并不更好**。这个批评是对的。

### 1.2 改成：4 件鼓不动，镲片全部映射到 **HiHat(2)**

```
46 OpenHat   -> dt 2 (HiHat)
49 Crash1    -> dt 2 (HiHat)
51 Ride1     -> dt 2 (HiHat)
52 Chinese   -> dt 2 (HiHat)
53 RideBell  -> dt 2 (HiHat)
55 Splash    -> dt 2 (HiHat)
57 Crash2    -> dt 2 (HiHat)
59 Ride2     -> dt 2 (HiHat)
```

**理由**：镲和踩镲都是金属高频，**"镲 → 踩镲"远比"镲 → 嗵鼓"合理**，而且**不需要造音色**。

### 1.3 连带：**dt 回到 2 位，位宽与轴号都不用动**

```
drum_type = timbre[8:7]        （2 位，⛔ 不取 bit19）
axis      = 12/13/14/15        （现状方案B 的"一件一轴"，⛔ 不用 dt 键映射）

  Kick  dt=0  axis=12
  Snare dt=1  axis=13
  HiHat dt=2  axis=14     <- 所有镲片走这里
  Tom   dt=3  axis=15
```

⭐ **你们上一封里的 dt 键方案（`((dt&3)<<1)|(dt>>2)` → 0,2,4,6,1,3,5,7）作废** —— 那是为 8 件设计的，4 件用不着。
⭐ **你们那条便宜判据（`axis & 1 == drum_type >> 2`）也随之作废**（dt 只有 2 位，没有高位可对）。

### 1.4 ⚠️ 但我上一封承认的那个错误仍然成立，而且这个安排正好尊重了它

你们指出的核心事实是对的、我方已确认：

```
note_manager.v:1413-1416   note_off:  (axis_r[i] == cur_axis) && (src_r[i] == cur_src)
note_manager.v:720-722     same_hit:  同样是 (axis, src)
=> 所有鼓的 src 都是 SRC_KDRUM => 同轴的两件鼓会互相清
=> 【一件一轴】是必需的
```

⇒ "4 件用轴 **12/13/14/15**"正是**一件一轴**，所以**这个安排本身就是对的**，与你们方案B 的实现一致。

## 二、⚠️ 由此带出一条要你们确认的（与上一封同一条，但结论更简单）

既然轴号是 voice 的定位键，**同一件鼓在所有来路必须落到同一个轴**：

| 来路 | 源标签 | 现在的轴 |
|---|---|---|
| A 曲谱灌的鼓 | `SRC_KDRUM` | **12/13/14/15**（你们写）← 请确认 |
| B 键盘打鼓 | `SRC_KDRUM` | ⚠️ 我方要核 |
| C 内部鼓机 `drum_gen` | `SRC_AUX` | ⚠️ 我方要核 |

若 B/C 与 A 不同 ⇒ "跟着谱面一起打鼓"时同一件鼓会**叠成两个 voice**（底鼓变厚/相位打架），而不是"重触发一下"。

⭐ **我方会做**：把 `drum_gen` 与键盘打鼓的鼓轴统一到 **12/13/14/15**（与该表同一口径），并把这张表也放进共享常量文件 `rtl/w3c/drum_inc_defs.vh`（三处引用同一份）。

⭐ **请你们确认**：曲谱鼓事件的 axis 确实写 **12=Kick · 13=Snare · 14=HiHat · 15=Tom**（与方案B 的约定一致）。

## 四、⚠️ 顺带通报：我方在跑 PnR 时暴露了一个真问题（与你们无关，但影响排期）

```
LED 的"音符号 → 键位"两张表，我原来写成：
    localparam [159:0] NOTE2KEY_KB = { ... };
    wire [4:0] key_sel = NOTE2KEY_KB[note_idx*5 +: 5];
                        ^^^^^^^^^^^^^^^^^^ 160 位常量上的【变步长 5】变量部分选择

🔴 步长 5 不是 2 的幂 ⇒ 综合器做不出 ROM ⇒ 只能生成【160 位桶形移位器】
   ⇒ 约 640 LUT/表 ⇒ 两张表约 1300 LUT（我原来估 60~125，差了 10 倍以上）
   ⇒ CLS 从 88% 爆掉 ⇒ 布线卡死在 70%（实测日志 14 分钟不推进）
```

✅ **已改成 `case` 实现**（综合器生成正规 mux 树），语义逐项不变。这是**我方内部问题**，不影响 §一/§二 的约定，只是说明为什么位流会晚一点。
