# 🎹 力度调节详细方案（⭐ 2026-09-26 定稿设计）

> **目标**：⭐ 力度**可实时调整**，⭐ 但**不破坏衰减曲线**
> **同时**：⭐ 阈值下调（⭐ 用户要求"5~10%"）
> **前置**：⭐ 音高 ✅ · 音量/削顶 ✅ · 迟滞 ✅（⭐ 都已修，待上板验）

---

## 〇、⭐⭐ 一句话

```
⭐ 力度分【三段】：⭐ ATTACK 速度式定初值 → ⭐ 过渡段位置式微调 → ⭐ DECAY 冻结
⭐ 阈值下调到 **10%**（⚠️ ⛔ 不是 5% —— 🔴 5% 会撞上 ch2 的噪声）
```

---

## 一、🔴🔴 先纠正一个数：阈值**不能**降到 5%

### ⭐ 我算过了（⭐ 用你的实测数据）

| ⭐ 项 | ⭐ 值 | ⭐ 出处 |
|---|---|---|
| 行程（静止→按下） | **744** 码 | ⭐ 上板实测 `1985 → 2729` |
| 正常通道帧间噪声 | **Δ ≤ 6** | ⭐ 上板实测 |
| 🔴 **ch2 的帧间跳变** | **> 48** | ⭐ `span` 被拒的**同一根因**（⭐ 见定案文档） |

### 🔴 关键：**`span` 标定会把噪声【同比例放大】**

```
⭐ `gain = (4095 << 8) / (span_code - zero)`
⭐ 当前行程 744 ⇒ gain = 4095/744 = 5.5  ⇒ ⭐ **增益 5.5 倍**
⇒ ⭐ 标定后噪声也放大 5.5 倍：
   · 正常通道:  6 → **33**
   · 🔴 ch2:   48 → **264**   （⚠️ 更大）
```

### ⭐ 阈值对照（⭐ 标定后空间，行程 = 4095）

| ⭐ 阈值 | ⭐ `TRIG_TH`（标定后） | ⭐ vs ch2 噪声 264 | ⭐ 判定 |
|---|---|---|---|
| ⚠️ **5%** | **205** | ⚠️ **205 < 264** | 🔴 **会误触！** |
| ⭐ **10%** | **410** | ✅ **410 > 264**（⭐ 余量 1.55×） | ✅ **安全** |
| ⭐ 13% | 532 | ✅ 余量 2.0× | ✅ 更稳 |

🔴 **⇒ 结论：⭐ 最低只能到 10%**，⭐ 5% 会撞上 ch2 的噪声。

📌 **⚠️ 但前提是"ch2 那个噪声是真实存在的"** ——
⭐ 若你**修好 ch2 的硬件**（⭐ 或换传感器），⭐ 那 5% 就可以用。
📌 **所以本方案把阈值做成【参数】**，⭐ 硬件修好后改一个数即可。

## 二、⭐⭐ 力度三段式（⭐ 核心设计）

### ⭐ 时间轴

```
   │
   │   ⭐ 阶段① ATTACK       ⭐ 阶段② 过渡      🔴 阶段③ DECAY
   │   （note_on → 包络达峰）  （达峰后窗口）     （包络下降后）
   │
   │   ⭐ 速度式定初值         ⭐ 位置式微调      🔴 冻结
   │   vel = f(dt)            vel += Δ(深度)     vel 不变
   └──────────────────────────────────────────────────────▶ t
```

### ⭐ 各段规则（⭐ 精确到可编码）

| ⭐ 段 | ⭐ 判据（可编码） | ⭐ 力度来源 | ⭐ 理由 |
|---|---|---|---|
| ⭐ **① ATTACK** | ⭐ `env_level < PEAK` 且 ⭐ 已越 `VEL_T2` | ⭐ **速度式**：`vel = LUT(dt)`<br>（⭐ 现有 `param_extract` 逻辑） | ⭐ 打击感的核心 —— ⭐ "这一下多响" |
| ⭐ **② 过渡** | ⭐ `env_level == PEAK` 后 M 帧内 | ⭐ **位置式微调**：<br>`vel = vel0 × (1 + k×Δpos)`<br>⭐ **限幅 ±20%** | ⭐ 满足"边按边调" |
| 🔴 **③ DECAY** | ⭐ `env_level` 开始下降之后 | 🔴 **冻结**（⛔ 不再改） | ✅ **保护衰减曲线**（⭐ 你的顾虑） |

### ⭐ 为什么"①是主导、②是修正"

```
⚠️ 若 ② 的权重太大 ⇒ 🔴 盖过速度式 ⇒ 打击感丢失（⭐ 变成纯位置式）
⭐ 所以 ② 限幅 ±20%  ⇒ ⭐ 只能"微调"，⛔ 不能"翻盘"
📌 这样既保住打击感，⭐ 又能"边按边修"
```

### ⭐ 参数表（⭐ 待上板调）

| ⭐ 参数 | ⭐ 默认建议 | ⭐ 说明 |
|---|---|---|
| `TRIG_PCT` | ⭐ **10%** | ⭐ 触发阈（⚠️ 见 §一，最低 10%） |
| `REL_PCT` | ⭐ **6%** | ⭐ 释放阈 ⇒ **迟滞 4%**（⭐ 164 码 > 噪声 264? ⚠️ **不够！** 见下） |
| ⭐ **`REL_PCT` 修正** | ⭐ **3%** | ⭐ 迟滞 7% = **287 码 > 264** ✅ **够** |
| `VEL_T1_PCT` | ⭐ **20%** | ⭐ 力度起始点 |
| `VEL_T2_PCT` | ⭐ **60%** | ⭐ 力度满点 |
| `ADJ_WINDOW` | ⭐ **20 帧**（⭐ 10 ms @500µs） | ⭐ ②段的窗口 |
| `ADJ_LIMIT` | ⭐ **20%** | ⭐ ②段的限幅 |

🔴 **注意 `REL_PCT`**：⭐ 迟滞必须 `> 264`（⭐ ch2 噪声）
⇒ ⭐ `TRIG=10%(410)` · `REL=3%(123)` ⇒ **迟滞 287** ✅

### ⭐ 判"阶段"的方法（⭐ 关键）

```
⭐ 需要一个【峰值检测】+【下降检测】：
   · `peak_seen`  : 包络曾达到过峰值（⭐ `env >= PEAK_TH`）
   · `falling`    : 当前 `env < prev_env`（⭐ 开始下降）
   ⇒ ⭐ 阶段 = ① 若 !peak_seen · ② 若 peak_seen && !falling · ③ 若 falling
📌 **复用一个减法器 + 两个比较器** ⇒ ⭐ 资源可忽略
```

## 五、⭐ 判据（⭐ 批次 2 要补的 tb）

```
① ⭐ 快速按 ⇒ 力度大；⭐ 慢按 ⇒ 力度小        （⭐ 速度式仍有效）
② ⭐ ①段内改深度 ⇒ 力度【不变】               （⭐ 起音定死）
③ ⭐ ②段内改深度 ⇒ 力度【小幅跟随】（限幅内）  （⭐ 实时微调）
④ ⭐ ③段内改深度 ⇒ 力度【完全不变】           （⭐ 保护衰减）
⑤ ⭐ 重触发 ⇒ 回到①重新计算                    （⭐ 语义正确）
⑥ ⭐ A8：⛔ 无 X/Z
```

⭐ **变异体**（⭐ 硬约束）：
- 删 ② 段限幅 ⇒ ⭐ tb ③ 应变红
- 删 ③ 段冻结 ⇒ ⭐ tb ④ 应变红
