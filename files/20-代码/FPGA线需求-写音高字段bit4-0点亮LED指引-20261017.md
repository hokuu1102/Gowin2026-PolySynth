# ESP32 侧需求：写音高字段 `bit[4:0]` —— 否则 LED 曲目指引在真曲上是**死的**

> 收件人：ESP32 线
> 日期：2026-10-17
> 触发：用户实测"**LED 指引不亮**"；FPGA 侧只读审计定位到根因在**上游载荷**，⛔ 不在 FPGA
> ⭐ **FPGA 侧零改动** —— 那个字段本来就存在、`guide_lamp` 本来就在读它。**只要你们开始写，灯就亮。**
> ⚠️ 已生成的 `.hex` 需要**重新生成 + 重灌**（旧文件里该字段恒 0）

---

## 〇、一句话

```
frame bit[4:0]  =  MIDI 音符号 − 45      （0..31）
⇒ 现在【恒 0】⇒ FPGA 的"按音高指键"永远只算到 offset 0
⇒ 钢琴模式：一盏灯都不亮
⇒ 指板模式：恒亮【键 5】一盏，而且灯跟着变调轮走、⛔ 不跟音乐走
```

---

## 一、字段在哪（帧格式，⭐ 与你们既有口径一致）

`rtl/top.v:1714`（FPGA 侧解包）：

```verilog
wire [4:0]  ps_note_off5 = ps_note_data[4:0];   // ⭐ MIDI − 45（查表用）
```

⇒ 那个 64 位事件字里，**`bit[4:0]` 是最后一个空闲字段**（其余已分配完）：

| 位 | 含义 | 状态 |
|---|---|---|
| `[63:44]` | tick | ✅ 已用 |
| `[43:23]` | `phase_inc`（音高/乐器身份）| ✅ 已用 |
| `[22:19]` | `axis`（轴号）| ✅ 已用 |
| `[18:11]` | `velocity` | ✅ 已用 |
| `[10:9]` | `kind`（0=on · 1=off）| ✅ 已用 |
| `[8:7]` | `drum_type`（⭐ 复用 timbre 字段）| ✅ 已用 |
| **`[6]`** | `guide_only`（只亮灯不出声）| ✅ 已用 |
| **`[5]`** | `is_drum` | ✅ 已用 |
| **🔴 `[4:0]`** | **音高 = MIDI − 45** | 🔴 **从未写过（恒 0）** |

## 二、证据（⭐ 逐条可复现，⛔ 不是推测）

### 2.1 上游工具**明确写着"不写"**

| 位置 | 原文 |
|---|---|
| `tools/mid2evt.py:496-502` | 拼字只写 tick/inc/axis/vel/kind/timbre，末尾注释 **`# bits 6..0 stay 0 (reserved)`** |
| `esp32/tools/score_word.py:46,77,116-121,201-202` | `MASK_RESERVED = 0x7F`，注释 **"保留，必须写 0"**，且它的校验器把"保留位非 0"当**问题**报出 |

### 2.2 真曲实测：**4 首全 0**

```
逐条解码 build/score/*/events.hex：
  bit[4:0] != 0 的条数 =  0 / 0 / 0 / 0
  （夜洋风景 11564 条 · 09_Conjurer 11858 条 · regen/夜洋风景 11566 条 · t6test 11865 条）

最新工具链产物（2026-10-14）同样全 0：
  esp32/tools/demo_scale.hex（111 条）· esp32/evidence/inc探针-*.hex（17/13 条）· _web_midi_demo.hex（15 条）
```

### 2.3 于是 FPGA 侧算出来的东西是常数

```verilog
// guide_lamp.v:394-398
note_tr  = {2'b00, note_off5_i} + {{2{transpose_i[4]}}, transpose_i};   // 恒 = transpose_i
in_range = (note_tr >= 0) && (note_tr <= 31);                            // 恒真（−12..+12 ⊆ 0..31）
```

| 模式 | 实际行为 |
|---|---|
| **钢琴（`fb_mode_i=0`，上电默认）** | offset 0 = `A2` ⇒ **`KEY_NONE`** ⇒ 🔴 **一盏灯都不亮** |
| **指板（`fb_mode_i=1`）** | offset 0 = **键 5** ⇒ 🔴 **恒亮键 5**；且拧变调轮会把灯"搬"到别的键（灯跟变调走）|

⚠️ **为什么判据是绿的**：`tb_guide_lamp` / `tb_top_guide_axes` **自己造 `note_off5`**（tb 里赋真值）⇒ 它们**测不到"上游不写"这件事** ✓ 典型的"判据绿、上板死"。

## 三、要改什么（⭐ 两处，各一行级）

### 3.1 `tools/mid2evt.py` —— 写进字段

```python
# 现在（:496-502 一带）
w = (tick << 44) | (inc << 23) | (axis << 19) | (vel << 11) | (kind << 9) | (drum_type << 7) | ...
#                                                                                        ↑ bits 6..0 stay 0 (reserved)

# 改成（⭐ 只需 OR 进 note_off5）
note_off5 = midi - 45                      # ⚠️ 负数/超 31 怎么办 → 见 §四
w |= (note_off5 & 0x1F)                    # ⭐ bit[4:0]
```

### 3.2 `esp32/tools/score_word.py` —— 解禁保留位

```python
MASK_RESERVED = 0x7F    # 🔴 现在把 bit[6:0] 全当保留位（:77）
# ⇒ 改成只保留 bit[6]（guide_only）与 bit[5]（is_drum），放开 bit[4:0]
MASK_RESERVED = 0x60
```

⚠️ 同时**改掉它的校验器**：现在"保留位非 0 ⇒ 报问题"会把合法帧判成坏帧
（`:136-138 reserved_bits()` · `:201-202` 报问题那一处）。

⚠️⚠️ **还有一条自检会挡住你**（⭐ 实测）：

```python
esp32/tools/score_word.py:260   MASK_RESERVED == (1 << OFF_TIMBRE) - 1
```

⇒ ⭐ 它把 `MASK_RESERVED` 与 `OFF_TIMBRE` **绑死**（"保留位必须紧跟在 timbre 之上"）
⇒ 🔴 **只改 `MASK_RESERVED` 会让这条自检失败** ⇒ 必须**一起**改 `OFF_TIMBRE`
（或把它改成"只保留 `bit[6:5]`"的新表达式）。⭐ 请按这条口径一起改，⛔ 别只改一个数。

### 3.2b ⚠️ `tools/mid2evt.py:61` 的注释**已过期**（顺手改）

```
tools/mid2evt.py:61    bit  6..0            (7 bit)    RESERVED -- must be written as 0
```

🔴 实际上 **`bit[6]` = `guide_only`、`bit[5]` = `is_drum` 早已在用**
（FPGA 侧 `rtl/top.v:1638 evt_guide_only = ps_note_data[6]` · `:1675 ps_is_drum = ps_note_data[5]`）
⇒ ⭐ 写 `bit[4:0]` 时**请连同这条注释一起订正**，⛔ 别让下一个人以为整个 `6..0` 都不能动。

### 3.3 顺带修一个**排序 bug**（`tools/mid2evt.py:450-460`）

```python
# 注释写的是：
#   "note_off must be ordered before note_on at the same tick,
#    so that a re-strike of the same pitch is not immediately cancelled"
# 而代码是：
sort(key=lambda e: (e.tick, -1 if e.is_tempo else e.kind))    # kind_on=0 < kind_off=1
#                                              ↑ ⇒ 同一 tick 上【ON 排在 OFF 前面】🔴 与注释相反
```

**hex 实证**（`夜洋风景` 前三行）：`t=0 on` / `t=480 on` / `t=480 off` ⇒ 那个 `on` **下一拍就被自己的 `off` 关掉**。

影响（实测比例）：
- **发声**：重击同音高的音被**立即关掉**（这正是注释想避免的）
- **LED**：那一拍点亮的灯**只亮 1 个周期（20 ns）⇒ 肉眼不可见**（占 2.2% / 1.4% / 0.6%）

```python
# 修法（一行）：
sort(key=lambda e: (e.tick, -1 if e.is_tempo else (0 if e.kind == KIND_OFF else 1)))
```

## 四、边界：音域与"查不到键"

FPGA 侧的灯位表（`rtl/w3c/guide_lamp.v:410-429`）**只覆盖 19 个 offset**：

```
键盘模式（fb_mode=0）14 项：MIDI 52,54,53,50,48,49,51,59,61,60,57,56,58,62
指板模式（fb_mode=1）16 项：MIDI 45,46,47,48,50,51,52,53,55,56,57,58,60,61,62,63
⇒ 表覆盖 MIDI 45..63 有键；64..76 【无键】⇒ 落 KEY_NONE（不点灯）
```

**真曲音域实测**（从 `build/score/*/events.csv` 的 `midi` 列统计 `note_on`）：

| 曲 | note_on | MIDI 范围 | 落在覆盖区 | 低于 45 | 高于 76 |
|---|---|---|---|---|---|
| 夜洋风景 | 5782 | **38..88** | **88.3%** | 243 | 436 |
| 09_Conjurer | 5929 | 30..73 | **81.2%** | 1115 | 0 |
| 6.世界悲 | 4889 | 28..76 | **82.7%** | 846 | 0 |
| t6test | 5929 | 30..73 | **81.2%** | 1115 | 0 |

⇒ **12~19% 的音符会落 `KEY_NONE`（不点灯）** —— ⚠️ 这是**另一件事**（灯位表覆盖不足），
⭐ **请先只改 §三**（写字段），覆盖不足那一半由 FPGA 侧另行扩表，⛔ 不要一起改（否则分不清是谁的功劳）。

**关于越界值**：
- `note_off5 = midi − 45` 若为负（MIDI < 45）或 > 31（MIDI > 76）⇒ ⭐ **FPGA 侧会安全地不点灯**（`in_range` 挡住）✅
- ⭐ 所以你们**可以直接写 `(midi − 45) & 0x1F`**，⛔ 不必自己做钳位 —— 但**别写 0**（0 是合法 offset A2，会被当成"真的有这个音"）
- 📌 若想更干净：`note_off5 = 0` 表示"**本事件不参与 LED 指引**"是**不可用**的（因为 0 有含义）⇒ 越界时请**照实写**，让 FPGA 去挡
