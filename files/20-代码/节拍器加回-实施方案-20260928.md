## 一、⭐ 为什么现在"没有节拍器"（根因）

```verilog
top.v:133   parameter integer METRONOME_ON = 0,        ← ⭐ 编译期常量，默认【关】
top.v:2430  wire src_b_valid = (sel_drum ? drm_evt_valid : met_evt_valid)
                             & (METRONOME_ON != 0);    ← ⭐ 常量 0 ⇒ 恒 0
```

⇒ ⭐ PnR 日志里的**证据**：
```
WARN (NL0002) : module "metronome" ... is swept in optimizing
WARN (NL0002) : module "drum_gen"  ... is swept in optimizing
WARN (NL0002) : module "beat_gen"  ... is swept in optimizing
```
⇒ ⭐ **模块被例化了，但综合把整条链扫掉**（输出恒 0）—— ⛔ 不是"没写"，是**被优化掉**。
⇒ ⭐ 而且 `METRONOME_ON` 是**编译期参数** ⇒ 要"运行时开关"必须改成**端口信号**。

## 二、⭐⭐ 关键设计问题：新增端口会波及 ~10 个 tb

⭐ 现有 tb 例化 `top` 时**按名字连端口**。新增一个 input 端口 ⇒
**未连接的 tb 端口会浮空（Z）** ⇒ 🔴 **X 传播** ⇒ `A8` 检查器可能 FAIL。

📌 实测证据：`tb_e2e` 的日志里就有
`warning: Instantiating module top with dangling input port 10 (pluck_up_i) floating.`
⇒ ⭐ **iverilog 允许悬空（只警告）**，但**信号是 Z**。

### ✅ 解决方案（⭐ 不用改任何 tb）

⭐ **把"悬空(Z)"按【未按下】处理** —— 与硬件上拉语义**一致**：

```verilog
// ⭐ 硬件：PULL_MODE=UP ⇒ 空闲=1、按下=0
// ⭐ 仿真：未连接 ⇒ Z ⇒ 这里按"未按下(1)"处理 ⇒ ⛔ 不 X 传播
wire met_btn_s = (met_btn_i === 1'b0) ? 1'b0 : 1'b1;   // ⭐ `===` 能识别 Z
```

⇒ ⭐ **未连接的 tb** ⇒ `met_btn_s = 1`（未按下）⇒ 节拍器**保持关**（= 现状）✅
⇒ ⭐ **上板**：空闲=1（上拉）、按下=0 ✅ **两边语义一致** ✅
⇒ ⭐ **一个 tb 都不用改** ✅

## 三、⭐ 改动清单（3 个文件）

### 3.1 `rtl/top.v`

| # | 改动 |
|---|---|
| 1 | ⭐ 新增端口 `input wire met_btn_i`（⭐ 放在 `rst_n` 附近） |
| 2 | ⭐ `sync_input`（`RESET_VAL=1'b1`）打两拍 —— ⚠️ **纪律**：板外异步信号**必须先同步再去抖**（`debounce.sv:9-11` 明确要求，`K-62`） |
| 3 | ⭐ 例化 `debounce #(.NKEY(1), .ACTIVE_LOW(1))` ⇒ 取 `key_down`（按下沿） |
| 4 | ⭐ **翻转触发器**：`if (key_down[0]) met_on_r <= ~met_on_r;`（⭐ 按一下开、再按一下关） |
| 5 | ⭐ `src_b_valid = (...) & (METRONOME_ON != 0) & met_on_r;` |
| 6 | ⭐ 复位：`met_on_r <= 1'b0`（上电默认关，⭐ 与现状一致） |

⚠️ **`METRONOME_ON` 保留**（作为编译期总开关，⭐ 默认仍 0 ⇒ 行为不变）；
   上板时若要"能用按键打开"，⭐ **`METRONOME_ON` 必须烧成 1**。

### 3.2 `constr/top.cst`

```tcl
IO_LOC  "met_btn_i" AB13;
IO_PORT "met_btn_i" IO_TYPE=LVCMOS15 PULL_MODE=UP BANK_VCCIO=1.5;
```
🔴 **为什么必须 `LVCMOS15` / `BANK_VCCIO=1.5`**：
`AB13` 属 **`BANK9` = 1.5 V 域**（与 `AA13`(`rst_n`) 同 bank）
⇒ ⚠️ 写 3.3 V 会**与同 bank 冲突、并可能损伤 IO**（`.cst:92-93` 已记）。

### 3.3 `tb/` —— ⭐ **0 个文件**（见 §二 的 Z-safe 方案）

## 五、⚠️ 疑问点（⭐ 需要确认或注意）

| # | 疑问 | 处理 |
|---|---|---|
| **1** | ⚠️ **`METRONOME_ON` 要不要一起改成 1？** | ⭐ **必须** —— 否则按键打开了但 `src_b_valid` 仍被 `METRONOME_ON=0` 挡住 |
| **2** | ⚠️ **节拍器音量/音色** | 节拍器走**源 B**（`RESERVED_N=5` 的保留池）⇒ ⭐ 会**占用保留 voice** ⇒ 键盘可用 voice 从 27 变 26（⭐ 设计如此） |
| **3** | ⚠️ **鼓机怎么办？** | ⭐ 源 B 是**二选一**（`SEL_DRUM`）⇒ 打开 `METRONOME_ON` 时**鼓机也会一起被解锁**（⭐ 但 `SEL_DRUM` 默认选节拍器） |
| **4** | ⚠️ **`debounce` 的编码器端口** | ⚠️ 该模块还有 `enc_a`/`enc_b`/`enc_sw` 端口 ⇒ ⭐ 不接会浮空（Z）⇒ **必须显式接常量**（⛔ 不能悬空） |
| **5** | ⭐ **S1 按下是低还是高？** | ⭐ 按 `.cst` 惯例（`PULL_MODE=UP`）⇒ **按下=低** ⇒ `ACTIVE_LOW=1` ✅ |
| **6** | ⚠️ **会不会影响 Fmax？** | 节拍器/鼓机/beat_gen 加回来 ⇒ **逻辑量增加** ⇒ ⭐ 当前 Fmax 55.119 MHz（余量 10.2%）要重新确认 |
