## 〇、三条硬约束（先立规矩，再谈实现）

```
1. 旋律线绝对不能变成鼓        <- 最高优先级，不许有任何例外路径
2. 鼓的身份由【显式标志】决定，不由轴号推断
3. 以音高为准（inc 是权威）
```

第 1 条是结构性的：**不靠"轴号不会撞上"这种运气**，而是**在通路上让旋律事件根本不可能被标成鼓**。

---

## 一、问题是怎么来的（历史与现状）

### 1.1 鼓的来源标签早就独立了

```
rtl/w3b/note_manager.v:316    localparam SRC_KDRUM = 3'd5
rtl/w3b/note_manager.v:650    pool_mask 按 src 选池子（鼓与旋律本来就是两个池）
rtl/top.v:5660                2026-10-11 P1-59：把 SRC_KDRUM 从"与源B共用"里剥离开
```

所以**池子分离和来源标签都是现成的**，那时候还没有灌谱。

### 1.2 灌谱时代临时加了一个轴号捷径

```
rtl/w3c/seq_arb.v:213
   wire [NW-1:0] score_src_w = (score_axis_i >= 4'd12) ? SRC_KDRUM : SRC_SCORE;
```

它原来的样子是 `== 4'd15`（只认一个轴），2026-10-16 为方案B 放宽成 `>= 4'd12`（认四个轴）。

### 1.3 后果（用户实测）

```
旋律轨的轴号一旦落在 12~15
  => 被标成 SRC_KDRUM
  => 走鼓的池子
  => 但它的 inc 是【音高换算出来的】
  => 听感：电子音
```

而**键盘打鼓走 drum_gen 自己的 inc 表，所以听起来是正常的**。这就解释了用户报的"灌谱像电子音、键盘打鼓没问题"。

## 二、目标架构

### 2.1 帧位域（新增两个字段）

```text
bit 63..44  tick(20)
bit 43..23  inc(21)
bit 22..19  axis(4)        <- 回归本义：哪个物理轴 / 哪条轨，不再表示"是不是鼓"
bit 18..11  vel(8)
bit 10..9   kind(2)
bit 8..7    timbre(2)
bit 6       guide_only     <- 已用（逐事件"只亮灯不出声"）
bit 5       is_drum        <- 新增：这一条是不是鼓（显式标志）
bit 4..2    key_pos(3)     <- 新增：键位高 3 位
bit 1..0    key_pos(2)     <- 新增：键位低 2 位（合起来 5 位，见 2.3）
```

实际分配建议：

```text
bit 5       is_drum        1 位
bit 4..2    key_pos[4:2]   3 位
bit 1..0    key_pos[1:0]   2 位  -> 合起来 key_pos[4:0]，范围 0..15（16 键）
```

即 **bits[4:0] = key_pos（5 位，只用 0..15）**，**bit5 = is_drum**。

### 2.2 FPGA 侧的路由（改完就是这样）

```verilog
// rtl/w3c/seq_arb.v
wire evt_is_drum = score_data_i[5];          // 显式标志，不再看 axis
wire [NW-1:0] score_src_w = evt_is_drum ? SRC_KDRUM : SRC_SCORE;
```

**关键性质**：`axis` 无论取什么值（包括 12~15），都**不可能**单独让一条事件变成鼓。

### 2.3 键位字段（给 LED 指引）

```verilog
// rtl/w3c/guide_lamp.v
wire [3:0] note_key = note_data_i[4:0];      // 键位，不再用 axis
guide_key_o[note_key] <= 1'b1;               // 点灯
```

理由：用户要求"**灯跟着音高走**"。上位机本来就知道 MIDI 音高，换算成键位是一张表的事；而 `axis` 是轨号，一条轨从头到尾是同一个轴号，所以灯永远只闪同一盏（这正是用户报的"只闪 C3"）。

## 三、ESP32 侧要改的地方

### 3.1 `tools/mid2evt.py`

| 改什么 | 怎么改 |
|---|---|
| **鼓的识别**（`classify()`，`:272` 附近） | 现在靠 ① 轨名含 `drum/perc/kit/cymbal/hat` ② GM 通道 9。**保留这两条，再加一条**：命令行/配置里允许**显式指定哪条轨是鼓**（用户最清楚），三者取或 |
| **鼓轨的输出** | 现在鼓轨被**排除**在 `events.hex` 之外（`:27`、`:350-351`、`:365-366`）。改成：**鼓轨也输出事件，但每条都置 `bit5=1`**，并把 `inc` 写 0（由 FPGA 用 `drum_gen` 的表填） |
| **旋律轨** | `bit5` **必须写 0**（写死，不依赖任何条件） |
| **键位** | 每条事件按 MIDI 音高算出键位，写进 `bits[4:0]` |
| **校验器**（`:463` 附近那条 inc 越界检查） | 加一条硬检查：**任何 `bit5=0` 的事件，都不许被路由到鼓池**；以及 `bit5=1` 的事件 `inc` 必须为 0 |

### 3.2 `esp32/tools/score_word.py`

| 改什么 | 怎么改 |
|---|---|
| 位域定义（`:66-73`） | 加 `bit5 = is_drum`、`bits[4:0] = key_pos` |
| 保留位断言（`:46` 写"bit 6..0 保留，必须写 0"） | 改成"**bit6 = guide_only · bit5 = is_drum · bits[4:0] = key_pos**" |
| 校验器（`:201-202`） | 同步更新：不再是"保留位必须为 0"，而是"按新语义校验" |
| 打包函数 | 加 `is_drum` 与 `key_pos` 两个入参 |

### 3.3 键位换算表

需要一张 **MIDI 音高 -> 键位(0..15)** 的表。两条路：

```
甲：直接照轴映射表反查（FPGA 侧 axis_map.v:395-410 钢琴 / :461-476 指板 已有正向表）
乙：ESP32 侧自己维护一张 16 键音高表（与 FPGA 的表必须逐项一致）
```

建议**乙**，但**必须与 FPGA 的表逐项对齐**，并写一个交叉核对脚本。

## 四、FPGA 侧要改的地方（供你了解，不需要你动）

```
1. rtl/w3c/seq_arb.v:213     删掉 axis >= 12 的判定，改成读 bit5
2. rtl/w3c/seq_arb.v         鼓事件（bit5=1）忽略曲谱的 inc，改用 drum_gen 的表
                             （帧的 inc 只有 21 位，装不下军鼓的 42,949,673 需要 26 位）
3. rtl/w3c/guide_lamp.v:81   改用 bits[4:0] 的键位，不再用 axis
4. rtl/top.v                 位域切片与文档同步
```

### 过渡期（bit5 机制落地之前）

FPGA 侧会先把 `seq_arb.v:213` 那条轴号判定**整个删掉**，让**曲谱通路永远不产生 `SRC_KDRUM`**：

```verilog
wire [NW-1:0] score_src_w = SRC_SCORE;   // 结构上保证：旋律绝无可能变成鼓
```

代价是"曲谱里的鼓暂时按旋律发声"，但**比"旋律变成电子音鼓"安全得多**。

## 五、验收判据（双方都要过）

### FPGA 侧（我会加 tb）

```
1. 旋律事件（bit5=0）在【任意轴号】下都不产生 SRC_KDRUM
   （⭐ 专门测 axis = 12 / 13 / 14 / 15 四条边界）
2. 鼓事件（bit5=1）必须产生 SRC_KDRUM
3. 灌一份 16 轨的谱，逐条比对 src，旋律不许有一条变成鼓
4. LED：同一条轨的不同音高，点亮不同的灯
5. 回归：既有的 seq_arb / key_drum / note_manager 判据全绿
```

### ESP32 侧（请你过）

```
1. 你的谱里那条鼓轨被正确识别（轨名或 GM 通道或显式指定）
2. 输出的 events.hex 里：鼓事件 bit5=1，旋律事件 bit5=0
3. 用现有校验器跑一遍，零问题
4. 灌谱上板：鼓听起来与键盘打鼓一致；旋律绝无电子音鼓
5. LED 跟着音高走，不再只闪一盏
```
