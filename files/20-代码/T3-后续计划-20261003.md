# T3 实时变调 · 后续计划（2026-10-03 · ⛔ 不做大改版）

> **前提（用户 2026-10-03 拍板）**：⭐ **暂时不做大改** —— 共享 ADSR 引擎、`oscillator_bank` 共享 DDS、`looper` 精简 **全部搁置**。
> **本计划的方针**：⭐ **小步、低风险、不阻塞其他交付**；把 T3 的代码**保住**，让它**不再拖累主线**，等资源问题解决后再一键打开。

---

## 一、现状（一句话）

T3 变调**功能逻辑没问题**，但**这颗 GW5AT-60 装不下它**：变调结果必须"按 lane 落进 32 深数组"，读侧要 1025 LUT（`PR0004 659` 不布通）、写侧也要 ~1024 LUT（`T_Lut 39295`，更差）、每 lane 乘法器则 DSP 98%（67 根不布通）⇒ ⭐ **三条路都实测不通**。

---

## 二、计划的四条原则

1. ⛔ **不动大结构**（ADSR / 振荡器 / looper / 混音都不碰）
2. ⭐ **T3 代码保留**，但用**参数开关**让它默认**不参与综合** ⇒ 主线恢复"能出位流"
3. ⭐ **每步都要能红判据 + 红绿证据**，改 `rtl/` 必过**四道门**（综合门 / 聚焦 tb / PnR / 全量回归）
4. ⭐ **一次只改一个变量**；每次 PnR **归档位流**；⛔ 不 push（需用户同意）

## 七、⭐ P3.1（用户 2026-10-03 拍板 A′）

**决定**：先让 P2+P3 的四道门跑完收口 ⇒ 再做 **P3.1 小修** ⇒ ⭐ **串口在档 0 也能用**。

**为什么需要**：P3 的实现里，档 0 的推子是"**每一拍都跟踪**"（`fader_gear.v:128-141` 的 `else if (gear_o == 2'd0) enc_next = fader_enc;`）⇒ 串口 `'F'`/`'G'`/`'H'` 设的值**只活 1 拍**就被推子值覆盖 ⇒ ⚠️ **档 0 下串口完全无效**（不是"同时用才冲突"）。

**改法（6 行，⛔ 不改判据）**：把"每拍跟踪"改成"**推子值变化时才接管**" ——
对 `ch2_i`/`ch3_i` 各加一级寄存做**边沿检测**，只有值变了才把 `fader_enc` 写进 `enc_next`；值没变就保持 `enc_r`。
- 串口设值 ⇒ 生效并**保持** ✅
- 手动动推子 ⇒ 推子立刻接管（手动的优先）✅
- 两者都不动 ⇒ 保持上次的值 ✅
- 成本：+6 FF / ~10 LUT ✅

**纪律**：改完必须重跑四道门（综合门 / 聚焦 tb / 一次干净 PnR / 全量回归），并确认 `tb_fader_gear` 的"档 0 推子跟随"判据**仍然成立**（⭐ 只允许改"何时接管"，⛔ 不许删判据语义）。
