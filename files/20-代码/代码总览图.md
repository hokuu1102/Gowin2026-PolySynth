## 二、⭐⭐ 开工顺序（**先看这个**）

### 2.1 前置条件（**没有这些，谁都别开工**）

| # | 前置 | 为什么是前置 | 状态 |
|---|---|---|---|
| **P0** | **参数定默认值**：`POLY_TARGET=32` / `OSC_PER_VOICE=2` / 位宽 | ⚠️ 所有模块的端口宽度依赖它。⭐ **但这两个参数早就有默认值，且都是"编译期参数、改它不动接口"** → ⛔ **不用等拍板**，按 32/2 开写即可 | ✅ **已定默认值**（最终值等综合报告微调） |
| **P1** | **工具链与工程**：Gowin 能综合、能下载、能上板 | 一切的地基 | ⬜ |
| **P2** | **引脚约束 `constr/top.cst`** | 不写约束 = 不能上板。已知：`clk50=F13`、`rst=D1`、⭐ **`beep=A13` 必须钉低**（悬空会一直叫）、`I2S_BCLK=Y17`/`LRCK=AB17`/`DIN=AA16`/`PA_EN=AB16`（低有效） | 🟡 可从基石板 `.cst` 改 |
| **P3** | ⭐⭐ **波表上板最小验证（A4b）** | ⚠️ **`$readmemh` 外部 `.mem` 在 GW5AT-60 上不加载** → ROM 全 0 → **没声音，但仿真正常**。不先验，联调时"没声音"会淹没在其它问题里 | 🔴 **必做，见第 0 批** |
| **P4** | **接口冻结**：`files\20-代码\W3接口冻结表.md` v0.1 → v1.0 | 多人并行改同一批接口的前提 | 🔴 待拍板（P0 定了就能冻） |
| ~~P5~~ | ~~板子到位（左手区板 / 右手区板）~~ | ⭐ **不是必需前置** —— **只有采集支需要板子**；合成/输出支可以用 **Test Mode 假输入**先做起来 | 9/24 投板 |

> ⭐ **P5 划掉是有意的**：`test_mode` 就是**解耦器** ——
> 它让"合成 + 输出"**不等采集链、也不等板子**就能独立开发和验证。

### 2.2 四批开工顺序

```text
第 0 批 · 地基（最先，且只有一批）          里程碑 1：板子能出声 ✅
  ├── 建 Gowin 工程 + rtl/ 目录树
  ├── clk_gen.v      ÷1024 → tick_audio（⛔ 不用 PLL）
  ├── top.v 骨架 + constr/top.cst
  ├── i2s_tx.v       → 板载 DAC
  ├── wavetable.v    ⭐ 上板验证 A4b（P3）
  └── test_mode.v    ⭐ 最小版：直接产生一个/多个不同频率的正弦
                     ↑ 不依赖任何传感器、不依赖任何自制板

              ┌──────────────┴──────────────┐
              ▼                              ▼
第 1 批 · 三支并行（互不阻塞）        第 1 批 · 采集支
  【合成支】                            （⚠️ 可先用 ADDA 模块 / 信号源
    osc → adsr → voice                  代替左手区板验证）
    → note_manager → mixer                adc_spi_master → chan_scan
  【输出支】                              → calib → debounce
    fx_* → master_mix                     → axis_map
    → led_data / vis_tap / uart_ui        → event_extract / param_extract

第 2 批 · 集成
  ① W3a 真实输出接进 note_manager（撤掉 test_mode 的假输入）
  ② W3b → W3c：音量、效果链真实接通
  ③ ⭐ 全链路复测：五条红线逐条测（见 files\20-代码\验收计划.md）

第 3 批 · 增强（有富余才做）
  FM 4~6 OP ／ 蓝牙 ／ 可视化 ／ 屏 UI 完善
```

> ⭐ **第 0 批刻意最小**：它唯一的目的是**打通"从代码到耳朵"的整条路**。
> 一旦板子能出声，后面所有模块都能**单独上板听效果** —— 这是最省时间的开发方式。
>
> ⭐ **第 1 批的三支之间没有依赖**：合成支不依赖采集支（靠 `test_mode`），
> 输出支只依赖合成支的 `audio_t` 格式（**格式在接口冻结时就定了**）。

## 四、⭐ 节拍域（写 RTL 最容易踩的地方）

> **全设计只有 `clk_sys = 50 MHz` 一个时钟**（⛔ 不用 PLL）。
> 需要慢节拍的地方**一律用"节拍脉冲"**，⛔ **不许派生时钟**。

| 节拍 | 频率 | 怎么来 | 谁用 |
|---|---|---|---|
| `clk_sys` | **50 MHz** | 外部晶振 `F13` 直接进 | **全部逻辑** |
| `tick_audio` | **48.828 kHz**（`fs`） | `÷1024` | W3b 逐样本、W3c 效果链、`i2s_tx` |
| `tick_sample` | **2 kHz / 通道** | 见 `files\20-代码\采集链参数复核.md` | W3a 采集 |
| `tick_slow` | 低速（去抖/UI/LED） | 整分频 | `debounce`、`led_data`、`uart_ui` |

> ⭐ **`1024`（每样本时钟数）是所有 TDM 时隙预算的分母** ——
> 定任何"每样本要做多少次运算"都拿它算。

## 五、四条铁律（违反就集成失败）

| # | 铁律 | 违反的后果 |
|---|---|---|
| **1** | **单时钟域 + 节拍脉冲**，⛔ 不用 PLL | 经验库记载：Gowin 上 PLL 输出做全设计时钟 → **综合通过但板子全死** |
| **2** | ⭐ **固定流水线深度**，写进接口表后不许随意改 | "确定性延迟"的保证；一改，延迟预算文档作废 |
| **3** | ⭐ **单周期脉冲必须"边沿时刻断言"**，⛔ 不许事后查询 | 经验库 `L12`：脉冲事后查询**必然漏采** |
| **4** | **一人一文件**，多人不改同一个 `.v` | 否则 git 冲突 + 语义冲突 |
