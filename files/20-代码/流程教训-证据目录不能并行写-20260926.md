# 🔴 流程教训：两个「写 `sim/evidence/`」的任务不能并行（2026-09-26 凌晨）

> **现象**：⭐ 全量回归报 **63/63 全过**，🔴 **但 exit code = 1**
> **真因**：🔴 **我的调度错误** —— ⚠️ 同时跑了两个都往 `sim/evidence/` 拷 VCD 的任务
> **性质**：⭐ **不是代码问题**（⭐ 判据在汇总行 `通过 63 / 共 63`，⭐ 那才是结论）

---

## 〇、⭐⭐ 一句话

```
🔴 我【同时】启动了两个任务：
   · ⭐ 全量回归（`sim/tb_all.ps1`）
   · ⭐ 变异测试（`bringup/mutation_test.ps1`）
⭐ 而两者【都会往 `sim/evidence/` 拷 VCD】
⇒ 🔴 `Copy-Item` 抢同一个文件 ⇒ `IOException`
⇒ ⚠️ 回归脚本的"拷证据"那一步失败 ⇒ 🔴 **exit 1**，⭐ 而 63/63 其实全过。
```

```
Copy-Item : The process cannot access the file
  '...\sim\evidence\tb_beat_gen.vcd' because it is being used by another process.
At ...\sim\tb_all.ps1:272 char:24
+ ... ch-Object { Copy-Item $_.FullName (Join-Path $evDir $_.Name) -Force } ...
```

📌 **注意"被我抓到的关键点"**：⭐ 报错在 **`tb_all.ps1:272`**（⭐ **拷证据**那一步），
⭐ **⛔ 不在任何 tb 内部** ⇒ ⚠️ **一眼就能看出"不是被测代码的问题"**。

---

## 二、⭐⭐ 这条为什么重要（⭐ 与既有纪律的关系）

```
⭐ `AGENTS.md` 的 **K-119 / K-123** 早就写了：
   · 🔴 变异测试跑的时候 ⛔ 不碰 `rtl/`、⛔ 不碰 `tb/`、⛔ 不 `git add`
   · 🔴 且⛔ 不与【另一个 worktree 的任何 git 写操作】并行
   📌 理由：⭐ 变异测试**就地改可跟踪文件** ⇒ ⚠️ 并行写操作会**污染结论**。

🔴 **本轮我踩的是同族的【新形态】**：⭐ 不是 git 写操作，⚠️ 而是
   **两个任务同时写【同一个输出目录】`sim/evidence/`**
   ⇒ 🔴 同样**污染结论**（⭐ 这里表现为 exit code 不可信）。
```

⇒ ⭐⭐ **建议把纪律**写成**更一般的形式**：

> 🔴 **任何「会写 `sim/evidence/` / `build/` / `rtl/`」的任务，⛔ 都不得并行。**

## 三、✅ 正确做法（⭐ 我后续遵守）

| ⭐ 场景 | ⭐ 做法 |
|---|---|
| ⭐ 要跑回归 **且** 要跑变异测试 | ⭐ **串行**：⭐ 先跑完一个，⭐ 再看结果，⭐ 再跑下一个 |
| ⭐ 想"并行省时间" | ⚠️ **只能并行【只读】任务**（⭐ 读文件 / 查资料 / 写文档） |
| ⭐ 收到 `exit 1` 但判据全过 | ⭐ **先看报错【在脚本的哪一步】** —— ⚠️ 若在"拷产物"那步 ⇒ ⭐ **调度问题，⛔ 不是代码问题** |

## 四、📌 判据分层（⭐ 本轮的真正教训）

```
🔴 **exit code ≠ 判据。**
   ⭐ 本项目的**权威判据**是脚本打印的汇总行：
      · ⭐ 回归 → `通过 63 / 共 63`
      · ⭐ PnR  → `0 setup / 0 hold` + ⭐ **产物新鲜度断言**
      · ⭐ 变异 → ⭐ **每个变异体 `RED (caught)`** + ⭐ **0 LEAK**
   ⚠️ 而 `exit code` 会被**环境因素**（⭐ 并行抢文件、⭐ 证据拷贝失败）影响
   ⇒ ⭐ **必须先看判据行，再看 exit code** —— ⛔ 不能反过来。
📌 这与 `K-94`/`K-97` 同族：⭐ **"验收工具自己误报"** 是真实存在的失败模式。
```
