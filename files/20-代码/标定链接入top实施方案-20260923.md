### 0.4 ⭐⭐ `uart_tx` 的取得方式 + **它自己带一个真缺陷**

⭐ **来源**：⭐⭐ **用户指出**"招新题文件夹有代码，可以借用或改得更好"
⇒ ⭐ 从 `Desktop/FPGA/FPGA招新题/phase4/uart_tx.v` **移植**，⭐ 并做本项目化改造：
* ⭐ 复位**异步 → 同步**（⭐ 与 `uart_rx` 统一）
* ⭐ **内建波特率发生器**（⭐ 原版外挂 `uart_baud_gen`）
* ⭐ 加参数自检

🔴🔴 **移植过程中抓出原版一个真缺陷（⭐ 值得单独记）**：

```
⭐ 现象：发 01 02 03 ⇒ 收到 01 04 0C（⭐ 第 1 字节侥幸对，⚠️ 越往后越偏）
🔴 探针实测（发 0x02）：
   低 100 拍 = 起始 + D0   ✅ 正确
   高  50 拍 = D1          ✅ 正确
   低 350 拍 = D2..D7 应为 300  🔴 多出 50
🔴 根因：`case` 里 `4'd1..4'd7` **已经覆盖到 D7**，
   而原版又单写了 `4'd8` 分支**把 D7 又发了一遍**
⇒ 🔴 **帧长 11 位（⛔ 不是 10）**
⇒ ⭐ 接收端收完 8 位后**线还在低** ⇒ 🔴 **被当成下一个起始位** ⇒ **幻影帧**
   （⭐ 实测：一次发送产生 **2 个 `rx_done`**）
✅ 修法：`4'd8` 分支改为发【停止位】
```

⭐ **教训**：⚠️ **"别人的代码跑过 tb" ⛔ 不等于"它是对的"** ——
⭐ 原版的 tb **只测了单字节**（⭐ 那种情况下 D7 重发恰好被"停止位也是高"掩盖了一半），
⚠️ **只有把 `tx` 接回【真 `uart_rx`】做环回、且【连发多个字节】**，这个缺陷才现形。
📌 这正是 **`87 号`** 的同族：⭐ **判据没覆盖的组合 = 缺陷的藏身处**。

## 二、⭐⭐ 接入设计（⭐ 分三块，按依赖顺序）

### 2.1 块 1 · `calib_span`（⭐ 最独立，风险最低）

```
        af_sample_valid ──┬──> u_autotare.sample_valid_i
        af_sample_ch    ──┼──> u_autotare.sample_ch_i
                          └──> u_span.sample_valid_i / sample_ch_i
        af0_pol ─────────────> u_span.raw_i          ⚠️ 必须是【反相后、calib 前】那一路
        u_span.span_o[0] ────> u_calib0.span
        u_span.span_o[1] ────> u_calib1.span
        u_span.cal_ch_o  ──┬─> u_calib0.cal_ch
                           └─> u_calib1.cal_ch
        u_calib0.busy/err ───> u_span.cal_busy_i / cal_err_i
```

#### 🔴🔴 难点：`cal_ch` 的**同拍仲裁**

⚠️ 现在 `u_calib0/1.cal_ch` 接的是 **`at_ch`**（autotare 的通道）。
⭐ 接入 `calib_span` 后，**两个模块都要驱动 `cal_ch`** ⇒ 🔴 **必须仲裁**。

**为什么必须同拍**（⭐ `calib.sv` 的契约）：
```verilog
// calib.sv 的 if (tare) 分支：zero_r[cal_ch] <= raw
if (tare) zero_r[cal_ch] <= raw;      // ⚠️ raw 是【当拍输入】
// calib.sv 的 den_r <= raw - zero_cc（zero_cc 即 zero_r[cal_ch] 的选通）
den_r <= raw - zero_r[cal_ch];        // ⚠️ 同理
```
⇒ 🔴 **`raw` 是当拍值** ⇒ ⭐ `cal_ch` 必须**与 `tare`/`span` 严格同拍**
⇒ ⚠️ 错一拍会把**别的通道**的值记成这个通道的零/满量程（⭐ `K-87` 同族，**静默**）。

**⭐ 仲裁方案**：
```verilog
// ⭐ 用"谁在忙"选 `cal_ch` —— ⚠️ 两者天然互斥（见下方互锁）
wire        span_active = span_busy;      // calib_span.busy_o
wire        tare_active = at_busy;        // calib_autotare.busy_o
wire [2:0]  cal_ch_mux  = span_active ? span_ch : at_ch;
wire [1:0]  tare_or_span = span_active ? 2'b00 : at_tare;   // ⚠️ 见下
```
⚠️ **`span` 与 `tare` 绝不能同拍拉高** —— 否则 `calib` 的
`if (!busy && span) ... else if (busy)` 与 `if (tare) zero_r[...]` **会同时生效**
⇒ 🔴 先记零点又立刻拿它做满量程 ⇒ **增益算错**。

**⭐ 互锁（⭐ 必须加）**：
```
🔴 在 `calib_cmd` 层禁止同时发起：
   · `span_req_o` 到达时，若 `at_busy` ⇒ ⭐ 忽略（⭐ 并计入一个 `rejected_cnt`）
   · `tare_req_o` 到达时，若 `span_busy` ⇒ ⭐ 忽略
⭐ 或在 `top.v` 里做门控（⚠️ 更靠近硬件、更可靠）
```

⚠️ **还要注意**：⭐ `calib_span.start_i` **一旦启动就会跑完 16 轴**
（⭐ 或超时/拒绝退出）⇒ ⚠️ 它**忙的时候不能被打断**（⭐ 除非用 `abort_i`）。

### 2.3 块 3 · 字节流三分（⭐ 最需要小心的一块）

🔴 **三个消费者接【同一个** `uart_rx` **】的 `rx_done_o`/`rx_data_o`**：

```
uart_rx.rx_done_o ─┬─> evt_uart_rx.rx_done_i     （⭐ 只认 0xA5 帧）
                   └─> calib_cmd.rx_done_i       （⭐ 只认帧外的 T/S/X）
```

⭐ **两者天然共存的关键**：⭐ **各自维护独立的帧边界概念**
* `evt_uart_rx`：⭐ 只在 **`idx==0`** 位置看 `0xA5`（⭐ 不做扫描）
* `calib_cmd`：⭐ 同样跟踪 `0xA5` 边界，⭐ **帧内字母一律当载荷**

⇒ ⭐ `'T'` **不是** `0xA5` ⇒ `evt_uart_rx` 记一次 `hdr_err_cnt` 后
**留在 `idx=0` 继续等** ⇒ ✅ 不会误同步，⛔ 也不会丢帧。

⚠️ **代价（⭐ 上板时要心里有数）**：
⭐ **每发一条命令，`evt_uart_rx.hdr_err_cnt_o` 会 +1**
⇒ 🔴 **看到它涨是【正常】的，⛔ 不是故障**。

⚠️ **波特率必须一致**（⭐ 否则静默收乱码，不报错）：
```
uart_rx     #(.BAUD_DIV(100))       // 500 kbps
evt_uart_rx #(.BAUD(500_000))
calib_cmd   #(.BAUD(500_000))
```
⇒ ⭐ **三处一起改**（⭐ `uart_rx` 用 `BAUD_DIV=50`，另两个用 `BAUD=1000000`）。

| **3** | ⭐ 顺手接 `evt_uart_rx`（⭐ 数据通路） | ⭐ 同上 | ⚠️ 中 |
| **4** | ⛔ **不接 `uart_tx`** | — | 🔴 **要新写模块** |

⚠️ **每一步之后都要：** ⭐ 完整回归（~15 min）+ PnR（~10 min）
🔴 **改完 RTL 必须立刻完整编译**（⭐ 本项目踩过"没编译就往下走 ⇒ 21 个 tb 失败"）。

## 四、⭐ 触发方式（⭐ 人怎么操作）

⚠️ **标定阶段用 PC 直连**（⭐ 证据：ESP32 侧文档 §1.1）

```
PC ──USB-C（板载 BL616 桥）──> FPGA 的 uart_rx（V14）
```

| 命令 | 动作 | ⭐ 操作者看到什么 |
|---|---|---|
| ⭐ **`'T'`** | ⭐ 重新逐轴 `tare`（记零点） | ⚠️ **约 1~2 秒内无输出**，之后恢复正常 |
| ⭐ **`'S'`** | ⭐ 启动逐轴 `span` 标定 | 🔴 **需要逐个把轴按到底**（⚠️ 见下方） |
| ⭐ **`'X'`** | ⭐ 取消当前标定 | ⭐ 立即回到空闲 |

### 4.1 🔴 `span` 的操作流程（⭐ 要点）

```
① 发 'S'  ⇒ 进入标定
② 提示"请按轴 0 到底"  ⇒ ⭐ 此时【没有回传】⇒ ⚠️ 只能靠"按了有反应/没反应"判断
③ 把轴 0 按到底【停住不动】  ⇒ 等读数稳定（24 帧 ≈ 4.7 ms）
④ 再收 32 帧投票  ⇒ ⭐ (max−min) ≤ 16 才算通过
⑤ 通过 ⇒ 自动标下一轴；⚠️ 不通过 ⇒ 拒绝重来（⭐ 最多 8 次）
⑥ 16 轴全完 ⇒ done
```

⚠️ **三个现实问题（⭐ 本轮无法解决，接入后也解决不了）**：

| # | 问题 | 说明 |
|---|---|---|
| **1** | 🔴 **没有进度回传** | ⚠️ `uart_tx.v` 不存在 ⇒ ⭐ **操作者不知道现在标到第几轴**<br>⭐ 只能靠"顺序按"（⭐ 从轴 0 开始逐个数） |
| **2** | ⚠️ **"按到底停住"的判定是自动的** | ⭐ 靠读数稳定 + 投票 ⇒ ⚠️ **手抖会被拒绝**（⭐ 但这比"静默记错"好） |
| **3** | 🔴 **`S_SETTLE` 若一直不稳会超时** | ⭐ 1 秒超时后**拒绝该轴并重来** ⇒ ⚠️ 最多重来 8 次 ⇒ 之后**放弃整个标定** |

⇒ ⭐⭐ **强烈建议先接 `uart_tx`**（⭐ 哪怕只回传 `cur_axis` 一个字节）
—— ⚠️ 否则 16 轴标定**几乎没法可靠完成**（⭐ 人不知道按到第几个了）。
📌 这属 `U-33` 的扩展，⭐ **建议排在块 3 之后、上板之前**。
