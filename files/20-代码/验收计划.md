## 一、⭐ 五条红线（**必须达标**）

### ① 独立可控演奏维度 ≥2（拓展 ≥3）

| 项 | 内容 |
|---|---|
| **我们的目标** | **4 维**：音高 / 力度 / 滑音 / 颤音 |
| **怎么测** | ⭐ **逐维单独演示**：固定其余维，**只变一维**，观察输出是否随之变化 |
| **判据** | 每一维都能**独立**改变输出（不是被别的维带动） |
| **记录什么** | 每维的「输入范围 → 输出变化」对应表 + 演示录音 |
| **证据** | `[板上实测]` 录像 + 波形/频谱 |
| **陷阱** | ⚠️ 必须**一次只变一维** —— 多维同变时"看起来有效"说明不了独立性（经验库 `C03`） |

### ② 复音数 ≥4（拓展 ≥32）

| 项 | 内容 |
|---|---|
| **怎么测** | ⭐ **用 Test Mode**：逐档 4 / 8 / 16 / 32 / 64，频谱数独立谱峰 |
| **判据** | 每档的**谱峰数 = 屏显 `Active OSC` = RTL 结构里的振荡器数**（三层一致） |
| **记录什么** | 每档的三层证据截图 + 谱峰计数表 |
| **证据** | `[板上实测]` 频谱截图 + 时域波形 + `[静态复核]` RTL |
| **陷阱** | ⚠️ **频率间隔要够**，否则谱峰糊成一团数不清；⚠️ 要**分档**测，不能只测一档 |

### ③ 控制→出声延迟 ≤10 ms（拓展 ≤5 ms **且确定性无抖动**）

| 项 | 内容 |
|---|---|
| **怎么测** | ⭐ **双通道示波器**：<br>· 通道 A = **触发动作的电信号**<br>· 通道 B = **DAC 模拟输出的起音** |
| ⭐ **通道 A 怎么拿** | 从 **J8 调试测试点**引一路"事件标志"（FPGA 内部事件产生时拉高）—— ⭐ **这正是 J8 的用途**；或用拨弦件霍尔开关信号本身 |
| **判据** | 延迟 ≤5 ms，且 **重复 ≥50 次的极差 ≤0.5 ms**（⭐ 要的是**上界稳定**，不是平均值好看） |
| **记录什么** | min / 中位数 / max / **极差** + 原始测量序列（⛔ 不要只记平均值） |
| **证据** | `[板上实测]` 示波器截图 + 数据表 |
| **陷阱** | ⚠️ 测量链本身要防坑：先确认**动作信号真的到达了被测点**（经验库 `U30` 测量纪律） |

> 📌 预算显示只有 ~0.59 ms（余量 8.5 倍，见 `files/20-代码/延迟预算逐段分解.md`），
> **所以这条的风险很低** —— 但**必须实测留证**，因为它是评分红线。

### ④ 音色数 ≥2

| 项 | 内容 |
|---|---|
| **怎么测** | 切换音色，**录同一段旋律**，对比频谱与听感 |
| **判据** | ≥2 种**可辨识地不同**的音色（不是"稍微不一样"） |
| **记录什么** | 每种音色的频谱特征 + 录音 |
| **证据** | `[板上实测]` 录音 + 频谱 |

### ⑤ 合规：全部 RTL / 严禁预录 PCM

| 项 | 内容 |
|---|---|
| **怎么测** | ⭐ **RTL 代码复核** + 波表内容检查 |
| **判据** | · 音频通路**全部** HDL（无 CPU 参与）<br>· **无 PCM 播放模块**、无整段录音触发<br>· ⭐ **波表 ROM 里是"单周期波形"**（几百~几千点），**不是整段音频** |
| **记录什么** | 代码结构图 + 波表内容（截图证明是一个周期的采样） |
| **证据** | `[静态复核]` 代码 + 波表 |

> ### ⚠️⚠️ 这是**最需要我们主动解释**的一项
> 因为**我们用波表** —— 评委看到 ROM 里有波形数据，**可能误以为在放预录音频**。
>
> **必须主动说清的区别**：
>
> | | 预录 PCM（⛔ 违规） | **我们的波表（✅ 合规）** |
> |---|---|---|
> | ROM 里存什么 | **一整段音频**（几秒~几分钟） | **一个周期的波形**（几百~几千点） |
> | 播放方式 | 按时间顺序**读出即输出** | 按**实时相位**查表，**音高/包络/叠加全是实时算的** |
> | 时长依赖 | ROM 大小 = 音频时长 | ROM 大小与音频时长**无关** |
> | 变调 | 做不到（或要重采样） | ✅ 相位增量一改就变调，**逐样本实时生成** |
>
> ➡️ **视频里要专门用一段解释这个区别**（配代码 + 波表内容截图）。

#### ⭐ 为了让代码**自证**，提前做这些准备（**在写 RTL 时就做，不是事后补**）

> 赛题原文：「**可通过 RTL 代码佐证**纯硬件实时合成通路，验证无预录音频播放行为」
> —— 所以代码要让人**翻一眼就信**，而不是靠我们口头解释。

| # | 准备什么 | 具体做法 |
|---|---|---|
| **1** | ⭐ **模块命名自解释** | `osc.v` / `phase_acc.v` / `adsr.v` / `wavetable.v` / `mixer.v` —— ⛔ **不要 `mod1.v` / `block_a.v`** |
| **2** | ⭐ **波表文件命名带语义** | 如 `wavetable_saw_1cycle_1024x16.v` —— "**1cycle**"直接写进文件名 |
| **3** | ⭐ **波表表头写清性质** | 注释里写：`单周期 / 1024 点 / 16 bit 有符号 / 零直流 / 生成方式` |
| **4** | ⛔ **避免误导性命名** | ⛔ 不要出现 `pcm_player` / `audio_playback` / `sample_rom` / `play()` 这类词（即使是别的东西） |
| **5** | ⭐ **准备"审查路径"** | 一份从 `top.v` → `w3b_top` → `voice` → `osc` → `wavetable` 的**调用链说明**，让评委 5 分钟能自己走一遍 |
| **6** | ⭐ **结构性佐证：点数 vs 时长** | `1024 点 @ 48.8 kHz = 21 ms`，而一个音符可以响**几秒** → **物理上不可能是整段录音**。⭐ 这句话写进说明文档，很有说服力 |
| **7** | ⛔ **RTL 里不能有"按时间顺序读大数组"的结构** | 那是**预录的形态特征**。合法形态是：**相位累加器 → 查表地址**（地址由相位决定，不由时间计数决定） |

> ⭐ **第 7 条是技术上的分水岭**：
> · **预录**：`addr = addr + 1`（**地址随时间线性增长**，读到尾就结束）
> · **波表合成**：`addr = phase[高位]`（**地址由相位决定**，相位增量改了就变调 → 可以无限循环）
>
> ➡️ **代码里只要能指出"地址来自相位累加器"，合规性就一目了然。**

#### ⭐ 建议的展示顺序（视频里怎么讲）

```text
① top.v 的模块框图  →  显示音频通路全是 HDL，没有 CPU、没有 PCM 模块
② wavetable.v 的表头  →  单周期 / 1024 点 / 零直流
③ osc.v 的相位累加器  →  地址 = phase[高位]，不是时间计数
④ 点数 vs 时长的算术  →  1024 点 = 21 ms，而音符响几秒 → 不可能是录音
⑤ Test Mode 频谱     →  多路不同频率实时生成
```

## 二、拓展项（**冲分**，按优先级）

| # | 项 | 判据 | 怎么测 | 证据 |

| **1** | ⭐ **Test Mode**（现场验证必需） | 分档 4/8/16/32/64 均可工作；三层证据一致 | 逐档演示 | `[板上实测]` 视频 + 频谱 |
| **2** | **≥3 维表情** | 力度动态 / 滑音 / 颤音 三维独立可用 | 同红线 ① | 录像 |
| **3** | **效果器**（混响 / 延迟 / 合唱） | 三个都在 **FPGA 内部**实现，**可独立开关** | ⭐ **A/B 对比**：开/关同一段音频，对比听感与频谱 | 录音 + 频谱 |

## 三、⭐⭐ Test Mode 专项验收（因为它两头都要演）

> **2026-09-13 定案（依据）**：（决赛）不会指定/检查固定测试条件 →
> ⭐ **满足最基础的就可以了**。所以本节的"基础版"就是**必做范围**，
> "增强版"是**有余力再加、且不改架构**。

| 项 | **基础版（必做）** | 🟡 增强版（可后加） |
|---|---|---|
| **行为** | 同时输出**多路不同频率** | 同左 |
| **分档** | **4 / 8 / 16 / 32**（⭐ 建议保留 —— 证明"数量可控"的最省事手段，实现上只是几个档位常量） | 任意档位（如 48 / 64） |
| **频谱** | 谱峰**数得清** | 同左 |
| **显示** | ⛔ 不要求 | ⭐ 屏显 `Active OSC: XX` + **各路频率** |
| **时域** | ⛔ 不要求 | 波形佐证"多频叠加" |
| **切换** | 辅助按键（J6）即可 | 屏 UI（J2）+ 按键兜底 |
| **复现要求** | ⭐ **换个人操作也能切进去**（决赛会这么考） | 同左 |

**判据（基础版）**：每档的**谱峰数 = 屏显或文档声明的振荡器数**（若不做屏显，则**视频/文档里写清档位**）。

> ⚠️ **两个基础版也必须守的**：
> 1. ⭐ **相邻频率要够开** —— 否则谱峰糊成一团，**评委会数错**（这是基础版最容易失败的点）
> 2. ⭐ **要有文档/代码说明档位与振荡器数的对应** —— 不靠"看着差不多"

> ### 📌 为什么"分档"值得保留（即便只做基础版）
> 规则原话是「输出多路不同频率音频，**频谱可观察到对应数量独立谱峰**」——
> **"对应数量"这四个字要求评委能对得上数**。分档（4/8/16/32）让"对得上"变得一眼可见，
> ⭐ 而实现上**只是几个常量**，近乎零成本。

## 五、⚠️ 不达标时的处理（按红线优先级）

| 红线 | 不达标的后果 | 退路 |
|---|---|---|
| **① 维度 ≥2** | 🔴 **直接不合格** | 必须有 2 维；4 维里任一维出问题，还有 3 维 |
| **② 复音 ≥4** | 🔴 **直接不合格** | 基础只要 4 → 余量极大；⚠️ 但拓展要 32 |
| **③ 延迟 ≤10ms** | 🔴 **直接不合格** | 预算余量 8.5 倍 → 风险最低的一条 |
| **④ 音色 ≥2** | 🔴 **直接不合格** | 换波表即换音色，成本最低 |
| **⑤ 合规** | 🔴 **直接不合格（性质最严重）** | ⭐ **靠"主动解释清楚"防守**，不靠退路 |
| 拓展项 | 只影响分数 | 按 §二 优先级取舍 |

> ⚠️ **五条红线里 ④ 最容易补、⑤ 最容易翻车、③ 风险最低。**
> 所以评审前的自查顺序应该是：**⑤ 合规 → ① 维度 → ② 复音 → ④ 音色 → ③ 延迟**。
