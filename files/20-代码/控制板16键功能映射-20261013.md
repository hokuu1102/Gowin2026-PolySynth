## 一、8 颗 WS2812 的功能与显示逻辑

### 1.1 核心原则

一颗 WS2812 同一时刻只能显示**一个**颜色。所以要在两个维度上分工：

- **颜色** 管 **离散档位**（音色是哪一种、鼓机是第几型）
- **时间** 管 **开关量**（节拍器开不开、正在录还是回放、EC11 刚被动过）

这条原则让"两个功能共用一颗灯"可行，而且大多能复用现有机制（例如 `led_indicator.v` 里 `BL_BEAT` 本来就是"拍点没来就熄灭"）。

### 1.2 定稿表

| # | 功能 | 颜色（档位） | 时间（开关量） |
|---|---|---|---|
| 1 | **音色** | 白 = BASS / 青 = GUITAR / 紫 = PIANO / 橙 = PAD | 无 |
| 2 | **16 键行为** | 橙 = 指板 / 绿 = 键盘 | 蓝 + 呼吸 = 键盘打鼓（覆盖前两者，因为它是 override） |
| 3 | **推子功能** | 紫 = 变调 / 青 = 颤音 / 黄 = 摇把 | 灭 = 当前无推子功能 |
| 4 | **节奏** | 红 / 洋红 / 黄 / 橙红 = 鼓机 4 型；绿 = 鼓机关但节拍器开 | 每拍短暂熄灭 100 ms = 节拍器开 |
| 5 | **looper** | 绿 = 回放 / 暗蓝 = 空闲 | 红 + 快闪 = 录音 |
| 6 | **EC11 对象 + 音高状态** | 见 §1.3 | 见 §1.3 |
| 7 | **HDMI 显示** | 蓝 = 波形 / 品红 = 李萨如 | 无 |
| 8 | **效果器** | 灭 = 关（占位期恒灭） | 预留 |

### 1.3 第 6 颗：EC11 对象 + 音高状态（方案 A · 分时）

**静止时显示音高状态**：

| 状态 | 颜色 | 说明 |
|---|---|---|
| 变调 > 0（升） | 暖橙 `FF8000` | 音高被整体抬高 |
| 变调 < 0（降） | 冷蓝 `0080FF` | 音高被整体压低 |
| 变调 = 0 | 灭 | 无偏移 |
| 滑音进行中 | 青 `00FFFF` | 优先级高于变调（正在滑的时候最需要知道） |

**EC11 被转动或按下时，临时切换成"对象色"，持续 1 秒后回落**：

| EC11 当前对象 | 临时颜色 |
|---|---|
| BPM | 黄 `FFFF00` |
| 调音高（变调） | 紫 `8000FF` |

理由：旋钮管什么是"你动它的那一刻"才需要知道的信息，静止时常显是浪费一颗灯。这也是大多数硬件旋钮的做法。

实现代价：一个约 20 位的超时计数器（50 MHz 下 1 秒 = 5×10⁷，需 26 位），面积可忽略。

### 1.4 第 4 颗：为什么两个功能能共用

| 鼓机 | 节拍器 | 显示 |
|---|---|---|
| 关 | 关 | 灭 |
| 关 | 开 | 绿 + 每拍暗一下 |
| 开 | 关 | 节奏型色常亮 |
| 开 | 开 | 节奏型色 + 每拍暗一下 |

四种组合全部可分辨。而且"闪烁本身传达速度"这个原有好处保留了（PCB 文档 §2.3 特意为此选的按拍闪）。

### 1.5 第 2 颗：为什么模式与键盘打鼓能共用

它们在代码里是**同一维度**：都决定"16 个键此刻是什么"。

- `play_fretboard_mode`（`top.v:1047`，= `~ui_mode_piano`）：指板 / 键盘
- `key_drum_r`（`top.v:740-743`，串口 `K` 切换）：键盘打鼓

而 `key_drum_r` 是**覆盖式**的：`top.v:4803` 的 `src_a_inc = key_drum_r ? key_drum_inc : ...`，打开时 16 键直接产出鼓声，模式在下面但不起作用。所以一灯三态（指板 / 键盘 / 键盘打鼓）语义成立，优先级：键盘打鼓 > 模式。

## 二、4×4 矩阵 16 键映射

### 2.1 定稿表

列 = 功能组；行内相邻也是同组。

| | 列 0 · 节奏/循环组 | 列 1 · 音色组 | 列 2 · 音高组 | 列 3 · 系统组 |
|---|---|---|---|---|
| 行 0 | 节拍器 `B` | 音色循环 `I` | 滑音 `W` | 显示切换 `E`（HDMI） |
| 行 1 | 键盘打鼓 `K` | 推子档位 `J` | 变调 升 `G` | 模式 指板/钢琴 |
| 行 2 | 鼓机节奏型 `D` | 效果器（占位） | 变调 降 `F` | Test Mode `M` |
| 行 3 | **looper 清空 `C`（长按 2 s）** | 备用 1 | 备用 2 | 标定 `T` 短按 / `S` 长按 |

14 个功能 + 2 个备用。

looper 清空放在这一格的理由：它是**破坏性**操作，所以放在最下一行（最难误触）并且要求**长按 2 s**；同时列 0 本来就是"节奏/循环"组，looper 归在这里语义上也顺。列 0 因此从"节奏组"改称"节奏/循环组"。

### 2.2 EC11 编码器的角色

| 动作 | 作用 |
|---|---|
| 旋转 | 改变**当前对象**的值（相对步进） |
| 按压 | **切换对象**：BPM 与 调音高 之间循环 |

接口已留好：`bpm_up_i` / `bpm_dn_i`（相对）与 `bpm_load_i` / `bpm_i`（绝对）在 `top.v:2007-2009`，目前硬接 `1'b0`；`enc_a_i`/`enc_b_i`/`enc_sw_i` 引脚已约束（E19/C19/C18），两个 `debounce` 例化的 `enc_cw`/`enc_ccw` 留空未接。

### 2.2.1 推子与 EC11 的分工（用户 2026-10-13 裁定）

两者**都保留**，改的是同一个量（`transpose_semi`），分工在手感与精度：

| 控件 | 性质 | 用途 |
|---|---|---|
| 推子 | 连续行程，可以一扫而过 | 粗调、快速大范围移动 |
| EC11 | 一格一个半音，离散 | 精调，精确 ±1 半音 |

**一处需要如实说明的地方**：当前代码里推子的输出**已经是半音量化的**，不是模拟连续量。

- `fader_gear.transpose_semi_o` 是 `signed [4:0]`，范围 −12..+12（`rtl/w3a/fader_gear.v:116`）
- `gear_step_of()` 是逐级阈值比较链（4095 / 3754 / 3413 / 3072 / 2730 …），每侧 13 档（同文件 `:124-131`）
- 最终按 `12 + right_step − left_step` 合成（同文件 `:95`）

所以"推子是连续变化量"描述的是**手感**（推子能平滑扫过很多档），**数值上仍是半音步进**。若你要的是真正的连续变调（pitch bend），那是另一处改动，需要单独确认。

### 2.3 键与灯的对应关系

| 键 | 对应灯 |
|---|---|
| 节拍器 `B` | 第 4 颗 |
| 键盘打鼓 `K` | 第 2 颗 |
| 鼓机节奏型 `D` | 第 4 颗 |
| 音色 `I` | 第 1 颗 |
| 推子档位 `J` | 第 3 颗 |
| 效果器 | 第 8 颗 |
| 滑音 `W` | 第 6 颗 |
| 变调 升/降 `G`/`F` | 第 6 颗 |
| 显示切换 `E` | 第 7 颗 |
| 模式 | 第 2 颗 |
| looper 清空 `C` | 第 5 颗（清空后回到"暗蓝 = 空闲"） |
| Test Mode `M` | 无（归屏） |
| 标定 `T`/`S` | 无（标定中指示已放弃） |

## 三、串口命令分类（从代码取准，不是文档转述）

来源 `rtl/w3a/calib_cmd.v:89-211`，共 22 条。

### A 类 · 开/关切换 ⇒ 上键

| 命令 | 功能 | 指示 |
|---|---|---|
| `B` | 节拍器 开/关 | 灯 4 |
| `K` | 键盘打鼓 开/关 | 灯 2 |
| `W` | 滑音 开/关（2026-10-11 新增） | 灯 6 |
| `E` | 显示 波形↔李萨如（2026-10-13 新增） | 灯 7 |
| `M` | Test Mode 进/出 | 屏 |

### B 类 · 循环/步进 ⇒ 上键

| 命令 | 功能 | 指示 |
|---|---|---|
| `I` | 音色循环 BASS→GUITAR→PIANO→PAD | 灯 1（且已有实体键 S2） |
| `D` | 鼓机节奏型 切下一个 | 灯 4 |
| `J` | 推子档位 切下一档 | 灯 3 |
| `F` / `G` | 变调 −1 / +1 半音 | 灯 6 |

### C 类 · looper ⇒ 不上键（有脚踏），但灯保留

实测 `rtl/top.v:506-507`：

```verilog
input  wire pedal_loop_rec_i,   // E18 · PMOD0 针 8 · looper 录/停 · 上拉
input  wire pedal_loop_play_i,  // B22 · PMOD0 针 6 · looper 播 · 上拉
```

| 命令 | 功能 | 谁管 |
|---|---|---|
| `R` | looper 录/停 切换 | 脚踏 `pedal_loop_rec_i` |
| `L` | looper 播/停 切换 | 脚踏 `pedal_loop_play_i` |
| `C` | looper 清空 | 没有脚踏，见 §六 待定 |
| — | looper 状态 | 灯 5 |

### D 类 · 需要数值 ⇒ 归 EC11

`Q`（BPM）与 `H`（变调绝对量）都是臂化命令，键盘打不出数值，交给 EC11 旋转。

### E 类 · 诊断 ⇒ 保持串口

`P` · `V` · `N` · `Y` 要读数，键上放不下。`X`（中止标定）再按一次标定键即可。

## 四、矩阵键盘代码评审（参考 `C:\Users\hokuu\Desktop\FPGA\key_board\`）

### 4.1 值得保留的设计

| # | 做法 | 为什么好 |
|---|---|---|
| 1 | 独热编码状态机，注释写明"省 LUT、无中间态、电路更安全" | 独热在 FPGA 上译码浅，且不会出现非法中间态 |
| 2 | "先赋 `state_next <= state`，再 `case` 覆盖" | 即"默认保持 + 覆盖"，所以不需要 `default`，也不会生成锁存器 |
| 3 | `STATE_DELAY` 用满 20 ms 才确认 | 在确认前把抖动耗掉，比"先出结果再补去抖"干净 |
| 4 | `STATE_PICKUP` 拉高列"助力上拉" | 真经验：FPGA 内部上拉弱、电平回升慢，松手后主动驱高让波形快速回高 |
| 5 | `key_filter` 输出 `key_p_flag` / `key_r_flag` | 方向对，上层要的正是边沿脉冲而不是电平 |
| 6 | `key_filter` 里三拍同步 | 异步输入必须先同步 |

### 4.2 对这块板有一个致命不匹配

原代码**同时驱动行和列**（`key_row_out` + `key_col_out`，靠 `key_row_en`/`key_col_en` 三态切换）：

```verilog
STATE_IDLE, STATE_END: key_col_en <= 1'b1; key_col_out <= 4'b0000;  // 驱动【列】
STATE_FLIP:            key_row_en <= 1'b1; key_col_en <= 1'b0;      // 改为驱动【行】
```

而我们的 PCB 方向是固定的（`constr/top.cst` 与 PCB 文档 §1 双向核对过）：

| 信号 | 方向 | 引脚 |
|---|---|---|
| `ctrl_row_o[3:0]` | 出（FPGA 驱动行） | D16 · E16 · E17 · F16 |
| `ctrl_col_i[3:0]` | 入（上拉，FPGA 只读列） | F15 · C20 · D20 · D19 |

列是纯输入，驱动不了，"拉高列助力上拉"那一招在这块板上用不了。好消息是那个助力只是提速、不是功能必需，标准做法（逐行拉低、读列）照样工作。

### 4.3 其余优化点

| # | 位置 | 问题 | 建议 |
|---|---|---|---|
| 1 | `always @(*)` 里用了非阻塞 `<=`（`:45-68`） | 组合块里用 `<=` 能跑但违反惯例，且 `if(!rstn)` 把复位混进组合逻辑 | 组合块一律 `=`；复位只放时序块 |
| 2 | 两相方案对多键有歧义 | 先"全列拉低读行"、再"全行拉高读列"，按了 `(r1,c1)+(r2,c2)` 只知道行集与列集，配不出是哪两对 | 改逐行拉低，每键唯一定位，且天然避开"同列两键"的推挽 |
| 3 | `judder_cnt` 26 位（`:34`） | `MCNT_JUDDER = 999_999`，只需 20 位 | 省 6 个 FF |
| 4 | `judder_fin` 没有复位项（`:122-124`） | 靠"`cnt=0` 则比较为假"自洽，能工作，但读代码容易误判 | 补注释说明自洽，或显式复位 |
| 5 | `key_data` = `{col, row}` 8 位 | 够 16 键，但上层还要再译码 | 直接输出 16 位"哪个键"加边沿脉冲 |

### 4.4 去抖层不用移植 `key_filter`

仓库里已有 `rtl/drivers/debounce.sv:24`，比 `key_filter` 更全：

| 参数/端口 | 作用 |
|---|---|
| `NKEY` | 任意键数，直接给 16 |
| `DB_MS` | 去抖毫秒数，参数化 |
| `ACTIVE_LOW` | 低有效（上拉加接地），正是我们这种 |
| `key_down` / `key_up` | 按下/抬起脉冲，正是上层要的 |
| `enc_a` / `enc_b` / `enc_sw` | 连 EC11 一起管 |

而且 `top.v` 已经接了 `enc_a_i`/`enc_b_i`/`enc_sw_i`，EC11 这一半是现成的。所以 `key_filter.v` 的思路已被覆盖，不重复造。

## 五、实现方案

### 5.1 结构

```
ctrl_row_o[3:0] --> [ ctrl_matrix_scan ]  新增：逐行拉低 + 读列
ctrl_col_i[3:0] --> [                  ]
                            |
                            | key_raw[15:0]
                            v
                    [ debounce #(NKEY=16, DB_MS=5, ACTIVE_LOW=1) ]   复用现成模块
                            |
                            | key_down[15:0]
                            v
                    [ ctrl_key_map ]      新增：16 键 -> *_req
                            |
                            v
                    与 calib_cmd 的同名 *_req 做 OR
```

`calib_cmd` 及其全部下游一行不改。硬件文档 `Console引脚与控制接口总表-20261001.md:129-130` 早就定了这个原则："按键接到同一组 `*_req` 脉冲上，与串口输出 OR"。

### 5.2 两个新增模块的要点

| 模块 | 要点 |
|---|---|
| `ctrl_matrix_scan` | 逐行拉低（`ctrl_row_o = ~(4'b1 << row_cnt)`），每行等一小段让列上拉电平稳定，再采 `ctrl_col_i`，拼成 `key_raw[15:0]`。一次只有一行低，所以同列两键也不会推挽，正是 `top.v:6077` 注释担心的那件事 |
| `ctrl_key_map` | 纯组合加 16 个单周期脉冲：`key_down[行*4+列]` 对应各自的 `*_req`。长按判定（标定 `T`/`S`、清空 `C`）各一个计数器 |

灯侧另加：`led_indicator` 的 `N_CH` 从 7 扩到 8，第 6 颗加"EC11 对象临时色"的超时计数器，`top.v` 的 `WS_LED_N` 从 16 改回 8。

### 5.3 成本与风险

| 项 | 估算 |
|---|---|
| 扫描器 | 约 10 FF · 约 20 LUT |
| `debounce`（NKEY=16, DB_MS=5） | 约 300 FF · 约 100 LUT（主要开销） |
| 键映射与长按 | 约 30 FF · 约 60 LUT |
| 灯侧（第 8 颗 + 超时计数器） | 约 30 FF · 约 40 LUT |
| 合计 | 约 370 FF（0.6%）· 约 220 LUT（0.7% CLS） |

面积很便宜。但当前 `CLS` 已到 86%（25,639 / 29,952）、Setup 最差余量只剩 +0.018 ns，所以真正的风险是时序不是面积。"布得进去"和"过得了时序"是两件事，落地必须一次只加一块并且每步重跑 PnR。

若 `DB_MS` 那约 300 FF 想省：可把扫描周期放慢（如 1 ms/行），用"连续 N 次相同"的小计数器去抖（3~4 位每键，约 64 FF）。但那就离开仓库现成模块了，建议先用现成的。

### 6.1 looper 清空 `C` —— 已裁定：给一个键

实测只有 2 个脚踏（录/停 与 播），没有"清空"的脚踏。

**用户 2026-10-13 裁定：给一个备用键。** 落在**列 0 行 3**（最下一行，最难误触），并且要求**长按 2 s** 才生效（破坏性操作必须有保护）。

### 6.2 效果器只有占位

`ui_fx_en` / `ui_fx_sel` 在 `top.v` 里只有声明与端口映射（`:998-999` 与 `:1033-1034`），**没有消费者**；全仓也搜不到任何 fx / delay / reverb 模块。所以第 8 颗灯与效果器键都是给未来功能占位，现在不能用。

### 6.3 剩余 2 个备用位

**用户 2026-10-13 裁定：剩下的留着备用**（丝印打 `SPARE`）。

位置是**列 1 行 3** 与 **列 2 行 3**。将来若要填，候选是：起始音（base semi）升/降（现为屏项）、主音量或静音（现在没有串口命令，需新增）。

### 6.4 推子与 EC11 —— 已裁定：都保留

见 §2.2.1。推子粗调（连续行程、可一扫而过），EC11 精调（一格一个半音），两者改同一个 `transpose_semi`。

需要留意的是 §2.2.1 记的那点：**当前代码里推子的输出已经是半音量化的**，所以"连续"是手感而非数值分辨率。
