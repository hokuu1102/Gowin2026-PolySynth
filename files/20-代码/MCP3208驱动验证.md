# MCP3208 驱动与扫描器验证

> **状态**：单片 MCP3208 的 RTL 与功能仿真已通过；三片并行总控、Gowin 顶层接入和真芯片时序仍待完成。

## 一、范围

`rtl/drivers/mcp3208_driver.sv` 负责一次单端通道转换，以 SPI Mode 0 时序发送 24 位事务，并返回 12 位采样值。

`rtl/drivers/mcp3208_scanner.sv` 在底层驱动之上依次扫描 CH0～CH7。默认参数下，每 `0.5 ms` 启动一轮扫描，即每个通道以 `2 kHz` 重访。

这两个模块只覆盖**一片** MCP3208。仓库规划中的三片独立四线并行总控 `adc_farm`、三片互不干扰检查以及顶层端口接入尚未实现，因此不能把 T11/T12 整体标记为完成。

## 二、接口与参数

### `mcp3208_driver`

| 名称 | 方向 | 含义 |
|---|---|---|
| `clk` | 输入 | 系统时钟，默认 50 MHz |
| `rst_n` | 输入 | 低有效同步复位 |
| `start` | 输入 | 空闲时拉高一拍，启动一次转换 |
| `channel[2:0]` | 输入 | 单端通道号 CH0～CH7 |
| `adc_data[11:0]` | 输出 | 最近一次转换结果 |
| `busy` | 输出 | SPI 事务进行中为 1 |
| `done` | 输出 | 转换完成后拉高一个系统时钟周期 |
| `adc_cs_n` | 输出 | MCP3208 低有效片选 |
| `adc_sclk` | 输出 | SPI Mode 0 时钟 |
| `adc_mosi` | 输出 | MCP3208 DIN |
| `adc_miso` | 输入 | MCP3208 DOUT |

### `mcp3208_scanner`

| 名称 | 方向 | 含义 |
|---|---|---|
| `enable` | 输入 | 扫描使能 |
| `sample_channel[2:0]` | 输出 | 与当前采样对应的通道号 |
| `sample_data[11:0]` | 输出 | 当前采样值 |
| `sample_valid` | 输出 | 单通道采样有效脉冲 |
| `frame_done` | 输出 | CH7 完成时产生的一周期脉冲 |

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `CLK_HZ` | `50_000_000` | 系统时钟频率 |
| `SCLK_HZ` | `1_000_000` | MCP3208 SPI 时钟频率 |
| `CHANNEL_RATE_HZ` | `2_000` | 每通道重访频率；对应整片帧周期 0.5 ms |

## 三、运行仿真

在仓库根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\sim\run_mcp3208.ps1
```

若要在仿真通过后打开 GTKWave：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\sim\run_mcp3208.ps1 -OpenWave
```

也可只运行全仓回归中的 MCP3208 项：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\sim\tb_all.ps1 -Filter mcp3208
```

## 四、自动验证项

`tb/drivers/tb_mcp3208_driver.sv` 覆盖：

- CH0～CH7 的单端命令字；
- 每笔事务恰好 24 个 SCLK 上升沿；
- 8 组不同的 12 位返回值；
- `busy`、`done`、`CS` 和 SCLK 空闲状态。

`tb/drivers/tb_mcp3208_scanner.sv` 覆盖：

- 连续两轮 CH0～CH7 扫描，共 16 笔事务；
- 通道顺序、命令字和返回数据一一对应；
- `frame_done` 与 CH7 的 `sample_valid` 同拍；
- 相邻两轮帧完成时间相差 500000 ns。
