# 🎨 `timbre` 扩到 3 位（5 个音色槽）—— 改动清单

> **日期**：2026-09-24
> **起因**：⭐ 用户要"**两个吉他**" ⇒ ⭐ 需 5 个音色槽（`BASS` / `GUITAR-1` / `GUITAR-2` / `PIANO` / `PAD`）
> ⚠️ 而 `timbre` **只有 2 位 = 4 档** ⇒ 🔴 **必须扩到 3 位**
> ⭐ **用户 2026-09-24 拍板**：⭐ **扩到 3 位，5 个音色全留**
> **状态**：🔴 **待落地**（⭐ 本文件是设计）

---

## 〇、⭐⭐ 一句话 + **一个好消息**

| 项 | 结论 |
|---|---|
| ⭐ **怎么做** | ⭐ **`timbre` 从 2 位扩到 3 位**（⭐ 用 `bit 6`） |
| ✅ **好消息** | ⭐ `bit 6` **确实空闲** —— ⭐ 保留区是 **`bit 6..0`（7 位）**，⭐ `timbre` 只用 `8..7`<br>⇒ ⭐ **⛔ 不改帧长（仍 9 字节）· ⛔ 不改缓冲区 · ⛔ 不动其他字段** |
| 🔴 **但改动是 10 处**（⭐ 不是 5 处） | ⚠️ 我第一版**低估了** —— ⭐ 实测有 **10 处**（⭐ 含 `TIMBRE_W` 参数、掩码、断言） |
| ⚠️ **跨 2 个仓库** | 🔴 **含 ESP32 侧 2 处**（⭐ 另一条线） |

## 一、⭐⭐ 位分配（⭐ 扩位后）

```
bit 63..44   tick      (20 bit)
bit 43..23   inc       (21 bit)
bit 22..19   axis      ( 4 bit)
bit 18..11   vel       ( 8 bit)
bit 10..9    kind      ( 2 bit)
bit  8..6    timbre    ( 3 bit)   ← 🔴 从 2 位扩到 3 位（⭐ 新增 bit 6）
bit  5..0              ( 6 bit)   ← ⭐ 保留区还剩 6 位
                            ⭐ 合计 = 20+21+4+8+2+3+6 = 64 ✅
```

⚠️ **⚠️ 关键：`timbre` 的位【位置】没变**（⭐ 仍是 `SH=7`）——
⭐ 只是**多用了 `bit 6`** ⇒ ⭐ **所以移位常量 ⛔ 不用改**，⭐ **只有【掩码】从 `0x3` 改成 `0x7`**。

🎯 **这大幅降低了改动风险**：
| 改什么 | ⭐ 数量 |
|---|---|
| 🔴 **掩码**（`& 0x3` → `& 0x7`） | ⭐ **4 处** |
| ⚠️ **位宽参数**（`TIMBRE_W` 2 → 3） | ⭐ **4 处** |
| ⚠️ **音色数**（`TIMBRE_N` 4 → 5） | ⭐ **1 处** |
| ⚠️ **断言**（`> 0x3` → `> 0x7`） | ⭐ **1 处** |
| ✅ **移位常量**（`TIMBRE_SH=7`） | ⭐ **⛔ 不用改**（⭐ 位置没变！） |

## 二、🔴🔴 **完整的改动清单**（⭐ 实测修正版）

> ⚠️ **本文档第一版把范围写错了**（⭐ 说 `evt2wav.py`/`play_seq.v` 要改掩码）——

### 2.0 🔴🔴 **先说一个更大的发现：`timbre` 现在【根本没被提取】**

```
🔴 `top.v:1387`  .evt_timbre_valid_i (1'b0)     ← ⭐ 恒 0！
🔴 `top.v:1388`  .evt_timbre_i       (2'd0)     ← ⭐ 恒 0！
🔴 `top.v:1418`  .timbre_id_i        (2'd0)     ← ⭐ 振荡器永远用音色 0
⚠️ `play_seq.v`  【不输出 timbre】 —— 它的 `note_data_o` 是 64 bit 原样
```

⇒ ⭐⭐ **所以"扩位"只是第一步** —— ⚠️ **真正的活是"把 `timbre` 从 64 bit 事件里提取出来"**：

| # | ⭐ 要做 | ⚠️ 说明 |
|---|---|---|
| **1** | ⭐ **加"拆字段"逻辑** | ⭐ `play_seq` 输出 `timbre`，⭐ 或在 `top.v` 里拆 |
| **2** | ⭐ **接进 `note_manager.evt_timbre_i`** | ⭐ 并把 `evt_timbre_valid_i` 接成真信号 |
| **3** | ⭐ **修 `timbre_id_i`** | ⭐ 应来自 `nm_timbre`，⛔ 不是恒 0 |

📌 **这一条【比扩位本身重要】** —— ⚠️ 不接的话，⭐ **扩到 3 位也没用**（⭐ 因为值恒 0）。

## 三、⭐⭐ 音色编号分配（⭐ 扩位后）

| `timbre` | ⭐ 音色 | ⭐ 波表 | ⭐ 备注 |
|---|---|---|---|
| **0** | ⭐ **`BASS`** | 三角波 | ⭐ 原计划 |
| **1** | ⭐ **`GUITAR-1`** | **锯齿波** | ⭐ **节奏吉他**（⭐ ADSR 短促、失谐 3 音分） |
| **2** | ⭐ **`GUITAR-2`** | **锯齿波（⭐ 同一张表！）** | ⭐ **主音吉他**（⭐ ADSR 长延音、失谐 12 音分） |
| **3** | ⭐ **`PIANO`** | 25% 脉冲波 | ⭐ 原计划 |
| **4** | ⭐ **`PAD`** | 多谐波叠加 | ⭐ 原计划（⭐ **⛔ 不删！**） |
| （5~7） | ⭐ 保留 | — | ⭐ 3 位还有 3 个空位 |

⚠️ **⚠️ 编号一旦定下【不能改】** —— 🔴 因为**曲谱文件（`events.hex`）是按编号打包的**
⇒ ⭐ 改了编号 ⇒ ⭐ **所有已生成的曲谱都错位**。

## 三之二、🔴 **`TIMBRE_W` 改动会波及【4 个 tb】**（⭐ 2026-09-24 中午补充）

> ⭐ **本节是"能不能直接落代码"的关键** —— ⚠️ **我核实后发现 tb 里有硬编码**。

### 3.2.1 ⭐ 受影响的 tb（⭐ 实测 grep）

| # | ⭐ 文件 | ⭐ 行 | ⚠️ 现状 | ✅ 改成 |
|---|---|---|---|---|
| **1** | `tb/w3b/tb_oscillator_bank.sv` | **:65** | 🔴 **硬编码** `.TIMBRE_N(4), .TIMBRE_W(2)` | ⭐ `(5)` / `(3)` |
| **2** | `tb/w3b/tb_note_manager.sv` | **:34** | 🔴 **自己定义** `localparam TIMBRE_W = 2;` | ⭐ `= 3` |
| **3** | `tb/w3b/tb_note_manager.sv` | **:83,85,93** | ⭐ 用 `TIMBRE_W` 算位宽（⭐ **会自动跟随**） | ✅ **⛔ 不用改**（⭐ 只要改 :34） |
| **4** | `tb/w3b/tb_w1_interfaces.sv` | **:50** | ⚠️ 传 `1'b0` 给 2 位端口（⭐ **现在就有位宽警告**） | ⭐ 改成 `3'b000` |
| **5** | `tb/w3c/tb_metronome.sv` | **:?** | 🔴 **3 处硬编码**（⭐ 实测）：<br>`.TIMBRE_W(2)` · `.default_timbre_i(2'd0)` · `.evt_timbre_i(2'd0)` | ⭐ `(3)` / `3'd0` / `3'd0` |

🔴 **⚠️ 关键：`tb_metronome` 是【传进 `note_manager` 的】** ——
⭐ 所以它的 `TIMBRE_W(2)` 必须与 `note_manager` 的新值**一致**，⛔ 否则**位宽不匹配**。


⚠️ **`tb_w1_interfaces.sv` 的位宽警告【现在就有】**（⭐ 回归日志里能看到）：
```
warning: Port 6 (timbre_id_i) of module oscillator_bank expects 2 bit(s), given 1.
```
⇒ ⭐ **扩位后会变成"expects 3, given 1"** ⇒ ⚠️ 建议**顺手修好**（⭐ 消除警告）。

### 3.2.2 ⭐⭐ **落地顺序（⭐ 避免中间态编译失败）**

```
⭐ 顺序很重要：⭐ 改【底层】再改【上层】，⭐ 否则中间态会位宽不匹配
   ① oscillator_bank.v  的 TIMBRE_N/TIMBRE_W
   ② note_manager.v     的 TIMBRE_W
   ③ top.v              的 3 处（含硬编码 *2）
   ④ 【4 个 tb】        的硬编码
   ⑤ tools/mid2evt.py   的掩码
   ⇒ ⭐ 则每步之后都能编译过（⭐ 或至少错在预期的地方）
```

⚠️ **⚠️ 特别注意**：⭐ **`TIMBRE_W` 是【端口宽度】** ⇒ ⚠️ 漏改一处
🔴 **`iverilog` 会报 "expects N bit(s), given M"**（⭐ **好**：⭐ 这次是**显式报错**）
📌 **但** ⚠️ 若只是**宽度不匹配但都不报错**（⭐ 如 `1'b0` 给多位）⇒ 🔴 **会静默补零**（⭐ 见上面第 5 条）

## 五、🔴 **⚠️ 一个必须提前决定的事：向后兼容**

🔴 **`events.hex` 里已生成的曲谱是【按 2 位 `timbre` 打包】的**：
```
⭐ 旧格式：`bit 8..7` = timbre（2 位），`bit 6..0` = 0（⭐ 保留）
⭐ 新格式：`bit 8..6` = timbre（3 位）
⇒ ⭐ **对旧曲谱**：⭐ `bit 6` 恒 0 ⇒ ⭐ **解出来还是原值** ⇒ ✅ **完全兼容！**
```

✅ **好消息**：⭐ **扩位是【向后兼容】的** —— ⚠️ 因为旧的 `bit 6` 本来就写 0。
⇒ ⭐ **⛔ 不用重新生成曲谱文件**。

## 六、⚠️ 需要注意的风险

| # | ⚠️ 风险 | ⭐ 对策 |
|---|---|---|
| **1** | 🔴 **ESP32 侧不同步** ⇒ ⭐ 静默错位（⚠️ 不报错） | ⭐ **先改 FPGA、验证、再通知 ESP32 同步**<br>⚠️ 中间状态：⭐ `bit 6` 恒 0 ⇒ ⭐ **其实无害**（⭐ 因为 FPGA 侧 `& 0x7` 对旧数据仍得原值） |
| **2** | ⚠️ **`TIMBRE_W` 改大 ⇒ 端口变宽** | ⚠️ 所有例化处**都要改**（⭐ 漏一处 ⇒ 🔴 位宽不匹配，⭐ 但**会报错**（⭐ 好）） |

| **4** | 🔴 **编号定错** | ⭐ **改完要重新生成曲谱**（⚠️ 或永远别改） |
