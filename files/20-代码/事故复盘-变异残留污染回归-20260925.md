## 三、⭐⭐ 三条教训

### ① 🔴 **先 commit，再跑变异测试**（⭐ 项目规则早就写了）

```
⭐ `AGENTS.md` 原文：⭐ 跑全量变异之前必须 commit
   —— ⚠️ 因为脚本**就地改可跟踪文件**
   ⇒ ⭐ 若中途被杀，🔴 **分不清"残留变异"和"我自己的改动"**
📌 ⭐ **本轮正是这个场景** —— ⭐ 而**能定位**恰恰是因为
   `git status` 能看出"哪个文件多改了"（⭐ 有 commit 做基准）
```

### ② 🔴 **别把"看脚本参数"当成"干跑"**

```
🔴 我以为 `-Filter M11` 只是"列出来"
⭐ 实际它**会真跑**（⭐ 每个变异体跑一遍全量回归）
⇒ ⚠️ 正确做法：⭐ **先读脚本源码确认有没有 dry-run/list 参数**
   （⭐ 本次读了之后确认：⛔ **没有** `-ListOnly`）
```

### ③ ⭐⭐ **"我刚好改过东西"会让残留污染伪装成自己的 bug**

```
⚠️ 时间线：⭐ 我刚改 `top.v`（DAC）⇒ ⭐ 紧接着回归报 FAIL
⇒ 🔴 **本能反应会是"我的 DAC 改坏了"**
✅ **正确做法**：⭐ **先 `git status`** —— ⭐ 看 FAIL 涉及的文件
   有没有**我没动过的改动**
📌 本次：⭐ FAIL 在 `tb_checkers`（⭐ 我根本没碰）
   ⇒ 🔴 **立刻就能排除自己**
```
