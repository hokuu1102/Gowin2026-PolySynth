## 一、🔴 `acc_r ≈ 2^31` —— ⭐ **假警报，已结案**

### ⭐ 现象（⭐ 旧探针报告）

⭐ 四组场景 `acc_r` 全部贴着 `2^31`（⭐ 误差 < 0.02%）⇒ ⚠️ 一度怀疑"位宽截断"。

### ⭐⭐ 真相：⭐ **探针的 `%0d` 打印 bug，⛔ 不是 RTL 问题**

| ⭐ 证据 | ⭐ 说明 |
|---|---|
| ⭐ **同组 `acc_r` 在两次实验中【逐位相同】** | ⚠️ 而 `gain` 从 16/13 变成 20/15/18 ⇒ 🔴 **真实的 40 位量不可能在 gain 变化时纹丝不动** |
| ⭐ 四组值**全部【低于】** `2^31 − 1` | ⚠️ 若是饱和/回绕 ⇒ ⭐ 必然**卡在** `2^31` 或**越过**它 |
| ⭐ 新实验实测 `acc_r` 真实值 | ⭐ **小得多**（⭐ 最大 ~1.37×10¹¹，⭐ 占 40 位空间 25%） |

⭐ **根因**：⭐ iverilog 对 **>32 位**的值用 `%0d` 打印时**截断成 32 位**，
⚠️ 且按**无符号**解释 ⇒ ⭐ **小的负数被折成接近 `2^31` 的大正数**。

```
⭐ 例：acc_r = −417256 ⇒ 2^31 区域 ⇒ 🔴 打印成 2147066392
```

📌 **同族隐患**：⭐ 旧探针的 `ab40()` 声明 `input signed [39:0]` 但**返回 `integer`（32 位）**
⇒ 🔴 **取绝对值也在 32 位里完成** ⇒ ⭐ 同一处 probe 里**两处独立的 32 位截断**。

✅ **结论**：⭐ `acc_r` 是 `reg signed [ACC_W-1:0]`，`ACC_W=40`，⛔ **无截断、无饱和逻辑**。
⭐ 评审怀疑的④（32 位中间表达式）**在本设计不成立**。

## 二、⭐⭐ `1/√N` 动态归一化 —— ⭐ **被实验否决**

### ⭐ 实验设计（⭐ `build/exp/exp_mixer_headroom.v`）

⭐ 直接例化生产 RTL `tdm_render_mixer`（⛔ 不改一行），⛔ 不接键盘/ADSR/`nm_gate`：
- ⭐ 固定 full-scale 正弦 · ⭐ `OSC_PER_VOICE=2` **同频同相**（⭐ 最坏相干情况）
- ⭐ N = 1/2/4/8/16/32

### 🔴 实测结果

| N | `n_active_o` | `gain` | `acc_r`/2²⁰ | mixer 原始输出 | 溢出计数 |
|---|---|---|---|---|---|
| 1 | 1 | 44 | 4095 | 5,766,992 (68.8%) | 0 |
| 2 | 2 | 31 | 8191 | 8,008,421 (95.5%) | 0 |
| **4** | 4 | 22 | 16383 | **8,388,608** | 🔴 **3800 (37.1%)** |
| 8 | 8 | 16 | 32766 | 8,388,608 | 🔴 6280 (61.3%) |
| 16 | 16 | 11 | 65533 | 8,388,608 | 🔴 7400 (72.3%) |
| 32 | 27 | 8 | 131066 | 8,388,608 | 🔴 8360 (81.6%) |

### ⭐⭐ 两条关键结论

**① `acc_r` 严格线性** —— 每 voice 恒定 `4096 × 2²⁰`，⛔ 无饱和、⛔ 无截断。

**② `1/√N` 数学上不够**：

```
峰值 ∝ N（⭐ 相干叠加）
gain ∝ 1/√N
⇒ 净效果 峰值 ∝ N/√N = √N  ⇒ 🔴 N 越大越容易削顶
```

⭐ **`gain` 从 44 降到 8（⭐ 降 5.5 倍），峰值却纹丝不动钉在满幅** ⇒ ⭐ **这就是"破音"的来源**。
⚠️ 且 **N=4 就已 37% 溢出** —— ⛔ **不是"极端复音才出问题"，是弹 4 个音就严重失真**。

## 三、⭐⭐ `OSC_PER_VOICE=2` 相干叠加 —— ⭐ **已修复**

### 🔴 两个 lane 完全相同（⭐ 代码依据）

```verilog
// oscillator_bank.v:130-133
wire [PHASE_W-1:0] lane_inc = base_phase_inc_i[VOICE_IDX*PHASE_W +: PHASE_W] + vib_off;
```

⭐ 两个 lane 拿**同一个** `base_phase_inc`，⭐ 且复位后 `phase_q` **同为 0**
⇒ 🔴 **永远同频同相** ⇒ ⭐ `lane0 + lane1 = 2 × lane0`。

⚠️ **注释声称"失谐叠加"** ⇒ 🔴 **"失谐"功能【根本没实现】** ——
⭐ 白白吃掉 2 倍幅度，⭐ 且**没有任何音色收益**。

### ⭐ 对照实验（⭐ `build/exp/exp_mixer_osc2.v`）

| N | A 相干 ×2（⭐ 修复前） | B `>>>1`（⭐ 修复后） |
|---|---|---|
| 1 | 5,766,992 | 2,883,408 |
| 2 | 8,008,421 ⚠️ | 4,062,984 |
| **4** | 🔴 **溢出 3800** | 5,766,772 ✅ |
| 8 | 🔴 溢出 6280 | 8,073,882 ⚠️ 96.2% |
| **16** | 🔴 溢出 7400 | 🔴 溢出 3800 |
| 32 | 🔴 溢出 8360 | 🔴 溢出 6280 |

⭐⭐ **精确对应**：⭐ B 组每个 N 的溢出次数 **恰好等于 A 组 N/4 的次数**
（⭐ 3800/6280 精确吻合）⇒ ⭐ **等价于白拿 12 dB headroom**。

### ⭐ 修复后的实测（⭐ `build/exp/hd_after.log`，⭐ N 扫描）

| N | ⭐ 修复前溢出 | ⭐⭐ **修复后溢出** |
|---|---|---|
| 1 | 0 | ✅ **0** |
| 2 | 0 | ✅ **0** |
| **4** | 🔴 **3800 (37.1%)** | ✅ **0** |
| 8 | 🔴 6280 (61.3%) | ✅ **0** |
| 16 | 🔴 7400 (72.3%) | ⚠️ 3800 (37.1%) |
| 32 | 🔴 8360 (81.6%) | ⚠️ 6280 (61.3%) |

⭐⭐ **`N ≤ 8` 现在【完全不溢出】**（⭐ 修复前 N=4 就爆）⇒ ⭐ **溢出点精确右移 4 倍**。
📌 `acc_r` 精确减半（⭐ 4095→2047 · 8191→4095 · …）⇒ ⭐ **确认 `>>>1` 生效且量级正确**。

### ⭐ 回归影响（⭐ `tb_tdm_render_mixer`）

⚠️ 该 tb 有 **3 条期望值**因 `>>>1` **精确减半**而失败（⭐ 132000→**66000**、
263912→**131912**、−264000→**−132000**）⇒ ⭐ **已按新语义更新**（⭐ 这不是回归，是**预期变更**）。

✅ **关键判据全部仍通过**：⭐ `max input SATURATES to signed24 MAX`（⛔ 不缠绕）·
⭐ `signed ok`（⭐ 负半周正确）· ⭐ `NORMALIZATION` 判据 · ⭐ `deadline_fault` sticky。

### ⭐ 修复落点（⭐ `rtl/w3b/tdm_render_mixer.v`）

```verilog
localparam integer NORM_SH = (OSC_PER_VOICE <= 1) ? 0 : 1;
always @(*) begin
    vs_sum = {SUM_W{1'b0}};
    for (oi = 0; oi < OSC_PER_VOICE; oi = oi + 1)
        vs_sum = vs_sum + $signed(osc_sample_bus_i[...]);
    vs_c = vs_sum >>> NORM_SH;      // ⭐ 取平均（⛔ 不是 /2 —— 见下）
end
```

| ⭐ 决策 | ⭐ 理由 |
|---|---|
| ⭐ 在 **mixer** 做而⛔ 不在 `oscillator_bank` | ⭐ 这里是 lane 求和的**唯一**位置；⚠️ `oscillator_bank` 是**队友文件**（⭐ 禁改清单） |
| ⭐ `>>>` 而⛔ 不是 `/2` | ⭐ 算术右移**保留符号**；🔴 `/` 向零取整 ⇒ ⚠️ 负半周与右移不等价 ⇒ **引入直流偏置** |
| ⭐ `NORM_SH` 算出来而⛔ 不写死 `1` | ⭐ `OSC_PER_VOICE==1` 时必须是 **0**（⭐ `K-91` 同族：位宽显式落定） |

## 四、⭐⭐ 力度：⭐ 两个**独立**问题（⭐ 必须分开看）

### ⚠️ 先纠正一处**误报**

⭐ 交接文档与评审都称"正常按键被 `vel_upd` 从 200 压到 64（−9.9 dB）"。
🔴 **该问题【已不存在】** —— `note_manager.v:429-433` **已修**（⭐ commit `c8b243f`）：

```verilog
if (vel_upd_value_i > vel_r[i])      // ⭐ 只允许调大
    vel_r[i] <= vel_upd_value_i;
```

⇒ ⭐ 起音 `velocity = 200`（0.784）**只会被调大、⛔ 不会被压低**。

### 🔴 真正的问题：⭐ `DT_MAX=10` 让力度表**覆盖不到真实按键速度**

| ⭐ 项 | ⭐ 值 |
|---|---|
| ⭐ **帧周期（实测）** | ⭐ **500 µs**（⚠️ ⛔ **不是** 196 µs —— ⭐ 同一笔误已在 `top.v` 的 `REFRACT_N` 旁更正，⭐ 见 `K-128`） |
| ⭐ 旧 `DT_MAX=10` | ⭐ **5 ms** ⇒ 🔴 **人手按键 10~50 ms ⇒ `Δt` 全部 `>= DT_MAX`** ⇒ ⭐ **力度恒为 `VEL_MIN`** |
| ⭐ 新 `DT_MAX=64` | ⭐ **32 ms** ⇒ ⭐ 落在人手按键时长的**中段** |

⚠️ **⇒ 旧参数下"力度响应"形同不存在**（⭐ 按快按慢同一个音量）。

### ⭐ 修复后的实测曲线（⭐ `build/exp/tb_dtmax_curve.sv`，⭐ DUT = 生产 RTL）

| `Δt`(帧) | `Δt`(ms) | `velocity` | 归一化 |
|---|---|---|---|
| 1 | 0.5 | 252 | 98.8% |
| 5 | 2.5 | 240 | 94.1% |
| 10 | 5.0 | 225 | 88.2% |
| 16 | 8.0 | 207 | 81.2% |
| 32 | 16.0 | 158 | 62.0% |
| 48 | 24.0 | 110 | 43.1% |
| **64** | **32.0** | **64** | **25.1%** |
| 100 | 50.0 | 64 | 25.1% |

✅ **判据 17/17 全过**：⭐ **单调不增**（⭐ 按得越快 ⇒ 越响）、⭐ `Δt>=64` 正确饱和到 `VEL_MIN`。
📌 **对照旧值**：⭐ 旧 `DT_MAX=10` ⇒ `Δt=10` 时**就已到底（64）**；
⭐ 新值下 `Δt=10` ⇒ **225（88.2%）** ⇒ ✅ **仍在渐变区**。

## 六、⚠️ 架构结论（⭐ 数据支撑）

```
                    ┌─ OSC0 ─┐
phase_inc ──────────┤        ├─ (+) ── >>>1 ── voice     ⭐ 已修复
                    └─ OSC1 ─┘
velocity ──> voice amplitude                            ⭐ 力度表已修正
    多个 voice ──> mixer
                    ↓
              固定 gain（⚠️ 待定值）
                    ↓
              安全 limiter（⚠️ 仅兜底）
                    ↓
                  DAC
```

⛔ **不再使用**：`N → 1/√N → gain`（⭐ 已由实验否决）。

### ⭐ 两条设计纪律（⭐ 来自本轮教训）

| ⭐ # | ⭐ 纪律 |
|---|---|
| **1** | ⭐ **limiter 是【安全网】，⛔ 不是正常的增益管理器** —— ⚠️ 若正常 8/16 音和弦天天撞 limiter ⇒ 🔴 **那是在做重度压缩**（⭐ 会"按第二个键、第一个音也被压"） |
| **2** | ⭐ **⛔ 不靠"改一个常量上板试"收敛** —— ⭐ 增益链有 5 个耦合参数 ⇒ 🔴 **组合爆炸**。⭐ **先用探针量清 N 与峰值，算清传递函数，再一次改全**（⭐ `L83` / `100 号`） |
