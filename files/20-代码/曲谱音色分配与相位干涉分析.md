> 1. ⭐ **曲谱里多把吉他音色怎么配**（⚠️ 用户实测听到"有一把像钢琴"）

## 一、⚠️ 先澄清："有一把像钢琴" 是怎么回事

### 1.1 🔴 这不是音色问题，是**试听工具的局限**

⭐ **`evt2wav.py` 是【试听工具】，⛔ 不是合成器**。它自己的注释（`:18-22`）写着：

> 「This is NOT the FPGA's sound. …here we use a simple sine/harmonic stack
> with a short envelope. The point is to check PITCH and TIMING, **not timbre**.」

⇒ ⭐ **它对【所有】音符用同一个音色** ⇒ ⚠️ **理论上所有声部应该听起来一样**。

**但用户听到"有一把像钢琴"** ⇒ ⭐ **说明差异来自【音域】，⛔ 不是音色**：

| 现象 | 真实原因 |
|---|---|
| ⭐ "像钢琴" | ⚠️ **音域偏高** —— 同一个正弦波，**音越高越"清脆"**，听着像钢琴 |
| ⚠️ "像贝斯" | 音域低 |

⭐ **结论**：⚠️ **这是试听工具的正常表现，⛔ 不代表 FPGA 里会这样** ——
但 ⭐⭐ **它暴露了一个真问题**：**FPGA 里现在也是"所有声部一个音色"**（见 §二）。

## 二、⭐⭐ 真问题：**所有声部共用一个音色**

### 2.1 现状：事件里**没有音色信息**

⭐ `mid2evt.py` 的 `pack_event` 打包的是：

```
tick(20) + inc(21) + axis(4) + vel(8) + kind(2) = 55 bit  （在 64 bit 内）
                                                        ↑
                                          🔴 没有 timbre 字段
```

⇒ ⭐ **FPGA 拿到 hex，只知道"弹什么音、多响、什么时候"，不知道"用什么音色"**。

### 2.2 ⭐⭐ 但接收端**早就准备好了**（⚠️ 关键发现）

⭐ **`note_manager` 已经实现了完整的"每音色"通路**（`rtl/w3b/note_manager.v`）：

```verilog
input  wire [TIMBRE_W-1:0]  default_timbre_i,      // 默认音色
input  wire                 evt_timbre_valid_i,    // ⭐ 事件带音色（注释写"Looper 每层覆盖"）
input  wire [TIMBRE_W-1:0]  evt_timbre_i,
...
wire [TIMBRE_W-1:0] new_timbre = evt_timbre_valid_i ? evt_timbre_i : default_timbre_i;
timbre_r[best_idx] <= new_timbre;      // ⭐ 起音时刻锁存（K-82 要求）
```

⇒ ⭐⭐ **接收端零改动** —— ⛔ **不用改 `note_manager`**！

### 2.3 🔴 但 `top.v` 把它**硬接死了**

```verilog
// rtl/top.v:325-327
.default_timbre_i  (2'd0),
.evt_timbre_valid_i(1'b0),    // 🔴 永远 0 ⇒ 永远走 default
.evt_timbre_i      (2'd0),    // 🔴 永远 0
```

⇒ ⭐ **所以现在全曲只有一个音色 `2'd0`**（= BASS）⇒ ⚠️ **吉他也在用贝斯音色**。

### 2.4 ⚠️ 还有一个前提：**波表数据还没补**

⭐ `K-82` + `W3接口冻结表` 都记着：

> `oscillator_bank` 的 `timbre_id_i` **"已接收但当前无效果"** ——
> 因为 **`wavetable_bank` 只有一块正弦 pROM**。

🔴 ⇒ **即使现在把 `timbre` 接通，声音也不会变** —— ⭐ **因为四种音色查的是同一张表**。

⇒ ⭐ **音色实装要等队友的 `T31b`（四音色波表）** ⇒ ⚠️ **按决定 4，改前要商量**。

## 三、⭐⭐ 方案 B：`timbre` 编进事件的保留 9 bit

### 3.1 位域分配（⭐ 记录仍是 64 bit）

| 位域 | 宽 | 字段 | 变化 |
|---|---|---|---|
| `[63:44]` | 20 | `tick` | ⛔ 不变 |
| `[43:23]` | 21 | `inc` | ⛔ 不变（`kind=2` 时存 `tick_inc`） |
| `[22:19]` | 4 | `axis` | ⛔ 不变 |
| `[18:11]` | 8 | `vel` | ⛔ 不变 |
| `[10:9]` | 2 | `kind` | ⛔ 不变（`0/1/2`） |
| ⭐ **`[8:7]`** | **2** | ⭐ **`timbre`** | ⭐ **新增**（4 种音色，`TIMBRE_N=4`） |
| **`[6:0]`** | 7 | 保留 | ⚠️ 仍留 7 bit 备用 |

> ⭐ **代价：0** —— ⭐ **64 bit 保留区有 9 bit，只用 2 bit** ⇒ ⛔ **不加宽记录、⛔ 不改帧长、⛔ 不改缓冲**。

### 3.2 ⭐⭐ 为什么选 B 而不是 A（`axis` 映射）

| 维度 | **A · `axis` 映射** | ⭐⭐ **B · 事件字段** |
|---|---|---|
| 占位宽 | ✅ 0 | ✅ **0**（9 bit 保留区够） |
| 改 `mid2evt.py` | ⛔ 不用 | ⚠️ 要 |
| **手弹/曲谱分开** | 🔴 **要额外加"来源"标志** | ⭐⭐ **天然分开** |
| ⭐ **换曲子要重综合吗** | 🔴 **要** | ⭐⭐ **不用** |
| **hex 自包含** | 🔴 否 | ⭐⭐ **是** |
| **与 Looper 兼容** | ⚠️ 要另设计 | ⭐⭐ **天然兼容**（`K-82`） |
| **接收端改动** | ✅ 无 | ✅ **无** |

⭐ **三条决定性理由**：
1. ⭐⭐ **换曲子不用重综合** —— ⚠️ A 把音色绑死在 RTL，实际使用中致命
2. ⭐⭐ **手弹/曲谱天然分开** —— 手弹走 `default_timbre_i`，曲谱走 `evt_timbre_i`
3. ⭐⭐ **`note_manager` 本来就是为 B 设计的**（端口注释写着"Looper 每层覆盖"）

### 3.3 ⭐ 音色分配表（⭐ 按"角色"合并，⛔ 不是按轨道）

⚠️ **实测三个谱子的实际轴位**：

| 曲目 | 用到的轴 | 轴数 |
|---|---|---|
| `09_Conjurer` | 0,1,2,3,4 | **5** |
| `夜洋风景` | 0,1,2,3,4,**5** | ⭐ **6** |
| `6.世界悲` | 0,1,2,3 | 4 |

`09_Conjurer` 轨名与⭐ **建议音色**：

| 轴 | 轨名 | ⭐ 音色 | 理由 |
|---|---|---|---|
| 0 | Duan GT OD | **GUITAR** | 节奏吉他 |
| 1 | Duan GT Delay | **GUITAR** | ⚠️ 只是效果不同，⭐ **音色本质相同 ⇒ 合并** |
| 2 | Biu GT OD | **GUITAR** | 另一把节奏吉他 ⇒ ⭐ **合并** |
| 3 | Biu GT Solo | ⭐ **SOLO**（可不同） | ⭐ **主音，单独给音色才有层次** |
| 4 | Electric Bass | **BASS** | ⭐ 低频，本来就分得开 |

⇒ ⭐⭐ **实际只需 3 种**：`GUITAR / SOLO / BASS` ⇒ ⭐ **`TIMBRE_N = 4` 够用**。

⭐ **对应 `README` 的既有定义**：

| `timbre_id` | 音色 | 波表 |
|---|---|---|
| 0 | **BASS** | 三角波 |
| 1 | **GUITAR** | 锯齿波 |
| 2 | **PIANO** | 25% 脉冲 |
| 3 | **PAD** | 多谐波 |

⇒ ⚠️ **注意**：⭐ **`SOLO` 不在现有 4 种里** ——
⭐ **建议**：⭐ **`SOLO` 先用 `PIANO`（25% 脉冲）的音色槽**（⭐ 脉冲波本身"亮"，适合主音），
⚠️ 或者**复用 `GUITAR` 但加增益/滤波区别**（⚠️ **更省，但要队友配合**）。

## 四、⭐⭐ 相位干涉：多把吉他同时放会冲突吗

### 4.1 ⚠️ 分两层看

| 层 | 会不会冲突 | 说明 |
|---|---|---|
| **① 通道层**（能不能同时发声） | ✅ **不会** | ⭐ 有 **32 voice**，4 把吉他同时弹**绰绰有余** |
| ⭐ **② 听感层**（分不分得清） | ⚠️ **这才是真问题** | ⭐ 见 §4.2 |

### 4.2 🔴 问题本质：**同音高 + 同音色 = 相位干涉**

⭐ 已有的 `K-95` 记录过：「**跨 axis 同音高**（380/558/1054 组）可能有**相位干涉**」。

```
axis 0 吉他 弹 A4   ┐
axis 2 吉他 弹 A4   ┘  同一时刻、同一音高、同一音色
        ⇒ 两个独立相位累加器各自算，相加后
        ⇒ 可能变响、可能变薄、可能"打拍"（听起来像弹了两次）
```

⚠️ **原因**：⭐ 两个相位累加器的**初始相位不同** ⇒ 相加时**部分抵消或部分增强**，
⭐ 而且**相位差会随时间漂移** ⇒ ⭐ 产生**拍频**（听起来"嗡嗡"或"像弹了两次"）。

### 4.3 ⭐ 已有缓解：**单轨内去重**（`mid2evt.py`）

⭐ `mid2evt.py:264-271` 已实现 —— ⚠️ **但只是【单轨内部】**：

```
seen = {}
for s, e, note in span:
    key = (s, note)          # 同 tick + 同音高
    if key in seen:
        stats["dedup"] += 1  # ⭐ 丢掉重复的
        continue
```

⭐ **实测效果**：`09_Conjurer` 去重 **90** 个、`6.世界悲` **141** 个、`夜洋风景` **91** 个。

🔴 **但跨轨的 `axis 0` vs `axis 2` 同音高【不会被去重】** ⇒ ⚠️ **干涉仍在**。

### 4.4 ⭐⭐ 三个对策（⚠️ 按代价排序）

| # | 对策 | 代价 | 评价 |
|---|---|---|---|
| ⭐⭐ **1** | ⭐ **按声部分音色**（§3.3） | ⭐ **零代价**（只是映射表） | ⭐⭐ **先做这个** |
| ⭐ **2** | **同音高微小失谐**（detune，几 cents） | ⚠️ 中等 —— 每 voice 要相位偏移 | ⚠️ **上板听过再定** |
| ⚠️ **3** | **跨轴去重**（同 tick 同音高只留一个） | ⚠️ **会丢声部** | ⚠️ 备份方案，⛔ 不首选 |

> ⭐⭐ **为什么"分音色"能缓解**：⚠️ **不同波形的同音高叠加，听感像"两件乐器齐奏"**，
> ⛔ **不像"同一个音重复弹"** ⇒ ⭐ **自然得多**。
> ⚠️ **但它【不能消除】相位干涉** —— ⭐ 只是**让干涉变得好听**。

### 4.5 ⚠️ 诚实说明：**当前根本不会干涉**

🔴 **因为现在四种音色查的是【同一张波表】**（§2.4）⇒
⭐ **所有声部就是同一个正弦波** ⇒ ⚠️ **干涉最严重的情况**。

⇒ ⭐ **换句话说**：⭐ **现在听起来"糊"，是预期的**；
⭐ **等波表补齐 + `timbre` 接通，才会变好**。
