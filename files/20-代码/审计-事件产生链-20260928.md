## 0. TL;DR（5 条最重要结论）

1. 🔴🔴 **`event_extract` 的 FIFO 水位 `q_cnt` 存在"同拍 +1/−1 后者覆盖前者"缺陷**（`event_extract.v:307` vs `:349`）。⇒ **相邻轴同帧越阈时后一个事件滞留 FIFO**，只在"下一次 push"时才吐出 ⇒ **note_off 被延迟到下一次按键/松键 ⇒ 听感=挂音，"再按一下就好"**（与 `files/20-代码/排查计划与疑问清单-20260928.md` §七 用户实测完全吻合）；同帧 ≥8 轴越阈时 **`q_wr` 追上 `q_rd` ⇒ 覆盖未读条目 ⇒ 事件永久静默丢失，且 `overflow_o`/`lost_cnt_o` 都不置位**（K-106「溢出可见」纪律被绕过）。
2. 🔴 **`key_on` 先清、`note_off` 后 push**（`:316` 在 `:317-326` 之前）：FIFO 满时 off 被丢，而 `key_on` 已清 0 ⇒ **该轴此后再也不会产生 off**（off 分支要求 `key_on==1`）⇒ **永久挂音**。
3. 🔴 **`enable_i===1'b0` 清 `key_on[]`/`refr[]` 但不发 note_off**（`:273-281`）。`enable_i = at_en_ready`（`top.v:1821`），而 `at_en_ready = at_done_dly[15]`，`at_done` 是 `calib_autotare` 的**电平**（`calib_autotare.v:96`）⇒ **只要发一次 UART `'T'`（`top.v:1185 retrig_i`）就令 `at_done→0` ⇒ 16 拍后 `enable_i=0` ⇒ 正在响的音全部永久挂音**。这是**可复现**的挂音入口。
4. ⚠️ `param_extract` 的「双阈值测速」**没有按设计实现**：`VEL_T1_EFF` 只出现在自检里（死参数），`t1_stamp` 记的是 **note_on 事件到达时刻**；且**同帧内既越 TRIG_TH 又越 VEL_T2_EFF（"重击"）时 `t1_seen==0` ⇒ 该次按键的 `vel_update` 永久不产生**——**最该给最大力度的那一下恰好测不到**。
5. ⚠️ 大量「预留/诊断」信号是**死路**：`event_extract.delta_i`(208bit) 未使用、`DELTA_TH` 未使用、`as_delta`/`as_seen` 悬空、`ee_ovf`/`ee_lost` **在 `top.v` 里没有任何消费者**（板上看不到溢出）、`play_mode_ctrl.pluck_up_i` **声明后完全未使用** ⇒ 上下拨弦方向信息被丢弃。

## 2. 状态机

### 2.1 `event_extract` 扫描 FSM（`:285-338`）

| 状态 | 进入 | 退出 | 输出 |
|---|---|---|---|
| `IDLE (scanning=0)` | 复位 / `enable_i===0`(`:280`) / 扫到轴15(`:331-333`) | `snap_valid_i` 且 `enable_i!==0` | 无 |
| `SCAN (scanning=1)` | `snap_valid_i`（`scan_axis<=0, scanning<=1`，`:291-292`） | `scan_axis==AXIS_N-1` ⇒ `scanning<=0` | 每拍处理 1 轴：可能 push 1 条 on/off |
| `DISABLED (enable_i===0)` | `enable_i===1'b0`（`:273`） | `enable_i!==0` | ⭐ 每拍清 `key_on[ai]`/`refr[ai]`，`scanning<=0`（**不发事件**） |

⚠️ 结构是 `if (enable) begin if (snap_valid) … else if (scanning) … end`：**`enable_i===0` 优先于 `snap_valid_i`**，且 `scan_axis` 在 enable 分支**不复位**（只 `scanning<=0`，`:280`）。

### 2.2 `event_extract` 每轴迟滞 FSM（隐式，`:296-328`）

| 状态 | 进入条件 | 退出条件 | 输出 |
|---|---|---|---|
| `RELEASED (key_on=0)` | 复位 / `enable=0` / `pos<REL_TH` | `pos>=TRIG_TH` **且 `refr==0`** | push `kind=0`(on)；`key_on<=1`；`refr<=60` |
| `HELD (key_on=1)` | 上一行 | `pos<REL_TH`（**不检查 refr**） | push `kind=1`(off)；`key_on<=0` |
| `BLOCKED (refr>0)` | 越阈时 `refr!=0` | `refr` 每帧 −1 到 0（`:229-231`） | ⭐ **什么都不做**（无 else 分支，`:298`） |

### 2.3 `param_extract` 双 FSM

扫描 FSM（`:261-295`）：`IDLE →(snap_valid)→ SCAN(16拍) → IDLE`。每轴比较 `pos >= VEL_T2_EFF`，用 `was_above_t2` 做迟滞，`!was_above_t2 && t1_seen` 时算 `dt` 并置 `dt_valid`（`:269-286`）。

出队 FSM（`:301-326`）：

| 状态 | 进入 | 退出 | 输出 |
|---|---|---|---|
| `emitting=0` | 复位 / 发完一拍 | 任一 `dt_valid[i]`（优先级编码 0→15） | 锁 `emit_axis`，`emitting<=1` |
| `emitting=1` | 上一行 | **无条件**（下一拍必退） | `vel_valid_o<=1` + `vel_axis_o`/`vel_value_o` 同拍；`dt_valid[emit_axis]<=0` |

⚠️ 优先级编码用 `{(SAW-4){1'b0}}` 零宽/负宽复制（`:312-318`），**`AXIS_N<=8`（SAW<4）时 `(SAW-4)` 为负 ⇒ 非法复制 ⇒ 模块编译失败**（参数化失效）。

### 2.4 `play_mode_ctrl`（隐式 FSM，`:51-84`）

| 状态 | 进入 | 退出 | 输出 |
|---|---|---|---|
| 键盘模式（`!fretboard_mode_i`） | 模式=0 | 模式=1 | `axis_valid_i` **直通**为 `evt_*`（`:53-58`） |
| 指板·选择（`selected_valid`） | `axis_kind_i==0`（`:69-72`） | 同轴 `axis_kind_i==1`（`:74-75`） | **不发事件**（只锁 `selected_axis/depth`） |
| 指板·拨弦门（`gate_valid`） | `pluck_valid_i && selected_valid`（`:59-67`） | 同轴 `KIND_OFF`（`:76-82`） | 发 `KIND_PLUCK`；置 `gate_valid`/`gate_axis` |
| 指板·门释放 | 同轴 OFF 且 `gate_valid` | — | 发 `KIND_OFF`；`gate_valid<=0` |

⚠️ 模式切换**不清理** `selected_*`/`gate_*`；`axis_kind_i` 非 0/1 时**无 else ⇒ 静默忽略**。

### 2.5 `async_pluck_capture`（无 FSM，`:44-50`）

`refractory_q!=0` ⇒ 只递减；否则 `up_rise||down_rise` ⇒ 发 1 拍 `pluck_valid_o`，`pluck_up_o<=up_rise`（UP 优先），`refractory_q<=1_500_000`。⚠️ **不应期内的边沿被丢弃且不锁存**（`up_prev`/`down_prev` 无条件更新，`:40-41`）。

### 2.6 `axis_snapshot.first_ch_of_frame`（`:127-130`）

| 状态 | 进入 | 退出 | 输出 |
|---|---|---|---|
| 0 | 复位 / 收到 `ch0` | `frame_done_i` | — |
| 1 | `frame_done_i` | `sample_valid_i && ch==0` | 该拍执行 `prev<=cur`（`:148-151`） |

⭐ 这是**正确的固化时机**（新帧第一个样本时 `cur` 仍是上一帧完整值）——这一处设计是对的（前两版错误的推理保留在 `:135-146`）。

## 3. ⭐ 事件产生逻辑

### 3.1 `event_extract` 逐轴完整判据（每帧每轴访问 1 次）

```verilog
// 每帧：refr 先各减 1 (:229-231)
// snap_valid 下一拍起，scan_axis = 0..15，每拍 1 轴 (:293-336)
if (!key_on[a]) begin                       // :296
    if (pos[a] >= TRIG_TH)                  // :297  (192)
        if (refr[a] == 0) begin             // :298  ⚠️ 无 else
            key_on[a] <= 1; refr[a] <= 60;  // :299-300
            push(kind=0, depth=pos[a]);     // :302-311 满则 overflow
        end
end else begin                              // :314  key_on==1
    if (pos[a] < REL_TH) begin              // :315  (80)
        key_on[a] <= 0;                     // :316  ⚠️ 先清
        push(kind=1, depth=pos[a]);         // :317-326 满则丢（不可重试）
    end
end
```

- **发 `note_on`**：`key_on==0` **且** `pos>=192` **且** `refr==0`（三条件同时满足才 push，且 `key_on`/`refr` 与 push 在**同一分支内原子置位**）。
- **发 `note_off`**：`key_on==1` **且** `pos<80`（**不受 `refr` 约束** ⇒ 「事后封锁」语义正确）。
- **迟滞带 [80,192)**：保持原状态、无事件（`tb_event_extract.sv:232` 守这条）。

### 3.2 🔴 `key_on[]` 与物理按键的同步性

**Q1：`key_on[a]=1` 但物理键已松 ⇒ 永远不发 note_off 的情况**

| # | 机理 | 位置 | 性质 |
|---|---|---|---|
| (a) | 松手后 `pos` 仍 **≥ REL_TH(80)**：`zero` 漂移/未有效 tare/松手残留偏置 ⇒ `key_on` 永不清 0 | `:315` + `top.v:1636-1646` | **标定域**（非 RTL 逻辑错），但与"挂音无规律、哪个键都有"吻合 |
| (b) | **`enable_i` 掉 0 清 `key_on` 但不发 off** ⇒ `key_on` 变 0、voice 仍 held ⇒ 挂音 | `:273-281` | 🔴 **RTL 缺陷**（见 Q4） |
| (c) | **`note_off` 被 FIFO 满丢弃**，而 `key_on` 已清 0 ⇒ off 分支此后再不进入 ⇒ **永不重试** | `:316` 先于 `:317-326` | 🔴 **RTL 缺陷（最严重）** |
| (d) | `q_cnt` 失步（见 §5-A1）⇒ off 滞留 FIFO，**只在下次 push 时吐出**；若是本次演奏最后一条 ⇒ **永久滞留** | `:307` vs `:349` | 🔴 **RTL 缺陷** |
| (e) | 下游 `evt_merge`/`seq_arb`/`note_manager.FIFO` 丢事件（K-106 已记录，本次未展开） | 不在 5 文件内 | 已知 |

**Q2：`key_on[a]=0` 但物理键还按着**

| # | 机理 | 位置 | 后果 |
|---|---|---|---|
| (a) | **`refr` 挡住 `note_on`**（不应期内按下）⇒ `key_on` 保持 0 | `:298`（无 else） | 若在 `refr` 过期前松手 ⇒ **整次按键被吞（无 on 无 off）**；若一直按着 ⇒ `refr` 过期后**下一帧扫描会补发 on**（每帧重判），**不是永久失步**，但最多延迟 30ms ⇒ **快速连击（>33Hz）被吞** |
| (b) | `enable_i=0` 期间（上电/重标定） | `:273-281` | **设计意图**（`top.v:1800-1820`），恢复后下一帧补发 on ✅ |
| (c) | 按下+松开**都落在同一帧内（<500µs）** | ADC 采样量子 | 完全不可见（采样定理限制，非 RTL 错） |

**Q3：`refr` 挡住 `note_on` 时 `key_on` 会不会被置位？**

⭐ **不会。** `key_on[a]<=1`（`:299`）、`refr[a]<=REFRACT_N`（`:300`）、push（`:302-311`）**全在 `if (refr[a]==16'd0)` 同一分支内**（`:298`）⇒ **三者原子，不可能"置了 key_on 却没发事件"或反之**。✅ 这一点是**正确的设计**，必须明确肯定。

⇒ 这一步的**真正后果**只有两个：
1. `refr>0` 时按下 ⇒ **该帧完全被忽略**（无 else，`:298`）；因为 `refr` 只在 `snap_valid_i` 递减（`:229`）而扫描每帧都重访该轴，**只要键一直按着，`refr` 到期后的下一帧就会补发 note_on** ⇒ 是"延迟"而非"丢失"；
2. **但在 `refr` 窗口内完成「按下+松开」⇒ 彻底吞掉**（`REFRACT_N=60`=30ms 的直接代价；K-128 把 150 改 60 已缓解，未消除）。

**Q4：`enable_i` 什么时候会变 0？**（⭐ 关键）

```
top.v:1821        .enable_i (at_en_ready)
top.v:1133-1140   AT_EN_DELAY=16; at_done_dly <= {at_done_dly[14:0], at_done};
                  wire at_en_ready = at_done_dly[15];   // 要求 at_done 连续 16 拍为 1
calib_autotare.v:96        assign done_o = (state == ST_DONE);   // ⭐ 电平，不是脉冲
calib_autotare.v:154-159   ST_DONE: if (retrig_i) state <= ST_SWEEP;
top.v:1185        .retrig_i (cmd_tare_req & ~sp_busy)   // UART 'T' 命令
```

⇒ `enable_i` 变 0 的**三种**情形：
1. **上电后 ~200ms（`AUTOTARE_DELAY_CLK`）内**：`state=ST_WAIT` ⇒ `at_done=0` ⇒ 设计意图（锁事件层，防脏 `pos` 全判按下）；
2. 🔴 **发一次 UART `'T'`（重标定）**：`ST_DONE→ST_SWEEP` ⇒ `at_done=0` ⇒ 16 拍后 `enable_i=0` ⇒ **`key_on[]`/`refr[]` 全清且不发 note_off** ⇒ **正在响的音全部永久挂音**（⭐ **可复现的挂音入口**；`top.v:1813` 注释只承认"会清 key_on"，**未提示不发 note_off**）；
3. `at_done` 若被任何原因拉低（复位、未来新增重入点）同理。

⚠️ 另注：`calib_span`（UART `'S'`）**不改** `at_done`，但它改变 `pos` 码值空间而 `key_on[]` 是**活跃**的 ⇒ 可能瞬间产生假 on/off（`top.v:1963-1964` 要求先 span，但**没有互锁**）。

### 3.3 `param_extract` 的 `vel_update` / `pitch_update`

- **`vel_update` 何时发**：扫描到某轴 `pos >= VEL_T2_EFF(595)`，且 `!was_above_t2 && t1_seen` ⇒ 算 `dt = frame_cnt - t1_stamp`（防下溢钳 0，`:275-278`）⇒ `dt_valid<=1` ⇒ 出队 FSM 在**下一拍**发 `vel_valid_o`（`:319-326`）。
- **会不会反复发**：`was_above_t2` 是**唯一的迟滞**（`:283-286`）：只要 `pos` 在 595 附近**抖动**（掉下再上来）就会**反复发**。⭐ `top.v:2327-2328` 已自认这条（"现在 pos 在 VEL_T2_EFF 附近抖动 ⇒ 反复发 vel_upd"）——⚠️ 参数扫描里**没有任何额外迟滞/去抖**，只有 1 bit。当前 `vel_upd_valid_i` 被**硬接 `1'b0`** 做诊断（`top.v:2329`）⇒ 该缺陷目前被屏蔽，**通路未删**。
- **`t1_stamp` 何时记**：`evt_valid_i && evt_kind_i != 1`（`:251-255`）⇒ 即**收到 note_on 事件的那一拍**，⭐ **不是「越过浅阈 VEL_T1_EFF 的那一拍」**。
  - 🔴 **后果 1**：`VEL_T1_EFF(372)`/`VEL_T1`/`VEL_T1_PCT` 是**死参数**（只在 `:361,366` 自检里出现）⇒ 实际测的是「**事件时刻(≈TRIG_TH=192 越阈) → 595**」，而注释声称测 `t1(372)→t2(595)`（`:15-24`）⇒ **Δt 系统性偏大 ⇒ 力度偏小**（文档/语义不一致）。
  - 🔴 **后果 2（新发现）**：`t1_seen` 由**事件到达**置位（`:254`），而事件经 FIFO 出队要 **2~17 拍**（见 §4）；`param_extract` 自己的扫描在**同一拍序**下比较 t2。⇒ **若同一帧内既越 192 又越 595（"重击"），`t2` 比较发生在 `t1_seen` 置位之前 ⇒ 条件为假 ⇒ 本次 `vel_update` 永久不产生**（`was_above_t2` 仍被置 1，`t1_seen` 随后才置 1，但不会再有新的 t2 越阈直到松手重按）。**"最该给 VEL_MAX 的那一下"恰好测不到。**
- **`pitch_update`**：`pitch_valid_o` 恒 0、`pitch_value_o` 恒 0（`:239,344`）⇒ 本版**完全不发**（阶段 2 TODO，`:328-339`）；`PITCH_DELTA_TH` 死参数。

## 5. 🔴 可疑点

### 5.A 高严重度（会导致挂音 / 静默丢事件）

#### A1. `q_cnt` 同拍 +1/−1 被覆盖 ⇒ 水位少计 ⇒ 事件滞留 / 覆盖 / 溢出指示失效

| 项 | 内容 |
|---|---|
| **位置** | `event_extract.v:307`（`q_cnt <= q_cnt + 1'b1;`）与 `:349`（`q_cnt <= q_cnt - 1'b1;`），**同一 `always` 块，drain 在后** |
| **问题** | Verilog 语义：同一 always 内对同一 reg 的多次非阻塞赋值**最后一条生效**。同拍既 push 又 pop 时真实占用不变，但 `q_cnt` **净减 1** ⇒ `q_cnt` **永久性少计**（误差只增不减） |
| **为什么可疑** | ① 与模块自称的"同帧多轴一个都不丢"（`:141-159`）直接冲突；② 溢出判定 `q_cnt < FIFO_D`（`:302,317`）用的是**少计后的值** ⇒ 溢出门限失效；③ `q_axis/q_kind/q_depth` **不复位**（`:203-209` 只复位 `q_cnt/q_wr/q_rd`），少计后 `q_rd` 可能指向未写位置 ⇒ 仿真出 `x` |
| **后果** | **相邻轴（i, i+1）同帧越阈** ⇒ 后一条滞留 FIFO，**只在"下一次 push"时才吐出** ⇒ `note_off` 被推迟到下一次按键/松键 ⇒ **听感=挂音，"再按一下就好"**（⭐ 与 `排查计划与疑问清单-20260928.md` §七 用户实测吻合）；若滞留的是**本次演奏最后一条事件** ⇒ **永久不发 ⇒ 永久挂音**。**同帧 ≥8 轴越阈** ⇒ `q_wr` 追上 `q_rd` ⇒ **覆盖未读条目 ⇒ 永久静默丢失，且 `overflow_o`/`lost_cnt_o` 都不置位** |
| **验证方法** | ① **改 tb（不改 RTL）**：把 `tb/w3a/tb_event_extract.sv:281-283` 的 `set_axis(1/5/9)` 换成**相邻轴 `set_axis(1)/set_axis(2)`** ⇒ 预测**只吐 1 条 note_on**（现 tb 因轴距=4 恰好避开，**是假守护**）；换成 `0,1,2,3` ⇒ 预测**只吐 2 条**；② 波形看 `u_event_extract.q_cnt/q_wr/q_rd` 与真实占用是否一致；③ 加"burst 结束后**不再发快照**，检查最后一条 off 是否发出"的判据 |

逐拍证据（轴1、轴2 同帧越阈，初态 `q_cnt=q_wr=q_rd=0`）：

| 拍 | scan_axis | 扫描分支 | 出队分支（用旧 `q_cnt`） | 拍末 q_cnt | q_wr | q_rd | 真实占用 |
|---|---|---|---|---|---|---|---|
| C0 | — | snap：`scan_axis<=0,scanning<=1` | `q_cnt=0` ⇒ 无 | 0 | 0 | 0 | 0 |
| C1 | 0 | 不越阈 | 无 | 0 | 0 | 0 | 0 |
| C2 | 1 | 越阈 ⇒ push idx0，`q_cnt<=1` | `q_cnt(旧)=0` ⇒ 无 | 1 | 1 | 0 | 1 |
| C3 | 2 | 越阈 ⇒ push idx1，`q_cnt<=2` | `q_cnt(旧)=1` ⇒ 吐 idx0，`q_rd<=1`，**`q_cnt<=0`** | **0** | 2 | 1 | **1** ❌ |
| C4…C16 | 3…15 | 不越阈 | `q_cnt=0` ⇒ 无 | 0 | 2 | 1 | 1（**滞留**） |

#### A2. `note_off` 不可重试：`key_on` 先清、push 可能被丢

| 项 | 内容 |
|---|---|
| **位置** | `event_extract.v:316`（`key_on[scan_axis] <= 1'b0;`）**先于** `:317-326`（push，满则只置 overflow） |

## 6. 建议的只读验证清单（不改 RTL，全部可先做）

1. **⭐ 最高优先：证实 A1** —— 把 `tb/w3a/tb_event_extract.sv:281-283` 的三轴（1,5,9）改成**相邻轴（1,2）**跑一次：预测 **只吐 1 条 note_on**（现 tb 因轴距=4 恰好避开 ⇒ **假守护**）。再试 `0,1,2,3` ⇒ 预测**只吐 2 条**。5 分钟即可定性。
2. **A1 的"最后一条"变体** —— burst 后**停止发快照**，断言最后一条 `note_off` 是否发出（预测：**不发**）⇒ 直接对应"挂音"。
3. **A2** —— 4 轴同帧越阈灌满 FIFO + 5 轴同帧释放，断言 `on 条数 == off 条数`，并看 `note_manager.voice_gate_o` 残留。
4. **A3** —— e2e tb："按下一个音 → 发 `cmd_tare_req`（或直接拉低 `at_en_ready`）→ 松手 → 连发多帧快照"，断言 `voice_gate_o` 是否仍非 0（预测：**仍非 0 ⇒ 挂音**）。⚠️ 这条同时能解释用户"等几分钟仍在"的现象。
5. **板上观测补充** —— `event_extract.key_on[]` **未引出为端口**（`top.v:2816` 的 `key_active_i` 还是 `16'd0` 占位）⇒ 现在**无法从外部确认失步**；建议把 `key_on` 引出（16 bit）或复用 `'N'` 探针的通道字段输出 `key_on` 快照。这是 A2/A3 上板定位的**必要前置**。
6. `ee_ovf`/`ee_lost` 接进 UART 状态回包（现在板上完全看不到溢出）。

### 结论一句话

`event_extract` 的**判据本身（迟滞 + 事后不应期 + on/off 原子置位）是正确的**，但**事件发布路径（小 FIFO 的水位管理 + off 不可重试 + enable 清零不发 off）有三处会直接造成"挂音/静默丢事件"的缺陷**；其中 **A1（`q_cnt` 同拍 +1/−1 覆盖）** 与用户实测的"挂音、再按一下就好"高度吻合，且现有 tb **恰好避开**了触发条件（假守护）。**建议第一件事就是把 tb 的轴号改成相邻轴复跑。**
