## 原说法 → 更正 → 原因

| 原说法 / 行为 | 更正 | 代码与复现依据 |
|---|---|---|
| Q 切波形时 `scope_run_r <= ~scope_mode_r` 能继续采样 | 删除采样冻结寄存器，两种模式都接收 `mm_valid` | 两个寄存器同沿取旧值，更新后 run 等于新 mode；切到 mode=0 就停止写历史。真实 UART Q 已复现 |
| 仅 CH0 连续 16 帧为 000/FFF 就能判定 ADC 死片 | 改为完整 CH0..CH7 扫描全部同一端点才累计；默认跳过最初 200 ms 完整扫描 | 三片真实 SPI 模型正常应答，第一片 CH0=0、其余通道正常，旧代码仍在约 7.525 ms 锁存 fault=001 |
| 切换模式可直接暂停 XY 状态机 | 模式请求经像素域两级同步，垂直消隐起点提交；已开始任务继续执行完毕，新任务只在消隐起点启动 | 原先暂停 FSM 不会取消显存写使能，返回 XY 可在活动显示期恢复绘图，占用显存读口 |
| XY 首帧无需等待就绪 | 只有 `xy_ready` 后才显示轨迹 | 避免未清屏 / 未绘制完成的 RAM 内容成为有效轨迹 |

没有改动 50 MHz 系统时钟、音频分频、声音合成数据通路或 SPI 引脚。保留当前工程既有的 HDMI 专用 PLL；本次没有增加 PLL。新模式请求的下降沿发射寄存器在 `constr/top.sdc` 保留显式 10 ns 半周期预算，不用 false-path 掩盖它。

## 限制与仍未修复的问题

- ADC 告警是数据端点异常嫌疑，不是 SPI 协议确认失败。八路真的全接地 / 全满量程与 MISO 卡死无法仅靠数值区分；也不能保证检测到非端点形式的通信错误。默认告警时间变为启动窗口之后约 8 ms，不影响控制或采样延迟。
- 快闪总源还包括 Mixer 与事件 / TX FIFO 溢出。约 8 ms 的现象吻合旧 ADC 判据，但目前没有实板分源读数，不能声称已证明实际板上唯一根因。
- UART 屏帧载荷仍可能误触发裸命令；曲谱 A5 帧仍有接收门控问题。本次没有改共享串口协议，屏幕数字 0x51 不等同于合法裸 Q 回归。
- XY 仍直接读取实时环形历史，未增加稳定快照；本次保证模式切换和 FSM 收尾，不承诺每帧全窗口数据一致。
- 默认 `TEST_MODE_EN=0`、状态 / 指引灯占位、FX 未接实际效果器等此前发现的功能缺口不在本次修复范围内。
