## 〇之一、⭐⭐⭐ **一个可复用的判据：改了代码后，老变异体要不要重跑？**

> ⭐ **2026-09-24 中午实测得出** —— ⭐ **这个判据让"只跑新的"变成安全操作**。

### ⭐ 问题

```
⭐ 我改了 rtl/top.v（⭐ 修组合环）
⇒ ⚠️ 那些【之前验证过】的老变异体，⭐ 结论还有效吗？
   ⭐ 若有效 ⇒ ✅ 只需跑【新的】
   🔴 若失效 ⇒ ⚠️ 必须重跑【全部】
```

### ✅ 判据：⭐ **逐个检查【锚点是否还在源码里】**

```powershell
# ⭐ 一条命令核实全部变异体的锚点（⭐ 可复制）
$src = Get-Content bringup/mutation_test.ps1 -Raw
$m = [regex]::Match($src, '(?s)\$mutations\s*=\s*@\((.*?)\r?\n\)')
$entries = $m.Groups[1].Value -split "`n"
$cache = @{}; $ok=0; $bad=@()
foreach ($e in $entries) {
  if ($e -match 'id = "(M\d+)"; file = "([^"]*)"; find = "((?:[^"\\]|\\.)*)"') {
    $id=$matches[1]; $file=$matches[2]; $find=$matches[3]
    if (-not $cache.ContainsKey($file)) {
      $cache[$file] = [System.IO.File]::ReadAllText((Join-Path (Get-Location) $file))
    }
    if ($cache[$file].Contains($find)) { $ok++ } else { $bad += "$id ($file)" }
  }
}
"✅ 有效: $ok"; "🔴 失配: $($bad.Count)"; $bad
```

### ⭐⭐ 判据与动作

| ⭐ 结果 | ⭐ 含义 | ⭐ 动作 |
|---|---|---|
| ✅ **全部锚点有效** | ⭐ **老变异体测的还是同一段代码** ⇒ ⭐ **结论依然成立** | ⭐ **只跑新的**（⭐ 省大量时间） |
| 🔴 **有锚点失配** | ⚠️ 那段代码**改过了** ⇒ ⭐ 该变异体**失去了保护** | 🔴 **必须修锚点 + 重跑那些** |

| # | ⭐ 情况 | ⭐ 判别 |
|---|---|---|

| **2** | ⚠️ **锚点含非 ASCII** ⇒ ⭐ **GBK 解码问题**（⭐ `K-125`） | ⭐ **查锚点的非 ASCII 字节数** |

⭐ 项目 2026-09-23 深夜新增了 4 个模块（`calib_span` / `calib_cmd` / `uart_tx` / `calib_autotare` 的重触发部分），

⇒ 🔴 **所以 `mutation_test.ps1` 里对它们仍然是 0 覆盖**。

📌 **教训（⭐ 值得记）**：⭐ **"我临时验过了" ≠ "回归会一直验它"** ——
⚠️ 临时靶点**不写进 catalogue 就等于没验**（⭐ 下次别人改动它，没有任何保护）。

## 一、⭐ 选靶点的原则（⭐ 照项目既有做法）

| # | 原则 | ⭐ 为什么 |
|---|---|---|
| **1** | ⭐ **选"会坏、但难发现"的** | ⚠️ 一眼能看出的错误**不值得**做变异体（⭐ 浪费 109 s/个） |
| **2** | ⭐ **锚点必须是【唯一子串】** | 🔴 否则 `find` 匹配到多处 ⇒ ⚠️ 脚本会报错或改错地方 |
| **3** | ⭐ **`find`/`repl` 长度尽量相等** | ⚠️ 便于人工核对 diff |
| **4** | ⭐ **每个变异体都要有"为什么它会坏"** | ⭐ `why` 字段是给**未来的人**看的 |
| **5** | 🔴 **锚点 ⛔ 不能落在注释里** | ⚠️ `M62` 踩过：锚点撞注释 ⇒ **永久失配**（`K-120`） |

## 二、⭐⭐ `calib_span.v`（⭐ 6 个靶点 —— 最重要，本轮缺陷都在这）

⭐ **这个模块的价值**：⭐ 它有 **3 个"静默卡死"路径** + **两个对齐要求**
⇒ ⭐ **每一处都值得一个变异体**。

### M98 ⭐⭐ `span` 与通道【错一拍】（⭐ 最关键）

```powershell
@{ id = "M98"; file = "rtl\w3a\calib_span.v";
   find = "else if (sample_valid_i && (sample_ch_i == cur_axis[2:0]) && !cal_busy_i) begin";
   repl = "else if (sample_valid_i && (sample_ch_i == cur_axis[2:0] + 3'd1) && !cal_busy_i) begin";
   why  = "span fires on the WRONG channel: calib consumes raw (the current-cycle value) => the gain is computed from another channel's code. Silent: no error, calib.err may not even fire. tb_calib_span must catch it via the align judgement." },
```

⚠️ **注意**：⭐ 这个 `find` 字符串在文件里**只出现 1 次**（⭐ 另一个相似行在 `S_SETTLE`/`S_VOTE`，但那两行**没有 `&& !cal_busy_i`**）⇒ ✅ **唯一**。

### M99 ⭐⭐ 稳定性判定失效（⭐ 手抖也认）

```powershell
@{ id = "M99"; file = "rtl\w3a\calib_span.v";
   find = "if (stable_cnt >= STABLE_NEED[5:0])";
   repl = "if (1'b1)";
   why  = "stability gate removed: the FSM votes on a moving key => the recorded full-scale point is garbage whenever the operator is still pressing. tb_calib_span's jitter case must catch it." },
```

### M100 ⭐⭐ 投票离散度检查失效（⭐ 本模块的核心价值）

```powershell
@{ id = "M100"; file = "rtl\w3a\calib_span.v";
   find = "if ((vmax - vmin) > VOTE_TOL) begin";
   repl = "if (1'b0) begin";
   why  = "sampling spread check removed => a wildly moving reading is accepted as the full-scale point (this is exactly what multi-frame voting exists to prevent). tb_calib_span's spread case must catch it." },
```

### M101 ⭐⭐ `calib.err` 检测失效（⭐ 防静默失败）

```powershell
@{ id = "M101"; file = "rtl\w3a\calib_span.v";
   find = "if (cal_err_i && span_sent_r) begin";
   repl = "if (1'b0 && span_sent_r) begin";
   why  = "calib.err ignored: a rejected calibration (key not pressed far enough) is silently treated as success, so the axis keeps its old gain. K-87 family. tb_calib_span's real-calib.err case must catch it (it is intentionally checked BEFORE the timeout)." },
```

### M102 ⭐ `abort_i` 失效（⭐ 取消命令）

```powershell
@{ id = "M102"; file = "rtl\w3a\calib_span.v";
   find = "if (abort_i) begin";
   repl = "if (1'b0) begin";
   why  = "'X' cancel stops working: the FSM can no longer leave a stuck state => only a board reset recovers. tb_calib_span's abort judgements must catch it." },
```

### M103 ⭐⭐ `S_SETTLE` 超时失效（⭐ 静默卡死回归）

```powershell
@{ id = "M103"; file = "rtl\w3a\calib_span.v";
   find = "if (stable_cnt >= STABLE_NEED[5:0])";   # ⚠️ 已被 M99 占用
   ...
```

🔴 **冲突** —— ⚠️ `M103` 的锚点与 `M99` 相同。⭐ **改用"删超时"这条**：

```powershell
@{ id = "M103"; file = "rtl\w3a\calib_span.v";
   find = "wire       sp_start_gated";   # ⛔ 不在本文件
```

🔴 **再修正** —— ⭐ 超时那条的准确锚点是 `wait_clk_cnt >= WAIT_TIMEOUT_CLK[WCW-1:0]`
⚠️ 但它在文件里出现 **4 次**（`S_SETTLE`/`S_VOTE`/`S_WAITBUSY`/`S_NEXT`）⇒ 🔴 **不唯一**。

⭐ **解法**：⭐ **用带上下文的更长锚点**：

```powershell
@{ id = "M103"; file = "rtl\w3a\calib_span.v";
   find = "if (wait_clk_cnt >= WAIT_TIMEOUT_CLK[WCW-1:0]) begin`n                        reject_o   <= 1'b1;`n                        reject_cnt <= reject_cnt + 4'd1;`n                        if (reject_cnt >= REJECT_MAX[3:0]) begin`n                            state  <= S_DONE;`n                            done_o <= 1'b0;              // ⚠️ 未成功`n                        end else begin`n                            state  <= S_PROMPT;          // ⭐ 重来`n                        end`n                    end`n                    else if (sample_valid_i && (sample_ch_i == cur_axis[2:0])) begin";
   repl = "if (1'b0) begin`n                    end`n                    else if (sample_valid_i && (sample_ch_i == cur_axis[2:0])) begin";
   why  = "S_SETTLE loses its timeout: if adc_farm stops scanning (SPI dead / cable loose) the FSM hangs forever with busy_o high and no output -- the exact 'silent hang' defect fixed on 2026-09-23. tb_calib_span's no-samples case must catch it." },
```

⚠️ **多行锚点的注意**：⭐ 脚本用**字面字符串替换**，
⇒ ⚠️ **必须与源码的缩进/行尾完全一致**（⭐ 本仓库是 **LF**，⛔ 不是 CRLF）
⇒ ⭐ **建议**：⭐ 落脚本时**用 `edit` 工具**从源码里复制粘贴，⛔ 别手打。

## 三、⭐⭐ `calib_cmd.v`（⭐ 4 个靶点）

### M104 ⭐⭐⭐ 帧边界跟踪失效（⭐ 本模块的**核心安全**）

```powershell
@{ id = "M104"; file = "rtl\w3a\calib_cmd.v";
   find = "if (idx_q == 4'd0) begin";
   repl = "if (1'b1) begin";
   why  = "frame-boundary tracking removed: in-frame payload letters are treated as commands => a song dump containing 0x53/0x54/0x58 would trigger calibration mid-playback. Catastrophic and silent. tb_calib_cmd's payload case must catch it." },
```

### M105 ⭐⭐ 帧内忽略的记账失效

```powershell
@{ id = "M105"; file = "rtl\w3a\calib_cmd.v";
   find = "in_frame_cnt_o <= sat_inc16(in_frame_cnt_o);";
   repl = "in_frame_cnt_o <= in_frame_cnt_o;";
   why  = "the 'ignored in-frame letter' counter stops counting => the evidence that boundary tracking DOES anything disappears. K-106 (nothing may fail silently). tb_calib_cmd checks this count." },
```

### M106 ⭐ 空闲归位失效

```powershell
@{ id = "M106"; file = "rtl\w3a\calib_cmd.v";
   find = "end else if (idle_expired && (idx_q != 4'd0)) begin";
   repl = "end else if (1'b0 && (idx_q != 4'd0)) begin";
   why  = "idle resync removed: if the PC dies half-way through a frame, the parser stays 'in frame' forever and ALL later commands are swallowed as payload. tb_calib_cmd's half-frame case must catch it." },
```

### M107 ⭐ 帧头不再推进索引

```powershell
@{ id = "M107"; file = "rtl\w3a\calib_cmd.v";
   find = "idx_q <= 4'd1;";
   repl = "idx_q <= 4'd0;";
   why  = "the 0xA5 header no longer advances the frame position => subsequent payload bytes are never counted, so the frame boundary is lost and payload letters can be mistaken for commands. tb_calib_cmd's payload case must catch it." },
```

## 四、⭐⭐ `uart_tx.v`（⭐ 4 个靶点）

### M108 ⭐⭐⭐ 位序反了（MSB 先发）

```powershell
@{ id = "M108"; file = "rtl\w3c\uart_tx.v";
   find = "tx_o      <= shifter_q[0];   // ⭐ LSB 先发";
   repl = "tx_o      <= shifter_q[7];   // MUTANT: MSB first";
   why  = "bit order inverted: 0x01 arrives as 0x80 -- every byte is wrong yet the frame structure is perfect, so only a loopback byte-compare catches it. tb_uart_tx's LSB-first judgement must catch it." },
```

### M109 ⭐⭐ 数据不锁存（发送中被打断）

```powershell
@{ id = "M109"; file = "rtl\w3c\uart_tx.v";
   find = "shifter_q  <= tx_data_i;";
   repl = "shifter_q  <= shifter_q;";
   why  = "the data latch is removed: the byte is taken from the live input instead of the latched copy, so changing tx_data_i mid-transmission corrupts the byte. tb_uart_tx's mid-transmission case must catch it." },
```

### M110 ⭐⭐ 停止位失效（⭐ 就是原版那个真缺陷）

```powershell
@{ id = "M110"; file = "rtl\w3c\uart_tx.v";
   find = "tx_o      <= 1'b1;           // ⭐ 停止位（高）";
   repl = "tx_o      <= shifter_q[7];   // MUTANT: re-sends D7 (the original bug)";
   why  = "regression for the ORIGINAL bug found on 2026-09-24: D7 is sent twice, making an 11-bit frame, so the receiver sees a low line after 8 data bits and treats it as the next start bit => a phantom frame (one send produced TWO rx_done). tb_uart_tx must catch it." },
```

### M111 ⭐ 空闲电平反了

```powershell
@{ id = "M111"; file = "rtl\w3c\uart_tx.v";
   find = "tx_o       <= 1'b1;         // ⭐ **空闲高**（⭐ 串口空闲态）";
   repl = "tx_o       <= 1'b0;         // MUTANT: idle low";
   why  = "reset drives the line LOW instead of the UART idle HIGH: the peer sees a permanent start-bit condition. tb_uart_tx's idle-level judgement must catch it." },
```

## 七、⚠️ 已知风险（⭐ 落地时注意）

| # | 风险 | ⚠️ 对策 |
|---|---|---|
| **1** | 🔴 **多行锚点容易因缩进/行尾失配** | ⭐ **用 `edit` 从源码复制**，⛔ 别手打；⭐ 落完**立刻跑一次**看是否 `anchor not found` |
| **2** | ⚠️ **`M99` 与 `M103` 曾撞锚点** | ⭐ 已改（`M99` 用 `stable_cnt`，`M103` 用带上下文的超时块） |
| **3** | ⚠️ **`M98` 的 `find` 含 `&& !cal_busy_i`** | ⭐ 那是**唯一化**的关键 —— ⛔ 别删掉它 |
| **4** | 🔴 **锚点落到注释上 ⇒ 永久失配**（`K-120`） | ⭐ **`M108`/`M110`/`M111` 的 `find` 都带了行尾注释** ⇒ ⚠️ **落脚本时把注释去掉**（⭐ 只留代码部分） |

⚠️ **针对风险 4 的修正**（⭐ 落地时用这几个）：

```powershell
# M108（去掉注释）
find = "tx_o      <= shifter_q[0];"
# M110（去掉注释）
find = "tx_o      <= 1'b1;           // ⭐ 停止位（高）"   →  ⚠️ 这行注释是源码的一部分，⭐ 保留反而更唯一
# M111（去掉注释）—— ⚠️ 但 "tx_o       <= 1'b1;" 在文件里可能多处
```

📌 **结论**：⭐ **注释能不能留在锚点里，取决于"它是否让锚点更唯一"**。
⭐ **判据**：⭐ **只要 `find` 在文件里唯一，就行**（⭐ 注释在不在都无所谓）——
⚠️ **`K-120` 讲的是"锚点【完全】落在注释里"**（⭐ 那才会因注释改动而失配）。
