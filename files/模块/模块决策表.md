## 二、每个模块的文件里有什么

每个 `决策表/Mx_*.md` 都包含三部分：

| 部分 | 内容 |
|---|---|
| **一、决策表** | 统一列结构：`# | 决策项 | 备选 | 关键判据 | 倾向 | 状态` |
| **二、本模块关键点** | 该模块的**坑与提醒**（已从各方案文档汇总过来） |
| **三、待确认** | 需要队友/外部确认的问题 |

> ⭐ **`M1_左手区.md` 内容最厚** —— 除决策表外还有六节分析：
> 轴数怎么定 / 钢琴式 vs 指板式 / **指板式能否像钢琴一样演奏** / 双排方案对比 /
> **上下对齐双排网格 + 双模式映射** / 键帽形式。

## 三、阻塞关系

```text
M1（传感器 / 轴数 / 排列）─┐
M4（通道数与 ADC）─────────┼──→  M10（PCB 开工）──→  冻结
M5（器件资源与算法）───────┤
M9（供电与预算）───────────┘
M7（灯数 / 驱动 / 层级）──→ 影响 M9 电流预算 与 M10 布局

🟢 M3 / M8 可最后定（接口已按最宽预留，不阻塞）
```

## 四、建议拍板顺序（6 轮）

| 轮次 | 内容 | 原因 |
|---|---|---|
| **第 1 轮** | **M1-1 / M1-3 / M1-4 / M1-5**（传感器、轴数、排列、排数） | **最大未决项**，决定演奏体验与走线规模 |
| **第 2 轮** | **M5-1 / M5-2 / M5-4**（器件资源与算法） | 决定能否实现，**需与 FPGA 侧一起定** |
| **第 3 轮** | M4-2 / M4-3（ADC 方案与通道数） | 跟随第 1 轮 |
| **第 4 轮** | M9-*（供电与预算） | 需要前几轮的电流需求 |
| **第 5 轮** | M7-2 / M7-3 / M7-4（LED 驱动、灯数、层级） | 依赖 M9 的电流余量 |
| **第 6 轮** | M2 / M3 / M6-5 / M8-2（收尾，可并行） | 相对独立 |
| **最后** | M10-*（PCB 与机械） | **前面定完才开工** |
