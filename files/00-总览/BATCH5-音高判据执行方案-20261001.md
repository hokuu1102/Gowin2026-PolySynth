### B. 端到端音高判据 —— 新增一个 tb（⛔ 不动 RTL）

⭐ **探针点（本轮已确认）**：
```
rtl/w3b/note_manager.v:1231   assign voice_phase_inc_o[g*PHASE_W +: PHASE_W] = phase_r[g];
rtl/w3b/note_manager.v:155    output wire [POLY_TARGET*PHASE_W-1:0] voice_phase_inc_o,  // → oscillator_bank
```
⇒ ⭐ **每个 voice 的相位增量就存在 `phase_r[g]`**，且**直接接给 `oscillator_bank`**
⇒ ⭐ **判据可写成**：`u_note_manager.phase_r[被分配的 voice] == u_axis_map.kb_inc[k]`

⭐ **手法先例（本项目已有，⛔ 不用发明）**：
```
tb/top/tb_am_pipe.sv:181   : u_axis_map.kb_inc[am_axis_out];     ← 层次引用直读表
```
⭐ **判据草案（每条都要能红）**：

| ⭐ | 判据 | ⭐ 怎么变红 |
|---|---|---|
| B1 | ⭐ 键 `k` 按下 ⇒ 该 voice 的 `phase_inc` **精确等于** `kb_inc[k]` | 把 `kb_inc[k]` 改错 / 在链路上插一个错值 ⇒ 红 |
| B2 | ⭐ **不同键 ⇒ 不同音高**（至少取样 4 个键，⛔ 避开 E#/B# 重复对） | 把索引改回"深度选音" ⇒ 红（⭐ 这正是 2026-09-27 上板的真缺陷） |
| B3 | ⭐ 键 `k` ⇒ 音高**与按多深无关** | 重新打开插值 / 让 `pos` 进索引 ⇒ 红 |
| B4 | ⭐ **键 → voice 的映射唯一**（同一键的重按不串到别的音高） | 把 `phase_r` 的写地址打错一拍 ⇒ 红 |

⚠️ **已知约束（⛔ 别踩）**：`top.v:2595-2607` 与 `:2913-2919` 明写
"⭐ `event_extract` 一帧可能报**多个事件**，而 `axis_map` **只有一个入口**" ⇒
⭐ **判据必须【单键单事件】**，⛔ 不要一帧多键（⚠️ 那是已知限制，不是本批要修的）。
