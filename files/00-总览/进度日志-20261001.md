## 六、⭐⭐ 三个重要发现（⭐ 都改变了判断）

### ⭐ ① `.sdc` 的**量纲错误** —— ⭐ 它一直在压制 `Fmax`

⭐ `set_output_delay -clock clk_sys -max 10.0`（⭐ 加在 `HP_BCK`/`HP_WS`/`HP_DIN` 上）
⭐ 注释的推理是"BCK 半周期 160 ns ⇒ 给 10 ns ⇒ 远小于 160 ns ⇒ 不会误报" ⚠️
🔴 **但 `-max D` 的真实含义是"外部器件要在 `clk_sys` 沿前 D ns 拿到数据"**
⇒ ⭐ **留给 FPGA 的 = 20 − D = 10 ns** ⚠️ ⇒ ⭐ **D 越大越紧**，⭐ 与注释直觉**正好相反** ✅
⇒ ⭐ 而且 BCK 的 320 ns 周期与"相对 `clk_sys` 的约束"**不是同一参考系** ✅
✅ 修法：⭐ `-max 10.0 → 2.0`（⭐ 内部预算 18 ns ⇒ ⭐ **检查没丢**，⛔ 不是 `false_path`）
⭐⭐ **效果：⭐ `Fmax` 从 ~52 涨到 58+** ⇒ ⭐ **之前"±3 MHz 波动"很大一部分是这条约束在放大噪声** ✅

### ⭐ ② `adc_farm` 的**片间不对称** —— ⭐ 它让 `'P'` 在板上**读不到片 1**

⭐ 片 0 走**寄存器**（保持 ✅）· ⭐ 片 1..N-1 走影子 `miso_shift`，⭐ 而它**每次 `cs_fall` 清零** ⚠️
⇒ 🔴 片 1 的数据只在 ~1 µs 内有效（⭐ 占空比 ≈ 0.2% ⚠️）⇒ ⭐ `'P'` 在任意时刻读**必得 0** ✅
✅ 修法：⭐ 加 `shadow_hold`（⭐ 与 `miso_shift` 同拍同式移位，⭐ **只是不清零**）
📌 **为什么不动实时通路**：⭐ 在 `sample_valid` 那一拍两份影子**内容相同**（⭐ 反串行器早于 `done` 数拍收满 ✅）
📌 代价：⭐ `(N_ADC-1)×24` 个触发器 ⇒ ⭐ `N_ADC=2` 时 **24 个** ✅

## The six findings that changed my judgement

1. top.sdc set_output_delay -max 10.0 was dimensionally wrong. -max D means the EXTERNAL
   device needs D ns before the clk_sys edge, so a LARGER D is TIGHTER -- the opposite of
   the comment. BCK 320 ns period has no bearing on a clk_sys-relative constraint.
   Fixing it raised Fmax from about 52 to 58 MHz, so much of the 3 MHz "placement noise"
   was this constraint amplifying placement differences.
2. adc_farm is asymmetric: chip 0 reads a holding register, chips 1..N-1 read a shadow
   cleared every cs_fall (~0.2% duty). So the P probe read zero. Fixed with a second
   shadow that shifts identically but never clears.
3. The synthesis gate caught a generate-block scope error (EX3872) that the testbenches
   did not -- the concrete case for the rule that RTL changes go through it.
4. The implicit-definition warning: Gowin tolerates it, so the synthesis gate alone
   cannot prove it fixed. iverilog is the tool that reports it. Check both.
5. Two tooling traps: the edit tool strips the BOM (breaking any non-ASCII .ps1 because
   PowerShell 5.1 then decodes it as GBK), and testbench mirrors of top.v constants must
   be synced while keeping the judgement teeth.
6. T3 has no cheap automatic criterion. git cherry over-reports (a reimplemented feature
   shows as absent) and diff-size is meaningless because main is 73 commits ahead so the
   diff shows main's new code as deletions. It is a manual review task.
