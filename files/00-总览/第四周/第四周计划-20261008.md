## 〇、一句话现状

三条主线都到了**可交付**状态（发声/自动功能/控制面 + HDMI 出图 + LED 映射层），
但**右手板的推子现在验不了** —— `RIGHT_ADC_ENABLE=1` 这个配置**从来没有通过过时序**（46.613 MHz / 1630 违例），
所以下周第一件事是**把右手板联调档的时序做达标**，否则右手板（推子/摇杆/音量）整条线都动不了。

## 二、已经实现的功能

### 2.1 发声核心（甲）
- **32 voice 复音**（`note_manager`：分配/抢占/释放/参数更新 + 事件队列 + 防挂音）
- **每 voice 2 个失谐 lane**（`oscillator_bank`，共 64 个相位累加器；失谐加权 `1.125 : 0.875` ⇒ 拍谷 −18.1 dB；每 voice 1/4 周期初相去相关）
- **4 音色波表**（`wavetable_bank`：BASS 三角 / GUITAR 锯齿 / PIANO 25% 方波 / PAD）
- **ADSR 共享引擎**（`envelope_bank`：32 路 → 1 引擎 + 32 拍轮转；−5403 LUT · DSP 38→7）
- **力度**：位置式跟随（每 tick 扫一轴，抬起冻结，松手自然衰减）
- **混音/输出**：软膝限幅器 + 复音归一化 → `tdm_render_mixer` → `i2s_tx`（**板载 + 外置 DAC 两路并存**）

### 2.2 输入与标定（甲）
- 左手 **2 片 MCP3208**（16 轴霍尔键 + 推子；锁步并行采样、每片 MISO 独立）
- 标定链：`calib`（raw 中值）· `calib_span`（归一化到 4095）· `calib_autotare`（上电自动零点，含"静止才捕获"守卫）
- 串口命令：`T`/`S`/`X`（标定）· `P`/`N`/`Q`（诊断）
- `axis_map`：轴 → 音高表（**指板 / 键盘**两种模式，按物理位置实测锚定）

### 2.3 自动功能（甲）
- **节拍器**（`metronome` + `beat_gen`，PPQN=960）
- **鼓机**（`drum_gen`：Kick/Snare/HiHat/Clap + 16 步音序器，**4 个节奏型现场可切**）
- **曲谱播放**（`evt_uart_rx` → `evt_merge` → `play_seq`：UART 灌谱 + 变速）

### 2.4 控制与表现（甲）

## 四、本周期最大的阻塞：右手板时序（专项）

### 4.1 事实（已归档）

| 项 | 值 |
|---|---|
| 配置 | `RIGHT_ADC_ENABLE = 1`（`rtl/top.v:292`，编译期参数） |
| setup 违例 | **1630** |
| `clk_sys` | **46.613 MHz**（⚠️ 低于物理 50 MHz ⇒ 烧上去行为不可靠） |
| Logic / Register / CLS | 36068 / 17085 / **24128（81%）** |
| 结论 | 这个配置**从来没通过过时序**（旧文档只写"要联调就改 1 后重跑"，暗示当时并未验证） |

### 4.2 为什么必须解决

- ⚠️ **推子验不了**：右手板的推子/摇杆/音量都要经第 3 片 ADC 进来 ⇒ 时序不过 = 这条线完全动不了。
- ⚠️ **串口也绕不过去**：`RIGHT_ADC_ENABLE=0` 时 `ADC_N=2` ⇒ **片 2 根本不扫描** ⇒ 任何串口命令都读不出右手板的数据。

### 4.3 下周动作（按顺序）

1. **先定位 1630 条违例集中在哪**（读 `rpt` 的违例表，按端点聚类）——
   队友的假设是「`adc_farm` 片 2 的 SPI 采样 → 颤音控制 → 相位增量」这条新链，或「片 2 的 CS/SCLK 输出路径」。
   ⭐ **先出结论再动手**（本周音频那条线的教训：先定位根因）。
2. **再决定修法**（三选一或组合）：
   - 给那条链**加流水**；
   - 把**片 2 的扫描降速**（分频/轮转，右手控制量带宽需求低）；
   - 把**颤音控制改成寄存器化输入**（打断组合路径）。
3. **顺手把运行时开关做掉**（`ADC_N` 恒 3 + 运行时使能 + 串口命令，默认关）——
   这样"只有左手板"的机器与"接了右手板"的机器**共用一个码流**。
4. **达标后必须**：过 51.5 门槛 + `0/0` + **双配置都跑全量回归**（`RIGHT_ADC_ENABLE=0` 与 `=1`）。

### 4.4 我们这条线能帮上的（⛔ 但要等用户点头，因为"不动时序"是本周约束）

| 手段 | 能省 | 风险 |
|---|---|---|
| `pos_probe` ×3 例化合并 | ~200–400 LUT | 低（要复验 `'P'`/`'N'`/`'Q'` 包时序） |
| `calib` ×2 合并（共用除法器 + 读 mux） | ~350–500 LUT + 1 DSP | 中（要改 `calib_span` 的 busy/err 握手） |
| `ep_mem` 去掉冗余字段 | ~3 块 BSRAM（7→4） | 低 |
| `oscillator_bank` 的 `sample_bus_r` 写译码 + TDM 读 mux 合并 | ~400 LUT | 中 |
| `perc_env_bank` 复用共享包络引擎 | 待测 | 中 |

⚠️ **注意**：这些是**降资源**手段；而 46.6 MHz 更像**长路径**问题（`CLS 81%` 说明也偏挤）
⇒ ⭐ **先做 4.3 第 1 步（定位违例集中在哪），再决定是"降资源"还是"加流水"**。

### 4.5 ⭐⭐ 结果（2026-10-08 当晚完成 —— 结论是「加流水」，⛔ 不是「降资源」）

| 项 | 修前 | ⭐ **修后** |
|---|---|---|
| `clk_sys` Setup **TNS** | −2718.329 ns | ✅ **0.000** |
| Setup **违例端点** | **1630** | ✅ **0** |
| 推算 `clk_sys` | 46.613 MHz | ⭐ **≈55.16 MHz**（过 51.5 门槛） |
| 最差路径 | `u_vibrato_lfo/phase_q_17 → gen_lane[*]`，−3.272 ns | `g_t3.rot_cnt → g_t3.phase_tr[31]`，**+0.051 ns** |
| 位流 | — | ✅ 18,853 KB · sha256 `679C76B0…` |

**根因**：⭐ 25 条最差路径 **100% 是同一条** —— 颤音 LFO 输出 → **48 位常量乘法** → 移位
→ 32 位加法 → **扇出 64 个 lane 相位累加器**，纯组合链 **21.4 ns**（约束 18.181）✅

**修法**：⭐ 在这条链上**切两级流水**（`vibrato_mod_r` ＋ `vib_mul_r`，`rtl/w3b/oscillator_bank.v`）
⇒ 代价 **64 个 FF**、颤音延迟 2 拍（40 ns，⭐ 听感不可闻）✅
⚠️ **参考副本 `tb/models/oscillator_bank_ref.v` 必须同步加同一条流水** ——
⛔ 否则 `tb_p5_osc_equiv` 的"逐位等价"会**假红**（⭐ 它验的是 P5-② 的等价性）✅

**证据**：`sim/evidence/rightboard-vibrato-fix-20261008/README.md`（含两配置对照 + 探针产物）
**探针**：`build/rightadc-probe/`（⭐ 隔离副本，只改 `RIGHT_ADC_ENABLE=1`，⛔ 不碰交付树）

⚠️ **两个新风险**（⭐ 记入监控）：
1. 新最差路径只剩 **+0.051 ns**（`g_t3.rot_cnt → g_t3.phase_tr[31]`，⭐ T3 影子数组的**写侧**）
   ⇒ ⚠️ **任何再往这条路上加逻辑的改动都可能把它打红** ——
   ⭐ `A3` 的**第一版**就是因为它被回退的；✅ **第二版（已实施）不碰写侧**（只是"读" `phase_r`）✅
2. =1 档 `CLS 81%`（=0 档 78%）· 多占 **3 个 DSP**（`T_MULTALU27X18` 7 → 10）✅
