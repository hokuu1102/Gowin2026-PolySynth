### 🔴 音频输出：**必须外接 I2S DAC**（⛔ 不能用板载 `J5`）

> ⚠️ **用户的贝斯音箱是【有源】的**（自带功放，接 `Line In`）
> ⇒ 🔴 **`J5` 是已放大的 BTL 输出 ⇒ 直连会烧音箱**（⚠️ BTL 任一端不能接地）。

⭐ **正解**：⭐ **从 `PMOD1` 引 I2S → 外接 I2S DAC → 贝斯音箱 `Line In`**

| 项 | 值 |
|---|---|
| **引脚（已预留）** | `PMOD1_IO3`=`F20`（BCLK）· `PMOD1_IO4`=`E22`（LRCK）· `PMOD1_IO5`=`D22`（DIN） |
| ⭐ **推荐 DAC 模块** | ⭐ **`PCM5102A`**（~15–30 元）或 **`UDA1334A`**（~20–40 元） |
| ⚠️ **选型注意** | ⭐ **必须买【带板载晶振】的版本** —— ⚠️ 我们 **`i2s_tx` 没有 `MCLK` 输出**（已核实） |
| ⭐ **要改的参数** | ⭐ **`i2s_tx` 的 `JUSTIFY` 1 → 0**（标准 I2S） |

> ⭐ **可以同时驱动两路**（`BCK/WS/DIN` 复制到两组引脚）⇒
> ⭐ **板载喇叭（调试当场出声）+ 外接 DAC（接贝斯音箱）并存**，⛔ 逻辑不用改两遍。

### 5.3 ⚠️ `uart_rx` 的自检升级（`U-2`）

⚠️ **现状**：`BAUD_DIV < 4` 只 `$display` 报错，⛔ **不阻止综合、也不让仿真失败**。

🔴 **实测的坑**：`BAUD_DIV=1` ⇒ `START_MID = (1>>1) - 1 = -1` ⇒ ⭐ **16 位回绕成 65535**
⇒ ⭐ **起始位中点检查永远不成立** ⇒ ⚠️ **毛刺保护静默失效**。

⭐ **修法**：`$display` → **`$fatal`**（或至少加一条 tb 判据）。

> 🔴 **⚠️ 本条的重要性已【上升】（2026-09-23）**：
> ⭐ 原文写"实际影响低（我们只用 `BAUD_DIV=434`）"—— ⚠️ **该前提已变**：
> 🔴 **波特率现在【参数化】了**（默认 **1 Mbps = `BAUD_DIV=50`**，⭐ 见 `U-29`）。
> ⇒ ⭐ **"切档"变成一件常做的事** ⇒ ⚠️ **填错档位不再有"反正只用 434"兜底**，
> ⭐ 而会**静默收不到数据**（⚠️ 综合不报错、仿真只打 ERROR）。
> ⇒ ⭐⭐ **建议优先级：低 → 中**（⭐ 切档越频繁，这个自检越值钱）。
> 📌 相关：`U-29` 的波特率参数化已落地（`BAUD_DIV=50` / `BAUD=1000000`）。

### 10.2 🔴🔴 三个真缺陷（⭐ 全部是"静默卡死"）

> ⭐ **共同根因**：⭐ **状态机的每个"等待"都没有上界** ——
> ⚠️ 一旦被等的事件永不到来，就**永久停在那个状态、`busy_o` 恒 1、无任何输出**。

| # | 缺陷 | 触发条件 | 🔴 后果 |
|---|---|---|---|
| **①** | `S_SETTLE` **无超时** | ⭐ `adc_farm` 停扫（SPI 挂 / 排线松 / 片没接）⇒ `sample_valid_i` 永不来；⚠️ 或操作者**中途松手走开** ⇒ 读数一直变 | 🔴 永久卡在 `S_SETTLE`（⭐ **探针实测**：`state=2`、`busy=1`、无输出） |
| **②** | `S_VOTE` **无超时** | ⭐ 已进入投票后**帧突然停了** | 🔴 永久卡在投票（⭐ 收不满 `VOTE_N`） |
| **③** | `S_NEXT` 等 `busy` 升起，🔴 **但 `calib.err` 路径永不拉 `busy`** | ⭐ 轴没按到底 ⇒ `raw <= zero` ⇒ `calib` 走 `err` 分支 | 🔴 永久卡在 `S_NEXT`（⭐ **探针实测**：`span_seen=0`、`done` 恒 0） |

#### ⭐⭐ 缺陷③ 的证据链（⭐ 值得单独记，因为最隐蔽）

```verilog
// calib.v:96-108 —— 🔴 err 与 busy 在【互斥的两个分支】上
if (!busy && span) begin
    if (raw <= zero_r[cal_ch]) begin
        err <= 1'b1;                    // 🔴 只置 err
        gain_r[cal_ch] <= (1 << 8);
    end else begin
        busy <= 1'b1;                   // ⭐ 只有这里才 busy
        ...
    end
end
```

⭐ **直连真 `calib` 的探针实测**（⭐ 发一次 `span` 且 `raw=0`）：

```
cycle right after span: err=0 busy=0
k=0 err=1 busy=0
k=1 err=1 busy=0        ← ⭐ err 恒高、⭐ busy 自始至终为 0
...
```

⇒ ⭐⭐ **结论：`err` 与 `busy` 在本设计中【物理上互斥】**
⇒ ⭐ 因此 `S_NEXT` 里"`busy` 为高 **且** `err` 为高"的分支是
🔴 **永不可达的死代码**（⭐ 变异测试佐证：删掉它**没有任何 tb 变红**）⇒ ⭐ **已删除**。

#### ⭐ 修法（⭐ 三条出口，⛔ 不留静默路径）

| 出口 | 条件 | 动作 |
|---|---|---|
| **①** | `cal_err_i && span_sent_r` | ⭐ **拒绝 + 重试**（⭐ "没按到底"） |
| **②** | `cal_busy_i` | ✅ 本轴成功 ⇒ 下一轴 |
| **③** | `wait_clk_cnt >= WAIT_TIMEOUT_CLK` | ⭐ **拒绝 + 重试**（⭐ 兜底） |

⭐ 新增 `WAIT_TIMEOUT_CLK` 参数（⭐ 默认 **1 秒** @50 MHz）
+ ⭐ `span_sent_r` 标志（⭐ 用于区分"还没开始"与"直接 `err` 了"）
+ ⭐ `S_SETTLE`/`S_VOTE`/`S_WAITBUSY`/`S_NEXT` **四处全部加超时**。

### 10.4 ⭐⭐ `calib_cmd` 的**核心安全**：帧内字母 ⛔ 不当命令

（⭐ 例如 `vel=0x54`，或 `tick` 的某个字节）
⇒ 🔴 **若不跟踪帧边界 ⇒ 曲谱灌入时会被误当成标定命令**（⭐ 灾难性）。

⭐ **做法**：⭐ `calib_cmd` **自带极简的帧同步计数**（⭐ 与 `evt_uart_rx` 同一套语义）：
见 `0xA5` ⇒ 进帧、数 8 拍；⭐ **帧内的命令字母 ⛔ 一律忽略**（⭐ 但**记账**）。
⚠️ 另加**空闲归位**（⭐ 自愈：⭐ PC 崩在半帧中间不会永久卡死）。

⭐ **tb 判据**：⭐ 构造**载荷里塞满 `T`/`S`/`X`（甚至再塞 `0xA5`）的合法事件帧**
⇒ ⭐ 必须**一个命令都不产生**（⭐ 24 条判据里的核心几条）。
