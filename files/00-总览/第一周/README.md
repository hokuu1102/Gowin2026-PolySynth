## 一、⭐ 基础题 / 提高题的划分（本周只碰基础题）

| | 赛题要求 | 我们的目标 | 本周 |
|---|---|---|---|
| **基础题** | 维度 ≥2 ｜ 复音 ≥4 ｜ 控制→出声 ≤10 ms ｜ 音色 ≥2 ｜ 严格 RTL ｜ I2S→DAC ｜ ⛔ 禁预录 PCM | **必须稳过** | ⭐ **全部做完** |
| **提高题** | 维度 ≥3 ｜ 复音 ≥32 ｜ ≤5 ms **确定性** ｜ 吞吐量 = 独立振荡器数 × 采样率 | 争取 | 🟡 **只做"预留"**：参数化接口与资源位留好，**不实装** |
| ⛔ **本周不碰** | 效果器 / FM / 完整 UI / `.cst` 冻结 | — | 见 `任务清单.md` §三 |

⭐ **"预留接口"的落地方式**：凡提高题相关的东西，一律走 **`parameter` / 端口预留位**，⛔ **不写死结构**。
> 例：`POLY_TARGET`（基础 4 → 提高 32）、`OSC_PER_VOICE`（1 → 2）、`TEST_N`（4 → 32）、效果器只留算术单元与 BRAM 余量。
>
> ⭐ **"题目档位"与"编译期默认值"是两回事**（消歧，细节见 `files/20-代码/W3接口冻结表.md` §二）：
> **编译期默认 / 交付档 = `POLY_TARGET=32` / `OSC_PER_VOICE=2`**（越提高题复音线、即 32 个独立可闻振荡器）；
> **必须同时可编译可验证的最小档 = 4 / 1**（守基础题复音 ≥4）。两者只改 `parameter`，⛔ 不动接口、不动板子。
