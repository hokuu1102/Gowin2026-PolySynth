## 议题 1 ⭐ 拨弦件最终形态

> **背景**：功能 2（触发/拨弦）**是赛题基础要求 1 点名的操作**（「支持选音、触发、**拨弦**、力度感应」）→ **不建议放弃拨弦件**。
> **力度已由磁轴承担** → 拨弦**只需要一路 0/1 事件**，不必占 ADC 通道。

| 候选 | 延迟 | 有"拨"的动作感 | 需要加什么 | 复杂度 |
|---|---|---|---|---|
| ⭐ **A. 自制摆杆 + 磁铁 + 霍尔开关（`HAL2033`）** | ≈1 ms | ✅ 好 | 自制摆动结构 | **低**（与磁轴同技术） |
| **B. 成品霍尔摇杆 + 外部比较器** | ≈1 ms | ✅ 好（自回中 + 限位） | 加比较器 + 设阈值 | 中 |
| **C. 光电遮断 + 摆动挡片** | ⭐ **<0.1 ms** | ⭐ **最像"拨"** | 遮光罩 + 比较器 | 中高（怕光/灰） |
| **D. 微动开关** | 🔴 1～10 ms（去抖） | ❌ 是"按"不是"拨" | 无 | 最低 |
| （退路）复用左手磁轴越过触发点 | ≈1 ms | ❌ 无 | 无 | 零（但"触发"与"选音"耦合） |

| # | 要定的 |
|---|---|
| 1.1 | **走 A / B / C / D 哪条？**（建议 **A**：最简单、与磁轴同技术、间距可控） |
| 1.2 | 若要**区分上拨/下拨** → 需要**两组**（2 个霍尔开关 / 2 路光电） |
| 1.3 | **摆动件的机械形式**：弹簧回中？还是靠拨片自身弹性？ |

> ✅ **好消息**：**无论选哪个，`J4`（`3V3 / GND / PLUCK_A / PLUCK_B`）都不用改** ——
> 它本来就是给 0/1 器件设计的。

## 议题 2 ⭐ LED 单色 / 双色 / RGB

> **背景**：赛题拓展要求 4 是「**脱机演奏 LED 曲目指引**，辅助规范演奏节奏」。
> **⚠️ 核心顾虑：LED 的电流纹波会干扰线性霍尔**（磁轴那段最敏感）。

| 方案 | 单灯电流 | 对霍尔的影响 | 需要什么 |
|---|---|---|---|
| ⭐ **单色 LED（直流驱动）** | 2～10 mA | ✅ **最友好** —— **理论上零纹波** | `74HC595`（3 线） |
| **双色 LED（红/绿）** | ~20 mA | 🟡 中（可组合出 4 种状态） | `74HC595`（3 线） |
| **RGB + I2C 驱动 IC** | 20～60 mA | ⚠️ 有 PWM 纹波（但频率/走线可控） | I2C 驱动 IC（2 线） |
| **RGB 可寻址（WS2812）** | ⭐ **≈60 mA/灯** | ❌ **最差** —— **灯亮就持续有纹波** | 单线，但占 FPGA 时间片与 BRAM |

| # | 要定的 |
|---|---|
| 2.1 | **单色 / 双色 / RGB？**（建议**单色**，最省事且对霍尔最友好） |
| 2.2 | **灯数** —— 16 个轴位每轴一颗？还是只做关键位？ |
| 2.3 | **指示层级** —— **L1（亮下一个音）+ L3（节拍闪烁）已满足赛题**；L4 整段滚动资源需求大，**建议不做** |
| 2.4 | 若坚持 RGB → **用 I2C 驱动 IC 还是 WS2812？** |

> ⚠️ **给队友的关键数据**：WS2812 全白 12 灯 ≈ **720 mA**，@5 mm 处磁场 ≈ **2.9 Gauss**；
> 而**磁轴要测的信号磁场有几十～几百 Gauss** → 干扰只占 ~1 %。
> **但决定性差别不是量级，而是"能不能标定掉"**：
> **静态直流 ✅ 可上电标定**；**PWM 交流纹波 ❌ 标不掉** → **WS2812 只要灯亮就持续有纹波**。
> 📌 **判据极简单**：**点亮灯，看霍尔读数抖不抖**（<20 元、半小时就能测）。

> ✅ **好消息**：`J7` 已按**最宽形态留 8 pin**（`3V3/5V/GND/SCL/SDA/DATA/CLK/LATCH`）→
> **四种驱动方式都不用改板**。

## 议题 3 ⭐ FPGA 平台 60K / 138K（**最阻塞的一项**）

> **这一项不能靠讨论解决，只能靠一个数字** —— **BSRAM 预算是多少**。

| 资源 | **GW5AT-60** | **GW5AT-138** | 对本项目的意义 |
|---|---|---|---|
| LUT4 / FF | 59,904 | 138,240 | 都够 |
| **BSRAM** | **2,124 kb ≈ 2.12 Mbit** | **6,120 kb ≈ 6.12 Mbit** | ⚠️ **唯一真短板** —— 预算需 **1～3 Mbit** |
| DSP | 118 | 298 | 纯 DDS+波表不吃；上 FM/滤波才要紧 |
| **片内 ADC** | 2 | 2 | ⭐ **相同，不是区分度** |
| 最大 GPIO | 320 | 312 | ⚠️ **60K 反而略多**；但**板上只引出 ~25** → 是**板级**限制 |

| # | 要定的 | 说明 |
|---|---|---|
| 3.1 | ⭐ **BSRAM 需求上限**（效果器做几个 / Delay 多长 / 复音数目标） | **给上限就行，不必承诺做到** |
| 3.2 | 是否需要**外挂 SRAM/PSRAM** | ⚠️ **唯一会传回硬件侧的结论** → 影响 PCB |
| 3.3 | 若要 138K → **是否自购 / 赛题是否允许** | 免费申请表里 138K 标为"推荐选题三" |

> ⚠️ **换 138K 的代价**：现有板级基线（`F13@50MHz`、J14、R19 判 CPU 专用脚）**全部作废要重测**；
> 且**手上的 138K 引脚资料不可用**（缺页 + 疑似混发 Xilinx 资料）。

> 📌 **唯一会传到硬件侧的问题**：**BSRAM 不够 → 要外挂 SRAM/PSRAM → 多一颗芯片、占 IO、PCB 变复杂**。
> ➡️ **所以：先让 FPGA 侧给一个 BSRAM 上限，就能定平台。**

## 议题 6 ⭐ 谁做「行程抖动做颤音」实测（**目前无人认领**）

| # | 要定的 |
|---|---|
| 6.1 | ⭐ **谁来做？** —— 这是**交互路线成立性的唯一判据**，也是**唯一没有先例可循的未知量** |
| 6.2 | 什么时候做？（需要磁轴 + 霍尔到货） |
| 6.3 | 判据怎么定？（手感是否自然、会不会累、抖动分辨率够不够） |

> 📌 **背景**：一维磁轴做"三维表达"的方案，核心是**把行程按频段拆开**：
> 触发瞬间取值 → 力度；慢变 <1 Hz → 音量；**4～7 Hz → 颤音**。
> ⚠️ 必须**把音量从行程解耦**，否则颤音会带着音量一起抖。

| # | 要定的 | 说明 |
|---|---|---|
| 7.1 | **供电方式**：USB / 航模电池 / **两路独立** | 建议**两路独立**（板走 USB、外设走电池）最稳 |
| 7.2 | ⭐ **电流预算** | LED 全亮 720 mA + 屏 300 mA + 传感器 80 mA + DAC 50 mA + FPGA 500 mA ≈ **最坏 ~1.5 A** |
| 7.3 | **J14 的 5 V 引脚是输入还是输出？** | ⚠️ **待查原理图** —— 决定能否用电池 |

| 7.5 | 演示时是否允许插 USB 取电 | 决定要不要做电池/USB 切换 |

> 🔴 **两条铁律**（不需讨论，直接执行）：
> ① **模拟侧必须「Buck → LDO」两级** ② **不要把电池 5 V 直接接 J14.1**
