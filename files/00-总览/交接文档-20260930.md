## 六、⭐⭐ 诊断方法论（⭐ 本轮最有价值的收获）

| # | 方法 | ⭐ 用途 |
|---|---|---|
| **1** | ⭐⭐ **烧 IDF 官方例子做对照** | **区分"我们的代码问题" vs "板子/IDF/环境问题"** —— ⭐ **最高效的一步** |
| **2** | ⭐ **完整 diff `sdkconfig`**（官方 vs 我们） | ⛔ 不要只盯自己怀疑的那一项 |
| **3** | ⭐ **逐行对照官方例子的源码** | 找"**官方有、我们没有**"的调用 |
| **4** | **引脚自证**（输入+上下拉，读电平） | 判断某脚**有无外部连接** |
| **5** | **本机自环**（TX 短接 RX） | 验证 UART/引脚**本身**是否可用 |
| **6** | **引脚定位器**（轮流在某脚发标识） | ⭐ 反推"**哪个物理针 = 哪个 GPIO**"，绕开丝印 |
| **7** | **RX 定位器**（全脚扫描） | ⭐ 反推"**对端数据进了哪个脚**" |
| **8** | **GAP 回调打 event 编号** | ⭐ 一眼看出事件常量对不对 |
