## 一、⭐⭐ 8.1 `'P'` 诊断探针：按轴选片（⭐ 优先级最高）

### 🔴 缺陷（⭐ 已核实）

```
rtl/top.v:1749   .pos_i (af0_pol)      ← ⭐ 【只接片 0】⚠️
rtl/w3c/pos_probe.v:91/97  ← ⭐ 只有一个 12 位 `pos_i` ＋ 一个 4 位 `ch_i`
                              ⇒ ⭐ 该模块【没有"片"这个维度】✅
```

⇒ 🔴 **`'P'` 永远只报片 0** ⚠️ ⇒ ⭐ **诊断板 2 时会给出【错误答案】**（⭐ 比"看不到"更危险 ✅）

### ✅ 修法（⭐ 与 `'N'`/`'Q'` 对齐）

⭐ **参考**：⭐ `'N'`（⭐ `top.v` 的 16 轴轮转）＋ ⭐ `'Q'`（⭐ 一次回 16 轴）**已经是全 16 轴的** ✅
⭐ 而 ⭐ `sp_raw_sel = sp_cur_axis[3] ? af1_pol : af0_pol`（⭐ 已有的选片手法 ✅）

⇒ ⭐ **最小改法**：
```
① ⭐ `top.v` 加一个"探针轴"计数器（⭐ 或复用 `'N'` 的 `np_axis_r` ✅）
② ⭐ `.pos_i ( pp_raw_sel )`，⭐ 其中
      `pp_raw_sel = pp_axis_r[3] ? af1_pol : af0_pol`   ← ⭐ 与 `sp_raw_sel` 同一手法 ✅
③ ⭐ `.ch_i` 同时跟着换（⭐ `pp_axis_r[2:0]`）⇒ ⭐ 回包里的 `ch` 与 `pos` **同源** ✅
④ ⭐ 回包格式**建议加一位片号**（⭐ `P<c><5 位 pos>CRLF` ⇒ ⭐ 9 字节 ⚠️ 会改格式）
      ⚠️ **或**：⭐ 保持 8 字节，⭐ 但**在文档里写清"每次 `'P'` 按 16 轴轮转"** ✅
```
⚠️ **格式取舍**：⭐ 改格式要同步 ESP32 侧文档 ⚠️ ⇒ ⭐ **建议先做②③（行为对了），⭐ 格式暂不动** ✅
📌 **理由**：⭐ `'P'` 是**调试命令**，⭐ 轮转 + 文档说明就够用 ✅；⭐ 改格式的收益不值那个协调成本 ✅

# 🔴 8.3 第一次尝试【失败并已回退】—— ⭐ 教训与正确修法

## ⭐ 事实

⭐ **commit `ab133ac`**：⭐ 在 `top.v` 的**模块级**（⭐ 心跳灯那段，⭐ `:4154`）加了
```
reg fault_sticky;
always @(posedge clk) if (|af_fault | mx_fault) fault_sticky <= 1'b1;
```
⇒ 🔴 **综合门直接报错** ❌：
```
ERROR (EX3872) : 'af_fault' is not declared("rtl\top.v":4154)
ERROR (EX3872) : 'mx_fault' is not declared("rtl\top.v":4154)
```
⇒ ⭐ **已 `git revert`（⭐ `2857cc8`）** ✅ ⇒ ⭐ **综合门复验 0 ERROR / 50 modules** ✅

## 🔴 根因：**作用域**

⭐ `wire mx_fault;`（⭐ `:1071`）与 ⭐ `wire [ADC_N-1:0] af_fault;`（⭐ `:1365`）
**都声明在 `generate` 块【内部】** ⚠️（⭐ 大概率是 `g_sound` ✅）
⇒ ⭐ 而心跳灯那段在**模块级** ⇒ ⭐ **够不到** ❌

## ✅ 正确修法（⭐ 下一轮照这个做）

```
① ⭐ 在**模块级**加一条声明：⭐ `wire fault_any_w;`
② ⭐ 在 `af_fault`/`mx_fault` **可见的那个 `generate` 块内部**加：
      `assign fault_any_w = |af_fault | mx_fault;`
③ ⭐ 模块级的故障锁存/快闪逻辑**只用 `fault_any_w`** ⇒ ⭐ 作用域就通了 ✅
```
