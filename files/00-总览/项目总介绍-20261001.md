## 一、⭐ 一句话：这是什么

⭐ **一台【32 音复音的硬件电子乐器】。**

⭐ 用**磁轴键盘**弹奏（⭐ 16 个键，⭐ 每个键都能测出**按了多深**），⭐ 声音由 **FPGA 内部纯硬件合成**（⭐ 波表振荡器 ＋ ADSR 包络 ＋ 混音），⭐ 从 **I2S DAC** 出音频；⭐ 同时支持**鼓机 · 循环录音（looper）· 节拍器 · 曲谱回放 · 实时变调**，
⭐ 并通过 **ESP32 无线桥**与电脑互通（⭐ 电脑能把曲谱"灌"进来，⭐ 也能把演奏"逆向还原成 MIDI"）。

⭐ **FPGA 型号**：⭐ **高云 Gowin GW5AT-LV60PG484AC1**（⭐ 开发板：⭐ **Sipeed Tang Console 60K**）✅
⭐ **系统时钟**：⭐ **50 MHz 单时钟域**（⭐ 无 PLL 做系统时钟 —— ⭐ 这是**赛题硬约束**）✅
⭐ **代码规模**：⭐ ~52 个 RTL 文件（⭐ Verilog/SV）＋ ⭐ ~108 个 testbench ✅

## 二、⭐ 赛题与硬约束（⭐ 决定了很多设计取舍）

| ⭐ 约束 | ⭐ 内容 | ⭐ 后果 |
|---|---|---|
| ⭐ **软核禁区** | 🔴 **音频与视觉效果部分【绝对不许】用软核/MCU**（⭐ 通用的跑 C 语言的 CPU 核，⭐ 含内置 RISC-V 硬核） | ⭐ 所有合成逻辑**必须**是**专门设计的状态机/数据通路** ⇒ ⭐ 这是"FPGA 不可替代性"的体现 ✅ |
| ⭐ **实时性** | ⭐ 今年三道题对实时性要求都高 | ⭐ 端到端延迟实测 **~25 µs**（⭐ 远优于 5 ms 目标 ✅） |
| ⭐ **单时钟** | ⭐ 系统时钟**不许用 PLL** 产生 | ⭐ 全设计跑在 50 MHz ✅ |
| ⭐ **交付截止** | ⭐ **2026-11-03** | ⭐ 排期以此为准 ✅ |

| ⭐ **HDMI** | ⭐ 板载 HDMI 口 | ⭐ **视觉效果**（⭐ 队友在做 ✅ ⭐ 640×480 彩条**已上板出图** ✅） |
| ⭐ **串口** | ⭐ **J9 排针**（⭐ `TX=D15`/`RX=D14`）· ⭐ **500000 8N1** | ⭐ 调试/标定/控制 ✅<br>🔴 **板载 USB-C 串口走不通**（⭐ 已实测）⇒ ⭐ **必须用排针** ✅ |

### 3.2 ⭐ 信号链（⭐ 从按键到出声，⭐ 这是全项目的主干）

```
⭐ 磁轴（霍尔）→ 电压
   ↓
⭐ MCP3208 ×3（SPI，⭐ 12 位）→ raw 码
   ↓
⭐ adc_farm          ⭐ 三片并行采集，⭐ 锁步扫描同一通道
   ↓
⭐ axis_snapshot     ⭐ (片, 通道) → 轴号：⭐ axis = adc×8 + ch（⭐ 16 轴）
   ↓
⭐ calib ×2          ⭐ 标定：⭐ pos = (raw − zero) × gain >> 8
   │                 ⭐ 未标定 ⇒ zero=0 / gain=1.0（⭐ 水位闸保证"复位 = 冷启动" ✅）
   ↓
⭐ calib_autotare    ⭐ 上电自动找零点（⭐ 静止判定 ＋ ⭐ 超时跳过 ＋ ⭐ 结果可见）
⭐ calib_span        ⭐ `'S'` 行程标定（⭐ 把满行程归一到 0..4095 ✅）
   ↓
⭐ event_extract     ⭐ 过阈值 ⇒ 产生 note_on / note_off（⭐ 带迟滞 ＋ ⭐ 不应期）
⭐ param_extract     ⭐ 从"两阈值之间的时间差"算【力度】（⭐ 快按 = 大声 ✅）
   ↓
⭐ axis_map          ⭐ 轴号 → 相位增量（⭐ 两张表：⭐ 键盘模式 / 指板模式）
   ↓
⭐ evt_merge         ⭐ 四路事件合流（⭐ 带【来源标签】✅）
⭐ seq_arb           ⭐ 三级仲裁（⭐ 手弹 / 曲谱 / 演示）
   ↓
⭐ note_manager      ⭐ 32 voice 分配 / 抢占 / 重触发 / 释放（⭐ 按来源隔离 ✅）
   ↓
⭐ oscillator_bank   ⭐ 32 voice × 2 lane 波表振荡器（⭐ TDM 时分复用 ✅）
⭐ envelope_bank     ⭐ 32 × ADSR 包络
   ↓
⭐ tdm_render_mixer  ⭐ 混音 ＋ 1/√N 归一化 ＋ 软限幅
   ↓
⭐ i2s_tx → MAX98357A → 🔊
```

⭐ **并行支路**：
```
⭐ beat_gen（节拍器）· ⭐ drum_gen（鼓机）· ⭐ looper（循环录音）
   ⇒ ⭐ 都经 `evt_merge` 作为【独立来源】注入 ⇒ ⭐ 与手弹互不干扰 ✅
```

## 四、⭐⭐ 功能全集（⭐ 这就是"最终成品能做什么"）

### 4.1 ⭐ 演奏

| ⭐ 功能 | ⭐ 说明 |
|---|---|
| ⭐ **16 键磁轴键盘** | ⭐ 两块左手板，⭐ 每块 8 键 ✅ |
| ⭐ **行程感知** | ⭐ 每个键的按下**深度**都读得到（⭐ 12 位）✅ |
| ⭐ **力度（velocity）** | ⭐ 由**按下的快慢**决定：⭐ 快按 ⇒ 大声；⭐ 慢按 ⇒ 小声 ✅<br>⭐ 算法：⭐ 两个阈值之间的**时间差** → 力度 ✅ |
| ⭐ **位置→力度跟随** | ⭐ 按住时**继续下压** ⇒ 力度实时变大（⭐ 表现力 ✅） |
| ⭐ **两种演奏模式** | ⭐ **键盘（钢琴）模式**：⭐ 轴事件直接发声 ✅<br>⭐ **指板模式**：⭐ 先选弦/品，⭐ 再由拨弦比较器（LM393）触发 ✅ |
| ⭐ **起始音（base note）** | ⭐ 整琴移调 **±八度**（⭐ **C4 / C5 / C6 三档** ✅）<br>⭐ **触发**：⭐ 串口屏 `RET_NUM` 帧 —— ⭐ 发 **`71 01 xx FF FF FF`**（⭐ `xx` = 八度 × 24 ✅）<br>⚠️ **更正**：⛔ **不是** `'F'`/`'G'`（⭐ 那两个字母是 T3 的方案，⭐ **尚未实现** ⚠️）| 
| 🔴 **实时变调（transpose）** | ⚠️ **⛔ 尚未实现** —— ⭐ 方案已定稿：⭐ `files/00-总览/T3变调与推子功能状态机-设计定稿-20261001.md` ✅<br>⭐ 目标：⭐ −12..+12 半音，⭐ 保持相位连续（⭐ 不产生啸叫 ✅）| 
| ⭐ **滑音（slide）** | ⭐ 沿键盘滑动 ⇒ 音高跟着滑（⭐ 用 `delta` 检测 ✅） |
| ⭐ **双音（two-note）** | ⭐ 同帧按下两个键的检测 ✅ |
| ⭐ **颤音（vibrato）** | ⭐ LFO 调制音高，⭐ 深度/速率由右手板模拟量控制 ✅ |

## 八、⭐⭐ 关键设计约束（⭐ 想改代码必须先知道）

| ⭐ # | ⭐ 约束 | ⭐ 为什么 |
|---|---|---|
| **1** | ⭐ **全设计单时钟 50 MHz，⛔ 不许用 PLL 做系统时钟** | ⭐ 赛题硬约束 |
| **2** | ⭐ **音频/视觉不许用软核** | ⭐ 赛题硬约束（⭐ 专门的状态机/数据通路**可以** ✅） |
| **3** | ⭐ **改 RTL 必须走完整门序**：⭐ **综合门 ⇒ 聚焦 tb ⇒ PnR ⇒ 全量回归** | ⭐ `iverilog` 全绿**不代表能综合**（⭐ 曾有"两个 `always` 驱动同一 `reg`"的例子：⭐ 仿真看不见、⭐ Gowin 直接报错 ⚠️） |
| **4** | ⭐ **判据必须"能红"** | ⭐ 否则"全绿"不构成证据（⭐ 唯一判据 = **跑未修复版本必须输出不同** ✅） |
| **5** | ⭐ **一次只改一个变量** | ⭐ 否则出问题分不清是谁的 |
| **6** | ⭐ **不许削弱已有判据**来让测试变绿 | ⭐ 那会变成假绿 ⚠️ |
| **7** | ⭐ **⛔ 不 push**（⭐ 需用户明确同意；⭐ 且**压成 1 个 commit** ✅） | ⭐ 项目纪律 |
| **8** | ⭐ **PvR 余量门槛 = 3%**（⭐ `Fmax ≥ 51.5 MHz`） | ⭐ 用户 2026-10-01 裁定（⭐ 原 5% 的依据已被撤回 ✅） |

⭐ **① PnR 是"布局噪声主导"的** —— ⭐ 同源重跑可能差 **±3 MHz** ⇒ ⭐ **判门槛要用【已观测的最差值】**，⛔ 别拿最好那一次当证据 ✅
⭐ **② `.ps1` 必须纯 ASCII 或带 UTF-8 BOM** —— ⭐ 否则 PS 5.1 按 GBK 解码 ⇒ ⭐ **静默吃掉换行/数组元素**（⭐ 零报错 ⚠️）✅
