| 项目 | 内容 |
|---|---|
| **做什么** | 用 FPGA 做**纯硬件 RTL 实时音频合成**的电子乐器引擎，**不是播放预录 PCM** |
| **核心交付** | 能真实演奏的交互乐器 + FPGA 实时合成 + 可视化 UI + LED 曲目指引 |
| **当前阶段** | **机械原型验证** —— 待打印磁轴结构件、**待做「行程抖动做颤音」手感实测** |
| **硬件负责人负责** | 演奏交互硬件 / 传感器 / PCB / 机械结构 / FPGA 外设接口 / 音频输出 / 整体硬件架构 |
| **不负责** | 合成算法本体、音色设计、RTL 架构（FPGA 侧） |
| **🔴 当前红线** | **`A1` 平台未定 + 机械结构未冻结之前，不画最终演奏 PCB** |

### ✅ 已经定案的部分（可以照做，不用再讨论）

```text
左手区：选音（音高 + 力度）   右手区：拨弦（触发）+ 颤音（推子/电容条）
                              ← 两者互斥，演奏中不同时操作
三个模块互相独立 → 不必共面、可以分板
```

1. **左手区布局定稿**：**2 行 × 8 列 = 16 轴位**，上下严格对齐，列间距 15 mm，排间距 **12～15 mm**，两排**严格等高**，3D 打印矮帽。
2. **传感器定稿**：**16 个线性霍尔**（⛔ 不用数字霍尔）→ 每块板一片 8 通道 SPI ADC → 到 FPGA 只占 **5 根 IO**。
3. **打板定稿**：每块板 4 列 × 2 行 ≈ **60 × 40 mm**，打板时两块**上下拼成 60 × 80**（落在 100×100 内），成品左右并排、轴中心跨距 **105 mm**、跨缝间距 **15 mm**。
4. **映射定稿**：**指板·差八度为默认**，钢琴模式作答辩/上手入口；**16 轴位全部装霍尔**。
5. **音频接口定稿**：`BCLK/LRCLK/DIN/MCLK/DAC_MUTE/AMP_EN` **6 根一次留到位**（换模块不改板）。
6. **电源定稿方向**：模拟侧必须「Buck → LDO」两级；**最稳 = 两路独立**（板走 USB、外设走电池）。
7. **不用板载 CPU**：赛题要求音频通路**全部基于 FPGA HDL**，CPU 参与音频**不合规**。

## 1. 赛题硬性指标（验收红线）

| 指标 | 要求 | 本项目落点 |
|---|---|---|
| 演奏事件识别 | 音符 / 和弦 / 触发 / **拨弦** | 左手区出音符事件，右手区出拨弦事件 |
| 独立可控演奏维度 | **≥2**（拓展 **≥3**） | 拟做：**力度 / 音高 / 颤音**（各占一个独立维度） |
| 合成链 | DDS/波形发生 → ADSR → 多 Voice 管理 → 混音 | **全部 RTL 实现** |
| 音频输出 | **I2S → DAC** | 待定（可能用板载音频，见 §7 F1′） |
| **控制→出声延迟** | **≤10 ms**（拓展 **≤5 ms 且确定性**） | 演奏输入必须**绕开串口屏** |
| 基础复音数 | **≥4** | 路线：4 → 8 → 16 → 32 |
| 拓展方向（三选一） | ≥32 Voice ／ ≥32 加性分量 ／ ≥32 并行物理建模单元 | 择一即可 |
| 音色数 | **≥2** | — |
| 效果器 | Reverb / Delay / Chorus（FPGA 内） | ⚠️ **BSRAM 是最大瓶颈**（见 §7） |
| 可视化 | 波形 / 频谱 / Lissajous | 走串口屏 |
| **脱机 LED 曲目指引** | 拓展要求 4 | **硬件侧责任**（灯的布局/驱动/共板关系） |
| **必须证明** | 是 FPGA RTL 实时合成，**不是播放预录 PCM** | 答辩现场**不给 CPU 上电**直接演奏 |

### ⚠️ 评分陷阱（全员必须知晓）

> **吞吐量 = 「同时活跃可闻独立振荡器总数 × 实际音频输出采样率」**，原文明确「**过采样不叠加加分**」。
> ➡️ **单纯拉高采样率是无效努力**；正确做法是**把真实 Voice 数做上去**。

## 2. 当前硬件方案（已定案部分）

### 2.1 系统架构

```text
┌────────── 演奏输入 ──────────────────────────────────────┐
│  左手区（磁轴 2×8）      右手区            辅助控制        │
│  选音 · 力度            拨弦 · 颤音（互斥） 按键/旋钮/编码器 │
└──────┬────────────────┬──────────────────────┬───────────┘
       ▼                ▼                      ▼
┌────────── 信号调理与采集 ────────────────────────────────┐
│  模拟前端（分压+偏置+RC）── 多通道 SPI ADC   数字输入去抖   │
└───────────────────────┬─────────────────────────────────┘
                        ▼
╔══════════ FPGA · 实时合成核心（全部 HDL 实现）═════════════╗
║ ① 输入接口层   采样时序 · 通道扫描 · 标定与滤波            ║
║        ▼                                                 ║
║ ② 事件与参数层 音符/触发/拨弦事件 · 表情与音色参数  ──────╫─→ 串口屏 UI（UART，非演奏通路）
║        ▼                                                 ║
║ ③ 合成引擎层   Voice 管理 → DDS/波形 → ADSR → 混音 → 效果器 ║
║        ▼                                                 ║
║ ④ 输出接口层   音频串行 · 显示数据 · 灯光数据流            ║
╚═══════╤═══════════════╤════════════════╤═════════════════╝
        ▼               ▼                ▼
   音频输出         可视化           LED 演奏指引
   I2S→DAC→音箱     波形/频谱/李萨如   灯光驱动 → 灯珠
```

**两条不可违反的结构原则**

| # | 原则 | 原因 |
|---|---|---|
| 1 | **演奏链路与 UI 链路必须分离** | 串口屏的触摸扫描 + UART 传输延迟**不可控**，不能进 ≤5 ms 的确定性通路 |
| 2 | **左手区 / 右手区 / 颤音模块互相独立** | 由不同手或不同动作操作 → **不必共面、可以分板** |

> ⭐ **② 层的「事件 / 参数分离」是整个架构的关键**：
> **事件**（选音、触发、拨弦）→ Note Manager，驱动 Note ON/OFF；
> **参数**（力度、颤音、表情、音色）→ Parameter Manager，**持续调制、永不产生音符**。
> 这是「误触发」问题的**结构性解法**，不依赖算法判断。

### 2.2 左手区（M1 · **已定稿**）

📄 详见 **`方案抉择/左手区方案.md`**

| 项 | 决定 |
|---|---|
| **布局** | **2 行 × 8 列 = 16 轴位**，上下**严格对齐**（同一 x 中心） |
| **结构** | 两块 **2 行 × 4 列** 板左右拼成；每块约 **60 × 40 mm** |
| **轴体** | 普通磁轴（标准 MX 兼容） |
| **检测** | **16 个线性霍尔** → 每板一片 8 通道 SPI ADC → **到 FPGA 只占 5 根 IO** |
| **列间距 / 排间距** | **15 mm** / **12～15 mm**（⚠️ **不是 6～8 mm**） |
| **两排高度** | **严格等高，不做台阶** |
| **键帽** | 3D 打印矮帽，边缘大倒角 + 下缘开窗透光 |
| **默认模式** | **指板 · 差八度**；钢琴模式作演示/上手入口 |

**为什么是它（三条收益）**

1. ⭐ **横向 176 mm → 105 mm**，落回单指扫奏舒适范围（100～120 mm）
2. ⭐ **音域不缩水**：钢琴模式可发音 = 8 白 + 6 升 = **14 个音（C..C#）**，比 12 轴单排还多
3. ⭐ **双模式零硬件成本**：切换只改 FPGA 里的映射表

**两种模式的映射**

| 钢琴模式 | 列 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| **上排** | C# | D# | *同下排* | F# | G# | A# | *同下排* | C# |
| **下排** | C | D | E | F | G | A | B | C |

| 指板模式（默认） | 列 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| **上排**（高八度） | C | C# | D | D# | E | F | F# | G |
| **下排**（低八度） | C | C# | D | D# | E | F | F# | G |

> ⚠️ **这不是「两者兼得」，而是「两者可切换」** —— 钢琴模式下滑弦**不成立**（下排步进 2·2·1·2·2·2 不均匀）。
> 它解决的是**入口问题**（会弹钢琴的人能上手 / 答辩给评委一个熟悉的入口）。

**必须守住的四条**

| # | 规则 |
|---|---|
| 1 | ⛔ **绝不引入键帽高度差** —— 定位只能靠**颜色 / 纹理 / 刻印 / LED** |
| 2 | ⚠️ **排间距 12～15 mm，不是 6～8 mm** —— 旧值只适用于「单排 X + Y 调制排」需要**故意双压**的场景；这里两排**都是音高键**，双压会误触发升半音 |
| 3 | ⭐ **上下排误触发用「行程比较」仲裁** —— 同列上下同时受压时**行程大的为主音**。**开关量做不到，磁轴做得到** |
| 4 | ⚠️ **插值只在单排内部横向做，绝不跨排插值** —— 横向 15 mm = 1 个半音；纵向 12～15 mm = 1 个或 12 个半音 |

**两个设计亮点**

- ⭐ **空位键容错**：列 3、列 7 上排（E/B 上方）在钢琴模式下**映射成"下方同音"** → 指腹蹭到上排只是**同音重复、音高不变、不出错音**，**把「上下排误触发」这个最大风险在 2 个位置结构性化解**。代价：FPGA 需**同音去重**。
- ⭐ **跨缝间距修正**：两块板紧贴时跨缝列距会小于 15 mm → 让**左板右侧留 8、右板左侧留 7**，紧贴后正好 **15 mm**。留边不浪费，正好放 ADC、连接器、螺丝孔 → **每块板宽 = 7 + 45 + 8 = 60 mm**。
  若跨缝只有 2～4 mm 却要走 1 个半音 → **局部音高变化率快好几倍，手感上明显"跳一下"**。

**分板三前提**：① 上方用**一整块 3D 打印定位板**统一固定 16 个轴 ② 两半**同厚度/同层数/同铜厚** ③ 同源拼版切出。
> 💡 **关键认知：「分板会不会卡手」取决于「手指能碰到什么」，不取决于 PCB 分了几块** —— 手指碰的是键帽。

**同列双音按模式区分**：钢琴模式同列 = 半音（极不协和）→ **互斥**；指板差八度同列 = **八度** → **允许**。

### 2.3 右手区（M2 拨弦 + M3 颤音）

| 项 | 结论 |
|---|---|
| **拨弦** | **事件型，延迟与可靠性优先**；微动（有触点磨损）或光电（无磨损但要供电与遮光）；1～2 路看是否需方向信息 |
| **颤音** | **推子 ≡ 电容条**（都是一路颤音连续量）→ **接口做成一模一样，后期可直接互换** |
| **架构定位** | 🔴 颤音属「**参数**」，**永不产生音符事件**（进 Parameter Manager，不进 Note Manager） |
| **归属手** | 右手（**与拨弦互斥，演奏中不同时操作**）；⚠️ 也可放左手独立区 —— **赛题不限手数** |
| **位置约束** | ⚠️ **推子不能放在与磁轴不同的平面高度上**（实测跨面移动会卡顿） |

### 2.4 音频输出（M6）

**关键认知：输出其实是「两段」**

```text
FPGA --I2S--> DAC 模块 --Line Out--> ┬--> 3.5mm → 有源音箱（用它的功放）
                                     └--> 功放模块 → 小扬声器
```

> 🔴 **DAC 出来的是「线路电平」，推不动扬声器。**
> 「两种用法」**不是两个 DAC**，而是**同一路 Line Out 后面分两路走**。

| 项 | 结论 |
|---|---|
| **接口预留** | ✅ 已定：`BCLK / LRCLK / DIN / MCLK / DAC_MUTE / AMP_EN` **6 根一次留到位** |
| **功放** | ⏸️ **当前暂缓不装**，但**接口预留不删**（板上保留 `AMP_EN` + 喇叭焊盘）→ 后期插上即可，**不改板** |
| **接音箱** | ⚠️ 接**有源音箱的 AUX IN**，**绝不接音箱的 INPUT**（那是乐器输入口，电平与阻抗都不匹配） |
| **时钟** | ✅ 全整数分频：`MCLK = 50 MHz ÷ 4 = 12.500 MHz`；`BCLK = MCLK ÷ 4 = 3.125 MHz`；`LRCLK = MCLK ÷ 256 ≈ 48.83 kHz` |
| **音量** | 数字侧为主（内部位宽 ≥20 bit） |
| **防爆音** | 上电顺序（DAC 先稳定 → 延时 100～200 ms → 使能功放）+ 静音脚 + 数字渐入，三者可叠加 |

> 💡 **fs 不必是精确的 48.000 kHz** —— **音高 = 相位增量 × fs / 2^N**，只要相位增量按同一个 fs 反算，**输出音高就是精确的**。只有需与外部设备（SPDIF 等）同步时才要求精确 48 k。

> ⚠️ **DAC 型号尚未核实**（见 §9）。**且有一条可能省掉整个 DAC 的线索**：若使用 Sipeed Tang Mega 系列底板，**底板自带 3.5 mm 耳机口 + 2×3 W 喇叭输出** → **必须先核实板载音频通路再下单 DAC**。

### 2.5 LED 演奏指引（M7 · 赛题拓展要求 4）

| 项 | 结论 |
|---|---|
| **承载方式** | **键盘下灯位**（灯珠在轴座 PCB，靠轴体导光柱导到键帽）→ 效果是**键帽下部发光**（不是字符发光） |
| **已实测** | ✅ 把键帽下面一部分切掉透光，在机械键盘上试 → **「比较清楚」**，这条路通 → 开窗 **0.6～0.8 mm**，可直接做进 3D 打印模型 |
| **指示层级** | ✅ **L1（只亮下一个音）+ L3（节拍闪烁）已满足赛题**；L4 整段滚动资源大、**不建议首版做** |
| **硬限制** | ⛔ **74HC595 做不了 RGB 调色**（只有开关量、无逐通道 PWM）；⛔ **RGB 直驱要 36 根 IO，不可行** |
| **驱动倾向** | 单色 → 74HC595（3 线）；要 RGB → **I2C 驱动 IC 比 WS2812 更适合本项目**（不占 FPGA 时间片、无需无中断发送、单灯坏不整链断） |
| **⭐ 对霍尔的影响** | **关键不是电流大小，而是「纹波是否常驻」** —— 静态直流 ✅ 可上电标定；**PWM 交流纹波 ❌ 标不掉**。WS2812 只要灯亮就持续有纹波（内部恒流+PWM）；**单色直流驱动可以没有** → **若「对霍尔影响最小」是首要判据 → 选单色 LED + 直流驱动** |
| **接口** | ✅ J7 已按最宽留 **8 pin**（`3V3/5V/GND/SCL/SDA/DATA/CLK/LATCH`）→ 四种驱动方式都不用改板 |

> ⚠️ **LED 是板上电流最大的负载**：LED 全亮 = **720 mA**（单色 ~120 mA）→ 单独供电、走线粗、就近大电容；驱动走线**必须远离模拟传感器走线**，必要时**分时**（刷新避开 AD 采样窗）。

### 2.6 电源（M9）

**三条铁律**

| # | 规则 | 原因 |
|---|---|---|
| 1 | 🔴 **模拟侧必须「Buck → LDO」两级** | 只上 Buck 给 DAC/传感器供电 = **一定会听到嗡嗡声** |
| 2 | 🔴 **不要把电池 5 V 直接接 J14.1** | 会与板载供电**冲突/反灌**（尤其同时插着 USB 时）→ 电池只给外设供电 |
| 3 | **大电流回路就近去耦** | 每个 LED 就地 0.1 µF + 段级 10～100 µF + 1000 µF 体电容 |

> ✅ **最稳方案：两路独立** —— FPGA 板走 USB、外设走电池，互不干扰也最安全。

**电流预算（必须算）**：LED 全亮 720 mA + 串口屏 300 mA + 传感器/ADC 80 mA + DAC 50 mA + FPGA 板 500 mA ≈ **最坏 ~1.5 A**；典型（指引态）≈ **0.5 A**。→ 决定走线宽度、去耦容量、Buck 额定电流。

⚠️ LiPo 安全：**禁短路 / 过放（单节 <3.0 V 永久损坏）/ 过充 / 物理损伤**；充电不离人，用防火袋。

### 2.7 UI（M8）

| 项 | 结论 |
|---|---|
| **屏** | 6 寸串口触摸屏，走 UART，**只有 4 根**（`5V/GND/TX/RX`） |
| **🔴 架构约束** | **绝不进演奏通路** —— 屏只做 UI 与显示，不做演奏输入 |
| **显示内容** | 音色 / 参数 / 当前音符 / 波形 / 频谱 / 李萨如 / 状态 |
| **待核实** | 屏的**串口电平**（5 V TTL 还是 3.3 V）→ 决定是否需电平转换 |

## 3. FPGA 平台（⚠️ 重新打开：60K / 138K 待定）

### 3.1 官方资源对比（**已核实**：高云 Arora V 产品页 GW5AT 系列表）

| 资源 | **GW5AT-60** | **GW5AT-138** | 对本项目的意义 |
|---|---|---|---|
| LUT4 / FF | **59,904** | **138,240** | 纯逻辑大概率都够（60K 有 2.3× 余量） |
| SSRAM (kb) | 468 | 1,080 | — |
| **BSRAM (kb)** | **2,124**（118 块） | **6,120**（340 块） | ⚠️ **唯一真正的短板** —— 预算需要 **1～3 Mbit**，60K 的 ≈2.12 Mbit **很紧**（1 秒 Delay 就 1.15 Mbit）；138K ≈6.12 Mbit 有 **2.9× 余量** |
| **DSP（18×18）** | **118** | **298** | 纯 DDS+波表**不吃**；上 FM / 逐 voice 滤波会**跳一个量级** |
| PLL | 8 | 12 | 都够 |
| 全局时钟 / HCLK | 16 / 20 | 16 / 24 | 都够 |
| **片内 ADC** | **2 个** | **2 个** | ⭐ **相同，不构成区分度** → **不要为了 ADC 换 138K** |
| GPIO 最大 / Bank | **320** / 11 | 312 / 6 | ⚠️ **60K 反而略多**；且**板上只引出 ~25 可用 IO** → 这是**板级**限制，换器件不自动解决 |

> 📌 **这张表推翻了两种直觉**：
> ① 「60K 一定够」——**BSRAM 卡在边缘**，效果器做多少直接决定够不够；
> ② 「138K 一定更好」——**IO 宽裕度取决于底板引出，不取决于器件**；**ADC 两者相同**。

### 3.2 ⚠️ 换 138K 的三条硬代价

| # | 代价 | 说明 |
|---|---|---|
| 1 | **现有板级基线全部作废** | `sys_clk = F13 @ 50 MHz`、`J14`（15×2，30 pin，~25 可用 IO）、`J14.12 → R19` 被判 **CPU 专用脚** —— 这些**都是 60K 那块板实测出来的**，换板要重新建立 |
| 2 | **138K 引脚资料当前不可用** | 手上的「高云138K核心板.pdf」**缺第 2～5 页**（标 `Sheet x of 10`，实际只有 1/6/7/8/9/10），FPGA 符号与球位正画在缺失页；且封面写 `XC7A100T`、bank 编号 13/14/15/16/34/35、出现 `XADC_VP/VN` —— **都是 Xilinx Artix-7 的特征** ⇒ **资料疑似混发**。<br>⚠️ **绝不可把 `XADC_VP/VN` 当作「高云 138K 有片内 ADC」的证据** |
| 3 | **IDE / 授权差异** | 138K 需 Gowin IDE ≥ V1.9.9（商业版 ≥ V1.9.11.03）；烧录用 GAO-Bridge 模式；教育版支持情况需确认 |

### 3.3 ⭐ 片内 ADC：从「待核实」到「已核实」

> ✅ **已核实**：**GW5AT-60 与 GW5AT-138 各带 2 个片内 ADC**，规格「**60 dB SNR、1 kHz 信号带宽、过采样型、无需外部基准**」。

| 限制 | 影响 |
|---|---|
| **只有 2 路** | 16 个霍尔**必须配模拟多路开关**（引入 Ron 误差与建立时间问题） |
| **1 kHz 信号带宽** | ⚠️ 刚好卡在目标采样率（每通道 1 kHz）上 → **需核实官方口径是"信号带宽"还是"采样率"** |

**⭐ 现成线索**：《GOWIN `DK_START_GW5AT-LV60PG484A` 用户手册》**第 24 页有「ADC Interface / Pin Distribution / ADC 接口原理图连接图」** → **说明该板确实把片内 ADC 引出来了**。
➡️ **行动：查这一页的引脚分布，确认 ADC 输入是否到达手中板的可用扩展口**；若方便引出，可作「省一片外部 ADC」的备选。

### 3.4 不用板载 CPU（龙芯）

| 用途 | 是否合规 |
|---|---|
| **CPU 参与音频生成 / 播放音频** | ❌ **不合规** —— 正是赛题要防的「软件串行运算滞后」 |
| CPU 做 UI 渲染、曲目存储与下发、网络/蓝牙、文件管理 | ✅ 合规（不影响「音频由 FPGA 生成」） |
| **CPU 完全不初始化** | ✅ **最省事** |

> ⚠️ **但有两个真实的坑**
> **坑 1：「不用 CPU」≠「被 CPU 占的引脚就能用」** —— 实证：`J14.12` → ball `R19` 被 Gowin P&R 判为 `dedicated pin (CPU)`，不能作普通 IO，只能飞线到 `P17`。
> ➡️ **排引脚必须留足余量，且一定要实际跑一次 P&R 验证（不能只看原理图）。**
> **坑 2：未使用的 CPU 会不会反过来影响 FPGA？** —— 需确认是否有共享总线/时钟、CPU 未上电时 FPGA 能否独立工作、是否共用电源域、板载 50 MHz 是否独立于 CPU。→ **做一个最小验证**（烧纯 LED 闪灯或串口输出）。

✅ **答辩话术**：「**整条音频通路 100% 在 FPGA HDL 内部实现；CPU 未参与，断开/不初始化 CPU 也能正常演奏。**」
**证据方式**：现场**先不给 CPU 上电**直接演奏 —— 声音照常出来，就**当场证明了"不是软件在算"**。

## 5. 架构原则与红线（不可违反）

| # | 原则 | 原因 |
|---|---|---|
| 1 | 🔴 **同一只手要移动来切换的操作，必须同一个平面、同一高度** | 实测「手指从磁轴面移到电容面」明显卡顿（高度差 + 台阶 + **必须先抬手**）。⚠️ **只对同一只手成立** —— 不同手各管一块时两区可完全独立 |
| 2 | ⛔ **任何键帽高度差都不允许** | 黑键高出白键约 10 mm → 钢琴上**根本无法从 C 滑到 D**（C# 挡着），而 E–F 无黑键可直接滑 → **同一动作在不同位置可行性不同** |
| 3 | **演奏链路与 UI 链路必须分离** | 串口屏延迟不可控，不能进 ≤5 ms 确定性通路 |
| 4 | **能用物理正交解决的，不要用算法解决** | 算法分离需 200～300 ms 滑窗，**正好落在最敏感的音高通路上** |
| 5 | **延迟预算按通路分级** | 把「延迟不确定」的器件，分配到**唯一不敏感**的通路上 |
| 6 | ⛔ **不以价格定方案，以效果定方案** | 成本只作记录 |
| 7 | ⛔ **IO 不是硬约束**（板上还有其他可引出的 IO，只是焊接不便） | 但**传感器信号必须走总线**，不要"一个信号一根线" |
| 8 | ⛔ **打样不是障碍**（打印机自有） | — |
| 9 | **接口一次留到位** | **待定的只是"接什么"，不是"留几针"** —— 按**最宽形态**预留，最多空几针不返工 |
| 10 | **器件型号一律标注"待核实"** | 核实封装/量程/物料编码后再下单 |

> 🔴 **PCB 阶段门红线**：
> **`M1 / M4 / M5 / M9 / M10` 的功能项 + `A1 / B1 / B2 / C1 / H*` 的选型全部拍板之前，不启动最终演奏 PCB 设计。**
> 这是避免「结构一改、PCB 全废」的关键纪律。

## 6. 延迟预算（按通路分级）

| 通路 | 敏感度 | 说明 | 分配 |
|---|---|---|---|
| **触发 / 拨弦 → 发声** | 🔴 最敏感 | 决定"音符什么时候响" | 磁轴 / 微动 / 光电（延迟确定） |
| **选音 / 音高** | 🟠 敏感 | 延迟 = 音符迟到；抖动 = 音高不稳 | 磁轴 |
| **力度** | 🟡 中 | 与触发时刻绑定，**取触发瞬间值即可** | 磁轴行程（采样保持） |
| **颤音 / 调制** | 🟢 **不敏感** | 4～7 Hz 低频调制，**几十 ms 更新听不出来** | 推子 / 电容条 ✅ |
| **可视化 / LED 指引** | ⚪ 无要求 | 视觉上同步即可 | 任意 |

> ➡️ **分配原则：把"延迟不确定"的器件，分配到唯一不敏感的通路上。**
> ⚠️ **但结构连续性优先级更高** —— 跨面卡顿**每次演奏都遇到**，电容延迟目前只是理论风险。

## 7. 时钟与资源预算

| 项 | 值 |
|---|---|
| 板载系统时钟 | **`sys_clk = F13 @ 50 MHz`**（60K 板实测） |
| 音频采样率 | 48 kHz（初期） |
| **每样本可用时钟** | 50 MHz ÷ 48 kHz ≈ **1041 clk / sample** |
| 分频 | `MCLK = ÷4 = 12.500 MHz (256fs)`；`BCLK = ÷4 = 3.125 MHz (64fs)`；`LRCLK = ÷256 ≈ 48.83 kHz` |

> ✅ **结论：不需要一个时钟周期算完所有 Voice** —— 可用**时分复用 + 流水线 + 多周期计算**换取更多并行声部。
> **32 voice 若时分复用，每 voice 只有约 32 clk → 勉强够但要精打细算**；若全并行则是 32 套独立硬件 → **逻辑规模直接乘 32 倍**。

**⚠️ 资源预算与最大风险**

| 资源 | 预算 | 风险 |
|---|---|---|
| 逻辑（LUT） | 中～大（DDS×N、效果器、FFT 是大头） | 相对乐观，60K 级器件做多 voice DDS 是业界常见规模 |
| **BSRAM** ⭐ | **Delay 200 ms ≈ 230 Kbit；1 秒 Delay ≈ 1.15 Mbit；Reverb ≈ 0.5～2 Mbit；波表 100～500 Kbit** → **合计 1～3 Mbit** | 🔴 **最大风险点**。60K 只有 2,124 kb **很紧**；不够时的退路：① 缩短延迟 ② 降位宽（24→16 bit）③ 只做一个效果器 ④ 外挂 SRAM/PSRAM |
| 乘法器 / DSP | 纯 DDS+波表**不吃**；ADSR×样本可时分复用 1～4 个；**FM 每算子一个 → 4×32 = 128 量级** | ⚠️ **一旦上 FM 或逐 voice 滤波器，需求跳一个量级** |

### 9.2 手感与体验类待实测

- **排间距实测**：12 / 15 mm 下按上排时下排会不会被带动 → 决定误触发严重程度与是否需要行程仲裁
- **双压插值抖动**（取决于霍尔线性度与装配一致性）
- **同平面划过一排磁轴**的手感（矮帽/平顶 + 小间隙 + 统一高度）
- **矮帽副作用**：行程感更明显（力度更灵敏），需适应；顶面薄壁受力需加厚/加肋
- **LED 效果实测**：1 轴 + 1 灯 + 1 透光键帽，暗光下看（**<20 元、半小时**）

### 9.3 需外部确认 / 上板实测

- **`B1` 霍尔在 3.3 V 下的实际量程与零点**；**16 片一致性离散度**；**相邻霍尔磁场串扰**
- **`B2` 轴体实际底座外廓尺寸**（决定列间距能否压到 15 mm 以下）
- **MPR121 端到端延迟**（若走电容条方案）
- **片内 ADC 引脚是否到达可用扩展口**（查 `DK_START` 手册第 24 页）
- ⚠️ **电子乐器项目与招新题（ADA107）是否同时占用这块板？**（影响扩展口剩余 IO）
- **CPU 与 FPGA 是否共享总线/时钟/电源域** + 「CPU 不参与时 FPGA 能否独立跑通」（**必须实跑 P&R**）
- 串口屏串口电平；`C1` ADC 型号；`E1` 拨弦器件；`G2` LED 驱动方式

### 9.4 需队友明确回答的 5 个问题

1. **ADA107 是否同时占用这块板？**
2. **片内 ADC 的 ADC 引脚能否引出使用？**（精度/通道/输入方式）
3. ⭐ **谁来做第一版「行程抖动作颤音」的手感验证？**（路线成立与否的唯一判据，最优先）
4. **一排磁轴的数量与音高映射最终形态？**（音阶 / 半音 / 自由）
5. **3D 打印排期？**（磁轴阵列 + 拨弦 + 外壳）

## 10. 风险与对策

| 风险 | 触发条件 | 对策 |
|---|---|---|
| **BSRAM 不够** | 查清效果器预算后 > 2 Mbit | 缩短延迟 / 降位宽 / 只做一个效果器 / 外挂 SRAM；或**改用 138K** |
| **换 138K 后板级基线作废** | 决定启用 138K | 重新实测时钟与扩展口；**重跑 P&R 验证引脚**；**不要用缺页的那份 138K 资料** |
| **行程抖动做颤音手感不佳** | 实测别扭或太累 | 升到路线 B（+1 条独立调制条），**A 的硬件是 B/C 的子集，不浪费** |
| **上下排误触发** | 指腹蹭到邻排 | 排间距 12～15 mm + **行程仲裁** + E/B 列同音容错 + FPGA 同音去重 |
| **双压插值抖动** | 插值结果跳变 | 降低键距 / 提高霍尔线性度与装配一致性；退路：不插值，接受离散音高 |
| **数字霍尔误选** | 采购时图便宜 | ⛔ **只用线性霍尔**；数字霍尔只有 0/1 → 拿不到力度 → 影响维度验收 |
| **铁质紧固件吸磁** | 用普通钢螺丝 | **改用铝/黄铜/尼龙/PLA 与非铁螺丝** |
| **飞线接触不良** | 间歇性、难复现故障 | **关键信号焊死、双绞 + 伴地回流**（已有实测教训） |
| **LED 纹波污染霍尔** | 选 WS2812 且走线松散 | **单色直流** 或走线**成对紧贴** + 远离霍尔 + 分时 |
| **串口屏污染演奏链路** | 误用屏做演奏输入 | **架构上强制分离**：屏只做 UI |
| **仿真器/IDE 版本不匹配** | 换 138K | 确认 Gowin IDE 版本与器件版本（B/C）选择正确 |
| **赛题合规风险** | 用 CPU 参与音频 | 音频通路**全部 HDL**；现场演示**不给 CPU 上电** |
| **吞吐量得分被误解** | 靠拉高采样率刷分 | 全员明确：**得分 = 活跃振荡器数 × 采样率，过采样不加分** |

## 附录 A · 术语表（给非硬件队友）

| 术语 | 一句话解释 |
|---|---|
| **DDS** | 直接数字频率合成，用相位累加器产生波形，音高精度高、切换快 |
| **ADSR** | 音符包络：起音 / 衰减 / 保持 / 释放 |
| **Voice** | 一个可独立发声的合成单元；复音数 = 同时能响的 Voice 数 |
| **磁轴** | 键盘用机械轴，内部带磁铁；配霍尔传感器测行程 |
| **线性霍尔 / 数字霍尔** | **线性霍尔输出随磁场连续变化的模拟量**（才能得到连续行程与力度）；数字霍尔只输出 0/1 |
| **颤音 Vibrato** | 音高的低频周期调制（典型 4～7 Hz），听感上是"揉弦" |
| **滑弦 Glissando** | 音高连续滑动，听感上是"抹过去"，与颤音是两种不同动作 |
| **双压插值** | 相邻两轴按行程比例插值算出准连续位置 |
| **行程仲裁** | 同列上下同时受压时，比较行程，大者为主音 |
| **BSRAM** | FPGA 内块状存储，效果器延迟线的主要消耗 |
| **I2S** | 数字音频串行总线（BCLK / LRCLK / DATA） |
| **Lissajous** | 李萨如图形，用两路信号互绘形成的可视化图形 |
| **确定性延迟** | 延迟有上界且可预测，不随负载抖动 —— 比"平均延迟低"更重要 |

## 附录 C · 历史决策留档（FSR 时代，**已作废**，仅供追溯）

> 📌 **以下内容全部不再有效**，保留是为了让队友理解为什么方向变了。**不要据此刻画任何现行方案。**

**v1.0 曾主推：`FPGA + FSR + 长条电容滑条 + 简单拨弦 + PCM5102A + 串口屏`**

| 角色 | 器件 | 职责 |
|---|---|---|
| 力度 / 触发 | FSR | Velocity、Note ON |
| 连续音高 | 电容滑条 | Pitch / Bend / Vibrato |
| 拨弦触发 | 微动开关 | Pluck Trigger |
| 第三维度 | 旋钮 | Filter / Timbre / Effect |

**为什么全部推翻（四条，全错）**：把 FSR 当成了「结构简单又便宜」的选项，但
① FSR **是买来的外购薄膜、不能 3D 打印**（机械验证阶段根本无法验证手感）
② 单价 **≥7 元/个**，**比磁轴更贵**
③ **对电容的干扰最大**（导电膜屏蔽电场 + 压力形变与位置**动态耦合**，**标定不掉**）
④ 与磁轴组合属**重复投入**（磁轴行程本身已提供力度）

**⭐ 通用教训：推荐方案前必须先确认「这个器件能不能被当前阶段的验证手段验证」。**

**其他已撤回的结论**

| # | 曾写过 | 更正 |
|---|---|---|
| 1 | 磁轴卡顿 = 数字霍尔只有开关量 | ❌ 那是**数据**问题，不是**手感**问题 |
| 2 | 磁轴卡顿 = 轴体/打印件公差 | ❌ 磁轴本身按着是可接受的 |
| 3 | **正确结论**：卡顿 = **跨面过渡** | ✅ 四根因：高度差 / 接缝台阶 / 摩擦突变 / **必须先抬手** |
| 4 | 「凡靠手指移动切换的操作必须同平面」 | **收窄为只约束"同一只手"** |
| 5 | 用「略高的键帽做定位锚点」 | ⛔ **撤回** —— 高度差是禁忌 |
| 6 | 「空位键装哑键省 2 通道」 | ⛔ **撤回** —— **16 轴位全部装霍尔**，改为映射「下方同音」做容错 |
| 7 | 旧规则「排间距 6～8 mm」 | ⚠️ **仅适用于"单排 X + Y 调制排"**；双排音高键必须 **12～15 mm** |
| 8 | 假设主时钟 100 MHz | 实测 **50 MHz** → 1041 clk/sample（不是 2083） |
| 9 | 电容「音高连续性」给 5 分 | **改为 4 分** —— 电容**也是离散电极 + 插值**，差别只是**等效分辨率** |
| 10 | 「IO 是硬约束」 | **IO 不是硬约束**（只是焊接不便） |
| 11 | 「FSR 比磁轴贵」作为否决理由 | **降级为参考** —— **不以价格定方案，以效果定方案** |
| 12 | 「拉高采样率可刷分」 | ❌ **吞吐量 = 活跃振荡器数 × 采样率，过采样不叠加加分** |
| 13 | 「不用 CPU 就等于被 CPU 占的脚可用」 | ❌ **实证 `J14.12 → R19` 被 P&R 判为 CPU 专用脚** |
| 14 | 「大厂键盘都是 WS2812」 | **幸存者偏差**（100 灯全白 = 6 A） |
| 15 | 颤音可由磁轴行程承担 | **修订为「颤音是独立模块」**（推子 / 电容条） |
| 16 | 担心右手"拨弦 + 颤音"过载 | **不存在** —— 有颤音就不用拨弦，两者二选一 |
| 17 | 把「原型打样成本/排期」当考量 | **移除** —— 打印机自有 |
