## 二、产品形态（✅ 已全部拍板）

| 项 | 决定 |
|---|---|
| **形态** | ✅ **分体式** —— 主体只留演奏区；**屏走串口线引出**；**旋钮/编码器另划一小块板** |
| **使用姿态** | ✅ **放桌上（坐演）**；📌 后续可选"琴颈式抱持"变体 |
| **模式** | ✅ **键盘 / 指板可切换**（同一物理网格 + 两套映射表）；**默认指板·差八度** |
| **参数面板** | ✅ **按参数性质分工**：**模糊量**（大小/多少）→ **编码器/电位器**；**精确量**（频率/数值）→ **串口屏** |
| **可视化** | ✅ **串口屏调参 + 显示**（自带曲线波形控件）；⏸️ **HDMI 后置**（答辩加分项） |
| **定位方式** | ⛔ **绝不用键帽高度差** → 只能靠**颜色 / 纹理 / 刻印 / LED** |
| **"自动"功能** | ✅ **要** —— 赛题拓展要求 4「脱机演奏 LED 曲目指引」本质需要**曲目/节拍引导引擎** |

## 三、⭐ 六个功能 → 物理来源（映射表）

| # | 功能 | ✅ **物理来源** | 怎么用 |
|---|---|---|---|
| **1** | **选音（音高）** | **左手磁轴的位置** | 16 轴位 → 离散音高；相邻两轴**双压插值**成准连续 |
| **2** | **触发 / 拨弦** | **右手拨弦件**（⬜ 形态待定，见 §八） | 边沿事件，**延迟最敏感** |
| **3** | **力度** | **左手磁轴的行程** | **触发瞬间取值**（采样保持）；⚠️ 建议用**双阈值测速法** |
| **4** | **滑音** | **左手磁轴的横向移动** | 位置**连续变化**即滑音（与"选音"同一路，靠"连续 vs 跳变"区分） |
| **5** | **颤音** | **右手推子** | 推子行程 → **颤音深度**；速率由 FPGA 内 LFO 固定 **5～6 Hz** |
| **6** | **LED 演奏指引** | **键帽下方灯珠** | 输出，不进演奏通路 |

> **一句话读法**：**左手管"哪个音 + 多用力 + 滑过去"；右手管"什么时候响 + 揉多狠"；灯只管指路。**

**三个控制功能**（不产生音符）：`模式切换`／`起始音选择` → **串口屏**；`参数调节` → 按模糊/精确分工。

## 四、系统架构

```text
┌────────── 演奏输入 ──────────────────────────────────────┐
│  左手区（磁轴 2×8）      右手区            辅助控制        │
│  选音 · 力度            拨弦 · 颤音（互斥） 编码器/按键     │
└──────┬────────────────┬──────────────────────┬───────────┘
       ▼                ▼                      ▼
┌────────── 信号调理与采集（★ 就地数字化）─────────────────┐
│ 16 霍尔→ADC①(8ch)  推子/电位器→ADC③    数字输入去抖      │
│ 16 霍尔→ADC②(8ch)  拨弦件→0/1 GPIO                      │
│        └──── 共用 SPI 总线（SCLK/MOSI/MISO）+ CS1/CS2/CS3 ┘
└───────────────────────┬─────────────────────────────────┘
                        ▼
╔══════════ FPGA · 实时合成核心（全部 HDL 实现）═════════════╗
║ ① 输入接口层   采样时序 · 通道扫描 · 标定与滤波            ║
║        ▼                                                 ║
║ ② 事件与参数层 音符/触发/拨弦事件 · 表情与音色参数  ──────╫─→ 串口屏 UI（UART，非演奏通路）
║        ▼                                                 ║
║ ③ 合成引擎层   Voice 管理 → DDS/波形 → ADSR → 混音 → 效果器║
║        ▼                                                 ║
║ ④ 输出接口层   音频串行 · 显示数据 · 灯光数据流            ║
╚═══════╤═══════════════╤════════════════╤═════════════════╝
        ▼               ▼                ▼
   音频输出         可视化           LED 演奏指引
   I2S→DAC→音箱     串口屏(+HDMI后置)  灯光驱动 → 灯珠
```

**两条不可违反的结构原则**

| # | 原则 | 原因 |
|---|---|---|
| **1** | **演奏链路与 UI 链路必须分离** | 串口屏延迟不可控，**不能进 ≤5 ms 确定性通路** |
| **2** | **左手区 / 右手区 / 颤音模块互相独立** | 由不同手或不同动作操作 → **不必共面、可以分板** |

> ⭐ **② 层的「事件 / 参数分离」是架构关键**：
> **事件**（选音、触发、拨弦）→ Note Manager，驱动 Note ON/OFF；
> **参数**（力度、颤音、表情、音色）→ Parameter Manager，**持续调制、永不产生音符**。
> 这是"误触发"问题的**结构性解法**，不依赖算法判断。

## 五、硬件方案（✅ 采集链已定案）

### 5.1 左手区（M1 定稿）

| 项 | 决定 |
|---|---|
| **布局** | **2 行 × 8 列 = 16 轴位**，上下**严格对齐** |
| **结构** | 两块 **2 行 × 4 列** 板左右拼成；每块约 **60 × 40 mm** |
| **列间距 / 排间距** | **15 mm** / **12～15 mm**（⚠️ 不是 6～8 mm） |
| **两排高度** | **严格等高，不做台阶** |
| **跨缝** | 左板右留 **8** / 右板左留 **7** → 紧贴后 **15 mm**；成品轴中心跨距 **105 mm** |
| **打板** | 两块**上下拼成 60 × 80** → 落在 100 × 100 内 |
| **键帽** | 3D 打印矮帽：边缘大倒角 + 下缘开窗 0.6～0.8 mm + 顶面刻音名 |
| **分板三前提** | ① 一整块 3D 打印定位板统一固定轴体 ② 两半同厚同层同铜厚 ③ 同源拼版切出 |

### 5.2 采集链（✅ **已定案**）

| 项 | 决定 |
|---|---|
| **线性霍尔** | ⭐ **`HAL49E`**（3～6.5 V ✅ / 灵敏度 **min 1.7 mV/G** ✅ / 量程 ±600 G → **靠调间距化解** ✅）<br>备选：`HAL4904`（⚠️ 不好买） |
| **霍尔供电** | ✅ **3.3 V 单电源**（不需要 5 V 轨、不需要电平转换） |
| **ADC** | ⭐ **`MCP3208` 类 8 通道 12 bit SPI × 3 片 = 24 通道**，3.3 V 单电源 |
| **采样率** | **每通道 2 kHz** 为目标（可轻松提到 4 kHz） |
| **模拟前端** | ✅ **不需要分压、偏置、5 V 轨、电平转换、双电源 ADC** |
| **原理** | ⭐ **「就地数字化」** —— 模拟量在传感器板上转数字，**长线只走 SPI 数字** |
| **通道分配** | 左手区 16（2 片）+ 右手区推子/电位器（1 片）→ **3 片** |

> 📌 **关键认知**：**多通道 ADC 内部本身就是「N:1 mux + 一个 SAR」** ——
> 所以"就地数字化"**不是"不用多路复用"**，而是**多路复用发生在芯片内部**，
> **自动规避了外置 mux 的 Ron 分压、建立时间、额外器件等全部麻烦**。
>（详见 `硬件选型表.md` §`C1′`）

### 5.3 右手区

| 项 | 决定 |
|---|---|
| **颤音** | ✅ **右手推子**（10 kΩ 线性 B，行程 ≥30 mm，导电塑料）；行程 → **深度**，速率 FPGA 内固定 |
| **拨弦** | ⬜ **形态待定**（见 §八）—— 候选：自制摆杆+霍尔开关 / 摇杆+比较器 / 光电 |
| **互斥** | ✅ 拨弦与颤音**二选一触发**，演奏中不同时操作 |

### 5.4 音频输出（⬜ 待核实）

| 项 | 状态 |
|---|---|
| **接口** | ✅ **已定**：`BCLK / LRCLK / DIN / MCLK / DAC_MUTE / AMP_EN` 6 根一次留到位 |
| **DAC** | ⬜ **待核实板载音频能否直接用**（若能用则**整个模块省掉**） |
| **功放** | ⏸️ **暂缓不装**，接口预留不删 |
| **接法** | ⚠️ 接**有源音箱的 AUX IN**，**绝不接音箱 INPUT** |

### 5.5 电源（⬜ 待定，但方向已定）

| 铁律 | 说明 |
|---|---|
| 🔴 **模拟侧必须「Buck → LDO」两级** | 只上 Buck 给 DAC/传感器供电 = **一定听到嗡嗡声** |
| 🔴 **不要把电池 5 V 直接接 J14.1** | 会与板载供电冲突/反灌 → 电池只给外设 |
| **大电流回路就近去耦** | 每 LED 0.1 µF + 段级 10～100 µF + 体电容 1000 µF |
| ✅ **最稳 = 两路独立** | FPGA 板走 USB、外设走电池 |

### 5.6 接口速查（详见 `10-硬件/硬件接口总表.md`）

```text
J1  音频输出      5pin   I2S_BCLK / LRCLK / DIN / MCLK / MUTE / AMP_EN + 3V3 GND
J2  UI 串口屏     4pin   5V / GND / TX / RX
J3  左手区传感器 10pin   3V3 / GND×2 / SPI_SCLK / MOSI / MISO / CS1 / CS2 / I2C×2   ✅ 不用改
J4  拨弦          4pin   3V3 / GND / PLUCK_A / PLUCK_B        ✅ 本就是 0/1 接口
J5  右手区        6pin   3V3 / GND / SPI×3 / CS3              ✅ 针数不变，只改信号定义
J6  辅助控制      8pin   3V3 / GND / ENC_A / ENC_B / ENC_SW / KEY1 / KEY2 / GND
J7  LED 指引      8pin   3V3 / 5V / GND / SCL / SDA / DATA / CLK / LATCH  （最宽留）
J8  调试测试点     —     I2S×4 / DAC 模拟 / 传感器原始信号 / 电源
```

## 七、延迟预算（按通路分级）

| 通路 | 敏感度 | 分配 |
|---|---|---|
| **触发 / 拨弦 → 发声** | 🔴 最敏感 | 拨弦件（µs～1 ms 级） |
| **选音 / 音高** | 🟠 敏感 | 磁轴（**2 kHz 采样 = 0.5 ms 周期**） |
| **力度** | 🟡 中 | 磁轴行程（**触发瞬间取值**） |
| **颤音 / 调制** | 🟢 **不敏感** | 推子（4～7 Hz 低频，几十 ms 听不出） |
| **可视化 / LED** | ⚪ 无要求 | 串口屏 / LED |

> ➡️ **原则：把"延迟不确定"的器件，分配到唯一不敏感的通路上。**
> ⚠️ **但结构连续性优先级更高** —— 跨面卡顿**每次演奏都遇到**，电容延迟只是理论风险。

## 十、⭐ 三条贯穿全局的设计铁律

| # | 铁律 | 出处 |
|---|---|---|
| **1** | **同一只手要移动来切换的操作，必须同一个平面、同一高度**（⛔ 任何键帽高度差都不允许） | 实测：跨面移动明显卡顿 |
| **2** | **能用物理正交解决的，不要用算法解决** | 算法分离需 200～300 ms 滑窗，**正好落在最敏感的音高通路上** |
| **3** | ⭐ **「间距」是唯一的量程 / 阈值调节旋钮** | 磁轴霍尔、拨弦霍尔开关 —— **场强不够就移近，太强就移远** |

> 📌 另有三条**方法论**纪律（都是踩过坑换来的）：
> ① **设计用「最小值 / 最大值」，绝不用「典型值」**
> ② **"别人能用" ≠ "我们能用"**（开源键盘用数字霍尔，是因为他们不做连续力度）
> ③ **推荐方案前先确认"它能不能被当前阶段的验证手段验证"**（FSR 就是这么被否掉的）
