## 三、核心评分规则与现场验证

### 3.1 振荡器统计规则

原文：独立发声单元 = 独立相位累加器 + 频率调控 + 包络控制；单波表采样查表不计多谐波数量，仅计单个振荡器；加法合成按运算分量、FM 按调制运算器、物理建模按并行弦/模态单元统计。

| 项 | 现状 | 判定 |
|---|---|---|
| 独立相位累加器 | 每 lane 一个（64 个） | 满足 |
| 独立频率调控 | 每 lane 独立增量（失谐 lane 加 `base_inc >> DETUNE_SH`） | 满足 |
| 独立包络控制 | **每 voice 一个 ADSR（32 个），两个 lane 共享** | 部分满足 |
| 波表路线 | 单周期波表查表，按规则只计 1 个振荡器 / voice | 满足（但吞吐量口径吃亏） |

可申报口径：

| 口径 | 振荡器数 | 吞吐量（× 实际采样率 48828.125 Hz） |
|---|---|---|
| 保守（按 voice 计） | 32 | 1.5625 M 振荡器·样本/秒 |
| 激进（按 lane 计，需澄清包络共享是否允许） | 64 | 3.125 M 振荡器·样本/秒 |

结论：保守口径可立即申报；激进口径需要向组委会确认"共享包络的失谐副本是否计为独立振荡器"。

### 3.2 系统吞吐量指标

原文：以「同时活跃可闻独立振荡器总数 × 实际音频输出采样率」为核心评分依据，过采样不叠加加分。

现状：`fs = 50 MHz ÷ 1024 = 48828.125 Hz`；Test Mode 32 档即最坏负载，`deadline_fault`（A6）判据保证每帧 1024 时钟内渲染完成。提高 `fs` 无收益（需同步提高振荡器数）。

### 3.3 现场验证：Test Mode

原文：测试模式下输出多路不同频率音频，频谱可观测对应数量独立谱峰，并可通过 RTL 代码佐证纯硬件实时合成通路。

| 要求 | 现状 | 判定 |
|---|---|---|
| 同时输出 N 路不同频率 | `test_mode_ctrl` 已实现，N = 4/8/16/32，频率为 FFT bin 对齐（`80 + 117v`） | 已实现 |
| 频谱可数出 N 个独立谱峰 | `sim/test_mode_fft.ps1` 判据：四档谱峰数精确为 4/8/16/32（当前用第 9 张专用纯正弦表保证） | 已实现并验证 |
| 分档可切换、可复现 | 串口 `M` 循环 4/8/16/32；串口屏控件 2 亦可 | 已实现 |
| **屏幕上显示「当前振荡器数 = N」与各路频率** | 无显示（`active_n_o` 仅在 RTL 内，未接显示） | **未实现** |
| RTL 可佐证（无预录） | 架构合规；波表为单周期表，无 PCM 播放路径 | 具备，但缺少便于展示的标注 |

补充结论：Test Mode 需按「正式功能」标准交付（决赛现场会重新测），当前功能已在，缺的是**可读标注**。

### 3.4 官方合规口径（2026-09-19 主办方答复）

| 要点 | 对我们的约束 |
|---|---|
| 音频与视觉效果部分不得使用软核 / MCU | 音频通路已是全 HDL；**HDMI 可视化的"生成"也必须在 FPGA 内**，屏只做搬运显示 |
| 专用状态机 / 串行算法加速器不算软核 | `tlc5916_driver`、`mcp3208_driver`、`i2s_tx` 等均为专用状态机，可全额计入 |

## 七、结论

1. **基础要求**：功能已覆盖，唯一缺口是**延迟证据**（`U-5`）。
2. **拓展要求**：复音规模与音色已达标；**效果器与可视化两项完全空白**，且都是评分项点名的内容。
3. **已实现的效果**共 17 类（见 §四），其中失谐叠加、按音色 ADSR、复音归一化去拉链、软膝限幅为近期新增。
4. 下一步优先级：效果器（延迟起步）→ 可视化（HDMI 出图 → 波形 → 李萨如 → 频谱）→ 延迟预算 → Test Mode 标注 → 实时变调 → LED 指引。
