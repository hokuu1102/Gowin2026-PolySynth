## 〇、🔴 先说清楚：哪些**不需要**现在讨论

## 五、⭐ 化解：用"预留"把「不必现在决定」变成「不用决定」

> **这是本清单最重要的一节。** 很多事之所以纠结，是因为**默认必须二选一**；但按项目已有的「接口按最宽形态预留」原则，**可以先不定，靠预留覆盖**。

| 不确定的事 | 化解方式 | 结果 |
|---|---|---|
| FPGA **60K 还是 138K** | 先定 **外设清单**（§三）。只要外设定了，**平台只影响"能不能多做一个效果器"** | **不必现在定** |
| **复音数 / 效果器**最终做到多少 | PCB 上**预留 SRAM/PSRAM 焊盘位**（不装）→ BSRAM 不够时插上即可 | **不必现在定** |
| **LED 驱动方式**（595 / I2C / WS2812） | **J7 已按最宽留 8 pin** → 四种驱动都不改板 | ✅ 已化解 |
| **ADC 走外部还是片内** | ✅ **已定：走外部（就地数字化）** —— 每块传感器板一片多通道 SPI ADC；`C1′`/`C2` 已否决 | ✅ 已定（理由见 `硬件选型表.md` `C1′`） |
| **要不要内置功放/喇叭** | **保留 `AMP_EN` + 喇叭焊盘**，不装模块 → 后期插上 | ✅ 已化解 |
| **颤音器件用推子还是电容条** | **J5 与 J3 同构** → 两者可互换，不用改架构 | ✅ 已化解 |
| **后期是否加传感器/按键** | **J10 预留 6 根通用 IO** | ✅ 已化解 |
| **参数面板走屏还是实体按键** | ⭐ **J2（UART 4 线）+ J6（编码器/按键 8 线）都已留** → 两条路都能接，甚至可同时留 | ✅ 已化解 |
| **可视化走串口屏还是 HDMI** | ✅ **已定：两者分工并行** —— **串口屏走 UART**（调参 + 文字）、**HDMI 走 TMDS**（图形动画）。互不干扰，**都不在演奏通路上、都不影响延迟指标** | ✅ 已定（性能评估见 §九-2） |
| **屏 / 旋钮放哪** | ✅ **分体式**：屏走串口线引出、旋钮独立一小块板 → **不占主面板，位置自由** | ✅ 已化解 |

> 🔎 **关于 HDMI 的一条重要提醒（见 §三 可视化行）**：
> **整帧缓冲放不下。** 720p 24 bit = 1280 × 720 × 24 ≈ **22 Mbit**，而 **60K 的 BSRAM 只有 2.12 Mbit、138K 只有 6.12 Mbit** → **换任何器件都放不下整帧**。
> ➡️ 所以 HDMI 可视化**只能"按扫描线实时生成像素"**（波形/频谱直接由采样数据算出来），**不能做复杂图形叠加、大块滚动文字、多层半透明**。
> ➡️ 这属于**"可视化做到什么程度"**的问题（§六 后置项），**不影响产品形态**。

> ➡️ **推论：本清单真正"必须现在拍"的，其实只有 §一～§四 那几组。**
> ✅ **2026-09-13 更新：§一～§四 + §七 已全部拍板，唯一剩下的是「六个功能 → 物理动作」的映射表（§七 第 4 行）。**

### A2 · ⚠️ 触发器件：延迟对比（**回答"哪个延迟最低"**）

| 方案 | **延迟** | 有"拨"的动作感？ | 抗环境 | 复杂度 | 评价 |
|---|---|---|---|---|---|
| **光电遮断（+ 竖直摆动挡片）** | ⭐ **最低（< 0.1 ms）** —— 光电器件响应 µs 级，**无触点弹跳、不需要去抖** | ✅ **最像"拨"**（挡片摆动遮光） | ⚠️ 怕环境光 / 积灰 | 中（需遮光结构） | ⭐ **延迟最低，动作最贴合"拨弦"** |
| **摇杆/拨片 + 霍尔** | 中（≈ **1 ms**，受 ADC 采样周期限制） | ✅ 像"拨" | ✅ 不怕光灰 | 中 | ⭐ **与磁轴同原理、器件可统一**；还能测方向与幅度 |
| **微动开关** | 🔴 **最高（去抖 1～10 ms）** | ❌ 是"按"不是"拨" | ✅ | 最低 | ⚠️ 动作不像拨弦，且有触点磨损 |
| （退路）复用左手磁轴越过触发点 | ≈1 ms（ADC 周期） | ❌ 无 | ✅ | 零（不装件） | ⚠️ 会让"触发"与"选音"耦合 → **变成键盘逻辑** |

> **答"哪个延迟最低"：光电遮断最低（µs 级）** —— 比磁轴阈值判定快约一个数量级，比微动快两个数量级（**微动慢在去抖**）。
>
> ⭐ **而"能竖直摇摆的东西"和光电是绝配** —— 一个可摆动的**挡片/摇杆**遮断光路：
> - **两组光电对管** → 可区分 **上拨 / 下拨**（方向）
> - ⭐ **遮挡深度是连续的** → **还能顺带得到"拨弦力度"**（模拟量）
> - 无触点、无磨损、几乎零延迟，**动作本质就是"拨"** → **物理一致性最好的方案**
>
> ⚠️ **代价与缓解**：① 需**遮光罩**防环境光（最主要）② 积灰敏感 ③ 光轴对齐的装配精度
> 📌 **若怕环境光/积灰** → 选**摇杆 + 霍尔**（同原理、器件与磁轴统一、不怕脏），代价是延迟回到 ~1 ms（仍够用）

### A2b · 摇杆：**两类摇杆的优劣，以及"普通摇杆精度够不够"**

> **先修正一条判据**：⚠️ **光电「延迟最低」这个优势在本项目几乎不产生收益** ——
> 赛题预算是 **≤10 ms（拓展 ≤5 ms）**，而**磁轴阈值判定 ≈1 ms、光电 ≈0.1 ms**，**两者都远在预算内、人耳听不出差别**（人耳约从 10 ms 量级才敏感）。
> ➡️ **判据应换成：手感像不像"拨"、可靠性、装配难度、与现有器件统不统一。**

| 维度 | **电位器摇杆**（普通） | **霍尔摇杆** |
|---|---|---|
| 原理 | 两个电位器分压 + 弹簧回中 | 两个**线性霍尔** + 摇杆上的磁铁 |
| **磨损** | ⚠️ **有**（摇杆是**高频往复**件，磨损远快于推子） | ✅ **无接触** |
| **寿命/漂移** | ⚠️ 用久会出现**死区 / 漂移 / 抖动** —— 这正是手柄"摇杆漂移"的根源 | ✅ 不会漂移（**手柄改用霍尔摇杆正是为了消除它**） |
| **输出线性度** | ✅ 好（电位器本身近似线性分压） | ✅ 好（需标定零点/增益） |
| **精度** | ✅ 够 | ✅ 够 |
| 噪声 | ⚠️ 碳膜有"爆米花噪声"，磨损后接触不良 | ✅ 低 |
| 温度漂移 | ✅ 小（比例式分压） | ⚠️ 有（可标定，与磁轴同方法） |
| 磁场干扰 | ✅ **不受磁场影响** | ⚠️ **受磁场干扰**（但要留意附近 LED 电流；摇杆在右手区、磁轴在左手区，距离远） |
| 标定 | ✅ 基本不用 | ⚠️ 需零点 + 增益标定 |
| 成本 | 便宜（几元） | 略贵 |
| ⭐ **与项目契合** | 通用 | ⭐ **与磁轴同技术** → **器件/算法/标定方法全部可复用** |

#### ⭐ 回答"普通摇杆精度够吗"：**精度上完全够** —— 因为**拨弦本质是「事件」，不靠精度**

| 理由 | 说明 |
|---|---|
| **拨弦是事件型** | 只需"越过阈值"这一个判断 → **精度要求极低** |
| **力度维度已由磁轴承担** | 映射表第 3 项（力度）用的是**磁轴行程**，**摇杆不需要提供力度** |
| 就算要做"拨弦力度" | 12 bit ADC 对"0～30° 摆角"能分几千档，**远超需求** |

> ➡️ **所以真正的差别不在精度，而在「寿命 / 可靠性」。**
>
> ⚠️ **而寿命是真实风险**：摇杆是**每次弹都要拨**的高频往复件（推子只是偶尔调参数）→ 电位器磨损后出现**漂移/死区/抖动 → 会误触发，且极难排查**。
> - 调试期反复演奏 + 答辩现场，正是暴露这个问题的场景。

**建议**

| # | 建议 |
|---|---|
| 1 | **要长寿命/省心 → 霍尔摇杆** ⭐（与磁轴同技术，器件、标定、FPGA 算法全可复用） |
| 2 | **要快速验证手感 → 先用几块钱的电位器摇杆试**，确认"拨"的手感能接受后**再换霍尔摇杆** |
| 3 | ⭐ 前提：**两者的输出接口做成一样**（都是两路模拟量 + 供电）→ 换件不改板，符合项目"接口按最宽形态预留"的原则 |

### A2c · ⭐ 不应期会不会引入延迟？—— **不会，但要说清为什么**

```text
拨动 → 越过阈值 → 【立即触发事件】 → 然后锁定 N ms 不再接受新触发
                    ↑
              事件在这一刻就产生了（零额外延迟）
```

> **关键：不应期是「事后封锁」，不是「事前等待」。**

| | **去抖 / debounce** | **不应期 / refractory** |
|---|---|---|
| 做什么 | **等**信号稳定 N ms **之后才确认**触发 | **先触发**，然后封锁 N ms |
| **延迟** | 🔴 **引入 N ms 固定延迟**（必须等） | ✅ **零延迟**（事后封锁） |
| 用在什么信号 | **机械触点弹跳** —— 触点真的在反复通断，**无法判断哪次是真的**，只能等 | **真实的位置过冲** —— **第一次越阈就是真的**，后面的是弹簧回弹 |
| 本项目 | 🔴 微动开关需要（**这就是微动慢的原因**） | ✅ 摇杆 / 霍尔需要（回弹振荡） |

> ⭐ **一句话：去抖是"因为不知道哪次是真的，所以等一等"；不应期是"知道第一次就是真的，所以直接认，然后闭嘴"。**

**⚠️ 但有一个前提**：不应期"零延迟"成立，要求**能可靠识别出"第一次越阈"** ——
若信号在阈值附近有噪声抖动，可能在真正拨动**之前**就误越阈 → 那是**提前误触发**（比延迟更糟）。
➡️ 所以需要：① **信号干净**（模拟量走 ADC + 数字滤波）② **阈值带迟滞（施密特特性）**。

**对本项目的具体结论**

| 项 | 结论 |
|---|---|
| 触发时刻精度 | ✅ **只取决于 ADC 采样周期（≈1 ms）**，**不受任何时间窗影响** |
| 总延迟 | ≈ **1 ms**（ADC 量化）+ 极小的处理延迟 → **远在 ≤5 ms 预算内** |
| 要不要提速 | ❌ **不必** —— 1 ms 已足够；若要更快可提高该通道采样率或用模拟比较器做硬越阈，**但没必要** |

### A3 · ⭐ 颤音怎么映射（**回答"推子行程怎么用"**）

**一维推子只能承载一个量**，所以必须选：

| 候选 | 是否推荐 | 理由 |
|---|---|---|
| **推子行程 → 颤音「深度」**，速率由 FPGA 内 LFO 固定 | ⭐ **推荐** | **真实揉弦就是"频率基本恒定、幅度可变"** → 推得越多揉得越狠，最符合直觉 |
| 推子行程 → 颤音「速率」 | ❌ 不推荐 | 真实乐器不会靠揉弦速率表达强度 |
| 推子位置 → 音高**单向偏移**（= 弯音 / 摇把） | ❌ **赛题不需要** | ⚠️ 赛题拓展要求 2 点名的是「力度动态、**滑音**、**颤音**」，**没有"弯音"**；而**滑音已由磁轴横向移动提供** → 推子不必兼做弯音，否则与功能 4 重叠 |

> ⭐ **建议：模仿真实揉弦** —— **推子行程 → 颤音深度（0～1）；速率固定 5～6 Hz**（可给 2～3 档可选）。
> 这样"推得越多 = 揉得越厉害"，符合真实弦乐直觉，也最好讲（**答辩时一推就有效果**）。
>
> 💡 **进阶（不建议首版做）**：用项目已有的**频段分离**思路让一维推子载两用 ——
> **慢变（推子停在哪）= 弯音偏移；快变（手在推子上抖）= 揉弦**。最"真"，但复杂且赛题不需要。

**推子 vs 电容条 —— ✅ 倾向推子是对的**

| | **推子** | 电容条 |
|---|---|---|
| 延迟 | ✅ 确定 | ⚠️ 不确定（但颤音 4～7 Hz **对延迟不敏感**，两者都行） |
| 手感 | ✅ **有行程阻尼**，适合表达"深度" | ❌ 无行程 |
| PCB | ✅ **好画**（一个元件 + 分压） | ⚠️ 要画电极 |
| 磨损 | ⚠️ 有（选**导电塑料**而非碳膜） | ✅ 无 |

> **推荐参数**：**10 kΩ 线性 B 型，行程 ≥ 30 mm，导电塑料** —— 行程够长才揉得细腻。

### A4 · ⭐「力度」与「音量」的精确表述（**回答"百分比 vs 绝对值"**）

| | **力度 Velocity** | **音量 Volume** |
|---|---|---|
| 作用范围 | **逐音**（per-voice） | **全局**（master） |
| 取值时机 | **触发瞬间锁定，之后不变** | 随时可变 |
| 数学位置 | **音内部的系数** | **乘在总输出上** |
| 对应"百分比 / 绝对值" | ✅ **"每个音自己的相对比例"** | ✅ **"整体的绝对增益"** |

```text
最终输出 = Σ( 每个音的波形 × 该音的力度系数 × 该音的包络 ) × 总音量系数
            └────────── 逐音 · 相对 ──────────┘          └ 全局 · 绝对 ┘
```

**两个关键推论**

1. **两路必须完全分开** —— 这正好是架构里「**事件 / 参数分离**」的一个实例：**力度跟触发事件绑定**（属音符的一部分），**音量是纯参数**（进 Parameter Manager）。
2. ⚠️ **力度只调振幅会"只是变响"，不像"用力弹"** —— 真实乐器越用力**音色越亮**（谐波更多）。所以力度最好**同时**映射到 ① 振幅 ② 包络 attack 快慢 ③ 音色亮度/滤波。
   📌 **但这是 FPGA 侧的事**；**硬件侧的职责只有一条：给出一个连续、单调、稳定的行程量**。
   ⚠️ 另外力度→振幅通常要**查表做曲线**（人耳对响度是对数感知），不是直接线性相乘。

### A5 · WS2812 的"磁通量"顾虑 —— **方向对，但关键不在量级**

| 项 | 数值 / 说明 |
|---|---|
| LED 芯片本身 | **不含铁磁材料 → 对霍尔几乎无直接影响** |
| 真正的干扰源 | **驱动电流产生的磁场**：`B = μ₀·I / (2πr)` |
| **量级** | WS2812 全白 12 灯（≈720 mA）@5 mm ≈ **2.9 Gauss**；**单色 12 灯（≈120 mA）≈ 0.5 Gauss** |
| 对比信号 | 霍尔要测的**磁铁磁场有几十～几百 Gauss** → 干扰只占 **~1%** |
| ⚠️ **决定性差别** | **不是量级，而是"能不能标定掉"**：<br>**静态直流** → ✅ **上电基线标定可消除**<br>**PWM 交流纹波** → ❌ **标不掉**，产生与 PWM 频率同步的**周期性读数抖动**<br>**WS2812 只要灯亮就持续有纹波**（内部恒流 + PWM 调光）→ **常驻干扰** |

**为什么开源社区用 WS2812 没事？**

| 原因 | 说明 |
|---|---|
| **多数开源键盘用「数字霍尔」** | 只要 0/1 阈值判断，**纹波引起的抖动根本不影响** |
| **而本项目用「线性霍尔做连续行程→力度」** | 对读数稳定性要求**高一个数量级** → ⭐ **别人能用 ≠ 我们能用** |
| LED 与霍尔距离较远 | 按 `1/r` 衰减 |
| 不追求精度 | 只要灯好看 |

> ⭐ **这正是项目既有教训的又一次印证：推荐方案前先确认"它能不能被当前阶段的验证手段验证"。**
> 这里的判据极其简单便宜：**点亮灯，看霍尔读数抖不抖。**

**结论**

| # | 结论 |
|---|---|
| 1 | ✅ **已定：单色**（2026-09-13 已确认）—— 对霍尔最友好 |
| 2 | ⭐ **单色 + 直流恒流驱动（不做 PWM 调光）→ 理论上零纹波**，对霍尔最友好 |
| 3 | 若要 RGB → 优先 **I2C 驱动 IC**，⚠️ **但恒流 IC 也是 PWM 调光、同样有纹波**，只是频率与走线可控 |
| 4 | **实测验证（<20 元、半小时）**：1 个霍尔 + 1 个灯，点亮看读数抖动 → **唯一可信的判据** |
| 5 | 措施排序：**① 去流与回流走线成对紧贴 ★★★ ② 远离霍尔（1/r）★★★ ③ 不与模拟走线平行 ④ 降电流/限亮 ⑤ 分时（避开 AD 采样窗）** |

### A6 · ⭐ 霍尔摇杆也走"就地数字化" —— **而且会改采集通道预算**

**结论：能，而且应该 —— 与磁轴完全同一套拓扑。**

```
霍尔摇杆（2 路模拟）──┐
推子（1 路模拟）──────┼──→ 右手区小板上的多通道 SPI ADC ──数字(SPI)──→ FPGA
面板电位器（1～2 路）──┘
```

#### ⚠️ 但发现一个规格缺口：**原定的 16 通道不够了**

| 模拟量来源 | 通道数 |
|---|---|
| 左手区磁轴霍尔 | **16** |
| 右手区霍尔摇杆 | **1～2**（用 1 个轴做拨弦；另一轴可留用） |
| 右手区推子 | **1** |
| 面板电位器（若有） | 1～2 |
| **合计** | **≈ 19～21 通道** |

> 🔴 **而 `硬件选型表.md` 的 `C1` 现在写的是「每块板 8 通道 × 2 片 = 16 通道」→ 不够。**
> ➡️ **行动：`C1` 的通道数要改（见 `硬件选型表.md`）。**

#### ⭐ 推荐做法：**右手区也做一块"带 ADC 的小板"**，与左手区对称

| 好处 | 说明 |
|---|---|
| ⭐ **器件统一** | 左手 2 片 + 右手 1 片 = **同一款 8 通道 ADC**（或换 16 通道） |
| ⭐ **拓扑统一** | 所有模拟量都在**所在的那块板上就地数字化**，`J3`/`J4`/`J5` 一律只走 **SPI 数字** |
| ⭐ **标定统一** | 霍尔摇杆与磁轴**同一原理、同一标定方法**（零点+增益），算法可复用 |
| **长线只走数字** | 与项目既有原则一致 |

#### ⚠️ 关于 `J5` 的 `MOD_ANALOG`（**含一处更正**）

> ✅ **更正（2026-09-13）**：**主板（底板）确实有 ADC** —— Sipeed Tang Mega 底板带 **2 路差分 ADC 输入**（即 FPGA 的**片内 ADC**）。此前写"主板没有 ADC"是错的。
>
> 但结论不变，**右手区仍然"就地数字化"更合理**，理由两条：
> 1. **只有 2 路** —— 远不够 17～21 路
> 2. **用它就要把模拟从右手区跨板送到主板** → **违背「长线只走数字」**；而且我们已否决片内 ADC 路线（`C1′`）
>
> 📌 **对 `J5` 的处理建议**：按"接口按最宽形态预留"原则，**保留 `MOD_ANALOG` 这根针做备用**（成本几乎为零），但**主路线不依赖它** —— 推子在**右手区小板上就地数字化**，走 SPI 数字回来。
>
> ⭐⭐ **2026-09-13 收口（更正）**：「**推子和摇杆就是放在右手板上的，所以第三片 `MCP3208` 也是放在右手板上**」
> ⇒ 第 3 片 ADC 从 **P1** 移到 **P4**，**`J5` 的 6 根针全部改成 SPI**（`3V3/GND/SCLK/MOSI/MISO/CS3`），**针数针位不变**。
> ⇒ ⚠️ 因此**没有余针再保留 `MOD_ANALOG`** —— 上面那条"保留做备用"**不再成立**（与 `files\30-方案决策\硬件选型表.md` §A6 的定案一致）。

### A7 · ⚠️⭐ 力度到底用「磁轴行程」还是「摇杆幅度」？—— **两个都留，但只让一个当力度**

#### 先说一个**两边都躲不开**的坑：力度的获取天然需要"观察一点时间"

| 方案 | 问题 |
|---|---|
| **力度 = 越过触发点时的行程值**（项目文档现写法） | 🔴 **可能力度恒定！** 因为触发点位置固定 ⇒ 每次越过它时的行程都≈该阈值深度，**与按得多快无关** |
| **力度 = 摇杆摆动的幅度** | 🔴 摇杆是**弹簧回中**的 ⇒ 幅度是**瞬态峰值**，必须"追峰"才能得到 ⇒ 要观察一个完整摆动过程 |

> ⭐ **两个正解（都不违反 ≤10 ms）**：
>
> | 解法 | 原理 | 代价 |
> |---|---|---|
> | **① 双阈值测速法**（经典 MIDI 做法） | 设**两个深度阈值**：越过浅阈值记时刻 `t1`，越过深阈值记时刻 `t2` → **`Δt` 越小 = 按得越快 = 力度越大** → **在越过第二阈值的瞬间力度就确定了，零额外延迟** ⭐ | **要求行程采样率够高**（`Δt` 的分辨率 = 采样周期） |
> | **② 起音不等力度** | **立刻起音**，力度在 **ADSR 的 attack 阶段内**（10～50 ms）确定后再修正包络峰值 → **感知上零延迟** | 需要包络支持"峰值动态修正" |
>
> ➡️ **建议：① + ② 结合**（双阈值给速度、attack 阶段内定力度）。
> ⚠️ **它反过来对硬件提了一个要求**：见下方"对 `C1` 的影响"。

#### 那到底谁来当力度？—— 对比

| 力度来源 | 物理含义 | 与触发的关系 | 优点 | 问题 |
|---|---|---|---|---|
| **磁轴行程** ⭐ | 按多深 / 按多快（**键盘逻辑**） | 与**选音同源**（左手） | ① **16 路都有** ② 行程是**稳态值**（比瞬态峰值好抓） ③ 与"键盘模式"契合 | 需要双阈值或时间窗才能表达"速度" |
| **摇杆幅度** | 拨多狠（**拨弦逻辑**） | 与**触发同源**（右手） | ① 物理上**最贴"拨弦"** ② 与触发**同一动作**，最自然 | ① 是**瞬态峰值**，要追峰 ② 摆角小，细腻度待实测 |

#### ✅ 我的建议：**磁轴行程 → 力度；摇杆幅度 → 触发的"真实性判据"（不当力度）**

| 分工 | 理由 |
|---|---|
| **磁轴行程 → 力度** | 稳态值好抓、16 路都有、与键盘模式契合 |
| **摇杆幅度 → 触发有效性判据** | ⭐ **同源同动作** —— "幅度真的超过阈值"才认为是一次**真拨弦**（把回弹抖动排除掉）→ **这正好落实了架构原则里的「事件 / 参数分离」**：摇杆出**事件**、磁轴出行程**参数** |
| **摇杆第 2 个轴** | 留作备用（可接 `J10` 的思路） |

#### ❌ 为什么不建议"两个都当力度"

| 理由 | 说明 |
|---|---|
| **赛题只要 ≥2 维（拓展 ≥3 维）** | 我们已有 **音高 / 力度 / 颤音** 三维 → 再加"拨弦力度"是**第 4 维，属过剩** |
| ⚠️ **会引入"两个力度源如何混合"的复杂度** | 需要仲裁规则（哪个优先？加权？），**收益却为零** |

> 💡 **如果你们就是觉得"拨弦力度"更真实** → 可做成**按模式切换**（**指板模式**用摇杆幅度做力度、**键盘模式**用磁轴行程）—— **零硬件成本**（FPGA 换映射表），但**FPGA 侧实现成本翻倍**，建议**后置**。

#### ⚠️ 对 `硬件选型表.md` 的 `C1` 的影响（**硬件侧要跟进的**）

| 项 | 影响 |
|---|---|
| **通道数** | 16 → **≈ 19～21**（见 A6） |
| **采样率** | ⚠️ 若采用**双阈值测速法**，`Δt` 的分辨率 = 采样周期 → **1 kHz/通道 只有 1 ms 步进，力度档位偏粗** → **可能要把磁轴通道提到 2～4 kHz** |
| 吞吐量核算 | 16 ch × 4 kHz = **64 ksps** —— 100 ksps 级 ADC 仍有余量 ✅，但**要重新算** |

### A8 · ⭐ 把拨弦做成「干净的 0/1」—— **两条路，而且 `J4` 已经支持**

> **前提**：既然力度由磁轴承担（A7），**拨弦只需要一个"事件"，不需要模拟量** → **可以彻底绕开 ADC**。

#### 两条路

| | **路 1：现成摇杆 + 外部比较器** | **路 2：数字霍尔开关（推荐）** |
|---|---|---|
| 做法 | 摇杆的模拟输出 → 比较器一端，另一端接参考电压 → 输出翻转成 0/1 | ⭐ **摇杆上装磁铁，旁边放「数字霍尔开关」芯片** → 磁铁靠近 → **芯片内部直接输出干净 0/1** |
| 需要什么 | 一片比较器（`LM393` 类，几毛钱）+ 分压电阻 | 只要**数字霍尔开关芯片**（如 `A3144` 类等） |
| 阈值 | ⚠️ 靠**硬件分压固定**，要改得改电阻；⚠️ 受器件离散与温漂影响 | ✅ **芯片内部自带比较器 + 迟豫**，出厂即定 |
| 标定 | ⚠️ 需要（阈值 + 摇杆零点漂移） | ✅ **不需要** |
| 延迟 | ⭐ **µs 级**（比较器传播延迟） | ⭐ **µs 级**（霍尔开关响应时间） |
| 用不用 ADC | ❌ 不用 | ❌ 不用 |
| 用几根线 | 1～2 根（加正反馈做迟豫可更稳） | 1～2 根（**两侧各放一个 → 上拨/下拨天然区分**） |
| 保留现成摇杆？ | ✅ **保留** | ⚠️ 需要自己装磁铁 / 或自制摆杆 |

> **路 1 要点**：比较器**必须加正反馈做迟豫（施密特特性）** —— 否则阈值附近的噪声会造成多次翻转。
> **路 2 精髓**：**"拨动件上的磁铁 + 旁边的数字霍尔开关"** ——
> **两个霍尔开关分列两侧 → 上拨触发 A、下拨触发 B → 2 根线，方向天然区分** ✅

#### ⭐⭐ 一个很漂亮的结论：**同一个项目里，两类霍尔各取所需**

| 用途 | 器件类型 | 为什么 |
|---|---|---|
| **磁轴（选音+力度）** | **线性霍尔** | 需要**连续行程** → 力度 |
| **拨弦（只要事件）** | **数字霍尔开关** | 只要 **0/1** → 数字霍尔**正好合适** |

> 💡 **项目早期曾否决"数字霍尔"，那是对磁轴而言的**（数字霍尔拿不到连续行程 → 毁掉力度维度）。
> **但对拨弦来说，数字霍尔恰恰是最优解** —— **同一类器件的两个变体，供应链熟悉、封装类似、外围电路几乎一样。**

#### ✅ 而且 **`J4`（拨弦接口）一个字都不用改**

现有 J4 定稿就是：**`3V3 / GND / PLUCK_A / PLUCK_B`** —— **本来就是给"微动 / 光电"这类 0/1 器件设计的**（`PLUCK_A`/`PLUCK_B` = 上拨 / 下拨）。
➡️ **改用「数字霍尔开关」或「摇杆 + 比较器」，`J4` 完全兼容，连针脚都不用动** ✅

#### 0/1 事件器件的横向对比

| 器件 | 输出 | 延迟 | 要 ADC？ | 要标定？ | 直觉性 | 寿命 | 复杂度 |
|---|---|---|---|---|---|---|---|
| ⭐ **数字霍尔开关**（+ 磁铁） | 干净 0/1（内置比较器+迟豫） | ⭐ **µs 级** | ❌ | ❌ | ⭐⭐ 拨动即触发 | ✅ 无接触 | ⭐ 低 |
| **线性霍尔 + 外部比较器** | 0/1 | ⭐ µs 级 | ❌ | ⚠️ 要设阈值 | ⭐⭐ | ✅ | 低 |
| 光电对管 + 比较器 | 0/1 | ⭐ µs 级 | ❌ | ⚠️ 阈值+遮光 | ⭐⭐⭐ 最像"拨" | ⚠️ 怕灰 | 中 |
| 磁簧开关（Reed） | 干接点 0/1 | ⚠️ 机械 0.5～2 ms + **要去抖** | ❌ | ❌ | ⭐⭐ | ⚠️ 玻璃管怕冲击 | 极低（**且无需供电**） |
| 微动开关 | 0/1 | 🔴 **去抖 1～10 ms** | ❌ | ❌ | ❌ 是"按" | ⚠️ 磨损 | 极低 |
| （参考）线性霍尔 + ADC | **连续量** | ≈1 ms | ✅ **要** | ⚠️ 要 | ⭐⭐ | ✅ | 中 |

> ➡️ **推荐：数字霍尔开关**（最省事：不要 ADC、不要比较器、不要标定、无磨损、µs 级）
> ➡️ **若想保留现成手柄摇杆** → **摇杆 + 外部比较器**（改动最小）
> ⚠️ **两条路都仍需「不应期」** —— 摇杆回中时的弹簧振荡会造成多次翻转，用 20～50 ms 不应期解决（**不影响触发时刻，见 A2c**）。

#### ✅ 连带好处：**采集通道数回落**

| 模拟量来源 | 通道数 |
|---|---|
| 左手区磁轴霍尔 | 16 |
| 右手区**推子**（仍是模拟） | 1 |
| 面板电位器（若有） | 1～2 |
| ~~拨弦~~ | **0**（走 0/1 GPIO，不占 ADC） |
| **合计** | **17～19**（原估 19～21 已含拨弦的 2 路） |

> 📌 仍建议**按 24 通道预留**（3 片 8 通道，或 1×16 + 1×8），留余量不吃亏。

## 九、技术评估（对应 §七 第 5、7 行）

### 九-1 · 串口屏做参数面板的难度：**中低（主要是人力成本，不是技术风险）**

| 维度 | 评估 |
|---|---|
| **FPGA 侧工作量** | **小** —— 一个 UART 收发 + 一张指令表。**显示部分（字库、画点、触摸扫描）全由屏自己搞定**，FPGA 不用碰 |
| **屏侧工作量** | 用屏厂的**组态软件**画界面、绑控件 → **学习成本**在软件使用，不在技术 |
| **协议** | 建议用**屏厂协议**（文本指令，如 `page` / `t0.txt=` / `n0.val=`），上手快；自定义协议省 FPGA 但屏侧难做 |
| **⚠️ 真正的限制：带宽** | 串口屏走 UART，**115200 bps ≈ 11.5 KB/s**：<br>• 一屏 **20 个数值**更新 ≈ 300 字节 → **约 26 ms/帧** ✅ 够<br>• 画**波形曲线**（100 点 × 4 字节 = 400 字节）→ **约 35 ms/帧 ≈ 28 fps** 🟡 勉强<br>➡️ **结论：串口屏适合"数值 / 文字 / 按钮"，不适合"高频图形动画"** |
| **其他** | ⚠️ 串口电平待核实（5 V TTL / 3.3 V）；🔴 **延迟不可控 → 绝不进演奏通路**（已定） |

> ✅ **所以 §七 第 6 / 7 行的分工是对的**：把**文字数值**留给串口屏、把**图形动画**交给 HDMI —— 各自干自己擅长的事。

### 九-2 · 串口屏调参 + HDMI 可视化：**硬件性能够，但"可视化程度"和"分辨率"要选对**

**先说结论**：
> ✅ **够用，但要分清"逻辑资源"和"BSRAM"—— 真正的瓶颈是逻辑（FFT），不是内存。**
> ⚠️ **而且这会成为选 138K 的第二个理由**（第一个是 BSRAM → 效果器）。

**(a) HDMI 需要的资源**

| 项 | 说明 | 消耗 |
|---|---|---|
| **像素时钟** | 720p@60 = **74.25 MHz**；1080p@60 = 148.5 MHz；640×480@60 = **25.175 MHz** | 需 **PLL**（60K 有 8 个 ✅ / 138K 有 12 个 ✅） |
| **⚠️ 时钟来源** | 板载 **50 MHz** → 74.25 MHz **不是整数分频** → 需 PLL 倍频；**用低分辨率（25.175 MHz ≈ 50/2）反而回避这个问题** | — |
| **TMDS 编码** | 3 通道 × 8b/10b | 中（几百 LUT） |
| **专用 IO** | TMDS 差分对需要专用输出原语 | ✅ **Sipeed 底板自带 DVI/HDMI 口**，已按 TMDS 布线 |
| **🔴 帧缓冲** | ⚠️ **整帧放不下** —— 640×480×24 bit = **7.4 Mbit**（60K 只有 2.12 / 138K 只有 6.12） | ➡️ **必须按扫描线实时生成像素，不能存整帧** |
| **实时生成可行性** | **波形/频谱天然适合实时生成**（扫到哪列就算出该点的 y 值） | ✅ |

**(b) 三种可视化的代价（从省到贵）**

| 可视化 | 额外存储 | 额外逻辑 | 评价 |
|---|---|---|---|
| **Lissajous（李萨如）** | 几乎为零（只要 2 个采样值） | **极小** | ⭐ **最省，且视觉最"炫"，建议第一个做** |
| **波形显示** | 一行缓冲（512 点 × 16 bit ≈ **8 Kbit**，可忽略） | 中 | ✅ 好做 |
| **频谱（FFT）** | 频谱缓冲 ≈ **4 Kbit**（可忽略） | 🔴 **大** —— FFT 是逻辑与乘法器大头 | ⚠️ **最后做，且是选 138K 的潜在理由** |

**(c) 建议**

| # | 建议 |
|---|---|
| 1 | **分辨率走 640×480 或 800×600**，别上 1080p（时序压力大，反正也不存帧） |
| 2 | **先做 Lissajous → 再做波形 → 最后才考虑频谱** |
| 3 | **BSRAM 不是瓶颈，逻辑/乘法器才是**（频谱的 FFT） |
| 4 | ⚠️ **这条与平台选择耦合**：若要做频谱 → 逻辑需求上升 → **倾向 138K** |
| 5 | **先核实手中板有没有引出 HDMI**（Sipeed Tang Mega 60K/138K 底板自带；若是高云官方基石板则需另查） |

### 九-3 · ⭐ 串口屏（淘晶驰 TJC **X2 7 寸**）评估 —— **结论：能做，而且比预期更强**

> 资料：`http://wiki.tjc1688.com/` ｜ ⚠️ 该 wiki 用 **HTTP**（HTTPS 会失败）

#### ① FPGA 实现难度：**低（属"小模块"级别）**

| 理由 | 说明 |
|---|---|
| **不用写屏驱动** | 字库、画点、触摸扫描**全由屏内部处理**，FPGA 完全不碰 |
| **协议极简** | 文本/16 进制**指令**，如 `t0.txt="123"`；返回数据**统一以 `FF FF FF` 结尾** → **定界清晰，状态机好写** |
| **FPGA 侧只要三样** | ① 一个 UART 收发 ② 一张指令表 ③ 一个返回解析状态机 |

**FPGA 需要解析的返回格式**（已核实）

| 返回码 | 含义 | 用途 |
|---|---|---|
| **`0x65`** | **控件点击事件返回** | ⭐ 触摸事件 |
| **`0x70` / `0x71`** | **字符串 / 数值变量数据返回** | ⭐ **双向参数同步**（屏 → FPGA） |
| `0x66` / `0x67` | 当前页面 ID / 触摸坐标 | 调试用 |
| `0x88` | 系统启动成功 | 握手 |
| `bkcmd`（系统变量） | 控制是否返回执行结果（**默认 2 = 只返回出错**） | 可关掉以省带宽 |

#### ② 能否实现我们要的功能：**✅ 能，且有意外收获**

| 我们的需求 | X2 对应控件 | 评价 |
|---|---|---|
| **模式切换**（指板/钢琴） | 双态按钮 / 单选框 / 复选框 / 下拉框 | ✅ 完美 |
| **起始音选择** | 下拉框 / 数字控件 / 滑块 | ✅ 完美 |
| **精确量参数** | **滑块控件 + 虚拟浮点数控件** | ⭐ **屏上直接拖滑块，还能把数值回传给 FPGA** |
| **模糊量参数** | 交给实体编码器/电位器（已定） | — |
| **波形显示** | ⭐ **曲线波形控件（Waveform）** | ⭐ **屏自带！FPGA 只需周期发数据点** |
| **频谱 / Lissajous** | 曲线波形控件（多通道） | ✅ 理论可行 |
| **当前音符 / 音色** | 文本 / 数字控件 | ✅ |
| **力度 / 颤音深度显示** | 进度条 / 指针控件（Gauge） | ✅ |

> ⭐ **最大收获：X2 自带「曲线波形控件」+「滑块控件」** →
> **① 波形/频谱可以让屏自己画**（FPGA 只发数据点）② **参数调节可以直接用屏上滑块**（比"发指令改参数"更直观，且**屏会回传数值**）。

#### ③ ⚠️ 对 HDMI 决策的影响：**HDMI 从"必需"降为"加分项"**

| 判断 | 说明 |
|---|---|
| **波形可以先用屏做** | 自带曲线控件 → **省掉 HDMI 的前期投入** |
| **但带宽要看波特率** | 默认 115200 bps ≈ 11.5 KB/s，画波形偏慢；⚠️ **若 X2 7 寸可设到 921600（≈92 KB/s），波形刷新就完全够用** → **待核实最高波特率** |
| **HDMI 仍有独立价值** | 7 寸屏在答辩现场**评委未必看得清** → **接大屏仍有冲击力** |
| ➡️ **建议** | **主体先只做串口屏**（调参 + 显示 + 波形），**HDMI 后置**，等主体跑通、有余力再接 |
