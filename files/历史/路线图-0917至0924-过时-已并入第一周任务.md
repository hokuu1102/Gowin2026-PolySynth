## 二、路线（三个阶段）

### 阶段 ①　把"能验证"这件事先建起来（最优先）

| 做什么 | 产出 |
|---|---|
| ⭐ **L0**：目录骨架 + **`tb_all.ps1` 一条命令跑全部 tb** + `.cst` 占位 | 回归入口 |
| ⭐ **仿真基础设施**：`MCP3208` 从机 / **I2S 解串 + DAC 重构** / `TLC5916` 从机（**含 Special Mode 检测**）/ 触点抖动 / golden 参考 | `tb/models/` |
| ⭐ **断言 A1~A8**（尤其 **A1: `OE` 无窄脉冲**、**A6: 1024 周期 deadline**） | 接口监视器 |
| ⭐ **`tools/` 脚本**：`vcd2csv` / `csv_fft` / `latency_stats` / `peak_count` | 验收图与统计 |
| ⛔ **给 `tlc5916_driver.sv` 加 `OE` guard**（`K-01`） | 唯一"已有代码就带隐患"的事 |

> ⭐ 这一阶段没有"功能"，但它决定后面每一步**能不能被证明**。

### 阶段 ②　把"声音"用仿真证明出来

| 做什么 | 验收（**仿真证据**） |
|---|---|
| **L1 `clk_gen`** | `BCLK`=3.125 MHz、`LRCLK`=48.828125 kHz（÷4/÷4/÷256） |
| **L2 `i2s_tx`**（帧格式参数化） | 解串回样点与激励一致；**M0 达成** |
| ⭐ **L3 单振荡器 DDS** + **L4 `adsr`** | ⭐ **解串样点与 golden 逐点一致 + FFT 单谱峰、频率 = `phase_inc×fs/2^32`** ⇒ **M1（仿真级）达成** |
| **L8 `adc_spi_master` + `chan_scan`** | 假从机回数据；同通道重访 = **0.5 ms**；`A4`/`A5` 通过 |
| **L9 `debounce` + TLC guard 回归** | 抖动注入只出一次事件；`A1`/`A2` 通过 |

> ⭐ **这一阶段的"出声"= 仿真里的 FFT 图**，不是耳机。系统板到货后再把这一条换成实测。

### 阶段 ③　把"能演奏、能拿分"证明出来

| 做什么 | 验收 |
|---|---|
| **L6 复音保守版**（`POLY_TARGET=32`，**每 lane 独立 ROM bank** —— `K-28` 未定先保守） | 综合报告可数出 32 份相位/包络状态 + 32 份 ROM bank |
| **L10 映射与演奏语义**（键盘过阈值即响 / 指板先选轴+拨弦；`UP` 优先） | 两模式共用一张音高表，音准一致 |
| ⭐ **M2 低延迟**（**合成 `UP/DOWN` 激励**，不依赖板A 实物） | 50 次统计：数字端 **<2 音频帧**、极差 **<0.1 ms**；`A7` 通过 |
| **L7 控制量**（音量对数映射、颤音死区+迟滞+斜率限制、变调不清零相位） | 音量曲线单调近似对数；颤音无断续；变调无咔哒 |
| ⭐ **M4 Test Mode `4/8/16/32`** | ⭐ **谱峰数正好 = N**；`deadline_fault=0` |
| **丁 · 硬件** | 板A/板B 出 Gerber、交叉复核封装与排针方向 ⇒ **9/24 投板** |
