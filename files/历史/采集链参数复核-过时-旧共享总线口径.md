## 一、2 kHz 是怎么来的（算式复核）

**`MCP3208` 一个通道的 SPI 帧**（保守估算）：

```text
Start(1) + SGL/DIFF(1) + D2..D0(3) + 采样期(≈1.5) + Null(1) + B11..B0(12)
≈ 20 个 SCLK
```

**共享总线（当前 J3 的接法：`SPI×4 + CS1/CS2`）**：24 通道**串行**轮询

```text
一轮 = 24 通道 × 20 SCLK = 480 SCLK
@ 1.0 MHz → 480 µs/轮 → 每通道 480 µs → 2.08 kHz   ✅ 与记录的 2 kHz 吻合
```

| SCLK | 一轮耗时 | 每通道采样率 |
|---|---|---|
| 1.0 MHz | 480 µs | **2.08 kHz** ← 当前 |
| 1.6 MHz | 300 µs | 3.3 kHz |
| 2.0 MHz | 240 µs | 4.2 kHz |

> ⭐ **结论 1**：2 kHz **不是芯片极限**（`MCP3208` 单通道可达 ~100 ksps），
> 而是**"24 通道共享一条 SPI 总线"**的结果。**提高 SCLK 或改并行都能上调。**

**若改并行 SPI**（3 片各自一组 `SCLK/MOSI/MISO`，同时转换）：

```text
每片 8 通道 × 20 SCLK = 160 SCLK @1 MHz = 160 µs/轮 → 每通道 6.25 kHz（3× 提升）
```

⚠️ 代价：IO 从「SPI×4 + CS×2 = 6 针」增到「3 组 SPI + 3 CS ≈ 12 针」。
⚠️ **且必须先核实 `MCP3208` 的 SCLK 上限**（datasheet，随供电电压变化）。

## 三、⭐⭐ 关键：采样率够不够，取决于**力度怎么测**

### 3.1 为什么"浅阈→深阈"最吃采样率

双阈值方案测的是 **Δt = t2 − t1**（越过浅阈 → 越过深阈）。

`t1`、`t2` 各有一个采样周期的不确定度 → **Δt 的绝对误差最大约 ±T（= ±0.5 ms @2 kHz）**

| 真实 Δt | 相对误差 | 说明 |
|---|---|---|
| **2 ms**（快速拨弦） | **±25 %** | ⚠️ **很差** |
| 10 ms（正常按） | ±5 % | 可以 |
| 50 ms（慢按） | ±1 % | 很好 |

**映射方式决定误差被放大还是压缩：**

| 力度映射 | 快速端（Δt=2 ms）的实际波动 |
|---|---|
| 线性 `v ∝ 1/Δt` | 测得 1.5/2.0/2.5 ms → 力度比 **1.33 : 1 : 0.80 → ±33 %** ⚠️ |
| ⭐ **对数/压缩** `v ∝ log(Δt₀/Δt)` | 波动被压缩到 **≈ ±11 %** ✅ |

> ⭐ **所以：2 kHz 若配"线性映射"不够，配"对数/压缩映射"勉强够。**

### 3.2 ⭐⭐ 更好的做法：把测速窗口**从"浅阈→深阈"改成"起始→触发"**

**核心洞察**：绝对误差是 **±T（固定）**，所以**窗口越长，相对误差越小**。
而"起始 → 触发"的窗口比"浅阈 → 深阈"**长 5~10 倍**：

```text
浅阈→深阈：   |----|                                    Δt ≈ 1~3 ms   → 误差 ±25%
起始→触发：   |----------------------------|            Δt ≈ 10~30 ms → 误差 ±2~5%   ⭐
```

**做法**：
- **"起始"** = 位置偏离静止基线超过一个小量（如 5 % 行程）
- **"触发"** = 越过触发阈值（如 50 % 行程）
- 力度 ∝ 1/(t_触发 − t_起始)（或用对数）

| 收益 | 说明 |
|---|---|
| ⭐ **分辨率好 5~10 倍** | 同样的 2 kHz，误差从 ±25 % 降到 ±2~5 % |
| ⭐ **不增加延迟** | 发声仍在**越过触发阈那一刻**（见 `files/历史/延迟预算逐段分解-过时-旧共享总线口径.md` §三：先触发、后修正） |
| ⭐ **不需要提高采样率** | **不用改 SPI 结构、不用多占 IO** |
| ⚠️ 代价 | 需要定义并标定"起始"阈值；静止噪声大时要配**死区**防误触发（经验库 `C12`） |

> ⚠️ **一个诚实的差别**：双阈值测的是**触发点附近的瞬时速度**，
> 而"起始→触发"测的是**整段平均速度**。
> 人手下压通常是加速的 → 平均速度**略低估峰值速度**。
> ⭐ 但对"力度"感知而言，整段动作强度本来就合理；若需要更细，可在触发后再用几个采样点补一个**局部斜率**。

### 3.3 ➡️ 三条路线的取舍

| 路线 | 采样率要求 | IO 代价 | 建议 |
|---|---|---|---|
| **A. 浅阈→深阈 + 线性映射** | 🔴 需 ≥10 kHz | —— | ⛔ **不推荐**（要么提采样率，要么忍受 ±33 %） |
| ⭐ **B. 起始→触发 + 对数映射** | ✅ **2 kHz 够** | **无** | ⭐⭐ **推荐** —— 零代价解决 |
| **C. 提高采样率到 4~6 kHz** | ✅ 够 | SCLK↑ 或多占 ~6 针 | 🟡 **作为 B 的加固**（若实测发现 B 仍不够） |

> ### 📌 推荐：**先走 B**（零代价），把 C 作为**备选**（若实测发现不够再上）。
> **不要在没实测的情况下先花 IO 去换采样率。**

## 四、⚠️ 以上都是算术 —— **必须实测才能定案**

| # | 要测什么 | 怎么测 | 为什么必须实测 |
|---|---|---|---|
| **1** | ⭐ **真实的「Δt ↔ 力度」分布** | 用真磁轴 + 不同速度按/拨，**采集原始序列**（不是统计量！） | 推算假设了速度范围；真实人手速度分布才是判据 |
| **2** | **轴体行程与触发点** | 量尺 + 电压↔行程曲线 | `Δt` 的分母 |
| **3** | **静止时的位置噪声** | 静置采 1 秒，看峰峰值 | 决定"起始阈值"能设多小（太大测不到起始、太小误触发） |

> ⭐ **测第 1 项时要采"原始序列"而不是均值/极值** —— 经验库 `C08`：
> **聚合量（均值/极值/计数）已经把单点事件的形状抹掉了**；
> 判"有没有"用统计量，判"**什么样**"必须用原始序列。
>
> ⭐ 回传原始序列可复用经验库 `U28` 的 `raw_dump` 思路（`#DEC` 头 + 上位机自适应）。
> ⭐ 并且**先确认激励真的到达**（经验库 `C10` 空测试陷阱）：反问"轴真的动了吗？幅度够吗？"

**由此得到的映射曲线设计原则**

```text
力度映射应是【对数/压缩】的，而不是 1/Δt 线性：
  · 慢速端（Δt 大）→ 分辨高（误差本来就小，不需要压缩）
  · 快速端（Δt 小）→ 压缩，让 ±T 的波动映射到小力度差异
  · 且快速端本来就直接映射到"最强力度" → 精确分辨在那里意义不大
```

> ⚠️ **另注**：还要防**死区/迟滞** —— 任何"过阈值就触发"的判据都必须留死区，
> 否则噪声会造出假边沿（经验库 `C12` / `L46`，我们自己的**不应期**也是同一族手段）。

## 五、🔴 待确认项（①**已确认**，② 仍待查）

### ① ✅ **已确认（2026-09-13）：每轴位只用 1 个霍尔** —— 通道数够

> **依据**：每轴位两个霍尔差分**只能提高精度** —— 因为**磁轴是直上直下的**，
> 横向移动时左右两个霍尔的变化都很小。⇒ **选"靠手指在轴位间移动"**。

**⭐ 这条物理论证很关键，理由比结论更重要：**

| 项 | 说明 |
|---|---|
| 磁轴的机械约束 | 轴体在**导向柱**里**只能上下运动**（直上直下） |
| 磁铁的位置 | 磁铁**固定在轴体上** → 随轴体**上下**移动，**不产生横向位移** |
| 加第二个霍尔的后果 | 左右两个霍尔测到的**几乎是同一个 Z 信号** → 差分≈0 → **只提高精度（共模抑制），拿不到横向量** | 
| 所以要测横向就得 | 改机械结构（让磁铁能横向偏移）→ ⛔ 与"标准 MX 兼容磁轴"冲突 |

> ### ➡️ **结论：横向移动（滑音）靠"手指在轴位间移动"实现，不靠额外传感器**
>
> **通道需求 = 16 轴位 + 1 推子 = 17 路** → **24 路够，余 7 路** ✅
> **ADC 按原计划买 3 片**（每片 8 通道）即可。

> ⚠️ **把这个理由记下来，是为了防止以后有人"顺手加第二个霍尔以为能测横向"** ——
> 那是**被机械结构否掉的**，不是"暂时没做"。

**⚠️ 但它带来一个架构影响（见 §六）**：滑音不再是"一个横向位移量"，
而是**"相邻轴位的双压插值"** → 实现位置从"参数量"挪到了**映射层**。

### ② `MCP3208` 的 SCLK 上限（决定能否靠提 SCLK 加速）

需查 datasheet：不同供电电压下的最大 SCLK。
- 若 3.3 V 下只到 ~1 MHz → 提 SCLK 的路走不通 → 只能并行化（多占 IO）
- 若可到 2 MHz → 走 §一 的表即可

## 六、⭐ 由 C7 引出的架构更正：滑音的实现位置变了

> ⚠️ **这一条会改 W3 的接口** —— 见 `files/20-代码/W3接口冻结表.md`。

**原表述**（`产品形态决议清单.md` §八）：「4 滑音 ← 磁轴**横向移动**」
—— 字面看着像"有一个连续的横向位移量"，**容易让人以为 W3a 会输出一个 `pitch_bend` 参数**。

**实际机制（由 C7 确认）**：

```text
手指横移 → 依次压到相邻轴位 → 常常出现【相邻两个轴同时被压】
                 ↓
        用两者的【行程比例】插值出中间音高   ← ⭐「双压插值 + 行程比较仲裁」
                 ↓
        输出的是【连续音高】，而不是一个"横向位移参数"
```

| 影响 | 说明 |
|---|---|
| ⭐ **滑音的计算落在【映射层】**（`axis_map.v`，属 W3a） | 因为**映射表（钢琴/指板双模式）本来就在那一层**，且插值需要知道轴位布局 |
| ⭐ **W3b 不需要"滑音参数"** | 它收到的是**已经算好的连续音高** → 职责更清晰 |
| ⚠️ **接口要能表达"连续音高"** | 只有 7 bit `note_num`（音符号）**不够** —— 需要音分级（或更细）的分辨 |
| ⚠️ **`expr_param_t.pitch_bend` 的定位要重新想** | 它到底是"滑音"还是"别的调音手段"（如整体微调）？**需要澄清** |

> 📌 **待改**：`files/20-代码/W3接口冻结表.md` §三 接口② —— 把 `pitch_bend` 的来源与含义写清，
> 并补"连续音高"所需的字段（如 `note_fine` 音分偏移）。
