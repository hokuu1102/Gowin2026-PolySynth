## §A 关键事实确认（板级基线）

### A.1 FPGA 与板子

| 项 | 值 | 来源 |
|---|---|---|
| FPGA 器件 | 高云 **GW5AT-LV60PG484AC2/I0**（`gw5at60b-003`） | ADA107 硬件确认记录 §0 |
| 开发板 | 高云 **60K 基石板 + 核心板** | 同上 |
| 板载时钟 | **`sys_clk = F13 @ 50 MHz`** | 同上 |
| 板载复位 | 核心板 P5 右下角 RST 键 → ball `IOL27B`，低有效，外部 10K 上拉 | 同上 §7 |
| 扩展口电平 | **3.3V LVTTL** | 同上 §1 |

### A.2 J14 扩展口

**J14 = 15×2 2.54mm 排针（30 pin）**，是基石板主要的可用扩展口。

| 分组 | 针位 | 数量 | 说明 |
|---|---|---|---|
| 电源/地 | J14.1(5V) ／ J14.2(GND) ／ J14.3(3V3) ／ J14.4(GND) | 4 | ✅ 有 5V 和 3V3，外设供电方便 |
| 信号脚 | J14.5 ～ J14.30 | 26 | 其中 J14.12 有坑（见下） |
| 实际可用 IO | —— | **≈ 25 个** | 扣掉 J14.12 |
| 其中 1-pin 测试点 | **P17 / V18 / P19** | 3 | ⚠️ 只有单点焊盘，**焊接不便**，实操中算"半可用" |

> ⚠️ **J14.12 的坑（已实测）**：原走线到 ball `R19`，但 R19 被 Gowin P&R 判为
> **CPU 专用脚**（`PR2017 cannot be placed ... dedicated pin (CPU)`），**不能作普通 IO**。
> 需要额外 IO 时只能飞线到旁边的 **P17** 测试点。
> 记录来源：`ADA107硬件确认记录.md` §6 / §9。

**➡️ IO 现状：J14 上约 25 个可用信号脚。**

> ⚠️ **重要修正（2026-09-12）**：**IO 并不是硬约束。**
> 板上还有**其他可以引出的 IO 资源**，只是**焊接难度大、不方便**，不是没有。
> 因此 **IO 数量只影响"要不要多焊几根飞线"，不构成方案否决条件。**
>
> 但下面这条**设计原则仍然成立**——它不是被 IO 逼出来的，本身就是更好的做法。

### A.3 IO 预算与设计原则

| 用途 | 接口 | 占用 IO | 备注 |
|---|---|---|---|
| I2S → PCM5102A | BCK / LRCK / DIN | 3 | MCLK 可省（模块内置 PLL），预留 1 → 3～4 |
| UART → 6 寸串口屏 | TX / RX | 2 | UI 专用 |
| 电容触摸控制器（若用 MPR121） | I2C | 2 | SCL / SDA |
| 多通道 ADC（读磁轴霍尔 / 力度） | SPI | 4 | SCLK / DIN / DOUT / CS |
| 拨弦微动开关 | GPIO | 2 | 上拨 / 下拨 |
| 旋转编码器 | GPIO | 3 | A / B / SW |
| 状态 LED / 辅助按键 | GPIO | 3 | |
| **小计** | | **19～20** | J14 基本够用，不必额外引线 |

#### ⚠️ 设计原则：传感器信号应走总线，而不是"一个信号占一个 IO"

> **这条不是被 IO 数量逼出来的，而是设计质量本身的要求。**
>
> | | 做法 | 后果 |
> |---|---|---|
> | ❌ | 12 个磁轴 × 数字霍尔各占 1 IO = **12 路独立线** | 走线多、飞线多、可维护性差、排查困难 |
> | ✅ | 12 个磁轴 × **线性霍尔** → **多通道 SPI ADC** → **只占 4 根线** | 走线少、可扩展、且**顺带拿到连续行程** |
>
> **结论：选"线性霍尔 + 多通道 ADC"的直接理由是"连续行程（力度）"，
> 而"省 IO / 少走线"是它的附赠好处 —— 两个理由指向同一个选择。**
>
> ⚠️ 数字霍尔方案即使 IO 够用也不推荐：它**只能给 0/1，拿不到连续力度**。

### A.4 时钟预算（用实测 50 MHz 重算）

| 参数 | 值 |
|---|---|
| 采样率 | 48 kHz（初期） |
| 主时钟 | **50 MHz** |
| 每样本时钟数 | 50 MHz ÷ 48 kHz = **≈ 1041 clk / sample** |

> 仍完全够用：**不需要"一个时钟周期算完所有 Voice"**，可用时分复用 + Pipeline + 多周期计算。
> 但要记住真实数字是 **1041**（不是 v1.0 写的 2083）。

## §B 更正：为什么撤回 v1.0 的 FSR 推荐

### B.1 两条事实（决定性的）

| # | 事实 | 对方案的影响 |
|---|---|---|
| 1 | **FSR 就是一片外购薄膜**，不是可打印 / 可加工件 | ⇒ **机械验证阶段根本无法用 3D 打印验证 FSR 的手感**。能打印的只有它的压板和限位框 |
| 2 | **FSR 与电容触摸共存时干扰最大**（详见 §C） | ⇒ 若还要用电容方案，FSR 是**最差**的邻居 |

### B.2 成本：参考信息，不作为决策依据

> ⚠️ **决策口径（2026-09-12 明确）**：**不以价格定方案，以效果定方案。**
> 下面数据**仅作记录**，不作为取舍理由。

| 方案 | 单点构成 | 12 点物料（参考） |
|---|---|---|
| **磁轴阵列** | 轴体 + 线性霍尔 | 轴体 + 霍尔 ×12 + ADC（待核实） |
| **FSR** | FSR ≥7 元/个 | ≥ 84 元 仅传感器 |

> 📌 **注意**：早前版本曾用"FSR 比磁轴贵"作为否决 FSR 的主要理由 ——
> **该理由已降级为参考**。FSR 被否决的真正原因是 **B.1 的可验证性** 与 **§C 的耦合**，与价格无关。

### B.3 结论

- **磁轴在"可打印性"和"可验证性"上优于 FSR** —— 这两项恰好是**当前阶段（机械原型）**最关键的
- **FSR 只在"结构薄、无机械件"一项上占优**，权重最低
- ➡️ **主推磁轴。FSR 从"推荐方案"降级为"不采用"。**

## §C 磁轴 vs FSR：对电容触摸的干扰谁更大？

> **结论：FSR 的干扰明显大于磁轴。**
> 而且更关键的是：**两者的干扰性质不同 —— 一个能标定掉，一个标定不掉。**

### C.1 先说一个常见误解

> ❗ **磁轴对电容的干扰，来源不是"磁场"，而是"导体靠近"。**
>
> 电容触摸测的是**电场耦合**。静磁场对电容测量**基本没有影响**（磁场会干扰霍尔，但不会干扰电容）。
> 磁轴之所以有干扰，是因为**磁铁是金属导体**，靠近电极时会增加**寄生电容**。

### C.2 干扰机制逐条对比

| 干扰源 | 物理机制 | 性质 | 能否消除 | 严重度 |
|---|---|---|---|---|
| **磁轴**：磁铁（导体）靠近电极 | 增加静态寄生电容 → 拉低基线 | **静态** | ✅ 上电标定 + 基线跟踪可消除 | 中 |
| **磁轴**：轴体上下往复 | 磁铁↔电极间距变化 → 寄生电容小幅波动 | 动态（幅度小） | ⚠️ 主要靠拉开距离 | 低～中 |
| **磁轴**：磁场本身 | 静磁场不影响电容测量 | —— | —— | **无** |
| **FSR**：薄膜覆盖在电极上方/邻近 | **面状导电/半导电层屏蔽手指与电极间的电场** → 灵敏度大幅下降 | **结构性** | ❌ **无法消除**（改不了它挡在中间的事实） | **高** |
| **FSR**：受压形变 | FSR↔电极间距随压力变化 → 寄生电容**随压力变** → **压力被误读为位置移动** | **动态 + 与压力耦合** | ❌ 无法标定（它不是偏移，是耦合） | **高** |
| **FSR**：FPC / 引线穿过感应区 | 邻近导体 + 走线 | 半静态 | ⚠️ 只能靠布线回避 | 中 |
| 手指出汗 / 环境湿度 | 介电常数变化 | 动态 | ⚠️ 靠基线跟踪缓解 | 两者都有 |

### C.3 为什么"能标定"和"标定不掉"是决定性的差别

```text
磁轴干扰 → 表现为「基线整体偏移」     → 上电标定一次 + 运行中缓慢跟踪 → 化解
FSR  干扰 → 表现为「压力和位置串在一起」→ 标定无效，因为它是"变量耦合" → 无法化解
```

**一句话**：**磁轴的干扰是"静态污染"，FSR 的干扰是"动态耦合"。前者能洗掉，后者洗不掉。**

### C.4 工程对策（无论选哪种都适用）

| 对策 | 做法 |
|---|---|
| **物理拉开** | 电容电极与最近的磁轴/干扰源 **水平净距 ≥ 15～20 mm** |
| **接地隔离** | 两者之间走 **接地隔离带 / guard ring**，电极背面铺**接地屏蔽层** |
| **上电标定** | 开机做一次基线标定，运行中保持慢速基线跟踪 |
| **远离开孔** | 磁轴开孔不要落在电容电极的电场边缘区 |
| **验证优先** | 先做**小样板实测**（3 个磁轴 + 1 条电容条），再定最终布局 |

> ⚠️ 上述数值（15～20 mm）与顺序为**工程经验判断，需实测验证**，不要当规格书用。

## §D ⚠️ 核心实测反馈：**跨面移动会"卡"**（2026-09-12）

### D.0 现象澄清（这条判断我改了三次，如实记录）

反馈原话：

> "如果在磁轴之间布电容滑块，手会比较卡顿，**不是磁轴本身卡顿**，
> 而是**从按下磁轴到左右移动到电容滑块平面卡顿**。"

| 版本 | 当时的判断 | 结论 |
|---|---|---|
| v2.0 初稿 | 怀疑"数字霍尔只有开关量"导致卡顿 | ❌ **错** —— 那是**数据**问题，不是**手感**问题 |
| 上一条修正 | 判断是"轴体 / 打印件公差"造成的手感卡顿 | ❌ **也错** —— 磁轴本身按着是可接受的 |
| **本版（正确）** | **是「跨面过渡」造成的动作卡顿** —— 手指从磁轴面移到电容面时动作断裂 | ✅ |

> ✅ **磁轴本身没问题，已排除。**
> ❌ **问题出在"磁轴区 + 电容区"这个「分离布局」上** —— 两块面不在同一平面上。

### D.1 为什么必然会卡：四个根因

```text
手指从「磁轴面」移动到「电容面」的路径：

  按下磁轴 ──→ (必须先抬起) ──→ 平移 ──→ (重新接触) ──→ 电容面滑动
                    ↑               ↑             ↑
                动作断裂         遇到台阶      摩擦突变
```

| # | 根因 | 具体表现 |
|---|---|---|
| **1** | **高度差（Z 不共面）** | 磁轴键帽是凸起的"高地"，电容面是另一层 → 手指要"翻"过去 |
| **2** | **接缝台阶 / 沟槽** | 两个零件（打印件 vs 电极板）拼接的缝，手指被绊住 |
| **3** | **摩擦系数突变** | 打印件表面 vs 电极覆膜/PCB → 阻力突然变化，手感"顿"一下 |
| **4** | **动作断裂** ⭐体感的根本来源 | 手指必须先抬起才能横移 → 演奏动作不连贯 |

### D.2 ⚠️ 这条反馈推翻了 P1 的原始布局图

> v2.0 里 P1 画的是"**磁轴区在上、电容 Y 区在下**"两块分离平面。
> **实测证明这个布局在体感上不成立** —— 手指没法在两个平面之间平滑过渡。
>
> ➡️ **凡"磁轴区 + 独立电容区"的分离布局，都必须重新设计。**
> 这不是传感器选型问题，是**布局 / 人体工学**问题。

### D.3 四个解决层级（按改动量从小到大）

#### 🟢 L4 — **交互分离**：让手指根本不需要跨面（最省事，优先考虑）

```text
┌───────────────────────────────┬──────────────┐
│                               │  左手控制区   │
│   磁轴阵列（右手演奏区）        │  触摸条/旋钮  │
│   ▤  ▤  ▤  ▤  ▤  ▤            │  ← 颤音/调制  │
│                               │              │
└───────────────────────────────┴──────────────┘
```

- **右手全程只在磁轴区**，不跨面 → 卡顿**从根上消失**
- 颤音 / 调制交给**左手**（触摸条、旋钮、小滑杆）
- ✅ **完全符合真实电子乐器惯例** —— 合成器里 Pitch Bend / Mod Wheel 本来就是左手控制
- ✅ 成本最低、不增加机械难度、不引入电容/磁轴耦合问题
- ⚠️ 代价：颤音需要双手协作（但很多乐器本来就如此）

#### 🟡 L1 — **共面化**：把两个面做成同一高度、无缝、同摩擦

| 措施 | 做法 |
|---|---|
| **统一高度** | 磁轴帽顶面 ≡ 电容面板表面，目标公差 **±0.1 mm** |
| **填缝** | 磁轴之间、磁轴区与电容区交界处用**填充块**填平，不留沟槽 |
| **矮帽 / 平顶** | 用**矮键帽或平顶盖**，避免键帽边缘形成"台阶" |
| **摩擦统一** | 两区表面用**同一材质 / 同一张贴膜**，避免摩擦突变 |
| **过渡倒角** | 若无法完全共面，在交界处做**斜边 / 圆角**，别留直角台阶 |

- ✅ 改动最小，基本保留现有结构
- ⚠️ 但"**按下后必须先抬手再滑**"这个动作断裂（根因 4）**依然解决不了**

#### 🟠 L2 — **嵌入式**：电容电极嵌在磁轴之间，合成一整片区域

```text
俯视：不再是"两块区"，而是"一整片区域里磁轴与电极交替"
┌──────────────────────────────────────┐
│  [轴] ══ [轴] ══ [轴] ══ [轴] ══      │
│   帽  电极  帽  电极  帽  电极  帽      │  ← 全部磨到同一高度
└──────────────────────────────────────┘
```

- ✅ 手指在任何位置滑动都连续
- ⚠️ 难点：**键帽会挡住电场**，电极只能布在键帽之间的空隙里 → 键帽要做小 / 做平顶
- ⚠️ 必须先做**小样板实测**，验证"键帽旁边的电极能否稳定检测手指"

#### 🔴 L3 — **单面架构**：整块柔性盖板 + 下方磁轴阵列（最彻底）

```text
剖面
   ┌──── 柔性盖板（表面完全平整）────┐  ← 滑动与按压都在同一面上
   ├─────────────────────────────────┤
   │  [轴心]   [轴心]   [轴心]        │  ← 按下时盖板局部变形压下轴心
   └─────────────────────────────────┘
```

- ✅ 真正连续表面，二维手势最自然
- ❌ 触觉反馈变弱（按下去"发肉"）
- ❌ 盖板材料要求高（薄、柔、绝缘、耐磨、手感好），工程难度大
- **不建议首版做**

### D.4 更新后的推荐

| 优先级 | 方案 | 理由 |
|---|---|---|
| **1** | **L4 交互分离**（左手控制颤音/调制） | 零改动即可消除卡顿；符合乐器惯例；不增加机械难度 |
| **2** | **L1 共面化**（若坚持同区滑动） | 改动小、保留现有结构；但动作断裂仍在 |
| 3 | L2 嵌入式 | 效果好，但需实测验证"键帽旁电极"的可用性 |
| 4 | L3 柔性面 | 首版不建议 |

> 🎯 **建议先按 L4 走**：右手负责触发 / 力度 / 音高（全在磁轴区），左手负责颤音 / 调制。
> 若实测觉得"单手表达不顺手"，再上 L1 共面化。
>
> **L4 与 L1 不互斥** —— 可以"左手有独立调制条（L4）"**且**"两区尽量共面（L1）"，双保险。

### D.5 顺带保留：后续做结构时要规避的机械公差坑

（这些**不是**本次"卡顿"的原因，但做最终结构时仍要注意）

| # | 坑 | 机制 | 对策 |
|---|---|---|---|
| 1 | **FDM 打印孔偏小** | 材料收缩 + 挤出膨胀 → 孔径常比模型小 **0.1～0.3 mm** | 孔径放大 0.15～0.3 mm；或钻头/铰刀修孔；**先打小样量孔径** |
| 2 | 孔内壁层纹台阶 | 层层台阶与轴体滑轨摩擦 | 打磨内壁 |
| 3 | 打印摆放方向 | 圆孔椭圆度随摆放变化 | 让**孔轴平行 Z 轴**，或竖打该零件 |
| 4 | 同轴度差 | 轴体被"别"住 | 台阶孔 + 定位柱 |
| 5 | **磁吸附加阻力** | 磁铁吸**铁质**件（铁螺丝、钢定位板） | 改用**铝 / 黄铜 / 尼龙 / PLA**、非铁螺丝 |

**二分诊断（若以后怀疑是轴体或公差）**：把轴**从结构里拆出来单独手按** ——
裸轴也卡 ⇒ 轴体问题（段落轴 / 品质）；裸轴顺滑、装进去才卡 ⇒ 公差问题。

### D.6 另一个独立问题（与卡顿无关，但必须单独关闭）

| | 症状 | 根因 | 验证方法 |
|---|---|---|---|
| **力度曲线阶跃** | 手感顺滑，但**数据上**行程只有几档跳变 | **用了数字霍尔**（只有 0/1 输出） | 画"行程 ↔ 输出电压"曲线，看是否**连续单调** |

> 💡 若霍尔只有开关量输出，**力度维度就拿不到连续值**，会影响"≥2 个独立演奏维度"的验收。
> 这条与手感问题**互不影响**，要分别记录、分别关闭。

## §E 二维表达架构（★ 本轮核心）

### E.1 先把坐标系定义清楚

以演奏者视角：

```text
          ↑  Y（前后 / 上下）  = 颤音 · 调制
          │
   ───────┼───────────────→  X（左右） = 音高 · 滑弦
          │
          ⊙  Z（按下深度，垂直面板） = 力度 · Velocity
```

### E.2 ❗ 两条必须先理解的约束

**约束一：手指按在磁轴上时，X 位置被"锁"在键位里**

> 磁轴键帽是绝缘塑料，会挡住电容电场；键位本身是离散的。
> 所以：**单指"按着某个磁轴 + 同时在键位内做连续 XY 移动"，做不到。**
> ➡️ 要拿到连续位置，只能靠**键位之间 / 之外的连续感应区**（电容），或放弃机械开关、改用整块连续感应面。

**约束二（2026-09-12 实测新增）⭐ 跨面移动必然卡顿**

```text
   同平面滑动：磁轴 → 磁轴        ✅ 顺滑
   跨面移动　：磁轴 → 电容面      ❌ 卡顿（已实测确认）
```

原因：高度差 + 接缝台阶 + 摩擦突变 + **必须先抬手**（详见 §D）。

> ➡️ 由此得到一条**比"选哪种传感器"更靠前的设计原则**：
>
> ## 🔴 **同一只手**要移动来切换的操作，必须发生在同一个平面、同一高度上。
>
> ⚠️ **适用范围修正（2026-09-12）**：这条**只约束"同一只手"**。
> **不同手各管一块区域时，两块区域可以完全独立** —— 不在同一平面、甚至不在同一块板上都没有关系。
> （依据：拨弦在右手、选音在左手，二者是分别操作的两个区域，不存在"从 A 面移到 B 面"这个动作。）

**这一条直接决定了下面的方案排序。**

### E.3 方案 P1～P5

#### 🟢 P1：**全磁轴二维阵列（主排 X/Z + Y 排调制）** ← **推荐（2026-09-12 上调）**

> 后续澄清很关键：**"水平方向全磁轴"= 手指在一排磁轴上横向划过，像键盘划过一行。**
> 也就是说 —— **滑弦根本不需要电容**，手指在同一排键帽之间移动就够了。
> 再叠加实测结论"跨到电容面会卡"，两条合起来直接指向：**全磁轴，别混平面。**

```text
俯视（同一平面、同一高度）
┌─────────────────────────────────────────┐
│  ▤  ▤  ▤  ▤  ▤  ▤  ▤  ▤      ← Y 排     │  ← 颤音 / 调制（★ 不发声）
│         ↕ 排间距 6～8 mm                 │
│  ▤  ▤  ▤  ▤  ▤  ▤  ▤  ▤      ← 主排     │  ← 音高（X）+ 力度（Z）
└─────────────────────────────────────────┘
      手指横向划过主排 = 滑弦
      手指纵向移到 Y 排 = 颤音
```

| 优点 | 说明 |
|---|---|
| **无跨面卡顿** ⭐ | 全程**同一平面、同一高度**，手指滑动连续 —— 这正是电容 Y 区做不到的 |
| **延迟全部确定** | 全磁轴，无电容延迟风险，"延迟预算分级"的纠结直接消失 |
| **成本低** | 轴体便宜；霍尔复用同一套 ADC |
| **可 3D 打印验证** | 与现有打样件同一条工艺路线 |
| **Y 排不发声 ⇒ 零误触发** | 见下方"三条硬约束"第 2 条 |

| 缺点 | 说明 |
|---|---|
| X 是**离散音高** | 需靠"双压插值"做准连续（见下方 ✅ 意外收获） |
| ADC 通道翻倍 | 用多通道 ADC / 多路复用解决，**IO 仍只占 4 个**（A.3） |
| 斜向移动需仲裁 | 见"三条硬约束"第 3 条 |

**❗ 必须同时满足的三条硬约束（做不到就别选这个方案）**

| # | 约束 | 做法 |
|---|---|---|
| **1** | **排间距 < 手指宽度** ⭐ | 排间距控制在 **6～8 mm**。这样手指纵向移动时会**同时压住两排的轴**，形成"双压过渡区" —— 音符不断，Y 也能连续估计 |
| **2** | **Y 排绝不产生音符事件** ⭐ | 架构上强制：**Y 排只输出调制量，永久不进 Note / Event Manager**。这是"零误触发"的唯一保证 |
| **3** | **过渡区需要仲裁** | 手指同时压住多个轴时：**主排优先**；主排音符**保持（latch）**直到真正离开；Y 排只贡献调制 |

**✅ 意外收获：双压插值 → 把"离散磁轴"变成"准连续音高"**

```text
手指横向划过、同时压住相邻两轴时：

   轴 n−1 行程  30%  ┐
                     ├──→ 按行程比例插值 ──→ 手指的连续 X 位置
   轴 n   行程  70%  ┘

   ⇒ 滑弦不再只是"依次触发"，而是能算出连续音高（近似连续滑音）
```

- 触发瞬间的**双压**特征，正是插值的依据
- ⚠️ 需要实测验证插值抖动是否可接受（取决于霍尔线性度与装配一致性）

**⚠️ 关于"手指划过一排键帽的顿挫感"**

- 划过一排键帽会经过每个键帽边缘 → 有轻微"哒哒"感
- 💡 **但这未必是缺点** —— 真实吉他滑弦时手指也会经过品格、有"格子"触感，
  这恰恰是**乐器感的一部分**（手指能"摸到"音位在哪）
- 要做的是**别让它变成硬台阶**：**矮帽 / 平顶帽 + 小间隙 + 统一高度**，
  把"绊手"压到"可控的触感"

#### 🟡 P2：**磁轴阵列（X + Z） + 独立电容 Y 区（颤音）** —— 原 v2.0 推荐，**现已降级**

> 降级原因：**实测证明"从磁轴面移动到电容面"会卡**（详见 §D）。
> 它"延迟预算最优"的分析仍然成立，但**结构代价盖过了延迟收益**。

```text
┌──────────────────────────────────────┐
│  Y 电容感应带                        │  ← 手指必须"跨面"才够得到 → ⚠️ 卡
│  ══════════════════════════════════  │
├──────────────────────────────────────┤
│  磁轴阵列：音高（X）+ 力度（Z）        │
│  ▤  ▤  ▤  ▤  ▤  ▤  ▤  ▤             │
└──────────────────────────────────────┘
```

| 优点 | 缺点 |
|---|---|
| 零误判（电容区不产生音符事件） | ❌ **跨面卡顿**（实测确认） |
| 延迟预算分配合理（电容给颤音） | ❌ 即使做 §D 的 L1 共面化也只能缓解，**"必须先抬手"的动作断裂解决不了** |
| IO 只需 2 个（I2C） | ❌ 电容与磁轴之间的耦合需额外处理（§C） |

> ✅ **唯一保留条件**：采用 **§D 的 L4（左手独立控制区）** ——
> 把电容区放在**左手**够得到的位置，右手全程不离开磁轴区。
> 此时它实际上变成"**磁轴主区 + 左手独立调制条**"，**与 P1 不冲突，可以并存**。
>
> ➡️ **所以这不是"P1 还是 P2"，而是"Y 排（右手同区）还是左手调制条（跨手分工）"的选择。**

#### 🟡 P3：**单条连续电容滑条（X） + 算法分离颤音** —— 另一思路

```text
┌──────────────────────────────────────┐
│  ═════════════════════════════════  │ ← 一条横向电容滑条
│        左右移动 = 滑弦（X）           │
│        小幅快速往复 = 颤音（需算法分离）│
└──────────────────────────────────────┘
        + 磁轴只做触发与力度（Z）
```

| 优点 | 缺点 |
|---|---|
| 结构最简单、成本最低、X 连续音高最自然 | ❌ **滑音/颤音混淆**（正是此前担心的问题） |
| 只有一个电容区，无正交布局难题 | ❌ 算法需要滑窗统计 → **额外延迟**，与 ≤5 ms 目标紧张 |
| | ❌ X 音高走电容 → **延迟不确定性落在最敏感的通路上**（最坏的分配） |

**⚠️ 关键判断**：**P3 把延迟风险放错了位置。**
音高是"会被听出来的"（音符迟到、音高抖），颤音是"5–50 ms 延迟根本感知不到"的。
**同一个电容传感器，做 Y 没问题，做 X 就是在冒险。**

#### 🔴 P4：**整块二维电容面（X + Y）+ 磁轴做 Z** —— 最接近 Roli Seaboard

| 优点 | 缺点 |
|---|---|
| 单指二维手势最自然、最像真乐器 | ❌ 二维电极网格走线复杂，MPR121 的 12 通道远不够 |
| 连续 X 滑弦 | ❌ 磁轴开孔会**破坏电极连续性**（架构冲突） |
| | ❌ 电容延迟风险集中在最敏感的两条通路上 |

**判定：技术上最难，不建议首版做。**

#### 🔴 P5：**探索性：磁轴 + 键位内差分电容**

在每个磁轴上下各放一对差分电容电极，检测手指在键位内的 Y 偏移。

| 优点 | 缺点 |
|---|---|
| 单指就能做二维 | ❌ 键帽挡电场，可行性未知 |
| | ❌ 每键 2 个电极 ×12 键 = 24 通道，通道数爆炸 |
| | ❌ 纯探索，**不建议首版碰** |

### E.4 ★ 核心洞察：**延迟预算应该分级**

> 这是选架构时最该抓住的一条原则。

| 通路 | 是否对延迟敏感 | 依据 | 应该交给谁 |
|---|---|---|---|
| **Z 力度 / Note ON** | 🔴 **最敏感** | 决定"音符什么时候响"，人对 5 ms 以上就可能有感 | **磁轴（确定性最好）** |
| **X 音高 / 滑弦** | 🟠 **敏感** | 延迟 = 音符迟到；抖动 = 音高不稳 | **磁轴（离散）或低延迟连续方案** |
| **Y 颤音 / 调制** | 🟢 **不敏感** | 颤音是 **4～7 Hz 的低频调制**，深度参数 10–50 ms 更新完全听不出来 | **电容（延迟不确定也没关系）** ← ✅ |

**➡️ 结论（2026-09-12 修订）**

- **"延迟分级"这条原则仍然成立** —— 它解释了"为什么电容天生适合做颤音"。
- **但它不是最高判据。** 实测表明：**结构连续性（同平面）的优先级更高** ——
  跨面卡顿是**每次演奏都会遇到**的问题，而电容延迟目前只是**理论风险**。
- ➡️ 所以：**能同平面就同平面**；电容只在"**不跨面**"的场景下才是好选择。
- ⚠️ 注意一个反转：如果把 Y 交给**左手独立控制区**（不跨面），那"Y 用磁轴还是电容"
  **就不再是卡顿问题**，而回到纯粹的 **延迟 vs 结构** 权衡 ——
  此时电容反而更好（I2C 只需 2 根线、无机械件、结构简单）。

### E.5 ⚠️ 一个必须讲清楚的设计细节：电容怎么测 Y？

> **仅在"Y 用独立电容区"（P2 / 左手调制条）时才需要这一节。**
> **P1（全磁轴）不需要它** —— 磁轴的位置本身就编码了 Y。

> 一条**横向**的长条滑条，电极沿**长度方向**排布，测到的是 **X**。
> **要测 Y，电极必须沿 Y 方向分布。**

两种可行做法：

```text
做法 ①：多条横向电极带，沿 Y 竖直叠放，相邻带插值
┌──────────────────────────────┐
│ ═══════════ Y=3 ═══════════  │
│ ═══════════ Y=2 ═══════════  │  ← 手指落在哪条 = Y 位置
│ ═══════════ Y=1 ═══════════  │     相邻两条插值 → 连续 Y
│ ═══════════ Y=0 ═══════════  │
└──────────────────────────────┘

做法 ②：一块小二维触摸板（如 4×3 电极网格），直接输出 (X, Y)
┌──────────────────────────────┐
│ ⊞ ⊞ ⊞ ⊞                     │
│ ⊞ ⊞ ⊞ ⊞   → 2D 定位          │
│ ⊞ ⊞ ⊞ ⊞                     │
└──────────────────────────────┘
```

**➡️ 推荐做法 ①**：布线简单、通道少（4～6 条）、Y 只需"方向 + 幅度"，
**颤音根本不需要细分辨率**，离散 4 段 + 插值足够。

### E.6 方案横向对比

| 维度 | 🟢P1 全磁轴二维 | 🟡P2 磁轴+电容Y | 🟡P3 单滑条+算法 | 🔴P4 二维电容面 |
|---|---|---|---|---|
| X 音高 | 离散（磁轴，可双压插值） | 离散（磁轴） | **连续** | **连续** |
| Y 颤音 | 磁轴（独立排） | 电容（独立区） | 算法分离 | 电容（独立轴） |
| Z 力度 | 磁轴行程 | 磁轴行程 | 磁轴行程 | 弱 |
| **跨面卡顿** ⭐ | **无**（全程同平面） | **有**（实测确认） | 无 | 无 |
| **误判风险** | 低（Y 排不发声即消除） | **无** | **高** | 低 |
| **延迟分配合理性** | **全部确定** | 最优 | **差** | 中 |
| 手感统一性 | **高**（同一手感） | 中（两套手感） | 高 | 中 |
| ADC 通道 | 高 | 中 | 低 | 中 |
| 结构难度 | **中低** | 中高 | **低** | **最高** |
| 3D 可验证 | ✅ | ✅ | ✅ | ⚠️ 部分 |
| 首版可行性 | **最高** | 中 | 中 | 低 |

> ⭐ **新增的"跨面卡顿"一行是本轮的决定性判据** —— 它把 P1（全磁轴）和 P2（混平面）直接分开了。

### E.7 如果坚持"单一电容轴 + 算法分离"（P3），判据如下

此前提到"应该可以通过逻辑判断改善"——**可以**，但要付出延迟代价。判据组合：

| # | 判据 | 典型参数（待调） |
|---|---|---|
| 1 | **死区门限** | 位移 < ±2% 行程 → 不产生任何事件 |
| 2 | **方向反转计数** | 200 ms 滑窗内反转 ≥ 4 次 → 判为颤音（颤音典型 4–7 Hz） |
| 3 | **速度形态** | 单向平滑 = 滑音；正弦往复 = 颤音 |
| 4 | **迟滞 + 状态机** | 进入 SLIDE 后需"速度≈0 持续 >30 ms"才允许切出，防边界抖动 |
| 5 | **仲裁优先级** | VIBRATO 判定优先于 SLIDE，但切换只能发生在音符稳定期 |

> ⚠️ **代价**：判据 2/4 需要 **200～300 ms 滑窗** → 引入**几十到上百 ms 延迟**，
> 这条延迟**正好落在最敏感的音高通路上** → **与赛题 ≤5 ms 确定性目标直接冲突**。
>
> ➡️ **所以能用物理正交（P1）解决的事，不要用算法（P3）解决。**
> 这句话就是本轮的核心结论。

### E.8 ⭐ 新增路线：**一维磁轴就够做出三维表达**

> 前面 P1～P5 都在讨论"怎么凑出第二个轴"。但换个思路：
> **如果同一根轴能同时承载两个维度，就不需要第二个轴了。**

**做法：把行程 Z 按频段拆开用**

```text
行程 Z 信号
   │
   ├─ 触发瞬间取值 ──→ 采样保持 ──→【力度 Velocity】   (阶跃/直流)
   ├─ 慢变分量(<1Hz) ─────────────→【音量 / 表情】
   └─ 4～7 Hz 分量 ───────────────→【颤音 Vibrato】
```

> ⭐ **核心技巧：触发瞬间锁定力度，之后的变化全部让给颤音。**
> 这解决了"Z 被两个维度抢"的冲突，而且**符合真实乐器的逻辑** ——
> 力度在击弦那一瞬就已确定，之后手指的动作都是"表情"。

**于是 1 排磁轴即可给出三维：**

| 维度 | 来源 |
|---|---|
| **滑音** | X —— 手指划过一排磁轴 |
| **力度** | Z —— 触发瞬间的行程（采样保持） |
| **颤音** | Z —— 触发之后的往复变化 |

> ⚠️ **待实测验证**：
> 1. 手指"抖压力"做颤音的手感是否自然、会不会累
> 2. Z 抖动的幅度与分辨率够不够
> 3. **必须把"音量"从 Z 解耦**（音量只在触发瞬间取值），否则颤音会带着音量一起抖

### E.8b 三条路线（A ⊂ B ⊂ C）

| 路线 | 硬件 | 三维来源 | 结构复杂度 | 效果上限 |
|---|---|---|---|---|
| **A · 一维磁轴** | 1 排磁轴 | 滑音 X ／ 力度 Z(瞬间) ／ 颤音 Z(后续) | **最低** | 中（颤音靠行程抖动，细腻度待验证） |
| **B · 一维磁轴 + 独立调制条** | 1 排磁轴 + 1 条电容条或推子（**任一手指**可及） | 滑音 X ／ 力度 Z ／ 颤音来自调制条 | 中 | 高（颤音独立、符合合成器惯例） |
| **C · 二维磁轴** | 2 排磁轴（**同平面**，间距 6～8 mm） | 滑音 X ／ 力度 Z ／ 颤音 Y 排 | 高 | **最高**（单指二维、连续性好） |

```text
先做 A ──→ 验证"行程抖动做颤音"的手感
            │
            ├── 够用 → 就用 A（结构最简）
            ├── 不够 → 升 B（+1 条调制条，改动最小）
            └── 要上限 → 升 C（+1 排磁轴，同平面）
```

> ✅ **为什么推荐"先做 A"**：**A 的硬件是 B 和 C 的子集** ——
> 先做 A 不会浪费；A→B 只是加一根调制条，A→C 只是加一排磁轴，
> 而 A 本身就能立刻验证最关键的未知量（颤音手感）。

### E.8c 一个具体的映射候选（供讨论）

```text
磁轴位置（哪个轴被按下）  → 音高
磁轴行程（按多深）        → 音量 / 力度
右手滑条 / 推子           → 颤音
开关 / 推子               → 拨弦触发
磁轴下方 PCB 加 LED       → 演奏指引
```

**它的位置**：相当于 **§E.8b 的路线 B**（一维磁轴 + 独立调制器件），
区别是把调制器件放在**右手**可及处（也可改放左手，赛题不限手数）。

| 特点 | 说明 |
|---|---|
| 优点 | 五个功能**分属不同器件** → 互不抢信号、无耦合、逻辑清晰 |
| 优点 | 音量与颤音来自不同器件 → **不存在"Z 被两个维度抢"的问题**（比路线 A 更干净） |
| 优点 | LED 与轴体天生配套（键盘生态有现成灯位 / 透光轴体 / 透光键帽） |
| ⚠️ 约束 | **推子不能放在与磁轴不同的平面高度上** → 实测跨面移动会卡顿（§D） |
| ⚠️ 约束 | 音高是**离散**的 → 连续滑音要靠"双压行程插值"近似（抖动待实测） |
| ⚠️ 待评估 | **LED 与霍尔同板**：LED 驱动电流大、开关噪声强 → 需分区、独立地、必要时 RC（§E.10） |

### E.9 ✅ 确认：**赛题不限制手数**

查 `高云2026FPGA.pdf`（选题指南 · 选题二）原文：

| 原文口径 | 含义 |
|---|---|
| 「实现至少 **2 个独立可控演奏维度**」「搭建 **≥3 维**演奏表情调控逻辑」 | 只规定**维度**，不规定由几只手完成 |
| 「**自主设计演奏交互形态**」 | 交互形式完全自由 |
| 拓展要求点名「**力度动态、滑音、颤音**」 | 这三样最好各占一个独立维度 |

> ➡️ **结论：双手分工（例如左手做颤音/调制）完全合规，手数不是约束条件。**
> ➡️ 反之，**如果一只手能完成全部维度，那是可选的结构简化，不是义务。**
>
> 「能分离手控制吗」——**能，而且赛题没有任何条款限制这么做。**

### E.10 ⚠️ 此前遗漏：**LED 演奏指引（拓展要求 4）的硬件落点**

赛题拓展要求 4 原文：「实现**脱机演奏 LED 曲目指引**功能，辅助规范演奏节奏」。
**这是硬件侧的责任**（灯的布局、驱动、与传感器的共板关系），此前几版没有覆盖。

#### 五种承载方式对比

| 承载方式 | 做法 | 优点 | 难点 |
|---|---|---|---|
| **键盘灯位** | 轴座 PCB 上的灯珠（单灯 / RGB） | 生态最成熟；逐键指引最直观 | LED 与霍尔同板 → 需分区分线防噪声 |
| **面板下埋光** | 触摸面板 / 亚克力板下的灯珠 | 可做整片光效 | 面板需半透；灯与电极同板 → 噪声污染基线 |
| **侧发光导光** | 侧发光灯珠 + 导光板 / 导光柱 | 光线均匀、可做长条光带 | 需额外导光结构件 |
| **发光管自身** | 光电方案的发射管 | 天然、零额外结构 | 受方案限制 |
| **独立灯带** | 乐器边缘 RGB 灯带 | **与传感器完全解耦，最省心** | 指引精度低，只能做整体氛围 / 进度 |

#### 通用注意（与方案无关）

| # | 注意点 |
|---|---|
| 1 | **驱动方式**：单线级联灯珠（WS2812 类）只需 **1 根 IO**，但刷新时序占逻辑资源；也可用移位寄存器（74HC595）串行驱动 |
| 2 | **供电与去耦**：多灯珠峰值电流大 → **独立供电 + 就近去耦**，不要与模拟传感器共用电源走线 |
| 3 | **与传感器共板**：**LED 驱动走线必须与模拟传感器走线分开**；考虑分时（LED 刷新避开 AD 采样窗口） |
| 4 | **对 FPGA 侧的影响** ⚠️：LED 指引需要解析曲目数据并实时驱动 → 与音频引擎**并行**，占逻辑资源与 BRAM，**必须与 FPGA 侧一起评估** |
| 5 | **指示内容分层**：只做"下一个音是哪个键"（简单）→ 到"整段曲目滚动预览"（复杂），资源差别很大 |

> 📌 **对方案选择的影响（中立陈述）**：
> 磁轴 / 微动方案的 LED 生态最成熟（键盘现成方案）；
> 光电方案的发光管本身就是视觉元素；
> **电容与 FSR 方案做 LED 都要额外解决"灯与传感电极同板"的噪声问题** ——
> 但**任何方案都能做**，只是做法与代价不同。

### F.2 若走磁轴路线：分阶段展开（v2.3）

> ⚠️ **这不是结论，只是"如果选了磁轴，应该怎么推进"。**
> 跨传感器的横向对比（磁轴 / 电容 / FSR / 光电 / 微动 / 混合）见 **`方案选择档案.md`**。

#### 第一版（硬件最小集）

```text
D0 路线 = A 一维磁轴      ← 先验证"行程抖动做颤音"的手感
D1 磁轴（线性霍尔）        ← 手感已实测可接受，可 3D 打印验证
D2 磁轴阵列做音高（X）      ← 10～12 个，手指横向划过 = 滑弦
D5 线性霍尔 + 多通道 SPI ADC ← 直接拿到连续行程（力度 + 颤音）
D6 双微动拨弦
D7 无弦单板式（键盘 / 指板双形态）
D9 传感器板 + FPGA 接口板
```

**三维全部由一维硬件给出**：滑音 X ／ 力度 Z(触发瞬间) ／ 颤音 Z(后续变化)  —— 见 §E.8

#### 升级路径（按验证结果决定）

| 若第一版… | 就… | 改动量 |
|---|---|---|
| 颤音手感够用 | **停在 A** | — |
| 颤音手感不够 | **升 B**：加 1 条独立调制条（电容条 / 推子），放**任一手指**可及处 | 加 1 个零件 |
| 追求表现力上限 | **升 C**：加**同平面第二排磁轴**做 Y 排，排间距 **6～8 mm** | 加 1 排磁轴 |

**为什么是这个顺序**：

1. **A ⊂ B ⊂ C** —— 先做 A 不会浪费：A→B 只加一根调制条，A→C 只加一排磁轴
2. **先验证最大的未知量** —— "手指抖行程能不能做颤音"是**唯一没有先例可循**的问题，
   其他都已有成熟做法。**把不确定性最大的事放到最前面做。**
3. **无跨面卡顿** —— A/B/C 都不涉及"在两层平面之间移动手指"（§D）
4. **延迟全部确定** —— 不必再纠结"电容延迟能不能达标"
5. **不以价格定方案** —— 这里的取舍理由全部是**效果与可验证性**，与成本无关
6. **少走线** —— 线性霍尔走多通道 ADC，比"每轴一根线"少得多的连线与排查量

> 🔀 **仍待表态的分歧**：**颤音由右手（行程抖动 / 同平面 Y 排）还是左手（独立调制条）控制？**
> - 右手 → 单手指完成全部维度，结构最简（路线 A / C）
> - 左手 → 颤音独立、可控性最好（路线 B）
> - ✅ **赛题对两者都无限制**（§E.9），可以按手感自由选
> **见 §G 表决表 D3。**
