## 二、✅ PT8211-S（V1.7 原件）：三条关键结论**全部确认**

> ⚠️ **补件历史**：2026-09-17 早些时候这份只有 **4 页**（页脚 `V1.6 2` → `V1.6 3` → **`V1.6 8`**，
> 缺第 4~7 页，正是时序章节），当时 `K-58` 记为"依据不足"。**现已补全为 V1.7** ⇒ `K-58` **关闭**。

**⭐ 原文逐字（V1.7 §FUNCTION DESCRIPTION, page 4）**：

> "The serial bus input data format of PT8211 is Japanese or called **LSBJ (Least Significant Bit
> Justified)** format. Each valid DIN data will be shifted to the input register in the **rising edge
> of the BCK**, only the first 16bit data (from MSB) is valid if the input data length is more than
> 16bits, other data bit will be truncated."

> "The DIN data must be the **2's complementary** format and the **MSB** (Most Significant Bit) must
> be the first. When the Word Select (WS) clock in the **Low** level, the DIN data will be shifted to
> the **right** input register. likewise, the DIN data will be shifted to the **left** input register
> when WS clock in the **High** level."

| 我们的结论 | V1.7 原文 | 状态 |
|---|---|---|
| DAC 在 **BCK 上升沿**采 DIN（`R-03` 的修法依据） | "…shifted to the input register in the **rising edge of the BCK**" | ✅ **原件确认** |
| **WS 低 = 右声道**（与标准 I2S 相反） | "WS **Low** → **right** input register; **High** → **left**" | ✅ **原件确认** |
| 格式 = LSBJ / 补码 / MSB first（`JUSTIFY=1`） | "Japanese or called **LSBJ**" + "**2's complementary**" + "**MSB** first" | ✅ **原件确认** |
| ⭐ **超过 16 bit 的数据被截断**（只取前 16 位） | "only the first 16bit data (from MSB) is valid if the input data length is more than 16bits" | ✅ **原件确认** ⇒ 我们 32-bit 时隙里"高 16 位有效、其余填充"**正是手册预期** |

**⭐ TIMING CHARACTERISTICS（page 5 原文）**：

| 参数 | 限值 | 我们实测 | 裕量 |
|---|---|---|---|
| `Fbck` Bit clock frequency | **≤ 18.4 MHz** | 3.125 MHz | **5.9×** |
| `Fws` Word clock frequency | **≤ 384 kHz** | 48.828 kHz | **7.9×** |
| `Fdin` Input data rate | ≤ 18.4 Mbit/s | 3.125 Mbit/s | 5.9× |
| `tH` H Level time | **≥ 25 ns** | 160 ns | **6.4×** |
| `tR` / `tF` Rise/Fall time | **≤ 20 ns** | 由 IO 驱动决定（`DRIVE=8`，典型 1~3 ns） | ✅ |
| ⚠️ 手册**没有** `tSU`/`tHD` | — | 我们自定 100 ns 目标，实测 160 ns | — |

**⚠️ 手册内部矛盾（已记录）**：正文 §FUNCTION DESCRIPTION 说 BCK "could run up to **20MHz**"，
而 §TIMING CHARACTERISTICS 写 **18.4 MHz**。⇒ ⭐ **取保守值 18.4 MHz**（我们 3.125 MHz 两者都满足）。

**⭐ DC 特性（page 5）**：`VDD` 3~6 V（THD<1%）✅ 板上 3V3 供电 OK；
`VIH ≥ 1.8 V`（VDD=5V 测试条件）、`VIL ≤ 1.8 V` ⇒ ⭐ 我们的 `HP_*` 是 **`LVCMOS33`**（VOH ≥ 2.4 V）**满足**；
⚠️ **若误配成 `LVCMOS15`（VOH≈1.5 V）就会低于 1.8 V ⇒ 可能识别失败**（已写进 `拓展板连接方案.md` 注意事项）。

**⭐ 其它（对我们有用的）**：内部 **8× 过采样**、**R-2R 16 bit**、双声道**无相位差**（`Pd` ≤ 0.2 µs）、
`S/N ≥ 89 dB`、`THD ≤ 0.3%`、**`NC` 脚（pin 7）不接**。

## 三、TLC5916：⭐ 权威原文逐条核对（全部通过）

### 3.1 我们据以设计 `OE` 防护的原文（**逐字确认**）

> "When a **one-clock-wide pulse** appears on OE(ED2), the device enters the **Mode Switching** phase.
> At this time, the voltage level on **LE(ED1)** determines which mode the TLC591x switches to."

> "…**At the fourth rising edge of CLK, if LE(ED1) is sampled as voltage high, TLC591x switches to
> Special Mode; otherwise, it switches to Normal Mode.** The signal LE(ED1) between the third and the
> fifth rising edges of CLK cannot latch any data. Its level is used only to determine into which mode
> to switch. However, the short pulse of OE(ED2) can still enable the output ports."

⇒ ✅ **`K-01` 的防护设计依据成立**：触发条件是"**OE 低电平恰好跨过 1 个 CLK 上升沿**"，
而我们的实现是「**稳定窗（滤毛刺）+ 只在 CLK 静止 & LE 低 & 非传输时更新 OE**」
⇒ "1 个 CLK 宽"在**结构上不可能**出现，因此进不了 Special Mode。
✅ 而且**恢复路径也确认了**：只要 LE 在第 3~5 个 CLK 上升沿之间为**低**，就会回到 **Normal Mode**
⇒ 即 TI 官方的"发一次 1-CLK 宽 OE 脉冲 + LE 低"**确实能强制回 Normal Mode**（我们的待办项依据正确）。

### 3.2 ⭐ 时序限值 vs 我们的实测（**新增核对，之前没做过**）

| 手册限值（原文） | 我们实测 | 裕量 | 判定 |
|---|---|---|---|
| `tw(CLK)` Pulse duration, CLK **≥ 20 ns** | **500 ns**（`HALF_DIV=25` 拍 @50 MHz） | 25× | ✅ |
| `tw(L)` Pulse duration, LE(ED1) **≥ 20 ns** | **500 ns** | 25× | ✅ |
| `tsu(D,ED1)` Setup time, SDI **≥ 3 ns** | **500 ns**（数据在 CLK 低电平期更新） | 167× | ✅ |
| `th(D)` Hold time, SDI **≥ 2 ns** | ≥ 500 ns | 250× | ✅ |
| `th(ED1,ED2)` Hold time, LE/OE **≥ 10 ns** | ≥ 500 ns（有稳定窗与状态机隔离） | 50× | ✅ |
| ⚠️ `tw(OE)` Pulse duration, **OE(ED2) ≥ 500 ns** | ✅ **已修**：`OE_STABLE` 由 8 拍 → **25 拍 = 500 ns** | ✅ **达标** | ✅ **见 3.3** |

### 3.3 ✅ `tw(OE) ≥ 500 ns` —— **已修复**（`K-57`）

- **字面**：`OE(ED2)` 的**脉冲宽度**至少要 **500 ns**。
- **它约束的是什么**：进 Special Mode / Error Detection 时那个**有意打的窄脉冲**必须够宽
  （另有 `tw(ED2) ≥ 2 µs` 是 Error Detection 模式下的要求）。
- **对我们的意义**：
  ① 我们**从不有意进 Special Mode**（`OE` 只作"LED 总开关"），所以这条限值**不约束正常使用**；
  ② ⚠️ 但**反面要小心**：若误产生一个"短于 500 ns 的 OE 低脉冲"，
     它**可能既不被识别为有效脉冲、又恰好跨过某个 CLK 沿** ⇒ 处于"半识别"的模糊区。
- ✅ **修法（2026-09-17 已完成）**：`OE_STABLE` 默认值 **8 → 25 拍**（@50 MHz = **500 ns**），
  并加了**参数自检**（`TLC_PARAM_OK` / `OE_NS`）：换时钟时若换算后 < 500 ns 会**明确告警**。
- ⚠️⚠️ **修的过程中踩到一个真坑（值得记）**：自检第一版写成
  `(OE_STABLE * 1_000_000_000) / CLK_HZ` ⇒ **32 位有符号 integer 溢出**（25 × 10⁹ ≫ 2³¹），
  算出 **−15 ns**，自检**反而误报**。⇒ ⭐ 改用 **`longint`（64 位）**。
  📌 教训：**"溢出"和"算错"长得一样** —— 任何"拍数 × 10⁹"的换算都要用 64 位。
- ⭐ **并且这条约束现在是"回归守得住"的**：`tb/drivers/tb_tlc5916_driver.sv` 里加了硬断言
  （`if (dut.TLC_PARAM_OK !== 1)` ⇒ `FAIL:`），变异体 **M14**（把 `OE_STABLE` 改回 8 拍）**被抓到**。
  ⚠️ 背景：一开始只打印 `ERROR`，而回归**只认 `FAIL:`** ⇒ 变异体**没被抓到** ——
  是变异测试把这个缺口逼出来的。

### 3.4 引脚/供电（与我们的设计一致）

- `VDD`：**3.3 V 或 5 V** 供电 ✅（与基石板 3.3 V 一致）
- 供电范围与 `VIH=VDD / VIL=GND` 的测试条件已在时序表脚注中列出 ✅

## 四、MCP3208：⭐ SPI 时序限值（原文抄录，丙写 `T11` 驱动**必须**对照）

> ⭐ 这份是**右手板模拟前端**的选型（8 通道 / 12 bit / SPI，与左手板同型号 ⇒ 驱动可复用）。
> ⚠️ 之前仓库里**只有型号与通道数，没有具体时序限值** —— 写驱动时一定要翻手册。
> 现在把限值抄在这里，**写驱动时直接对照，不用再翻**。

**原文（Timing Parameters 表，TA=25 °C）**：

| 参数 | 限值 | 备注 |
|---|---|---|
| `f_CLK` Clock Frequency | **2.0 MHz**（`VDD=5V`）/ **1.0 MHz**（`VDD=2.7V`） | ⭐ SPI 时钟**上限** |
| `t_HI` Clock High Time | **≥ 250 ns** | ⭐ 由它推出"`f_CLK ≤ 2 MHz`"（半周期 250 ns） |
| `t_LO` Clock Low Time | **≥ 250 ns** | 同上 |
| `t_SUCS` CS Fall → First Rising CLK | **≥ 100 ns** | ⭐ **CS 拉低后要等 ≥100 ns 再发第一个时钟**（容易漏！） |
| `t_SU` Data Input Setup | **≥ 50 ns** | |
| `t_HD` Data Input Hold | **≥ 50 ns** | |
| `t_DO` CLK Fall → Output Data Valid | **≤ 200 ns** | ⭐ 读数据要在**下降沿**之后留 200 ns |
| `t_EN` CLK Fall → Output Enable | ≤ 200 ns | |
| `t_DIS` CS Rise → Output Disable | ≤ 100 ns | |
| `t_CSH` CS Disable Time | **≥ 500 ns** | ⭐ 两次转换之间 CS 必须高够 500 ns |
| `t_CONV` Conversion Time | **12 个 clock** | |
| `V_DD` | 2.7 ~ 5.5 V | 与基石板 3.3 V 兼容 ✅ |
| ⚠️ **脚注 3** | **有效时钟低于 10 kHz 会影响线性度**（采样电容漏电） | ⛔ 别把 SPI 时钟调得过慢 |

**⭐ 我们 `clk_sys = 50 MHz` 下的可用分频（已算好，直接用）**：

| SPI 时钟 | 半周期 | 是否整数分频 | 满足 `t_HI/t_LO ≥ 250 ns` |
|---|---|---|---|
| 2.0 MHz | 12.5 拍 | ⛔ **不是整数**（50÷4 = 12.5） | — |
| **1.0 MHz** | **25 拍** | ✅ **整数（÷50）** | ✅ 500 ns（2× 裕量） |
| 0.5 MHz | 50 拍 | ✅ | ✅ 1000 ns |

⇒ ⭐ **建议用 `clk_sys ÷ 50 = 1 MHz`**（整数分频、且满足全部限值）。

**⭐ 带宽核算（验证"24 通道 @2 kHz"是否够）**：
一帧 = 15 个 clock（12 数据 + 起始/模式/填充）÷ 1 MHz + `t_CSH` 500 ns ≈ **15.5 µs**
⇒ 24 通道轮询一遍 = **372 µs** ⇒ **每通道 2.69 kHz** ✅
（若用 2 MHz 则每通道 5.21 kHz，但**分频不是整数** ⇒ 优先 1 MHz。）
⚠️ 前提：**三片 MCP3208 共享 SPI 时钟但各自独立 CS**（互斥片选 = `A4` 检查器守的就是这条）。
