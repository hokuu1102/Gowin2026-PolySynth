## 五、⭐⭐ 效果器怎么触发

### 5.1 帧格式（⭐ 与串口屏同一套协议）

```
71 <变量序号> <值> FF FF FF          （HEX，500000 8N1）
```

### 5.2 变量表

| 序号 | 名字 | 值域 | 换算 | 上电默认 |
|---|---|---|---|---|
| `0x10` | **mask** | 0..254 | 直传（位掩码） | `0`（全关） |
| `0x11` | **gain** | 0..254 | ×256 ⇒ Q4.12（**32⇒2.0** · 64⇒4.0 · 254⇒15.875） | `64`（4.0） |
| `0x12` | **trim** | 0..254 | ×256 ⇒ Q1.15（32⇒0.25） | `32` |
| `0x13` | **mix** | 0..254 | Q0.8（0=全干 255≈全湿） | `128` |
| `0x14` | **fb** | 0..254 | Q0.8（延迟反馈） | `96` |
| `0x15` | **depth** | 0..254 | 直传（⭐ **0 = 数值恒等**） | `0` |
| `0x16` | **rate** | 0..254 | 直传（颤音速率） | `7` |
| `0x17` | **dlylen** | 0..254 | ×128 采样（64⇒8192⇒168 ms；⭐ **>127 饱和到 16383**） | `64` |
| `0x18` | **chorlen** | 0..254 | ×32 采样（23⇒736⇒15 ms；⭐ **>63 饱和到 2047**） | `732` |

### 5.3 掩码速查（⭐ 已修正）

```
0x00 全关        0x01 只失真        0x02 只合唱        0x04 只延迟
0x07 = 失真+合唱+延迟（⭐ 这才是"全开"）
```
🔴 **`bit4` 是【空闲位】**（`fx_chain.v:168-173` 明写"bit4 空闲"）⇒
⭐ **`0x17` 与 `0x07` 完全等价**，⛔ **别指望它开颤音**（旧文档写"0x17 全开（含颤音）"是**错的**，已更正）。

### 5.4 ⭐⭐ 颤音怎么开（最容易搞错的一条）

**颤音级【常开】**，它**没有使能位** —— 只由 **`depth`** 控制：
```
71 15 60 FF FF FF     ⭐ depth = 96 ⇒ 音量周期起伏（这才是"开颤音"）
71 15 00 FF FF FF     关掉（depth=0 ⇒ 数值恒等，听不出）
```
📌 `rate`（`0x16`）控制速率，默认 7。

### 5.5 用工具（推荐）

```bash
python tools/fx_ctrl.py --port COMxx list        # 看变量表（⚠️ 是【本地默认值】，本协议无读回通路）
python tools/fx_ctrl.py --port COMxx on          # 发 0x17（= 0x07 等效）
python tools/fx_ctrl.py --port COMxx off         # 全关
python tools/fx_ctrl.py --port COMxx mask 0x01   # 只失真
python tools/fx_ctrl.py --port COMxx mask 0x04   # 只延迟
python tools/fx_ctrl.py --port COMxx gain 64     # 失真 4.0 倍（默认档）
python tools/fx_ctrl.py --port COMxx drive 64    # ⭐ 归一化驱动（gain 64 + trim 32，推力↑音量不变）
python tools/fx_ctrl.py --port COMxx depth 96    # ⭐ 开颤音
python tools/fx_ctrl.py --port COMxx sweep       # ⭐ 增益扫描（32→240，找"破"的点）
python tools/fx_ctrl.py --port COMxx raw 10 07   # ⭐ 发任意帧体（⛔ 不带返回码 0x71）
```
⚠️ **`raw` 的示例已修正**：原来写 `raw 71 10 17` ⇒ 实际会发 `71 71 10 17 FF FF FF`（**多发一个 `0x71`**）⇒ `body_q = 0x71` 不匹配任何变量 ⇒ **静默无效**。⭐ 现在是 **`raw 10 07`**。

### 5.6 串口助手手动发（HEX 模式，⭐ 直接抄）

```
71 10 01 FF FF FF     只失真（应该明显"破"）
71 10 02 FF FF FF     只合唱（应该变宽）
71 10 04 FF FF FF     只延迟（应该有回声）
71 10 07 FF FF FF     ⭐ 全开（失真+合唱+延迟）
71 11 40 FF FF FF     失真增益 64 ⇒ 4.0 倍（⭐ 默认档）
71 11 FE FF FF FF     失真增益 254 ⇒ 15.875 倍（最大可发）
71 12 20 FF FF FF     失真补偿 32 ⇒ 0.25（⭐ 默认档）
71 13 80 FF FF FF     延迟混合 128

71 17 C8 FF FF FF     ⭐ 延迟长度 200 ⇒ 饱和到 16383（最长回声；⭐ 已修，以前会变成 41 µs）
```

## 六、⭐ 上板验收步骤（按顺序）

```
1. ⭐ 烧完先别发任何帧 ⇒ 听起来应该和"没有效果器"【一样】（零回归）
      📌 代价：整体延迟 19 拍 = 380 ns（相对音频周期 20.5 µs 是 1.9%，听不出来）
2. 发 71 10 07 FF FF FF ⇒ ⭐ 灯 7 应该亮（⚠️ 颜色别信，见 §七）
3. 按住一个音，逐个试：
      71 10 01 ⇒ 只失真（"破"）
      71 10 02 ⇒ 只合唱（变宽）
      71 10 04 ⇒ 只延迟（回声）
4. ⭐ 失真"听不出来" ⇒ 扫增益：sweep，或手发 71 11 20 / 40 / 60 / 80 / A0 / C0 / E0 / FE
      （失真够不够 = 增益能不能把信号推过满量程）
5. ⭐ 颤音：71 15 60 FF FF FF ⇒ 音量应周期起伏；71 15 00 关掉
6. ⭐ 延迟拉到最长：71 17 C8 FF FF FF ⇒ 现在真的到 16383 采样
7. 回干声：71 10 00 FF FF FF ＋ 71 15 00 FF FF FF
```

## 七、⚠️ 四个必须知道的坑

| # | 坑 | 说明 |
|---|---|---|
| **1** | **值 `0xFF` 不可用** | 它是**帧尾标记**（`FF FF FF`）⇒ 所有变量**最大只能发 254**。⭐ 掩码只用 bit0/1/2 ⇒ 最大 `0x07`，⛔ 永远不需要 0xFF（工具会**主动拒绝** 0xFF） |
| **2** | **值只有一个字节** | 所以增益只能表达 **256 的整数倍**（32/64/254…）。要精确写 Q4.12 原值用 `gain-raw` |
| **3** | ⚠️ **灯 7 的颜色【不可信】** | 审查发现（`P1-6`）：`ui_fx_sel = ui_fx_mask[1:0]` 把**位掩码当枚举下标**用了 ⇒ `0x01`(只失真) 显示成"合唱"色、`0x07` 显示成"混响"色（根本不存在的效果）；而且 `0x08/0x20/0x40/0x80` 会让灯亮却**零效果**。<br>⇒ ⭐ **只用"亮/灭"判断有没有开效果器，⛔ 别信颜色**（这是**未修**的已知缺陷） |
| **4** | **链延迟 = 19 拍**（⭐ 不是旧文档写的 17 拍） | 拆时序锥后 `fx_delay` 4→5 级，链上有**两个**实例 ⇒ 17→**19** 拍（380 ns）。⭐ 听不出来，但**零回归口径要按 19 拍写** |
