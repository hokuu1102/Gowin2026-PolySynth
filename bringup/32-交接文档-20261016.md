```

本轮工作区证据（18:10 抓的）  : setup 304 / hold 0 · Fmax 15.052 MHz · Logic Level 67
```

**机理**（`event_extract.v:336-357` 自己写的诊断，与实测对得上）：
```
axis_snapshot.delta_o = cur − prev 是【组合】12 位减法器（~9~10 级 ALU）
而 2026-10-16 把 B 的选法从"第一个形成就 break"改成"行程最大的同排邻居"
⇒ 16 次迭代每次做一次 12 位比较，且第 k 次依赖第 k−1 次的结果
⇒ 顺序链 ≈ 16 × 12 位比较 ≈ 60+ 级；实测 67 级
上一版"第一个命中就短路" ⇒ 比较链被 or 树提前截断 ⇒ 基线才 0 违例
```

## 二、⭐⭐ 三条最贵的教训（下一个人必读）

### 1. 一个信号两个消费者 ⇒ 改一处崩两边
```
seq_arb 的 evt_axis_o 有【两个】消费者：
  · top.v 的 .evt_axis_i(mg_evt_axis)      ← 上行回传帧
  · top.v 的 .note_axis_i(mg_evt_axis)     ← 下行 note_manager 的 (axis,src) 定位键
我为给 ESP32 加鼓标记把它改成 "鼓回传 drum_type" ⇒ 两个 P0：
  · P0-1 鼓垫四件全退化成踩镲（key_drum_sel = src_a_axis[3:2] 恒 0）
  · P0-2 鼓 note_off 轴不配对 ⇒ voice 永久 held ⇒ RESERVED_N=5 保留池耗尽
✅ 修法：上下行拆两条独立输出（evt_axis_o 原样透传 + evt_up_axis_o 新加）
📌 判据：改字段前先 grep 它有几个消费者
```

### 2. Verilog"先声明后使用"踩了 4 次
```
把 case / wire 放在它引用的信号【声明之前】⇒ Verilog 隐式建一根 1 位网线
⇒ 报错是 "Unable to bind xxx"，⛔ 极难联想到是顺序问题
本轮踩 4 次：note_idx · case 查表 · step_done · 重复声明
✅ 纪律：新逻辑块的引用信号必须已在上方声明
```

### 3. ⭐⭐ 判 PnR"卡死"的判据是错的（本轮最贵）
