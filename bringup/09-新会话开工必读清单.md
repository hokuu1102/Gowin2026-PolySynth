## 一、🔴🔴 push 纪律（⭐ 本项目最容易犯的一条）

### 1.1 ⭐ 核心规则：**多个 commit 要【压成 1 个】再推**

```text
⚠️ "攒起来 push" ≠ "一次推多个 commit"
⭐ 含义：把【本周期所有 commit 压成 1 个】再推
⇒ ⭐ 远端【一周期 = 一提交】
```

### 1.2 ⭐⭐ 正确流程（⭐ 完整版见 `CONTRIBUTING.md` §一「推送三步」）

```powershell
# ① ⛔ 先确认没人动过远端
git fetch origin
git rev-parse origin/main          # ⭐ 必须 === 你上次推完记下的那个 SHA

# ①b ⭐⭐ 若远端已变（别人推了/合了 PR）⇒ 改用 rebase，⛔ 绝不再 force
#     🔴 force 会把你没看到的提交【整体抹掉】，且不留痕迹
git log --oneline -6 origin/main
git branch archive/<日期>-<主题> HEAD
git rebase origin/main
git reset --soft origin/main
git commit -F 交付说明.txt
git push origin main               # ⭐ 普通推送（快进）

# ② 存档别丢：压之前先存一条本地分支
git branch archive/2026-09-23-<主题>

# ③ 压成 1 个
git reset --soft <上次交付的那个 commit>
git commit -F 交付说明.txt
git diff --stat archive/... HEAD   # ⭐ 必须为空 —— 内容不变，只是历史变干净
git push --force-with-lease origin main
```

### 1.3 ⭐ 备份三件套（⭐ 缺一不可）

| 方式 | ⭐ 能否回滚 |
|---|---|
| ⚠️ 只记 SHA | 🔴 **短期能，90 天后失效**（reflog 过期 / `gc`） |
| ⭐ **本地 tag** `pre-squash/<日期>` | ✅ 永久 |
| ⭐ **`git bundle`**（⚠️ 存**仓库外**） | ✅ **最稳**，连 `.git` 丢了都能恢复 |

### 1.4 ⛔ 禁令

- ⛔ **禁止 `git push --tags`**（⭐ 公开仓库，会把备份 tag 推上去）
- ⛔ **禁止 `git push --all`**
- ⛔ **禁止 `--force`**（⭐ 只能用 `--force-with-lease`）
- ⛔ **禁止 `git add -A` / `git add .`**（⭐ 用**具体路径**）
- 🔴 **push 必须先问用户**，⭐ 且要**列出改了哪些文件**

## 二、⚠️ push 前必查的两项（⭐ 今晚刚踩过）

### 2.1 🔴 **审 `git diff --name-only`** —— ⛔ 不只看"我提交了几个"

```powershell
git diff --name-only origin/main..HEAD
```

⭐ **然后问自己**：⭐ **"这份清单能让别人复现我的结论吗？"**

> 🔴 **真实教训（2026-09-23）**：⭐ 提交说明写着"22 个 ball 核对一致"，
> ⚠️ **而那个约束文件根本没进版本库** —— 🔴 只 `git add sim/evidence/` 了。
> ⭐ **极难发现**：测试/构建**全过**（它们读**工作区**）、证据文件确实提交了、
> ⭐ `git status` 当时也干净 ⇒ ⭐ **只有审 diff 才暴露**。

### 2.2 ⭐ **改名/重构后必须【全仓库扫描】**

```powershell
# ⛔ 不要限定目录（别只搜 tb/ 或 rtl/）
grep -r '<旧名>' --include=*.v --include=*.sv --include=*.md .
# ⭐ 判据：旧名的命中数 = 0
```

> 🔴 **真实教训**：⭐ 改一个信号的接口名，"记得"有两个 tb 用了 ⇒ 改了那两个，
> 🔴 **第三个漏了** ⇒ ⭐ 回归里编译失败。

## 三、⭐ 长任务纪律（⭐ 详情见 `bringup/08-长任务不阻塞-工作方法.md`）

### 3.1 ⭐ 本项目的长任务

| 任务 | 脚本 | ⭐ 实测耗时 |
|---|---|---|
| **全量回归** | `sim/tb_all.ps1` | ⭐ **~15 分钟** |
| **PnR** | `sim/gowin_build.ps1` | ⭐ **~10 分钟** |
| **变异测试** | `bringup/mutation_test.ps1` | 🔴 **~5 小时** |

### 3.2 ⭐⭐ 四步机制

```
⭐ 挂后台 → ⭐ 报四要素（job id/在跑什么/预计多久/判据）
   → ⭐ 干"不依赖它"的活 → ⭐ 等通知 → ⭐ 核判据
```

⭐ **核心认知**：⚠️ **问题不是"别等"**（等待是必须的），
⭐ **问题是"在等的时候干什么"**。

### 3.3 ⛔ 不能并行的

| 长任务在跑 | ⛔ 不能做 |
|---|---|
| 回归 | ⛔ **改 `rtl/` 或 `tb/`**（⭐ 它读工作区） |
| PnR | ⛔ **改 `constr/` 或 `rtl/`** |
| 🔴 变异测试 | ⛔ **改 `rtl/`** ＋ ⛔ **`git add`** |

## 四、⛔ 硬约束（⭐ 违反会出事）

| # | 约束 | ⚠️ 为什么 |
|---|---|---|
| **1** | ⭐ **Verilog-2001 语法**（`.v`/`.sv` 都是） | 🔴 用了 SV 专有构造 ⇒ **整个模块被静默丢弃**，而 `iverilog` 全绿（`K-91`） |
| **2** | ⭐ **同步复位、低有效、单时钟域 50 MHz** | 🔴 项目约定 |
| **3** | ⛔ **不碰 `esp32/`** | 🔴 那是**另一条线**（⭐ 有独立会话） |

| **6** | ⭐ **`git add` 用具体路径** | ⛔ 禁 `-A` / `.` |
| **7** | ⚠️ **`.ps1` 必须纯 ASCII** | 🔴 PS 5.1 按 GBK 解无 BOM 的 UTF-8 ⇒ **中文注释可能改语法** |

| **10** | 🔴 **tb 里 ⛔ 不用 `wait(信号)`** | 🔴 它**不推进仿真时间** ⇒ **永久阻塞** |
| **11** | ⭐ **长任务挂后台**，⛔ 不 `wait: true` | ⚠️ 见 §三 |
