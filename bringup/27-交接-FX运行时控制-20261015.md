### 2.1 效果器参数从编译期常量改成运行时寄存器

**改之前**（合并队友 fx 分支后的状态）：

```verilog
top.v:57-66    FX_EN_MASK / FX_DIST_GAIN / ... 全是 parameter
```

问题：`mask = 0` 时**整条链根本不综合进去**，只剩旁路 ⇒ 运行时发什么都进不了
效果器；且改任何参数都要重新综合 + 重新 PnR（几十分钟一轮）。

**改之后**：

| 文件 | 改动 |
|---|---|
| `rtl/w3c/uart_ui.v` | 删掉 `fx_en_o`/`fx_sel_o`（恒 0 的留位），加 **9 个运行时寄存器 + `fx_commit_o`**；`RET_NUM` 分支加 `0x10..0x18` 解析；加 9 个 `FX_*_DEF` parameter 做上电初值 |
| `rtl/top.v` | `g_fx`/`g_fx_bypass` 的**编译期 generate 改成无条件例化**；参数全部接 `uart_ui` 的运行时寄存器；`uart_ui` 例化透传 `FX_*_DEF` |

**为什么保留 `FX_*_DEF` parameter**：队友的 `tb_top_fx_audio` 会编译期覆盖
`FX_EN_MASK=8'hFF` 做全开档验收 ⇒ 透传之后**判据不用重写**。

### 2.2 零回归口径更新（必须知道）

```
旧口径 = 输出【逐拍】相同
新口径 = 输出【逐样本】相同，整体延迟 19 拍（380 ns @50 MHz）
```

原因：无条件例化 `fx_chain` 才能运行时控制，代价是旁路时也走那 19 拍。
380 ns 相对音频周期 20.5 µs 是 **1.9%**，听不出来。

### 2.3 顺带修出一个真健壮性缺陷

```
症状：发 `71 10 FF FF FF`（想把掩码设成 0xFF）
  0xFF 是帧尾标记 ⇒ 不计入 body_len ⇒ body_len 只到 1
  而帧尾一到【照样落地】⇒ 把【上一帧遗留的陈旧 val_q】写进了寄存器
```

不只是"设不进去"，而是**写入了垃圾值**（用户会看到参数莫名跳变）。

**修法**：`RET_NUM` 加闸门 —— `body_len < 2` 时一律不落地。
- 零回归：既有的合法用法（`71 01 18`）`body_len` 恰好 = 2
- 只对 `RET_NUM` 生效 —— `0x65`（触摸）本来就是 1 字节帧，不能加这个限制

## 三、串口控制速查（上板用这个）

### 3.1 接线与参数

```
引脚：uart_rx = D14（助手 TX → FPGA）· uart_tx = D15（FPGA → 助手 RX）
参数：500000 8N1
```

**注意**：这条串口与**串口屏共用**。两者靠"字节形态"区分（屏是 TJC 帧、
命令是单字母），不冲突。但物理上共用一根 RX 线 ⇒ **两个都在发就会撞** ⇒
插助手时把屏拔掉（或反过来）。

### 3.2 帧格式

```
<返回码> <变量序号> <值> FF FF FF
   0x71      0x10..0x18
```

效果器变量表：

| 序号 | 名字 | 值域 | 换算 | 说明 |
|---|---|---|---|---|
| 0x10 | mask | **0x00..0x07** | 直传 | bit0=失真 bit1=合唱 bit2=延迟 · ⚠️ **bit4 不是颤音**（见 §3.5）· ⭐ 全开 = **0x07** |
| 0x11 | gain | 0..254 | ×256 ⇒ Q4.12 | 失真增益：32⇒2.0 · **64⇒4.0（默认）** · 254⇒15.875 |
| 0x12 | trim | 0..254 | ×256 ⇒ Q1.15 | 失真补偿：**32⇒0.25（默认）** · 128⇒1.0 |
| 0x13 | mix | 0..254 | 直传 Q0.8 | 延迟/合唱混合 |
| 0x14 | fb | 0..254 | 直传 Q0.8 | 延迟反馈 |
| 0x15 | depth | 0..254 | 直传 | 颤音深度，0 = 数值恒等 |
| 0x16 | rate | 0..254 | 直传 | 颤音速率 |
| 0x17 | dlylen | 0..254 | ×128 采样 | 延迟长度：64⇒8192（168 ms），**>127 饱和到 16383** |
| 0x18 | chorlen | 0..254 | ×32 采样 | 合唱长度：23⇒736（15 ms），**>63 饱和到 2047** |

掩码速查：

```
0x00 全关          0x01 只失真        0x05 失真+延迟
0x07 失真+合唱+延迟  ⚠️ 0x17 与 0x07 **等价**（bit4 空转，⛔ 不是"含颤音"）
```

### 3.3 用工具（推荐）

```bash
python tools/fx_ctrl.py --port COM31 list        # 看全部变量
python tools/fx_ctrl.py --port COM31 on          # 全开（0x07 = 失真+合唱+延迟）
python tools/fx_ctrl.py --port COM31 off         # 全关
python tools/fx_ctrl.py --port COM31 mask 0x05   # 只要失真+延迟
python tools/fx_ctrl.py --port COM31 gain 64     # 失真 4.0 倍（默认档）
python tools/fx_ctrl.py --port COM31 drive 64    # ⭐ 归一化驱动（gain 64 + trim 32，推力↑音量不变）
python tools/fx_ctrl.py --port COM31 depth 96    # 颤音开
python tools/fx_ctrl.py --port COM31 sweep       # 增益扫描（找明显失真的点）
python tools/fx_ctrl.py --port COM31 raw 10 17   # 发任意帧体（⛔ 不带返回码 0x71）
```

### 3.4 用串口助手手动发（HEX 模式）

```
71 10 07 FF FF FF     失真+合唱+延迟（⭐ 这才是"全开"；⚠️ 0x17 出声相同但 bit4 空转）
71 11 40 FF FF FF     失真增益 64 ⇒ 4.0 倍（⭐ 默认档）
71 11 FE FF FF FF     失真增益 254 ⇒ 15.875 倍（最大）
71 12 20 FF FF FF     失真补偿 32 ⇒ 0.25（⭐ 默认档）
71 10 00 FF FF FF     全关
```

### 3.5 两个必须知道的约束

**约束一：值 0xFF 不可用。** 它是帧尾标记（`FF FF FF`），协议固有约束。
- 实用影响很小：掩码只用 **bit 0/1/2** ⇒ ⭐ **全开 = `0x07`**，**永远不需要 0xFF**
- 要"全开"用 `0x07`；要"差一位"用 `0x06`（少失真）/ `0x05`（少合唱）/ `0x03`（少延迟）
- ⚠️ **`0xFE` ⛔ 不是"差一位"** —— 它是 **bit0 清零 = 把失真关掉**（⭐ 只剩合唱+延迟），
  与"全开差一位"**无关**（⭐ 旧版本这里写错过，见 2026-10-15 修正）
- 工具会**主动拒绝** `0xFF`，不会静默发出去

**约束二：值只有一个字节。** 所以增益只能表达 **256 的整数倍**。
- 值 64 ⇒ 16384（4.0 倍），这是默认
- 想精确写 Q4.12 原值请用 `gain-raw`，它会提示最接近的那一档
- ⭐ **`drive <值>`** 一次发两帧（`gain = 值` + `trim = round(2048/值)`）⇒
  ⭐ **推力↑而音量不变**；对照表 `16→128 · 32→64 · 64→32 · 128→16 · 254→8`
  ⚠️ **`254→8` 那一档的净增益是 `254×8/2048 = 0.9921875`**（⭐ 差 0.78%，听不出来），
  ⛔ **不是正好 1.000** —— ⭐ 因为补偿字节只能取整（`round(2048/254) = 8`）✅

### 5.4 工具类的坑
