## 三、🔴🔴 先做**这一个**测量：`t` → `T` 的时间差（**T0**）

> ⭐⭐ **为什么先做它**：⭐ **一行判据同时覆盖三件事**，⭐ 而且**几十秒就能做完**。

```powershell
python tools\board_probe.py <COM口> --send T        # ⭐ 看 t 与 T 的时间戳差
```

| ⭐ 实测 | ⭐ 判定 |
|---|---|
| ⭐ **≈ 7 ms** | ✅ **正确**（静止守卫在工作 ＋ `WAIT_CLK` 没溢出 ＋ `STILL_TOL=48` 够松） |
| 🔴 **≈ 0.3~0.5 ms** | 🔴 **溢出版 / 无守卫** —— `WAIT_CLK` 回绕 ⇒ **一个 `tare` 都不发，却照回 `T`** |
| 🔴 **≈ 8 s** | 🔴 **全通道静默超时**（⭐ AU 下**不该出现** —— `STILL_TOL` 已是 48） |

**⚠️ 最重要的一条认知**：⭐ **两种失败【都照回 `T`】** ⇒ ⛔ **看到 `T` 绝不能判定"autotare 成功"**。

### 🔴🔴 **T0b（⭐ 主判据）** —— 2026-10-01 实测更正：**T0 的"看时间"在本机测不出来**

⭐ **实测结论**：⭐ **PC 串口驱动的 `LatencyTimer`（本机 ≈10~16 ms）比 `t→T` 的 7 ms 还长**
⇒ ⭐ 两个字节被**批量投递** ⇒ ⭐ 连 `'X'` 的回包都显示 `@0.0 ms`
⇒ 🔴 **本机用 Python 读串口【分辨不了 🟢7 ms 与 🔴0.5 ms】**
（⭐ 要测那个时间得**示波器**，或把串口驱动的 `LatencyTimer` 调低 —— ⚠️ 属系统配置，⛔ 别随手改）
⇒ ⭐ **所以主判据换成【语义】的 T0b**（⛔ 不依赖时间分辨率）：

```powershell
# ⭐ 采集期间【请勿碰任何键】，让 16 轴都处于松手静止态
#   （先发 T 触发 tare，再连发 16 次 N 读 16 轴）
python tools\board_probe.py <COM口> --send "T,@0.6,N,N,N,N,N,N,N,N,N,N,N,N,N,N,N,N"
```

⭐ **回包格式**：`N` ＋ **轴号(1 hex)** ＋ **校准后 `pos`(5 hex)** ＋ `CR LF` = **8 字节**，共 **128 字节**

| | ⭐ 观察 | ⭐ 含义 |
|---|---|---|
| **🟢 绿** | ⭐ 16 轴**全 ≈ `00000`**（⭐ 允许个位数 `00001` —— 那是松手静止噪声） | ⭐ **`zero` 被成功捕获** ⇒ ⭐ **tare 真的发出去了** |
| **🔴 红** | ⭐ 16 轴**全 ≈ `01023`** | ⭐ **zero 全没写**（被跳过 ⇒ 全体挂音）**或** `WAIT_CLK` 回绕 ⇒ **一个 `tare` 都不发** |

⭐⭐ **为什么 T0b 能替代 T0**：⭐ `t→T` 那个"0.5 ms 失败模式"的定义就是
**"一个 `tare` 都不发，却照样回 `T`"** ⇒ ⭐ **只要 T0b 绿，那个模式就【已被排除】** ✅
⚠️ 但它**证明不了**"守卫/" `STILL_TOL` 参数合适" ⇒ ⭐ 那个要靠 **T6 的 E2/E3**
（⭐ 那里的时间差是 **8 s** 量级 ⇒ ⭐ **本机测得出** ✅）。

> ⚠️ 而且它回的是 **`adc_farm` 的原始码**（≈2110 松手 / ≈2854 按下），⛔ **不是** `calib` 后的 `pos`

⭐ **操作**：
```powershell
# ⭐ 连发 16 次 ⇒ 依次得到 轴0..轴15 的原始码（⭐ 数次数！）
python tools\board_probe.py <COM口> --send "P,P,P,P,P,P,P,P,P,P,P,P,P,P,P,P"
```

| | ⭐ 观察 |
|---|---|
| **🟢 绿** | ⭐ **轴 8~15（板2）的值【跟着板2 的键动】**；⭐ 松手 ≈2110、按到底 ≈2854 |
| **🔴 红** | ⭐ **轴 8~15 的值恒 ≈2110 不变**（= 修前：恒读片 0 ⇒ 板2 的按键**被无视**） |

⚠️ ⭐ **本版已修**：⭐ 修前 `'P'` **永远只回片 0**，⭐ 按板2 的键会看到**板1 同号键（静止）的码**
⇒ 🔴 **会得出"板 2 按键没反应"的错误结论**（⭐ 比"看不到"更危险）⇒ ⭐ **这是本版要验的改进**。

### T7 · ⭐ 故障指示灯（⭐ 本版新增，⛔ 上卡没有）

⭐ **依据**：`top.v:4179-4203` —— `fault_sticky`（**sticky，只有复位才清**）⇒
`hb_div_eff = HEARTBEAT_DIV >> 3` ⇒ ⭐ **半周期 62.5 ms = 8 Hz 快闪**

| | ⭐ 观察 |
|---|---|
| **🟢 绿（正常）** | ⭐ 心跳灯 **≈ 1 Hz 慢闪**（⭐ 一直如此） |
| **🔴 红（有故障）** | ⭐ 心跳灯 **≈ 8 Hz 快闪** ⇒ ⭐ **`adc_farm` 或渲染超时出过错**，⭐ **复位才清** |

⚠️ ⭐ **判据**：⭐ **上电自检到弹琴全程，灯都不许变快闪**。
⭐ 若快闪 ⇒ ⭐ **记下"什么时刻开始快闪"**（⭐ 那是最有价值的现场证据）。

### T8 · ⭐ `span_sent_r2`：`err` 必须归属**本轴**（⛔ 不是上一轴的残值）

⭐ **操作**：① 让某轴**真失败一次**（中途松手）⇒ 看到 `1`
② ⭐ **立刻纠正**（两片该键按到底**保持住**）③ 看下次尝试的回包
🟢 纠正后**直接 `.`**　｜　🔴 ⭐ **还会再回一个 `1`**，**第三次**才 `.`
⇒ ⭐ **判据 = "失败 → 纠正 → 通过"之间多出的拒绝次数：修后 `0`、修前 `1`**
⚠️ 拒绝字节**总紧跟在轴号之后** ⇒ ⭐ `1` 与轴号 `1` **同形**，⭐ **按位置数**。
