# H4 验证记录：1920×1200@60（2026-10-01）

> **结论：H4 上板验收通过。** `K_h4_1920x1200_led.fs` 烧入 Tang Console 60K 后屏幕出八色彩条，**画面干净稳定**。
> 这同时回答了本项目此前最大的未知数：**OSER10 在 768.75 MHz FCLK / 1.5375 Gb/s 每 lane 下可用**，且**板级 TMDS 通路能跑 153.75 MHz 像素时钟**。

## 二、时钟方案（必须先合法化）

第三周计划里原写的 `50 × 77 / 25 = 154 MHz` **是违规的**：`VCO = 50 × 77 = 3850 MHz`，远超 700–1400 MHz 允许范围，会报 `PA1019`（方案 B 就是栽在这里）。

硬约束：
- `VCO = 50 × (MDIV_SEL + MDIV_FRAC_SEL/8) ∈ [700, 1400] MHz`
- `serial = 5 × pixel`（OSER10 每像素 10 bit、`FCLK = PCLK × 5`）⇒ `ODIV1_SEL = 5 × ODIV0_SEL`

要 `pixel ≈ 154 MHz`，**只能取 `ODIV0_SEL = 1`、`ODIV1_SEL = 5`**（`ODIV0 = 2` 会让 VCO = 1540 MHz 越界）：

| 参数 | 值 |
|---|---|
| `MDIV_SEL` / `MDIV_FRAC_SEL` | **15 / 3** |
| VCO = serial（CLKOUT0） | **768.75 MHz** ∈ [700,1400] ✅ |
| pixel（CLKOUT1） | **153.75 MHz**（对 154.000 MHz 偏 **−0.162%**） |
| SDC 生成时钟 | serial `-divide_by 8 -multiply_by 123`；pixel `-divide_by 40 -multiply_by 123` |
| 帧率 | 59.853 Hz |
| 同步极性 | **正极性**（与 640×480 的负极性相反） |

## 四、器件额定速率核查（Gowin DS981-1.1.3E）

| 指标 | GW5AT-60 额定 | H4 需求 | 余量 |
|---|---|---|---|
| OSER10 10:1 最大串行输出（表 3-38） | **2000 Mbps** | 1537.5 Mb/s | **−23.1%** ✅ |
| LVDS TX（表 1-1） | **2.0 Gb/s** | 1.5375 Gb/s | **−23.1%** ✅ |
| PLL 输出上限（表 3-44） | 1400 MHz | VCO 768.75 MHz | ✅ |
| OSER10 最高 FCLK | 手册**未单列**；由 2000 Mbps 反推等效 ≤ **1000 MHz** | 768.75 MHz | ✅（推算，非规格） |

使用条件（手册原文）：
> *"Vccx needs to be greater than or equal to 2.5V for input-output applications with Fmax greater than 600Mbps"*

本设计 TMDS 引脚所在 bank 声明 `BANK_VCCIO=3.3` ⇒ 满足 ✅

⚠️ **易混淆点**：DS981 里另有一张 `FMAXOSER10 = 1600 Mbps` 的表，那是 **Table 3-39 Gearbox Timing Parameters (138K)**，
**不是 60K**；60K 的表（Table 3-38）里 OSER10 是 **2000 Mbps**。若误按 1600 计算，余量会从 23% 变成 3.9%。

## 七、仍未验证 / 遗留

- **只在一台显示器、一根线上**验证过；线材长度容忍度、其它显示器、长时间稳定性未测。
- H4 的 `pixel_clk` 由 `ODIV1_SEL = 5`（**奇数分频**）产生，Gowin 时序报告中有 10 条
  `Low Pulse Width` 条目 `slack = −0.883 ns`（`Actual Width = −0.658`，`Required = 0.225`）；
  而 640×480 基线同类条目全为 **+7.075 ns**。PnR 未报错、上板画面干净稳定，
  **推断为工具对奇数分频输出的建模假象**（÷5 的占空比只能 2:3，低电平 ≈ 3.9 ns ≫ 0.225 ns 需求），
  但**未最终证实**，留作待查项。
- `PR1014`（`clk_d` 走通用布线）与 `EX3791`（编码器位宽截断）两项告警未清。
