## 二、⭐ 开源调研带来的两处"想当然被纠正"
### 2.1 PT8211 手册原文（⭐ 直接改变了 RTL）

| 手册原文 | 对我们的影响 |
|---|---|
| "Each valid DIN data will be shifted to the input register in the **rising edge of the BCK**" | ⇒ **DAC 在 BCK 上升沿采样** ⇒ 数据必须在下 **降**沿变化（**这就是 R-03 的修法依据**） |
| "…the serial bus input data format … is **Japanese or LSBJ**" | ✅ 我们的 `JUSTIFY=1`（右对齐）判定**与手册一致** |
| "When the Word Select (WS) clock in the **Low** level, the DIN data will be shifted to the **right** input register … High → **left**" | ⚠️ **WS 低 = 右声道**，与标准 Philips I2S **相反**！本项目音频是**单声道**（左右同一路）⇒ 无听感影响；真要分左右时用 `LRCK_POL` 切。⛔ 别再照抄"WS 低 = 左" |
| Fbck ≤ **18.4 MHz** · Fws ≤ **384 kHz** · tH ≥ **25 ns** | ✅ 我们 3.125 MHz / 48.828 kHz / 160 ns ⇒ **裕量 5.9× / 7.9× / 6.4×** |
| **手册没有 tSU/tHD** | ⇒ `tb_i2s_tx_timing` 的 100 ns 判据是**我们自己的工程目标**（≥半个位周期），⛔ 不是手册值（已写在 tb 头） |
| 无 MCLK 引脚 | ✅ 我们不用 MCLK（`mclk_en` 只是留观测，未被引出） |

### 2.2 TLC5916 手册原文（⭐ 决定了防护的设计）

- 触发条件**不是某个 ns 宽度**，而是「**OE 的低电平恰好跨过 1 个 CLK 上升沿**」（判据 = CLK 上升沿采到 `101`）。
  ⇒ 只要"**CLK 静止时 OE 才变**"，就**结构性不可能**进入 Special Mode —— 这正是 R-01 防护 ② 的依据。
- **TI 官方给了恢复手段**（NOTES：该序列"may be used frequently to ensure … proper mode"）：
  发一次「1-CLK 宽 OE 脉冲 + LE 低」即可**强制回 Normal Mode**。⭐ 建议把它做进**上电自检**（把致命故障降级为可自愈）—— 列为待办。

## 四、其它有价值的调研结论（记下来，不一定马上做）

| 主题 | 结论 | 对我们的建议 |
|---|---|---|
| **波表深度** | 相位截断杂散 `SFDR ≈ 6.02 × W`（W=地址位宽）：256 项 → **48 dBc**；1024 项 → **60 dBc**；4096 项 → **72 dBc** | ⭐ 上 **1024 项**只多占 **1 块 BSRAM**（共 118 块）—— 性价比极高 |
| **相位累加器位宽** | 24 bit @50 MHz ⇒ 1 LSB = 2.98 Hz（A1 误差 **91 cents**，不可接受）；**32 bit** ⇒ A0 误差 0.73 cents | ⭐ **必须 32 bit**（乙的 T8 要注意） |
| **变调保相位** | 只要"只改 `phase_inc`、永不写 `phase`"，波形**天然连续**（ADI 原话："no phase discontinuity, or glitch"） | ✅ 与我们的 `K-10` 一致；`A7` 检查器已就绪 |
| **zipper noise 的真正来源** | 不是 `phase_inc` 阶跃，而是**增益/幅度阶跃** | 音量变化要做斜坡；`phase_inc` 不必插值 |
| ⭐ **有符号 `>>` 的 DC 陷阱** | 算术右移向 −∞ 取整 ⇒ **正的小余数会卡成固定点**，产生**单向 DC**（实测 16-bit 混音 1 个 count）；**多声部同号 DC 会相干叠加**（4 声部就削顶） | ⭐ 乙做 `sample*env>>N` 与混音时要**向零取整或加 DC blocker**；32 声部 headroom 要算 |
| **note steal** | 参考项目干脆不做（满了静默丢音） | ⭐ 我们有余量，应做"~1 ms 快速 release 的无 click 抢占"，否则 32 声部满时"按了没声音" |
| **ROM 初始化** | Gowin 官方路线是 **`pROM` IP + `.mi`**；`$readmemh` 的支持性**公开渠道查不到可靠来源**，且有 Gowin BSRAM 推断"仿真过、上板错"的真实案例 | ⭐ 波表落地时**优先 IP 路线**，并加"**rom[0]/rom[N] 回读**"验收（`U18` 的坑） |
| **按键上拉** | Sipeed 官方 `.cst` 注释：*"Keys must be internal pull-up, **there aren't any pull-up on the dock board**"* | ⛔ 按键/输入脚**必须写 `PULL_MODE=UP`**，否则浮空 |
| **复位** | 真正危险的是**异步复位的撤销时刻**（与时钟随机相位）；工具**默认不分析终止于异步复位端的路径** | ✅ 我们用**同步复位**（天然规避）；外部 `rst_n` 已加 2 级同步（`R-08`） |

## 五、⭐⭐ 变异测试（mutation testing）—— "判据不是摆设"的黄金标准

> ⭐ **为什么必须做这件事**：**"所有测试都通过"本身不能证明任何事** ——
> 如果判据根本不会失败，那么"全绿"和"没测"没有区别。
> 本项目的验收**全部依赖仿真**（没有系统板），所以"判据的有效性"是**最底层的前提**。
>
> 📌 做法（`bringup/mutation_test.ps1`）：拿**真实 RTL**，每次**只改一处**已知缺陷，
> 然后跑整条回归；**要求它必须变红**。若某个变异体仍然全绿 ⇒ 说明套件对该类缺陷**有盲区**。
> 每个变异体跑完**自动还原**并**逐字节核对**（还原失败时脚本 `exit 2`）。

**结果：13 个变异体全部被抓到（13/13）**

**第一层 · 变异"被测设计"（RTL）**

| 变异 | 改了什么（对应哪个历史缺陷） | 结果 |
|---|---|---|
| **M01** | `clk_gen` 帧计数回绕改成 `CLK_PER_SAMPLE-2`（帧长差 1） | ✅ 抓到 |

### 5.1 ⭐ tb 审查发现的两个**激励强度缺口**（已补）

> 审查方法：逐个 RTL 端口核对"是否真被断言"，再检查"激励是否可能**恰好避开**边界"。
> ⚠️ 先纠正一个**误报**：`led_heartbeat` 一度看似"零断言"，实际它在 `tb_top_m0` 里
> 用局部名 `hb_a` 被充分断言（`hb_a_trans >= 8` + 半周期精确）⇒ **覆盖是有的**。

| 缺口 | 问题 | 补法 |
|---|---|---|
| ⭐ **值域覆盖不足** | `tb/w3c/tb_i2s_tx.sv` 的正弦表**只有 64 个不同值**（256 帧 ⇒ 每值重复 4 次）⇒ 24 bit 里**绝大多数位模式从未出现**；对"某一位恒错/相邻位粘连/截断方向错"这类缺陷**是盲的** | ⭐ 新增 **`tb/w3c/tb_i2s_tx_prbs.sv`**：**LCG 伪随机 512 帧**（固定种子 ⇒ 可复现）+ **逐位走查 48 帧**（`1<<k` 与 `~(1<<k)`，k=0..23）+ **边界值 16 帧**（`7FFFFF/800000/0/FFFFFF/0000FF`）⇒ 全值域逐点一致（**L 578 / R 580 点，0 错**） |
| ⭐ **位序完备性** | `tb/drivers/tb_tlc5916_driver.sv` 只测 5 个字节（`00/A5/FF/3C/5A`）—— 覆盖了全 0/全 1/交替，但**"某一位接错或位序反"不一定被抓到**（例如只错 OUT3，而那 5 个字节恰好没让该位单独出现） | ⭐ 补 **逐位走查 8 个单 1 字节**（`0x01<<k`）⇒ 证明"每一位的位置与 **MSB-first** 位序都对"（8/8 通过） |

> ⚠️ **为什么新开一个文件而不是改 `tb_i2s_tx.sv` 的激励**：
> 那个 tb 同时产出 **M1 的证据链**（`sim/evidence/i2s_tx_l.csv` → FFT 单谱峰 + SNR）。
> 把激励换成随机流会让频谱变成噪声、**毁掉 M1 的证据**。⇒ 覆盖任务交给独立文件。
> ⭐ 这是"**一个 tb 一个职责**"的实例：证据 tb 保持干净、覆盖 tb 单独做。

⭐ 结论：**12 个变异体全部被回归抓到** —— 说明
① 每一条"已修"的 RTL 缺陷都有判据守着；
② **判据自身被破坏时也会被发现**（不是"检查器永远说 OK"）。
⛔ 将来若某个变异体变成 GREEN，就说明**那条判据被改坏了**。

> ⚠️ 使用纪律：变异测试会**临时改 RTL** ⇒
> ① 必须在**干净工作区**跑（跑完 `git status rtl/ tb/` 应为空）；
> ② 跑完**必须重跑一次干净回归**，否则 `sim/evidence/` 里可能留下"变异态"的日志。
