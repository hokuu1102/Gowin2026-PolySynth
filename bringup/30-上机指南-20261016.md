## 二、本轮必测（按优先级）

### A1. 内部鼓机（源 B）—— ⭐ 本轮核心修复：**能同时响多件了**

```
触发：键 0（源 B 开关：鼓机/节拍器）+ 键 8（鼓机节奏型）
```

**要测什么**

```
1. 四件鼓是否【同时响】（原来四件共用轴 15，同一时刻只能响一件）
2. 四件音色：底鼓 60Hz · 军鼓 480Hz · 踩镲 1920Hz · 嗵鼓 200Hz
3. 正常 funk 鼓型：底鼓 1/3 · 军鼓 2/4 · 踩镲八分 => 不缺件
4. 节奏型切换（键 8）是否跟着换
```

**判据**：改之前内部鼓机四件挤一个轴 ⇒ 互相抢 voice ⇒ **同时只能响一件**。改之后四件分轴 12/13/14/15，各自独立。

### A2. 键盘打鼓

```
触发：键 4（键盘打鼓开关）
```

```
1. 四件鼓各占一个键区（sel = src_a_axis[3:2]）
   按不同位置出不同鼓
2. 力度：max(键盘力度, 本件基础力度) => 轻敲也够响
3. 与 A1 对比：同一件鼓（如同为底鼓）在 A1 与 A2 下
   应该落在【同一个轴】=> 互相重触发，不叠成两个 voice
```

### A3. LED 指引（⭐ 本轮改动最大）

```
触发：灌谱后自动（或键 3 切显示模式看 HDMI 上的引导）
```

**⚠️ 重要预期**：LED 点亮现在**靠帧里 bits[4:0] 的 `note_off5`**（= MIDI 音高 − 45）。ESP32 侧**还没填这个字段**（现有 hex 那 5 位是 0），所以：

```
✅ 上板时 LED 很可能是【全暗】—— 这是已知的过渡状态，不是 bug
   旧的 hex：offset 0 = A2 => 查表是哨兵 => 不点灯
✅ 一旦 ESP32 填上 note_off5，灯会跟着音高走（同轨不同音高 => 不同灯）
```

**这条是"两边必须一起上"的第三处**。如果测到全暗，请确认 ESP32 的 `score_word.py` 是否已填 `note_off5`。

### A4. 鼓与旋律彻底分离

```
1. 灌一份含鼓轨的谱 => 鼓必须是鼓的发声（不是电子音）
2. 旋律轨绝不能变成鼓（结构保证，与轴号无关）
3. ⚠️ 镲片（46/49/51/52/53/55/57/59）目前【全部按 HiHat 发声】
   —— 这是本轮裁定的映射，别当成 bug
```

### A5. 键 14 = 一键恢复默认音高

```
1. 按变调升（键 6）几次，确认变了
2. 按键 14（列2行3）=> 变调回 0
3. 换一个偏移再来一次
```

### A6. 指板一次拨弦出和弦

```
1. 按住 2 个品，拨一次 => 两个音都响
2. 按住 3 个品，拨一次 => 三个音都响
3. 按 1 个品 => 仍只响 1 个（边界，别改过头）
4. 拨弦后松其中一品 => 只放掉那个音，其余继续
```

## 三、滑音（⭐ 触发条件很具体，先按这个试）

### 三个开关/模式前提

```
1. 滑音开关：键 2（必须开）
2. 模式：指板模式（键 7 或串口 'A'）
3. 硬件布局：【水平相邻】的 12 对（霍尔键位表，不是轴号相邻）
```

### 触发手势（三个条件同时满足）

```
① 水平相邻：A 和 B 必须是邻居表里的水平邻居
② 一减一增：
   · A 侧行程【减少】超过 8 码（dA < −8）
   · B 侧行程【增加】超过 64 码（dB > +64）
③ 时间窗口：A 离开后 1000 帧内（约 500 ms）B 要形成
```

### 你反馈"难触发、听不出" —— 手册里如实记录

```
可能原因（按排查优先级）：
1. 水平邻居关系不对 —— 请在 A 上按住，试【左右】邻居而不是任意两个
2. B 侧增量不够 —— 若按 A 时手已压到 B 边缘，从 A 移到 B 时增量可能很小
   => 试"更大幅度地滑过去"，或确认 B 是从零开始形成
3. 时间窗口 —— 从 A 离开到 B 越阈要在半秒内完成
4. 开关没开 —— 键 2 在指板模式下必须开
```

### ⚠️ 已知限制与"设计如此"的行为（⛔ 不是 bug）

```
1. 邻居表"同排相邻"：
   上排左：6-7-0-1     下排左：5-4-3-2
   上排右：14-15-8-9   下排右：13-12-11-10
   => ⛔ 跨排不算滑音（上排甩到下排）
   => ⛔ 跨板不算滑音（右手甩到左手）

2. ⭐⭐ "甩过多个键"时，滑音目标 = 行程最大的那个邻居
   —— 这是【有意的产品裁定】，不是 bug：
     本项目裁定"滑音模式开着 ⇒ 相邻先后发生就算滑音"，
     而"取行程最大"让 B 持续跟到【最终停下的那个键】，
     中间不会断成多段滑音（否则音高一跳一跳）。
   => 所以：快速从左甩到右时，滑音【一路跟到最右】而不是分段跳
   => ⚠️ 若你觉得"甩过两个键时音高/方向不对"，这是设计如此，
     ⛔ 不要当 bug 报；应在 slide_position_ctrl / 标定层看插值

3. 实际物理上，每个键的【同排邻居最多 2 个】（不是 4 个）
   =>"取最大"的搜索深度 ≤2（比预估更省）
```

## 四、效果器串口命令（速查）

### 帧格式与三条硬规则

```
71 <变量号> <值> FF FF FF
1. 值不能是 0xFF（帧尾）=> 最大 254
2. 值只有一个字节 => 增益只能表达 128 的整数倍（精确值用 gain-raw）
3. 上电 mask=0 => 效果器全旁路，必须先发 0x10
```

### 变量表

| 变量 | 名字 | 换算 | 默认 |
|---|---|---|---|
| `0x10` | mask | bit0=失真 bit1=合唱 bit2=延迟，bit4 空闲 | 0（全关） |
| `0x11` | gain | 值/16（64=4.0× · 254=15.875×） | 64 |
| `0x12` | trim | 值/128（32=0.25× · 128=1.0×） | 32 |
| `0x13` | mix | Q0.8，加湿量 | 128 |
| `0x14` | fb | Q0.8，延迟专用 | 96 |
| `0x15` | depth | 音量颤音深度（0=听不出） | **0** |
| `0x16` | rate | 音量颤音速率 | 7 |
| `0x17` | dlylen | 值×128 采样（64=168ms · 200 饱和到 333ms） | 64 |
| `0x18` | chorlen | 值×32 采样（23=15ms） | 23 |

### 最常用的十几条

```
71 10 00 FF FF FF     全关
71 10 01 FF FF FF     只失真
71 10 02 FF FF FF     只合唱
71 10 04 FF FF FF     只延迟
71 10 07 FF FF FF     全开（注意是 07 不是 17）

71 11 80 FF FF FF     gain=128 => 8.0×（要削顶至少要 8 倍）
71 11 C0 FF FF FF     gain=192 => 12.0×
71 11 FE FF FF FF     gain=254 => 15.875×
71 12 20 FF FF FF     trim=32 => 0.25×（默认）=> 净增益 1.0

71 17 40 FF FF FF     延迟 168 ms
71 17 C8 FF FF FF     延迟 333 ms
71 14 00 FF FF FF     反馈 0 => 只回一声
71 18 17 FF FF FF     合唱 15 ms
71 15 60 FF FF FF     ⭐ 音量颤音深度 96（默认 0，不发就听不出）
71 16 20 FF FF FF     颤音速率 32
```

### 用工具（省得手打）

```bash
python tools/fx_ctrl.py --port COMxx on / off / mask 0x01 / gain 128 / trim 128
python tools/fx_ctrl.py --port COMxx drive 200    # 驱动拉高，音量自动不变
python tools/fx_ctrl.py --port COMxx sweep        # 增益扫描
```

### 三个容易搞错的口径

```
1. 净增益 = gain × trim。默认 (64,32)=1.0。旧字节值 (128,64) 现在 = 4.0（响 12dB）
2. 全开 = 0x07，不是 0x17（bit4 是空转位）
3. 音量颤音 depth 默认 0（数值恒等）—— 不发 71 15 就听不出颤音
```

### 失真为什么听不出（你的实测已确认）

```
你实测输入约 1/8 FS，默认 gain 4.0× => 0.5 FS => 到不了削顶阈值
要削顶至少 gain 8.0×（71 11 80），推荐 12~15.9×
失谐导致削顶只在拍峰附近 => 间歇性破音 => 这是已知特性
```
