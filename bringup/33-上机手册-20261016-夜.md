## 二、🔴 本版修了什么（11 条，逐条带证据）

### 🔴 1. 上板回归：键盘无声 + 持续杂音 —— 根因是**约束，⛔ 不是 RTL**

| | |
|---|---|
| **根因** | `constr/top.cst` 把 `GROUP h5_scope` / `GRP_LOC h5_scope R[1:44]C[1:148]` **整条注释掉**（10-16 的 A/B 实验），**从未回退** |
| **为什么键盘死、灌谱活** | 键盘是**物理扫描型**（行列矩阵 + ADC + 消抖 + 时钟偏斜）⇒ 对布局敏感；灌谱是 **UART 喂的数字流** ⇒ 鲁棒。日志有 `PR1014 ... 'clk_d' ... excessive delay or skew` |
| **证据** | 同一次 PnR：setup 违例 **0 → 226** · `clk_sys` Fmax **61.071 → 55.571 MHz** · `Logic Level` 19 → 9 |
| **修法** | 把两行约束**恢复**（`constr/top.cst` 与 HEAD 逐字一致） |
| **修后** | 违例 **226 → 63** · Fmax **55.571 → 56.482 MHz** · 🔴 **上板键盘恢复** ✅ |
| **教训** | ⚠️ 交接文档曾写"已回退" —— **实际没有**。⭐ 纪律：**A/B 实验要么跑完落盘结论、要么当场回退，⛔ 不留中间态** |

### 🔴 2. 滑音判定链 **67 级 → 9 级**（时序）

```
改前：Logic Level 67 · Fmax 15.052 MHz · 304 条 setup 违例
      （最差 slack −50.033 ns，比 20 ns 周期还长 2.5 倍）
根因：滑音 B 的选法从"第一个形成就 break"改成"行程最大的同排邻居"
      ⇒ 16 次迭代、第 k 次依赖第 k−1 次 ⇒ 综合成 16 级串联 12 位比较器
修法：① 16 级串联链 → 4 级两两合并树
      ② 再 → 2 邻居直选（⭐ 关键洞察：候选最多 2 个，⛔ 不需要 16 路 argmax）
      ③ `is_h_adj(A,si)` → 16 位邻居掩码查表（干掉 384 个比较器）
结果：Logic Level 67 → 33 → 21 · 综合 Fmax 19.505 → 40.503 → 50.365 MHz
```

### 🔴 3. `left_ax_n` 取【最大】轴号的**语义回归**（真 bug）

```verilog
原循环丢了 `!left_hit` 短路 ⇒ 每个命中都覆盖 ⇒ 取【最大】轴号
而 HEAD 与 event_extract.v:328 的注释都是【最小】⇒ 语义回归
⇒ 同帧 ≥2 个轴离开时，滑音的 A 取错、B 配对集错、方向错
⚠️ 为什么仿真全绿：旧判据每次只驱动【一个】负 delta 轴 ⇒ 多轴同帧从未被测
✅ 新判据 tb/w3a/tb_ee_multileave.sv（改前必红 · 非空洞控制为绿）
```

### 🔴 4. 上行帧 `byte[7][3:0]` 鼓标记**只覆盖灌谱鼓**

| 来路 | 改前 `[3:0]` | 后果 |
|---|---|---|
| 灌谱鼓 | ✅ `drum_type` | 正常 |
| **键盘打鼓** | 🔴 **0** | ESP32 解成**旋律**（而 `[5:4]` 那时是 drum_type）|
| **内部鼓机** | 🔴 **上次 pop 的陈旧值** | 可能取到 4..15 越界值 |

```
修法：top.v 新增 `up_drum_mark_w` —— 三路鼓统一按 `mg_evt_axis[1:0]` 反推 drum_type
      （⭐ 三路鼓的轴号都等于 12 + drum_type）
      ⭐ 全程只用 evt_merge 下游信号 ⇒ 结构上不可能成环
      ⛔ 不再 OR 上 `sa_up_axis`（它是寄存器、对源 B/C 事件是陈旧值）
判据：tb/top/tb_top_upstream_timbre.sv 补"键盘打鼓 Snare ⇒ byte[7] = 0x11"
```
