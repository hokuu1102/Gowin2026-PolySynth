## 二、⭐ 要约束的信号（**7 个**，即全部端口）

| 信号名（`.cst` 里必须完全一致） | 方向 | 本工程已填的 ball | 出处 |
|---|---|---|---|
| `clk` | 输入 | **F13** | 官方 9 个基石板例程 + ADDA 实测 |
| `rst_n` | 输入 | **D1** | 同上（⚠️ 在 **1.2 V bank**：`LVCMOS12`） |
| `HP_BCK` | 输出 | **T18**（= **`J14.19`**） | ⭐ **J14 排针**（原 `DAC_D0`，本项目用不到） |
| `HP_WS` | 输出 | **F20**（= **`J14.20`**） | ⭐ 同上（原 `DAC_D1`） |
| `HP_DIN` | 输出 | **R17**（= **`J14.21`**） | ⭐ 同上（原 `DAC_D2`） |
| `led_heartbeat` | 输出 | **F21** | 官方 `02_LED_test` 例程 |
| ⭐ `beep` | 输出 | **A13** | 官方 9 个例程一致 + ADDA `beep_off` |

> ⚠️⚠️ **选脚要满足两个条件，缺一不可**（2026-09-17 实测踩到）：
> ① **能落位**（不报 `CT1113`/`PR2017`/`PR2028`）；
> ② ⭐⭐ **引到了"你够得着"的地方**（排针 / 焊盘 / 测试点）。
> ⛔ 我第一版选的 `K13/L14/L16` **只满足①** —— 它们**合法且能落位**，
> 但**板上没引到任何排针**（抽文核对过扩展板原理图，这三个脚不在上面）⇒ **根本量不到**。
> ⇒ ⭐ 现在改用 **`J14.19/20/21`**（`J14` 是 ADA107 的 **2×15 排针**，
> 脚位 19~30 是 DAC 那半边，本项目**用不到**）⇒ **杜邦线直插即可量**。

### ⚠️ 三条必须注意的

| # | 注意 | 为什么 |
|---|---|---|
| **1** | ⭐⭐ **`beep` 必须约束、且必须 `PULL_MODE=DOWN`** | `beep` 不约束 ⇒ 引脚悬空 ⇒ **一直叫**（对乐器项目是灾难）。⚠️ 而且光"驱动低"不够：FPGA **上电未配置完/复位期间引脚是高阻**，此时 NPN 基极可能被漏电顶起来 ⇒ **上电瞬间叫一声甚至持续叫**。⇒ 加弱下拉把那段窗口也钉低 |
| **2** | ⚠️ **`HP_BCK/HP_WS/HP_DIN` 的 ball 不能照抄官方例程** | 官方例程面向的**封装变体不同** ⇒ 有些 ball 会报 `CT1113 Can't find pad location`；⚠️ 还有些 ball **能解析但落不下去**（报 `PR2017`：专用脚 CPU/MSPI，或 `PR2028`）—— 与文档里 `R19` 那条是同一类坑 |
| **3** | ⚠️ **`rst_n` 是 1.2 V bank** | `LVCMOS12` / `BANK_VCCIO=1.2`。⛔ 写成 `LVCMOS33` 会报电平冲突（Dock 的 `AA13` 是 1.5 V，两者不同） |

### ⭐ 为什么要加"测试音"

正式顶层送的是**静音**（全 0）⇒ 上板只能看到 `BCK/WS` 在动、而 **`DIN` 是一条直线**
⇒ ⚠️ "**DIN 到底通没通**"**分不出来**。
⇒ 本工程加了 `TEST_TONE=1`（默认）：每 16 帧在 **±1/4 满量程**之间翻转 ⇒
**约 1526 Hz 方波**，示波器好触发、耳朵也能听见。
⛔ 它不是正式功能，只是"看得见"的探针；`TEST_TONE=0` 退回静音。

### 3.3 ⭐⭐ 换 ball 时：**用探测器，不要猜**

```powershell
# 编辑 probe_balls.ps1 顶部的 $BALLS 列表，然后：
powershell -NoProfile -ExecutionPolicy Bypass -File bringup\jishi\probe_balls.ps1
```

它对每个候选 ball 建一个**最小工程**跑一遍，打印 `legal` / `ILLEGAL`。

> ⭐⭐ **为什么必须用工具问，而不是查例程**（本次实测踩到）：
> | 现象 | 报错 | 含义 |
> |---|---|---|
> | ball 在这个封装里不存在 | `CT1113 Can't find pad location` | 例程里的 ball **不能照抄**（封装变体不同） |
> | 存在但**落不下去** | `PR2017 … is a dedicated pin (CPU/MSPI)` | 被**龙芯 CPU 占用**（同 `R19` 那条坑） |
> | 约束无意义 | `PR2028 The constrained location is useless` | 该 ball 在当前封装不可用 |
>
> ⇒ ⭐ **"能解析" ≠ "能用"**：探测器必须把**三种报错都当 ILLEGAL**（第一版我只查了 `CT1113`，
> 于是 `L12` 被判成 legal，正式跑时才在布局阶段报 `PR2017`）。
> 📌 规矩：**每一次换 ball 都要重跑探测器**，⛔ 不要凭"上次能用"推断。

### 阶梯 2 · ⭐⭐ I2S 三线在动（**上板的核心判据**）

> ⚠️ 基石板**没有 I2S DAC**（那是 Dock 才有的 PT8211）⇒
> 这三根**只是引出来给示波器/逻辑分析仪看**。

#### 2.0 ⭐⭐ 怎么接示波器（**先看这节，接线错了后面全是白测**）

| 信号 | **`J14` 引脚号** | 板上位置 | 探针接哪 |
|---|---|---|---|
| **`HP_BCK`**（位时钟） | **`J14.19`**（ball `T18`） | ADA107 排针，**下半排靠里** | **CH1** |
| **`HP_WS`**（帧时钟） | **`J14.20`**（ball `F20`） | 19 的隔壁 | **CH2** |
| **`HP_DIN`**（数据） | **`J14.21`**（ball `R17`） | 20 的隔壁 | **CH3**（双通道机可先不接） |
| **GND** | `J14` 上的 **GND 脚**（或板上任意 GND） | — | ⭐⭐ **探针夹子/地线必须接** |

> ⭐ **接线方式：杜邦线（母头）直插 `J14` 排针即可**（`J14` 是 2.54 mm 排针）。
> ⛔ **不需要 SMA/BNC**：见 §2.0b（为什么）。

**⭐ 2.0b 为什么不用 SMA/BNC（也不需要改任何代码）**

| 事 | 归谁管 |
|---|---|
| I2S 用哪个 ball | ⭐ `.cst` **一行**（已定 `J14.19/20/21`） |
| 信号怎么引到示波器 | ⭐ **物理层**：杜邦线 / 排针 / 焊 SMA 座 |

⭐ **SMA 只是"最后一厘米"的接头形式** —— FPGA 到排针之间那段是**数字信号**
（3.3 V、**3.125 MHz**），**杜邦线 / 排针 / SMA 在电学上没有区别**。
SMA 的价值在**高频 / 长距离 / 阻抗匹配**；而这里信号只有 **3.125 MHz、飞线 ≤10 cm**，
⇒ ⚠️ 焊 SMA 反而多三样麻烦（要焊座、要配 SMA 转 BNC 线、还要考虑阻抗不连续），**收益为零**。
📌 另外：**这块基石板上没有 SMA/BNC 座**（抽文核对过扩展板原理图；`SMBJ12CA` 是 TVS 二极管、不是座子）。

> ⭐ **什么时候才值得上 SMA**：信号 > 50 MHz、线长 > 30 cm、或需要 50 Ω 匹配时
> （例如以后要测 DDR3/HDMI/SerDes）。⛔ 本阶梯这个信号**不属于**这类。

**⭐ 2.0c 示波器设置（照这个设，别自己试）**

| 项 | 设置 | 为什么 |
|---|---|---|
| **耦合** | **DC**（⛔ 不是 AC） | 是数字方波；AC 耦合会把 0/1 直流电平也滤掉，波形会变形 |
| **探头** | **×10**，⚠️ **示波器里也要选 ×10** | 3.125 MHz 用 ×10 更准；⛔ 只在探头上拨 ×10 而软件没选，幅度会显示差 10 倍 |
| **电压档** | **1 V/div** | 3.3 V 信号占约 3 格 |
| **时基** | `BCK` → **200 ns/div**；`WS` → **5 µs/div**；⭐ `DIN` **帧结构** → **2 µs/div**（要装下 10.24 µs）；`DIN` **脉宽交替** → **200 µs/div** 或用 `+Width` 测量 | ⭐ **规矩：屏上总跨度 = 时基 × 格数，必须 ≥ 2×你要判的周期**。⚠️ 实测踩过：用 **100 ns/div**（跨度仅 ≈1 µs）去看 **10.24 µs** 周期的 `DIN` ⇒ **连一个周期都装不下** |
| **触发** | **上升沿**、源 **CH1**、电平 **1.5 V** | `BCK` 稳、好触发 |
| **带宽限制** | ⭐ **量电平/时序时开 20 MHz 限带**；⛔ 只在"专门看边沿质量"时才关 | ⭐ **2026-09-18 修正**：3.125 MHz 方波的能量集中在前几次谐波（≤16 MHz）⇒ 20 MHz 限带**不影响**周期/电平/相位判据，却能把**飞线振铃**滤掉。⚠️ 全带宽 + 长地线 ⇒ 屏上全是振铃，会把**正常信号判成"信号质量差"** |
| **探头地线** | ⭐ **用最短的弹簧地**；⚠️ 没有探头、只有鳄鱼夹时见 §2.0c-3 | 长地线会在 ns 级边沿上引入振铃，让你误判成"信号质量差" |

**⭐ 2.0c-2 触发源怎么选（⛔ **不用**接 `EXT TRIG`）**

| 问 | 答 |
|---|---|
| 触发源要"接"到示波器上吗？ | ⛔ **不用**。触发源是**示波器内部**从**已经接好的通道**里选一路（菜单里 `Trigger Source = CH1 / CH2 / …`）⇒ ⭐ **那一路探头接好 = 触发源就接好了** |
| 那 `EXT TRIG` 那个 BNC 是干嘛的？ | 只给两种情况用：① 有**三个以上**信号但通道不够 ② 要拿**外部时钟**当基准。⭐ 本阶梯**两样都不占** ⇒ 用不到 |
| 双通道机：量 `BCK`/`WS` | `CH1 = HP_BCK`（⭐ **触发源 CH1**、**上升沿**、1.5 V）× `CH2 = HP_WS` |
| 双通道机：量 `DIN` | ⭐ `CH1 = HP_WS`（**触发源 CH1**、⭐ **下降沿** = 帧起点）× `CH2 = HP_DIN`（这样脉冲在屏上的**位置**才有意义） |
| 四通道机 | `CH1 = HP_BCK`（触发源）、`CH2 = HP_WS`、`CH3 = HP_DIN` |
| ⚠️ 屏上"乱 / 抖 / 抓不住" | 99% 是**触发源选到了没接的那一路**（示波器退化成 AUTO 自由跑）；其次才是**触发电平跑到信号范围外**（3.3 V 逻辑 ⇒ 电平取 **1.5 V**） |

**⭐ 2.0c-3 没有探头、只有鳄鱼夹怎么办（2026-09-18 实测补充）**

⚠️ 鳄鱼夹的**长地线 = 一个大环路天线** ⇒ 在 ns 级边沿上**必然**振铃/过冲。
⭐ **这不是被测信号的毛病**，换谁夹都一样。
⭐⭐ **关键在于：振铃只污染"边沿"，不污染"电平"和"周期"。** ⇒ 判据要**挑不受振铃影响的量**：

| 量 | 鳄鱼夹下可信吗 | 为什么 |
|---|---|---|
| **周期 / 频率** | ✅ **可信** | 测的是**阈值穿越时刻**；限带后振铃被压掉，穿越点不受影响 |
| **高 / 低电平** | ✅ **可信** | 平顶是稳的，振铃只在跳变处 |
| **脉宽 / 占空比**（在平顶中部量） | ✅ **可信** | 同上 |
| ⛔ **建立/保持时间**（第 4 步那个 160 ns） | ⛔ **不可信** | 它**恰好就是**"边沿时刻" ⇒ 被振铃糊掉 |
| ⛔ 上升时间 / 过冲幅度 / 边沿质量 | ⛔ **不可信** | 同上（要探头才测得了） |

**减轻办法（不花钱，按效果排序）**
1. ⭐⭐ **开示波器的 20 MHz 带宽限制** —— 最有效、零成本（见 §2.0c 表）
2. ⭐ **地夹夹在"离被测脚最近的 GND"上**（`J14` 上就有 GND），⛔ 别夹到板子另一头的 GND
3. ⭐ **信号线与地线并在一起走**（贴紧 / 双绞），把**环路面积**压到最小
4. ⭐ 飞线本身**越短越好**（≤10 cm）

**⚠️ 2.0c-4 鳄鱼夹的第二个坑：两个通道可能互相串扰（`[假设]` —— ⚠️ 尚未验证，2026-09-18）**

> ⚠️⚠️ **状态标签 `[假设]`**：下面这条是**从原理推出来的可能性**，**我没有实测到它**。
> 写在这里是为了**下次遇到时知道往哪查**，⛔ **不要当成已确认的结论**。

两根**长信号线并排**时，一根线上的**快速边沿**可能耦合到另一根上，在被测通道上造出一个
⭐ **与那条边沿"时间上重合"的窄尖峰**。它**长得像"数据脉冲"**，但**不是**。

⭐ **若真出现，怎么分辨"串扰尖峰"和"真数据脉冲"** —— 看它**相对帧起点的位置**：

| 现象 | 含义 |
|---|---|
| 尖峰 ⭐ **正好压在**另一路的跳变沿上（≈0 ns 偏差） | ⚠️ 疑似**串扰**（待验证） |
| 尖峰出现在帧起点后 ⭐ **≈5.12 µs（= 16 个 `BCK`）** | ✅ 这才是 `DIN` 的真数据脉冲（见 §2.0d-2） |

> ⭐ **为什么设计上能这样判**：`JUSTIFY=1`（LSBJ 右对齐）⇒ 每个时隙的**前 16 个 `BCK` 恒为 0**
> ⇒ ⭐ **任何时隙边界前后约 5 µs 内，`DIN` 必须是平的**。
> ⇒ 所以"贴着 `WS` 跳变沿的窄脉冲"**在物理上不可能是数据**。

**若怀疑串扰，这样验证/消除**：① 两根夹子的走线**分开**、别并排贴在一起；
② ⭐ **一次只夹一根线**（另一根拔掉）来做单信号判据 —— 本阶梯的判据**本来就不需要同时夹两根**；
③ 若"分开走线后尖峰消失" ⇒ ⭐ **坐实是串扰**（这一步做了才算 `[已确认]`）。

> ⭐⭐ **结论**：鳄鱼夹足够验完 §2.0d 的**第 1~3 步**（频率 / 电平 / 相位 / 脉宽都在"平顶"上）；
> ⛔ **只有第 4 步（160 ns 建立/保持）必须等探头** —— 那一步量的正是被振铃污染的区域。
> ⇒ ⛔ **别因为"边沿有振铃"就判信号有问题**；也⛔ **别用鳄鱼夹去量建立时间**（量到的是振铃，不是真相）。

**⭐ 2.0c-5 读数纪律：三条"读到了但不算数"的坑（2026-09-18 实测踩到）**

| # | 坑 | 规矩 |
|---|---|---|
| 1 | ⭐⭐ **时基太短 ⇒ 屏上装不下一个周期** | 屏上总跨度 = **时基 × 格数**（本机 10 格）。⭐ 要判"**每 T 出现一次**"，总跨度必须 **≥ 2T**。⚠️ 实测踩到：用 **100 ns/div**（跨度仅 **≈1 µs**）去看 **10.24 µs** 周期的 `DIN` ⇒ ⛔ **连一个周期都装不下**，只能证明"在动"，判不了"多久一次" |
| 2 | ⭐⭐ **光标随手卡 ⇒ 读数作废** | 光标读数（`Δ206ns`/`Δ3.28V`）**只有在放在"判据定义的那两个点"上**才是证据。⛔ 随手卡出来的 Δ 值**看起来很像结论**，实际什么都证明不了。⭐ 放光标前先写清"我要量的是哪两个沿/哪两个电平" |
| 3 | ⭐ **频率计测的是"触发源那一通道"** | 双通道机上频率计**只显示触发源通道**的频率。⇒ 想量另一路的频率，**先把触发源切过去**。⚠️ 别把"CH2 的读数"当成"CH1 的读数" |

> ⭐ **通用规矩**：**先确认"这一屏的档位能不能装下我要判的东西"，再去看波形。**
> 档位选错时，屏上的一切都"看着像有问题"（`L61` 的同类坑：判据与观测口径不匹配）。

**⭐ 2.0d 测量顺序（按这个顺序，每步有明确判据）**

**第 1 步 · 只看 `HP_BCK`（CH1，200 ns/div）** —— 最基础

| 该看到 | 判据 |
|---|---|
| ⭐ **3.125 MHz 方波**（周期 **320 ns**、高电平 **160 ns**） | 就是仿真里验过的数字 |
| 幅度 **3.3 V**（×10 探头在示波器上显示 0.33 V，若软件也选了 ×10 则显示 3.3 V） | 电平正常 |
| 边沿干净、无振铃/过冲 | ⚠️ 有过冲 ⇒ 飞线太长（可串 22~33 Ω 源端电阻） |

**第 2 步 · 加 `HP_WS`（CH2，5 µs/div）**

| 该看到 | 判据 |
|---|---|
| ⭐ **48.828 kHz 方波**（周期 **20.48 µs**） | 与 `BCK` 同源 |
| ⭐⭐ **`WS` 的跳变与 `BCK` 的"下降沿"对齐**（⛔ 不是上升沿） | ⭐ **这条最关键** —— 它证明 `R-03` 的修法（`HP_BCK` 复位极性）在**真硅片**上生效 |

**第 3 步 · 加 `HP_DIN`（`CH1=WS` 触发、`CH2=DIN`，⭐ **时基 2 µs/div**）**

| 该看到 | 判据 |
|---|---|
| ⭐ **每隔 10.24 µs 一根窄脉冲**（= 频率计读 **≈97.66 kHz**） | ⚠️⚠️ **这是对的，不是故障** —— 见 §2.0d-2（左右声道送同一路数据 ⇒ 波形按**一个时隙**重复，⛔ 不按音频周期重复）。⛔ **时基必须 ≥2 µs/div** 才装得下这个周期 |
| ⭐ 脉冲出现在**帧起点后 ≈5.12 µs**（`WS` 下降沿之后） | 这就是 `JUSTIFY=1`（右对齐）在真板子上的样子 |
| ⭐ 脉冲宽度在 **320 ns ↔ 640 ns** 之间**慢慢交替**（每 ≈328 µs 换一次） | 这才是那个 **1526 Hz 测试音**（它只体现在**脉冲宽度**上）⇒ 用 **`+Width` 测量**看读数跳变 |
| ⛔ 若 `DIN` 是**一条直线** | 才会真的是故障：① `TEST_TONE=0`（那是静音）② 数据通路断 |

**第 4 步 · ⭐⭐ 量建立/保持（价值最高的一步）**

接法：触发源选 **`HP_WS`**、观测 **`HP_DIN`**、时基 **100 ns/div**，
放大到某个数据跳变处，量：

```
HP_DIN 的跳变沿  →  下一个 HP_BCK 上升沿     应 ≈ 160 ns
```

⚠️ **这一量法有个前提**（2026-09-18 补）：`BCK` 上升沿**不落在** `DIN` 的跳变沿附近
（按 §2.0d-2，`DIN` 只在第 16/17 位附近动，`BCK` 每 320 ns 一个沿 ⇒ 附近**必有**一个上升沿）。
⭐ 量的是**"最近的**那个上升沿**"** —— 先确认屏上那两根线的**时间关系**，别把"下一个"数错成"上一个"。

⭐ 这就是 PT8211 手册要求的那件事（**DAC 在 `BCK` 上升沿采 `DIN`**）。
仿真里 `tb/w3c/tb_i2s_tx_timing.sv` 测得 **tSU = tHD = 160 ns** ——
**这一步就是拿真实板子复现同一个数字**。
⚠️ 若量到接近 0 ⇒ 抢跑（`R-03` 复发）⇒ 查 `HP_BCK` 的复位值。
⛔⛔ **必须用探头量**：鳄鱼夹的长地线在边沿上振铃，**恰好污染的就是这个 160 ns**（见 §2.0c-3）。

**⭐ 2.0d-2 `HP_DIN` 到底该长什么样（2026-09-18 上板实测后补：⚠️ 别拿"1526 Hz 方波"去套它）**

⭐ **先把账算清楚**（这一步是**纸上推算**，但与实测读数吻合）：

| 量 | 值 | 怎么来的 |
|---|---|---|
| `DIN` 的**重复周期 / 频率** | ⭐ **10.24 µs / 97.656 kHz** | 一个声道时隙 = `SLOT_BITS` **32** 个 `BCK` = 32 × 320 ns = 10.24 µs；⭐ **左右声道送的是同一路数据** ⇒ 整帧 = 两个**一模一样**的时隙 ⇒ 波形**按半个帧重复** |
| ⭐ 频率计读 **≈97.66 kHz** | ✅ **正常，不是故障** | 频率计读的是"**最内层重复周期**"，⛔ **不是音频频率**（频谱里的"基频"要看**包络**，不是看单根线的重复） |
| **1526 Hz 体现在哪** | ⭐ **脉冲宽度的慢变化**，周期 **655.36 µs**（= 32 帧） | `TONE_HALF=16` ⇒ 每 16 帧（**327.68 µs**）宽度变一次 |
| 一个 10.24 µs 时隙内的结构 | 前 **16 个 `BCK` 全低**（时隙前半 = 空），后 16 个 `BCK` 才是数据 | `JUSTIFY=1`（LSBJ 右对齐）⇒ 数据占时隙**尾部** |
| ⭐ `DIN` 的脉冲形状 | `+1/4` 半周 ⇒ 只有 **1 个 `BCK`** 高（**320 ns**）；`−1/4` 半周 ⇒ **2 个 `BCK`** 高（**640 ns**） | `+1/4 FS = 0x4000` 的高 16 位里**只有 1 个 1**；`−1/4 FS = 0xC000` 是 **2 个 1**（符号位 + 符号扩展位）⇒ ⚠️ **两个半周长得不一样是设计使然**，⛔ 别当成 bug |
| 脉冲出现的时刻 | 帧起点后 **≈5.44 µs / ≈15.68 µs**（每帧两根） | 每个时隙从第 16 位开始出数据（`b = 16 + i2`） |

⭐⭐ **结论：`DIN` 的正确画法是"每隔 10.24 µs 一根 320 ns / 640 ns 的窄脉冲"**，
⛔ **不是** 1526 Hz 的方波，也⛔ **不该**每 `BCK` 都翻（那才是真错）。
想在屏上"看见" 1526 Hz，只有两个办法：
① ⭐ 打开示波器的**脉宽测量**（`+Width`），看读数在 **320 ns / 640 ns** 之间**每 ≈328 µs 跳一次**；
② ⭐ 去看 **DAC 的模拟输出**（阶梯 3），那里才是真正的 1526 Hz 方波。

> ⭐ **这里吃到一条通用教训**（已记入经验库 `L61` / `U55` / `TROUBLESHOOTING 66 号`）：**"某根线上的频率"取决于它的重复结构**，
> ⛔ 不能拿"设计里那个音频频率"直接去对。串行数据/时钟分频/帧结构这类信号，
> 必须**先算清"最小重复单元"**再定判据，否则会把**正常波形判成故障**（也会反过来把故障判成正常）。

#### 2.1 逐项判据（接好线之后跑这张表）

| # | 测什么 | ✅ 期望值（⭐ 就是仿真里验过的数字） | ⚠️ 不对说明 |
|---|---|---|---|
| 2.1 | `HP_BCK`（`J14.19`）频率 | ⭐ **3.125 MHz** 方波，占空比 ≈ 50% | 频率 = 表值的一半/两倍 ⇒ 时钟不是 50 MHz 或分频参数被改 |
| 2.2 | `HP_BCK` 高电平时间 | ⭐ **≈ 160 ns**（手册 `tH ≥ 25 ns`，裕量 6.4×） | 明显更短 ⇒ 分频不对 |
| 2.3 | `HP_WS`（`J14.20`）频率 | ⭐ **48.828 kHz**（周期 **20.48 µs**） | 与 2.1 同源问题 |
| 2.4 | `HP_WS` 相对 `HP_BCK` 的相位 | ⭐ `WS` 变化发生在 **`BCK` 下降沿那一刻**（数据/WS 同沿变） | ⚠️ 若 `WS` 与 `BCK` 上升沿对齐 ⇒ `HP_BCK` 复位极性被改回去了（那会重现 `R-03`） |
| 2.5 | ⭐⭐ **`HP_DIN`（`J14.21`）有没有在动** | ⭐ **每隔 10.24 µs 一根窄脉冲**（频率计读 **≈97.66 kHz** = `BCK`/32）；脉冲宽度在 **320 ns ↔ 640 ns** 之间每 **≈328 µs** 交替（`TEST_TONE=1` 时） | **一条直线** ⇒ ① `TEST_TONE=0`（正常，那是静音）② 数据通路断。⚠️ ⭐ 读数是 **97.66 kHz** ⇒ **正常**（见 §2.0d-2），⛔ 别按"1526 Hz"去判故障 |
| 2.6 | ⭐ **`DIN` 的建立/保持**（= 上面"第 4 步"） | 数据变化沿超前 `BCK` **上升**沿 ⭐ **≈ 160 ns** | 建立时间≈0 ⇒ 抢跑（`R-03` 复发）⇒ 查 `HP_BCK` 复位值 |

> ⭐ **2.5 与 2.6 是这块板最值得看的**：仿真里 `tb/w3c/tb_i2s_tx_timing.sv` 测出
> **tSU = tHD = 160 ns / WS setup = 160 ns**，这里就是**用真实板子复现那个数字**。
