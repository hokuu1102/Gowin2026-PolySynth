## 一、🔴🔴 第一件事：把串口弄通（⭐ 最重要）

### 1.1 ⭐ 先看清「该接哪三根线」（⭐ 从 `.cst` 读出的真值）

| ⭐ FPGA 信号 | ⭐ ball | ⭐ **J9 针号** | ⭐ 接 USB-TTL |
|---|---|---|---|
| ⭐ `uart_rx` | ⭐ **`D14`** | ⭐ **`N26`** | ⭐ **USB-TTL 的 `TX`** |
| ⭐ `uart_tx` | ⭐ **`D15`** | ⭐ **`N25`** | ⭐ **USB-TTL 的 `RX`** |
| ⭐ GND | ⭐ — | ⭐ `J9` 的 **`GND`** | ⭐ **GND** |

### 🔴🔴 **最容易犯的错：接错到 `N24`**

```
⭐ `N24` = `led_oe_n[4]`（⭐ LED 的使能）—— ⛔ **不是 UART！**
⭐ 而 `N25`/`N26` 就紧挨着它 ⇒ 🔴 **非常容易数错一格**
```

⭐ **`J9` 下半部分的针号顺序（⭐ 从 `.cst` 排出来的）**：

```
  N16 ··· N17  N18  N19  N20  N21  N22  N23  N24  N25  N26
            ↑    ↑    ↑    ↑    ↑    ↑    ↑    ↑    ↑    ↑
          led  led  led  oe0  oe1  oe2  oe3  oe4  ⭐uart uart
          _le  _sdi _clk                          _tx  _rx
                                               (D15) (D14)
```

⇒ ⭐ **认准"最边上那两根"** —— `N25`/`N26` 是**靠边**的，⭐ `N24` 是它旁边第一根 LED 线。

### 1.2 ⭐ 操作步骤（⭐ 按顺序）

| # | ⭐ 动作 | ⭐ 判据 |
|---|---|---|
| **1** | ⭐ **确认用的是外接 USB-TTL**（⛔ 不是板载 DAP） | ⭐ 设备管理器里应出现一个新 COM 口 |
| **2** | ⭐ **接线**：`TX→N26`、`RX→N25`、`GND→GND` | ⭐ 三根都要接（⭐ **GND 必须接**，⚠️ 不接会乱码/无响应） |
| **3** | ⭐ **烧板**（⭐ 见 §二） | ⭐ `Operation "Reprogram" Finished` |
| **4** | ⭐ **找 COM 口**（⭐ 命令见下） | ⭐ 记下那个**新出现的**口 |
| **5** | ⭐ **发 `'P'` 试探** | ⭐ **回 `P<通道><4位数>`**（⭐ 8 字节）⇒ ✅ **通了** |

```powershell
# ⭐ 找串口（⭐ 插入 USB-TTL 前后对比，看新增了哪个）
python -c "import serial.tools.list_ports as p; [print(x.device,'|',x.description) for x in p.comports()]"

# ⭐ 试探（⭐ 把 COMx 换成你的口）
python tools\board_probe.py COMx --send "P,P,P"
```

### ⭐⭐ 如果还是不通（⭐ 按这个顺序排查）

| # | ⭐ 检查 | ⭐ 判据 |
|---|---|---|
| **1** | ⭐ **TX/RX 是不是接反了** | ⭐ **对调一下再试**（⭐ 这是最高频原因，⭐ 成本最低） |
| **2** | ⭐ **GND 接了吗** | ⭐ 不接 GND ⇒ **必然不通或乱码** |
| **3** | ⭐ 是不是接在 `N24` 上了 | ⭐ 挪到 `N25`/`N26` |
| **4** | ⭐ 波特率 | ⭐ **`500000`**（⭐ `BAUD_DIV=100`）；⭐ 8N1、⛔ 无流控 |
| **5** | ⭐ USB-TTL 电平 | ⭐ **必须是 3.3 V** ⚠️（5 V 可能损坏 `D14`） |
| **6** | ⭐ 板子烧了吗 | ⭐ `.fs` 是 **SRAM 配置，断电就丢** ⇒ ⭐ 断电过就要**重烧** |
| **7** | ⭐ 串口助手 | ⭐ 关掉"显示发送"（⚠️ 否则分不清收发）；⛔ 别让别的软件占着口 |

📌 **⭐ 通了之后立刻做这件事**：⭐ **把 COM 口号记下来**（⭐ 后面所有命令都要用）。

### ✅ 验证 ②：`'S'` 是否回轴号（⭐ `K-132` 复核）

```

         ✅ **每个 `!` 前面都有轴号** ⇒ ⭐ `K-132` 修复生效
```

📌 **上一轮已上板确认过一次**（⭐ `s0!0!0!0!0!0!0!0!0!` ⇒ 轴号 **9** 次）⇒ ⭐ 这次是**复核**。

### ⭐⭐ 验证 ③：`span` 卡在哪一步（⭐ **串口通了才能做**）

```
⭐ 动作：⭐ 发 'S' 后【立刻】连发 5~10 次 'V'
   ⭐ **用脚本自动做**（⭐ 人工来不及 —— ⭐ `'S'` 几秒就跑完 9 轮）：
   python tools\board_probe.py COMx --send S --follow V --follow-gap 0.05 --follow-count 20
```

| ⭐ 看到 | ⭐ 含义 | ⭐ 下一步 |
|---|---|---|
| ⭐ 一直 `V2xx` | 🔴 卡在 **SETTLE**（⭐ 稳定判定过不去） | ⭐ 印证"ch2 帧间噪声大" |
| ⭐ 一直 `V3xx` | 🔴 卡在 **VOTE**（⭐ 收不齐 8 帧） | ⭐ 查 `sample_valid` 丢帧 |
| ⭐ 在 `1/2/3` 之间跳 | ⭐ 走到 FIRE 被拒 | ⭐ 离散度超 |
| ⭐ `V7xx` | ⭐ 已放弃（rej 到顶） | ⭐ 跑了 9 轮 |

⚠️ **格式**：⭐ `V<state><axis><rej><固定'0'>`（⭐ 末尾那个 `'0'` 是**硬编码常量**，⛔ 不是数据 —— ⭐ `K-133`）

### ⭐⭐ 验证 ④：ch2 的硬件排查（⭐ **本次最重要的硬件实验**）

```
⭐ 动作：⭐ 把"被拒那一路"与"正常那一路"的【传感器对调】
```

| ⭐ 结果 | ⭐ 结论 |
|---|---|
| 🔴 "被拒"**跟着传感器走** | ⭐ **传感器或其接线**有问题 |
| 🔴 "被拒"**跟着通道号走** | ⭐ **板上走线 / ADC 通道**有问题 |

📌 **一次对调就能把范围劈成两半**（⭐ 见 `files/20-代码/待查异常-span被拒-定案-20260925.md`）

⚠️ **⛔ 不要先放宽 `STABLE_TOL`** —— 🔴 那会让 `vmin/vmax` 被噪声撑开
⇒ 🔴 **记下的满行程码是错的** ⇒ ⚠️ **"标定成功但值是错的"比"标定失败"更糟**。

### ⭐⭐ 验证 ⑤：外置 DAC 出声（⭐ 今天的新硬件）

#### 🔴🔴 接线前必读三条（⛔ 违反会烧/没声）

| # | ⭐ 警告 |
|---|---|
| **1** | 🔴🔴 **⛔ 绝对不要接到板载 `J5`** —— ⭐ 它是 **BTL 输出**，⚠️ **接有源音箱会烧** |
| **2** | 🔴 **模块必须【带板载晶振】** —— ⭐ `PCM5102A` 靠它从 BCK 恢复时钟；⛔ 没晶振 ⇒ **没声/爆音** |
| **3** | ⚠️ 接音箱的 **`Line In`**（⛔ 不是功放/BTL 输入） |

#### ⭐ 接法（⭐ 从 `.cst` 读出的真值）

| ⭐ FPGA 信号 | ⭐ ball | ⭐ `PMOD1` 脚 | ⭐ 接 `PCM5102A` |
|---|---|---|---|
| ⭐ `I2S2_BCK` | ⭐ **`F20`** | ⭐ `IO3` | ⭐ **BCK** |
| ⭐ `I2S2_LRCK` | ⭐ **`E22`** | ⭐ `IO4` | ⭐ **LRCK** |
| ⭐ `I2S2_DIN` | ⭐ **`D22`** | ⭐ `IO5` | ⭐ **DIN** |

⭐ **另外必须接**：⭐ 模块的 **`VIN` → 3.3 V**、⭐ **`GND` → GND**。

#### ⭐ 判据

| ⭐ 判据 | ⭐ 期望 |
|---|---|
| ⭐ **音箱出声** | ✅ **且板载【同时】也有声**（⭐ 两路并存） |
| ⭐ 若有示波器 | ⭐ `F20` ≈ **3.125 MHz** · ⭐ `E22` ≈ **48.83 kHz** |
| ⚠️ 若"移位/噪声" | ⭐ 调**外置这一路**的 `JUSTIFY`/`MSB_DELAY`（⭐ 板载那路已验证是对的） |
| ⚠️ 若完全没声 | ⭐ 查：⭐ ① 模块有晶振吗 ② 3.3 V 供电 ③ 接的是 `Line In` 吗 |

📌 **最省事的判别**：⭐ **板载有声、外置没声** ⇒ ⭐ 问题在**外置接线/模块**
（⭐ 因为两路信号在仿真里是**逐拍完全相同**的 —— ⭐ 65536/65536 拍）。
