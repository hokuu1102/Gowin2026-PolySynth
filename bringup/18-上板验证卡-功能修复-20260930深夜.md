### 一、⭐ 上电正常时的【现象时间线】

| 时间 | ⭐ 你该听到 / 看到 |
|---|---|
| **0 s** | 上电 ⇒ 电源灯亮 · `CFG_LED`（`V13`）**绿灯 ~1 Hz 闪**（⭐ 唯一的活体见证） |
| **40 ms ~ 1.04 s** | ⭐ **自检和弦**：A4 + C#5 + E5 **同时响** ⇒ 约 **1 秒后自己停** ⇒ 之后**安静** |
| **≈0.2 ~ 1 s 之间** | 串口吐一个 **`T`** ⇒ ⭐ **这就是"可以开始弹了"的信号**（autotare 跑完） |
| **之后** | ⭐ **按第一下键就出声**（⛔ 不用先按十几个键）· 每个键发**它自己的音** · 按住 ⇒ 松开**正常衰减、不挂音** |
| **复位** | ⭐ **与上电完全一致**（等 ~1 秒、按第一下就出声）—— ⭐ **这就是"修A"的全部意义** |

⚠️ **从复位到串口出 `T` 之前，手别碰键**（⭐ 否则零点可能被记成"按下的位置"）。

### 二、⭐⭐ 修前现象 vs 修后现象（⭐ 一张表看完）

| # | 你听到 / 看到 | 🔴 修前（故障现象） | ✅ 修后 |
|---|---|---|---|
| **1** | **自检和弦** | 🔴 **"分解版"** —— 三个音**不是一个一个响**（16 轴全被判"按下"⇒ 事件洪泛） | ⭐ **三个音同时响**，1 秒后干净停下 |
| **2** | **第一下键** | 🔴 **要按十几个键才出声**（只有"碰巧捕获对零点"的轴能响） | ⭐ **第一下就出声** |
| **3** | **复位之后** | 🔴 **"复位一下就好了"**（复位**保留**了上次的零点，所以复位后正常、上电反而不正常） | ⭐ **复位 == 上电**，两者行为一致 |
| **4** | **某几个键** | 🔴 某个键**怎么按都不响**（零点被记成"按下位"⇒ `pos ≡ 0`） | ✅ 正常出声。⚠️ **但有个例外** ⇒ 见 §三 |
| **5** | **板2 的音量** | 🔴 ⭐ **"板2 比板1 小声"** —— 只按板1 跑 `'S'`，串口**照样回 `.`**（**假成功**），⭐ 而板2 那一路**根本没标上** | ⭐ 串口**回 `'1'`** ⇒ 板2 的失败**看得见**了 |
| **6** | **`'S'` 为什么失败** | 🔴 串口**只有一串 `!`** ⇒ 分不清"没按稳"还是"那片报 err"（⭐ 两者修法完全不同） | ⭐ 回**不同字母**：`w`=手在动 · `!`=没按稳 · `1`/`2`=哪一片报 err |
| **7** | **按对了还失败** | 🔴 某轴失败后，**明明按对了还回 `!`**（读到**上一轴**的残留 `err`）⇒ 要多试一两次才过 | ⭐ 纠正后**下一次直接过** |
| **8** | **上电瞬间发 `'S'`** | 🔴 **受理**（回 `s`）⇒ 但随后 autotare 会把**正在标的那个轴**的零点写坏 | ⭐ 回**一个孤零零的 `!`**（⭐ 不带 `s`、不带轴号） |
| **9** | **标定时手在动** | 🔴 零点被记成**晃动中的瞬时值** ⇒ 那几个键就坏了 | ⭐ **帧间在变就不捕获** ⇒ 标定期间碰键**不毁零点** |
| **10** | **`t` → `T` 的间隔** | 🔴 **快得看不出来（~0.5 ms）** —— ⭐ 溢出那一版"**一个 `tare` 都不发，却照样回 `T`**" | ⭐ **约 7 ms**（8 轴 × 2 ms） |
| **11** | **鼓机** | —（本版才有） | ⭐ **本版默认就是鼓机** ⇒ 发 `'B'` **开始打鼓**（从强拍起）· 发 `'D'` **换节奏型**（4 个）<br>⚠️ **不发 `'B'` 就一点声都没有**（源 B 上电静音）—— ⭐ **这不是坏的** |

### 三、⚠️ 两种**症状相反**的"某个键不正常"（⭐ 别记混）

```
🔴 修前：零点被记成【按下的位置】⇒ 松手后 pos ≈ 0
        ⇒ 现象 = ⭐ 那个键【怎么按都不响】（或只有一点点声）

⚠️ 修后（守卫【跳过】了那个轴）：zero_vld = 0 ⇒ 退回默认 ⇒ pos = 1023（≫ 触发阈 64）
        ⇒ 现象 = ⭐ 那个轴【永久判"按下"】⇒ 一直响 / 挂音

⇒ ⭐ 一句话区分：⭐ 串口发 'N' 读那一轴 —— 松手时 ≈ 0000 = 正常 ／ ≈ 1023 = 被跳过
```

### 四、⭐ `'S'`（span 标定）的现象流程

```
① 发 'X'                     ⇒ 回 'x'（⭐ 取消上一轮 —— 【每轮都必须先发】）
② 发 'S'                     ⇒ 回 's'（受理）⇒ 之后【逐轴】提示轴号
③ 按当前轴的键到底、【停住】1~2 秒
      · 成功 ⇒ 回 '.'，随后提示下一轴的轴号
      · 失败 ⇒ 回【拒绝字节】（'!' / 'w' / '1' / '2' …）⇒ 重试（每轴最多 8 次）
④ 16 轴走完                  ⇒ 回 'D'

⚠️ 'D' 是【粘滞】的 ⇒ ⭐ 第二轮【不会】再有 'D'（⛔ 别等它）⇒ 所以每轮先发 'X'
⚠️ 标定期间会听到"卡卡的重触发声" ⇒ ⭐ 正常现象，松手就停
⚠️ 标定时【两块板的同号键必须同时按到底】（⭐ K-127 不免除这一点）
⚠️ 标定完之后**手感会变**（一碰就触发 / 半按=满按）⇒ ⭐ 一次复位即恢复（⛔ 别当故障）
```

### 1.1 🔴 串口必须走 **`J9` 排针**，⛔ **不是板载 USB-C**

⭐ **实测结论**（用户 2026-09-30 亲验 ＋ `constr/top.cst:331-357` 的记录）：

```
🔴 板载 USB-C 的串口【走不通】——
   BL616 跑的是 TangCore 游戏机固件，它的 UART 是【私有协议】（2 Mbps）
   ⇒ ⛔ 不透传我们的 T/S/X 命令（⭐ 实测：发任何字节都被"回显"）
⭐ 而原来的 V14/U15 【只在 J2 板对板连接器上】（0.4 mm 间距）⇒ 🔴 物理上插不了线
⇒ ✅ UART 已搬到 J9 排针（2.54 mm，杜邦线可插）：

      USB-TTL 的 TX   →  J9 的 N26   （ D14 = uart_rx ）
      USB-TTL 的 RX   →  J9 的 N25   （ D15 = uart_tx ）
      USB-TTL 的 GND  →  J9 的 GND

   ⭐ 500000 baud · 8N1 · ⛔ 无流控（BAUD_DIV=100 ⇒ 50 MHz ÷ 100 = 500 kbps 整除）
```

## 二、⭐⭐ 先做**这一个**测量：`t` → `T` 的时间差（**T0**）

> ⭐⭐ **为什么先做它**：它**一行判据同时覆盖三件事**，而且**能提前暴露 R1 那条致命风险**。

**依据**：`'t'` = 受理 tare（`top.v:2049`）· `'T'` = autotare 完成（`at_done` 上升沿，`top.v:2042`）
`WAIT_MS = 1000` · `STILL_FRAMES = 4` · 帧 500 µs ⇒ 每轴最快 **2 ms**，8 轴 ≈ **7 ms**；
`STILL_TOL = 8`（`top.v:1616`）· 超时 ⇒ 该轴**跳过**、8 轴全超时 ≈ **8 s**。

```powershell
python tools\board_probe.py <COM口> --send T        # ⭐ 看 t 与 T 的时间戳差
```

| 实测 | 判定 |
|---|---|
| ⭐ **≈ 7 ms** | ✅ **正确**（守卫在工作 ＋ `WAIT_CLK` 没溢出 ＋ `STILL_TOL` 够松） |
| 🔴 **≈ 0.3~0.5 ms** | 🔴 **修复前 / 溢出版** —— `WAIT_CLK` 回绕成负数（`WAIT_N=1`）⇒ **一个 `tare` 都不发，但照回 `T`**。`autotare` 无守卫时也是这个量级 |
| 🔴 **≈ 8 s** | 🔴 **全通道静默超时** ⇒ ⭐ 见 **R1**（`STILL_TOL=8` 对静止噪声太紧）⇒ 16 轴 `zero_vld=0` ⇒ **全体挂音** |

**🔴 红**：≈0.3~0.5 ms（溢出版）或 ≈8 s（守卫全超时）。⭐ 两种都**照回 `T`** ⇒
⛔ **只看到 `T` 绝不能判定"autotare 成功"**（这是本卡最重要的一条认知）。

⚠️ **补充判据（行为面）**：T0 之后连发 16 次 `'N'`：
🟢 松手静止 ≈ **`0000`**（16 轴全标上）｜🔴 全 ≈ **`1023`**（全被跳过 ⇒ 全体挂音）。

## 三、⭐ 判据 T1 ~ T8（⭐ 每条都能红）

### T1 · ⭐⭐ 水位闸 A：一次【失败的 `'S'`】不得毁掉已标定的归一化

**依据**
```
✅ 修复后：`calib.sv:275-286` —— `err` 分支【只置 err】，⛔ 不再写 `gain_r`
🔴 修复前：`e1d36bf^:rtl/drivers/calib.sv:202-204` ——
           if (raw_f <= zero_r[cal_ch]) begin
               err <= 1'b1;
               gain_r[cal_ch] <= (1 << 8);      // 🔴 归一化增益被清成 1.0
           end
           ⇒ 受害轴满按读数从 4095 掉回 ≈ 0744（旧量纲）
```

**操作**
1. 发 `'X'` ⇒ 双板同号键**同时按到底** ⇒ 发 `'S'` ⇒ 等到 `D`
2. 连发 16 次 `'N'`（**松手**）⇒ 再逐个**按到底**读一遍（**满按**）
3. 🔴 **故意制造一次失败**：⭐ **确定性造法**（见下）⇒ 再发 `'S'`
4. 第三次连发 16 次 `'N'` ＋ 再按到底

⭐ **确定性造法（`err` 判据是 `raw <= zero`，`calib.sv:275`，⛔ "只按板1"不保证）**：

```
⭐ 按住【板2】某个键、【静止不动】⇒ 发 'T' ⇒ 等 T ⇒ 松手 ⇒ 发 'X' ⇒ 再发 'S'
   📌 为什么必然 err：⭐ tare 脉冲【两片广播】、而每片的 calib 各读【自己的 raw】
      ⇒ 片1 的 zero[该ch] 被记成"按下位" ⇒ 松手后 raw < zero ⇒ 必 err
   ⚠️ 而静止守卫【只看片0】（`top.v:1628`）⇒ 按板2 不触发守卫 ⇒ tare 照常发出
```

**🟢 绿**：步2 松手 ≈ **`0000`**、满按 ≈ **`4095`**；步3 回**拒绝码**；
⭐ 步4 满按 **仍 ≈ `4095`**。
**🔴 红**：步4 满按**掉到 ≈ `0744`** ⇒ `gain_r` 被清 = **修前形态**。

⚠️ `MAX_TRAVEL = 1023`（`calib.sv:38`）是**静默上界**：⭐ 某轴 raw 行程 > 1023 时
`pos` **永远到不了 4095**（被夹住且不报错）⇒ ⭐ 先读 `'P'` 确认行程再解读。

### T2 · ⭐ `at_done` 门控：上电/复位后的 **200 ms 窗口**内 `'S'` 必被拒
