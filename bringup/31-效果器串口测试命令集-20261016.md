# 效果器串口测试命令集（2026-10-16）

> 码流：`impl/pnr/Gowin2026.fs` · sha256 `73FB99D1B8A078FCC152FCB90A056E534A607CEC64BDB353A6A0F9AD8546B486`
> 串口：**500000 8N1**（不是 115200）· 交叉接线 · 共地
> 帧格式：`71 <变量号> <值> FF FF FF`（HEX）
> 工具：`tools/fx_ctrl.py`（推荐，省得手打）

---

## 〇、帧格式与三条硬规则

```
71 <变量号> <值> FF FF FF
 |    |       |
 |    |       +-- 值：一个字节，0..254
 |    +---------- 变量号：0x10..0x18
 +--------------- 返回码（固定 0x71）
```

**三条硬规则**

```
1. 值不能是 0xFF（它是帧尾标记）=> 所有参数最大只能发 254
2. 值只有一个字节 => 增益只能表达 128 的整数倍（要精确值用 gain-raw）
3. 上电默认 mask=0 => 效果器全旁路，必须先发一条 0x10 才有声音变化
```

---

## 一、变量表（本轮最终口径）

| 变量 | 名字 | 值域 | 换算 | 上电默认 |
|---|---|---|---|---|
| `0x10` | mask | 0..254 | 位掩码：bit0=失真 · bit1=合唱 · bit2=延迟 · **bit4=空闲位** | 0（全关） |
| `0x11` | gain | 0..254 | 值 / 16 => Q4.12（16=1.0× · 64=4.0× · 128=8.0× · 254=15.875×） | 64（4.0×） |
| `0x12` | trim | 0..254 | 值 / 128 => Q1.15（32=0.25× · 128=1.0× · 254=1.984×） | 32（0.25×） |
| `0x13` | mix | 0..254 | Q0.8，**加湿量**（不是干湿淡化）：输出 = 干声 + 湿声 × 值/256 | 128 |
| `0x14` | fb | 0..254 | Q0.8，**延迟专用**反馈（96=0.375） | 96 |
| `0x15` | depth | 0..254 | 直传，音量颤音深度（0=数值恒等，听不出） | 0 |
| `0x16` | rate | 0..254 | 直传，音量颤音速率 | 7 |
| `0x17` | dlylen | 0..254 | 值 × 128 采样（64=8192=168ms；>127 饱和到 16383=333ms） | 64 |
| `0x18` | chorlen | 0..254 | 值 × 32 采样（23=736=15ms；>63 饱和到 2047） | 23 |

**两个必须记住的口径**

```
1. 净增益 = gain × trim
   上电默认 (64, 32) => 4.0 × 0.25 = 1.0（单位增益，和干声一样响）
   这轮把字节映射从乘 128 改成乘 256，所以旧字节值 (128, 64) 现在 = 4.0（响 12 dB）
2. 掩码全开 = 0x07，不是 0x17
   bit4 是空闲位，0x17 与 0x07 完全等价
```

## 二、链路通断（先测这个）

```
71 10 00 FF FF FF     全关（确认帧能发出去，听感应该和没开一样）
71 10 01 FF FF FF     只开失真（应该能听出变化）
71 10 00 FF FF FF     再关（应该回到干声）
```

如果这三条听不出任何变化，先查串口（波特率 500000、交叉、共地），不是效果器的问题。

---

## 三、逐效果器单独开

```
71 10 01 FF FF FF     只失真（明显的破）
71 10 02 FF FF FF     只合唱（变宽）
71 10 04 FF FF FF     只延迟（回声）
71 10 07 FF FF FF     全开（失真 + 合唱 + 延迟）
71 10 00 FF FF FF     全关
```

**逐个听的判据**

```
只失真：波形被削平，听感"破/扎"
只合唱：声音变宽，有轻微的梳状染色（不再有共振的喷气机音）
只延迟：原音不衰减，168 ms 后叠一声回声
```

## 四、失真专项

### 4.1 量程与归一化（本轮重点）

```
71 10 01 FF FF FF        只失真
71 11 40 FF FF FF        gain = 64  => 4.0×（默认）
71 12 20 FF FF FF        trim = 32  => 0.25×（默认）=> 净增益 1.0，和干声一样响
71 11 FE FF FF FF        gain = 254 => 15.875×（最大驱动）
71 12 08 FF FF FF        trim = 8   => 0.0625× => 净增益 0.99，音量基本不变
```

### 4.2 用 drive 命令一步到位（推荐）

```
python tools/fx_ctrl.py --port COMxx drive 200    # 驱动拉高，音量自动保持不变
python tools/fx_ctrl.py --port COMxx drive 40     # 轻一点的失真
```

`drive` 内部发两帧：`gain = 值`，`trim = round(2048 / 值)`。对照表：

```
值 16  -> trim 128     值 64  -> trim 32      值 254 -> trim 8（饱和）
值 32  -> trim 64      值 128 -> trim 16
```

注意：值小于等于 8 时 trim 会超过 254，工具会饱和到 254 并告警（那种情况下音量会变小）。

### 4.3 增益扫描找"破"的点

```
python tools/fx_ctrl.py --port COMxx sweep
```

或手发（gain 从 32 扫到 254，trim 保持 32）：

```
71 11 20 FF FF FF      gain 32  => 2.0×   （干净）
71 11 40 FF FF FF      gain 64  => 4.0×   （开始有一点）
71 11 60 FF FF FF      gain 96  => 6.0×
71 11 80 FF FF FF      gain 128 => 8.0×
71 11 A0 FF FF FF      gain 160 => 10.0×
71 11 C0 FF FF FF      gain 192 => 12.0×
71 11 E0 FF FF FF      gain 224 => 14.0×
71 11 FE FF FF FF      gain 254 => 15.875×（最破）
```

### 4.4 用示波器验收（FPGA 自带波形显示）

```
干声：波形占屏幕约 1/8
最大驱动 + trim 拉满：波形应该是明显的平顶（方波状）
如果只是"变响但仍是圆顶"，说明驱动不够，把 trim 也拉上去
```

## 五、延迟专项

```
71 10 04 FF FF FF      只延迟
71 17 40 FF FF FF      dlylen = 64  => 168 ms（默认，像"拍一下回一声"）
71 17 20 FF FF FF      dlylen = 32  => 84 ms（更近，像双音）
71 17 10 FF FF FF      dlylen = 16  => 42 ms
71 17 C8 FF FF FF      dlylen = 200 => 饱和到 16383 = 333 ms（最长）
71 14 00 FF FF FF      fb = 0   => 只回一声，不重复
71 14 60 FF FF FF      fb = 96  => 0.375（默认，回 2~3 声）
71 14 FE FF FF FF      fb = 254 => 0.99（几乎不衰减，小心啸叫）
71 13 40 FF FF FF      mix = 64  => 回声轻（加湿量 0.25）
71 13 80 FF FF FF      mix = 128 => 回声中等（默认）
71 13 FE FF FF FF      mix = 254 => 回声接近原音大小
```

**判据**

```
本轮改成 send/return：开延迟时原音【不衰减】，只是把回声叠加上去
改之前是交叉淡化：开延迟时原音被砍一半，听感"突兀地响两下"
```

## 六、合唱专项

```
71 10 02 FF FF FF      只合唱
71 18 17 FF FF FF      chorlen = 23 => 736 采样 = 15 ms（默认）
71 18 08 FF FF FF      chorlen = 8  => 256 采样 = 5.2 ms（更紧）
71 18 3F FF FF FF      chorlen = 63 => 2016 采样 = 41 ms（更宽）
71 18 C8 FF FF FF      chorlen = 200 => 饱和到 2047 = 42 ms
```

**判据**

```
本轮把合唱读下界从 128 改成 129（MOD+1）
长时间听，LFO 峰值处不应有周期性爆音
合唱不再吃反馈，不应有共振的"喷气机"音
```

## 七、音量颤音专项

```
71 15 00 FF FF FF      depth = 0   => 数值恒等（听不出，这是上电默认）
71 15 30 FF FF FF      depth = 48  => 轻微起伏
71 15 60 FF FF FF      depth = 96  => 明显起伏
71 15 FE FF FF FF      depth = 254 => 最深的起伏
71 16 04 FF FF FF      rate = 4    => 慢
71 16 07 FF FF FF      rate = 7    => 默认
71 16 20 FF FF FF      rate = 32   => 快
```

**注意**

```
音量颤音固定常开，没有开关位，depth=0 就是"听不出"而不是"关掉"
mask=0 时它仍然在工作（这是设计如此）
```

## 八、组合与边界

```
71 10 07 FF FF FF      全开
71 11 FE FF FF FF      全开 + 最大驱动
71 12 FE FF FF FF      全开 + trim 拉满
71 17 C8 FF FF FF      全开 + 最长延迟
71 14 FE FF FF FF      全开 + 最大反馈
71 15 FE FF FF FF      全开 + 最深颤音
71 10 00 FF FF FF      全关（回到干声，应与上电一致）
71 15 00 FF FF FF      颤音也归零
```

**边界测试**

```
71 10 10 FF FF FF      mask = 0x10（bit4 空转位）
                       => 灯 7 会亮，但【没有任何效果】。这是已知行为
71 90 05 FF FF FF      变量号 0x90（越界）
                       => 掩码应该【不变】（本轮修好了别名，改之前会静默写 mask=5）
71 10 FF FF FF FF      值用 0xFF
                       => 帧被当成两帧，行为不确定，正常使用不要这么发
```

## 九、用工具（推荐，省得手打）

```bash
python tools/fx_ctrl.py --port COMxx list         # 看变量表（是本地默认值，本协议无读回）

python tools/fx_ctrl.py --port COMxx trim 128     # 输出补偿 1.0×

python tools/fx_ctrl.py --port COMxx drive 200    # 驱动拉高，音量不变
python tools/fx_ctrl.py --port COMxx sweep        # 增益扫描
python tools/fx_ctrl.py --port COMxx raw 10 07    # 发任意帧体（不带 0x71）
```
