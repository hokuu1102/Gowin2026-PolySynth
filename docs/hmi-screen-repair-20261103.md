# 串口屏配套修订与验收记录

日期：2026-11-03。基于 51 线的源码提交 `d3420c54bd82cc99547b70a4c784af99b88bb31b`。

本轮交付为 FPGA 源码和 HMI 源工程。未生成 FPGA `.fs`、屏幕 `.TFT`，未执行新的综合、布局布线或时序验收，未推送远端。板上已有码流不会因本地源码修改而变化。

## 已落实的修改

1. 将诊断发送 FIFO 的地址宽度从写死的 3 位改成随深度变化，顶层深度改为 64。保留默认深度 8 的模块兼容性。新增深度 8/64 的满空、绕回、溢出和清除测试，原实现的深度 64 用例已先失败。
2. 保留屏幕回显直连 UART 的所有权和背压规则。该路径绕过诊断 FIFO，不能将本版长帧现象直接归因于 FIFO 只有 8 字节。修正了相应过时注释。
3. 增加页面通知 `71 06 <page> FF FF FF`，page 只能为 0 或 1。页面后初始化发送通知，再发送原有 `88 FF FF FF`。FPGA 只回显已加载页面的私有控件，切页时重新刷新该页。
4. FPGA 按实际 `ui_fx_mask[2:0]` 回写 Program.s 的 `fx0/fx1/fx2`，并更新当前页的效果器灯、文字或头部颜色。保留屏端按钮逻辑与 `71 19` XOR 命令。没有页面通知的旧屏工程继续使用旧的 58 个状态字段刷新协议。
5. 进入 page0 时幂等退出 EC11 参数模式并恢复原 BPM/变调对象；重复通知不会重新进入参数模式。保留旧的 raw `p` 切换、`o+n` 选择及屏幕数值载荷隔离。
6. Loop 背景色改为录音 51461、回放 7142、武装 56224，空闲色保持原值。`t_lock` 改为“锁定／实时生效”，仍取当前档真实 hold 位；保留 `t_lock_info` 对音高、音量两档的独立锁定汇总。
7. 增加可查询的 HMI 发送诊断计数，含起帧、物理完成帧、已接受字节、非法启动以及 FIFO 溢出/丢弃。诊断回复单独取得 UART 所有权，不插入屏幕帧内部。
8. 在 HMI 副本中将 `t_slide` 字体由 9 改为 UTF-8 字体 4（18 像素），宽度从 232 改为 128，保留位置 `(254,216)` 和高度 48，初值改为完整“关闭 (GLIDE OFF)”。编辑器预览确认文字完整显示、刷新区域避开滑音灯和按钮。
9. 将 `b_uplink.y` 从 240 改为 252，使其避开 `t_kd` 的 y=207、高度 40 区域，保留触摸事件。将 `b_vv_hdr.pco/pco2` 均改为 0，匹配音量颤音黑字要求。

## HMI 核对结果

使用现有 USART HMI 1.68.1，在工作副本中编辑并通过原生保存操作写回，原附件未修改。型号为 `TJC1060X570_011`，1024×600，UTF-8，115200，recmod=0。

有效 Program.s 声明 `int fx0=0,fx1=0,fx2=0`，没有 va0/va1/va2 初始化。原两页前初始化中的记忆恢复逻辑保留，新增通知放在后初始化，确保控件已加载。

| 控件 | 参数 | 发送 HEX，尾部均为 FF FF FF |

| b1 | 补偿 | 6F 01 |
| b2 | 合唱长度 | 6F 07 |
| b3 | 干湿比 | 6F 02 |
| b4 | 延迟长度 | 6F 06 |

`b_back` 原事件只有 `page page0`，现由 page0 后初始化通知完成 FPGA 退出动作。`b_uplink` 保留 `65 00 0F FF FF FF`，未勾选自动发送键值，避免重复触发。

效果器头部保持私有作用域。跨页写私有控件会失败，因此使用页面通知后只刷新当前页；这也符合[厂商对跨页操作作用域的说明](https://www.tjc1688.com/contents/25/465.html)。

## 发送计数的实机读取方法

此方法只适用于将本轮源码生成并烧入 FPGA 后。旧码流不包含此接口。

1. 将串口助手接到板载主 UART，设为 115200、8N1、HEX 发送；先避免上位机或屏幕同时驱动板载 RX。
2. 发送 `71 07 00 FF FF FF`。
3. FPGA 在当前完整包结束后回复一行 30 字节 ASCII：`HMI ` + 24 位大写十六进制数字 + CR LF。

24 位数字连续排列为 `SSSSCCCCBBBBBBBBEEEEDDFF`：

| 字段 | 含义 |
|---|---|
| SSSS | 起帧计数，16 位 |
| CCCC | 最后一个 FF 的 UART 发送完成后才增加的完整帧计数，16 位 |
| BBBBBBBB | HMI 被 UART 接受的字节数，32 位 |
| EEEE | 无所有权或 UART 忙时仍启动的次数，16 位，正常应为 0000 |
| DD | 原 FIFO 饱和丢弃计数，8 位 |
| FF | bit0 为 FIFO sticky overflow，其他位为 0 |

起帧、完成帧、字节、非法启动计数按位宽回绕，复位清零；FIFO 的丢弃计数沿用原来的饱和/清除规则。查询期间计数先快照再发送。正常操作不会自动发送这条诊断回复。

要定位长帧现象，应同时抓取 FPGA TX 的原始 HEX，包含 `t_mode/t_slide/t_kd/b_uplink` 的完整内容和三个 FF。只看到帧头或生成端日志不足以证明屏幕已收到整帧。

## 必须保留的待验收项

- FPGA 单独复位后，需在新 HMI 中切页或重新进入当前页面，发送完整页面通知与握手以恢复页面识别；旧式裸 88 仅保持兼容刷新，不携带当前页信息。自动跨页重连尚未实机验证。
- 本轮仿真未复现实机“长帧发不全”，因此不将 FIFO 扩容或显示修订宣传为 R10 根因修复。仍需烧录配套版本后抓取实际 TX，结合计数闭环。
- “武装中不开始录音”在当前受控顶层测试中没有复现。本轮未修改录音状态机，也未覆盖所有真实 BPM、按键时机和接线组合，仍需实机验证。
- HMI 已原生保存并重新打开核对，不等同于新 TFT 编译及屏端运行验收；未运行会产生 TFT 的编译/调试步骤。
- 新源码尚无综合资源和时序结果，不能沿用旧码流的 50MHz/Fmax 数字作为本轮结论。
- 需要后续明确要求统一生成 FPGA 与屏幕烧录件后，再做配套编译、50MHz 时序门禁和上板验收。
