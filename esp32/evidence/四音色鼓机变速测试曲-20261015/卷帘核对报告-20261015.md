## 二、六个缺陷（现象 / 证据 / 根因 / 修法）

### 缺陷 1：鼓栏把最低 8~10 个半音盖掉

**现象**：卷帘底部一整条音域没有音符 —— 那里本该是贝斯。

**证据**（真跑 draw()，记录每个 `fillRect` 后比对）：

| 谱子 | 修前被盖 | 修后 |
|---|---|---|
| 本测试曲（当前版：funk 7 小节演示卡） | 11 / 40（28%）· 盖住 A2~C#3 五个半音 | 0 |
| 6.世界悲(已修订) | 342 / 5030（7%） | 0 |
| 円 | 1262 / 9319（14%） | 0 |
| 09_Conjurer | 535 / 6019（9%） | 0 |

**根因**：`Y()` 把音域铺满整个 `ph`（`:1481`），音符块先画、鼓栏不透明底色后画
（`:1372`）⇒ 被擦掉。`drawPiano` 有 `noDrawBelow` 保护，**音符块这一路没有**。

**修法**：乐音区让出鼓栏高度 `melPh = ph - drumLaneHeight(ph)`，
`Y / rowH / blockH / drawPiano` 全用它（**一处几何，⛔ 不在每处画之前各写一遍判断**）。

### 缺陷 2：悬停提示基本总是错的

**现象**：光标指着一根 PAD 的 C4 长音，提示却写 `tick 21120 · 轴 15 · B6 · 力度 0 · off`
—— 轴 15 是**鼓**，B6 是**踩镲的假音名**，`力度 0 · off` 是**音符结束事件**。

**证据**（沿时间轴每 2px 扫一个光标位置）：修前命中 off **79~100%**、命中鼓 **38~83%**；
修后串行 0%、命中鼓 0%，鼓栏扫描 311~483 次全部命中对应件。

**根因**（`:1628` 原实现）：

```js
const t = vw.t0 + ((px - PAD.l) / pw) * vw.span;      // 只算了时间
for (const n of score.notes) {                        // on/off 混放
  const d = Math.abs(n.tick - t); if (d < bd) { bd = d; best = n; }
}
```

**完全没用 `y`** ⇒ 同一条竖线上，光标在 C5 行还是在 A2 行，提示**一模一样**。

**修法**：抽出 `pickHover(px, py)`（可单测）：先由 y 定行（乐音行 / 鼓栏某一件），
再在这一行里找**覆盖该 tick** 的段；鼓栏按件分行命中；提示里鼓显示**件名**（⛔ 不是音名）。

### 缺陷 3：总览条把 tick 当 120 BPM 换算秒

| 谱子 | 真实时长 | 修前显示 | 修后 |
|---|---|---|---|
| 本测试曲（当前版） | 16.02 s | 28.00 s（+74.8%） | 16.02 s |
| 6.世界悲(已修订) | 378.00 s | 756.00 s（+100.0%） | 378.00 s |
| 円 | 407.07 s | 1092.25 s（+168.3%） | 407.07 s |
| 09_Conjurer | 305.63 s | 849.00 s（+177.8%） | 305.63 s |

**根因**：`vw.t0 / 960`（`:1596-1598`）—— `960` = 120 BPM 下一拍的 tick 数，写死了。

### 缺陷 4：面板时长 / 游标回退 / 提前量只用首个 tempo

| 项 | 修前 | 修后 |
|---|---|---|
| 面板「时长」 | 本曲 **+4.9%**（16.80 s vs 真值 16.02 s）· 円 **+5.9%** | 0.0% |
| 游标回退漂移 | 本曲 **−4.7%** · 円 **−5.6%** | 0.0% |
| 提前量（固件给 1920 tick） | 写死 `d.lead/1920` ⇒ 1.00 s | `tickToSec(1920)` = **1.20 s** |

**根因**：`duration = (tickMax-tickMin)/tempos[0].hz`（`:1219`）、
`secPerTick = duration/tickMax` 当常数（`:2208`）。**tick ↔ 秒 变速后不成线性。**

**修法（3+4 同一个根因）**：新增 `tickToSec()` / `secToTick()`（分段积分），四处调用全改。

### 缺陷 5：总览条点击跳转不落在点击处

**证据**：修前最坏偏 **72% 视口宽**（zoom 20 · 点击 75% 处；点正中会落到最右边缘），修后 0%。

**根因**：`theo = frac - 0.5/viewZoom`（`:1662`）少除了 `(1 - 1/zoom)`。
正确：`viewScroll = (frac*z - 0.5)/(z - 1)`。注释写的意图是对的，实现没跟上。

**修法**：抽出 `overviewScrollFor(frac, zoom)`（可单测）。

### 缺陷 6：重叠的同音高被"单槽 open"覆盖 ⇒ 兜底拉成到曲末的长条

**现象**：卷帘里出现一根横跨几分钟的音符长条（鼓栏里最常见）。

**证据**：

| 谱子 | 修前的长条 | 假 orphanOff |
|---|---|---|
| 09_Conjurer | **1 根 247680 tick ≈ 4.3 分钟**（踩镲，t0=567360 t1=815040） | 6 个 |
| 6.世界悲(已修订) | 1 根 65280 tick ≈ 68 秒 | 2 个 |
| 本测试曲 / 円 | 无 | 0 |

**根因**：`buildScore` 用**单槽** open（`open.set(key, seg)` 直接覆盖）：

```js
open.set(key, seg);            // 🔴 同轴同音高的 on 重叠时，前一个 seg 被顶掉
...
const seg = open.get(key);
if (seg) { seg.t1 = n.tick; open.delete(key); }
else { orphanOff++; }          // 🔴 于是后一个 off 找不到对象 => 假 orphanOff
...
for (const s of segs) if (s.t1 === null) s.t1 = endTick;   // 🔴 被顶掉的 seg 拉成到曲末
```

⇒ 一个 bug 同时造成三件事：**配对错 + 假 orphanOff + 兜底长条**。
（我第一版报告把 orphanOff 判成"源 MIDI 里的多余 off"——**那个判断是错的**，
根因就是这里，特此更正。）

**修法**：`open` 改成**队列**（FIFO），与 `mid2evt.py` 的 `pending[note].append/pop(0)` 口径一致。

## 三、改动清单（`esp32/tools/score_studio.html`，只动卷帘相关区）

| 位置 | 改动 |
|---|---|
| `tickToSec` / `secToTick`（新增，约 :341） | 按 tempo 表分段积分 |
| `buildScore` 配对 | 单槽 open -> **FIFO 队列**（缺陷 6） |
| `buildScore` duration | 首个 tempo -> `tickToSec`（缺陷 4）；tempo 表排序 |
| `draw()` | 新增 `melPh`/`laneTop`/`lastView`；`Y`/`rowH` 改用 melPh（缺陷 1） |
| `drawPiano()` | 第 4 参改为"乐音区高"，`noDrawBelow = PAD.t + melPh`（缺陷 1） |
| `pickHover()`（新增） | 按行命中 + 鼓栏按件命中（缺陷 2） |
| 悬停提示文本 | 鼓显示**件名**，⛔ 不再是假音名（缺陷 2） |
| 总览条 "Ns" | `tick/960` -> `tickToSec`（缺陷 3） |
| `overviewScrollFor()`（新增） | 点击处居中，除 `(z-1)`（缺陷 5） |
| 游标回退 / 提前量 | `secPerTick` 常数 -> `secToTick`；`d.lead/1920` -> `tickToSec`（缺陷 4） |

**没有碰**：上传/流控/连接那一区（你正在改的 `FC_WINDOW_BYTES`、`sendChunkWithFlowControl`）。
