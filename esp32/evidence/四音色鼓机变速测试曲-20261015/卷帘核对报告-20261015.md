## 二、四个缺陷

### 缺陷 1：鼓栏把最低 ~18% 的音域盖掉（音符看不见）

**现象**：卷帘底部一整条音域没有音符 —— 而那里本该是贝斯。

**证据**（4 份谱子全中，`check_roll.js` 判据 ⑤ 与 ⑪）：

| 谱子 | 被盖住的音高 | 半音数 | 真跑 draw() 的实测 |
|---|---|---|---|
| 本测试曲 | E2 F2 F#2 G2 G#2 A2 | 6 | 画了 183 个乐音块，**36 个（20%）**落在鼓栏区域 |
| 6.世界悲(已修订) | D#1 E1 F1 F#1 G1 G#1 A1 A#1 B1 | 9 | 画了 5030 个，**342 个（7%）**被盖 |
| 円 | F1 F#1 G1 G#1 A1 A#1 B1 C2 C#2 D2 | 10 | 画了 9319 个，**1262 个（14%）**被盖 |
| 09_Conjurer | F1 F#1 G1 G#1 A1 A#1 B1 C2 | 8 | 画了 6019 个，**535 个（9%）**被盖 |

> 判据 ⑪ 不是读代码得出的：`check_roll.js` 用假 canvas **真的调了一次 `draw()`**，
> 把每个 `fillRect` 连 `fillStyle` 一起记下来，再比对"乐音块的 y 有没有落进
> 鼓栏底色矩形（`#12181f`，y=571 高 120）的区间"。
> 实测那些块的 y 范围 582~683，**全部在鼓栏顶 571 以下**。

**根因**（`score_studio.html`）：

```js
// draw()：音域铺满【整个】 ph —— 没有给鼓栏留位置
const Y = m => PAD.t + ph - ((m - lo) / (hi - lo)) * ph;   // :1481
...
ctx.fillRect(x0, y, bw, blockH);        // :1527  乐音块先画
drawDrumLane(X, pw);                    // :1535  鼓栏后画
// drawDrumLane 里：
ctx.fillStyle = "#12181f";
ctx.fillRect(PAD.l, top, pw, laneH);    // :1372  不透明底色 => 把乐音块擦掉
```

`drawPiano()` **有** `noDrawBelow` 保护（:1299 起，键盘与音名不画进鼓栏），
但**音符块这一路没有** —— 先画、后被擦掉，所以是"看不见"而不是"没解析出来"。

**修法**：乐音区让出鼓栏高度（`melPh = ph - drumLaneHeight(ph)`），
`Y / rowH / blockH / drawPiano` 全用它。**一处算法，不要各写一份**。

### 缺陷 2：悬停提示基本总是错的

**现象**（你的截图）：光标指着一根 PAD 的 C4 长音，提示却写
`tick 21120 · 轴 15 · B6 · 力度 0 · off` —— 轴 15 是**鼓**，B6 是**踩镲的假音名**，
`力度 0 · off` 是**音符结束事件**。

**证据**（沿时间轴每 2px 扫一个光标位置）：

| 谱子 | 命中 off 事件 | 命中鼓事件 |
|---|---|---|
| 本测试曲 | 385 / 490 = **79%** | 188 / 490 = **38%** |
| 6.世界悲(已修订) | 487 / 490 = **99%** | 405 / 490 = **83%** |
| 円 | 490 / 490 = **100%** | 379 / 490 = **77%** |
| 09_Conjurer | 479 / 490 = **98%** | 384 / 490 = **78%** |

**根因**（`:1618-1631`）：

```js
const t = vw.t0 + ((px - PAD.l) / pw) * vw.span;      // 只算了时间
let best = null, bd = Infinity;
for (const n of score.notes) {                        // score.notes 里 on/off 混在一起
  const d = Math.abs(n.tick - t); if (d < bd) { bd = d; best = n; }
}
```

两个问题叠在一起：

1. **完全没用 `y`** —— 不比音高行。同一条竖线上，光标在 C5 行还是在 A2 行，提示**一模一样**。
2. **`score.notes` 里 on 与 off 混放** —— 而 off 的数量与 on 一样多，且 off 常常更靠近光标
   （一个长音中间没有事件，最近的往往是它自己或别人的 off）⇒ 于是提示写"力度 0 · off"。

**修法**：抽成 `pickHover(px, py)`（可单测）：

- 先由 `y` 反算光标在哪一行（用缺陷 1 修好后的 `melPh`/`lo`/`hi`）；
- 在该行里找**覆盖该 tick 的段**（`t0 <= t <= t1`），而不是"最近的 tick"；
- **排除鼓**（鼓有自己的栏）；光标落在鼓栏时，按鼓的 4 行单独命中；
- 只提示**音符段**，不提示 off。

### 缺陷 3：总览条把 tick 当 120 BPM 换算成秒

**现象**：底部总览条写「全长 48s」，而这首曲子实际 **28.5 秒**。

**证据**：

| 谱子 | 真实时长（按 tempo 表积分） | 总览条显示（tick/960） | 误差 |
|---|---|---|---|
| 本测试曲 | 28.46 s | 48.00 s | **+68.7%** |
| 6.世界悲(已修订) | 378.00 s | 756.00 s | **+100.0%** |
| 円 | 407.07 s | 1092.25 s | **+168.3%** |
| 09_Conjurer | 305.63 s | 849.00 s | **+177.8%** |

**根因**（`:1596-1598`）：

```js
ctx.fillText("视口 " + (vw.t0 / 960).toFixed(0) + "s ~ " +
             (vw.t1 / 960).toFixed(0) + "s / 全长 " +
             (vw.total / 960).toFixed(0) + "s", ...);
```

`960` = 120 BPM 下一拍的 tick 数 —— 写死了。曲子只要不是 120 BPM，这个"秒"就是错的。
（`vw.total` 是 tick，没问题；错的是把它除以 960 当秒。）

**修法**：按 tempo 表分段积分算 `tickToSec(tick)`，总览条用它。

### 缺陷 4：面板「时长」与游标回退只用【首个 tempo】

**证据**：

| 谱子 | 真实 | 面板 | 误差 | 游标回退漂移 |
|---|---|---|---|---|
| 本测试曲 | 28.46 s | 28.80 s | +1.2% | −1.2% |
| 6.世界悲(已修订) | 378.00 s | 378.00 s | 0.0% | 0.0% |
| 円 | 407.07 s | 431.15 s | **+5.9%** | **−5.6%** |
| 09_Conjurer | 305.63 s | 303.21 s | −0.8% | +0.8% |

**根因**：

```js
const hz0 = tempos.length ? tempos[0].hz : TPS120;              // :1213
duration: (tickMax - tickMin) / (hz0 || 1),                     // :1219  只按首速折算
...
const secPerTick = score.duration / Math.max(1, score.tickMax); // :2208  当成常数
heardTick = Math.max(0, (fedSec - leadSec)) / (secPerTick || 1);
```

**tick ↔ 秒 在中段变速后【不是线性关系】**，用首速或常数换算必然漂。
漂多少取决于变速幅度：本曲 ±1.2%，円 ±5.9%。

**同一族的还有**：`:2203` 的 `leadSec = d.lead / 1920`（"960PPQN/120BPM"）——
本曲 1920 tick 实际是 **1.20 s**，代码按 1.00 s 显示。

**修法**：与缺陷 3 共用同一个 `tickToSec()`；提前量按当前 tempo 折算。

### 缺陷 5：总览条点击跳转不落在点击处（放大后越偏越多）

**现象**：放大后点底部总览条想跳过去，落点不在点击的位置。

**证据**（判据 ⑫）：点击处偏离视口中点最坏 **72% 视口宽**（zoom 20 · 点击 75% 处）；
zoom 20 时点总览条正中，落点跑到视口**最右边缘**附近。

**根因**（`:1660-1663`）：

```js
/* 让点击处成为视口【中点】—— ⛔ 不作为左边缘（那样点右边看不到右边）*/
const theo = frac - 0.5 / viewZoom;      // ← 少了除以 (1 - 1/zoom)
viewScroll = Math.max(0, Math.min(1, theo));
```

`viewWindow()` 里 `off = viewScroll * (total - span)`，所以要满足"点击处居中"：

```
viewScroll = (frac*total - span/2) / (total - span) = (frac*z - 0.5) / (z - 1)
```

代码少除了 `(1 - 1/zoom)` ⇒ zoom 越大偏得越多。**注释写的意图是对的，实现没跟上。**

**修法**：`const theo = (frac * viewZoom - 0.5) / (viewZoom - 1);`（zoom==1 时无平移，直接 return）。
