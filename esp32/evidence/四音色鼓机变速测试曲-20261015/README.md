# 四音色 + 鼓机 + 变速 + 复音 · funk 功能演示卡（2026-10-15）

**这是什么**：给「曲谱上位机」（`esp32/tools/score_studio.html`）灌谱用的测试段子。
风格 = **funk**（单一风格）。编曲思路 = **功能演示卡**：
⭐ **一小节只演示一件事**，音符刻意稀疏（用户："不要塞爆，每个都体现一下就可以了"）。
**7 小节、约 16 秒、88 个音**（上一版是"每小节所有乐器一起上"，280 个音，听感是糊的）。

---

## 一、一小节演示什么

| 小节 | 速度 | 演示的内容 | 同时在响的音 |
|---|---|---|---|
| 1 | 100 | **BASS**（走 A2–C3）+ 底鼓 / 踩镲 | 1~2 |
| 2 | 100 | **+ GUITAR**（单音 riff） | 2~3 |
| 3 | 100 | **+ PIANO**（三音和弦） | 3~5 |
| 4 | 100 | **+ PAD** ⇒ **四音色同框**（长音为主） | 6 |
| 5 | 126 | **鼓机四件** + tom 过门 | 1~2 |
| 6 | 126 | **复音**：每半拍进一个音 → 7 声 | 1→7 |
| 7 | 92 | **收尾 + 鼓探针**（第 4 拍三件同敲） | 6 |

变速点：小节 1（100）· 小节 5（126）· 小节 7（92）。
整曲只用 **Am7** 一个和弦 —— 这是演示卡，⛔ 不是歌；换和弦就要换音高素材，很容易又撞上下面第 1 条。

**怎么听**：每小节进一个新乐器，听"这一件对不对"；第 4 小节四件齐；
第 5 小节只听鼓（kick/snare/hihat/tom 四件都要有）；第 6 小节从 1 数到 7。

---

## 二、⭐ 三条硬约束（全是踩过坑才加的）

### 1. 不许两个音色发同一个音高

两个音色同频 ⇒ 两个 voice 相位干涉（`mid2evt.py` 文件头："可能变响、变薄、
或在起音处打拍子，听起来像被敲了两次"）。

📌 用户实测："第一次变速之后怪怪的，好像两个音色没对上" ⇒ 用判据 ⑨ 量出 **44 处**，
且从第 3 小节（第一次变速）开始。

⇒ 音高素材**按音色分区**，且只用 Am7 的和弦音：

| 音色 | 音高 | 频率 |
|---|---|---|
| BASS | 45 / 48 / 52（A2 C3 E3） | 110~165 Hz |
| PAD | 57 / 60（A3 C4） | 220~262 Hz |
| GUITAR | 64 / 67（E4 G4） | 330~392 Hz |
| PIANO | 69 / 72（A4 C5） | 440~523 Hz |

四组互不重叠 ⇒ 同音高在结构上不可能发生（判据 ⑨ = **0 处**）。

### 2. 鼓的不同件不许在同一 tick 同时敲

已知未解决项（`same_hit` 复用）。⇒ 每档鼓的落点互不相同；
⛔ 只有**第 7 小节第 4 拍**故意让 `kick+snare+hihat` 同 tick 敲一下，作探针（判据 ⑦）。

### 3. ⭐⭐ 鼓的相邻落点间隔必须 ≥ 鼓长（480 tick）—— 鼓机其实是单声部

**FPGA 侧 RTL 查证**（`rtl/w3b/note_manager.v:1305-1321`）：

```verilog
// note_off：清掉【所有】同轴位且 gate 高的 voice（同源才清）
if ((gate_r[i] | retrig_low[i]) && (axis_r[i] == cur_axis) && (src_r[i] == cur_src))
    gate_r[i] <= 1'b0;
```

四个鼓件**共用 axis 15 且同源（`SRC_KDRUM`）**
⇒ ⭐ **任何一个鼓的 `note_off` 会把该轴上所有还在响的鼓一起释放**
⇒ ⭐ **鼓机实际是"单声部"**：后一下会被前一下的 off 掐掉。

📌 所以**16 分鼓花（240 间隔）在这里是听得出问题的写法** ——
本曲原来第 5 小节的 tom 过门就是 16 分，已改成八分（2400 / 2880 / 3360）。
✅ 判据 ⑩ 卡这条（当前最小间隔 **480**）。

> ⚠️ 顺带说明为什么鼓长不能再加长：加长会让"前一个鼓还没释放"的窗口变大，
> 反而制造约束 2 的撞车。**480 tick 是这两条约束的交点。**

## 五、怎么用

### A. 网页上位机（推荐，**鼓能出声**）

1. 双击 `esp32/tools/start_score_studio.bat`
2. 开 `http://127.0.0.1:8777/score_studio.html`，**`Ctrl+F5` 强刷**（卷帘有 6 处修复）
3. 点**连接蓝牙** → 选 `FPGA2026-Synth*`
4. 把 `四音色鼓机变速-funk-演示卡.mid` **拖进去**，看日志：
   - `MIDI 解析成功：179 个事件 · BPM 100.0 · 960 PPQN`
   - `该谱子有 3 个 tempo 点（变速）—— 已全部转成 kind=2 事件`
   - 轨分配 5 行；左下角图例 **5 种颜色**；底部总览条 **全长 16s**
5. 点**一键上传** → 进度条走到 `1656 B / 184 帧`
6. 点**起播** → 按第一节"怎么听"逐小节听

### B. Python 路（`score_uploader.py`）—— **鼓会被丢掉**

```powershell
python esp32\tools\score_uploader.py --autotest "esp32\evidence\四音色鼓机变速测试曲-20261015\events.hex"
```

`events.hex` 是网页解析器导出的（含鼓）✓；但用 `tools/mid2evt.py` 自己转会**丢掉整条鼓轨**
（实测 `drums_excluded`）——那是它的已知局限。

## 七、想改这段曲子

改 `gen_test_piece.py` 顶部的 `DEMO` 表（一小节一条，`bass`/`gtr`/`pno`/`pad`/`ladder`/`drums`
逐音显式列出），然后：

```powershell
python -X utf8 gen_test_piece.py && node verify_piece.js --hex events.hex && node check_roll.js
```

**改完必须重跑这两个核对**。四条硬约束（前三条见第二节，第四条在下面）：

1. 别让两个音色落在同一个音高上（判据 ⑨）。
2. 鼓的不同件别在同一 tick 敲（判据 ⑦ 只允许那 1 处探针）。
3. 鼓的相邻落点间隔 ≥ 480（判据 ⑩）。
4. 可用轴是 `0..14`（15 条，15 是鼓轴）⇒ 同时发声的音**别超过 15 个**（判据 ④ 报峰值）。
