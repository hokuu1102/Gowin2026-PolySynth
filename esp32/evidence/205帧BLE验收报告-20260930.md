## 四、⚠️ 逐条判读（⭐ 含一条必须澄清的）

### 4.1 ✅ 真通过的

| 字段 | ⭐ 判读 |
|---|---|
| `total=200` | ⭐ **总数帧收到并正确解析** |
| `tf=1` | ⭐ **只发了 1 次总数帧**（⛔ 无重复） |
| `rst=4` | ⭐ **4 个复位标记帧**（36 字节 = 4×9）✅ 正确识别 |
| `unk=0` | ⭐ **无未知帧头** → 帧头区分逻辑（0xA5 / 0x00 / 全A5）正确 |
| `ovf=0` | ⭐ **池未溢出**（18204 帧容量，200 帧远未满） |
| `pool=200` | ⭐ **一帧不丢**（1845 字节 = 205 帧；4 复位帧被丢弃、1 总数帧被留下 ⇒ **恰好 200 事件帧入池**） |
| `exp=200` | ⭐ **期望值被正确设置**（`pool_set_expected()` 确被调用，`ble_main.c:464`） |
| `mismatch=0` | ⭐ **实收 == 应到** ⇒ ⭐ **【真判据】** —— `pool_set_expected` 有效，此校验**确实在跑** |
| `clamp=0` | ⭐ **tick 限流未截断**（⚠️ 因未起播，本来就无放水） |

### 4.2 ⚠️ `sent=0` —— ⭐ 不是故障，但**也不是"正常"**

🔴 **`sent=0` 表示：池里有 200 帧，但一帧都没往 FPGA 放。**

⚠️ **根因（⭐ 本轮查清）**：`pool_start()` **全工程零调用** ⇒ `s_running` 恒 `false`
⇒ `task_pool_pump` 每轮走 `else` 空转（`pool.c:643-645`）。

🔴 **而这是【设计性】的，⛔ 不是缺陷**：

| 依据 | 原文 |
|---|---|
| `FPGA侧答复-ESP32对接清单-20260923.md:24` | 「方案③ —— **上板手动按键起播**。⛔ 你那边不用改固件」 |
| 同上 `:58` | 「固件要不要改 \| ⭐ **一行都不用改**」 |

⇒ ⭐ **起播是 FPGA 板上的物理按键（`Y12`），ESP32 不参与。**

🔴🔴 **但本轮同时发现「方案③ ⇔ 模式 B」架构互斥**（⚠️ 文档未点破）
⇒ ⭐ **详见 `files/20-代码/矛盾裁定单-方案3与模式B-20260930.md`**（⭐ 待 FPGA 侧裁定）。
