## 一、🔴 开工前第一件事：确认芯片

🔴 **必须用【初代 ESP32（经典版）】**，⚠️ **⛔ 不是 ESP32-S3** ——
**S3 芯片没有经典蓝牙 BR/EDR**，⇒ **SPP 在 S3 上物理上不可实现**（只有 BLE）。

### 三步确认

| # | 方法 | 判据 |
|---|---|---|
| **1** | 看模组丝印 | 应印 **`ESP32-WROOM-32E`**（⚠️ 不是 `-S3`、不是 `-S2`） |
| **2** | ⭐ **读芯片 ID**（最确凿） | `esptool.py chip_id` ⇒ ⭐ 应报 **`ESP32-D0WD-V3`** |
| **3** | 功能实测 | 烧 `bt_spp_acceptor` 示例 ⇒ 手机"蓝牙串口助手"能搜到、能收发 |

```powershell
# ⭐ 方法 2（推荐）—— 一句话定死芯片型号
python -m esptool --port COM7 chip_id
#    ✅ 期望：Chip is ESP32-D0WD-V3 (revision v3.x)
#    🔴 若报 ESP32-S3 / ESP32-S2  ⇒ 芯片选错了，⛔ 停下来告诉用户
```

> ⚠️ **为什么必须实测**：⚠️ 市面上有把 S2/S3 当"ESP32"卖的，
> ⚠️ 而**商品简介常常只写 WiFi、不提蓝牙** —— ⛔ **不能作为判据**。
> ⭐ 依据：`ESP32-WROOM-32E` 官方数据手册 §1.1 明写
> **"Bluetooth V4.2 BR/EDR and Bluetooth LE specification"**（⭐ `BR/EDR` 就是经典蓝牙）。

## 二、⭐ 回环自测接线（⛔ 不需要 FPGA）

```
PC ──USB──> ESP32（蓝牙 SPP）      ← 发送端
PC ──USB-TTL──> ESP32 的 UART2      ← 接收端（⭐ 带时间戳）
```

| 项 | 值 |
|---|---|
| UART2 引脚 | ⚠️ **定为 `GPIO17` = TX / `GPIO18` = RX**（⚠️ **避开 `GPIO43`/`GPIO44`** —— 那是 U0 日志口） |
| 波特率 | ⭐ **1 Mbps**（⚠️ 固件做成可配置 —— FPGA 侧现值是 115200） |
| 格式 | 8N1，无流控，3.3 V |
| ⚠️ USB-TTL | ⚠️ **须支持目标波特率** —— 部分 CP2102 上限就是 1 Mbps（无余量）、CH340G 到 2 Mbps ⇒ ⭐ **先看实物型号** |

⚠️ **ESP32 与 USB-TTL 之间要【交叉接】**：ESP32 的 TX → USB-TTL 的 RX，反之亦然。

## 三、⭐⭐ 最关键的一条纪律

> 🔴🔴 **写 UART 的字节数【恒为 9 的整数倍】**（余数留到下次）。

⚠️ **为什么**：**RFCOMM 是【字节流】，⛔ 不保留 `write()` 的边界** ⇒
⚠️ PC 的一次 `write(9 字节)` 到 ESP32 **可能变成两次回调**，中间隔一个任务调度周期
⇒ 🔴 远超 FPGA 的 160 µs 归位门限 ⇒ **静默截帧**。

| # | 要求 |
|---|---|
| **1** | ⭐ **维护一个 0–8 的余数计数器**，只有凑够 9N 才写 UART |
| **2** | ⭐ **块大小也必须是 9N** —— ⚠️ **1024 不是 9 的倍数**（`1024 = 9×113 + 7`）⇒ 🔴 **边界落在帧中间**<br>⭐ 正确值：**1026 B = 114 帧** |
| **3** | 🔴 **一帧的 9 字节【一次写入】**（⛔ 不分 9 次、⛔ 中间不 `vTaskDelay`） |

✅ **这仍然不看内容、不改内容** ⇒ ⭐ **仍然算透传**。
