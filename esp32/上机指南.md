## 〇、⭐⭐ 先明确"这次上机能证明什么、⛔ 不能证明什么"

🔴 **这条最重要** —— ⚠️ 否则会误判成 ESP32 的问题：

| 能证明 | ⛔ 不能证明 |
|---|---|
| ✅ 芯片型号对、能烧录、能启动 | 🔴 **FPGA 会出声** |
| ✅ BLE 能连、MTU 协商成功 | 🔴 **按节奏演奏** |
| ✅ ⭐ **ESP32 侧"按谱子时间喂"是对的** | ⚠️ 端到端联调 |
| ✅ 串口屏显示与变色 | — |

⭐ **原因**（⚠️ 已核实）：**FPGA 侧这一环还没接** ——

```
ESP32 ──UART──> uart_rx ──> evt_uart_rx ──> [事件缓冲] ──> play_seq ──> evt_merge 源A
  ✅就绪         ❌没接      ✅模块已有     🔴【不存在】   ✅模块已有    ⚠️源A还接着 demo
```

> ⭐ 证据：`rtl/top.v` 里 **`play_seq` 只出现在一行注释里**，⛔ **没有例化**。
> ⇒ ⭐ **现在烧上去：ESP32 会认真放水，但 FPGA 收不到 ⇒ 不会响。**

⇒ ⭐ **本次上机的判据全部围绕【ESP32 侧自己】**（见 §六）。

## 一、⭐ 准备清单（⭐ 先点一遍，⛔ 别开工才发现缺东西）

| # | 需要什么 | ⚠️ 注意 |
|---|---|---|
| **1** | ⭐ **ESP32-S3 开发板** | ⭐ **必须带 PSRAM**（⚠️ 模组型号带 `R`，如 `N16R8`） |

## 二、⭐⭐ 第一步：确认芯片（⭐ 这步不过，后面全白做）

⭐ **先查出你的板子插在哪个口**（⚠️ **每次插拔都可能变**，⛔ 不要凭记忆）：

```powershell
Get-PnpDevice -Class Ports -PresentOnly |
  Where-Object InstanceId -like '*VID_303A*' |
  Select-Object -ExpandProperty FriendlyName
```

⭐ **期望输出**（括号里就是你的端口号）：

```
USB 串行设备 (COM29)
```

⚠️ **把下面的 `COM29` 换成你上面看到的口**（⭐ 全文其余 `COM29` 同理）。

```powershell
cd C:\Users\hokuu\Desktop\FPGA\FPGA2026-esp32\esp32\ble
.\build.ps1 -Action chipid -Port COM29
```

⭐ **期望输出**：

```
Chip is ESP32-S3 (revision v0.x)
```

> 🔴 **为什么是 `VID_303A`**：Espressif 的专有 USB VID。
> ⚠️ **⛔ 不要用 `COM7` 之类的固定号** —— 本机 `COM7`/`COM8` 是**蓝牙串行口**，
> 照抄会把固件往蓝牙口上烧。

🔴 **判据表**：

| 看到什么 | ⭐ 结论 |
|---|---|
| ⭐ **`Chip is ESP32-S3`** | ✅ **对了，继续** |
| 🔴 **`ESP32-D0WD`** | 🔴 **这是经典版** ⇒ ⛔ **烧 `esp32/bridge/`（SPP 版），⛔ 不是这个** |
| 🔴 **`ESP32-S2`** | 🔴 **S2 没有 BLE 主机栈可用性差** ⇒ ⚠️ 停下来问 |

### 2.1 ⚠️ 顺手确认 **PSRAM**（⭐ 模式 B 靠它放整曲）

⭐ **最省事的办法**：上面 `chipid` 的输出里**直接就有** —— 看这一行：

```
Features: WiFi, BLE, Embedded PSRAM 8MB (AP_3v3)
```

| 看到 | ⭐ 结论 |
|---|---|
| ✅ **`Embedded PSRAM 8MB`** | ✅ **有 PSRAM，继续** |
| 🔴 **没有 `PSRAM` 字样** | ⚠️ **模组没 PSRAM** ⇒ 见下方后果 |

> ⚠️ **⛔ 不要用 `python -m esptool ... flash_id`** —— 系统 python 里**没有 `esptool`**
> （它只存在于 ESP-IDF 环境内部），敲了会报 `No module named esptool`。
> ⭐ **烧完看启动日志的 `SPIRAM` 字样**（见 §四）是另一个有效办法。

🔴 **没有 PSRAM 的后果**：
⚠️ 水池会**优雅降级**到内部 DRAM（⭐ **能跑，但放不下整曲 104.3 KB**）⇒
⭐ **断链容忍从"整曲"降到约 60 秒** —— ⚠️ **不是不能用，是余量小**。

## 三、⭐ 第二步：编译并烧录

```powershell
cd C:\Users\hokuu\Desktop\FPGA\FPGA2026-esp32\esp32\ble

# ⭐ 编译（⭐ 默认就是模式 B）
.\build.ps1 -Action build

# ⭐ 烧录（⚠️ COM29 换成你 §二 查到的口）
.\build.ps1 -Action flash -Port COM29

# ⭐ 看日志（⭐ 出了事第一个看这个）
.\build.ps1 -Action monitor -Port COM29
```

> ⚠️ **`monitor` 退出用 `Ctrl + ]`**（⛔ 不是 Ctrl+C）。

### 3.1 ⚠️ 要切模式 A 时（⭐ 有坑）

```powershell
.\build.ps1 -Action build -Mode 0     # 模式 A（透传）
.\build.ps1 -Action build -Mode 1     # 模式 B（水池，默认）
```

⚠️ **`build.ps1` 会在切换时自动删 `build/`** ——
🔴 **因为 CMake 缓存会粘住上一次的 `-D` 值**（⭐ 见经验 `C61` / `T95`）。

⭐ **怎么确认模式真的生效**：⚠️ **看体积** ——

| 模式 | ⭐ 参考体积 |
|---|---|
| ⭐ **B（默认）** | `0xc1250` |
| A | ⚠️ 略小 |

⚠️ **两次体积完全相同 ⇒ 开关没生效**（⭐ 这是这条经验的判据）。

## 四、⭐⭐ 第三步：看启动日志（⭐ 一眼确认三件事）

⭐ 上电后 `monitor` 里应该看到：

```
=== ESP32-S3 BLE <-> UART bridge ===
mode = B / POOL (buffer whole score, self-paced)
uart=1 baud=1000000 tx=GPIO17 rx=GPIO18 frame=9B name=FPGA2026-Synth
```

⭐ **要点检的三条**：

| # | 看什么 | ⭐ 期望 | 🔴 不对说明 |
|---|---|---|---|
| **1** | `mode = B / POOL` | ⭐ **模式 B** | ⚠️ 编译时模式没切对 |
| **2** | `baud=1000000` | ⭐ **1 Mbps** | ⚠️ 改过配置 |
| **3** | ⭐ **有没有 `SPIRAM` 相关行** | ⭐ **有** | 🔴 无 ⇒ 模组**没有 PSRAM** |

⚠️ **还要看有没有报错**：
- 🔴 `pool reset: NO MEMORY` ⇒ ⚠️ 水池分配失败（⭐ PSRAM 与 DRAM 都不够）
- 🔴 `create attr tab FAILED` ⇒ 🔴 **GATT 属性表建失败**（⭐ 后面 BLE 一定连不上）

## 五、⭐ 第四步：接线（⭐ 两块**分开**接，⛔ 别混）

### 5.1 ⭐ 串口屏（⭐ 独立 UART，与 FPGA 那条互不影响）

| 屏引脚 | → | ESP32-S3（BLE 版） |
|---|---|---|
| **VCC** | ← | 🔴 **5 V**（⛔ **不是 3.3 V**） |
| **GND** | — | GND |
| **TX** | → | **`GPIO5`**（RX） |
| **RX** | ← | **`GPIO4`**（TX） |

⭐ **波特率 `115200`**（⭐ 必须与屏 `program.s` 里的 `bauds` 一致）。

### 5.2 ⭐ USB-TTL 当"假 FPGA"

| USB-TTL | → | ESP32-S3 |
|---|---|---|
| **TX** | → | **`GPIO18`**（RX） |
| **RX** | ← | **`GPIO17`**（TX） |
| **GND** | — | 🔴 **必须共地** |
| **5V** | ⛔ **不要接** | ⚠️ ESP32 自己从 USB 取电 |

⚠️ **波特率 `1000000`** —— 🔴 **⚠️ 有些 USB-TTL 撑不到 1 Mbps**：
（⭐ 见经验 `FPGA问题排查手册 27`）——⚠️ **若发出去 ESP32 完全没反应**：
- ⭐ **先量 USB-TTL 能不能真的跑 1 Mbps**
- ⚠️ 或**临时把固件改成 115200**（`ble_config.h` 的 `BLE_BAUD`）先跑通

## 六、⭐⭐ 第五步：灌数据 + 验收（⭐ 本次上机的**正题**）

### 6.1 先做**离线自检**（⭐ 确认 PC 侧工具是好的）

```powershell
cd C:\Users\hokuu\Desktop\FPGA\FPGA2026-esp32\esp32\tools
python send_frames.py --selftest
```

⭐ **期望**：**8/8 全过**（⚠️ 这一步 ⛔ 不需要任何硬件）。

### 6.2 灌数据

```powershell
# ⭐ 先小量试（200 事件）
python send_frames.py --port COM8 --events 200

# ⭐ 模式 B 就该"一口气灌完"
python send_frames.py --port COM8 --events 200 --full-speed
```

⚠️ **`COM8` 换成 USB-TTL 的串口号**（⛔ **不是 ESP32 自己的下载口**）。

### 6.3 ⭐⭐ 验收判据（⭐ 逐条对，⛔ 别只看"跑完了"）

⭐ **ESP32 日志每 1 秒打一行**，重点看这几个字段：

| 字段 | ⭐ 期望 | 🔴 不对说明 |
|---|---|---|
| ⭐ **`total=`** | ⭐ **= 你发的事件数**（如 200） | 🔴 0 ⇒ **总数帧没收到** |
| ⭐ **`tf=`** | ⭐ **1** | 🔴 0 ⇒ 同上；⚠️ >1 ⇒ PC 发了多次 |
| ⭐ **`rst=`** | ⭐ **4** | ⚠️ 复位序列帧数（⭐ 4 帧 = 36 字节） |
| 🔴 **`unk=`** | ⭐ **恒为 0** | 🔴 **非 0 ⇒ 对端发了 ESP32 不认识的东西** |
| ⭐ **`pool=N/…`** | ⭐ **N = 你发的事件数** | 🔴 少 ⇒ 丢帧 |
| 🔴 **`ovf=`** | ⭐ **恒为 0** | 🔴 **非 0 ⇒ 池满丢帧** |
| 🔴 **`mismatch=`** | ⭐ **恒为 0** | 🔴 **非 0 ⇒ 实收 ≠ 应到**（⭐ 发送被截断） |
| ⚠️ **`clamp=`** | ⚠️ **可以有值** | ⭐ 含义：tick 限流截断次数（⚠️ 大 = 老落后，⭐ 但**不致命**） |
| ⭐ **`sent=`** | ⭐ **会自己往上涨**（⭐ 模式 B 按谱子时间放） | 🔴 一直 0 ⇒ 没起播 |

⭐⭐ **最关键的三条**：**`unk=0`** · **`ovf=0`** · **`mismatch=0`**
（⭐ 这三个**非 0 都是真故障**，⛔ 不是"正常的波动"）。

### 6.4 ⭐ 串口屏应该显示什么

| 屏上控件 | ⭐ 期望 |
|---|---|
| `t0` + `g0` | `曲谱：` + 曲谱名 |
| `j0` + `n0` | ⭐ **进度条会动、百分比非 0**（⭐ 这是本次修好的） |
| `t1` | 状态字（`待机` / `灌谱中` / `就绪` …） |
| `t2` | ⭐ **`4820/11865` 形式**（⛔ **不再是 `4820/0`**） |
| `t3` | `BT --`（红）/ `BT OK`（绿） |

⚠️ **`t2` 若还是 `x/0`** ⇒ 🔴 **总数帧没被解析**（⭐ 查 `tf=`）。

## 七、⭐⭐ 第六步：BLE 真机连通

⭐ 这块**不依赖 USB-TTL**：

| # | 做什么 | ⭐ 期望 |
|---|---|---|
| **1** | 手机装 **Serial Bluetooth Terminal**（⭐ 或 nRF Connect） | — |
| **2** | 扫描 | ⭐ 看到 **`FPGA2026-Synth`** |
| **3** | 连接 | ⭐ 日志打 `BLE CONNECTED`，屏上 `t3` 变绿 |
| **4** | ⭐ **看 MTU 协商结果** | ⭐ 日志 `MTU negotiated = N` |
| **5** | 在 App 里**写 `0xABF1`**（⭐ 发特征） | ⭐ 数据进来 |
| **6** | ⭐ **订阅 `0xABF2`**（⭐ 接收特征） | ⚠️ **不订阅就收不到 ESP32 发的** |

### ⚠️ 三条容易卡住的

| # | 坑 | ⭐ 说明 |
|---|---|---|
| **1** | 🔴 **必须写 CCCD** | ⭐ `0xABF2` 的 CCCD 要写 `0x0001` 才会收到通知 —— ⚠️ **App 里就是"订阅/使能通知"那个开关** |
| **2** | ⚠️ **MTU 影响吞吐** | ⚠️ 默认 23 ⇒ 有效载荷仅 20 字节 ⇒ **整曲要 5200+ 包** |
| **3** | ⚠️ **`0xABF3`（CMD）目前没用上** | ⭐ 留给"控制命令"（⭐ 现在总数走的是 `0xABF1` 里的**总数帧**） |

## 八、⚠️ 出问题先查这六条（⭐ 按概率排序）

| # | 现象 | ⭐ 先查 |
|---|---|---|
| **1** | 🔴 **ESP32 完全没反应** | ⭐ **USB-TTL 能不能真跑 1 Mbps** + **共地**（⭐ 见经验 `手册 27`） |
| **2** | 🔴 **`unk=` 一直在涨** | 🔴 **对端发的东西 ESP32 不认识** ⇒ 查是不是把 `FF FF FF` 当字符发了 |
| **3** | 🔴 **`pool=0`**（一帧都没进池） | ⚠️ 帧头不对 ⇒ 查 PC 侧到底发了什么字节 |
| **4** | ⚠️ **屏上没变化** | ⭐ 先看**屏的回显**（⭐ 有回显=指令到了）；⚠️ 再查 `font` 指向的字库存不存在 |
| **5** | 🔴 **BLE 连不上** | ⚠️ 查日志有没有 `create attr tab FAILED`（⭐ 属性表没建起来） |
| **6** | ⚠️ **`SPIRAM` 没有** | 🔴 **模组真没 PSRAM** ⇒ ⚠️ 水池降级（⭐ 能跑但余量小） |
